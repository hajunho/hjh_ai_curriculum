# Lecture 11 · Level 00 — LLM이란: 초대형 '다음 단어 예측기'

> ChatGPT·Claude 같은 대규모 언어모델(LLM)이 실제로 하는 일은 "다음 단어 맞히기"라는 것을 미니 모델로 직접 체험합니다.
**난이도** ⭐ / **선행** lecture02 (파이썬 기초) / **예상 시간** 30분

## 1. 왜 배우나 — 비즈니스 관점

요즘 회사에서 "AI로 이거 안 되나요?"라는 질문이 하루에도 몇 번씩 나옵니다. 그런데 LLM(Large Language Model, 대규모 언어모델)이 무엇을 잘하고 무엇을 못하는지 모르면 두 가지 실수를 하게 됩니다. 하나는 과대평가 — "AI가 알아서 다 해주겠지"라며 검증 없이 보고서에 붙여 넣는 것이고, 다른 하나는 과소평가 — "어차피 챗봇이잖아"라며 업무 자동화 기회를 놓치는 것입니다.

이 레벨에서 LLM의 원리를 한 문장으로 이해하면, 이후 모든 판단이 쉬워집니다. **LLM은 "지금까지의 글 다음에 올 단어"를 확률로 예측하는 기계**입니다. 이 한 문장에서 LLM의 강점(유창한 글쓰기, 요약, 번역)과 약점(사실 검증 불가, 최신 정보 부재, 환각)이 모두 따라 나옵니다. 도구의 원리를 아는 사람이 도구를 지배합니다.

## 2. 비유로 이해하기

**스마트폰 자동완성의 초대형 버전**을 떠올려 보세요. "안녕하"까지 치면 키보드가 "세요"를 제안하죠. 이 자동완성이 (1) 단어 몇 개가 아니라 책 수백만 권 분량의 글을 읽었고, (2) 바로 앞 한두 단어가 아니라 수만 단어의 문맥을 기억하고, (3) 한 단어가 아니라 문단 전체를 이어서 제안한다면 — 그것이 바로 LLM입니다.

**파라미터(parameter)는 경험치**입니다. 게임 캐릭터의 경험치가 쌓일수록 더 어려운 퀘스트를 깨듯, 파라미터(모델이 학습으로 조정한 숫자들)가 많을수록 더 미묘한 언어 패턴을 기억합니다. 신입사원(작은 모델)은 매뉴얼에 있는 것만 처리하지만, 20년차 베테랑(큰 모델)은 처음 보는 상황도 "비슷한 경험"으로 유추해 냅니다.

다만 베테랑에게도 약점이 있습니다. **퇴사한 직원은 퇴사 이후의 회사 소식을 모릅니다.** LLM도 학습이 끝난 시점(지식 시점, knowledge cutoff) 이후의 일은 모릅니다. 그리고 기억이 가물가물할 때 "아마 그랬을 거예요"라고 그럴듯하게 지어내는 것 — 이것이 환각(hallucination)입니다.

## 3. 핵심 개념

### 3.1 토큰 단위 생성

LLM은 문장을 통째로 만들지 않습니다. 토큰(token, 단어 조각) 하나를 예측하고, 그것을 입력에 붙인 뒤 또 다음 토큰을 예측합니다. 100단어 답변이면 이 과정을 수백 번 반복한 것입니다. API 요금이 "토큰당 과금"인 이유, 긴 답변이 느린 이유가 여기 있습니다.

### 3.2 확률 분포와 샘플링

매 순간 모델은 "다음에 올 수 있는 모든 토큰"의 확률표를 만듭니다. 예를 들어 "어제 개발자가" 다음에는 "프로그램을 41%, 보고서를 22%, ..." 같은 분포입니다. 여기서 항상 1등만 뽑으면(탐욕적 선택) 답이 늘 같고 단조롭습니다. 확률에 따라 추첨하면(샘플링) 매번 조금씩 다른, 다양한 답이 나옵니다. 같은 질문에 ChatGPT가 매번 다른 답을 주는 이유입니다.

### 3.3 n-gram 언어모델 — 오늘의 실습 재료

신경망 이전 시대의 언어모델은 단순한 통계표였습니다. n-gram 모델은 "앞의 (n-1)개 단어가 이것일 때, 다음 단어가 무엇이었는지"를 세어 둔 표입니다.

| 문맥 (앞 2단어) | 다음 단어 후보 | 횟수 |
|---|---|---|
| 어제 개발자가 | 프로그램을 | 87 |
| 어제 개발자가 | 보고서를 | 45 |

실제 LLM은 이 "표"를 신경망으로 대체해, 표에 없던 문맥도 유추할 수 있게 만든 것입니다. 원리는 같습니다: **과거 글의 통계로 다음 단어를 예측한다.**

### 3.4 두 가지 태생적 한계

1. **지식 시점**: 학습 데이터에 없는 것은 모릅니다. 우리 회사 규정, 어제 뉴스, 고객 DB — 전부 모릅니다. (해결책이 이 강의 후반의 RAG입니다.)
2. **환각**: "유창하게 말하기"를 배웠지 "사실만 말하기"를 배운 게 아닙니다. 통계적으로 그럴듯한 조합이면 사실이 아니어도 자신 있게 말합니다.

## 4. 실습 — main.py

실행:

```bash
cd lecture11_llm_and_rag/level00_what_is_llm
python3 main.py
```

출력 해설:

- **[1]~[2]** `hjh_data.tiny_corpus()`의 한국어 미니 코퍼스(약 3.9만 자)로 bigram/trigram 통계표를 만듭니다. 이 "표 만들기"가 곧 학습입니다.
- **[3]** "회사원이" 다음에 올 단어의 확률 분포를 막대그래프로 보여줍니다. LLM이 매 토큰마다 내부적으로 하는 일이 정확히 이것입니다.
- **[4]** 같은 시작 문맥("오늘 요리사가")에서 샘플링으로 3개의 서로 다른 문장을, 탐욕적 선택으로 항상 같은 문장을 생성합니다.
- **[5]** 생성된 20문장 중 학습 데이터에 **없던 새 조합**이 섞여 있음을 확인합니다. 문법은 맞지만 사실 보증은 없습니다 — 환각의 미니어처입니다.
- **[6]** 코퍼스에 없는 단어("신입사원이")를 문맥으로 주면 분포 자체가 없습니다. 지식 시점의 미니어처입니다.

코드 핵심부는 `build_ngram_model`(문맥→다음 단어 카운트), `next_word_distribution`(카운트→확률), `generate`(확률→추첨→반복)의 3단 구조입니다. LLM의 뼈대도 이와 같고, 카운트 표가 신경망으로 바뀐 것뿐입니다.

## 6. 자주 하는 실수

- **"LLM이 검색해서 답한다"는 오해** — 기본 LLM은 아무것도 검색하지 않습니다. 학습 때 본 통계로 생성할 뿐입니다. 검색을 붙이는 것은 별도 기술(RAG, level08)입니다.
- **"자신 있게 말하니 사실이겠지"** — 확률 1등 토큰을 뽑았다는 뜻이지, 사실이라는 뜻이 아닙니다. 유창함 ≠ 정확함.
- **같은 질문에 답이 달라지면 고장이라고 생각** — 샘플링의 정상 동작입니다. 재현성이 필요하면 temperature를 낮추는(탐욕적 선택에 가깝게) 설정을 쓰면 됩니다.
- **시드 고정 없이 실험** — 오늘 코드는 `random.Random(42)`로 고정했습니다. 실험을 비교하려면 항상 시드를 고정하세요.
