# Lecture 11 · Level 09 — 검색 품질 개선: 하이브리드·MMR·리랭킹

> RAG 답변 품질의 병목은 대부분 검색입니다 — BM25를 직접 구현해 의미 검색과 결합하고, MMR로 중복을 줄여 전후를 비교합니다.
**난이도** ⭐⭐⭐⭐ / **선행** level08 / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

level08의 챗봇을 실제 사용자에게 열면 곧 이런 불만이 옵니다. "정확한 용어로 물었는데 엉뚱한 문서가 나와요", "답변이 같은 말만 반복해요". 원인은 생성이 아니라 검색입니다 — **LLM은 검색이 가져다준 재료 이상의 답을 만들 수 없습니다.**

검색 품질 개선은 모델 교체보다 훨씬 싸고 효과가 확실한 투자입니다. 오늘 배우는 세 기법 — 하이브리드(키워드+의미), MMR(다양성), 리랭킹(2단계 정밀 채점) — 은 실제 기업 RAG 시스템의 표준 구성이며, 전부 "검색된 조각 목록을 더 좋게 만드는" 기술입니다.

## 2. 비유로 이해하기

**두 명의 사서**가 있는 도서관을 상상해 보세요. 사서 A(키워드/BM25)는 꼼꼼한 색인 카드파입니다. "미사용 연차 수당"이라고 정확히 말하면 눈 깜짝할 새 정확한 페이지를 찾지만, "쉬는 날 안 쓰면 돈으로 주나요?"라고 물으면 카드에 없는 단어라 멍해집니다. 사서 B(의미 검색)는 눈치가 빨라 돌려 말해도 알아듣지만, 가끔 "느낌이 비슷한" 엉뚱한 책을 가져옵니다.

**하이브리드**는 두 사서에게 모두 물어보고 추천 목록을 합치는 것입니다. 실패하는 지점이 서로 달라, 합치면 보험이 됩니다.

**MMR**은 책 바구니 규칙입니다. 4권을 담을 수 있는데 사서가 내용이 거의 같은 책 2권을 담으면 한 자리가 낭비입니다. "관련 있으면서, 이미 담은 책과 다른 책"을 담는 것이 MMR입니다.

**리랭킹**은 채용의 2단계 전형입니다. 서류 전형(빠른 1차 검색)으로 후보 30명을 추리고, 면접(정밀하지만 느린 채점)으로 최종 3명을 뽑습니다.

## 3. 핵심 개념

### 3.1 BM25 — 키워드 검색의 표준 공식

수십 년간 검색 엔진의 기본기였던 점수식입니다. 세 가지 직관의 조합입니다.

1. **TF(단어 빈도)**: 질문 단어가 그 조각에 많이 나올수록 가점 — 단, 10번이 5번의 2배는 아니게 포화시킴(k1 파라미터).
2. **IDF(희귀도)**: "코어타임"처럼 드문 단어의 일치는 크게, "기준"처럼 흔한 단어는 작게.
3. **길이 보정**: 긴 조각은 우연히 단어를 포함하기 쉬우므로 감점(b 파라미터).

### 3.2 한국어에서 키워드 검색의 함정

한국어는 조사·어미가 붙습니다. 문서의 "코어타임인"과 질문의 "코어타임"은 **다른 단어**로 취급되어 일치 0이 됩니다. 실무에서는 형태소 분석기나 부분단어(n-gram) 색인으로 완화하지만, 오늘 실습은 이 함정을 일부러 그대로 보여줍니다 — 하이브리드가 필요한 이유이기 때문입니다.

### 3.3 하이브리드 결합

BM25 점수와 코사인 유사도는 눈금이 다릅니다(BM25는 0~10+, 코사인은 0~1). 그래서 각각 0~1로 정규화(min-max)한 뒤 가중 평균합니다: `score = α·BM25 + (1-α)·의미`. α는 평가셋으로 튜닝하며 0.3~0.7이 흔합니다. (참고: 순위만 결합하는 RRF라는 방식도 널리 쓰입니다.)

### 3.4 MMR(Maximal Marginal Relevance)

한 번에 하나씩 뽑되, `λ·(질문과의 관련성) − (1−λ)·(이미 뽑은 것과의 최대 유사도)`가 가장 큰 후보를 선택합니다. λ=1이면 그냥 유사도 순, λ가 작을수록 다양성 우선. 사내 문서는 규정·공지·FAQ에 같은 내용이 중복되기 마련이라 MMR의 효과가 특히 큽니다.

### 3.5 무엇부터 적용할까 — 개선 우선순위

검색 품질이 아쉬울 때의 실무 순서입니다. (1) 먼저 **검색 로그를 눈으로** 봅니다 — 실패 질문 20개만 봐도 원인(청킹? 표기 불일치? 중복?)이 드러납니다. (2) 청킹 문제면 level06으로 돌아가고, 표기 불일치가 많으면 **하이브리드**를, 답변이 같은 말을 반복하면 **MMR**을 먼저 넣습니다. (3) 리랭킹은 효과가 크지만 호출 비용·지연이 늘어나므로 마지막에, 평가셋으로 개선 폭을 확인하며 도입합니다. "전부 한꺼번에"가 아니라 병목 하나씩 고치고 재는 것이 정석입니다.

## 4. 실습 — main.py

실행:

```bash
cd lecture11_llm_and_rag/level09_retrieval_quality
python3 main.py
```

출력 해설:

- **[1]** 사내 문서에 연차 규정과 내용이 겹치는 "사내공지"를 추가해, 중복이 존재하는 실전형 코퍼스(21조각)를 만듭니다.
- **[2]** 명사 나열형 질의("미사용 연차 수당 정산")에서 BM25가 정답을 정확히 1위로 찾는 것을 확인합니다.
- **[3]** 두 검색기의 실패 모드: "코어타임 시간을"에는 BM25가 0점(조사 문제), "출장 일비 기준"에는 흔한 단어 '기준'에 낚여 휴가 규정을 1위로 올립니다. 두 경우 모두 의미 검색은 성공합니다.
- **[4]** 세 질문의 O/X 표: BM25 단독 1승 2패, 의미 단독 3승, 하이브리드 3승 — 실패 모드가 다른 두 검색을 합치면 안정성이 올라간다는 것이 요점입니다.
- **[5]** MMR 전후: 유사도 순 top-4는 1·2위가 사실상 같은 문장(신청 기한 중복)이지만, MMR은 중복을 버리고 "15일 부여"라는 새 정보를 확보합니다.
- **[6]** 리랭킹 2단계 구조 소개.

코드 핵심부: `BM25` 클래스(`_idf()`와 `scores()`의 TF 포화·길이 보정), `minmax()` 정규화 후 가중 합, 그리고 `mmr_select()`의 탐욕적 선택 루프(관련성 − 중복 페널티)를 읽어 보세요. 세 함수 모두 20줄 내외로, 실전 시스템에서도 뼈대는 이와 같습니다.

## 6. 자주 하는 실수

- **정규화 없이 점수 합산** — BM25(0~10+)와 코사인(0~1)을 그대로 더하면 사실상 BM25 단독 검색입니다. 반드시 눈금을 맞춘 뒤 결합하세요.
- **의미 검색 도입 후 키워드 검색 폐기** — 제품코드·조항번호·고유명사 질의에서 품질이 뚝 떨어집니다. 보완재이지 대체재가 아닙니다.
- **중복 제거를 색인에서만 시도** — 문서 정리는 좋지만, 규정/공지/FAQ의 중복은 없앨 수 없는 현실입니다. 검색 단계의 MMR이 현실적 해법입니다.
- **평가셋 없이 파라미터 튜닝** — α, λ, top-k를 감으로 정하면 개선인지 개악인지 알 수 없습니다. level06처럼 명중률로 재세요.
- **한국어 조사 문제를 잊음** — "단어 일치 0개"의 상당수는 조사 때문입니다. 실서비스에서는 형태소 분석·n-gram 색인을 검토하세요.
