# Lecture 11 · Level 05 — 임베딩과 의미 검색

> 문장을 숫자 좌표(벡터)로 바꾸면 "단어가 달라도 뜻이 비슷한" 문서를 찾을 수 있습니다 — RAG의 첫 번째 부품입니다.
**난이도** ⭐⭐⭐ / **선행** level00, lecture03(NumPy) / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

사내 검색창에 "재택으로 일할 수 있는 날"이라고 치면 아무것도 안 나오고, "재택근무"라고 정확히 쳐야 규정이 나오는 경험, 다들 있으실 겁니다. 고전적 키워드 검색은 **단어가 글자 그대로 일치**해야 찾습니다. 그런데 고객과 직원은 문서 작성자와 같은 단어를 쓰지 않습니다 — "환불"을 "돈 돌려주세요"라고, "연차"를 "쉬는 날"이라고 말합니다.

임베딩(embedding) 기반 의미 검색은 이 문제를 풉니다. 문장을 "의미 좌표"로 바꿔서, 표현이 달라도 뜻이 가까우면 찾아냅니다. 사내 규정 챗봇, 고객센터 자동 응답, 유사 민원 찾기 — 이 강의 후반의 RAG 챗봇까지, 모든 것이 이 부품 위에 서 있습니다.

## 2. 비유로 이해하기

**대형마트의 상품 배치**를 떠올려 보세요. 라면과 우동과 국수는 같은 통로에 있습니다. 이름은 다르지만 "면류"라는 의미가 같아서입니다. 마트 지도에서 두 상품의 **거리**가 곧 두 상품의 **유사성**입니다.

임베딩은 문장마다 이런 "마트 내 좌표"를 부여하는 기술입니다. 다만 통로가 2개 축이 아니라 수백 개 축(차원)입니다. "연차 휴가 며칠 쓸 수 있나요?"와 "제1조 연차휴가는 15일 부여된다"는 다른 문장이지만 좌표가 가깝고, "제품 보증 기간"과는 멉니다. 검색은 이제 간단합니다: **질문의 좌표에서 가장 가까운 문장을 찾으면 됩니다.** 각도가 가까운 정도를 재는 자가 코사인 유사도(cosine similarity)입니다 — 1에 가까울수록 같은 방향(같은 주제)입니다.

## 3. 핵심 개념

### 3.1 임베딩 = 텍스트 → 고정 길이 숫자 벡터

어떤 길이의 문장이든 같은 길이(오늘은 512칸, 실제 모델은 1024~3072칸)의 실수 배열로 바뀝니다. 핵심 성질은 하나: **의미가 비슷하면 벡터가 가깝다.** 이 성질 덕분에 검색·군집·중복 제거·추천이 전부 "벡터 거리 계산" 문제로 바뀝니다.

### 3.2 코사인 유사도

두 벡터가 이루는 각도의 코사인 값입니다. 벡터를 길이 1로 정규화해 두면 내적(dot product) 한 번이 곧 코사인이라, NumPy 행렬곱으로 문장 수천 개를 한 번에 비교할 수 있습니다(`vectors @ qv`).

### 3.3 오늘의 모의 임베딩 — 문자 n-gram 해시 + 동시출현

실제 임베딩 모델은 신경망이지만, 원리 체험용 `MockEmbedding`은 두 가지 고전 기법을 씁니다.

1. **문자 n-gram 해시**: 문장에서 2~3글자 조각("연차", "차휴", "휴가"...)을 뽑아 해시 함수로 512칸 중 한 칸에 배정해 셉니다. "재택근무는"과 "재택으로"는 "재택"이라는 조각을 공유하므로 벡터가 겹칩니다 — 조사·어미가 달라도 통하는 이유입니다.
2. **동시출현(co-occurrence) 확장**: 학습 코퍼스에서 같은 문장에 자주 함께 나온 단어("연차"↔"휴가")를 기억해 두고, 임베딩할 때 이웃 단어의 조각도 약하게 섞습니다. 단어가 아예 달라도 주제로 연결되는 효과를 냅니다.

실제 신경망 임베딩은 이보다 훨씬 정교하게 "문맥"을 반영하지만, **"비슷한 곳에 쓰이는 말은 가까운 좌표를 갖는다"**는 철학은 같습니다.

### 3.4 키워드 검색과의 관계 — 대체가 아니라 보완

의미 검색이 항상 이기는 것은 아닙니다. 제품 코드("A-1042"), 고유명사, 정확한 조항 번호는 키워드 검색이 더 정확합니다. 그래서 실무에서는 둘을 섞은 하이브리드 검색(level09)을 씁니다.

### 3.5 임베딩의 다른 용도 — 검색만이 아니다

"비슷하면 가깝다"는 성질은 검색 외에도 널리 쓰입니다. (1) **유사 민원 묶기**: 같은 내용의 민원 수백 건을 군집화해 이슈를 조기 발견. (2) **중복 탐지**: 거의 같은 문서·FAQ를 찾아 정리. (3) **추천**: "이 문서를 본 사람이 볼 만한 문서". (4) **이상 탐지**: 평소 문의들과 좌표가 동떨어진 입력을 감지. 모두 오늘 배운 코사인 유사도 계산 하나로 구현되며, lecture06의 군집화(k-means)와 결합하면 곧바로 실무 도구가 됩니다.

## 4. 실습 — main.py

실행:

```bash
cd lecture11_llm_and_rag/level05_embeddings_semantic_search
python3 main.py
```

출력 해설:

- **[1]** `SAMPLE_DOCS` 5개 문서를 18개 문장으로 분해합니다.
- **[2]** 각 문장이 512차원 벡터가 됩니다. 0이 아닌 칸이 59개 정도 — n-gram이 배정된 칸들입니다.
- **[3]** 유사도 3쌍 비교: 연차 질문↔연차 규정(0.17), 연차 질문↔보증 문장(0.00), 보증 질문↔보증 문장(0.53). 같은 주제일수록 값이 크게 나오는 것을 확인하세요.
- **[4]** 핵심 장면입니다. "재택으로 일할 수 있는 날은?"이라는 질문에 키워드 검색은 **일치 단어 0개**(문서에는 "재택근무는"이라고 쓰여 있으므로)로 실패하지만, 의미 검색은 재택근무 규정을 1위로 찾습니다. 두 번째 질문("경비 영수증 언제까지?")은 둘 다 찾지만, 의미 검색이 관련 문장들을 더 풍부하게 올립니다.
- **[5]** 벡터들을 SVD로 2차원에 사영한 지도를 `outputs/embedding_map.png`로 저장합니다. 같은 문서의 문장들이 뭉쳐 있는지 눈으로 확인해 보세요.

코드 핵심부: `semantic_search()`의 `sims = vectors @ qv` 한 줄이 전부입니다 — 정규화된 벡터의 행렬곱 = 모든 문장과의 코사인 유사도. `keyword_search()`는 "단어 완전 일치 개수"라는 고전 방식을 씁니다. 두 함수의 결과 차이가 이 레벨의 학습 목표입니다.

## 6. 자주 하는 실수

- **임베딩 벡터를 사람이 해석하려는 시도** — 각 칸은 "가격", "색상" 같은 의미가 아닙니다. 벡터는 오직 "서로 간 거리"로만 의미를 갖습니다.
- **정규화 없이 내적을 유사도로 사용** — 긴 문장일수록 값이 커지는 왜곡이 생깁니다. 길이 1로 정규화하거나 `cosine()`을 쓰세요.
- **서로 다른 임베딩 모델의 벡터를 섞어 비교** — 모델이 다르면 좌표계가 다릅니다. 문서와 질문은 반드시 같은 모델로 임베딩해야 합니다.
- **의미 검색 만능주의** — 코드번호·인명 검색은 키워드가 낫습니다. level09의 하이브리드가 실무 정답입니다.
