# Lecture 04 · Level 05 — 집계 함수와 GROUP BY

> COUNT·SUM·AVG·MIN·MAX 로 요약하고, GROUP BY 로 "도시별·카테고리별" 소계를 내고, HAVING 으로 소계에 조건을 겁니다. 엑셀 피벗 테이블이 하던 일을 SQL 로 합니다.

**난이도** ⭐⭐ / **선행** level04 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

경영진은 행 목록을 보지 않습니다. **요약 숫자**를 봅니다. "고객이 총 몇
명인가", "도시별로는 몇 명씩인가", "카테고리별 매출은 얼마인가". 엑셀에서
피벗 테이블을 만들던 바로 그 일이 SQL 의 집계(aggregate)와 GROUP BY(그룹
바이)입니다. 차이점은 규모와 재현성입니다. 수백만 행도 DB 안에서 요약된
결과만 받아오므로 파일이 무거워질 일이 없고, 쿼리를 저장해 두면 매주 같은
보고서를 몇 초 만에 다시 만들 수 있습니다. "GROUP BY 를 할 줄 안다"는 것은
"보고서의 어떤 소계든 직접 만들 수 있다"는 뜻입니다.

## 2. 비유로 이해하기

창구 직원에게 이번엔 이렇게 부탁합니다. "고객 카드를 **도시별로 묶어서**,
묶음마다 **몇 장인지 세어** 주세요."

직원의 작업은 두 단계입니다. 먼저 카드를 도시별 **바구니에 나눠 담고**
(GROUP BY city), 각 바구니에 대해 **요약 계산 하나**를 합니다(COUNT).
결과는 카드가 아니라 **바구니당 한 줄**입니다 — 서울 41장, 부산 33장…

여기서 대원칙이 나옵니다. **GROUP BY 결과의 한 행 = 바구니 하나.**
그러니 SELECT 에는 (1) 바구니 이름표(그룹 기준 열)와 (2) 바구니 요약값
(집계 함수)만 올 수 있습니다. 바구니 안 개별 카드의 이름 같은 것을 달라고
하면 "어느 카드요?"가 되어 버립니다.

HAVING(해빙)은 요약이 끝난 뒤 **바구니를 골라내는 체**입니다. "35장 넘는
바구니만 보고해 주세요." WHERE 가 바구니에 담기 전 카드 하나하나를
거른다면, HAVING 은 다 세고 난 뒤 바구니를 거릅니다.

## 3. 핵심 개념

### 3-1. 집계 함수 다섯 형제

| 함수 | 뜻 | 예 |
|---|---|---|
| COUNT(*) | 행 수 | 고객 수 |
| SUM(x) | 합계 | 매출 합 |
| AVG(x) | 평균 | 평균 단가 |
| MIN(x) / MAX(x) | 최소/최대 | 최저가/최고가 |

집계 함수는 여러 행을 받아 **한 개의 값**으로 접습니다. GROUP BY 없이 쓰면
테이블 전체가 바구니 하나가 되어 결과도 한 행입니다.

### 3-2. COUNT 의 세 가지 표정

- `COUNT(*)` — 행 자체를 셉니다 (NULL 포함).
- `COUNT(열)` — 그 열이 **NULL 이 아닌** 행만 셉니다.
- `COUNT(DISTINCT 열)` — NULL 아닌 **서로 다른 값**의 개수.

employees 의 manager_id 로 세 표정을 비교하면 차이가 또렷합니다. 사장님
(manager_id 가 NULL)은 `COUNT(manager_id)` 에서 빠집니다.

### 3-3. GROUP BY — 소계 만들기

```sql
SELECT city, COUNT(*) AS customer_cnt
FROM   customers
GROUP BY city
ORDER BY customer_cnt DESC;
```

집계를 여러 개 나란히 둘 수도 있습니다: `COUNT(*), AVG(price), MAX(price)`.
그룹 기준을 두 개 쓰면(`GROUP BY city, grade`) "도시×등급" 조합마다 한 행이
됩니다 — 피벗 테이블의 행/열 영역에 필드 두 개를 넣는 것과 같습니다.

### 3-4. HAVING — 소계에 거는 조건

```sql
SELECT city, COUNT(*) AS cnt
FROM   customers
GROUP BY city
HAVING COUNT(*) >= 35;
```

WHERE 와의 구분이 이 레벨의 핵심 시험 포인트입니다.

- **WHERE**: 묶기 **전**, 개별 행 조건. 집계 함수를 쓸 수 없음.
- **HAVING**: 묶은 **후**, 바구니(그룹) 조건. 집계 함수를 쓰는 곳.

"취소 주문은 빼고(WHERE), 주문 100건 이상인 도시만(HAVING)"처럼 둘을 함께
쓰는 것이 실무 표준형입니다.

### 3-5. 실행 순서 업데이트

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

골라내고 → 묶고 → 바구니를 거르고 → 요약을 다듬고 → 줄 세우고 → 끊는다.
이 순서를 알면 "WHERE 에 왜 집계를 못 쓰는지"(아직 안 묶였으니까)가 자연히
이해됩니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1] 전체 요약**: 고객 총수, 그리고 상품 가격의 SUM/AVG/MIN/MAX 를 한
  행으로 — GROUP BY 없는 집계는 "테이블 전체 = 바구니 하나".
- **[2] COUNT 의 세 표정**: `COUNT(*)` vs `COUNT(manager_id)` vs
  `COUNT(DISTINCT dept)` 를 employees 로 비교합니다.
- **[3] 도시별 고객 수**: GROUP BY 기본형 + 많은 순 정렬.
- **[4] 도시×등급별 고객 수**: 그룹 기준 두 개.
- **[5] 카테고리별 매출**: 주문 상세(order_items)와 상품(products)을 연결해
  `SUM(quantity * price)` 를 계산합니다. 두 테이블을 잇는 JOIN 은 다음
  레벨의 주인공이라, 여기서는 "이렇게 붙이는구나" 정도로 미리 맛만 봅니다.
- **[6] HAVING**: 고객 35명 이상인 도시만. WHERE 로 같은 걸 시도하면 에러가
  난다는 사실도 주석으로 확인합니다.
- **[7] WHERE + HAVING 합동**: 취소 주문을 빼고(WHERE) 월별 주문 수를 센 뒤
  80건 이상인 달만(HAVING) — 실무 표준형입니다.

## 6. 자주 하는 실수

- **그룹 기준에 없는 열을 SELECT 에 넣기**: `GROUP BY city` 인데
  `SELECT city, name` — "바구니당 한 행"에 개별 카드의 이름은 올 수
  없습니다. (SQLite 는 에러 대신 아무 행이나 하나 골라 주기도 해서 더
  위험합니다. 다른 DB에서는 대부분 에러.)
- **WHERE 에 집계 함수**: `WHERE COUNT(*) > 10` 은 에러. 묶기 전에는 셀 수
  없습니다. 그룹 조건은 HAVING 으로.
- **AVG 와 NULL**: AVG 는 NULL 을 **무시하고** 평균을 냅니다. "0으로 치고
  평균"을 원하면 `AVG(COALESCE(x, 0))` 처럼 명시해야 합니다.
- **정수 나눗셈**: SQLite 에서 `SUM(a)/COUNT(*)` 는 정수끼리라 소수점이
  잘립니다. `1.0 *` 를 곱하거나 AVG 를 쓰세요.
- **집계 결과 검산 생략**: 소계의 합이 전체와 맞는지(`SUM(소계) = 전체`)
  한 번 확인하는 습관이 보고서 사고를 막습니다.
