# Lecture 04 · Level 03 — WHERE: 조건 검색

> "전부 다"가 아니라 "조건에 맞는 것만" 꺼내는 법을 배웁니다. 비교 연산, AND/OR, IN, LIKE, BETWEEN, NULL 처리까지 — 업무 질문 6개를 SQL 로 번역합니다.

**난이도** ⭐⭐ / **선행** level02 / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

실무의 데이터 질문은 거의 전부 조건이 붙습니다. "서울 사는 **VIP** 고객",
"**취소된** 주문", "**3분기** 매출", "**김씨 성**을 가진 담당자". 엑셀에서
필터 버튼을 누르고 체크박스를 고르던 일이 SQL 에서는 WHERE(웨어) 한 줄입니다.
차이가 있다면, 엑셀 필터는 손으로 다시 눌러야 하지만 WHERE 문장은 **저장해
두면 언제든 같은 조건을 재실행**할 수 있고, 조건을 말로 설명하는 대신 문장
자체를 동료에게 전달할 수 있다는 점입니다. "어떤 조건으로 뽑았어요?"라는
질문에 쿼리 한 줄로 답하는 것 — 그것이 데이터 소통의 정확함입니다.

## 2. 비유로 이해하기

WHERE 는 창구 직원에게 건네는 요청서의 **세 번째 칸**입니다.

> 어느 장부에서 (FROM) / 어떤 항목을 (SELECT) / **어떤 행만** (WHERE)

창구 직원은 장부를 한 줄씩 넘기며 각 행에 질문을 던집니다. "이 고객,
서울 거주인가? 그리고 VIP 인가?" — 답이 '참(true)'인 행만 결과 바구니에
담습니다. 즉 WHERE 뒤에 오는 것은 **행마다 참/거짓을 판정하는 문장**입니다.

lecture02 에서 배운 파이썬의 if 조건식과 정확히 같은 역할입니다.
`if city == "서울" and grade == "VIP":` 를 SQL 로 쓰면
`WHERE city = '서울' AND grade = 'VIP'` — 등호가 하나(=)라는 것과
문자열이 작은따옴표라는 것만 다릅니다.

## 3. 핵심 개념

### 3-1. 비교 연산자

`=`(같다), `<>` 또는 `!=`(다르다), `>`, `>=`, `<`, `<=`.
파이썬과 달리 "같다"가 `==` 가 아니라 `=` 한 개입니다.

```sql
WHERE price >= 100000        -- 10만 원 이상
WHERE status <> '취소'        -- 취소가 아닌 것
```

### 3-2. AND / OR / NOT — 조건 조합

```sql
WHERE city = '서울' AND grade = 'VIP'          -- 둘 다 만족
WHERE grade = 'VIP' OR grade = 'GOLD'          -- 하나만 만족해도
```

AND 가 OR 보다 먼저 계산됩니다. `A OR B AND C` 는 `A OR (B AND C)` 로
해석되어 의도와 달라지기 쉬우니, **OR 가 섞이면 괄호를 무조건 치는 습관**을
들이세요.

### 3-3. IN — 목록 중 하나

`grade IN ('VIP', 'GOLD')` 는 `grade='VIP' OR grade='GOLD'` 의 줄임말입니다.
목록이 길수록 IN 이 압도적으로 읽기 좋습니다. 반대는 `NOT IN`.

### 3-4. LIKE — 패턴 검색

문자열의 "~로 시작/끝/포함" 검색입니다. `%` 는 "아무 글자 0개 이상",
`_` 는 "아무 글자 정확히 1개"를 뜻하는 와일드카드입니다.

```sql
WHERE name LIKE '김%'      -- 김으로 시작 (김씨 성)
WHERE name LIKE '%커피%'   -- 커피가 포함된 상품명
```

### 3-5. BETWEEN — 범위

`price BETWEEN 10000 AND 100000` 은 `price >= 10000 AND price <= 100000` 과
같습니다. **양 끝을 포함**한다는 점을 기억하세요. 날짜 문자열에도 그대로
쓸 수 있어 기간 조회의 단골입니다:
`ordered_at BETWEEN '2025-07-01' AND '2025-09-30'` (3분기).

### 3-6. NULL — 값이 '없음'을 다루는 법

NULL(널)은 0도 빈 문자열도 아닌 **"기록되지 않음"** 입니다. 그래서 보통의
비교가 통하지 않습니다. `manager_id = NULL` 은 항상 거짓이 되어 아무 행도
나오지 않습니다. 반드시 전용 문법을 씁니다.

```sql
WHERE manager_id IS NULL       -- 상사가 없는 사람 (= 최고 책임자)
WHERE manager_id IS NOT NULL   -- 상사가 있는 사람
```

"왜 = 로 안 되나요?" — NULL 은 '모름'이므로 "모름 = 모름"의 답도 '모름'이기
때문입니다. SQL 초보 사고 1위 지점이니 IS NULL 만큼은 암기하세요.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

main.py 는 실제 업무에서 나올 법한 질문 6개를 한국어로 먼저 보여 주고,
그것을 번역한 SQL 과 실행 결과를 출력합니다.

- **[Q1] "서울에 사는 VIP 고객 명단 주세요"** — `=` 와 AND.
- **[Q2] "10만 원 이상이거나 마진율 50% 넘는 상품은?"** — OR 와 괄호,
  계산식을 조건에 쓰는 예.
- **[Q3] "수도권(서울·인천) 아니면 부산 고객 중 GOLD 이상만"** — IN 두 번과
  AND/OR 괄호 조합.
- **[Q4] "김씨 성 고객을 찾아 주세요"** — LIKE '김%'.
- **[Q5] "3분기(7~9월) 취소 주문 내역"** — BETWEEN + AND.
- **[Q6] "상사가 없는 직원(조직도 최상단)은 누구?"** — IS NULL. 비교용으로
  `= NULL` 로 잘못 쓴 쿼리도 함께 실행해 **0건이 나오는 함정**을 보여 줍니다.

각 질문에서 "한국어 질문 → WHERE 조건"이 어떻게 대응되는지 밑줄 긋듯
따라가 보세요. 조건을 한 줄씩 읽으며 "이 행은 참인가?"라고 스스로 판정해
보는 것이 최고의 연습입니다.

## 6. 자주 하는 실수

- **`= NULL`**: 영원히 0건입니다. `IS NULL` / `IS NOT NULL` 만 기억하세요.
- **OR 괄호 생략**: `WHERE city='서울' OR city='인천' AND grade='VIP'` 는
  "서울 전체 + 인천 VIP"가 됩니다. 의도가 "서울·인천의 VIP"라면
  `(city='서울' OR city='인천') AND grade='VIP'`.
- **문자열 숫자 비교**: 따옴표를 붙인 `'100' > 20` 같은 비교는 자료형이
  섞여 엉뚱한 결과를 낳습니다. 숫자 열은 따옴표 없이 비교하세요.
- **LIKE 대소문자**: SQLite 의 LIKE 는 영문 대소문자를 구분하지 않지만,
  다른 DB(예: PostgreSQL)는 구분합니다. 회사 DB에서 결과가 다르면 이것부터
  의심하세요.
- **BETWEEN 날짜 끝값**: `BETWEEN '2025-07-01' AND '2025-09-30'` 은 9월
  30일을 포함합니다. 단, 날짜에 시각까지 붙는 DB라면 '9월 30일 00시까지'로
  해석될 수 있으니 실무에선 `< '2025-10-01'` 방식도 함께 알아 두세요.
