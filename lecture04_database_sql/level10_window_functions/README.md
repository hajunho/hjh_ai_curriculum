# Lecture 04 · Level 10 — 윈도우 함수와 분석 쿼리

> 행을 접지 않고 옆에 요약을 붙이는 윈도우 함수를 배웁니다. ROW_NUMBER·RANK 로 순번과 순위를, SUM OVER 로 누적 매출과 이동합계를 만들며 GROUP BY 와의 차이를 몸에 새깁니다.

**난이도** ⭐⭐⭐⭐ / **선행** level05, level06 / **예상 시간** 55분

## 1. 왜 배우나 — 비즈니스 관점

보고서를 만들다 보면 GROUP BY 로는 안 되는 요청을 만납니다. "각 고객의
**몇 번째** 구매인지 표시해 주세요"(첫 구매 분석), "부서 **안에서의** 매출
순위를 매겨 주세요", "월별 매출에 **누적** 달성액을 붙여 주세요", "최근
3개월 **이동합계**로 추세를 보여 주세요". 공통점은 **행은 그대로 두고**
순번·순위·누적 같은 계산 결과를 옆 열에 붙여야 한다는 것. GROUP BY 는
행을 접어 버리므로 불가능합니다. 윈도우 함수(window function)는 바로 이
"접지 않는 집계"이며, 분석가 채용 SQL 테스트의 단골이자, 엑셀에서 수식
복사와 정렬을 반복하던 월말 작업을 한 문장으로 끝내 주는 도구입니다.

## 2. 비유로 이해하기

GROUP BY 는 **바구니에 담아 요약 한 줄만 남기는** 직원이었습니다. 카드
200장이 도시 바구니 6줄로 접혔죠.

윈도우 함수는 다릅니다. 직원이 카드를 **책상 위에 전부 펼쳐 둔 채**, 카드
한 장 한 장 옆에 포스트잇을 붙입니다. 포스트잇에 뭐라고 쓸지는 세 가지로
지시합니다.

- **어느 범위를 보고**(PARTITION BY — "같은 고객의 카드끼리만 보고")
- **어떤 순서로 세어**(ORDER BY — "주문 날짜순으로")
- **무엇을 적을지**(ROW_NUMBER — "몇 번째인지", SUM — "여기까지의 합계")

"창문(window)"이라는 이름은, 각 카드 입장에서 **자기 주변의 일부 카드만
내다보는 창**이 하나씩 있다고 생각하면 됩니다. 같은 고객 카드만 보이는
창, 이번 달까지의 카드만 보이는 창. 창밖을 요약해 내 포스트잇에 적는 것 —
그게 `함수() OVER (창 정의)` 입니다.

## 3. 핵심 개념

### 3-1. 기본 문법 — OVER 가 신호다

```sql
SELECT name, category, price,
       AVG(price) OVER (PARTITION BY category) AS cat_avg
FROM   products;
```

`OVER` 가 붙는 순간 AVG 는 행을 접지 않습니다. 상품 10행이 그대로 나오고,
각 행 옆에 "자기 카테고리의 평균가"가 붙습니다. `price - cat_avg` 로
"카테고리 평균 대비 얼마나 비싼가"를 바로 계산할 수 있습니다 — GROUP BY
결과를 원본에 다시 조인하던 일이 한 절로 끝납니다.

### 3-2. ROW_NUMBER — 순번 매기기

```sql
ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY ordered_at) AS nth
```

고객마다 1부터 다시 시작하는 구매 순번. `WHERE nth = 1` (서브쿼리나 CTE 로
감싸서)로 "각 고객의 첫 주문"만 뽑는 것이 실무 최빈 패턴입니다.
"그룹마다 최신/최초/최대 1건" = ROW_NUMBER + 필터, 공식처럼 외워 두세요.

### 3-3. RANK / DENSE_RANK — 순위와 동점 처리

셋 다 순서를 매기지만 동점 처리에 차이가 있습니다.

| 값 | ROW_NUMBER | RANK | DENSE_RANK |
|---|---|---|---|
| 100 | 1 | 1 | 1 |
| 90 | 2 | 2 | 2 |
| 90 | 3 | 2 | 2 |
| 80 | 4 | **4** | **3** |

ROW_NUMBER 는 동점도 줄 세우고(순서는 임의), RANK 는 공동 2위 후 4위로
건너뛰고, DENSE_RANK 는 3위로 이어집니다. 시상식은 RANK, "상위 3개
등급"은 DENSE_RANK, "무조건 한 줄씩"은 ROW_NUMBER 입니다.

### 3-4. 누적 합계 — ORDER BY 가 있는 SUM OVER

```sql
SUM(revenue) OVER (ORDER BY month) AS cum_revenue
```

ORDER BY 가 창의 범위를 "처음부터 현재 행까지"로 만듭니다. 월별 매출 옆에
연초부터의 누적 매출이 붙습니다. PARTITION BY 를 더하면 "부서별로 각자
누적"처럼 그룹 안 누적도 됩니다.

### 3-5. 이동합계/이동평균 — ROWS BETWEEN

```sql
SUM(revenue) OVER (ORDER BY month
                   ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS mov3
```

"직전 2행 + 현재 행" — 최근 3개월 이동합계입니다. 월별 들쭉날쭉한 수치의
추세를 부드럽게 보여 주는 보고서 단골 기법으로, 창의 크기를 직접 지정하는
문법입니다.

### 3-6. 실행 순서 주의

윈도우 함수는 WHERE·GROUP BY 가 끝난 **뒤에** 계산됩니다. 그래서 윈도우
결과(nth, rank…)를 WHERE 에 바로 쓸 수 없고, CTE 나 서브쿼리로 감싼 뒤
바깥에서 필터링합니다. main.py 의 [2]가 이 패턴입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1] GROUP BY vs 윈도우**: 같은 "카테고리 평균가"를 두 방식으로 —
  6→10행 차이(접힘 vs 유지)를 나란히 확인합니다.
- **[2] 고객별 구매 순번**: ROW_NUMBER 로 순번을 붙이고, CTE 로 감싸
  "각 고객의 첫 주문"만 뽑습니다.
- **[3] 동점 처리 3형제**: 상품 가격(동점이 있는 데이터)에
  ROW_NUMBER/RANK/DENSE_RANK 를 나란히 붙여 3-3절의 표를 실데이터로
  재현합니다.
- **[4] 부서별 매출 순위**: 직원별 처리 매출을 구한 뒤(CTE), 부서 안에서
  RANK — "지점별 순위" 류 보고서의 골격입니다.
- **[5] 월별 매출 + 누적 매출**: SUM OVER (ORDER BY month).
- **[6] 3개월 이동합계**: ROWS BETWEEN 2 PRECEDING AND CURRENT ROW.

출력마다 "행이 접혔는가, 유지됐는가"를 확인하는 것이 핵심 관전 포인트입니다.

## 6. 자주 하는 실수

- **윈도우 결과를 WHERE 에 직접 쓰기**: `WHERE ROW_NUMBER() ...` 는
  에러입니다. CTE 로 감싸고 바깥에서 필터 — 항상 이 2단 구조입니다.
- **PARTITION BY 와 GROUP BY 혼동**: PARTITION BY 는 접지 않습니다.
  "행 수가 줄면 GROUP BY, 유지되면 윈도우"로 구분하세요.
- **ORDER BY 빠진 누적 합계**: OVER () 에 ORDER BY 가 없으면 창이 전체가
  되어 모든 행에 총합이 붙습니다. 누적이 이상하면 ORDER BY 부터 확인.
- **동점자 있는 ROW_NUMBER 재현성**: 동점일 때 누가 1번인지는 실행마다
  다를 수 있습니다. ORDER BY 에 고유 키를 추가해(`ORDER BY 금액 DESC,
  주문번호`) 순서를 못박는 것이 보고서의 예의입니다.
- **오래된 DB 버전**: 윈도우 함수는 SQLite 3.25(2018) 이후 지원입니다.
  회사의 아주 오래된 DB에서는 문법 에러가 날 수 있습니다.
