# Lecture 04 · Level 07 — 서브쿼리와 CTE

> 쿼리의 결과를 다른 쿼리의 재료로 쓰는 서브쿼리(스칼라·IN·상관)를 배우고, WITH(CTE)로 복잡한 쿼리를 읽기 좋은 단계별 문장으로 정리합니다.

**난이도** ⭐⭐⭐ / **선행** level06 / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

실무 질문에는 "기준 자체를 데이터에서 구해야 하는" 것들이 많습니다.
"**평균보다** 비싼 상품은?" — 평균이 얼마인지 먼저 구해야 합니다.
"**노트북을 산** 고객 명단은?" — 노트북 구매 주문 목록이 먼저 필요합니다.
"**자기 부서 평균보다** 급여가 높은 직원은?" — 행마다 기준이 다릅니다.
이런 2단계 질문을 한 문장으로 표현하는 도구가 서브쿼리(subquery)입니다.
그리고 분석이 3~4단계로 길어지면, 각 단계에 이름을 붙여 위에서 아래로
읽히게 만드는 CTE(Common Table Expression, WITH 절)가 협업 필수품이
됩니다. 남이 읽을 수 있는 쿼리를 쓰는 사람과 아닌 사람의 차이가 여기서
갈립니다.

## 2. 비유로 이해하기

창구 직원에게 "평균보다 비싼 상품 목록 주세요"라고 하면, 직원은 **쪽지를
두 장** 씁니다. 첫 쪽지: "상품 가격 평균 구하기" → 답 290,850원. 둘째
쪽지: "가격이 290,850원 넘는 상품 찾기". 첫 쪽지의 **답을 둘째 쪽지의
빈칸에 끼워 넣는** 것 — 이것이 서브쿼리입니다. SQL 에서는 괄호가 쪽지의
경계입니다: `WHERE price > (SELECT AVG(price) FROM products)`.

쪽지의 답 모양에 따라 쓰임이 다릅니다.

- 답이 **숫자 하나**(평균값) → 비교 연산에 끼움 = **스칼라 서브쿼리**
- 답이 **목록**(주문번호들) → IN 에 끼움 = **IN 서브쿼리**
- 바깥 행을 **하나 읽을 때마다 쪽지를 새로 씀**(그 직원의 부서 평균) =
  **상관 서브쿼리**

CTE 는 쪽지에 **이름표를 붙여 책상에 펼쳐 두는 것**입니다. "이 쪽지는
'고객별구매액'이라고 부르자" — 다음 단계에서 테이블처럼 갖다 씁니다.
괄호 속에 괄호가 겹치는 대신, 요리 레시피처럼 1단계·2단계로 읽힙니다.

## 3. 핵심 개념

### 3-1. 스칼라 서브쿼리 — 답이 값 하나

```sql
SELECT name, price
FROM   products
WHERE  price > (SELECT AVG(price) FROM products);
```

괄호 안이 먼저 실행되어 값 하나로 바뀐 뒤, 바깥 쿼리가 실행된다고 읽으면
됩니다. SELECT 목록 안에 넣어 "전체 평균" 열을 나란히 보여 줄 수도 있습니다.

### 3-2. IN 서브쿼리 — 답이 목록

```sql
SELECT name FROM customers
WHERE  customer_id IN (SELECT customer_id
                       FROM orders
                       WHERE status = '취소');
```

"취소 주문을 낸 적 있는 고객". 괄호 안의 결과(고객번호 목록)가 IN 의
목록 자리에 들어갑니다. 반대(`NOT IN`)를 쓸 때는 목록에 NULL 이 섞이면
전체가 0건이 되는 유명한 함정이 있으니, NOT IN 서브쿼리에는
`WHERE ... IS NOT NULL` 을 함께 쓰는 습관을 들이세요.

### 3-3. 상관 서브쿼리 — 행마다 다시 묻기

```sql
SELECT e.name, e.dept, e.salary
FROM   employees AS e
WHERE  e.salary > (SELECT AVG(e2.salary)
                   FROM   employees AS e2
                   WHERE  e2.dept = e.dept);   -- 바깥 행의 부서를 참조!
```

안쪽 쿼리가 바깥 행의 값(`e.dept`)을 참조하므로, **바깥 행마다** 안쪽이
다시 실행됩니다. "자기 부서 평균보다 높은 급여"처럼 행마다 기준이 다른
질문의 표준 해법입니다. 행 수가 아주 많으면 느려질 수 있다는 점은 level09
에서 다룹니다.

### 3-4. CTE (WITH 절) — 단계에 이름 붙이기

```sql
WITH customer_totals AS (        -- 1단계: 고객별 구매액
    SELECT o.customer_id, SUM(oi.quantity * p.price) AS total
    FROM   orders o
    JOIN   order_items oi ON oi.order_id = o.order_id
    JOIN   products p     ON p.product_id = oi.product_id
    GROUP BY o.customer_id
)
SELECT c.name, t.total            -- 2단계: 평균 이상만 고르기
FROM   customer_totals t
JOIN   customers c ON c.customer_id = t.customer_id
WHERE  t.total > (SELECT AVG(total) FROM customer_totals);
```

같은 중간 결과(customer_totals)를 두 번 재사용하면서도 위에서 아래로
읽힌다는 것이 핵심입니다. WITH 안에 쿼리를 쉼표로 이어 여러 단계를 둘
수도 있습니다. **"서브쿼리가 두 번 이상 쓰이거나 괄호가 두 겹이 되면
CTE 로 승격"** — 실무에서 통하는 좋은 기준입니다.

### 3-5. FROM 절 서브쿼리

괄호 친 쿼리를 FROM 자리에 놓고 별칭을 붙이면 임시 테이블처럼 쓸 수
있습니다(파생 테이블). CTE 와 기능이 겹치는데, 읽기는 CTE 쪽이 거의 항상
좋습니다. 남의 쿼리에서 만나면 "이름 없는 CTE구나"라고 해석하면 됩니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1] 스칼라**: 평균보다 비싼 상품 — 기준값을 먼저 보여 준 뒤(쪽지 1),
  그것이 끼워진 본 쿼리(쪽지 2)를 실행해 두 단계를 눈으로 잇습니다.
- **[2] IN**: '노트북'을 산 적 있는 고객 명단 — order_items → orders →
  customers 로 이어지는 2중 IN 서브쿼리.
- **[3] 상관**: 자기 부서 평균보다 급여가 높은 직원 — 부서 평균 표를 먼저
  보여 주고, 상관 서브쿼리 결과와 대조합니다.
- **[4] CTE**: "평균 이상 구매 고객" — customer_totals 라는 1단계에 이름을
  붙이고, 2단계에서 평균과 비교. 같은 CTE 가 두 번 재사용되는 것에
  주목하세요.
- **[5] CTE 여러 단계**: 월별 매출 → 그중 최고 매출 달 찾기를 WITH 두
  단계로 — 리포트 쿼리의 전형적 골격입니다.

## 6. 자주 하는 실수

- **스칼라 자리에 여러 행 반환**: `price > (SELECT price FROM ...)` 의
  괄호가 여러 행을 돌려주면 에러이거나(다른 DB), 첫 행만 조용히 쓰입니다
  (SQLite). 스칼라 자리에는 집계나 LIMIT 1 로 "한 값"을 보장하세요.
- **NOT IN + NULL**: 목록에 NULL 이 하나라도 있으면 결과가 통째로
  0건입니다. NOT IN 서브쿼리엔 IS NOT NULL 필터를.
- **상관 서브쿼리 별칭 생략**: 안팎이 같은 테이블이면 별칭(e, e2)이
  없을 때 어느 쪽 열인지 뒤엉킵니다. 상관 서브쿼리는 별칭 필수.
- **괄호 3겹 중첩**: 읽을 수 있는 사람이 본인뿐이 됩니다. 두 겹부터 CTE 로.
- **CTE 를 성능 도구로 오해**: CTE 는 기본적으로 '읽기 좋게 이름 붙이기'
  입니다. 빨라지는 것은 아닙니다(속도는 level09 의 주제).
