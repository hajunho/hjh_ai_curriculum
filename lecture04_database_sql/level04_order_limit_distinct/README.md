# Lecture 04 · Level 04 — 정렬·중복 제거·상위 N

> ORDER BY 로 결과를 줄 세우고, LIMIT 로 상위 N개만 끊고, DISTINCT 로 중복을 걷어냅니다. "최고가 상품 톱5" 같은 랭킹 표를 SQL 한 문장으로 만듭니다.

**난이도** ⭐⭐ / **선행** level03 / **예상 시간** 35분

## 1. 왜 배우나 — 비즈니스 관점

보고서의 표는 대부분 **줄 세운 표**입니다. "매출 상위 10개 지점", "최근
주문 20건", "가장 싼 견적 3개". 그리고 회의에서 자주 나오는 질문 —
"우리 고객들이 어느 도시에 있죠?" — 는 사실 **중복을 제거한 목록**을 묻는
것입니다. ORDER BY(정렬), LIMIT(상위 N), DISTINCT(중복 제거) 세 도구만
있으면 이런 요청의 대부분이 한 문장으로 끝납니다. 특히 "톱 N" 패턴은
현업 SQL 에서 체감상 가장 자주 쓰는 형태 중 하나이니 손에 완전히 붙여
두는 것이 좋습니다.

## 2. 비유로 이해하기

창구 직원의 작업 순서를 상상해 보세요. 요청서에 적힌 대로 장부에서
조건에 맞는 행을 골라 바구니에 담은 뒤(FROM + WHERE), 마지막에 세 가지
마무리 손질을 합니다.

- **ORDER BY = 줄 세우기**: 바구니 속 행들을 요청한 기준(가격순, 날짜순…)
  으로 정렬해 쟁반에 올립니다. 동점자가 있으면 두 번째 기준으로 다시
  줄 세웁니다 — 운동회에서 "키 순으로, 키가 같으면 이름 가나다순"과
  같습니다.
- **LIMIT = 위에서 몇 장만 끊기**: 줄 세운 쟁반에서 위에서부터 N장만
  건네줍니다. 정렬 없이 끊으면 "그냥 아무 5장"이 되므로, **톱 N 은 반드시
  ORDER BY 와 세트**입니다.
- **DISTINCT = 겹치는 카드 버리기**: 같은 내용의 카드가 여러 장이면 한
  장만 남깁니다. "고객들이 사는 도시 목록"처럼 **종류**를 물을 때
  씁니다.

중요한 점: 이 손질은 전부 **결과 바구니에 대한 작업**입니다. 원본 장부는
전혀 바뀌지 않습니다.

## 3. 핵심 개념

### 3-1. ORDER BY — 오름차순과 내림차순

```sql
SELECT name, price
FROM   products
ORDER BY price DESC;   -- 비싼 것부터 (DESC = descending, 내림차순)
```

기본은 오름차순(ASC, 생략 가능)입니다. 날짜 열을 DESC 로 정렬하면 "최신순"이
됩니다. 문자 열은 사전순(한글은 가나다순)으로 정렬됩니다.

### 3-2. 다중 정렬 기준

```sql
ORDER BY city ASC, grade DESC
```

먼저 도시 가나다순으로, 같은 도시 안에서는 등급 역순으로. 쉼표 순서가
우선순위입니다. 별칭이나 계산식도 기준이 될 수 있습니다:
`ORDER BY price - cost DESC` (마진 큰 순).

### 3-3. LIMIT 와 OFFSET

`LIMIT 5` 는 앞 5행만, `LIMIT 5 OFFSET 5` 는 6~10번째 행을 가져옵니다.
웹사이트의 "2페이지"가 바로 OFFSET 입니다. 주의: **LIMIT 는 계산을 줄여 주는
것이 아니라 보여 주는 양을 줄이는 것**입니다. 정렬은 전체에 대해 일어난 뒤
윗부분만 잘립니다.

### 3-4. DISTINCT — 종류를 묻는 질문

```sql
SELECT DISTINCT city FROM customers;
```

200명의 고객 행에서 도시 값만 뽑으면 중복투성이지만, DISTINCT 가 같은 값을
한 번씩만 남깁니다. 열을 두 개 쓰면 `(city, grade)` **조합**의 중복을
제거합니다 — "도시별로 존재하는 등급 조합"처럼요. "몇 종류인가?"까지 세는
`COUNT(DISTINCT city)` 는 다음 레벨(집계)에서 만납니다.

### 3-5. 문장 안에서의 위치 (어순 규칙)

SQL 절은 순서가 정해져 있습니다.

```
SELECT [DISTINCT] 열목록
FROM   테이블
WHERE  조건
ORDER BY 기준
LIMIT  N;
```

실행 순서는 FROM → WHERE → SELECT → ORDER BY → LIMIT. "골라내고(WHERE),
열을 다듬고(SELECT), 줄 세우고(ORDER BY), 끊는다(LIMIT)"로 기억하세요.

- **[1] 최고가 상품 톱5**: `ORDER BY price DESC LIMIT 5` — 랭킹 표의 기본형.
- **[2] 마진 큰 상품 톱3**: 계산식 `price - cost` 를 정렬 기준으로 사용.

## 6. 자주 하는 실수

- **ORDER BY 없는 '톱 N'**: LIMIT 만 쓰면 DB가 편한 순서(사실상 무작위)로
  N개를 줄 뿐입니다. 톱 N = ORDER BY + LIMIT 세트, 예외 없음.
- **DESC 를 빼먹은 랭킹**: "매출 톱5"를 뽑았는데 꼴찌 5개가 나왔다면 십중팔구
  DESC 누락입니다. 기본값이 오름차순이라는 걸 기억하세요.
- **DISTINCT 를 아무 데나 붙이는 것**: DISTINCT 는 SELECT 바로 뒤에 한 번만
  쓰며, **선택한 열 조합 전체**에 적용됩니다. `SELECT DISTINCT city, name` 은
  "도시만 중복 제거"가 아니라 "(도시, 이름) 조합의 중복 제거"입니다.
- **숫자처럼 보이는 문자 정렬**: 가격이 TEXT 로 저장돼 있으면 '9' > '1200000'
  같은 사전순 정렬이 일어납니다. 정렬이 이상하면 자료형부터 확인하세요.
- **절 순서 뒤섞기**: `LIMIT 5 ORDER BY price` 처럼 순서를 바꾸면 문법
  에러입니다. WHERE → ORDER BY → LIMIT 순서를 지키세요.
