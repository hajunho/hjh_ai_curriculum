# Lecture 04 · Level 02 — SELECT 기초

> SQL 의 첫 문장이자 전부의 시작인 SELECT 를 배웁니다. 원하는 테이블에서 원하는 열만 골라 보고, 열 이름에 별칭을 붙이고, 계산된 열을 만들어 봅니다.

**난이도** ⭐ / **선행** level01 / **예상 시간** 35분

## 1. 왜 배우나 — 비즈니스 관점

실무에서 SQL 사용의 90% 이상은 **조회**입니다. 데이터를 바꾸는 일은 시스템이
하고, 사람은 주로 "보여 줘"라고 묻습니다. 그 "보여 줘"가 바로
SELECT(셀렉트)입니다. SELECT 한 문장만 자유로워져도 "고객 명단 뽑아
주세요"라고 다른 팀에 요청하고 이틀 기다리던 일이, 30초짜리 셀프서비스가
됩니다. 게다가 SELECT 는 데이터를 읽기만 할 뿐 절대 바꾸지 않으므로, 초보가
마음껏 연습해도 사고가 나지 않는 안전한 문장입니다.

## 2. 비유로 이해하기

SELECT 문장은 **창구 직원에게 건네는 요청서 양식**입니다. 문구점 장부
비유를 이어가면, 요청서에는 두 칸이 있습니다.

> **어느 장부에서** (FROM customers — 고객 명부에서)
> **어떤 항목을** (SELECT name, city — 이름과 도시 항목만)

읽는 순서가 우리말과 반대라는 점만 주의하세요. SQL 은 "SELECT 이름, 도시
FROM 고객명부"라고 쓰지만, 창구 직원은 "고객명부에서(FROM) → 이름과 도시를
(SELECT)" 순서로 처리합니다. SQL 을 읽을 때 **FROM 부터 찾아 읽는 습관**을
들이면 긴 쿼리도 무섭지 않습니다.

별칭(alias)은 요청서의 "보고서에는 이 이름으로 적어 주세요" 칸입니다.
`price AS 판매가` 라고 쓰면 결과 표의 열 제목이 판매가로 바뀝니다. 데이터
자체는 그대로 두고 **보이는 이름만** 바꾸는 것입니다.

## 3. 핵심 개념

### 3-1. 기본 형태

```sql
SELECT 열1, 열2      -- 무엇을 (열 목록)
FROM   테이블;        -- 어디서
```

- 대소문자는 구분하지 않지만, 관례상 예약어(SELECT, FROM…)는 대문자,
  테이블·열 이름은 소문자로 씁니다. 눈에 잘 띄기 때문입니다.
- 문장 끝의 세미콜론(;)은 "요청서 끝"이라는 표시입니다.
- `--` 뒤는 주석으로, 실행되지 않습니다.

### 3-2. 모든 열: `SELECT *`

`*` 는 "전부"라는 뜻입니다. 테이블을 처음 살펴볼 때는 편리하지만, 실무
쿼리에서는 필요한 열만 명시하는 것이 좋습니다. 열이 수십 개인 테이블에서
`*` 는 화면 낭비이자, 나중에 열이 추가되면 결과 모양이 바뀌는 원인이 됩니다.
"일단 * 로 훑고, 진짜 쿼리는 열 이름으로" — 이것이 실무 리듬입니다.

### 3-3. 별칭 (AS)

```sql
SELECT name AS 상품명, price AS 판매가
FROM   products;
```

AS 는 생략할 수도 있지만(`price 판매가`), 초보 때는 명시하는 편이 읽기
좋습니다. 별칭은 결과 표의 열 제목만 바꿀 뿐, 테이블의 실제 열 이름은
바뀌지 않습니다.

### 3-4. 계산된 열 (expression)

SELECT 목록에는 열 이름뿐 아니라 **계산식**도 쓸 수 있습니다.

```sql
SELECT name,
       price,
       cost,
       price - cost AS 마진
FROM   products;
```

행마다 `price - cost` 가 계산되어 새 열처럼 나타납니다. 엑셀에서 D열에
`=B2-C2` 수식을 채워 넣는 것과 같지만, 수식을 복사해 붙일 필요 없이 문장
하나로 모든 행에 적용됩니다. 문자열을 이어 붙이는 `||` 연산자, 반올림
`ROUND()` 같은 함수도 같은 자리에 씁니다.

### 3-5. 미리 만나는 LIMIT

결과가 수백 행이면 화면이 넘어가므로, 이 레벨부터 `LIMIT 5` (앞 5행만)를
붙여 출력을 줄입니다. 정식 설명은 level04 에서 하니, 지금은 "미리보기
장치"라고만 알아 두세요.

### 3-6. SELECT 는 원본을 바꾸지 않는다

SELECT 의 결과는 원본 테이블의 **사본 화면**입니다. 별칭을 붙이든 계산 열을
만들든 hjh_shop.db 안의 데이터는 1바이트도 변하지 않습니다. 그래서 조회
연습은 아무리 실수해도 안전합니다. 데이터를 실제로 바꾸는 문장(INSERT,
UPDATE, DELETE)은 level08 에서 트랜잭션과 함께 조심스럽게 배웁니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

main.py 는 매번 `hjh_shop.db` 를 새로 만든 뒤, SQL 문장을 먼저 print 로
보여 주고 바로 아래에 실행 결과 표를 출력합니다. **SQL> 로 시작하는 줄이
주인공**이고, 파이썬 코드는 그 문장을 전달하는 실행기일 뿐입니다.

- **[1] 전체 열 훑어보기**: `SELECT * FROM customers LIMIT 5` — 테이블
  첫인사. 열 구성과 데이터 생김새를 확인합니다.
- **[2] 필요한 열만**: `SELECT name, city FROM customers LIMIT 5` — 요청서에
  항목을 명시하는 기본형.
- **[3] 별칭 붙이기**: products 를 `상품명/카테고리/판매가` 라는 한글 제목의
  보고서형 표로 출력합니다.
- **[4] 계산된 열**: `price - cost AS 마진`, 그리고
  `ROUND(100.0*(price-cost)/price, 1) AS 마진율` 로 행마다 계산.
- **[5] 문자열 조합**: `name || ' (' || grade || ')'` 로 "김민준 (VIP)" 형태의
  표시용 열을 만듭니다. 메일 머지 등 실무에서 자주 쓰는 패턴입니다.

각 단계에서 SQL 문장을 읽을 때 FROM 을 먼저 찾고 → SELECT 목록을 읽는
연습을 해 보세요. 출력 표의 열 제목이 별칭 그대로 바뀌는 것도 확인하세요.

## 6. 자주 하는 실수

- **문자열에 큰따옴표 사용**: SQL 에서 글자 데이터는 작은따옴표(`'서울'`)로
  감쌉니다. 큰따옴표는 열·테이블 이름용이라, 섞어 쓰면 헷갈리는 에러가 납니다.
- **열 이름 오타**: `SELECT nmae` 처럼 오타가 나면 "no such column" 에러가
  납니다. 에러 문구에 힌트가 다 있으니 겁먹지 말고 읽어 보세요.
- **SELECT 뒤 쉼표 빠뜨림/남김**: `SELECT name city` 는 에러가 아니라 city 가
  name 의 **별칭**으로 해석되어 엉뚱한 결과가 나옵니다. 쉼표를 꼭 확인하세요.
- **`SELECT *` 를 정식 쿼리에 쓰는 것**: 훑어볼 때만 쓰고, 저장해 두고 다시
  쓸 쿼리에는 열 이름을 명시하세요.
