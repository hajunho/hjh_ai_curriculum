## 1. 목표

IT 비전공 비즈니스 직장인을 "AI 를 이해하고 직접 다루는 사람"으로 만드는
실습 중심 커리큘럼을 새로 만들고, 공개 저장소로 배포한다.

요구사항은 네 가지였습니다.

1. 비전공 직장인 대상 — 머신러닝·딥러닝까지 도달하는 완주 코스
2. **라이선스 문제 원천 제거** — 모든 코드와 글을 새로 창작
3. `lecture1, 2, 3...` 폴더 구조, 각 강의는 기초(level0)부터 심화(level11)까지
4. GitHub 공개 저장소로 업로드

## 2. 설계 결정

### 2-1. 12 강의 × 12 레벨 = 144 유닛

"컴퓨터란 무엇인가"에서 시작해 "LLM 을 직접 학습시키고 배포하기"로 끝나는
단일 상승 곡선으로 배치했습니다. 각 강의 안에서도 level00 은 비유와 개념,
level11 은 실무 심화가 되도록 난이도를 12단으로 쪼갰습니다.

| 강의 | 주제 |
|---|---|
| lecture01 | 컴퓨터와 개발 환경 |
| lecture02 | 파이썬 프로그래밍 기초 |
| lecture03 | 데이터 다루기 (NumPy · Pandas) |
| lecture04 | 데이터베이스와 SQL |
| lecture05 | 통계와 데이터 시각화 |
| lecture06 | 머신러닝 입문 |
| lecture07 | 비즈니스 머신러닝 실전 |
| lecture08 | 딥러닝 기초 |

| lecture10 | 자연어처리 |

각 레벨은 강의 노트(`README.md`)와 실행 가능한 실습 코드(`main.py`) 한 쌍입니다.

### 2-2. 라이선스 청결성 — 데이터를 코드로 만든다

외부 데이터셋을 쓰지 않는 것이 이 커리큘럼의 핵심 설계입니다.
`common/hjh_data.py` 한 모듈이 실습에 필요한 모든 데이터를 직접 생성합니다.

- 카페 체인 일별 매출 (결측·음수 오염을 일부러 심어 정제 실습용)
- 구독 서비스 고객 이탈 (로그오즈를 직접 설계해 "정답이 있는" 데이터)
- 카드 이상거래 (사기 비율 약 1.5% 의 심한 불균형)
- 한국어 리뷰 감성 코퍼스, 사내규정·제품매뉴얼 문서 5종
- 미니 언어모델 학습용 한국어 코퍼스
- 도형 분류용 흑백 이미지 (MNIST 대체)
- SQL 실습용 SQLite 쇼핑몰 DB (5개 테이블)

모든 생성기가 seed 고정이라 강의 노트에 적힌 숫자와 실행 결과가 항상 일치합니다.
덕분에 **다운로드 없음 · 인터넷 없음 · API 키 없음 · GPU 없음**으로 전 과정이 돌아갑니다.

### 2-3. 밑바닥 구현 원칙

블랙박스를 열어 보는 것이 이 커리큘럼의 교육 철학입니다. 편의 패키지를 쓰지 않고
직접 만든 것들:

- 퍼셉트론과 역전파 (numpy, 수치미분으로 그래디언트 검증)
- 합성곱 연산, 슬라이딩 윈도우 객체 탐지, NMS
- TF-IDF (sklearn 결과와 1e-16 수준까지 일치 확인)
- 동시출현 + PPMI + SVD 워드 임베딩
- scaled dot-product attention, 멀티헤드, 포지셔널 인코딩
- BPE 토크나이저, uint16 패킹 파이프라인
- 미니 GPT 사전학습, LoRA 어댑터, SFT loss 마스킹, DPO loss
- int8/int4 양자화, BM25, MMR, 미니 벡터스토어, ReAct 에이전트 루프

`konlpy`, `transformers`, `langchain`, `chromadb`, `xgboost` 등은 개념만 설명하고
구현은 전부 직접 했습니다. lecture11 은 API 키 없이도 돌아가도록 규칙 기반
`mock_llm.py`(MockLLM + MockEmbedding)를 만들어 썼습니다.

## 3. 작업 방식

강의 12개를 12개의 병렬 에이전트에 나눠 맡겼습니다. 품질 편차를 막기 위해
공통 저작 스펙을 먼저 고정했습니다: 강의 노트의 섹션 구조(왜 배우나 → 비유 →
핵심 개념 → 실습 → 직접 해보기 → 자주 하는 실수), 존댓말 강의체, 한국어 주석과
영어 식별자, seed 고정, 그림은 `Agg` 백엔드로 `outputs/` 에 저장, 레벨당 실행
90초 이내.

각 담당자는 작성 후 저장소 전용 venv 로 자기 담당 코드를 실제 실행해 검증했고,
마지막에 제가 144개를 한 번 더 전량 실행했습니다.

## 5. 다국어 작업 현황 (진행 중 · 미완)

전 세계 언어로 확장하는 작업을 시작했습니다. 방식은 언어별 최상위 폴더
(`en/`, `ja/`, `zh/`, …)에 **완전 독립 버전**을 만드는 것입니다. 강의 노트뿐
아니라 코드의 주석·출력 메시지까지 현지화하고, 폴더·파일 이름은 원본과 동일하게
유지합니다.

### 핵심 기법: RNG 정렬

각 언어의 `<lang>/common/hjh_data.py` 는 지점명·카테고리·요일·리뷰·문서 등을
현지화하되 **모든 리스트의 길이를 원본과 똑같이** 유지합니다. 난수 호출 순서와
횟수가 보존되므로 숫자 결과가 원본과 바이트 단위로 일치하고, 강의 노트의 수치를
언어마다 다시 계산할 필요가 없습니다. 영어판은 이 일치를 프로그램으로 검증했습니다.

언어 특성상 결과가 달라지는 강의(NLP, LLM, LLM 엔지니어링)는 예외입니다.
코퍼스가 바뀌면 TF-IDF 값, 분류 정확도, 학습 loss, 생성 문장이 달라지므로,
실제 실행 결과를 정답으로 삼아 강의 노트를 고쳐 쓰도록 했습니다.

### 언어별 적응

단순 번역이 아니라 교육 내용 자체를 조정했습니다.

- 일본어·중국어는 띄어쓰기가 없어, 한국어의 형태소·조사 수업을
  일본어 형태소 분석 / 중국어 분사(分词) 수업으로 재구성하고 한국어를 대조
  사례로 남겼습니다. 바이트 단위 BPE 를 가르치기에 오히려 더 좋은 소재입니다.
- SQL 강의는 쿼리 안의 문자열 리터럴(도시명, 주문 상태, 성씨 LIKE 패턴)을
  현지화된 DB 값에 맞춰야 결과가 나옵니다. 언어별로 전부 다시 맞췄습니다.
- CJK 언어는 폰트 깨짐을 막기 위해 그림 내부 라벨은 영어로, 터미널 출력은
  해당 언어로 분리했습니다.
- 통화는 원화(KRW) 숫자를 그대로 두고 표기만 현지화했습니다.

### 중단 시점 상태

세션 종료 시점의 진행률입니다. 완성된 강의는 해당 언어로 12레벨 전부 실행
검증까지 끝난 것입니다.

| 언어 | 기반(데이터 생성기 + 루트 문서 4종) | 완성 강의 | 비고 |
|---|---|---|---|
| 영어 (en) | 완료 | 11 / 12 | lecture11 이 11레벨까지 |
| 일본어 (ja) | 완료 | 6 / 12 | lecture03·08·10 거의 완성 |
| 중국어 (zh) | 완료 | 2 / 12 | 여러 강의 부분 진행 |
| 스페인어 (es) | 미착수 | — | 계획됨 |

계획했던 순서: en → ja → zh → es → fr → de → pt → ru → id → vi

### 이어서 작업하는 방법

1. `<lang>/CURRICULUM.md` 에 그 언어의 확정된 144개 레벨 제목이 있습니다.
   `<lang>/common/hjh_data.py` 에는 그 언어의 확정된 현지화 값(지점명·카테고리 등)이
   있습니다. 새 강의를 번역할 때 이 두 파일이 기준입니다.
2. 강의 단위로 나눠 진행하고(예: 1–3, 4–6, 7–9, 10–12), `lecture11` 에는
   `mock_llm.py` 포팅이, `lecture02/level08` 에는 `utils.py` 가 포함됩니다.
3. 번역 후 반드시 저장소 venv 로 해당 강의의 12개 `main.py` 를 실행해 exit 0 을
   확인하고, 실제 출력과 다른 강의 노트의 숫자를 실측값으로 고칩니다.
4. 한 언어가 전부 끝나면 그 언어만 담은 커밋 하나를 만들어 push 합니다.

중단된 작업이 파일을 쓰다 만 강의가 있을 수 있으므로, 재개할 때 부분 완성
강의는 파일이 잘리지 않았는지 먼저 확인하는 것이 안전합니다.
