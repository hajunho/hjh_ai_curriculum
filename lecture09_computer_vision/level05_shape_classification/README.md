# Lecture 09 · Level 05 — 도형 이미지 분류 실습

> 데이터 분할부터 학습·평가·오분류 분석까지, 이미지 분류 프로젝트의 표준 사이클을 CNN 으로 완주합니다.
**난이도** ⭐⭐⭐ / **선행** level03~04, lecture08 level08 (학습 루프) / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

이번 레벨은 이 강의의 첫 번째 "완주"입니다. 지금까지 부품(합성곱·풀링·Linear)을 하나씩 익혔다면, 오늘은 실제 프로젝트와 같은 순서로 전부 조립합니다: **데이터 분할 → 모델 정의 → 학습 → 검증 → 테스트 → 오분류 분석**.

이 사이클을 한 번 스스로 돌려 본 사람과 아닌 사람은, 외부 업체의 "정확도 96.7%입니다"라는 보고를 듣는 태도가 다릅니다. 전자는 곧바로 묻습니다 — "어떤 데이터로 잰 숫자인가요? 학습에 쓴 데이터는 아니죠? 틀린 3.3%는 어떤 사례들인가요?" 이 세 가지 질문이 비전 프로젝트 검수의 핵심이고, 오늘 실습이 그 질문의 근거를 만들어 줍니다.

덤으로 오래된 논쟁 하나를 실험으로 끝냅니다: "이미지에 왜 굳이 CNN 인가? 그냥 신경망(MLP)에 픽셀을 다 넣으면 안 되나?" — 같은 데이터, 같은 학습 설정으로 둘을 겨루게 해서 숫자로 답합니다.

## 2. 비유로 이해하기

**신입 검수원 교육 과정**으로 전체 사이클을 읽어 봅시다.

- **데이터 분할**: 교육용 문제집(학습 600장), 모의고사(검증 150장), 그리고 봉인된 본고사(테스트 150장)를 미리 나눠 둡니다. 본고사 문제를 교육에 쓰면 성적이 거짓말이 됩니다 — lecture06 level04 에서 배운 그 원칙이 이미지에서도 그대로입니다.
- **학습 루프**: 문제집을 여러 바퀴(에폭) 풀립니다. 한 바퀴마다 모의고사 점수를 기록해 실력이 느는지 지켜봅니다.
- **평가**: 마지막에 단 한 번, 봉인을 뜯고 본고사를 치릅니다.
- **오분류 분석**: 점수만 보고 끝내지 않고, **틀린 문제를 펼쳐 놓고 왜 틀렸는지** 봅니다. 검수원이 유독 헷갈려 하는 유형(잡음이 심한 이미지? 가장자리에 걸린 도형?)이 보이면, 다음 교육(데이터 보강)의 방향이 나옵니다.

## 3. 핵심 개념

### 3.1 오늘의 모델 — ShapeCNN

```
입력 (1,16,16)
Conv(1→8, 3x3, pad1) + ReLU + MaxPool2 → (8,8,8)
Conv(8→16, 3x3, pad1) + ReLU + MaxPool2 → (16,4,4)
Flatten → Linear(256→3)
```

level03 의 설계 리듬(채널↑, 공간↓) 그대로, 총 파라미터 약 2,000개짜리 초소형 CNN 입니다. 과제가 작으면 모델도 작게 — 필요 이상 큰 모델은 비용이고 과적합 위험입니다.

### 3.2 학습의 4요소 (lecture08 복습을 이미지에 적용)

- **손실 함수**: 다중 분류의 표준, 교차 엔트로피(CrossEntropyLoss). "정답 클래스에 준 확률이 낮을수록 벌점".
- **옵티마이저**: Adam. 벌점이 줄어드는 방향으로 커널 숫자들을 조금씩 수정.
- **미니배치**: 600장을 64장씩 나눠 처리. 메모리 절약 + 학습 안정.
- **에폭**: 전체 데이터를 몇 바퀴 돌지. 오늘은 18바퀴 — 검증 정확도 곡선을 보고 정한 값입니다.

### 3.3 혼동 행렬 — "몇 점"이 아니라 "무엇을 무엇으로 착각하나"

정확도 한 숫자는 착각의 방향을 숨깁니다. 혼동 행렬(confusion matrix)은 행=실제, 열=예측으로 집계해 "원을 사각형으로 본 게 몇 건"까지 보여 줍니다. 잡음 때문에 윤곽이 흐려진 원과 사각형이 서로 헷갈리는 것이 이 데이터의 전형적 패턴입니다. 불량 검사라면 "불량을 정상으로 본 칸"이 치명 칸이니, 어느 칸이 비싼 실수인지 표시하며 읽는 습관을 들이세요 (lecture06 level06 의 재현율 이야기와 연결됩니다).

### 3.4 CNN vs MLP — 구조가 곧 사전 지식

MLP 는 픽셀 256개를 한 줄로 펴서 받습니다. 이 순간 "어떤 픽셀이 어떤 픽셀 옆인지"라는 공간 정보가 사라집니다. 도형이 두 칸 이동하면 MLP 에게는 전혀 다른 입력이 됩니다. CNN 은 지역성(커널)과 위치 불변성(가중치 공유, 풀링)을 **구조로 내장**했으므로, 같은 데이터에서 더 적은 파라미터로 더 잘 일반화합니다. 실행 결과에서 CNN(약 2천 파라미터)이 MLP(약 1.9만 파라미터)를 정확도로 이기는 것을 확인하세요 — 좋은 구조는 공짜 데이터와 같습니다.

### 3.5 오분류 분석 — 성적표 뒤의 이야기

틀린 이미지를 직접 보면 대부분 납득이 갑니다: 잡음이 유난히 심하거나, 도형이 프레임 가장자리에 걸려 일부가 잘렸거나, 크기가 작아 원·사각형 구분이 사람 눈에도 어려운 사례들입니다. **모델의 약점 목록은 다음 개선 작업의 주문서**입니다 — 이 관점을 level08 (실전 파이프라인)에서 본격적으로 확장합니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1]** `shape_images(n=900)` 를 학습 600 / 검증 150 / 테스트 150 으로 분할합니다. 테스트는 마지막까지 봉인.
- **[2]** ShapeCNN 을 18에폭 학습합니다. 3에폭마다 학습 손실과 검증 정확도가 출력됩니다 — 손실은 내려가고 정확도는 올라가는 리듬을 확인하세요.
- **[3]** 같은 데이터·설정으로 MLP 를 학습합니다.
- **[4]** 봉인을 뜯고 테스트 150장으로 두 모델의 최종 성적표와 CNN 의 혼동 행렬을 출력합니다. (전형적 결과: CNN ≈ 0.97, MLP ≈ 0.85)
- **[5]** CNN 이 틀린 테스트 이미지를 최대 8장, 실제/예측 라벨과 함께 `outputs/shape_classification.png` 에 저장합니다. 왼쪽 학습 곡선(CNN vs MLP)도 같은 그림에 담깁니다.

코드 핵심부는 `train()` 함수 — `zero_grad → forward → loss → backward → step` 다섯 박자의 표준 학습 루프입니다. lecture08 에서 배운 그 루프가 이미지에서도 한 글자도 다르지 않다는 것이 오늘의 숨은 교훈입니다.

## 6. 자주 하는 실수

- **테스트 데이터로 에폭·구조를 고르기**: 테스트 성적을 보고 모델을 고치기 시작하면 테스트가 검증으로 오염됩니다. 튜닝은 검증 점수로만, 테스트는 최후의 한 번만.
- **정확도만 보고 종료**: 혼동 행렬과 오분류 사례까지 봐야 "어떤 실수를 하는 모델인지" 압니다. 실무에서 비싼 것은 평균이 아니라 특정 칸의 실수입니다.
- **손실이 줄면 무조건 좋아진다고 믿기**: 학습 손실은 줄어드는데 검증 정확도가 멈추거나 떨어지면 과적합 신호입니다 (lecture08 level09).
- **매 실행 결과가 조금씩 다른 것에 놀라기**: seed 를 고정해도 라이브러리 버전 등에 따라 소수점이 흔들릴 수 있습니다. 결론은 "숫자 하나"가 아니라 "경향"으로 읽으세요.
