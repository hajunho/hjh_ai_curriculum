# Lecture 09 · Level 07 — 전이학습

> 과제 A로 배운 "보는 눈"을 얼려서 과제 B에 이식하면, 새 라벨 24장만으로 백지 학습을 이기는 것을 실험으로 증명합니다.
**난이도** ⭐⭐⭐⭐ / **선행** level05~06 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

실무 이미지 과제의 9할은 이렇게 시작합니다: "라벨 붙은 우리 데이터는 몇십~몇백 장뿐입니다." 이 조건에서 밑바닥부터 학습하는 것은 대부분 무모하고, 업계 표준 해법은 **전이학습(transfer learning)** — 대규모 데이터로 이미 학습된 모델의 앞부분을 가져와 내 과제에 맞게 뒷부분만 다시 가르치는 것입니다. "비전 AI 도입 견적이 생각보다 싸게 나오는" 이유가 대부분 이것이고, 반대로 "우리 데이터가 특수해서 전이가 안 통한다"는 진단이 프로젝트 비용을 몇 배로 만들기도 합니다. 전이가 왜 통하는지, 언제 안 통하는지를 오늘 원리 수준에서 이해합니다.

이 레벨의 특징: 보통 전이학습 실습은 대형 사전학습 모델을 내려받지만, 우리는 **다운로드 없이** 전이학습의 원리를 증명합니다. 과제 A(사각형/원/삼각형)를 우리가 직접 사전학습시키고, 그 눈을 과제 B(마름모/타원/고리)에 이식합니다. 규모만 작을 뿐 메커니즘은 실무와 동일합니다.

## 2. 비유로 이해하기

**경력직 채용 vs 신입 채용**입니다.

품질검사팀에 새 제품(과제 B) 검사 인력이 필요합니다. 후보는 둘.

- **신입(from scratch)**: 백지 상태. "물체의 윤곽을 본다", "형태를 비교한다" 같은 기본기부터 새로 가르쳐야 합니다. 교육 자료(라벨 데이터)가 24장뿐이라면 기본기조차 못 갖춥니다.
- **경력직(transfer)**: 다른 제품(과제 A)을 오래 검사한 사람. 새 제품은 처음 보지만, **"보는 법" 자체는 이미 갖고 있습니다.** 새 제품의 판정 기준만 가르치면 되니 자료 24장으로도 충분합니다.

CNN 에서 "보는 법"은 앞부분(특징 추출기)에, "판정 기준"은 뒷부분(head)에 들어 있습니다. level04 에서 본 특징의 계층을 떠올리세요 — 앞 층의 엣지·곡선·덩어리 감지는 **어떤 이미지 과제에서든 필요한 공통 기본기**입니다. 그래서 과제가 달라도 앞부분은 재사용이 됩니다.

## 3. 핵심 개념

### 3.1 두 가지 전이 방식

| 방식 | 하는 일 | 언제 |
|---|---|---|
| 특징 추출(feature extraction) | 앞부분을 **동결(freeze)**하고 head 만 학습 | 새 데이터가 아주 적을 때 (오늘의 방식) |
| 미세조정(fine-tuning) | 앞부분도 **작은 학습률로** 같이 갱신 | 새 데이터가 좀 있고, 과제가 원 과제와 좀 다를 때 |

동결은 코드로 `param.requires_grad = False` 한 줄입니다. 옵티마이저에 동결된 파라미터를 주지 않으면 그 무게는 사전학습 상태 그대로 보존됩니다.

### 3.2 왜 통하는가 — 특징의 계층, 다시

과제 A 에는 마름모도 고리도 없습니다. 그런데 A 로 배운 눈이 B 에 통하는 이유: 앞 층이 배우는 것은 "삼각형 감지기"가 아니라 **엣지·곡선·덩어리·모서리 감지기**이기 때문입니다. 이런 저수준 특징은 과제 보편적(task-general)입니다. 반면 마지막 head 는 "이 특징 조합이면 삼각형" 같은 과제 특수(task-specific) 판정이라 재사용이 안 됩니다. **"앞은 보편, 뒤는 특수"** — 전이학습 설계의 제1원리입니다.

### 3.3 전이가 안 통하는 경우

경력직도 업종이 너무 다르면 힘을 못 씁니다. 사전학습 데이터와 내 데이터의 **도메인 격차**가 크면(일상 사진으로 배운 모델 ↔ X선·현미경·열화상 이미지) 저수준 통계부터 달라 전이 효과가 급감합니다. 이럴 때는 유사 도메인 사전학습 모델을 찾거나, 미세조정 비중을 키우거나, 자체 사전학습을 검토합니다 — 프로젝트 견적이 갈리는 지점입니다.

### 3.4 실무에서는

실제로는 대규모 공개 데이터로 사전학습된 백본(backbone)을 받아 쓰는 것이 표준입니다. 절차는 오늘 실습과 동일합니다: (1) 백본 로드 → (2) head 를 내 클래스 수로 교체 → (3) 동결 범위 결정 → (4) 내 데이터로 학습. 오늘 코드의 `load_state_dict` + `requires_grad=False` 두 줄이 그 절차의 축소판입니다.

### 3.5 공정 비교 실험의 설계

오늘 실험은 "같은 구조, 같은 초기 head, 같은 학습 설정, 다른 것은 특징 추출기의 출발점뿐"으로 통제됩니다. 모델을 일부러 약 1.5만 파라미터로 키운 것도 설계의 일부입니다 — 데이터 24장 대비 충분히 커서, 백지 학습이 힘들어지는 현실적 조건을 만들기 위해서입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1]** 과제 A(사각형/원/삼각형, 600장)로 CNN 을 사전학습합니다. 과제 A 테스트 정확도 1.0 — 이 모델의 features 는 이제 형태를 보는 눈을 갖췄습니다.
- **[2]** 과제 B 등장: **마름모/타원/고리** — main.py 안에서 numpy 로 직접 그린, 과제 A 에 없던 도형 3종입니다. 라벨 데이터는 24장뿐(테스트 336장).
- **[3]** 방법 1 — 백지 학습: 같은 구조를 무작위 초기값에서 24장으로 학습합니다 (학습 파라미터 15,587개 전부).
- **[4]** 방법 2 — 전이학습: 사전학습된 features 를 `load_state_dict` 로 이식하고 동결, head 1,539개만 학습합니다.
- **[5]** 에폭별 테스트 정확도를 비교합니다. 전형적 결과: 10에폭부터 전이가 앞서고(0.66 vs 0.49), 최종도 전이 승(0.94 vs 0.91). **학습한 파라미터가 1/10인데 더 빠르고 더 좋습니다.** 곡선과 과제 B 샘플을 `outputs/transfer_learning.png` 로 저장합니다.

주목할 정직한 관찰 하나: 에폭을 충분히 주면 백지 학습도 꽤 따라옵니다. 전이학습의 이득은 "불가능을 가능으로"라기보다 **"적은 데이터·적은 계산으로 더 빨리, 조금 더 좋게"** 입니다. 데이터가 더 줄거나 모델이 더 커질수록 이 격차는 벌어집니다.

## 6. 자주 하는 실수

- **head 를 교체하지 않는 것**: 사전학습 모델의 출력은 원 과제의 클래스 수·의미입니다. 내 과제에 맞는 새 head 로 갈아 끼우는 것이 항상 첫 단계입니다.
- **동결을 잊은 미세조정**: 적은 데이터로 전체를 큰 학습률로 갱신하면, 애써 빌려 온 좋은 특징이 몇 에폭 만에 망가집니다(파국적 망각). 데이터가 적을수록 많이 얼리세요.
- **전이 = 만능이라는 착각**: 도메인 격차가 크면 효과가 급감합니다. "사전학습 데이터가 무엇이었는지"는 모델 선택의 핵심 질문입니다.
- **비교 실험의 통제 실패**: 전이 모델과 백지 모델의 구조·에폭·학습률이 다르면 무엇 때문에 이겼는지 알 수 없습니다. 오늘 코드처럼 차이를 하나만 남기세요.
