# Lecture 09 · Level 06 — 데이터 증강

> 라벨이 변하지 않는 변형(회전·이동·반전·잡음)으로 데이터를 부풀려, 한 장도 새로 찍지 않고 정확도를 30%p 끌어올리는 실험을 합니다.
**난이도** ⭐⭐⭐ / **선행** level05 / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

비전 프로젝트의 병목은 거의 항상 모델이 아니라 **라벨 붙은 데이터**입니다. 불량 이미지 수집에는 실제 불량이 나야 하고, 라벨링에는 검사 경력자의 시간이 들며, 개인정보·보안 문제로 수집 자체가 막히기도 합니다. "데이터 1만 장 모아 오세요"가 불가능한 상황이 기본값입니다.

데이터 증강(data augmentation)은 이 병목에 대한 가장 값싼 처방입니다. **이미 가진 이미지를 살짝 변형한 사본**을 학습에 추가하는 것 — 추가 촬영도 추가 라벨링도 필요 없습니다. 현업의 이미지 학습 파이프라인에서 증강은 선택이 아니라 기본 장착이며, "증강 뭐 쓰셨어요?"는 비전 엔지니어들의 인사말 수준의 질문입니다. 오늘 이 기술의 원리와 한계를 실험으로 익힙니다.

## 2. 비유로 이해하기

**신제품 등록 사진 촬영**을 떠올려 보세요. 쇼핑몰에 상품을 올릴 때 한 각도로만 찍지 않습니다. 정면, 살짝 왼쪽, 뒤집어서, 조명 바꿔서 — 같은 상품을 여러 조건으로 찍습니다. 상품(정체)은 그대로인데 보이는 모습만 다양해집니다.

증강은 이 "여러 각도 촬영"을 **코드로 흉내 내는 것**입니다. 이미 있는 사진을 회전시키고, 밀고, 뒤집고, 잡음을 섞으면 — 마치 다른 조건에서 다시 찍은 것 같은 사진이 됩니다. 신입 검수원 비유로는 **같은 문제를 숫자만 바꿔 여러 번 풀리는 변형 문제집**입니다. 원 하나를 한 위치에서만 본 검수원은 다른 위치의 원에 약하지만, 온갖 위치·방향으로 변형된 원을 본 검수원은 "위치가 아니라 둥긂이 본질"임을 배우게 됩니다.

단, 절대 규칙이 하나 있습니다: **변형해도 정답이 변하면 안 됩니다.** 원은 돌려도 원이지만, 숫자 6을 180도 돌리면 9가 됩니다. 화살표 표지판을 좌우 반전하면 방향이 바뀝니다. 어떤 변형이 안전한지는 **과제의 의미**가 정합니다 — 이것이 증강 설계의 전부입니다.

## 3. 핵심 개념

### 3.1 라벨 보존 변형(label-preserving transform)

증강의 정식 정의: 입력은 바꾸되 정답 라벨은 보존하는 변형. 오늘 구현하는 4종은 모두 도형 분류에서 안전합니다.

| 변형 | 구현 | 흉내 내는 현실 |
|---|---|---|
| 회전 (90도 단위) | `np.rot90` | 제품이 돌아간 채 놓임 |
| 좌우 반전 | `img[:, ::-1]` | 카메라 반대편 설치 |
| 이동 (±2px) | `np.roll` + 가장자리 0 처리 | 컨베이어 위 위치 편차 |
| 가우시안 잡음 | `img + normal(0, 0.1)` | 센서 노이즈, 조도 잔떨림 |

### 3.2 왜 효과가 있나 — 과적합과의 관계

데이터가 120장뿐이면 모델은 "이 120장의 우연한 특징"(3번 이미지의 왼쪽 위 잡음 얼룩 같은)까지 외워 버립니다 — 과적합(lecture08 level09)입니다. 증강본이 섞이면 우연한 특징은 변형마다 달라지니 외울 수 없게 되고, 변형에도 살아남는 본질(도형의 형태)만 배우게 됩니다. 즉 증강은 **"본질만 남기는 규제"** 이기도 합니다. level04 에서 풀링이 구조로 주는 이동 강건성을, 증강은 데이터로 한 번 더 가르치는 셈입니다.

### 3.3 절대 금지 — 평가 데이터 증강과 분할 전 증강

- 테스트/검증 데이터에는 증강본을 넣지 않습니다. 시험지는 현실 그대로여야 합니다.
- **분할 전에 증강하면 안 됩니다.** 원본이 학습에, 그 회전본이 테스트에 들어가면 사실상 같은 문제가 시험에 나온 것 — 성능이 부풀려집니다(데이터 누수). 순서는 반드시 "분할 먼저, 증강은 학습 쪽에만".

### 3.4 얼마나, 어떤 강도로?

증강도 과유불급입니다. 잡음 std 를 0.5로 올리면 도형 자체가 묻히고, 이동을 ±6px 로 키우면 도형이 프레임 밖으로 나갑니다. 실무 요령은 **"사람이 봐도 여전히 정답을 맞힐 수 있는 범위"** 까지만 변형하는 것입니다. main.py 의 강도(회전 90도 단위, 이동 ±2, 잡음 0.1)는 이 기준으로 고른 값입니다.

### 3.5 요즘은 어떻게 하나

실무 프레임워크는 증강을 학습 루프 안에서 **매 에폭 무작위로** 적용합니다(on-the-fly). 오늘처럼 미리 부풀려 두는 방식보다 다양성이 더 커집니다. 원리는 같으므로, 오늘 구현을 이해하면 토치비전(torchvision.transforms) 류의 설정 파일을 읽을 수 있게 됩니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1]** 일부러 데이터 부족 상황을 만듭니다: 학습 120장, 테스트 300장.
- **[2]** 증강 4종을 numpy 로 구현하고 한 이미지의 변형본들을 만들어 봅니다.
- **[3]** 이미지마다 무작위 증강본 4장을 만들어 학습 데이터를 120→600장으로 부풀립니다. 테스트는 원본 그대로 둡니다.
- **[4]** **공정 비교 실험**: 같은 모델 구조, 같은 에폭, 같은 초기 무게로 "증강 없음 vs 증강 있음"을 학습해 테스트 정확도를 비교합니다. 전형적 결과: 0.59 → 0.91 (**+32%p**). 새 데이터 0장으로 얻은 이득입니다.
- **[5]** 변형본 갤러리와 성능 비교 막대를 `outputs/augmentation.png` 로 저장합니다.

코드 핵심부는 `augment_dataset()` 입니다. 회전→반전→이동→잡음을 무작위로 조합해 변형본을 만드는 15줄 — 실무 증강 파이프라인의 축소판입니다. `torch.manual_seed(6)` 를 두 실험 직전에 똑같이 호출해 **초기 무게를 통일**하는 부분도 눈여겨보세요. 비교 실험의 공정성은 이런 디테일에서 나옵니다.

## 6. 자주 하는 실수

- **라벨이 변하는 변형을 쓰는 것**: 문자·숫자·방향성 있는 물체에 회전/반전을 무심코 걸면 정답이 바뀝니다. 증강 목록은 과제 의미를 아는 사람이 검토해야 합니다.
- **분할 전에 증강하기**: 원본과 변형본이 학습/테스트 양쪽에 갈라져 들어가는 데이터 누수. 성능이 배포 후에 뚝 떨어지는 단골 원인입니다.
- **테스트 성능이 아니라 학습 성능으로 효과 판정**: 증강은 학습을 "더 어렵게" 만들므로 학습 손실은 오히려 커 보입니다. 효과는 반드시 손대지 않은 테스트로 잽니다.
- **증강을 만능으로 믿기**: 증강은 있는 데이터의 변주일 뿐, 없는 유형(한 번도 안 찍힌 불량 종류)을 만들어 주지 못합니다. 수집을 대체하는 것이 아니라 보완합니다.
