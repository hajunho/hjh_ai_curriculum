# Lecture 09 · Level 01 — 픽셀·채널·이미지 연산

> 밝기 조절은 덧셈, 대비는 곱셈, 반전은 빼기 — 이미지 편집 앱의 버튼들을 numpy 산수로 직접 만들어 봅니다.
**난이도** ⭐⭐ / **선행** level00 / **예상 시간** 30분

## 1. 왜 배우나 — 비즈니스 관점

비전 AI 프로젝트에서 모델링보다 먼저 만나는 일이 **전처리(preprocessing)** 입니다. 매장 CCTV 는 밤낮으로 밝기가 다르고, 스캔 문서는 대비가 약하고, 카메라마다 해상도가 제각각입니다. 이런 이미지를 모델에 그대로 넣으면 성능이 요동칩니다. 실무 파이프라인의 첫 단계는 언제나 "밝기 정규화, 크기 통일, 관심 영역 잘라내기" 같은 이미지 연산입니다.

이 연산들은 포토샵의 전유물이 아닙니다. level00 에서 봤듯 이미지는 숫자 표이므로, **밝기 조절 = 전체 셀에 덧셈, 대비 조절 = 전체 셀에 곱셈**입니다. 엑셀에서 열 전체에 `+10`을 채우는 것과 같은 일입니다. 이 감각이 생기면 "전처리 뭐 하셨어요?"라는 질문을 던지고 답을 알아들을 수 있게 됩니다.

## 2. 비유로 이해하기

**무대 조명 콘솔**을 떠올려 보세요.

- **마스터 페이더를 올린다** → 무대 전체가 균일하게 밝아진다 = 모든 픽셀에 같은 수를 **더한다**
- **디머 배율을 키운다** → 밝은 곳은 더 밝게, 어두운 곳은 조금만 밝게, 차이가 벌어진다 = 모든 픽셀에 같은 수를 **곱한다** (대비)
- **네거티브 필름** → 밝던 곳이 어두워지고 어둡던 곳이 밝아진다 = `1 - 픽셀값` (반전)

그리고 컬러. 무대 조명은 빨강·초록·파랑 세 대의 조명을 겹쳐 온갖 색을 만듭니다. 컬러 이미지도 같습니다. **빨강 밝기 표, 초록 밝기 표, 파랑 밝기 표** — 흑백 이미지 3장을 겹친 것이 RGB 컬러 이미지입니다. 이 낱장 하나하나를 **채널(channel)** 이라고 부릅니다.

## 3. 핵심 개념

### 3.1 채널 — 컬러는 흑백 3장

컬러 이미지는 `(높이, 너비, 3)` 배열입니다. `img[:, :, 0]` 이 빨강 채널, `[..., 1]` 이 초록, `[..., 2]` 가 파랑. 픽셀 하나는 숫자 3개(R, G, B)의 묶음이고, (1, 0, 0)은 순수 빨강, (1, 1, 0)은 노랑, (1, 1, 1)은 흰색입니다. 흑백 변환은 세 채널의 가중 평균(사람 눈은 초록에 민감하므로 `0.299R + 0.587G + 0.114B` 를 관례로 씁니다)입니다.

### 3.2 픽셀 연산 4형제

| 연산 | 수식 | 조명 콘솔 비유 | 주의 |
|---|---|---|---|
| 밝기(brightness) | `img + b` | 마스터 페이더 | 1.0 초과分은 잘라야(clip) 함 |
| 대비(contrast) | `(img - 0.5) * a + 0.5` | 디머 배율 | 중심 0.5 기준으로 벌림 |
| 반전(invert) | `1 - img` | 네거티브 필름 | — |
| 클리핑(clip) | `np.clip(img, 0, 1)` | 안전 리미터 | 연산 후 항상 확인 |

대비에서 `- 0.5` 를 먼저 하는 이유: 그냥 `img * 2` 를 하면 전체가 밝아지기만 합니다. 중간 밝기(0.5)를 축으로 위아래로 벌려야 "어두운 곳은 더 어둡게, 밝은 곳은 더 밝게"가 됩니다.

### 3.3 기하 연산 — 크롭과 리사이즈

- **크롭(crop)**: 관심 영역만 잘라내기. numpy 슬라이싱 그 자체입니다 — `img[y0:y1, x0:x1]`. 엑셀에서 표의 일부 범위를 복사하는 것과 같습니다.
- **리사이즈(resize)**: 크기 바꾸기. 가장 단순한 방법은 **최근접 이웃(nearest neighbor)** — 새 좌표에서 가장 가까운 원본 픽셀 값을 가져옵니다. 확대하면 픽셀이 계단처럼 각져 보이는데, 그것이 이 방법의 정직한 한계입니다(실무 라이브러리는 주변 픽셀을 섞는 보간을 씁니다).

### 3.4 정규화 — 모델에 넣기 전 마지막 관문

딥러닝 모델은 입력 숫자의 범위에 민감합니다. 그래서 학습 전 이미지들을 "평균 0 부근, 비슷한 스케일"로 맞춰 줍니다. 가장 흔한 두 가지는 0~255 를 0~1 로 나누는 것과, `(img - 평균) / 표준편차` 입니다. "같은 조건으로 촬영을 못 맞추면, 코드로라도 맞춘다" — 정규화의 실무적 의미입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

이 프로그램은 numpy 만으로 RGB 이미지를 만들고, 이미지 연산 전부를 한 장의 비교판 PNG 로 정리합니다.

- **[1]** numpy 로 48×48 RGB 이미지를 **직접 그립니다** (하늘 그라데이션 + 빨간 사각형 + 노란 원). 다운로드도, 그림 파일도 없이 배열 조작만으로 컬러 그림이 나온다는 것을 먼저 확인합니다.
- **[2]** R/G/B 채널을 낱장으로 분리해 각 채널에서 어떤 물체가 밝게 보이는지 출력합니다. 빨간 사각형은 R 채널에서 밝고 B 채널에서 어둡습니다 — "빨갛다"의 정체가 숫자로 드러납니다.
- **[3]** 밝기(+0.25), 대비(×1.8), 반전, 흑백 변환을 각각 적용하고, 연산 전후의 픽셀 값 통계(min/mean/max)를 표로 출력합니다. clip 을 안 했을 때 값이 1.0 을 넘는 것도 일부러 보여 줍니다.
- **[4]** 크롭(사각형 부분만)과 최근접 이웃 리사이즈(48→96 확대, 48→16 축소)를 직접 구현합니다. 확대본의 계단 현상을 PNG 에서 확인하세요.
- **[5]** 원본·채널 3장·연산 결과들을 3×4 격자의 비교판으로 `outputs/pixel_ops.png` 에 저장합니다.

코드 핵심부는 `resize_nearest()` 입니다. `np.linspace` 로 "새 이미지의 각 픽셀이 원본의 어느 좌표를 참조할지" 인덱스 배열을 만들고, 팬시 인덱싱 한 줄 `img[yy][:, xx]` 로 리사이즈를 끝냅니다. 반복문 없이 배열 인덱싱만으로 기하 연산이 된다는 것이 numpy 식 사고방식입니다.

## 5. 직접 해보기

1. **(쉬움)** `[3]`의 밝기 조절을 `+0.25` 에서 `-0.25` 로 바꿔 어두운 버전을 만들어 보세요. PNG 에서 그림자 속으로 들어간 듯한 결과를 확인하세요. (힌트: `BRIGHT_DELTA` 상수)
2. **(보통)** "세피아 톤" 필터를 만들어 보세요: 흑백 변환값 `g` 를 만든 뒤 R=g×1.0, G=g×0.8, B=g×0.55 로 채널을 다시 조립하면 됩니다. (힌트: `np.stack([...], axis=-1)` 후 clip)
3. **(도전)** 대비 공식의 중심을 0.5 대신 **이미지의 실제 평균값**으로 바꿔 보세요. 어두운 이미지에서 두 방식의 결과가 어떻게 다른지 통계로 비교해 보세요. (힌트: `img.mean()` 을 축으로 사용)

## 6. 자주 하는 실수

- **clip 을 잊는 것**: `img + 0.5` 후 값이 1.4 가 되어도 numpy 는 에러를 내지 않습니다. 저장·표시 단계에서 색이 이상하게 튀고 나서야 발견됩니다. 픽셀 연산 후에는 습관적으로 `np.clip` 하세요.
- **정수 이미지에서의 오버플로**: 0~255 의 uint8 배열에 200+100 을 하면 300 이 아니라 44 가 됩니다(넘침). float 로 바꿔 계산하고 마지막에 되돌리는 것이 안전합니다.
- **채널 순서 혼동**: 이 강의는 RGB 순서지만, 일부 라이브러리(OpenCV 등)는 BGR 순서를 씁니다. 파랗게 나온 얼굴 사진의 90%는 채널 순서 버그입니다.
- **리사이즈로 정보가 살아난다는 착각**: 16×16 을 96×96 으로 키워도 정보는 늘지 않습니다. 커 보일 뿐입니다. 없는 디테일은 만들어지지 않습니다.
