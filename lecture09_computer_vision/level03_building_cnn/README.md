# Lecture 09 · Level 03 — CNN 구조 만들기

> Conv2d 의 채널·커널·스트라이드·패딩을 조립 설명서처럼 읽고, 미니 CNN 을 지으며 층마다 데이터의 모양이 어떻게 변하는지 추적합니다.
**난이도** ⭐⭐⭐ / **선행** level02, lecture08 level05~07 (PyTorch 텐서·MLP) / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

비전 모델 도입을 검토하다 보면 "백본은 ○○넷이고, 3×3 컨브 32채널로 시작해서…" 같은 말을 듣게 됩니다. 구조 설명서를 읽지 못하면 모델의 크기(비용), 속도(응답 시간), 요구 해상도(카메라 사양)를 스스로 가늠할 수 없고, 전부 공급 업체의 말에 의존하게 됩니다.

CNN 구조 읽기의 핵심 기술은 단 두 가지입니다. **(1) 층을 지날 때 데이터 모양(shape)이 어떻게 변하는가, (2) 각 층의 파라미터가 몇 개인가.** 이 두 가지를 계산할 수 있으면 어떤 구조 그림도 견적서처럼 읽힙니다. 오늘 이 계산법을 익히고, 코드로 검산합니다.

## 2. 비유로 이해하기

CNN 한 층은 **검사 도장 여러 개를 든 검사팀**입니다.

level02 에서는 도장(커널)이 하나였습니다. 실제 Conv2d 층은 도장을 **여러 개** 듭니다. 수직 엣지 도장, 수평 엣지 도장, 둥근 모서리 도장… 도장이 16개면 검사 결과 지도(특징 맵)도 16장 나옵니다. 이 "지도 몇 장"이 **출력 채널(out_channels)** 입니다.

다음 층의 검사팀은 원본 이미지가 아니라 **앞 팀이 만든 지도 16장 묶음**을 검사합니다. 그래서 다음 층 도장은 16장을 동시에 뚫어 보는 입체 도장(3×3×16)입니다. 이것이 **입력 채널(in_channels)** 의 의미입니다. 층이 깊어질수록 "엣지 지도들의 조합" → "모서리·곡선 지도" → "도형 부품 지도"로 검사 내용이 고차원이 됩니다.

마지막으로, 지도들을 다 본 뒤 최종 판정을 내리는 **결재 라인**이 필요합니다. 지도를 한 줄로 펴서(Flatten) 일반 신경망(Linear)에 넘기면, "이 증거 조합이면 원(circle)"이라는 결론이 나옵니다.

## 3. 핵심 개념

### 3.1 Conv2d 의 5대 설정값

`nn.Conv2d(in_channels, out_channels, kernel_size, stride, padding)`

| 설정 | 비유 | 효과 |
|---|---|---|
| in_channels | 검사할 지도 묶음 수 | 입력 채널 수와 반드시 일치 |
| out_channels | 도장(질문) 개수 | 출력 지도 수 = 표현력 |
| kernel_size | 도장 크기 | 한 번에 보는 이웃 범위 |
| stride | 도장 이동 보폭 | 2면 출력 가로세로 절반 |
| padding | 서류 가장자리 여백 | 1이면 3×3 커널에서 크기 유지 |

### 3.2 출력 크기 공식 — 이 강의에서 가장 자주 쓸 식

```
out = (in + 2*padding - kernel) / stride + 1
```

예: 입력 16, kernel 3, padding 1, stride 1 → (16+2-3)/1+1 = **16** (유지).
stride 2 로 바꾸면 → (16+2-3)/2+1 = **8** (절반). 층을 설계할 때마다 이 식으로 끝까지 추적해야, Flatten 직전의 크기(= Linear 층의 입력 크기)를 알 수 있습니다.

### 3.3 파라미터 수 계산 — 모델 견적 뽑기

- **Conv2d**: `out_ch × (in_ch × k × k) + out_ch` (마지막 항은 편향). 예: 1→8채널 3×3 이면 8×9+8 = **80개**.
- **Linear**: `out × in + out`. 예: 256→3 이면 3×256+3 = **771개**.

주목할 점: Conv 층의 파라미터는 **이미지 크기와 무관**합니다. 도장은 이미지가 커져도 같은 도장이니까요. 반면 Flatten 후 Linear 는 이미지 크기에 정비례합니다. 그래서 CNN 파라미터의 대부분이 뒷단 Linear 에 몰리는 일이 흔하고, 이를 줄이는 것(풀링, 글로벌 평균)이 level04 의 주제와 이어집니다.

### 3.4 활성화 함수와 층 쌓기

합성곱은 곱셈-덧셈뿐인 선형 연산이라, 사이에 비선형(ReLU)을 끼우지 않으면 몇 층을 쌓아도 한 층과 같아집니다(lecture08 level02 의 복습). 그래서 기본 블록은 `Conv → ReLU` 이고, 전형적인 소형 CNN 은 이렇게 생겼습니다.

```
입력 (1, 16, 16)
Conv(1→8, 3x3, pad 1) + ReLU     → (8, 16, 16)
Conv(8→16, 3x3, pad 1, stride 2) + ReLU → (16, 8, 8)
Conv(16→32, 3x3, pad 1, stride 2) + ReLU → (32, 4, 4)
Flatten                           → (512,)
Linear(512→3)                     → (3,)  # 클래스 점수
```

채널은 늘리고(8→16→32) 공간은 줄이는(16→8→4) 흐름 — "장소 정보는 요약하고, 의미 정보는 풍부하게"가 CNN 설계의 기본 리듬입니다.

### 3.5 배치 차원

PyTorch 의 이미지 텐서는 `(배치, 채널, 높이, 너비)` 4차원입니다. 이미지 32장을 한 번에 처리하면 `(32, 1, 16, 16)`. shape 오류의 대부분은 이 4차원 규약을 어겨서 생기므로, "B-C-H-W" 순서를 입에 붙이세요.

## 6. 자주 하는 실수

- **Flatten 크기 계산 실수**: Linear 층의 in_features 가 안 맞아 `mat1 and mat2 shapes cannot be multiplied` 에러가 나는 것은 CNN 입문 1위 에러입니다. 항상 공식으로 끝까지 추적하세요.
- **채널 사슬 끊기**: 앞 층 out_channels ≠ 다음 층 in_channels 면 즉시 에러. 채널은 릴레이 바통입니다.
- **4차원 규약 위반**: `(16,16)` 이미지를 그대로 넣으면 실패합니다. `unsqueeze` 로 배치·채널 차원을 만들어 `(1,1,16,16)` 으로 넣어야 합니다.
- **파라미터 수와 계산량 혼동**: Conv 층은 파라미터는 적지만 모든 위치에서 반복 계산하므로 계산량(FLOPs)은 클 수 있습니다. "가볍다"가 "빠르다"와 항상 같지는 않습니다.
