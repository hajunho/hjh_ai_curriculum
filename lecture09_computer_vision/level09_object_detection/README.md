# Lecture 09 · Level 09 — 객체 탐지의 원리

> "무엇이 있나"를 넘어 "무엇이 어디에 있나" — 슬라이딩 윈도우와 분류기만으로 미니 탐지기를 만들고, IoU 와 NMS 로 탐지의 문법을 익힙니다.
**난이도** ⭐⭐⭐⭐ / **선행** level05, level08 / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

분류는 "이 사진에 불량이 있는가?"까지 답합니다. 그런데 현장의 질문은 한 걸음 더 갑니다 — "불량이 **몇 개**, **어디에** 있는가?" 매대 사진에서 결품 위치 찾기, 서류에서 도장·서명 위치 찾기, CCTV 에서 사람·차량 위치 추적 — 전부 **객체 탐지(object detection)** 문제입니다.

탐지 솔루션을 검토할 때 반드시 만나는 용어가 셋 있습니다: **바운딩 박스**(물체를 감싸는 사각형), **IoU**(예측 상자가 정답과 얼마나 겹치는지), **NMS**(중복 상자 정리). 그리고 성능표의 mAP. 이 용어들을 모르면 "mAP@0.5 가 0.91"이라는 성능 보고를 읽을 수 없습니다. 오늘 이 부품들을 전부 직접 만들어 보며, 탐지가 결국 **"분류기를 위치마다 반복 실행하는 것"** 에서 출발했음을 확인합니다.

## 2. 비유로 이해하기

**돋보기로 벽화 조사하기**입니다. 큰 벽화(장면)에서 특정 그림(도형)을 모두 찾아 위치를 보고해야 합니다. 방법은 우직합니다 — **돋보기(창문)를 왼쪽 위부터 오른쪽 아래까지 한 뼘씩 밀며, 매 위치에서 "여기 뭐가 보이나?"를 판정**합니다. 이것이 슬라이딩 윈도우(sliding window)입니다. 판정 요원은 level05 에서 만든 바로 그 분류기입니다. 단, 한 가지가 추가됩니다 — **"아무것도 없음(배경)"이라고 답할 줄 알아야** 합니다. 벽화 대부분의 위치엔 아무 그림도 없으니까요.

조사가 끝나면 보고서에 같은 그림이 여러 번 적혀 있습니다. 돋보기를 2cm 밀어도 같은 그림이 계속 보이기 때문입니다. 그래서 **"거의 같은 위치의 중복 보고는 가장 확신 있는 것 하나만 남긴다"** 는 정리 규칙이 필요합니다 — 이것이 NMS(non-maximum suppression, 비최대 억제)입니다.

마지막으로 채점. "위치를 맞혔다"를 어떻게 정의할까요? 상자가 픽셀 하나까지 같기를 요구하면 아무도 못 맞힙니다. 그래서 **겹침의 비율(IoU)이 기준 이상이면 정답**으로 칩니다. 부동산에서 "두 필지가 얼마나 겹치나"를 재는 것과 같은 산수입니다.

## 3. 핵심 개념

### 3.1 IoU (Intersection over Union)

```
IoU = 겹친 넓이 / (A 넓이 + B 넓이 − 겹친 넓이)
```

완전 일치 1.0, 전혀 안 겹침 0.0. 관례적으로 **IoU ≥ 0.5 면 "맞힌 탐지(TP)"** 로 봅니다. IoU 는 채점에만 쓰이는 게 아니라, 학습 데이터 라벨링(3.3)과 NMS(3.4)에도 쓰이는 탐지의 만능 자입니다.

### 3.2 탐지의 3대 오류와 mAP

- **정탐(TP)**: 클래스 일치 + IoU ≥ 0.5 인 탐지
- **오탐(FP)**: 없는 곳에서 울리거나, 클래스·위치가 틀린 탐지 (경보 피로의 원인)
- **미탐(FN)**: 있는데 못 찾음 (불량 유출의 원인)

확신 임계값을 낮추면 미탐이 줄고 오탐이 늘어납니다 — lecture06 level06 의 정밀도/재현율 트레이드오프가 탐지에서 재등장합니다. **mAP**(mean Average Precision)는 이 트레이드오프 곡선을 클래스별로 평균해 하나의 숫자로 만든 표준 지표입니다.

### 3.3 학습 데이터도 IoU 가 만든다

탐지기 학습의 재료는 "창문 크롭 + 라벨"입니다. 오늘 코드의 규칙: 크롭이 정답 상자와 **IoU ≥ 0.55 면 그 도형**, 아니면 **배경**. 중요한 디테일 — 도형에 반쯤 걸친 창도 배경으로 가르칩니다. 그래야 분류기가 "물체가 중앙에 제대로 들어온 창"에서만 울리게 되어, 탐지 상자가 물체 중심에 정확히 붙습니다. 실습 첫 버전에서 이 규칙 없이 학습했다가 오탐투성이가 되는 것을 겪어 보면(직접 해보기 3), 왜 실제 탐지기들이 이런 라벨 할당 규칙에 공을 들이는지 체감됩니다.

### 3.4 NMS — 확신 순 정렬 + 겹침 제거

후보 상자를 확신(score) 내림차순으로 보면서, 이미 채택된 상자와 IoU 가 기준(오늘 0.3) 이상 겹치면 버립니다. 단순하지만 모든 현대 탐지기가 (변형된 형태로) 쓰는 후처리입니다.

### 3.5 슬라이딩 윈도우의 한계와 현대적 방법 (개념만)

오늘 방식의 약점은 명확합니다: (1) 창 289개를 **각각** CNN 에 넣으니 느립니다. (2) 창 크기가 고정이라 크기가 다른 물체를 놓칩니다. 현대 탐지기의 진화는 이 두 약점의 해소사입니다.

- **2단계 계열(R-CNN 계열)**: "물체가 있을 법한 후보 영역"을 먼저 추리고, 후보만 정밀 분류.
- **1단계 계열(YOLO·SSD 계열)**: 이미지를 격자로 나눠, CNN **한 번의 순전파**로 모든 격자의 "클래스 + 상자 좌표"를 동시에 출력. 합성곱이 원래 모든 위치를 병렬로 훑는 연산이라는 점(level02)을 이용한 것으로, 실시간 처리가 가능해 산업 현장의 표준이 되었습니다.

이름은 몰라도 됩니다. 기억할 것은 하나 — **어떤 최신 탐지기도 "위치마다 분류 + 상자 회귀 + NMS + IoU 채점"이라는 오늘의 문법 위에 있다**는 것입니다.

- **[2]** 학습 장면 40개를 만들어 창문으로 훑고, IoU 규칙으로 크롭을 자동 라벨링해(도형 3클래스 + 배경) 분류기를 학습합니다.

코드 핵심부는 세 함수입니다: `iou()` 7줄, `sliding_window_detect()` 의 2중 for 문, `nms()` 5줄. 탐지의 문법 전체가 이 20여 줄에 들어 있습니다.

## 6. 자주 하는 실수

- **분류 정확도로 탐지를 평가**: 탐지의 성능은 TP/FP/FN 과 mAP 로 말해야 합니다. "분류기 정확도 97%"는 탐지 품질을 보장하지 않습니다.
- **NMS 를 잊는 것**: 후처리 없는 탐지기는 물체 하나에 상자 수십 개를 출력합니다. 데모에서 상자가 벽지처럼 도배됐다면 십중팔구 NMS 누락입니다.
- **배경 클래스 없이 탐지 시도**: "아무것도 없음"을 배우지 않은 분류기는 모든 창에서 무언가를 봤다고 우깁니다.
- **오탐/미탐의 비용을 같게 취급**: 불량 검출은 미탐이 치명적이고, 보안 경보는 오탐이 시스템을 무력화합니다. 임계값은 비즈니스 비용으로 정하는 것입니다 (lecture07 level11 과 연결).
