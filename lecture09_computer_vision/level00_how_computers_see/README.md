# Lecture 09 · Level 00 — 컴퓨터가 이미지를 보는 방식

> 사진 한 장이 컴퓨터 안에서는 숫자 격자일 뿐임을, 도형 이미지를 텍스트 아트로 찍어 보며 직접 확인합니다.
**난이도** ⭐ / **선행** 없음 (lecture03 level02 의 NumPy 기초가 있으면 편합니다) / **예상 시간** 25분

## 1. 왜 배우나 — 비즈니스 관점

"AI 가 사진을 보고 불량을 잡아낸다"는 말을 들으면 컴퓨터가 사람처럼 '본다'고 상상하기 쉽습니다. 그러나 컴퓨터에게 이미지는 처음부터 끝까지 **숫자 표**입니다. 이 사실을 모르면 비전 AI 프로젝트에서 이상한 판단을 하게 됩니다. "해상도를 왜 줄여요? 화질 좋은 게 낫잖아요?" (숫자가 4배로 늘어 계산도 4배가 됩니다), "조명이 좀 어두워도 되죠?" (모든 숫자가 통째로 작아져 모델이 헷갈립니다) 같은 질문에 스스로 답하려면, 이미지가 숫자라는 출발점이 필요합니다.

엑셀에 익숙한 분이라면 오히려 유리합니다. 이미지 한 장은 **셀마다 밝기 숫자가 적힌 스프레드시트 한 장**과 정확히 같기 때문입니다. 이 레벨이 끝나면 "이미지 처리"가 곧 "표 계산"임을 알게 되고, 이 감각이 lecture09 전체의 토대가 됩니다.

## 2. 비유로 이해하기

**모자이크 벽화**를 떠올려 보세요. 멀리서 보면 사람 얼굴이지만, 가까이 가면 작은 단색 타일 수천 개가 격자로 붙어 있을 뿐입니다. 얼굴은 타일 안에 있지 않습니다. **타일들의 배열 속에** 있습니다.

디지털 이미지가 정확히 이렇습니다. 타일 하나가 **픽셀(pixel)**, 타일의 색이 **픽셀 값(숫자)**, 타일의 개수가 **해상도(resolution)** 입니다. 16×16 이미지는 타일 256개짜리 모자이크, 스마트폰 사진(4000×3000)은 타일 1,200만 개짜리 모자이크입니다.

또 하나의 비유는 **좌석표**입니다. 공연장 좌석표에서 "3열 7번"으로 자리를 찾듯, 이미지에서도 `img[3, 7]` 로 픽셀 하나를 집습니다. 행(row)이 먼저, 열(column)이 나중 — 엑셀의 "행, 열"과 같은 순서라는 점만 기억하면 됩니다.

## 3. 핵심 개념

### 3.1 흑백 이미지 = 2차원 숫자 배열

흑백(grayscale) 이미지는 `높이 × 너비` 모양의 2차원 배열입니다. 각 칸의 숫자가 밝기입니다.

- 0.0 = 완전한 검정, 1.0 = 완전한 흰색, 0.5 = 중간 회색 (0~255 정수로 표현하기도 합니다)
- 이 강의의 도형 이미지는 16×16, 값 0.0~1.0 의 float 배열입니다.

즉 아래 왼쪽의 "그림"과 오른쪽의 "숫자 표"는 완전히 같은 것입니다.

```
■ □        1.0  0.0
□ ■        0.0  1.0
```

### 3.2 해상도 — 타일 개수의 트레이드오프

해상도가 높을수록 세밀하지만, 숫자 개수는 가로×세로에 비례해 폭발합니다. 16×16 은 256개, 32×32 는 1,024개(4배), 1024×1024 는 100만 개가 넘습니다. 딥러닝에서 입력 숫자 하나하나가 계산량이므로, 실무에서는 "과제를 풀 수 있는 최소 해상도"를 찾는 것이 중요한 설계 결정입니다. 불량 검사에서 흠집이 3픽셀짜리로 보이는 해상도라면 충분하고, 그 이상은 비용입니다.

### 3.3 밝기 — 숫자의 크기

이미지의 "밝다/어둡다"는 그저 숫자가 크냐 작냐입니다. 조명이 절반으로 어두워지면 모든 픽셀 값이 대략 절반이 됩니다. 같은 도형이라도 밝기가 다르면 숫자 배열은 크게 달라지므로, 비전 시스템 구축 시 "촬영 조건 고정"이 데이터 품질의 절반을 차지합니다. (밝기를 코드로 조절하는 법은 level01 에서 다룹니다.)

### 3.4 컬러는 어떻게? — 예고

컬러 이미지는 빨강·초록·파랑(RGB) 밝기 표 3장을 겹친 것입니다. 즉 `높이 × 너비 × 3` 배열입니다. 이 레벨에서는 흑백만 다루고, 채널(channel) 이야기는 level01 에서 본격적으로 합니다.

### 3.5 오늘 쓰는 데이터 — 직접 그린 도형

이 강의는 유명 데이터셋을 내려받지 않습니다. `common/hjh_data.py` 의 `shape_images()` 가 numpy 로 그 자리에서 그려 주는 16×16 흑백 도형(사각형·원·삼각형, 3클래스)을 씁니다. 위치·크기가 무작위이고 잡음이 섞여 있어, 작지만 "진짜 분류 문제"의 성질을 다 갖추고 있습니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

이 프로그램은 도형 이미지를 세 가지 방식 — 숫자 표, 텍스트 아트, PNG — 으로 "같은 데이터"임을 보여 줍니다.

- **[1]** `shape_images()` 로 도형 이미지를 만들고, 배열의 모양(shape)·값 범위·클래스 구성을 출력합니다.
- **[2]** 이미지 한 장을 **소수점 숫자 격자**로 그대로 출력합니다. 화면 가득한 0.0 과 1.0 사이에서 도형 윤곽이 보이는지 찾아보세요.
- **[3]** 같은 이미지를 **텍스트 아트**로 출력합니다. 밝기 구간별로 ` .:-=#@` 같은 문자를 배정하면, 숫자 격자가 갑자기 "그림"으로 읽힙니다. 숫자→문자 규칙 하나 바꿨을 뿐인데 사람 눈에 도형이 보인다는 것 — 이것이 "이미지는 숫자다"의 체험판입니다.
- **[4]** 해상도 비유: 16×16 이미지를 8×8, 4×4 로 뭉개 가며(2×2 블록 평균) 텍스트 아트로 비교합니다. 타일이 줄면 어느 순간 원과 사각형이 구분 불가능해지는 지점을 눈으로 확인하세요.
- **[5]** 클래스별 도형 샘플 9장을 `outputs/shapes_grid.png` 로 저장합니다. 파일을 열어 보세요 — 지금까지 텍스트로 보던 것과 같은 배열입니다.

코드 핵심부는 `to_ascii()` 함수입니다. `int(v * (len(chars) - 1))` 한 줄로 밝기 0~1 을 문자 인덱스로 바꿉니다. 렌더링이란 결국 "숫자를 보기 좋은 기호로 바꾸는 규칙"임을 보여 주는 다섯 줄짜리 함수입니다.

## 6. 자주 하는 실수

- **`img[x, y]` 로 착각하기**: NumPy 이미지는 `img[행, 열]` 즉 `img[y, x]` 순서입니다. 가로 좌표를 먼저 쓰면 이미지가 90도 돌아간 듯한 버그를 만나게 됩니다.
- **값 범위 혼동**: 0~1 float 이미지와 0~255 정수 이미지를 섞어 쓰면 화면이 새하얗거나 새까맣게 나옵니다. 배열을 받으면 먼저 `min/max` 부터 찍어 보는 습관을 들이세요.
- **해상도 = 품질이라는 착각**: 해상도는 비용입니다. 과제가 요구하는 만큼만 쓰는 것이 실무의 기본입니다.
- **"컴퓨터가 도형을 안다"고 생각하기**: 지금 단계의 컴퓨터에게는 0.0 과 1.0 의 배열이 있을 뿐입니다. 숫자 배열에서 "도형"이라는 의미를 뽑아내는 것이 이 강의의 나머지 11개 레벨이 하는 일입니다.
