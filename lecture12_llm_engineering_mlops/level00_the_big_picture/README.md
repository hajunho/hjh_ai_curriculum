# Lecture 12 · Level 00 — 모델을 만든다는 것 — 전체 지도

> ChatGPT 같은 모델이 공장에서 제품 나오듯 어떤 라인을 거쳐 만들어지는지, 단계별 입력·출력·비용을 한눈에 잡는 강의입니다.

**난이도** ⭐ / **선행** 없음 (lecture11 수강 권장) / **예상 시간** 30분

## 1. 왜 배우나 — 비즈니스 관점

지금까지의 강의에서 여러분은 LLM(대형 언어 모델)을 "쓰는" 법을 배웠습니다. 이번 강의부터는 관점을 바꿔서, 그 모델이 "만들어지는" 과정을 미니어처로 직접 재현해 봅니다. 왜 비전공 직장인이 여기까지 알아야 할까요?

첫째, 의사결정 때문입니다. "우리 회사 전용 모델을 만들자"는 제안이 나왔을 때, 그것이 수백억 원짜리 사전학습을 뜻하는지, 수십만 원짜리 파인튜닝을 뜻하는지 구분하지 못하면 예산도 일정도 세울 수 없습니다. 실제로 기업에서 "자체 LLM"이라고 부르는 것의 대부분은 공개 모델 위에 뒷단계 몇 개만 얹은 것입니다.

둘째, 협업 때문입니다. AI 팀이 "지금 SFT 중이고 다음 주에 DPO 들어갑니다"라고 말할 때, 그것이 공장 라인의 어느 공정에 해당하고 무엇이 산출되는지 알면 대화의 질이 완전히 달라집니다.

셋째, 채용 시장 때문입니다. LLM 엔지니어링을 "지도" 수준에서라도 설명할 수 있는 비개발 직군은 아직 드뭅니다. 이 레벨은 그 지도를 그려 드리는 시간입니다.

## 2. 비유로 이해하기

LLM 제작은 자동차 공장과 놀랄 만큼 닮았습니다.

- **사전학습(Pretraining)** 은 제철소입니다. 철광석(웹의 원시 텍스트 수조 토큰)을 용광로에 넣고 몇 달간 녹여 강철(언어의 기본기)을 뽑아냅니다. 전체 비용의 대부분이 여기서 나가고, 한 번 망치면 처음부터 다시 해야 합니다.
- **어닐링(Annealing)** 은 열처리 공정입니다. 학습 막바지에 교과서급 고품질 데이터만 골라 천천히 마무리하면, 같은 강철도 훨씬 단단해집니다.
- **SFT(지시학습)** 는 조립 라인입니다. 강철 덩어리는 아직 자동차가 아니듯, 사전학습만 마친 모델은 "이어쓰기"만 할 뿐 지시를 따르지 못합니다. 매뉴얼(지시-응답 예제)대로 조립해야 비로소 제품 꼴이 납니다.
- **선호정렬(DPO)** 은 품질검사(QC) 라인입니다. 두 답변 중 고객이 더 좋아한 쪽을 골라 마감 품질을 다듬습니다.
- **양자화(Quantization)** 는 포장 공정입니다. 완성차를 컨테이너에 실으려면 부피를 줄여야 하듯, 14GB짜리 모델을 4GB로 압축해 배송 가능하게 만듭니다.
- **배포(Serving)** 는 물류센터입니다. 여기서부터는 "만드는 비용"이 아니라 주문량에 비례하는 "운영비"의 세계입니다.

이 여섯 공정을 순서대로 기억하세요. 이번 강의의 level01~11이 정확히 이 라인을 따라갑니다.

## 3. 핵심 개념

### 3-1. 두 개의 큰 국면: 사전학습 vs 사후학습

- **사전학습**: 인터넷 규모의 텍스트로 "다음 토큰 맞히기"만 시킵니다. 결과물인 base 모델은 언어의 통계적 구조를 알지만, 질문에 답하라는 개념이 없습니다.
- **사후학습(post-training)**: SFT와 선호정렬을 묶어 부르는 말입니다. 데이터는 수만~수십만 건으로 사전학습의 수만분의 일이지만, 사용자가 체감하는 "말귀"는 대부분 여기서 만들어집니다.

### 3-2. 비용 감각 — 6 × N × D 공식

학습에 필요한 연산량(FLOPs)은 대략 **6 × 파라미터 수(N) × 토큰 수(D)** 로 근사합니다. 7B(70억) 파라미터 모델을 2조 토큰으로 학습하면 약 8.4×10²² FLOPs. H200급 GPU 한 장의 실효 연산력으로 나누면 수만 GPU시간, 클라우드 요금으로 환산하면 수억 원 규모가 나옵니다. 반면 SFT는 같은 공식으로 계산해도 몇 GPU시간, 몇만 원 수준입니다. **단계마다 비용이 1만 배씩 차이 난다**는 감각이 이 레벨의 핵심입니다.

### 3-3. 체크포인트라는 이름의 반제품

각 공정의 산출물은 체크포인트(checkpoint)라는 파일입니다. base → base-annealed → sft → chat(정렬 완료) → int4(양자화) 순으로 이름이 붙으며, 허깅페이스 같은 모델 저장소에서 보는 `-base`, `-instruct`, `-int4` 접미사가 바로 이 공정 위치를 알려 주는 꼬리표입니다.

### 3-4. 왜 대부분의 회사는 중간부터 시작하나

사전학습이 총비용의 95% 이상을 차지하기 때문에, 공개 base 모델(무료)을 받아 SFT/DPO/양자화만 수행하는 것이 업계 표준 전략입니다. 이 강의의 실습도 같은 구조입니다. level04에서 미니 base 모델을 한 번 만들어 본 뒤, 이후 레벨은 전부 그 위에 얹는 공정입니다.

| 단계 | 데이터 규모 | 비용 자릿수 |
|---|---|---|
| 사전학습 | 수조 토큰 | 수억~수천억 원 |
| 어닐링 | 수백억 토큰 | 수백만~수천만 원 |
| SFT | 수만~수십만 건 | 수만~수백만 원 |
| DPO | 수만 쌍 | 수만~수백만 원 |
| 양자화 | 학습 없음 | 수천~수만 원 |

## 4. 실습 — main.py

실행 방법은 다음과 같습니다.

```bash
cd lecture12_llm_engineering_mlops/level00_the_big_picture
python3 main.py
```

프로그램은 가상의 7B 모델이 공장 라인 6단계를 통과하는 과정을 시뮬레이션합니다. `[1]`~`[6]` 단계마다 **비유·입력·출력**을 먼저 보여 주고, 학습 단계라면 `train_cost()` 함수가 6 × N × D 공식으로 FLOPs → GPU시간 → 달러를 차례로 환산해 출력합니다. loss 값이 단계마다 조금씩 내려가는 모습도 흉내 내는데(시드 고정), 사전학습에서 10.5 → 2.1로 크게 떨어지고 이후 단계는 소폭만 움직이는 것이 실제 학습 로그의 전형적인 모양입니다.

마지막 `[7]` 요약에서 총 제작비 중 사전학습 비중이 97% 이상임을 확인하세요. 코드에서 눈여겨볼 부분은 세 곳입니다. 상단의 사양 상수(PARAMS, PRETRAIN_TOKENS 등)는 여러분이 바꿔 볼 실험 손잡이이고, `train_cost()`는 이 강의 내내 다시 쓸 비용 근사식이며, stages 리스트는 이 강의 전체의 목차이기도 합니다.

## 5. 직접 해보기

1. **(쉬움)** PARAMS를 70e9(70B)로 바꿔 실행해 보세요. 총비용이 몇 배가 되는지, 사전학습 비중은 어떻게 변하는지 관찰해 보세요. (힌트: 공식이 N에 비례하므로 학습 비용은 정확히 10배가 됩니다.)
2. **(보통)** GPU_PRICE를 국내 클라우드 시세로 바꾸고, MFU(실효 효율) 0.4를 0.25로 낮춰 보세요. 같은 모델인데 견적이 얼마나 벌어지나요? (힌트: MFU는 GPU_FLOPS 상수 안의 0.40입니다. 실무 견적이 회사마다 다른 이유가 이 두 변수입니다.)
3. **(도전)** stages 리스트에 "안전성 평가(Red-teaming)" 단계를 배포 앞에 추가해 보세요. 입력·출력·비유를 직접 지어 보면 파이프라인 구조가 손에 익습니다. (힌트: tokens=None인 단계를 참고하면 학습 없는 단계를 쉽게 넣을 수 있습니다.)

## 6. 자주 하는 실수

- **"파인튜닝 = 모델 제작"으로 착각**: 뉴스에서 "자체 모델 개발"이라는 표현을 보면 어느 공정부터 했는지 따져 보세요. 대부분 SFT 이후만 수행한 것입니다.
- **비용을 단계 구분 없이 뭉뚱그리기**: "LLM 학습은 수백억"이라는 말은 사전학습에만 해당합니다. 뒷공정은 노트북 수준 예산으로도 가능합니다.
- **양자화를 학습의 일종으로 오해**: 양자화는 다 만든 모델의 숫자 표현만 바꾸는 변환 작업입니다. 새로 배우는 것이 없으므로 몇 시간이면 끝납니다.
- **배포를 "완성"으로 여기기**: 배포 순간부터 비용 구조가 고정비에서 사용량 비례 운영비로 바뀝니다. 견적서에 서빙 비용 줄이 빠져 있으면 그 견적은 미완성입니다.
