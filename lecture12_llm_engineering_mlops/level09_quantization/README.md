> 고화질 원본 대신 "적당한 화질"로 저장해 모델을 4~8배 가볍게 만드는 기술, 양자화를 직접 구현합니다.

## 1. 왜 배우나 — 비즈니스 관점

앞 레벨까지 우리는 모델을 학습시키는 과정을 따라왔습니다. 그런데 학습이 끝난 모델을 실제 서비스에 올리려는 순간 현실적인 벽을 만납니다. 바로 크기입니다. 70억 파라미터짜리 모델을 fp32(32비트 부동소수점)로 저장하면 약 28GB입니다. 웬만한 서버 GPU 한 장에도 다 안 들어가고, 노트북에서는 꿈도 못 꿉니다.

양자화(quantization)는 이 문제를 정면으로 해결합니다. 파라미터 하나를 4바이트 대신 1바이트(int8)나 0.5바이트(int4)로 저장하면 같은 모델이 7GB, 3.5GB로 줄어듭니다. 성능 손실은? 놀랍게도 대부분의 경우 거의 없습니다. 요즘 노트북에서 오픈소스 LLM이 돌아가는 것, API 요금이 계속 내려가는 것, 스마트폰에 AI 비서가 내장되는 것 — 전부 양자화 덕분입니다.

비즈니스 관점에서 양자화는 곧 비용입니다. 같은 서비스를 GPU 4장 대신 1장으로 돌릴 수 있다면 인프라 비용이 4분의 1이 됩니다. "우리 회사 데이터로 만든 모델을 사내 서버에서 돌리고 싶다"는 요구가 나올 때, 가능 여부를 가르는 것이 바로 이 기술입니다.

## 2. 비유로 이해하기

스마트폰으로 찍은 원본 사진은 한 장에 10MB가 넘습니다. 그런데 메신저로 보내면 자동으로 압축되어 500KB가 되지요. 화질을 자세히 들여다보면 미세한 차이가 있지만, 일상적으로 보기에는 거의 구분이 안 됩니다. 양자화가 정확히 이것입니다. 가중치라는 "사진"을 살짝 낮은 해상도로 다시 저장하는 것입니다.

조금 더 정확한 비유는 자로 재기입니다. fp32는 0.0001mm 단위까지 재는 정밀 자이고, int8은 1mm 단위 눈금자입니다. 책상 길이를 재는 데 0.0001mm 정밀도는 필요 없습니다. 1mm 자로 재도 책상은 책상입니다. 다만 눈금자의 범위를 어디까지로 잡을지가 중요합니다. 30cm 자로 3m 책상을 재려면 눈금을 10배 늘려야 하고, 그러면 한 눈금이 1cm가 되어 오차가 커집니다. 이것이 실습에서 확인할 scale(눈금 간격)의 개념입니다.

그리고 반에서 키를 재는데 한 명만 2m 30cm 라면? 그 한 명 때문에 눈금 범위를 크게 잡으면 나머지 학생들의 키가 뭉개집니다. 그래서 "모둠별로 자를 따로 쓰자"는 아이디어가 나오는데, 이것이 블록 양자화입니다.

## 3. 핵심 개념

### 3.1 대칭 양자화 공식

가장 기본이 되는 int8 대칭 양자화는 딱 두 줄입니다.

```
scale = max(|w|) / 127
q     = round(w / scale)      # -127 ~ 127 의 정수
복원   = q × scale
```

가중치 중 절댓값이 가장 큰 값이 127에 오도록 눈금을 정하고, 모든 값을 그 눈금의 정수배로 반올림합니다. 복원할 때는 정수에 scale을 다시 곱합니다. 반올림에서 생기는 차이가 양자화 오차이며, 최대 오차는 scale의 절반입니다.

### 3.2 비트 수와 메모리

| 포맷 | 파라미터당 크기 | 70억 파라미터 모델 | 표현 단계 수 |
|---|---|---|---|
| fp32 | 4바이트 | 28 GB | 사실상 연속 |
| fp16 | 2바이트 | 14 GB | 사실상 연속 |
| int8 | 1바이트 | 7 GB | 255단계 |
| int4 | 0.5바이트 | 3.5 GB | 15단계 |

int8까지는 성능 손실이 거의 없고, int4부터는 눈금이 15개뿐이라 요령이 필요합니다.

### 3.3 이상치와 블록 양자화

학습된 모델의 가중치에는 가끔 유난히 큰 이상치(outlier)가 섞여 있습니다. 텐서 전체에 scale 하나만 쓰면 이상치 하나가 눈금을 키워 나머지 수만 개 값의 정밀도를 망칩니다. 해결책은 가중치를 32개, 64개 단위 블록으로 잘라 블록마다 scale을 따로 두는 것입니다. scale 저장 공간이 조금 늘지만 오차는 크게 줄어듭니다.

llama.cpp가 쓰는 GGUF 포맷이 바로 이런 블록 양자화 가중치를 담는 배포용 파일 형식입니다. "Q4_K_M" 같은 이름은 "4비트, 블록 양자화 방식 K" 정도로 읽으면 됩니다. 실습에서는 이 아이디어를 numpy로 직접 만들어 봅니다.

### 3.4 언제 어떤 정밀도를 쓰나

- 학습: fp16/bf16 (혼합 정밀도) — 기울기 계산에는 어느 정도 정밀도가 필요합니다.
- 서버 추론: int8 — 손실 거의 없이 비용 절반 이하.
- 개인 PC·엣지: int4 — 약간의 품질 저하를 감수하고 메모리 우선.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture12_llm_engineering_mlops/level09_quantization
python3 main.py
```

출력 단계별 안내:

- **[1]** 다섯 개짜리 작은 배열로 양자화→복원 과정을 눈으로 확인합니다. 원본 0.82가 정수 80이 되었다가 0.8189로 돌아오는 것, 최대 오차가 scale의 절반 이하인 것을 확인해 보세요.
- **[2]** 파라미터 100만 개 기준으로 fp32/fp16/int8/int4의 저장 크기를 비교합니다.
- **[3]** tiny_corpus로 문자 단위 초소형 언어모델(약 3.3만 파라미터)을 400스텝 학습합니다. 수 초면 끝납니다.
- **[4]** 학습된 가중치 전체를 int8로 양자화했다가 복원한 모델의 평가 loss를 원본과 비교합니다. 소수 넷째 자리까지 같게 나오는 것이 핵심 관찰입니다.
- **[5]** int4로 더 줄였을 때의 loss 증가를 보고, 이상치가 든 배열에서 텐서 전체 scale 방식과 64개 블록 방식의 복원 오차를 비교합니다. 블록 방식이 수 배 정확한 것을 확인합니다.
- **[6]** 포맷별 크기·loss 요약 표로 마무리합니다.

코드 핵심부는 `quantize()` 함수입니다. `scale = |w|.max() / 127` 한 줄과 `round(w / scale)` 한 줄이 전부입니다. 거대해 보이는 양자화 기술의 뼈대가 이렇게 단순하다는 것, 그리고 `apply_quant()`가 모델의 모든 파라미터에 "양자화→복원"을 적용해 성능 영향을 측정하는 실험 방법을 눈여겨보세요.

## 5. 직접 해보기

1. **(기본)** `quantize(w, bits)`의 `bits`를 2로 바꿔 int2 양자화를 실험해 보세요. 눈금이 3단계뿐일 때 loss가 얼마나 무너지는지 확인해 보세요. 힌트: [5] 단계의 `quantize(a, 4)`를 `quantize(a, 2)`로 바꾸면 됩니다.
2. **(중급)** 블록 크기를 16, 64, 256으로 바꿔 가며 이상치 배열의 복원 오차가 어떻게 변하는지 표로 만들어 보세요. 힌트: 블록이 작을수록 정확하지만 scale 저장 공간이 늘어나는 트레이드오프를 함께 계산해 보면 좋습니다(블록당 fp32 scale 1개 = 4바이트).
3. **(도전)** 지금은 가중치 최댓값을 그대로 scale에 씁니다. 이상치를 상위 0.1% 지점 값으로 잘라내고(clipping) 양자화하면 오차가 어떻게 변할까요? `np.percentile`로 구현해 비교해 보세요. 힌트: 이상치는 큰 오차를 갖게 되지만 나머지 99.9%가 정확해집니다.

## 6. 자주 하는 실수

- **양자화하면 계산도 정수로 한다고 오해하기.** 이 실습처럼 "저장만 정수, 계산은 복원 후 실수"인 방식도 널리 쓰입니다. 진짜 정수 연산까지 하려면 하드웨어 지원이 필요합니다.
- **scale 없이 그냥 반올림하기.** `round(w)`만 하면 0.5보다 작은 가중치가 전부 0이 되어 모델이 망가집니다. 반드시 눈금(scale)을 먼저 정해야 합니다.
- **int8에서 손실이 없다고 int4도 안심하기.** 비트가 하나 줄 때마다 눈금 수는 절반이 됩니다. int4부터는 블록 양자화 같은 보정 기법이 사실상 필수입니다.
- **양자화 후 성능 측정을 생략하기.** 모델·데이터마다 민감도가 다릅니다. 이 실습의 [4]~[5]처럼 반드시 같은 평가 지표로 전/후를 비교하는 습관을 들이세요.
- **fp16과 int8을 혼동하기.** fp16은 여전히 부동소수점(눈금 간격이 값 크기에 따라 변함)이고, int8은 고정 눈금입니다. 압축 원리가 다릅니다.
