# Lecture 12 · Level 06 — 파인튜닝과 LoRA

> 이미 배운 모델의 뇌는 그대로 두고, 얇은 "포스트잇 어댑터"만 덧붙여 새 업무를 가르치는 기술을 직접 구현합니다.

**난이도** ⭐⭐⭐⭐ / **선행** level04, level05 / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

level05에서 계산해 봤듯이, 대형 모델을 처음부터 학습하는 비용은 수십억 원 단위입니다. 하지만 실무에서 우리가 원하는 것은 대개 "우리 회사 말투로 답해라", "우리 제품 용어를 써라" 같은 작은 조정입니다. 이럴 때 모델 전체를 다시 학습하는 것(전체 파인튜닝, full fine-tuning)은 비용도 크고, GPU 메모리도 몇 배로 필요하며, 고객사마다 수백 GB짜리 모델 사본을 따로 보관해야 합니다.

LoRA(로라, Low-Rank Adaptation)는 이 문제를 해결한 기법입니다. 원본 가중치는 전혀 건드리지 않고, 아주 작은 "보정 행렬" 두 개만 학습합니다. 학습 파라미터가 전체의 1~3% 수준으로 줄어들기 때문에, 소비자용 GPU 한 장으로도 수십억 파라미터 모델을 파인튜닝할 수 있게 되었습니다. 오늘날 기업의 LLM 커스터마이징 대부분이 LoRA 계열(QLoRA 포함)로 이루어집니다. "우리 데이터로 모델을 튜닝해 주세요"라는 요청을 받았을 때 견적과 방식을 판단하려면 이 원리를 알아야 합니다.

## 2. 비유로 이해하기

회사에 20년 경력의 베테랑 직원(사전학습된 모델)이 새로 합류했다고 상상해 보세요. 이 사람은 일반 업무는 완벽하지만, 우리 회사의 보고서 양식과 결재 말투는 모릅니다.

- **전체 파인튜닝** = 이 사람을 다시 대학부터 재교육시키는 것. 회사 말투는 배우겠지만, 시간과 비용이 엄청나고, 잘못하면 원래 잘하던 것까지 잊어버립니다(파괴적 망각).
- **LoRA** = 이 사람의 모니터에 "우리 회사에서는 이렇게 씁니다"라는 포스트잇 몇 장을 붙여 주는 것. 본인의 지식(원본 가중치)은 그대로이고, 포스트잇(어댑터)만 추가됩니다. 다른 부서로 옮기면 포스트잇만 떼고 다른 것을 붙이면 됩니다.

포스트잇이 작아도 효과가 있는 이유가 LoRA의 핵심 통찰입니다. "회사 말투로 바꾸기" 같은 조정은 사실 몇 가지 단순한 규칙("~했다를 ~했소로")이라서, 거대한 수정이 아니라 **낮은 차원의 작은 수정**만으로 충분하다는 것입니다.

## 3. 핵심 개념

### 3-1. 저랭크 분해 — 큰 행렬의 작은 수정

전체 파인튜닝은 가중치 행렬 W(예: 4096×4096, 약 1,678만 개 숫자)를 W + ΔW 로 바꿉니다. LoRA의 발견은, 이 변화량 ΔW 가 사실상 "낮은 랭크(low-rank)" — 즉 훨씬 적은 정보량으로 표현 가능하다는 것입니다. 그래서 ΔW 를 두 개의 얇은 행렬의 곱으로 대체합니다.

```
y = W·x  +  (α/r)·B·A·x        # A: r×4096, B: 4096×r, r은 4~64 정도
```

r=8이면 학습할 숫자는 4096×8×2 ≈ 6.5만 개 — 원래의 0.4%입니다. A 는 작은 무작위값, B 는 0으로 초기화하기 때문에 부착 직후에는 B·A = 0, 즉 원본과 완전히 같은 출력에서 출발합니다. 학습이 진행되면서 B·A 가 조금씩 "보정"을 배웁니다.

### 3-2. 어디에 붙이나

관례적으로 attention 의 Q·K·V·출력 프로젝션 선형층에 붙입니다(실습에서도 qkv 와 proj 에 부착). MLP 층까지 붙이면 표현력이 늘지만 파라미터도 늘어나는 트레이드오프가 있습니다.

### 3-3. 하이퍼파라미터 r 과 α

- **r (랭크)**: 포스트잇의 크기. 클수록 표현력이 늘지만 파라미터도 늘어납니다. 말투 교정 같은 가벼운 과제는 r=4~8, 새 도메인 지식 주입은 r=32~64를 씁니다.
- **α (알파)**: 보정항의 세기 배율. 보통 α = 2r 로 두고 실질 배율 α/r = 2 를 유지합니다.

### 3-4. 병합과 배포

학습이 끝나면 두 가지 배포 방식이 있습니다. (1) **병합(merge)**: W' = W + (α/r)·B·A 를 미리 계산해 하나의 가중치로 합치면, 추론 시 추가 연산이 전혀 없습니다. (2) **어댑터 분리 유지**: 원본 모델 하나에 고객사별 어댑터(수십 MB)를 갈아끼우며 서빙합니다. 어댑터 파일은 원본(수십 GB)의 1% 이하라서, 100개 고객사 커스터마이징도 저장 공간 걱정이 없습니다.

### 3-5. 한 걸음 더 — QLoRA

실무에서 자주 듣게 될 QLoRA 는 "원본 가중치를 4비트로 양자화해 얼려 두고(level09에서 배웁니다), 그 위에 LoRA를 붙이는" 조합입니다. 덕분에 노트북급 GPU로도 대형 모델 튜닝이 가능해졌습니다.

## 4. 실습 — main.py

실행:

```bash
cd lecture12_llm_engineering_mlops/level06_finetuning_lora
python3 main.py
```

약 10초 안에 다음 흐름이 출력됩니다.

- **[1]~[2]** hjh_data.tiny_corpus()(평서체 "~했다" 문장들)로 2층 미니 GPT(약 11만 파라미터)를 400스텝 사전학습합니다. 생성 샘플이 "~했다"체로 나오는지 확인하세요.
- **[3]** 새 말투 데이터(같은 문형이지만 어미가 "~했소"인 하오체)에 대한 loss 를 측정합니다. 약 1.26 — 베이스 모델은 하오체를 모릅니다.
- **[4]** 모델 전체를 동결(requires_grad=False)한 뒤, 각 블록의 qkv 와 proj 를 `LoRALinear` 로 감쌉니다. 출력에서 핵심 숫자를 보세요: 전체 파인튜닝이라면 111,232개, LoRA는 3,072개(2.76%)만 학습합니다.
- **[5]** LoRA만 300스텝 학습하면 하오체 loss 가 0.35 수준으로 떨어지고, 생성 샘플의 어미가 "~했소"로 바뀝니다. 베이스 가중치는 단 하나도 변하지 않았는데도요.
- **[6]** 병합 검증: W + scale·B@A 로 합친 일반 선형층과 어댑터 부착 층의 출력이 완전히 같음을 `torch.allclose` 로 확인합니다.

코드에서 가장 중요한 부분은 `LoRALinear.forward` 입니다. `self.base(x)` (동결된 원본) 더하기 `scale * (x @ A.T @ B.T)` (학습되는 보정) — 이 한 줄이 LoRA의 전부입니다.

## 6. 자주 하는 실수

- **B를 0으로 초기화하지 않음**: A, B 둘 다 무작위로 시작하면 부착 순간 모델 출력이 망가진 상태에서 학습을 시작하게 됩니다. "원본에서 출발"이 LoRA 안정성의 핵심입니다.
- **동결을 빼먹음**: 베이스를 동결하지 않으면 그냥 전체 파인튜닝에 어댑터만 얹은 셈이 되어 LoRA의 이점이 사라집니다. 학습 전 trainable 파라미터 수를 반드시 출력해 확인하는 습관을 들이세요.
- **학습률을 사전학습과 똑같이 사용**: LoRA는 파라미터가 적어 보통 전체 파인튜닝보다 큰 학습률(예: 1e-4 vs 1e-5 수준)을 씁니다. 미니 실습에서는 차이가 작지만 실전에서는 중요합니다.
- **어댑터만 저장해야 하는데 전체 모델을 저장**: LoRA의 장점은 수십 MB짜리 어댑터 파일입니다. state_dict 에서 A, B 만 골라 저장하는 것이 실무 관례입니다.
