# Lecture 12 · Level 07 — 지시학습(SFT)

> "이어쓰기 기계"인 베이스 모델에 챗 템플릿과 loss 마스킹으로 "질문에 답하는 법"을 가르칩니다.

**난이도** ⭐⭐⭐⭐ / **선행** level06 / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

여러분이 매일 쓰는 챗봇형 LLM은 사실 두 단계로 만들어집니다. 사전학습을 마친 베이스 모델(base model)은 인터넷 텍스트의 "다음 단어 이어쓰기"만 할 줄 압니다. "환불 규정을 알려줘"라고 입력하면 답을 하는 게 아니라, 그 문장 뒤에 올 법한 아무 텍스트를 이어 씁니다 — 예를 들어 비슷한 질문 목록을 계속 나열할 수도 있습니다.

이 이어쓰기 기계를 "질문하면 답하는 비서"로 바꾸는 공정이 지시학습(SFT, Supervised Fine-Tuning)입니다. 수만~수십만 개의 (지시, 모범 응답) 쌍을 만들어 모델에게 "이런 형식으로 입력이 오면 이런 형식으로 응답하라"를 가르칩니다. 기업이 자체 챗봇을 만들 때 "우리 회사 FAQ 데이터로 SFT 한다"는 말이 바로 이것이고, SFT 데이터의 품질이 챗봇 품질을 사실상 결정합니다. 데이터 몇 건으로 어떤 행동이 만들어지는지 감을 잡으면, 데이터 구축 예산과 일정 협상에서 훨씬 유리해집니다.

## 2. 비유로 이해하기

박학다식하지만 눈치가 없는 신입사원을 떠올려 보세요. 지식(사전학습)은 이미 충분합니다. 그런데 고객이 "배송 조회 어떻게 해요?"라고 물으면, 답을 하는 대신 배송에 관한 에세이를 쓰기 시작합니다. 이 신입에게 필요한 것은 지식이 아니라 **응대 역할극 훈련**입니다.

SFT는 role-play 대본 훈련입니다. "고객이 이렇게 말하면 → 당신은 이렇게 답한다"라는 대본 수백 개를 반복 연습시키는 것이죠. 이때 중요한 규칙이 하나 있습니다. 채점(loss 계산)은 **신입이 말해야 하는 부분에만** 합니다. 고객의 대사(프롬프트)는 신입이 생성할 부분이 아니므로, 그 부분을 잘 "예측"했는지는 채점하지 않습니다. 이것이 loss 마스킹입니다.

대본에는 무대 지시문도 필요합니다. "여기부터 고객 대사", "여기부터 당신 대사", "대사 끝" — 이것이 챗 템플릿의 특수 토큰(<|user|>, <|assistant|>, <|end|>)입니다.

## 3. 핵심 개념

### 3-1. 챗 템플릿(chat template)과 특수 토큰

모델에게 대화는 그냥 하나의 긴 토큰열입니다. 역할 구분은 특수 토큰으로 표시합니다.

```
<|user|>3 더하기 5는?<|assistant|>3 더하기 5는 8입니다.<|end|>
```

특수 토큰은 일반 글자와 겹치지 않는 **통째로 1개의 토큰**이어야 합니다. 실제 모델들의 템플릿 문법(ChatML 등)은 조금씩 다르지만 구조는 같습니다. 추론 시에는 `<|assistant|>`까지 채워 넣고 모델이 그 뒤를 생성하게 하며, `<|end|>`가 나오면 생성을 멈춥니다. SFT가 가르치는 것 중 하나가 바로 "응답이 끝나면 <|end|>를 내라"입니다 — 이것을 못 배우면 챗봇이 혼자 끝없이 말하게 됩니다.

### 3-2. loss 마스킹 — 응답에만 채점하는 이유

학습 데이터는 프롬프트+응답이 이어진 한 줄이지만, cross entropy 를 전체에 걸면 모델이 "사용자 질문을 예측하는 능력"에도 용량을 쓰게 됩니다. 심하면 사용자 말투를 흉내 내거나 질문을 되뇌는 버릇이 생깁니다. 그래서 프롬프트 구간의 정답 레이블을 -100(PyTorch cross_entropy 의 ignore_index)으로 바꿔 채점에서 제외합니다. 실습 코드의 핵심 두 줄입니다.

```python
Y[k, :] = -100                      # 기본은 전부 채점 제외
Y[k, plen-1:] = 응답 토큰들          # 응답(과 <|end|>)만 채점
```

인덱스가 plen-1 인 이유: x=ids[:-1], y=ids[1:] 로 한 칸 밀려 있어서, "응답 첫 토큰을 맞히는 예측"은 프롬프트 마지막 토큰(<|assistant|>) 위치에서 일어나기 때문입니다.

### 3-3. SFT 데이터의 3요소

실전 SFT 데이터를 만들 때는 (1) **다양성** — 같은 의도의 다양한 표현, (2) **모범성** — 응답은 그대로 따라해도 되는 품질이어야 함(모델은 응답을 문자 그대로 모방합니다), (3) **형식 일관성** — 템플릿·말투·종료 토큰의 일관성이 중요합니다. "쓰레기를 넣으면 쓰레기가 나온다"(level03)는 SFT에서 가장 극적으로 나타납니다. 나쁜 응답 100개가 좋은 응답 1만 개를 오염시킬 수 있습니다.

### 3-4. 형식 학습 vs 능력 학습

SFT가 실제로 가르치는 것은 주로 **형식과 행동 방식**입니다. 지식과 능력 대부분은 이미 사전학습에서 만들어져 있고, SFT는 그것을 꺼내 쓰는 인터페이스를 입힙니다. 그래서 실습의 미니 모델처럼 사전학습이 빈약하면, SFT 후에도 "형식은 완벽한데 내용이 틀리는" 답이 나옵니다. 이것이 실제 산업에서 베이스 모델의 크기를 따지는 이유입니다.

## 4. 실습 — main.py

실행:

```bash
cd lecture12_llm_engineering_mlops/level07_sft
python3 main.py
```

- **[1]** 장난감 지시 데이터 34쌍을 코드로 생성합니다: 인사(이름 8개), 덧셈(1~5 조합 중 a≠b만 — a=b는 시험용으로 남겨 둡니다), 재고 조회(6품목). 특수 토큰 4개를 포함한 글자 단위 토크나이저를 만듭니다.
- **[2]** tiny_corpus 로 베이스 모델을 300스텝 사전학습합니다.
- **[3]** 베이스 모델의 한계를 눈으로 확인합니다. "오늘 회사원이 "를 주면 그럴듯하게 이어쓰지만, 챗 템플릿에 "3 더하기 5는?"을 넣으면 코퍼스풍의 엉뚱한 이어쓰기가 나옵니다. **베이스 모델은 답하지 않고 이어씁니다.**
- **[4]** 챗 템플릿 한 줄과 loss 마스크(-는 채점 제외, #는 채점)를 나란히 출력합니다. 프롬프트 11토큰은 제외되고 응답 15토큰만 학습됨을 확인하세요.
- **[5]** 응답 부분만 채점하는 SFT를 700스텝 수행합니다. loss 가 0.004까지 떨어집니다.
- **[6]** 같은 지시에 대한 응답이 완전히 바뀝니다. "3 더하기 5는?" → "3 더하기 5는 8입니다." 그리고 <|end|>에서 스스로 멈춥니다. 본 적 없는 "4 더하기 4는?"에는 "4 더하기 4는 9입니다."처럼 **형식은 완벽하지만 내용이 틀린** 답이 나올 수 있습니다 — 3-4절에서 설명한, 작은 모델의 전형적 한계입니다.

## 6. 자주 하는 실수

- **특수 토큰을 글자로 쪼갬**: "<|user|>"를 일반 문자열로 인코딩하면 8글자 토큰이 되어 버립니다. 템플릿 구분자는 반드시 vocab 에 통째 토큰으로 등록해야 합니다. 실제 프레임워크에서 add_special_tokens 를 빼먹는 실수가 정확히 이것입니다.
- **한 칸 밀림(off-by-one)**: x=ids[:-1], y=ids[1:] 시프트 때문에 마스크 경계는 plen 이 아니라 plen-1 입니다. 경계가 한 칸 틀리면 <|assistant|> 직후 첫 토큰을 학습하지 못해 응답 시작이 불안정해집니다.
- **평가를 학습 데이터로만 함**: [6]처럼 본 적 없는 지시를 꼭 넣어 보세요. 학습 예시만 잘 답하는 것은 암기이지 능력이 아닙니다.
- **SFT 데이터에 나쁜 응답 방치**: 모델은 응답을 그대로 모방합니다. "모르겠어요 ㅋㅋ" 같은 응답이 섞이면 그 말투까지 배웁니다.
