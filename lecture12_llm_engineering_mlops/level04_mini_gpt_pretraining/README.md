# Lecture 12 · Level 04 — 미니 GPT 사전학습

> "다음 글자 맞히기"만 시켰는데 문법이 생겨납니다 — 2층짜리 트랜스포머를 밑바닥부터 만들어 직접 사전학습을 돌려 봅니다.

**난이도** ⭐⭐⭐⭐⭐ / **선행** Level 03, lecture08(딥러닝 기초) / **예상 시간** 70분

## 1. 왜 배우나 — 비즈니스 관점

이번 레벨은 이 커리큘럼 전체의 정점입니다. 여러분이 매일 쓰는 챗봇의 심장인 **사전학습(pretraining)** 을 미니어처로 직접 재현합니다. 물론 실제 대형 모델은 수천억 개 파라미터를 수조 개 토큰으로 몇 달간 학습하고, 우리는 11만 개 파라미터를 4만 글자로 약 15초 학습합니다. 규모는 수백만 배 차이지만 **원리는 글자 그대로 동일합니다.** 손실 함수도, 옵티마이저도, 어텐션 수식도 같습니다.

왜 비즈니스 직장인이 이걸 알아야 할까요? 첫째, **협상력**입니다. "우리 회사 전용 모델을 만들어 드립니다"라는 제안을 받았을 때, 사전학습·파인튜닝·프롬프트 엔지니어링 중 무엇을 말하는 건지 구분할 수 있으면 견적의 타당성을 판단할 수 있습니다(비용이 수천 배 차이 납니다). 둘째, **한계에 대한 감각**입니다. 모델이 왜 그럴듯한 거짓말(환각)을 하는지는 학습 목표를 알면 자명해집니다 — 모델은 "사실을 말하도록"이 아니라 "다음에 올 법한 토큰을 맞히도록" 학습되었기 때문입니다. 셋째, 앞으로 이어질 레벨(LoRA, SFT, DPO)이 전부 "이 사전학습된 모델을 어떻게 다듬는가"의 이야기라서, 이 레벨을 통과해야 나머지가 이해됩니다.

## 2. 비유로 이해하기

**사전학습은 갓난아기의 언어 습득과 같습니다.** 아기에게 문법책을 주는 사람은 없습니다. 아기는 그저 주변 어른들의 말을 엄청나게 많이 들을 뿐입니다. 그런데 어느 날부터 "밥 줘"가 아니라 "밥을 주세요"라고 말하기 시작합니다. 조사와 어순을 아무도 명시적으로 가르치지 않았는데도요. 통계적 패턴에 충분히 노출되면 규칙이 **저절로 내면화**됩니다. 언어모델도 똑같습니다. 우리는 "다음 글자를 맞혀 봐"라는 단 하나의 문제만 수백만 번 냅니다. 그 문제를 잘 풀려면 모델은 어쩔 수 없이 어휘를, 조사를, 어순을 배워야 합니다. 문법은 목표가 아니라 **부산물**로 생겨납니다.

또 하나의 비유는 **끝말잇기의 확장판**입니다. "어제 학생이 보고서를 ___" 다음에 올 말을 맞히려면, "보고서를"이 목적어라는 것과 목적어 뒤에는 동사가 온다는 것, 그리고 보고서는 "만들었다/정리했다"와 어울리고 "끓였다"와는 안 어울린다는 것까지 알아야 합니다. 다음 토큰 예측은 단순해 보이지만, 잘하려면 언어에 대한 거의 모든 지식이 필요한 문제입니다.

## 3. 핵심 개념

### 3-1. 학습 목표 — 다음 토큰 예측

입력 문장을 한 글자씩 밀어서 정답을 만듭니다. 입력이 "오늘 학생"이면 정답은 "늘 학생이"입니다. 즉 모든 위치에서 동시에 "다음 글자는?" 문제를 풉니다. 손실은 교차 엔트로피(cross entropy) — "정답 글자에 준 확률이 낮을수록 벌점"입니다. loss 값은 직관적으로 읽을 수 있습니다. 글자 종류가 54개일 때 완전 무작위 찍기의 loss는 ln(54) ≈ 4.0입니다. 학습 후 0.34까지 내려간다는 것은 모델이 다음 글자를 거의 확신에 가깝게 좁힌다는 뜻입니다.

### 3-2. 디코더 트랜스포머의 구조

우리 모델(TinyGPT)은 실제 GPT 계열과 같은 뼈대를 가집니다.

| 구성 요소 | 역할 | 비유 |
|---|---|---|
| 토큰 임베딩 | 글자 → 64차원 벡터 | 글자마다 명함 만들기 |
| 위치 임베딩 | "몇 번째 글자인가" 정보 | 명함에 좌석 번호 적기 |
| 셀프 어텐션 ×2층 | 앞 글자들 중 필요한 곳에 주목 | 회의에서 관련 발언자 쳐다보기 |
| MLP ×2층 | 모은 정보로 계산 | 듣고 나서 혼자 생각하기 |
| 출력층(head) | 벡터 → 54개 글자 점수 | 다음 글자 후보 채점표 |

핵심은 **인과 마스크(causal mask)** 입니다. 각 위치는 자기보다 앞에 있는 글자만 볼 수 있게 미래를 가립니다(하삼각 행렬). 이게 없으면 모델이 정답을 커닝하게 되어 학습이 무의미해집니다.

### 3-3. 학습 루프 — 4박자 반복

배치 뽑기 → 순전파(예측·loss 계산) → 역전파(각 파라미터의 책임 계산) → 옵티마이저 스텝(파라미터 살짝 수정). 이 4박자를 700번 반복합니다. 옵티마이저는 실제 LLM 학습의 표준인 AdamW를 씁니다. 대형 학습과 다른 점은 규모뿐입니다 — 실제로는 이 루프가 수십만 스텝, 수천 개 GPU에서 병렬로 돕니다.

### 3-4. 생성(디코딩) — 확률에서 문장으로

학습된 모델은 "다음 글자의 확률 분포"를 내놓을 뿐입니다. 문장을 만들려면 그 분포에서 글자를 하나 뽑고, 뽑은 글자를 입력 끝에 붙여 다시 예측하는 일을 반복합니다. 우리 코드는 temperature(분포를 뾰족/평평하게 조절)와 top-k(상위 k개 후보만 남기기) 샘플링을 씁니다. 챗봇 API의 `temperature` 파라미터가 바로 이것입니다.

### 3-5. 이번 실습에서 타협한 것

실제와 두 가지가 다릅니다. 첫째, Level 01에서 만든 BPE 대신 **글자 단위 토큰**을 씁니다(코퍼스가 작아 글자 단위가 더 안정적으로 학습됩니다). 둘째, 코퍼스가 반복 패턴이 강한 인공 문장이라 모델이 빨리 배웁니다. 진짜 웹 텍스트라면 같은 모델로는 어림도 없습니다 — 그 격차가 바로 다음 레벨(스케일링 법칙)의 주제입니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture12_llm_engineering_mlops/level04_mini_gpt_pretraining
python3 main.py
```

전체 실행은 CPU에서 15초 안팎입니다. 출력에서 다음을 관찰하세요.

- **[1]~[2]** 코퍼스 38,851글자, 글자 사전 54종, 모델 파라미터 111,158개가 준비됩니다.
- **[3] 학습 전 생성** — 완전한 무작위 글자 뒤죽박죽입니다. 이것이 출발점입니다.
- **[4] 학습 로그** — loss가 4.18(무작위 수준)에서 0.34로 급락합니다. **step 30의 중간 생성**을 눈여겨보세요: "학생님이 정리사원이"처럼 단어 조각은 배웠지만 아직 이어 붙이기가 서툰, 마치 아기의 옹알이 같은 단계입니다. step 200에서는 이미 완전한 문장을 씁니다.
- **[5] 학습 후 생성** — "오늘 개발자가 계획서를 만들었다"처럼 어순과 조사가 완벽한 문장이 나옵니다. 중요한 점: 이 문장들 상당수는 코퍼스에 그대로 있는 문장이 아니라 모델이 배운 패턴으로 **조합해 낸** 문장입니다.
- **[6] 체크포인트 저장** — `outputs/tiny_gpt.pt`에 가중치·글자사전·설정을 저장합니다. Level 06(LoRA), 07(SFT), 08(DPO)에서 바로 이 "사전학습된 베이스 모델"을 다듬는 이야기가 이어집니다.

코드에서 꼭 읽어야 할 핵심부는 `CausalSelfAttention.forward`(어텐션 점수 계산과 미래 가리기), `TinyGPT.forward`의 `cross_entropy` 한 줄(학습 목표 전부), 그리고 `generate`(한 글자씩 뽑아 붙이는 루프)입니다. 세 곳을 합쳐도 30줄이 안 됩니다.

## 5. 직접 해보기

1. **temperature 실험** — `sample_text` 호출부에서 `generate`의 temperature를 0.2와 1.5로 바꿔 보세요. 낮으면 가장 흔한 패턴만 반복하고, 높으면 창의적(?)이지만 문법이 무너집니다. (힌트: 챗봇 API에서 답변이 너무 뻔하거나 너무 산만할 때 조절하는 값이 바로 이것입니다.)
2. **모델 키우기** — `D_MODEL=128, N_LAYER=4`로 키우면 loss가 얼마나 더 내려가나요? 학습 시간은 몇 배가 되나요? (힌트: 파라미터 수와 시간을 함께 기록해 두세요. 다음 레벨의 스케일링 법칙 미리보기입니다.)
3. **인과 마스크 제거 실험** — `masked_fill` 줄을 주석 처리하고 학습해 보세요. loss가 비정상적으로 빨리 0 근처로 떨어지지만 생성은 엉망이 됩니다. 왜일까요? (힌트: 시험 중에 정답지를 보며 푼 학생은 점수는 높지만 실력은 없습니다.)

## 6. 자주 하는 실수

- **loss가 낮으면 무조건 좋다고 믿기** — 마스크 버그(미래 커닝)나 심한 데이터 중복이 있으면 loss는 낮은데 생성 품질은 형편없습니다. 반드시 생성 샘플을 눈으로 확인하세요.
- **train loss만 보기** — val loss가 함께 내려가야 일반화입니다. train만 내려가면 암기(과적합)입니다.
- **학습 도중 seed를 안 고정하기** — 재현이 안 되면 하이퍼파라미터 실험을 비교할 수 없습니다. `torch.manual_seed`는 실험의 기본기입니다.
- **작은 코퍼스에 큰 모델 쓰기** — 파라미터가 데이터보다 크면 통째로 외워버립니다. 모델 크기는 데이터 양과 균형을 맞춰야 합니다(다음 레벨 주제).
- **생성 문장을 '이해'의 증거로 착각하기** — 모델은 그럴듯한 다음 글자를 뽑을 뿐입니다. 이 사실을 기억하면 환각 현상이 이상하지 않게 느껴집니다.

## 다음 레벨 예고

우리 모델은 11만 파라미터로 15초 만에 배웠지만, 실제 모델은 왜 수천 개의 GPU로 몇 달을 학습할까요? 그 비용은 얼마일까요? Level 05에서는 모델 크기·데이터 양·컴퓨트의 삼각관계(스케일링 법칙)와 "파라미터의 약 20배 토큰"이라는 친칠라 직관을 배우고, GPU 시간을 전기료와 클라우드 비용으로 환산하는 견적 계산기를 만듭니다.
