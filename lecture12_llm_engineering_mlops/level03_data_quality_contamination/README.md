# Lecture 12 · Level 03 — 데이터 품질·중복 제거·오염 검사

> 쓰레기를 넣으면 쓰레기가 나옵니다 — 학습 데이터의 중복과 '시험문제 유출(오염)'을 n-gram으로 직접 탐지해 봅니다.

**난이도** ⭐⭐⭐⭐ / **선행** Level 02 (데이터 파이프라인·패킹) / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

LLM을 만드는 회사들이 가장 많은 인력과 돈을 쓰는 곳은 의외로 모델 코드가 아니라 **데이터 정제**입니다. 모델 아키텍처는 논문으로 공개되어 회사마다 큰 차이가 없지만, "어떤 데이터를 얼마나 깨끗하게 넣었는가"는 각 사의 영업 비밀이자 실력 차이의 원천입니다. 업계에서 오래된 격언인 GIGO(Garbage In, Garbage Out) — "쓰레기를 넣으면 쓰레기가 나온다" — 는 LLM 시대에 더 강력해졌습니다. 모델은 데이터에 있는 것만 배우기 때문입니다.

품질 문제 중 비즈니스 임팩트가 가장 큰 두 가지가 이번 레벨의 주제입니다. 첫째는 **중복(duplication)** 입니다. 웹에서 긁어온 데이터에는 같은 글이 수백 번 복사되어 있습니다. 같은 문서를 반복 학습하면 모델은 그 문서를 통째로 외워버리고(암기), 다양한 표현을 배울 기회를 잃으며, 학습 비용(GPU 시간 = 돈)만 낭비됩니다. 둘째는 **벤치마크 오염(benchmark contamination)** 입니다. 모델 성능을 평가하는 시험 문제가 학습 데이터에 섞여 들어가면, 모델은 "실력"이 아니라 "족보 암기"로 점수를 냅니다. 오염된 벤치마크 점수를 믿고 모델을 도입한 회사는 실제 업무에서 기대에 못 미치는 성능에 당황하게 됩니다. 모델 도입을 검토하는 실무자라면 "이 점수는 오염 검사를 거친 것인가?"라고 물을 수 있어야 합니다.

## 2. 비유로 이해하기

**중복 제거는 신입사원 교육 자료 정리와 같습니다.** 교육 자료 폴더에 같은 매뉴얼이 파일명만 다르게 200부 들어 있다고 상상해 보세요. 신입사원은 교육 시간의 대부분을 같은 매뉴얼을 200번 읽는 데 씁니다. 그 매뉴얼은 토씨 하나 안 틀리고 외우겠지만, 정작 다른 업무는 배우지 못합니다. 교육 담당자가 해야 할 일은 명확합니다 — 같은 자료는 한 부만 남기는 것.

**벤치마크 오염은 시험문제 유출입니다.** 자격증 학원이 "우리 학원 합격률 98%"라고 광고하는데, 알고 보니 교재에 실제 기출문제가 답과 함께 실려 있었다면 어떨까요? 그 합격률은 학원의 교육 실력을 증명하지 못합니다. 학생(모델)이 문제를 이해한 것이 아니라 답을 외운 것이기 때문입니다. LLM 세계에서는 웹을 통째로 긁다 보면 벤치마크 문제와 정답이 올라온 블로그·게시판까지 딸려 들어오는 일이 실제로 일어납니다. 그래서 진지한 모델 개발팀은 학습 데이터와 평가 문제 사이의 **겹침 검사(overlap check)** 를 반드시 수행합니다.

그런데 수십억 개 문서를 어떻게 서로 비교할까요? 문서 전체를 글자 단위로 비교하면 너무 느리고, 한 글자만 바뀐 "거의 복사본"은 놓칩니다. 여기서 쓰는 도구가 **지문(fingerprint)** 입니다. 사람 지문처럼, 문서에서 잘게 자른 조각(n-gram)들의 집합을 그 문서의 지문으로 삼으면, 지문이 많이 겹치는 두 문서는 내용도 거의 같다고 판단할 수 있습니다.

## 3. 핵심 개념

### 3-1. n-gram과 슁글(shingle)

n-gram은 텍스트를 길이 n의 연속 조각으로 자른 것입니다. "오늘 회의"를 문자 3-gram으로 자르면 "오늘 ", "늘 회", " 회의"가 됩니다. 문서에서 뽑은 n-gram들의 집합을 슁글(shingle) 집합이라고 부릅니다. 핵심 직관은 이렇습니다 — **문서가 조금만 달라져도 대부분의 n-gram은 그대로 남는다.** 따라서 두 문서의 n-gram 집합이 많이 겹치면 "거의 같은 문서"입니다.

### 3-2. 자카드 유사도(Jaccard similarity)

두 집합 A, B가 얼마나 겹치는지는 자카드 유사도로 잽니다.

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

교집합(둘 다 가진 조각) 크기를 합집합(둘 중 하나라도 가진 조각) 크기로 나눈 값입니다. 완전히 같으면 1, 하나도 안 겹치면 0입니다. 실무에서는 보통 0.7~0.8 이상이면 "근사 중복(near-duplicate)"으로 판정하고 한 부만 남깁니다.

| 상황 | 자카드 값 (대략) | 판정 |
|---|---|---|
| 완전 복사본 | 1.0 | 중복 — 제거 |
| 한두 단어만 바뀐 복사본 | 0.8~0.95 | 근사 중복 — 제거 |
| 같은 주제의 다른 글 | 0.1~0.3 | 유지 |
| 무관한 글 | 0.0~0.05 | 유지 |

### 3-3. 대규모에서는 MinHash — 개념만

문서가 수십억 개면 모든 쌍(수십억 × 수십억)을 비교할 수 없습니다. 실제 파이프라인은 **MinHash/LSH**라는 기법으로 "자카드 값이 높을 것 같은 쌍"만 후보로 추려 비교합니다. 슁글 집합을 몇 개의 해시 숫자로 요약해 두고, 요약이 비슷한 문서끼리만 정밀 비교하는 방식입니다. 이번 실습은 문서가 수십 개뿐이라 모든 쌍을 정직하게 비교하지만, 원리(슁글 + 자카드)는 대규모 기법과 동일합니다.

### 3-4. 오염 검사 — 시험문제가 교재에 있는가

오염 검사는 방향이 반대입니다. 중복 제거가 "학습 데이터 안에서" 겹침을 찾는다면, 오염 검사는 "평가 문제와 학습 데이터 사이"의 겹침을 찾습니다. 방법은 단순합니다 — 벤치마크 문항을 n-gram으로 자르고, 그 조각들이 학습 코퍼스에 얼마나 나타나는지 셉니다. 문항의 n-gram 중 상당 비율(예: 30% 이상)이 코퍼스에 그대로 있으면 "유출 의심"으로 플래그를 답니다. 오염이 확인되면 두 가지 대응이 있습니다. 학습 전이라면 해당 문서를 데이터에서 빼고(디컨태미네이션), 학습 후라면 오염된 문항을 평가에서 제외한 "클린 점수"를 따로 보고합니다.

### 3-5. 오염이 점수를 부풀리는 메커니즘

모델은 학습 데이터에 있던 문장을 통째로 외울 수 있습니다. 유출된 문항은 "본 적 있는 문장"이라 정답을 그대로 이어 쓰면 되므로 정답률이 비정상적으로 높아집니다. 이번 실습에서는 "외운 것만 맞히는 가상의 모델"로 이 효과를 시뮬레이션합니다 — 유출 문항 포함 점수와 제외 점수가 얼마나 벌어지는지 직접 확인해 보세요.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture12_llm_engineering_mlops/level03_data_quality_contamination
python3 main.py
```

출력 흐름은 다섯 단계입니다.

- **[1] 코퍼스 구성** — `hjh_data.tiny_corpus()`의 문장으로 문서 24개를 만들고, 일부러 "완전 복사본" 1개, "한 단어만 바꾼 근사 복사본" 1개, 그리고 벤치마크 문항이 통째로 섞인 "유출 문서" 1개를 심어 둡니다.
- **[2] 중복 탐지** — 모든 문서 쌍의 자카드 유사도를 계산해 임계값(0.7) 이상인 쌍을 보고합니다. 심어 둔 복사본 2개가 정확히 잡히는지, 유사도 값이 각각 1.0과 0.9 근처인지 확인하세요.
- **[3] 중복 제거** — 잡힌 쌍에서 뒤에 온 문서를 버리고 남은 문서 수를 보고합니다.
- **[4] 오염 검사** — 벤치마크 6문항 각각에 대해 "문항 n-gram이 코퍼스에 존재하는 비율"을 계산해 유출 의심 문항을 플래그합니다.
- **[5] 점수 부풀림 시연** — 외운 것만 맞히는 가상 모델로 오염 포함/제외 벤치마크 점수를 비교합니다. 유출 문항 하나 때문에 점수가 눈에 띄게 부풀어 오르는 것을 보게 됩니다.

코드의 핵심부는 세 함수입니다. `char_ngrams(text, n)`은 문자열에서 문자 n-gram 집합을 만들고, `jaccard(a, b)`는 두 집합의 자카드 유사도를 계산하며, `contamination_ratio(question, corpus_grams)`는 문항 n-gram이 코퍼스 n-gram 집합에 포함되는 비율을 구합니다. 세 함수 모두 10줄이 안 됩니다 — 대규모 파이프라인의 뼈대도 이 단순한 원리 위에 서 있습니다.

## 5. 직접 해보기

1. **임계값 실험** — `DUP_THRESHOLD`를 0.7에서 0.3으로 낮춰 실행해 보세요. 중복이 아닌 문서까지 잡히기 시작하나요? (힌트: 같은 단어 재료로 만든 문서들이라 낮은 임계값에서는 "같은 주제의 다른 글"도 걸립니다. 임계값은 정밀도와 재현율의 트레이드오프입니다.)
2. **n 크기 실험** — `char_ngrams`의 n을 5에서 2로 줄이면 자카드 값들이 전반적으로 어떻게 변하나요? 반대로 12로 키우면요? (힌트: n이 작을수록 흔한 조각이 많아져 모든 쌍의 유사도가 올라가고, n이 클수록 정확한 복사만 잡습니다.)
3. **교묘한 유출 만들기** — 유출 문서에 넣는 벤치마크 문항의 어순을 살짝 바꾸거나 조사를 수정한 뒤, 현재 검사기가 놓치는지 확인해 보세요. 놓친다면 어떻게 보완할 수 있을까요? (힌트: n을 줄이거나, 공백 제거 후 비교하거나, 단어 단위 n-gram을 병용하는 방법이 있습니다. 실제 팀들도 표현을 바꾼 오염은 잡기 어려워 골머리를 앓습니다.)

## 6. 자주 하는 실수

- **중복 제거를 학습 후에 고민하기** — 중복은 학습 전에 제거해야 합니다. 이미 외워버린 모델에서 암기를 빼낼 방법은 사실상 없습니다.
- **완전 일치만 검사하기** — 해시값 비교로는 한 글자만 달라도 놓칩니다. 근사 중복까지 잡으려면 반드시 n-gram + 유사도 방식이 필요합니다.
- **벤치마크 점수를 무조건 신뢰하기** — 발표 자료의 점수가 오염 검사를 거쳤는지, 클린 점수를 따로 보고하는지 확인하는 습관을 들이세요.
- **n-gram의 n을 아무렇게나 잡기** — 너무 작으면 오탐(흔한 표현이 다 걸림), 너무 크면 미탐(살짝 바뀐 복사를 놓침)이 늘어납니다. 데이터 특성에 맞춰 실험으로 정해야 합니다.
- **중복 = 무조건 나쁨으로 단정하기** — 고품질 데이터는 일부러 여러 번 학습(멀티 에폭)시키기도 합니다. 문제는 "의도하지 않은, 통제되지 않은" 중복입니다.
