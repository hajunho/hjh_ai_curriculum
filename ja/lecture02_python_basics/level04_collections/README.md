# Lecture 02 · Level 04 — リスト・タプル・辞書・集合

> 複数の値を入れる4種類の入れ物 — 順序のあるリスト、変更できないタプル、名札付きの引き出し (辞書)、重複のない袋 (集合) — の用途と選び方を学びます。
**難易度** ⭐⭐ / **前提** level03 / **目安時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

実務のデータは値1つではなく、まとまりでやって来ます。今月の販売記録のリスト、商品別の在庫数量表、
取引先の事業者番号の名簿。このまとまりをどの入れ物に入れるかによって、コードの長さと速度、
バグの発生率がまったく変わります。

たとえば「商品コードで在庫数量を探す」処理をリストで組むと毎回全体を探し回ることになりますが、
辞書 (dictionary) で組めば一発で取り出せます。「今週の来店顧客から重複を除く」のは
集合 (set) の1行で終わります。入れ物の選択は些細に見えますが、Excel で表をどう設計するかが
業務効率を左右するのと同じ問題です。このレベルでは在庫管理のミニ例題で
4つの入れ物をすべて使ってみて、選択基準を体に覚えさせます。

## 2. たとえ話で理解する

オフィスの備品管理にたとえてみましょう。

- **リスト (list) = 入庫記録台帳。** 入ってきた順に1行ずつ書きます。順序に意味があり、
  同じ品目が何度も現れることがあり、行の追加・修正・削除ができます。
- **タプル (tuple) = ラミネートした規格表。** 「A4用紙、500枚、25000ウォン」のように一度決めたら
  変えない値のまとまりです。修正できないのは欠点ではなく、**うっかりでも変えられないという安全装置** です。
- **辞書 (dict) = 名札付きの引き出し。** 「ボールペン」の引き出しを開ければ在庫37個が出てきます。
  引き出しの名前 (キー、key) さえ分かれば、上から順に探す必要なくすぐ取り出せます (値、value)。
- **集合 (set) = 重複を許さない袋。** 同じものを2回入れても1つしか残りません。
  「今週発注した品目の種類」のように、**あるかないか、と種類** だけが重要なときに使います。

## 3. 核心となる考え方

### 3.1 リスト — 順序のある一覧

```python
sales = [45000, 120000, 89000]
sales.append(56000)       # 末尾に追加
sales[0]                  # 最初の項目 (番号は0から!)
sales[-1]                 # 最後の項目
sales[1:3]                # スライス: 1番から3番の直前まで
len(sales), sum(sales), sorted(sales)   # 件数、合計、ソート版
```

インデックス (index) が0から始まること、スライスの終わりの番号は含まれないこと
(range と同じルール) を覚えてください。

### 3.2 タプル — 変更不可のまとまり

```python
product = ("P001", "ボールペン", 1200)   # (コード, 名前, 単価)
code, name, price = product              # アンパック: 一度に取り出す
```

タプルは作った後は項目を変えられません (不変、immutable)。座標・設定値・関数の
複数戻り値のように「セットで持ち歩く値」に使います。level03 で `for name, qty in orders:` と
取り出して使ったのが、まさにタプルのアンパック (unpacking) でした。

### 3.3 辞書 — キーで値を探す

```python
stock = {"ボールペン": 37, "A4用紙": 12, "ホッチキス": 4}
stock["ボールペン"]        # 37 (キーで即座に照会)
stock["蛍光ペン"] = 20     # 新しい項目を追加
stock.get("消しゴム", 0)   # なければ 0 を返す (KeyError 防止)
for item, qty in stock.items():   # キーと値のペアを巡回
    ...
```

存在しないキーを角かっこで照会すると `KeyError` になります。あるかどうか確信がなければ、
`in` で確認するか `get(キー, デフォルト値)` を使うのが実務の習慣です。

### 3.4 集合 — 重複除去と所属チェック

```python
visited = {"P001", "P002", "P001"}    # -> {"P001", "P002"} 重複は自動除去
"P001" in visited                      # 所属チェックが非常に速い
a & b, a | b, a - b                    # 積集合、和集合、差集合
```

「両方の名簿に載っている顧客」(積集合)、「発注したのに入庫していない品目」(差集合) のような
名簿の突き合わせ業務が、演算子1つで終わります。ただし、集合には順序がありません。

### 3.5 選択基準のまとめ

| 状況 | 入れ物 | イメージ |
|---|---|---|
| 順序のある記録、追加/修正が必要 | リスト | 入庫台帳 |
| 変わってはいけない値のまとまり | タプル | 規格表 |
| 名前 (キー) で高速に照会 | 辞書 | 引き出し |
| 重複除去、あるかないか、名簿の突き合わせ | 集合 | 袋 |

そして実務データの標準形は **「辞書のリスト」** です。
1行 (row) が辞書、表全体がリスト — Excel の表1枚がそのまま移された形であり、
lecture03 の pandas へ自然につながっていきます。

## 4. 実習 — main.py

実行方法:

```bash
cd lecture02_python_basics/level04_collections
python3 main.py
```

文具卸売店の在庫管理ミニ例題です。

- **[1] リスト**: 今日の入庫記録をリストに積み上げ、インデックス・スライス・ソートを実演します。
- **[2] タプル**: 商品規格表 (コード・名前・単価) をタプルにしておき、修正しようとするとエラーになることを
  安全に見せます (try で包んであるのでプログラムは止まりません)。
- **[3] 辞書**: 商品名 -> 在庫数量の引き出しを作って入出庫を反映し、
  `get` で存在しない商品を安全に照会します。
- **[4] 集合**: 今週の発注品目と入庫品目を突き合わせて「発注したのにまだ届いていない品目」を
  差集合で見つけます。
- **[5] 総合**: 「辞書のリスト」の形で在庫表を作り、繰り返しで
  在庫不足 (安全在庫未満) 品目の発注レポートを出力します。

[5] のデータの形 — `[{"name": ..., "qty": ..., ...}, {...}]` — が、この先すべての
データ講義で出会うことになる標準形なので、目に焼き付けておいてください。

## 5. やってみよう

1. **在庫の追加** — [3] の引き出しに「はさみ」の在庫15個を追加し、「ボールペン」の在庫を10個
   出庫 (減算) してみましょう。(ヒント: `stock["はさみ"] = 15`、`stock["ボールペン"] -= 10`)
2. **名簿の突き合わせ** — 先週の発注品目の集合をもう1つ作り、「2週連続で発注した品目」を

3. **品切れ間近の並べ替え** — [5] の在庫表を数量が少ない順に並べ替えて出力してみましょう。
   (ヒント: `sorted(inventory, key=lambda row: row["qty"])`。lambda は level10 で
   詳しく学ぶので、今は真似して書いてみるだけで大丈夫です。)

## 6. よくある間違い

- **インデックスは0から** — `items[1]` は2番目の項目です。「1番目」が必要なら `items[0]`。
- **存在しないキーの照会** — `stock["消しゴム"]` は消しゴムがなければ `KeyError` でプログラムが止まります。
  `stock.get("消しゴム", 0)` または `if "消しゴム" in stock:` を使いましょう。
- **リストのコピーの勘違い** — `b = a` はコピーではなく、同じリストに名札をもう1枚付けただけです。
  `b.append(...)` すると a も変わります。本当のコピーは `b = a.copy()`。
- **タプルなのに修正を試みる** — `product[2] = 1500` は `TypeError` です。変える必要のある値なら、
  最初からリストか辞書に入れましょう。
- **集合に順序を期待する** — 集合は入れた順序を保証しません。順序が必要なら
  `sorted(集合)` でソートしてリストとして受け取りましょう。
