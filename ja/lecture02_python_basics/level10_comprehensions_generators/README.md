# Lecture 02 · Level 10 — 内包表記・ジェネレーター・ラムダ・デコレーター入門

> 「リストから条件に合うものを選んで変換し、新しいリストへ」を1行で書く内包表記、データを一度に作らず必要なときに1件ずつ流すジェネレーター — Python らしいコードの4大表現を味わいます。
**難易度** ⭐⭐⭐⭐ / **前提** level09 / **目安時間** 60分

## 1. なぜ学ぶのか — ビジネスの視点

ここまで学んだ文法だけでも、あらゆるプログラムは書けます。ところが実務で他人のコード —
同僚のスクリプト、オープンソースの例、AI が生成してくれたコード — を開いてみると、
`[row["amount"] for row in rows if row["ok"]]` のような1行が押し寄せてきます。
これらの表現を知らなければ読めず、読めなければ直すこともできません。

もう一つ、データが大きくなったときの問題があります。1億件の取引ログをリストで丸ごと
メモリに載せると、コンピュータが止まります。ジェネレーター (generator) は「必要なときに1件ずつ」
流す方式でこの問題を解決し、大容量ストリーム処理という実務テクニックへの入り口になります。
このレベルの目標は文法の暗記ではなく、**読める目 + メモリの感覚** を手に入れることです。

## 2. たとえ話で理解する

**内包表記 = Excel のフィルタ+数式を一撃で。** 「売上シートから渋谷店の行だけを絞り込み、金額に
1.1 を掛けた新しいシートを作れ」。Excel ではフィルタをかけて数式をドラッグする2つの動作ですが、
言葉にすれば一文です。内包表記 (comprehension) は、その一文をそのままコードに写した
文法です: `[x * 1.1 for x in sales if x.store == "渋谷"]` — 「渋谷店の x それぞれについて
1.1 を掛けたもののリスト」。

**ジェネレーター = 蛇口。** リストは、ミネラルウォーターをペットボトル1億本にあらかじめ全部詰めて
倉庫 (メモリ) に積んでおく方式です。ジェネレーターは蛇口です — ひねるたびに1杯ずつ出てきて、
倉庫が要りません。月末の精算で「全部集めてから計算」ではなく
「流れてくる1件ごとに累積」する方式だと考えてください。

**ラムダ = 付箋の指示。** 正式なマニュアル (def の関数) を作るまでもない1行の指示 —
「金額順に並べ替えて」— を付箋に書いて手渡すのがラムダ (lambda) です。

**デコレーター = 決裁の判子。** 既存の文書 (関数) の中身には触れず、表に
「検討済」の判子を押して共通の手順 (時間記録、ログ) を上乗せする仕組みがデコレーター (decorator) です。

## 3. 核心となる考え方

### 3.1 リスト内包表記

```python
# ループ方式 (4行)
result = []
for x in sales:
    if x >= 100000:
        result.append(int(x * 1.1))

# 内包表記 (1行) — 意味: 「10万以上の x それぞれに 1.1 を掛けたリスト」
result = [int(x * 1.1) for x in sales if x >= 100000]
```

読む順序は **for から**: 「sales の各 x について → 条件に合えば → 前の式を計算して入れる」。
辞書バージョン `{k: v for ...}`、集合バージョン `{x for ...}` も同じ原理です。
ただし、条件が2つを超えたり式が複雑になったりしたら、**ループにほどいて書くほうが良い** です。
1行に詰め込んだ暗号文は、洗練されたコードではありません。

### 3.2 ジェネレーター — 必要なときに1つずつ

```python
def transaction_stream(n):
    for i in range(n):
        yield make_row(i)        # return の代わりに yield: 1件送り出して止まって待つ

for row in transaction_stream(100_000_000):   # 1億件でもメモリは1件分
    process(row)
```

`yield` のある関数は、呼び出してもすぐには実行されず、「蛇口」(ジェネレーターオブジェクト) を
返します。for が1周回るたびに次の yield までだけ実行され、値を1つ送り出して
止まります。全部をメモリに載せないので、大容量処理の標準テクニックです。
内包表記の角かっこを丸かっこに変えた `(x * 1.1 for x in sales)` は
ジェネレーター式 (generator expression) で、`sum(...)` に直接入れる使い方が定番です。
蛇口から出た水を元に戻せないように、**一度消費したら終わり** という点だけ注意してください。

### 3.3 ラムダ — 名前のない1行関数

```python
sorted(rows, key=lambda r: r["amount"], reverse=True)   # 金額基準の降順
max(rows, key=lambda r: r["amount"])                     # 最高売上の行
```

`lambda 引数: 戻り値の式` という形で、`sorted`/`max`/`min` の `key` 引数に「何を基準に?」を
渡すときが主な出番です。2行以上必要なら、素直に `def` で名前のある関数を作りましょう。

### 3.4 デコレーター — 関数を包む関数 (入門)

```python
@stopwatch                 # = report = stopwatch(report) の省略表記
def report():
    ...
```

デコレーターは「関数を受け取り、機能を上乗せした新しい関数を返す関数」です。
実行時間の計測、ログの記録、権限の確認のように、**複数の関数に共通で押す判子** に使います。
自分で作る機会は当分ありませんが、`@` の表記を読めなければ、実務のコードやフレームワークの
ドキュメントが読めません。

## 6. よくある間違い

- **内包表記の欲張りすぎ** — 条件3つ、ネスト2段の1行は誰にも読めません。
  「1行で短く」ではなく「一文として読めるか」が基準です。
- **ジェネレーターの再利用** — 一度消費したジェネレーターをもう一度回すと、空の結果になります。
  2回使うデータならリストで受けるか、ジェネレーターを作り直しましょう。
- **len() を試みる** — ジェネレーターは長さを事前に知りません。`len(gen)` は TypeError。
  件数が必要なら、流しながら数える必要があります。
- **ラムダにロジックを詰め込む** — 条件文の入った長いラムダは def に昇格させましょう。
  ラムダは「付箋」、マニュアルが必要なら正式な文書 (def) へ。
- **内包表記の中の変数が漏れると勘違い** — ループ変数 `x` は内包表記の外には漏れません
  (Python 3 基準)。外側の同名変数とは別物です。
