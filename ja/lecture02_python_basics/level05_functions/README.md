# Lecture 02 · Level 05 — 関数: 再利用できる業務手順

> 関数は、よく使う手順に名前を付けておき、「この仕事、お願いします」と委任する仕組みです。引数で仕事を渡し、戻り値で結果を受け取ります。
**難易度** ⭐⭐ / **前提** level04 / **目安時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

付加価値税の計算ロジックが、会社のコード6か所にコピーされているとしましょう。税率が変わったら
6か所すべてを探して直さなければならず、1か所でも見落とせば部署ごとに違う税額を計算する
事故が起きます。実務のバグの大きな要因が、この「コピー&ペーストされたロジックの不一致」です。

関数 (function) は、ロジックを **1か所に** 定義し、必要な場所ごとに名前で呼び出して使う仕組みです。
税率が変わっても関数の中の1行を直すだけで、すべての場所に反映されます。しかも `calc_vat(総額)` のように
名前がそのまま説明になり、コードが業務マニュアルのように読めるようになります。今回の実習では、税金・割引の計算が
あちこちにコピーされた「リファクタリング前」のコードと、関数で整理した「後」のコードを並べて実行し、
その差を確認します。

## 2. たとえ話で理解する

**業務委任のたとえ。** 課長が経費精算を自分でやらず、担当者に任せる場面を思い浮かべてください。

> 課長:「精算担当さん、この領収書の束 (入力)、精算をお願いします。」
> 担当者: (自分の席で自分のやり方で処理した後)「精算結果は32万ウォンです (出力)。」

ここでのポイントは3つです。

1. **名前** — 「精算担当」という役割の名前さえ知っていればいい。 → 関数名
2. **入力** — 領収書の束を手渡す。 → 引数 (argument)
3. **出力** — 結果の金額を受け取る。 → 戻り値 (return value)

そして重要なのは、課長は担当者が **どうやって** 計算するのかを知らなくてもいいことです。担当者の
机の上 (関数内部の変数たち) は担当者の領域で、課長の机とは混ざりません。
これがスコープ (scope、有効範囲) です。委任がうまく機能している組織ほど各自の机が
分離されているように、良い関数は外の世界と引数・戻り値だけでやり取りします。

## 3. 核心となる考え方

### 3.1 定義と呼び出し

```python
def calc_vat(amount):          # 定義: 「こういう手順がある」と登録するだけ
    return int(amount * 0.1)   # 戻り値: 結果を呼び出し元に返す

vat = calc_vat(50000)          # 呼び出し: 実際に仕事をさせる瞬間 (-> 5000)
```

`def` は定義 (define) であって実行ではありません。関数名の後ろにかっこを付けて **呼び出す** ことで
初めて本体が実行されます。`return` に到達すると関数は即座に終了し、値を持って戻ります。
`return` のない関数は `None` を返します。

### 3.2 引数 — 複数、名前指定、デフォルト値

```python
def calc_discount(amount, grade, rate=0.05):     # rate はデフォルト値付きの引数
    ...

calc_discount(100000, "VIP")                     # rate はデフォルト値 0.05 を使用
calc_discount(100000, "VIP", rate=0.1)           # 必要なときだけ指定
calc_discount(amount=100000, grade="VIP")        # キーワード引数: 順序不問、意味が明確
```

デフォルト値 (default) 付きの引数は「特別な指示がなければ標準規定どおり処理」に相当します。
**デフォルト値付きの引数は、ない引数の後に** 置かなければなりません。呼び出すときに名前を付ける
キーワード引数は、引数が3つを超えると可読性を大きく高めてくれます。

### 3.3 戻り値 — 複数を返す

```python
def summarize(sales):
    return sum(sales), len(sales), max(sales)    # タプルにまとまって返る

total, count, best = summarize(data)             # アンパックで受け取る
```

level04 のタプルのアンパックがここで真価を発揮します。「合計・件数・最大値」のようにセットで
出てくる結果を、一度に返せます。

### 3.4 スコープ — 関数の中の変数は関数の中だけ

```python
def process():
    temp = 100        # ローカル変数 (local): この関数の机の上にだけ存在

process()
print(temp)           # NameError! 外からは見えない
```

関数の中で作った変数は、関数が終わると消えます (ローカル変数)。関数の外の変数 (グローバル変数、
global) を関数の中で読むことはできますが、**書き換える癖はつけないでください。** どこで値が
変わったのか追跡できないコードになります。必要な値は引数で受け取り、結果は return で
返すこと — これが「各自の机」の原則です。

### 3.5 良い関数の条件

- **一つの仕事だけ** をします。「税金計算 兼 ファイル保存 兼 メール送信」の関数は3つに分割します。
- **名前が動詞句** です: `calc_vat`、`apply_discount`、`format_receipt`。
- **docstring** (関数の最初の行の説明文字列) で用途・引数・戻り値を1〜2行書きます。
- 同じコードを **2回コピーしそうになった瞬間** が、関数に切り出すタイミングです
  (DRY 原則: Don't Repeat Yourself)。

- **[3] 前後の比較**: 2つの方式の結果を並べ、どの注文でいくらずれたかを出力します。
- **[4] 関数文法のまとめ**: デフォルト値引数、キーワード引数、複数の戻り値、スコープ (NameError の再現) を
  短く実演します。

`calc_payment` が内部で他の2つの関数を呼ぶ構造 — 担当者がさらに実務者へ
委任する構造 — にも注目してください。関数はこのように階層で積み上がっていきます。

## 6. よくある間違い

- **print と return の混同** — print は画面に見せるだけで、値を返しません。
  `result = show_total(...)` としたのに `None` が入っていたら、その関数が return の代わりに print だけ
  していたのです。「計算は return、報告は print」と役割を分けましょう。
- **呼び出しのかっこの付け忘れ** — `calc_vat` だけでは関数そのもの (オブジェクト) で、`calc_vat(50000)` として
  初めて実行されます。
- **引数の順序ミス** — `calc_discount("VIP", 100000)` のように順序を入れ替えて渡すと、見当違いの
  計算になります。迷ったらキーワード引数で名前を付けて呼び出しましょう。
- **グローバル変数の書き換え** — 関数の中で外の変数をこっそり変えると、バグの追跡が悪夢になります。
  引数で受け取り、return で返しましょう。
- **デフォルト値にリストを使う** — `def f(items=[])` は、呼び出し同士がリストを共有してしまう有名な
  罠です。`def f(items=None)` として、関数の中で `if items is None: items = []` と処理しましょう。
