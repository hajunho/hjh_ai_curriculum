# Lecture 02 · Level 02 — 条件分岐: コンピュータに判断させる

> if/elif/else は「もし〜なら A、それ以外で〜なら B、どれでもなければ C」という社内決裁規定をコードに置き換えたものです。
**難易度** ⭐ / **前提** level01 / **目安時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

会社の仕事の多くは「規定に従って判断すること」です。出張経費が15万ウォン以下なら課長の専決、
超えたら部長決裁。在庫が安全在庫を下回ったら発注。顧客ランクが VIP なら追加割引。
こうした判断を人間がやると1日数百件で疲弊しますし、担当者ごとに基準がぶれます。

条件分岐 (conditional) を学べば、規定集をコードに置き換えて **判断そのものを自動化** できます。
一度正確に書いておけば、1件でも10万件でも同じ基準で即座に判定します。
このレベルの実習が、まさに「出張経費の自動承認判定機」です。Excel の `IF` 関数を
使ったことがあれば半分はすでに知っている内容で、Python ではもっと読みやすく書けます。

## 2. たとえ話で理解する

**決裁規定のたとえ。** 社内の経費規定に、こう書かれているとしましょう。

> 1. 金額が5万ウォン以下なら: 自動承認
> 2. それ以外で、金額が15万ウォン以下かつ領収書があれば: 課長専決
> 3. それ以外で、金額が50万ウォン以下なら: 部長決裁
> 4. 上のどれにも当てはまらなければ: 差し戻して説明を求める

この文書構造こそが条件分岐そのものです。「もし (if)」—「それ以外でもし (elif)」—
「どれでもなければ (else)」。そして重要なルールが一つ。決裁規定を上から読んでいって
**最初に該当した条項で止まる** のと同じように、Python も上から順に検査して、
最初に真 (True) になった枝を一つだけ実行して抜けます。7万ウォンの経費は
2番の条項に該当した瞬間、3番・4番はまったく読まれません。

## 3. 核心となる考え方

### 3.1 if / elif / else の基本骨格

```python
if amount <= 50000:
    result = "自動承認"
elif amount <= 150000 and has_receipt:
    result = "課長専決"
elif amount <= 500000:
    result = "部長決裁"
else:
    result = "差し戻し"
```

- 条件の後ろにはコロン (`:`) を付け、実行する行は **インデント (indentation)** 4文字で内側に書きます。
  Python はインデントで「どこまでがこの条件の管轄か」を区別します。かっこではなく
  インデントが文法であることが Python の特徴です。
- `elif` はいくつでもつなげられ、`else` は最後に一つだけ、省略も可能です。
- 上から順に検査して **最初に真になった枝を一つだけ** 実行します。だから条件の順序が
  そのまま規定の優先順位です。

### 3.2 比較演算子 — 真/偽を作る道具

| 演算子 | 意味 | 例 | 結果 |
|---|---|---|---|
| `==` | 等しい | `grade == "VIP"` | True/False |
| `!=` | 等しくない | `status != "キャンセル"` | True/False |
| `<` `<=` `>` `>=` | 大小比較 | `amount <= 150000` | True/False |

比較式の結果は常にブール値 (bool)、つまり `True` か `False` のどちらかです。
**`=` (代入) と `==` (比較) を絶対に混同しないでください。** 条件の場所に `=` を書くと文法エラーになります。

### 3.3 論理演算子 — 条件を組み合わせる

規定はたいてい複数条件の組み合わせです。

- `and` : 両方とも真なら真。「15万ウォン以下 **かつ** 領収書あり」
- `or` : どちらか一方でも真なら真。「役員 **または** 海外出張」
- `not` : 真/偽を反転。「領収書が **なければ**」 → `not has_receipt`

`and` は `or` より先に計算されるので、混ぜて使うときはかっこで意図を明示しましょう。
`(a or b) and c` と `a or (b and c)` はまったく別の規定です。

### 3.4 Python ならではの便利な書き方

```python
if 50000 < amount <= 150000:     # 範囲を数学のようにつなげて比較
if grade in ("VIP", "VVIP"):     # 複数の値のどれかに当てはまるか
if has_receipt:                  # == True と書く必要はない
```

`in` は「この値がリストの中にあるか」を問う演算子で、ランクやカテゴリの判定に特に便利です。

### 3.5 ネストと可読性

if の中に if を入れるネスト (nesting) も可能ですが、3段以上重なると規定集が迷路になります。
`and` で条件をまとめるか、例外ケースを先にはじいて (early return、level05 で扱います)
フラットに書くほうが読みやすくなります。「この規定集を初めて見る新人でも理解できるか」が基準です。

- **[4] 一括判定**: 経費申請6件を1つの判定ルールで処理し、承認/決裁/差し戻しの件数を集計します。

ほぼ 1:1 に対応していること、そして条件の順序 = 規定の優先順位であることを確認してください。

## 6. よくある間違い

- **`=` と `==` の混同** — `if grade = "VIP":` は `SyntaxError` です。判断は常に `==`。
- **インデントの不一致** — 同じブロックなのにある行は4文字、ある行は3文字だと
  `IndentationError` になります。エディタの自動インデントを信じて、タブとスペースを混ぜないでください。
- **条件の順序ミス** — `if amount <= 500000` を一番上に置くと、5万ウォンの経費まで全部
  「部長決裁」になります。狭い (厳しい) 条件を上に、広い条件を下に置きましょう。
- **`else` の乱用で規定に穴を開ける** — 最後の `else` は「上のすべての条項に該当なし」です。
  そこに「承認」を置くと、想定外のケースが全部承認されてしまいます。else には安全なデフォルト
  (差し戻し、保留、担当者確認) を置くのが原則です。
- **float を `==` で比較** — level01 の誤差のせいで `0.1 + 0.2 == 0.3` は False です。
  範囲比較か `round` 後の比較を使いましょう。
