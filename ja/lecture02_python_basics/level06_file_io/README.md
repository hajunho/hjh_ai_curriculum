# Lecture 02 · Level 06 — ファイルの読み書き

> open/with でテキストと CSV ファイルを読み書きできるようになると、プログラムが終わっても残る成果物 — レポート・データファイル — を作れるようになります。
**難易度** ⭐⭐ / **前提** level05 / **目安時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

これまでの実習は、結果を画面に出力するだけでした。プログラムが終われば変数も結果も
すべて消えます。実務は違います。売上データは CSV ファイルとして届き、
分析結果はファイルに保存してメールに添付したり、共有フォルダに上げたりしなければなりません。

ファイル入出力 (file I/O) は、プログラムと外の世界をつなぐ関門です。このレベルを終えれば、
「毎朝、取引明細の CSV を読んでサマリーレポートのテキストを作る仕事」を自動化できます —
実際、多くのビジネスパーソンが Python で最初に自動化する業務がまさにこれです。
そして、日本語データを扱う人が必ず出会う落とし穴、エンコーディング (encoding) 問題を
未然に防ぐ方法も学びます。

## 2. たとえ話で理解する

**書類キャビネットのたとえ。** ファイルを扱う手順は、オフィスのキャビネットからファイルフォルダを取り出して使うのと同じです。

1. キャビネットからフォルダを **取り出す** → `open("ファイル名")`
2. 読むか、内容を **書き足す** → `read()` / `write()`
3. 必ず元の場所に **戻す** → `close()`

フォルダを机に積んだまま退勤すると、次の人が使えず、紛失のリスクも生まれますよね。
ファイルも閉じないと内容が保存されなかったり、他のプログラムが開けなかったりします。
問題は、人間はうっかり忘れるということ。そこで Python は `with` という「自動返却システム」を
提供しています。`with` ブロックが終われば — 途中でエラーが起きて飛び出したとしても — ファイルは
自動的に閉じられます。図書館の自動返却機だと思ってください。

**エンコーディングは文字の保存規格** です。同じ日本語の文書でも、どの規格 (utf-8、Shift_JIS/cp932 など) で
保存したかによって、違う規格で開くと文字が化けます。海外規格のコンセントに、
アダプターなしでプラグを挿そうとする状況と同じです。今日の標準は utf-8 であり、
**開くときも書くときも常に `encoding="utf-8"` を明示する** ことが、日本語データを扱ううえでの生存ルールです。

## 3. 核心となる考え方

### 3.1 with open — 標準パターン

```python
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("第1四半期サマリー\n")    # \n は改行 (自動では入らない!)

with open("report.txt", "r", encoding="utf-8") as f:
    content = f.read()               # 全体を1つの文字列として
```

モード (mode) はまず3つだけ覚えてください。

| モード | 意味 | 注意 |
|---|---|---|
| `"r"` | 読み込み (デフォルト) | ファイルがなければ FileNotFoundError |
| `"w"` | 書き込み | **既存の内容を全部消して** 新しく書く |
| `"a"` | 追記 (append) | 既存の内容の末尾に書き足す (ログに最適) |

`"w"` が既存ファイルを丸ごと上書きしてしまうことは、実務で最も痛いミスなので二度強調しておきます。

### 3.2 行単位で読む

大きなファイルを `read()` で丸ごと読むと、メモリを使い果たします。ファイルオブジェクトは繰り返しに入れると
1行ずつ出てくるので、次が標準パターンです。

```python
with open("data.txt", encoding="utf-8") as f:
    for line in f:                   # 1行ずつ (メモリ節約)
        line = line.strip()          # 行末の改行文字を除去
        ...
```

`strip()` を忘れると、すべての行の末尾に見えない `\n` が付いたままになり、比較や変換が失敗します。

### 3.3 CSV — 表データの共通語

CSV (comma-separated values) はカンマで区切った表形式のテキストで、Excel・DB・Python が
どれも読める共通語です。カンマを自分で `split(",")` してもよいのですが、値の中にカンマが入っている場合
(「東京都, 渋谷区」) に壊れるので、標準ライブラリの `csv` モジュールを使います。

```python
import csv

with open("sales.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["date", "item", "amount"])       # ヘッダー
    writer.writerow(["2026-09-01", "ボールペン", 24000])

with open("sales.csv", encoding="utf-8", newline="") as f:
    for row in csv.DictReader(f):                     # 各行が辞書として!
        print(row["item"], row["amount"])
```

`DictReader` はヘッダーをキーにして、各行を辞書として返します — level04 で学んだ
「辞書のリスト」の形そのままです。CSV から読んだ値は **すべて文字列** なので、
数値は `int()`/`float()` の変換が必須です (level01 のあの落とし穴です)。
書き込み時の `newline=""` は、Windows で空行が挟まる問題を防ぐお約束です。

### 3.4 パスと os.makedirs

結果ファイルは、実習フォルダの下の `outputs/` のような決まった場所に集めます。

```python
import os
os.makedirs("outputs", exist_ok=True)     # フォルダがなければ作り、あれば静かに通過
```

スクリプトをどのフォルダから実行するかによって相対パスの基準が変わるので、
main.py では `os.path.dirname(__file__)` で「このファイルがあるフォルダ」基準のパスを作ります。

## 6. よくある間違い

- **`"w"` で大切なファイルを上書き** — 書き込みモードは既存の内容を即座に消します。
  元データのファイルは読むだけにして、結果は必ず **別の名前** で保存しましょう。
- **encoding の省略** — 省略すると OS のデフォルトが使われ、Windows (cp932) で作ったファイルが
  Mac/Linux で化けます。読み書きともに `encoding="utf-8"` を習慣に。
- **CSV の値を文字列のまま計算** — `row["amount"] + 100` は TypeError か、見当違いの
  文字列連結になります。必ず `int(row["amount"])`。
- **close せずに open** — `f = open(...)` とだけ書いて閉じないと、バッファが保存されないことが
  あります。常に `with` を使えば悩む必要がありません。
- **行末の `\n` の放置** — 読んだ行を比較する前に `strip()`。`"ボールペン\n" == "ボールペン"` は False です。
