# Lecture 02 · Level 00 — プログラミングとは何か

> プログラミングとは、コンピュータが誤解なく実行できるように仕事の手順を書き下すことです。そしてその手順は、順次・分岐・繰り返しの3つだけですべて表現できます。
**難易度** ⭐ / **前提** なし (lecture01 level03 を終えていればなお良いです) / **目安時間** 30分

## 1. なぜ学ぶのか — ビジネスの視点

会社で私たちは毎日「手順」を作り、それに従っています。新入社員のオンボーディングチェックリスト、
月末締めの処理手順、顧客クレーム対応マニュアル — すべて手順書です。プログラミング (programming) とは、
この手順書を、人間ではなくコンピュータが読んで実行できる形で書く仕事です。

一つだけ違いがあります。人間はマニュアルが多少あいまいでも「空気を読んで」補ってくれますが、
コンピュータは書かれたとおりにしか動きません。だからこそ、プログラミングを学ぶと2つの力が身につきます。
第一に、繰り返しの業務を丸ごとコンピュータに任せられるようになります。第二に、あいまいさのない手順を
設計する思考力が育ち、コードを書かない業務文書の質まで上がります。
このレベルでは、文法を暗記する前に「プログラムとは何か」という全体像をつかみます。

## 2. たとえ話で理解する

**レシピのたとえ。** カップ麺ではなく袋麺のレシピを思い浮かべてください。「水550mlを沸かす → 麺とスープを入れる →
4分30秒煮る」。上から下へ順番に実行されます。これが **順次 (sequence)** です。

レシピには分かれ道もあります。「辛いのが好きなら唐辛子を加え、そうでなければ加えない」。
条件によって違う道を進むこと、これが **分岐 (branch)** です。

そして「麺がほぐれるまでかき混ぜる」のように同じ動作を何度も行うのが **繰り返し (loop)** です。

驚くべきことに、世の中のすべてのプログラムはこの3つの組み合わせです。給与計算システムも、
スマホゲームも、チャットボットも、結局は順次・分岐・繰り返しを非常に多く、非常に精巧に積み上げたものです。
新しい文法に出会うたびに「これは3つのうちどれを楽にしてくれる道具なのか?」と問いかければ、
道に迷うことはありません。

**業務マニュアルのたとえ。** カフェのアルバイト初日に渡される注文処理マニュアルを考えてみましょう。
「注文を受ける → 支払金額を計算する → ポイント会員なら付与する → ドリンクを作る →
お客様が受け取るまで呼び出しベルを鳴らす」。このマニュアルをコンピュータの言語に置き換えたものが、
まさにプログラムです。今回の実習の main.py が、ちょうどこの仕事をします。

## 3. 核心となる考え方

### 3.1 プログラム = データ + 手順

プログラムは2つの要素でできています。扱う材料である **データ (data)** — 注文数、単価、
顧客名 — と、材料を加工する **手順 (procedure)** — 計算し、判断し、出力するステップです。
Excel にたとえると、セルに入っている値がデータで、数式とマクロが手順です。

### 3.2 順次 — 上から下へ

Python のコードは、特別な指示がなければ1行目から最後の行まで順番に実行されます。
順序が変われば結果も変わります。「割引を適用してから消費税を計算」と「消費税を計算してから割引を適用」で
金額が違ってくるのと同じです。

### 3.3 分岐 — 条件によって違う道へ

「もし〜ならば A、そうでなければ B」。Python では `if` という単語で書きます。詳しい文法は
level02 で学ぶので、今日は「プログラムが自分で判断するポイント」という概念だけつかめば十分です。

### 3.4 繰り返し — 同じ仕事を何度も

「リストにあるすべての注文について〜せよ」。Python では `for` という単語で書きます。
人間は100回繰り返せば疲れてミスをしますが、コンピュータは100万回でも同じ品質でやり遂げます。
自動化の恩恵の大部分は、ここから生まれます。

### 3.5 なぜコンピュータには正確に書かなければならないのか

新入社員に「適当にまとめて報告してください」と頼めば、なんとか結果は出てきます。
経験と常識で空白を埋めてくれるからです。コンピュータにはその常識がありません。
「売上を集計せよ」とだけ書いても、どのファイルの、どの列を、どんな基準で足すのか分からず
止まってしまいます。だからプログラミングの半分は「自分が知っている手順を、漏れなく、あいまいさなく
言葉にほどいて書き出す仕事」です。コードを書く前に、手順を日本語の文章として番号付きで書いてみる
習慣 (これを擬似コード (pseudocode) と呼びます) をつければ、文法を知らなくてもプログラムの
設計はすでに終わったも同然です。

### 3.6 プログラミング言語と Python

コンピュータが理解できる手順の表記法をプログラミング言語 (programming language) と呼びます。
その中でも Python は文法が英語の文章に近く、非エンジニアが学ぶのに最も取り組みやすいうえ、
データ分析・AI 分野の標準言語でもあるため、このカリキュラム全体を通して使用します。

## 4. 実習 — main.py

実行方法:

```bash
cd lecture02_python_basics/level00_what_is_programming
python3 main.py
```

main.py は、カフェの「アメリカーノ注文処理」手順をコードに置き換えたデモです。
出力は4つのステップに分かれています。

- **[1] 順次**: 注文受付 → 金額計算 → レシート出力が上から下へ実行される様子を見せます。
- **[2] 分岐**: ポイント会員かどうかで付与のメッセージが変わります。コードの `if is_member:` の部分が分かれ道です。
- **[3] 繰り返し**: 注文3件を `for` の繰り返し1つで処理します。注文が300件になってもコードはそのまま、という点がポイントです。
- **[4] まとめ**: 「すべてのプログラムは順次・分岐・繰り返しの組み合わせ」という今日の結論を出力します。

まだ文法を学んでいないので、コードを全部理解しようとしないでください。
`cup_price * quantity` のような部分が「あれ、読めるぞ?」と感じられたら成功です。
コメント (# で始まる日本語の説明) をたどりながら、どの行が順次・分岐・繰り返しなのか、目印を探すだけで十分です。

## 5. やってみよう

1. **値を変えてみる** — main.py を開いて `cup_price = 4500` を別の値に変え、もう一度実行してみましょう。
   出力される金額はどう変わりますか? (ヒント: データが変われば、同じ手順でも結果が変わります。)
2. **分岐を体験する** — `is_member = True` を `False` に変えて実行し、出力からどの行が
   消えるかを確認しましょう。(ヒント: `if` の下のインデントされた行が実行されなくなります。)
3. **日常業務を手順に分解する** — あなたが毎週行っている業務を1つ (例: 週報の作成) 選び、
   順次・分岐・繰り返しがそれぞれどこにあるか紙に書き出してみましょう。
   (ヒント: 「〜まで繰り返す」「〜の場合のみ」という言葉が出てきたら、そこがポイントです。)

## 6. よくある間違い

- **文法の暗記から始めてしまう** — 文法は道具にすぎません。「どんな手順を自動化したいのか」を
  先に言葉で整理する習慣のほうがずっと重要です。
- **コンピュータが察してくれると期待する** — コンピュータは書かれたとおりにしか動きません。
  「当然、消費税込みだろう」と思っても、コードに書かれていなければ計算されません。
- **一度で完璧なプログラムを作ろうとする** — 実務のプログラムも、小さな手順を作り、
  実行して確認し、少しずつ育てる方式で作られます。実行ボタンをこまめに押しましょう。
- **エラーを失敗と考える** — エラーメッセージはコンピュータからの質問です。
  level07 で読み方を学ぶので、今は怖がらないことだけで十分です。
