# Lecture 05 · Level 11 — ベイズ的思考と不確実性の伝え方

> ベイズは「正解」ではなく「信念の会計帳簿」を作ります。証拠が入ってくるたびに残高が更新されます。
**難易度** ⭐⭐⭐⭐⭐ / **前提** level10 / **想定時間** 70分

## 1. なぜ学ぶのか — ビジネスの視点

level09〜10 の p 値は、訓練が必要なほど不自然な言語でした。
「差がないという仮定の下で、これほどの差が偶然出る確率 3%」という文を
経営層にそのまま伝えると、返ってくる質問は 1 つです。**「で、B 案のほうが
良い確率はいくつなんですか?」** — p 値はこの質問に答えられませんが、
ベイズ (Bayesian) アプローチは正面から答えます。「現在のデータに基づくと、B 案が
優れている確率は 92% です。」

ベイズ的思考の骨格は、すでに level06 で出会っています (病気検査のパラドックス:
事前確率 × 証拠)。このレベルではそれを連続的な問題 — コンバージョン率の推定と
A/B 比較 — に拡張し、最後に「不確実な結果を意思決定者に
伝える方法」という、もしかすると統計の技術より重要なコミュニケーション技術で締めくくります。

## 2. たとえ話で理解する

ベイズ更新は**お見合い後の評判の更新**です。会う前でも、私たちは
白紙ではありません — 紹介者の言葉、プロフィール写真という**事前の信念 (prior)** が
あります。初対面 (証拠、evidence) が良ければ好感度は上がりますが、それでもまだ
確信ではありません。会う回数が重なるほど (データの蓄積)、信念の分布はだんだん
狭くなり、ある時点で紹介者の言葉 (事前の信念) はほとんど影響力を失います。
**事後の信念 (posterior) = 事前の信念 × 証拠** — そして今日の事後の信念は、
明日の事前の信念になります。

不確実性の伝え方は**天気予報の言語**です。気象庁は「明日は雨が降ります/降り
ません」とは言わず、「降水確率 70%」と言います。この言い方が良い報告なのは、間違えないから
ではなく、**聞き手が傘のコストと濡れるコストを自分で天秤にかけられる**ように
してくれるからです。「B 案が優れている確率 92%、劣っていた場合の
想定損失は月 300 万ウォン」 — これが意思決定者のための報告形式です。

## 3. 核心となる考え方

### 3.1 確率に対する 2 つの見方

- **頻度主義 (frequentist)**: 確率 = 長期的な反復の比率。母数は固定された未知数
  であり、確率はデータ (標本抽出) にだけ付きます。→ 信頼区間、p 値
- **ベイズ主義**: 確率 = 信念の度合い。母数そのものに確率分布を与え、
  データを見るたびに分布を更新します。→ 事後分布、優越確率

2 つは敵ではなく、用途の違う工具です。規制当局への提出や論文には頻度主義の
慣例が強く、連続的なビジネスの意思決定や早期モニタリングにはベイズの話法が
よく合います。

### 3.2 コンバージョン率のベータ分布の更新

コンバージョン率のように 0〜1 の間の値に対する信念は、ベータ分布 (Beta distribution) で
表現します。Beta(α, β) は「成功を α-1 回、失敗を β-1 回見た状態の信念」
くらいに読めば十分です。更新ルールは驚くほど単純です。

> 事前の信念 Beta(α, β) + 観測 (コンバージョン s、非コンバージョン f) → 事後の信念 Beta(α+s, β+f)

- 何の情報もない出発点: Beta(1, 1) — 0〜1 がすべて同等の平らな分布
- 訪問 100 人中コンバージョン 3 人を観測 → Beta(4, 98): 3% 近くの山、まだ幅広い
- 訪問 10,000 人後 → 山が針のように狭くなる: 「もうかなり確信している」

分布の**幅が不確実性の大きさ**です。点推定 (「コンバージョン率 3%」) ではなく
分布 (「2.1〜4.2% のどこか、3% 近くが最もありそう」) で考えることが、
ベイズ的思考の核心的な習慣です。

### 3.3 「B 案が優れている確率」の計算

A、B それぞれの事後分布があれば、2 つの分布から乱数を数万ペア抜き取り、
**B の標本が A の標本より大きい比率**を数えればよいのです。これがモンテカルロ
(Monte Carlo) 方式の優越確率 P(B > A) です。公式なしで、level06 の
「作って数えてみる」がここでも通用します。おまけに「B は A より何 %pt
良いのか」の分布 (期待改善幅、損失リスク) も、同じ標本からタダで得られます。

### 3.4 不確実性を経営層に伝える方法

1. **質問の言語で答える**: 「p=0.03」の代わりに「B 案が良い確率 92%」。
2. **区間で語る**: 「コンバージョン率 3.4%」の代わりに「3.1〜3.7% (最もありそうな値 3.4%)」。
3. **決定と結びつける**: 「92% の確信 + 間違っていたときの損失 月 300 万ウォン + 待てば
   週あたり標本 5 千人の追加」 — 今決めるかもっと待つかは経営層の仕事で、
   アナリストの仕事はこの 3 つの数字を正確に渡すことです。
4. **分からないと言う勇気**: 分布が広ければ「まだ判断するには早いです。
   あと n 人必要です」が、唯一の誠実な報告です。

## 6. よくある間違い

- **事前の信念を隠す**: 事前分布は恥ずかしい仮定ではなく、明示すべき
  入力です。報告書に「事前の信念: 無情報 Beta(1,1)」のように一行書きましょう。
- **P(B>A)=92% を「8% の確率で大惨事」と誤読する**: 残りの 8% の大半は「B が
  ごくわずかに悪い」です。優越確率と一緒に期待損失を見てはじめて、リスクの大きさが
  見えます。
- **分布ではなく点だけ報告する**: 事後分布の平均だけ抜き出して使うなら、ベイズをやった意味が
  ありません。幅 (信用区間) こそが核心の情報です。
- **標本が十分なのに事前の信念のせいにする**: データが貯まれば、合理的な事前の信念
  たちはほぼ同じ事後分布に収束します。事前の信念の議論が長引くのは、たいてい
  データが足りないというサインです。
- **不確実性の報告を自信のなさと錯覚する**: 「92%」と言うアナリストのほうが、
  「確実です」と言うアナリストより長期的に信頼を得ます。後者は
  間違えた瞬間、すべての信用を失います。
