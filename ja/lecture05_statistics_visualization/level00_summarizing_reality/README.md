# Lecture 05 · Level 00 — 数字で現実を要約するということ

> 統計は「要約」と「推論」の技術です。要約は便利ですが、必ず何かを失います。
**難易度** ⭐ / **前提** lecture03 修了 / **想定時間** 30分

## 1. なぜ学ぶのか — ビジネスの視点

会社の中を飛び交う数字は、ほとんどすべてが要約です。「今月の平均客単価 18,400 ウォン」、
「顧客満足度 4.2 点」、「1 店舗あたり日商 320 万ウォン」。元データは数万行あるのに、
報告書には 1 行に圧縮されて上がってきます。問題は、この圧縮の過程で情報が
消えてしまうことです。同じ「平均 4.2 点」でも、大半が 4 点台の店と、
5 点と 1 点が半々の店とでは、状況がまったく違います。後者は今まさに何かが
深刻に壊れかけている最中かもしれません。

統計 (statistics) を学ぶ理由は 2 つあります。第一に、データを**要約**して
人に伝えるため。第二に、一部のデータ (標本) だけを見て全体について
**推論 (inference)** するため。この講義の前半 (level00〜04) は要約を、
後半 (level06〜11) は推論を扱います。今回のレベルはその出発点として、
「要約が何を失うのか」を体で確かめます。

## 2. たとえ話で理解する

要約は**履歴書**に似ています。ある人の 10 年間を A4 一枚に縮めたものが
履歴書です。採用担当者は履歴書のおかげで 100 人をすばやく比較できますが、
履歴書だけで採用して痛い目を見ることもあります。紙に書かれていないもの —
協働の姿勢、危機対応力 — のほうが実際には重要だったからです。

平均という数字も、データの履歴書です。便利ですが、「平均の裏にどんな
データがあるのか」を問わなければ、間違った採用、つまり間違った意思決定を
してしまいます。だからこそ、統計が得意な人の最初の習慣は計算ではなく**疑うこと**です。
「この要約、元データをどれくらいうまく代表しているだろう?」

もう 1 つのたとえ。地図は現実を要約した絵です。地下鉄の路線図は実際の
距離や方角を歪めていますが、乗り換えには最高の地図です。つまり**良い要約とは、
「目的に合わせて」失うものを選んで失った要約**です。何を失ったかを分かっている限り、
要約は強力な道具になります。

## 3. 核心となる考え方

### 3.1 記述統計と推測統計

- **記述統計 (descriptive statistics)**: 手元のデータを要約・描写します。
  平均、中央値、分散、ヒストグラムがここに属します。
- **推測統計 (inferential statistics)**: 標本を見て全体 (母集団) を
  推測します。世論調査、A/B テスト、信頼区間がここに属します。

Excel の AVERAGE は記述統計、「このアンケート 500 人の結果で全顧客の傾向を
語ってよいか?」は推測統計の問いです。

### 3.2 同じ平均、違う現実

今回の実習の中心となる実験です。平均がまったく同じ 100 のデータを 4 種類作ります。

| データ | 形 | ビジネスでの状況例 |
|---|---|---|
| A | 100 の周りに均等に集まる | 常連中心の安定した売上 |
| B | 60 前後と 140 前後の二つの山 | 平日客と週末客がまるで違う店 |
| C | 大半は 80 前後、極端な値が少数 | 普段は静かで、大型契約が 1 件 |
| D | 40〜160 の間に広く散らばる | 売上が当たり外れの激しい店 |

平均だけを見れば、4 つの店は同じ店です。しかし在庫の準備、人員配置、
キャッシュフロー管理の戦略は、すべて変えなければなりません。要約 1 つ (平均) では
この違いがまったく見えないのです。

### 3.3 要約を疑う 3 つの質問

1. **散らばり**: 値は平均の周りに集まっているか、広く散っているか? (→ level01 分散)
2. **形**: ひとかたまりか、複数の山か、どちらかに偏っているか? (→ level02 分布)
3. **極端な値**: ごく少数の値が要約を引きずっていないか? (→ level01 中央値)

この 3 つの質問は、この講義前半の目次そのものでもあります。

### 3.4 要約が都合よく操作されるとき

要約はうっかりミスだけで歪むのではありません。意図的にも歪められます。「平均
年収 5,000 万ウォンの会社」という求人広告の裏に、役員数名の高額報酬が隠れて
いるかもしれませんし、「顧客の 90% が満足」という広告の裏に、アンケート回答者を
選り好みした過程が隠れているかもしれません。統計を学ぶことは、数字を作る技術で
あると同時に、他人が作った数字にだまされないための防御術でもあります。この講義を通して
「この要約はどうやって作られたのか」を問う習慣を身につけていきます。

## 4. 実習 — main.py

```bash
python3 main.py
```

コードは、平均がすべて 100 になる架空の売上データ 4 種類 (A〜D) を作り、

- [1] 各データの平均を計算して「要約の上では同じ」であることを確かめ、
- [2] 最小値・最大値・中央値を並べて、要約の裏にある違いをあぶり出し、
- [3] テキストヒストグラム (アスタリスクのグラフ) で 4 つのデータの形を描きます。
- [4] 最後に「どの店に夜間の人員を増やすべきか」といった判断が
  要約値だけでは不可能であることを出力で示します。

核心となるのは `ascii_hist()` 関数です。値を区間 (bin) に分けて数え、個数の分だけ
`*` を打ちます。matplotlib を学ぶ前ですが、ヒストグラムの原理 (区間を
分けて頻度を数える) は、すでにここに全部登場しています。出力で A〜D のアスタリスクの
形がどれほど違うか、それなのに平均はなぜ同じなのかを、目で比べてみてください。

## 6. よくある間違い

- **平均 1 つで結論を出す**: 「平均が上がったから良くなった」は半分だけの事実です。
  極端な値 1 件が押し上げただけかもしれません。
- **要約なしで生データを突きつける**: 逆の極端も問題です。数万行をそのまま
  報告しても誰も読みません。要約しつつ、何を失ったかを添えて伝えるのが正解です。
- **「統計は難しい」と直感だけに頼る**: 今回のレベルで使った道具は、足し算と割り算、
  そしてアスタリスクを打つことだけでした。統計の半分は、こうした「誠実な観察」です。
