# Lecture 05 · Level 02 — 分布とヒストグラム

> 代表値がデータの履歴書なら、分布はデータの顔です。顔を見なければ誤解が生まれます。
**難易度** ⭐⭐ / **前提** level01 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

平均と中央値を学びましたが、数個の数字だけではまだ見落とすものがあります。
顧客の待ち時間データを例にすると — 平均 4 分、中央値 3 分。悪くなさそうに
見えます。ところが分布を描いてみると、大半は 2〜3 分なのに、20 分以上待った
顧客が毎日十数人いました。クレームと離脱は、まさにこの**裾 (テール)** から
生まれます。平均を改善することと裾を縮めることは、まったく別のプロジェクト
なのです。

分布 (distribution) を描く最も基本的な道具がヒストグラム (histogram) です。
値の範囲を区間 (bin) に分け、各区間の頻度を棒で描きます。
Excel のピボットで区間別に COUNTIF をしたことがあれば、すでにヒストグラムを
手作りした経験があるということです。このレベルでは Python でそれを 1 行で
描き、「bin の幅を変えると物語が変わる」という罠まで学びます。

## 2. たとえ話で理解する

ヒストグラムは**マンション団地の夜景写真**です。各世帯 (値) がどの
棟 (区間) に住んでいるかを見せてくれます。どの棟に明かりが多く灯っているか (頻度が
高いか)、団地がひとかたまりか 2 つの団地に分かれているか (山の数)、
ぽつんと離れた場所に明かりの灯った家があるか (極端な値) が一目で分かります。

bin の幅は**地図の縮尺**です。全国地図 (大きい bin) で見れば「首都圏に
人が多い」程度しか見えず、街区地図 (小さい bin) で見れば路地の一本一本は
見えますが全体のパターンは消えます。間違った縮尺の地図はありませんが、**目的に
合わない縮尺**はあります。ヒストグラムも同じで、bin をいくつに
分けるかによって、同じデータがのっぺり見えたり、でこぼこに見えたり
します。

## 3. 核心となる考え方

### 3.1 ヒストグラムの読み方

ヒストグラムで見るものは 4 つです。

1. **中心**: 山がどのあたりにあるか (代表値とつながる)
2. **散らばり**: 横にどれだけ広いか (標準偏差とつながる)
3. **形**: 左右対称か、片側に裾が長いか、山はいくつか
4. **特異点**: 本体からぽつんと離れた棒 (極端な値)、不自然に空いた区間

山が 2 つ (bimodal) なら「異なる集団が混ざっている」という強い
サインです。平日/週末、新規/常連のように集団を分けて描き直すべきです。

### 3.2 歪度 — 裾の方向

歪度 (skewness) は分布が片側に偏っている度合いです。

- **右の裾 (正の歪度)**: 売上、年収、待ち時間。大半は小さい値 +
  まれに大きい値。このとき平均 > 中央値。
- **左の裾 (負の歪度)**: 満点近くに集まった試験の点数のように、大きい値が
  多く小さい値がまれな場合。このとき平均 < 中央値。

平均と中央値の大小を見るだけでも、裾の方向を推測できます。
level01 で見た「平均 > 中央値」現象の正体が、まさに右の裾でした。

### 3.3 bin の幅の影響

| bin の数 | 見えるもの | 危険 |
|---|---|---|
| 少なすぎ (5個) | 大きな流れだけ | 2 つの山が 1 つに潰れる |
| ほどよい (20〜40個) | 中心・散らばり・形 | — |
| 多すぎ (200個) | 細かな凹凸 | 乱数のノイズをパターンと錯覚 |

正解の公式はありませんが、慣例的な出発点は「ルート n 個」または 20〜50 個の間で
いくつか描いてみて、物語が安定するポイントを探すことです。**bin を
変えても生き残るパターンだけを信じる** — これが実務のルールです。

### 3.4 ヒストグラム vs 棒グラフ

見た目は似ていますが別物です。ヒストグラムは**連続した数値を区間に
分けたもの**なので棒がくっついていて、順序に意味があります。棒グラフは
店舗・カテゴリのような**カテゴリ (範疇)** の比較なので棒が離れていて、順序を入れ替えても
構いません。報告書でこの 2 つを混同すると、読み手が軸を誤解します。

### 3.5 分布を数字 1 つで — パーセンタイルの味見

ヒストグラムを要約する補助的な数字にパーセンタイル (percentile) があります。90
パーセンタイルが 8 分というのは「顧客の 90% は 8 分以内に処理される」という意味です。
IT サービスの応答速度の目標を平均ではなく p95 や p99 で設定する理由が、まさに
裾の管理のためです。実習の [1] で売上の p50 (中央値) と p95 を一緒に
出力するので、2 つの数字の開きから裾の長さを感じ取ってください。

- [4] `outputs/hist_bimodal.png`: 平日と週末の売上を重ねて描いた図。
  全体では鈍い形の分布が、実は 2 つの集団の合成だったことを確かめます。

実行後、3 つの PNG を開き、出力された解説と照らし合わせてみてください。コードでは
`plt.hist(..., bins=...)` の 1 行が核心で、残りはタイトル・軸ラベル・保存
といった包装です。

## 6. よくある間違い

- **bin を 1 種類だけ描いて結論を出す**: 山の数のような重要な判断は、
  必ず bin を 2〜3 種類に変えて確かめましょう。
- **集団が混ざったまま分布を解釈する**: 2 つの山を「変な分布」で片付けず、
  集団を分けて描き直しましょう。たいてい平日/週末、店舗、商品群のような
  隠れた軸があります。
- **y 軸が頻度なのか比率なのかを明示しない**: 標本サイズの違う 2 つの分布を
  比較するときは `density=True` (比率) にそろえないと不公平です。
- **極端な値を切り落として描いた事実を隠す**: 見やすさのために範囲を制限するのは
  構いませんが、「上位 1% 除外」のような注記を必ず図に残しましょう。
