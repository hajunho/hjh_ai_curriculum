# Lecture 01 · Level 11 — リモートサーバー・クラウド・GPU 環境

> ssh で他人のコンピュータを借りて使うという概念、GPU が AI に必須である理由(並列性)、クラウド費用の感覚を学び、並列計算の効果をコードで確認します。

**難易度** ⭐⭐⭐⭐ / **前提** level02、level10 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

自分のノートパソコンで AI モデルを学習させると数日かかる作業が、クラウドの GPU サーバーなら数時間で終わります。だから AI プロジェクトの実際の作業は、ほぼすべて**リモートサーバー**の上で起きています。開発者たちが「サーバーに接続して」「GPU インスタンスを立ち上げて」「A100 を8枚で2日間回しました」といった話をするのはそのためです。

非エンジニアにとってこのレベルが重要な理由は、**費用**にあります。クラウドの GPU は時間単位の課金なので、「何日回すか」がそのまま予算になります。高性能な GPU サーバーは1時間あたり数万ウォン(このカリキュラムの金額は韓国ウォン、KRW 建てです)にもなるため、計画を誤った実験ひとつが数百万ウォンを燃やすこともあり、逆に概念を知っている管理者は「もっと小さい GPU で短く実験してから確定しよう」という判断で予算を守ります。このレベルを終えれば、AI プロジェクトの見積書の「GPU 費用」の項目が読めるようになり、並列性という GPU の本質をコードで体感できます。

## 2. たとえ話で理解する

### リモートサーバー = 設備の良いシェアオフィス

自分のオフィス(ノートパソコン)の設備が足りないとき、会社は設備の良い**シェアオフィスの席を時間単位で借ります**。これがクラウド(cloud)です。Amazon(AWS)・Google(GCP)・Microsoft(Azure)のような会社が、巨大な建物(データセンター)にコンピュータを数十万台置いて、時間単位で貸してくれます。借りたコンピュータ1台を**インスタンス(instance)**と呼びます。

**ssh(Secure Shell)は、そのシェアオフィスにつながる保安専用の電話線**です。`ssh アカウント@サーバーアドレス` の1行で、リモートコンピュータのターミナルが自分の画面に現れ、level02 で学んだコマンドが**そのまま**通じます(リモートサーバーはほとんど Linux です — ターミナルを学んでおいた甲斐がここで出ます)。ファイルを送るときは宅配便サービスの `scp`(secure copy)を使います: `scp ファイル アカウント@サーバー:/パス`。パスワードの代わりに**鍵ファイル(ssh キー)**で出入りするのが標準で、この鍵も level09 の原則どおり、コードやリポジトリには入れません。

### CPU と GPU = 博士4人とアルバイト4千人

- **CPU** は**博士級の専門家数名**(コア4〜16個)です。どんな複雑な問題でも解けて個々の速度も速いのですが、人数が少ない。
- **GPU(グラフィックス処理装置)**は**単純計算のアルバイト数千人**です。ひとりひとりは単純な算数しかできませんが、数千人が**同時に**計算します。

封筒にチラシを入れる作業を100万枚頼んだら、どちらが勝つでしょうか? 圧倒的にアルバイト軍団です。そして AI の学習がまさにこういう仕事です — 数百万個の数字を掛けて足す**単純計算の無限の繰り返し**(行列の掛け算)。もともとゲーム画面の数百万ピクセルを同時に塗るために作られた GPU が、同じ構造の計算である AI の学習にぴったりだったのです。キーワードは**並列性(parallelism)** — 仕事を分割して大勢の働き手が同時にやることです。

## 3. 核心となる概念

### 3-1. リモート作業の基本の流れ

```bash
ssh myname@203.0.113.10       # 1) 保安電話線でサーバーに接続
git clone <リポジトリのアドレス>  # 2) コードは GitHub を経由して持ってくる (level07!)
scp data.csv myname@サーバー:~/   # 3) データファイルは scp で直接転送
python3 train.py               # 4) サーバーのターミナルで実行 (level02 のコマンドそのまま)
```

ひとつ注意。ssh の接続が切れると、実行中だったプログラムも一緒に死にます。だから実務では、接続が切れても作業が続くようにする道具(tmux、nohup など)を一緒に使います — 「こういう道具が必要になる理由」まで知っておけば十分です。

### 3-2. なぜ AI は GPU なのか — 数字で見る

AI モデルの学習は、本質的に行列の掛け算(膨大な掛け算・足し算)の繰り返しです。この計算は互いに**依存関係が無い**ので、1万個に分割して1万人に同時にやらせることができます。CPU コア8個 対 GPU コア数千個という並列性の差が、実戦では「数日 対 数時間」の差を作ります。逆に、分割できない仕事(前の段階の結果が無いと次の段階に進めない仕事)は GPU の方がむしろ遅いです。**「分割できる仕事か」が GPU 活用の判断基準**です。

### 3-3. クラウド費用の感覚

クラウド課金の3原則だけ覚えてください。

1. **時間単位の課金**: インスタンスは点いている間ずっと課金されます。**消し忘れ**が初心者の支出事故の第1位です。
2. **GPU のグレード差が大きい**: 実習用の小型 GPU(1時間あたり数百〜数千ウォン)と最上級の学習用 GPU(1時間あたり数万ウォン)では数十倍の差があります。実験は小さい機材で、確定した学習だけ大きい機材で。
3. **付帯費用**: ストレージ容量、データ転送(特にデータセンターの外へ出ていくトラフィック)にも料金が付きます。

簡単な見積もりの練習(金額は KRW): 1時間3万ウォンの GPU インスタンスで48時間学習すると144万ウォン。事前実験を1時間1千ウォンのもので2回(各3時間)やって設定ミスを先につかまえれば、6千ウォンで144万ウォンの再実験を予防できる計算です。

### 3-4. 並列化の限界 — アムダールの法則の感覚

仕事の一部は必ず順次的です(データの読み込み、結果の取りまとめなど)。全体の20%が順次作業なら、働き手を無限に増やしても5倍以上は速くなりません。これをアムダールの法則(Amdahl's law)と呼びます。「働き手を2倍にすれば2倍速くなる」が常に成り立つわけではないという感覚 — 人員投入と納期の関係とまったく同じです。

## 4. 実習 — main.py

```bash
python3 main.py
```

GPU 無しで、皆さんの CPU のコア数個だけで**並列性の効果**を直接測定します。

- **[1] 仕事の準備**: 「素数(prime)の個数を数える」という分割しやすい計算の仕事を作ります。seed 固定で毎回同じ仕事です。
- **[2] ひとりで働く**: 1人(単一プロセス)が全区間を処理する時間を測ります。
- **[3] 分担して働く**: 区間を複数の断片に分割して複数の働き手(マルチプロセス)に同時に任せ、時間を測ります。
- **[4] 成績表**: 2つの方式の時間・倍速を比較し、コア数どおりに正確には比例しない理由(働き手の招集コスト、順次区間)を解説します。
- **[5] GPU への拡張**: 「この原理で働き手が数千人になれば GPU」というつながり、そしてクラウドの見積もり例を出力します。

核心となるコードは `concurrent.futures.ProcessPoolExecutor` を使う部分です。`executor.map(作業関数, 断片たち)` の1行で「仕事を分けて同時にやらせる」が実現します。ここで、**仕事を分割できたからこそ並列化できた**という点が、GPU・AI へつながる核心的な洞察です。

## 6. よくあるつまずき

- **インスタンスの消し忘れ**: クラウド支出事故の第1位です。作業終了 = インスタンス停止をワンセットで習慣化し、予算アラートを設定しましょう。
- **最初から最高級 GPU**: 設定ミスやコードのバグは小さい機材でも同じように見つかります。実験は安く、本番の学習だけ高く。
- **ssh キーをリポジトリにコミット**: 鍵ファイル(`id_rsa` など)が流出すればサーバー全体が開きます。level09 の原則は鍵ファイルにも適用されます。
- **すべての作業に並列化を試みる**: 分割できない順次作業は並列化しても速くならず、コードが複雑になるだけです。「分割できるか」を先に問いましょう。
