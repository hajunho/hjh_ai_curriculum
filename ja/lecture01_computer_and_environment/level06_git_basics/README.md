# Lecture 01 · Level 06 — Git: バージョン管理の考え方

> 「最終_本当に最終.xlsx」を終わらせるツール Git の核心概念(スナップショット・コミット・ブランチ)を、決裁とタイムトラベルにたとえて理解し、実際の git コマンドで実習します。

**難易度** ⭐⭐ / **前提** level02 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

こんなフォルダを見たことがあるはずです。`提案書_v1.docx`、`提案書_v2_修正.docx`、`提案書_最終.docx`、`提案書_最終_本当に最終(部長コメント反映).docx`。どれが本当の最終版なのか、v2 で何が変わったのか、誰が変えたのか、誰にもわかりません。うっかりファイルを上書きすれば、過去は永遠に消えます。

開発の世界はこの問題を20年前に解決しました。そのツールが **Git(ギット)** です。Git はファイルの変更履歴をすべて記録しておき、いつでも過去のどの時点にも戻れて、何が・いつ・誰によって・なぜ変わったのかを1分以内に追跡できるようにしてくれます。コードだけでなく、文書・設定・データパイプラインまで、今日「作られるものすべて」の履歴管理の標準です。AI プロジェクトも例外ではなく、モデルのコードや実験設定の履歴はすべて Git の上で管理されています。Git を知らないと、開発チームとの協業の会話の半分が聞き取れません。

## 2. たとえ話で理解する

**コミットは決裁のハンコ、リポジトリは決裁書類棚、ブランチは並行宇宙へのタイムトラベル**です。

- **リポジトリ(repository)**: プロジェクトフォルダに付属する、目に見えない決裁書類棚(`.git` フォルダ)です。`git init` は「このフォルダの履歴管理を始めます」と宣言して書類棚を設置することです。
- **コミット(commit)**: いまこの瞬間のフォルダ全体の状態を写真に撮り(スナップショット、snapshot)、決裁のハンコとともに書類棚に保管する行為です。ハンコには通し番号(ハッシュ)、日付、担当者、そして**決裁の理由(コミットメッセージ)**が刻まれます。「v1、v2 のファイルを別々に作る」代わりに、「同じファイルの状態を時点ごとに保管」するのです。
- **ステージング(staging)**: 決裁に上げる前に、**決裁板に載せる書類を選ぶ段階**です。`git add` で「今回の決裁にはこのファイルだけを含める」と選別します。デスクの上の書類全部ではなく、選んだものだけがハンコをもらいます。
- **ブランチ(branch)**: 並行宇宙をひとつ開くことです。本編のストーリー(main ブランチ)はそのままにして、「価格ポリシーを変えてみたらどうだろう?」のような実験を、分岐した宇宙で進めます。実験が成功すれば本編に合流させ(merge)、失敗すればその宇宙だけ廃棄すれば本編は無事です。
- **チェックアウト/タイムトラベル**: 書類棚のどのハンコの時点にも、フォルダの状態を戻して見ることができます。「先週火曜日の状態に戻ってみよう」がコマンド1行です。

## 3. 核心となる概念

### 3-1. 3つの空間

Git の作業は、3つの空間の間の移動です。

```
作業フォルダ(デスク)  --git add-->  ステージング(決裁板)  --git commit-->  リポジトリ(書類棚)
```

| 空間 | たとえ | 状態 |
|---|---|---|
| 作業フォルダ(working directory) | いま編集中のデスク | 自由に修正できる、まだ記録ではない |
| ステージングエリア(staging area) | 決裁板 | 次のコミットに含まれる候補 |
| リポジトリ(repository) | 決裁書類棚 | ハンコの押された永久記録 |

`git status` は「いまデスクと決裁板に何があるか」を見せてくれる万能の確認コマンドです。

### 3-2. 必須コマンド7つ

```bash
git init                       # 書類棚の設置 (フォルダごとに一度)
git status                     # 現在の状態確認 (こまめに!)
git add ファイル または .      # 決裁板に載せる
git commit -m "理由"           # ハンコを押す (メッセージ必須)
git log --oneline              # 決裁履歴の照会
git branch 名前 / git switch 名前   # 並行宇宙を作る / 移動する
git diff                       # 何が変わったかを比較
```

初めて使うコンピュータでは、ハンコに刻む名前を登録する必要があります: `git config --global user.name "名前"`、`git config --global user.email "メール"`。

### 3-3. 良いコミットのコツ

- **小さく、こまめに**: 1日分をまとめて一度に押すのではなく、意味のある単位(機能ひとつ、修正ひとつ)ごとに押します。巻き戻しが簡単になります。
- **メッセージには「なぜ」を**: 「修正」のようなメッセージは無いのと同じです。「割引率の計算式の誤りを修正(10%→15%)」のように、未来の自分が読んで理解できる理由を書きます。
- **コミットは消えない安全網**: コミットしておいたものは、どんな失敗をしても取り戻せます。「とりあえずコミット」が最高のバックアップ習慣です。

### 3-4. .gitignore — 記録しないもの

一時ファイル、`.venv` フォルダ、シークレットキーのファイル(level09)は書類棚に入れません。プロジェクトルートの `.gitignore` ファイルに除外リストを書いておけば、Git はそれらのファイルを無いものとして扱います。

## 4. 実習 — main.py

```bash
python3 main.py
```

このスクリプトは、皆さんのコンピュータに git がインストールされていれば、**一時フォルダに本物のリポジトリを作って全体の流れを自動実習**します。(git が無ければ、同じ流れを概念シミュレーションで見せて、インストール方法を案内します。)

- **[1] 書類棚の設置**: `git init` でリポジトリを作り、実習用の名前・メールを登録します。
- **[2] 最初の決裁**: 価格表ファイルを作り、`add → commit` で最初のハンコを押します。
- **[3] 修正と diff**: 価格を変えてから `git diff` で「何が変わったか」を確認し、2つ目のコミットをします。
- **[4] 履歴の照会**: `git log` でハンコが積み重なった決裁履歴を見ます。
- **[5] ブランチ実験**: `experiment` ブランチ(並行宇宙)で価格を大胆に変え、main に戻ると**ファイルの内容が元どおりに見えること**を確認します — タイムトラベルの実感ポイントです。

核心となるコードは `run_git()` 関数です。Python の `subprocess.run()` で実際の git コマンドを実行し、出力を受け取ります。つまり、皆さんがターミナルに打つコマンドを Python が代わりに打ち、解説を付けてくれる構造です。出力の `$ git ...` の行が「皆さんが自分で打つコマンド」なので、実習の後に空のフォルダで同じ順番に手で打ってみれば完璧です。

## 5. やってみよう

1. **(易しい)** 実習の出力 [5] 段階で、main ブランチに戻ったとき価格表の内容が何だったか確認してみましょう。experiment ブランチの修正は main に影響を与えましたか? *(ヒント: 与えていないのが正常です — それが並行宇宙です。)*
2. **(普通)** 本物のターミナルで練習用フォルダを作り、`git init → ファイル作成 → git add → git commit → git log` を自分で打ってみましょう。*(ヒント: main.py の出力の `$ git ...` の行を順番になぞれば OK です。)*
3. **(挑戦)** main.py の [3] 段階の後に3つ目のコミット(例: 新メニューの追加)を追加して、log にハンコが3つ押されるか確認してみましょう。*(ヒント: `demo_edit_and_diff()` を参考に、ファイル修正 → add → commit の流れをもう一度繰り返すだけです。)*

## 6. よくあるつまずき

- **add せずに commit**: 決裁板が空だと、ハンコを押す書類がありません。「nothing to commit」が出たら、`git status` で決裁板の状態から確認しましょう。
- **コミットメッセージなしでコミットしようとする**: `-m "メッセージ"` を省くと見慣れないエディタ画面が開いて慌てることになります(脱出方法: `:q!` の後 Enter)。常に `-m` を付ける習慣をつけましょう。
- **すべてのファイルを問答無用で `git add .`**: シークレットキーや大容量ファイルまで書類棚に入ってしまう事故への近道です。`git status` で何が載るのかを見てから add しましょう。
- **`.git` フォルダの削除・移動**: このフォルダこそが書類棚そのものです。消せば履歴全体が消えます。
