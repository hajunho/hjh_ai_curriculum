# Lecture 01 · Level 08 — シェルスクリプトで繰り返し作業を自動化する

> 毎週手作業でやっていたファイル整理・名前変更をスクリプト1回で終わらせる、自動化の考え方を学び、Python でファイルの一括整理を実習します。

**難易度** ⭐⭐⭐ / **前提** level02 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

こんな業務を思い浮かべてください。毎週月曜日、共有フォルダに溜まった店舗別売上ファイル数十個をダウンロードし、ファイル名をルールどおりに直し、月別フォルダに分類し、古いファイルは保管庫へ移す仕事。1回20分、1年で17時間です。しかも人間はミスをします — ファイルひとつを見当違いのフォルダに入れたり、名前の日付を打ち間違えたりします。

自動化の損益計算はシンプルです。**「繰り返し回数 × 節約時間 > 自動化の製作時間」なら必ず得**であり、おまけにミスがゼロになります。このレベルはその最初の実戦として「ファイルの一括整理」を扱います。ファイル整理は事務職の繰り返し業務の最大公約数であり、ここで身につけたパターン(一覧の取得 → ルールの適用 → 一括実行 → 結果報告)は、のちにデータ前処理・レポート生成・メール送信など、あらゆる自動化にそのまま再利用できます。

## 2. たとえ話で理解する

**スクリプトは新人に渡す業務マニュアル**です。

有能な先輩は、新人に仕事を口頭だけで指示せず、マニュアルを書いて渡します。「1) 受信ファイルの箱を開く 2) ファイル名の先頭に日付を付ける 3) 店舗別フォルダに入れる 4) 完了リストを報告する」。マニュアルが良ければ、誰がやっても、何回やっても同じ結果になります。

スクリプト(script)がまさにこのマニュアルです。ただし実行者が新人ではなくコンピュータなので、(1) 指示が少しでも曖昧だと止まるか見当違いのことをやり、(2) その代わり一度正確に書いておけば、1万回やらせても文句もミスもありません。

マニュアルを書く言語は2つあります。**シェルスクリプト(.sh)**は、level02 で学んだターミナルコマンド(cp、mv など)をファイルに順番に書いたもの — 「ターミナル語で書いたマニュアル」です。**Python スクリプト(.py)**は、同じことを Python で書いたものです。単純なコマンドの羅列ならシェルが簡潔で、条件・例外・データ加工が絡むなら Python が圧倒的に有利です。このカリキュラムでは「2〜3行ならシェル、それ以上は Python」を目安にします。

## 3. 核心となる概念

### 3-1. シェルスクリプトの最小文法

```bash
#!/bin/bash                      # 1行目: このマニュアルの実行者は bash
mkdir -p archive                 # コマンドを順番に書く
mv report_*.csv archive/         # * ワイルドカード: パターンに合うすべてのファイル
echo "整理完了: $(date)"         # 進行の報告
```

`bash cleanup.sh` で実行します。`*`(任意の文字列)、`?`(1文字)のような**ワイルドカード(wildcard)**が「パターンに合う全部」をつかまえてくれるのが、一括処理の核心です。

### 3-2. 自動化スクリプトの4段階パターン

どんな自動化でも骨組みは同じです。

1. **収集**: 対象の一覧を得る — `Path.glob("*.csv")`
2. **判断**: 各対象にルールを適用する — ファイル名の解析、分類の決定
3. **実行**: 移す/変える/作る — `rename`、`mkdir`
4. **報告**: 何をしたか記録する — ログ出力、サマリー表

この中でいちばん大事な習慣が**ドライラン(dry run)** — 3段階目の実行をロックして「何をする予定か」だけを出力してみる予行演習です。ファイル500個を間違って移してから後悔するより、移す前に計画表を目で検証するのがプロのやり方です。

### 3-3. Python でファイルを扱う核心ツール

| ツール | やること |
|---|---|
| `Path.glob("*.csv")` / `rglob` | パターンでファイル一覧を収集 (下位フォルダも含めるのは rglob) |
| `path.rename(新パス)` | 移動兼名前変更 (シェルの mv) |
| `shutil.copy2(元, 先)` | コピー (シェルの cp、更新時刻を保持) |
| `path.mkdir(parents=True, exist_ok=True)` | フォルダ作成 (シェルの mkdir -p) |
| `re.match(パターン, 名前)` | 正規表現でファイル名を解析 |

**正規表現(regular expression)**は「文字パターンの検索言語」です。たとえば `r"(\d{4})-(\d{2})"` は「数字4個-数字2個」(年-月)を意味します。ファイル名から日付や店舗名のような情報を抜き出すときに強力で、いまは「こういう道具がある」というレベルで十分です。

### 3-4. 安全装置の設計

自動化は速い分、事故も速いです。最低限の安全装置は3つ: **(1) ドライランモード**をデフォルトに、**(2) 削除の代わりに移動**(quarantine フォルダへ退避)、**(3) 実行ログを残す**(何をいつ移したか)。この3つを守るだけで、自動化事故の大部分を予防できます。

## 4. 実習 — main.py

```bash
python3 main.py
```

一時フォルダに**散らかった共有フォルダ**を再現しておき、自動整理スクリプトが片付ける全過程を見せます。

- **[1] 散らかりの生成**: `売上報告_渋谷_2024-03.csv`、`sales_fukuoka_2024-04.csv`、`メモ.txt`、`発表資料.pptx` など、命名ルールがばらばらのファイル14個を、seed 固定の乱数で作ります。
- **[2] 収集・判断**: 正規表現でファイル名から年月・店舗を解析し、ファイルごとに「どこへ送るか」の分類計画を立てます。解析できないファイルは `_要確認` フォルダ行きです。
- **[3] ドライラン**: 実行の前に、移動計画表だけを出力します — 「何をする予定か」の予行演習。
- **[4] 実際の実行**: 計画どおりフォルダを作り、ファイルを一括移動・名前の統一(`店舗_年-月.csv` 形式)を行います。
- **[5] 結果報告**: 整理後のフォルダツリーと処理サマリー(整理 n 件、要確認 n 件)、そして手作業ならかかったはずの時間を比較します。

核心となるコードは `plan_moves()` と `execute_moves()` の分離です。**計画づくりと実行を別々の関数に分ければ**、ドライランがタダで手に入り、テストも簡単になります。この構造は実務の自動化の標準設計です。

## 5. やってみよう

1. **(易しい)** [1] 段階のファイル一覧に `sales_sapporo_2024-05.csv` を追加して、札幌店舗のフォルダが新しくできるか確認してみましょう。*(ヒント: `MESSY_FILES` リストに1行追加。)*
2. **(普通)** いまは pptx が `_要確認` へ行きます。`発表資料` フォルダを作って pptx ファイルをそこへ送るよう、分類ルールを追加してみましょう。*(ヒント: `plan_moves()` の中に `suffix` を検査する分岐をひとつ追加すれば OK です。)*
3. **(挑戦)** 皆さんのコンピュータの実際のダウンロードフォルダを対象に、**ドライラン専用**バージョンを作り、「整理するとしたら何がどこへ行くか」だけを出力してみましょう。*(ヒント: 実行関数は呼ばず、計画関数だけを使いましょう。実際の移動は、計画表を十分に検証してから!)*

## 6. よくあるつまずき

- **ドライランなしで一括実行**: 数百個のファイルが間違って移された後の巻き戻しは何倍も大変です。計画表の出力 → 目での検証 → 実行、の順序を守りましょう。
- **同名ファイルの上書き**: 移動先に同名のファイルがあると、静かに上書きされてデータが消えることがあります。移動前の存在確認(`exists()`)か、名前への番号付与が必要です。
- **自動化スクリプトに絶対パスをハードコーディング**: `/Users/自分の名前/...` が埋め込まれていると、同僚のコンピュータで即死します。対象フォルダは引数や設定で受け取るようにしましょう。
- **一度使って捨てるコードへの過剰投資**: 繰り返されない仕事は手でやった方が速いです。自動化の損益計算を先にしましょう。
