# Lecture 01 · Level 00 — コンピュータとは何をする機械なのか

> コンピュータとは結局「入力を受け取り → 計算し → 出力する」機械であり、CPU・メモリ・ストレージが会社の組織のように分業していることを理解します。

**難易度** ⭐ / **前提** なし / **想定時間** 30分

## 1. なぜ学ぶのか — ビジネスの視点

このカリキュラムでは、これからコンピュータに数えきれないほどの仕事を任せていきます。データを整理させ、グラフを描かせ、やがては AI モデルの学習までさせます。ところが、仕事を頼む側が働く側の事情をまったく知らないと、困ったことが起きます。たとえば「なぜこの作業は1秒で終わるのに、あの作業は1時間かかるのか」「なぜプログラムを閉じたら作業中の内容が消えたのか」「メモリ不足というエラーはどういう意味か」といった疑問に、自分で答えられなくなるのです。

仕事でも同じです。協力会社に業務を委託するとき、その会社の組織構成や仕事の進め方を大まかにでも知っていれば、見積もりや納期がなぜそうなるのか理解できます。コンピュータも、私たちが毎日仕事を任せている「協力会社」です。内部構造をざっくりとした全体像だけでも押さえておけば、この先すべてのレベルで出会う用語(CPU、メモリ、ディスク、プロセス)が怖くなくなります。

このレベルの目標はただひとつ。**コンピュータは「入力 → 計算 → 出力」を繰り返す機械である**という全体像を体に染み込ませることです。

## 2. たとえ話で理解する

コンピュータを小さな会社だと想像してみましょう。

- **CPU(中央処理装置、Central Processing Unit)は実務担当者**です。実際に計算し判断する唯一の存在です。ものすごく速いのですが、一度にできるのはごく小さな仕事(足し算や比較など)だけです。その代わり、その小さな仕事を1秒に数十億回こなします。書類1枚を 0.0000001 秒で決裁する超高速の担当者というわけです。
- **メモリ(RAM)は担当者のデスク**です。いままさに作業中の書類を広げておく場所です。デスクの上の書類は手を伸ばせばすぐ取れるのでとても速いのですが、退勤(電源オフ)するとデスクはきれいに片付けられてしまいます。つまり**メモリは高速だが揮発性**です。「保存せずに閉じたら文書が消えた」という事故がまさにこれです。
- **ストレージ(SSD/HDD)は書類倉庫**です。書類を永久保管する場所です。倉庫まで歩いて行って書類を探してくるには時間がかかりますが(メモリより数百〜数千倍遅い)、電源を切っても中身は残ります。ファイルを「保存する」とは、デスクの上の書類を倉庫に正式に収めるという行為です。
- **入力装置(キーボード・マウス)はお客様の受付窓口**、**出力装置(モニター・プリンター)は結果の発送部門**です。

仕事が処理される流れは、会社の業務フローとまったく同じです。受付窓口に注文が届くと(入力)、倉庫から必要な資料を取り出してデスクに広げ(ストレージ → メモリ)、担当者が計算し(CPU)、結果をお客様に発送し(出力)、記録を倉庫に保管します(メモリ → ストレージ)。皆さんが Excel を開き、数式を入れ、保存するという一連の作業が、まさにこの流れです。

## 3. 核心となる概念

### 3-1. 入力 → 計算 → 出力(IPO モデル)

すべてのプログラムは、例外なくこの3段階でできています。これを IPO(Input-Process-Output)モデルと呼びます。

| 段階 | Excel での例 | このレベルの実習での例 |
|---|---|---|
| 入力(Input) | セルに売上の数字を入力 | 注文リストのデータ |
| 計算(Process) | SUM、AVERAGE の数式 | 合計・平均を Python で計算 |
| 出力(Output) | 画面に結果を表示、ファイル保存 | 画面出力 + ファイル保存 |

この先どんなに複雑な AI プログラムを見ても、「入力は何で、どんな計算をして、出力は何か?」と3つに分けて眺めれば、半分は理解したも同然です。

### 3-2. コンピュータはなぜ 0 と 1 なのか

CPU は電気信号で働きます。電気が流れている/流れていないという2つの状態しか確実に区別できないため、あらゆる情報を 0 と 1(二進法、binary)で表現します。0 か 1 のひとつをビット(bit)、8個の束をバイト(byte)と呼びます。文字も写真も動画も Excel ファイルも、結局はすべて 0 と 1 の並びです。「1MB、1GB」といった容量の単位は、このバイトを百万個、十億個という単位で数えたものです。

### 3-3. 速度の階層 — なぜ遅い作業があるのか

デスク(メモリ)と倉庫(ストレージ)のたとえで肝心なのは**速度の差**です。だいたいの感覚だけつかんでおきましょう。

- CPU 内部の計算: 1秒に数十億回
- メモリの読み取り: CPU の計算より数十〜数百倍遅い
- SSD の読み取り: メモリより数百倍遅い
- インターネットからのダウンロード: SSD よりさらに数十倍以上遅い

だからプログラムが遅いとき、原因の多くは「計算が多いから」ではなく「倉庫(ディスク)や外部(ネットワーク)と頻繁に行き来しているから」です。この感覚は、後の大容量データの講義で再び登場します。

### 3-4. プログラムとプロセス

倉庫に保管された業務マニュアル(ファイルとして保存されたプログラム)は、それ自体では何の仕事もしません。担当者がマニュアルをデスクに広げ、実際に仕事を始めて初めて業務が動き出します。このように**実行中のプログラムをプロセス(process)**と呼びます。同じマニュアルで複数の担当者が同時に働けるように、ひとつのプログラム(例: Chrome)を複数起動すれば、複数のプロセスが生まれます。

## 4. 実習 — main.py

ターミナルでこのフォルダに移動して実行します。(ターミナルに不慣れでも大丈夫。level02 で詳しく学ぶので、いまはまず真似して打ってみてください。)

```bash
python3 main.py
```

このスクリプトは、小さな「カフェチェーン本社の売上集計業務」を、コンピュータという会社の組織になぞらえて処理します。なお、教材のデータはすべて韓国ウォン(₩、KRW)建ての金額です。

- **[1] 入力**: 店舗別の注文データが届きます(受付窓口)。
- **[2] ストレージ → メモリ**: データを一時ファイル(倉庫)に保存してから読み戻し、「保存すれば残る、メモリは揮発する」という違いを見せます。
- **[3] 計算**: CPU 役として合計・平均・売上トップの店舗を計算します。同じ計算を100万回繰り返しても1秒かからないことを、時間計測で確認します。
- **[4] 出力**: 人が読みやすいレポートの形で画面に出力します。
- **[5] 二進法の味見**: 「AI」という文字が実際にどんな 0/1 で保存されるかを見せます。

コードで注目してほしいのは `process_orders()` 関数です。入力(orders リスト)を受け取り、計算(合計・平均)をして、出力(辞書を返す)をする — IPO モデルが関数ひとつにそのまま収まった構造です。Python の文法をまだ知らなくても大丈夫です。`#` の後ろの日本語コメントを追って読むだけで流れが見えるように書いてあります。

## 6. よくあるつまずき

- **「保存済み」と「実行中」の混同**: 文書を編集している間、内容はデスク(メモリ)の上にしかありません。保存ボタンを押して初めて倉庫(ディスク)に収まります。コードも同じで、ファイルを修正したら保存してから実行しないと、変更が反映されません。
- **容量と速度の混同**: 「メモリ 16GB」と「SSD 512GB」はどちらも記憶領域ですが役割が違います。メモリはデスクの広さ(同時に広げられる作業量)、SSD は倉庫の広さ(保管できる総量)です。
- **コンピュータは賢いという誤解**: コンピュータは指示されたことだけを、指示されたとおりにやります。今後の講義でエラーに出会ったら、「コンピュータがおかしい」ではなく「自分の指示のどこが曖昧だったか」をまず疑う習慣をつけましょう。
