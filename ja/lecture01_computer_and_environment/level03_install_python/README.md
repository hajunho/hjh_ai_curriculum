# Lecture 01 · Level 03 — Python のインストールと初めての実行

> 自分のコンピュータの Python を確認し、対話型(REPL)実行とスクリプト実行の違いを理解し、自己診断スクリプトで環境を点検します。

**難易度** ⭐ / **前提** level02 / **想定時間** 35分

## 1. なぜ学ぶのか — ビジネスの視点

Python(パイソン)は、このカリキュラム全体の共通語です。データ分析、自動化、AI — 私たちが学ぶすべてが Python の上で動きます。Python が世界的に業務自動化と AI の標準言語になった理由はシンプルです。文法が英語の文章に近くて学びやすく、世界中の人々が作っておいてくれた道具(パッケージ)が圧倒的に多いからです。

ところが意外にも多くの入門者が、最初の時間にコードではなく**インストールと実行**でつまずきます。「python と打ったら『無い』と言われた」「確かにインストールしたのに別のバージョンが実行される」「会社のパソコンには2つ入っていて、どれがどれだかわからない」— どれもよくある話です。このレベルは、その入り口の壁を越えるための時間です。自分のコンピュータに、どの Python が、どこに、どのバージョンで入っているのかを自分で診断できれば、この先環境の問題に出会っても慌てずに済みます。

## 2. たとえ話で理解する

Python のインストールは、**会社に有能な通訳者を採用すること**です。私たちが書く Python のコードは人間が読みやすい言語で、コンピュータは 0 と 1(機械語)しか理解しません。Python インタプリタ(interpreter)という通訳者が、私たちの指示文を1行ずつ機械語に通訳してくれます。

通訳者に仕事を頼む方式は2つあります。

- **対話型(REPL)** — 通訳者と向かい合って座り、**一言ずつその場で会話**する方式です。ターミナルに `python3` とだけ打つと `>>>` というプロンプトが現れ、`2 + 3` と打てば即座に `5` と答えます。電卓のように気軽に実験するのに向いています。REPL は Read(読んで)-Eval(計算して)-Print(答えて)-Loop(繰り返す)の頭文字です。
- **スクリプト(script)実行** — 指示事項を**文書にまとめて丸ごと渡す**方式です。`main.py` のようなファイルに指示文を書いておき、`python3 main.py` で渡すと、上から順にすべて実行します。保管・再実行・共有ができるので、実際の業務はほとんどこの方式です。

その場の会話(REPL)はアイデアの実験用、文書での指示(スクリプト)は正式な業務用 — この区別だけ覚えておけば十分です。

## 3. 核心となる概念

### 3-1. まずはインストールの確認から

新しくインストールする前に、すでに入っているかを確認します。ターミナルで:

```bash
python3 --version    # 例: Python 3.12.9
which python3        # Mac/Linux: 実行ファイルの場所 (Windows は where python)
```

バージョンが 3.10 以上なら、このカリキュラムを進めるのに十分です。無ければ python.org 公式サイトのインストーラを入手するか、Mac なら Homebrew(`brew install python`)、Windows なら公式インストーラで **「Add Python to PATH」のチェック**を忘れないことがポイントです。

### 3-2. Python 2 と 3、そして複数の Python

歴史的な理由で、コマンドには `python` と `python3` の2種類が存在します。古い Python 2 はすでにサポートが終わっているので、**私たちは常に `python3`** を基準にします。また、1台のコンピュータに Python が複数インストールされているのはよくあることで、正常です(OS 内蔵のもの、自分でインストールしたものなど)。大事なのは「いま自分のコマンドが**どの** Python を実行しているのか」で、その答えが `which python3` と `sys.executable` です。複数の Python が共存しても混乱しないための正式な解決策が、次のレベルの仮想環境です。

### 3-3. PATH — コンピュータがコマンドを探す順序

ターミナルに `python3` と打つと、シェルは **PATH というフォルダの一覧**を先頭から順に探し、その名前のプログラムを見つけます。会社でいえば「通訳者を探すとき、順番に訪ねる部署のリスト」です。「command not found」はそのリストのどこにも無いという意味で、見当違いのバージョンが実行されるなら、リストの前の方に別の Python がいるという意味です。PATH は環境変数のひとつで、level09 でさらに詳しく扱います。

### 3-4. スクリプト実行の慣例

- Python ファイルの拡張子は `.py` です。
- ファイル冒頭のダブルクォート3つ(`"""..."""`)で囲まれた段落は**ドックストリング(docstring)** — このファイルが何なのかを説明する文書です。
- `if __name__ == "__main__":` は「このファイルが直接実行されたときだけ以下を実行せよ」という慣例的な書き方です。いまは「本文開始の目印」とだけ理解すれば十分で、モジュールを学ぶ講義(lecture02)で仕組みを扱います。

## 4. 実習 — main.py

```bash
python3 main.py
```

このスクリプトは**自分の Python 環境の健康診断書**を出力します。

- **[1] 通訳者の身元確認**: Python のバージョン、実行ファイルの実際の場所(`sys.executable`)、そしてバージョンが 3.10 以上かを判定します。
- **[2] 勤務地の確認**: OS の種類(Mac/Windows/Linux)、プロセッサの種類、カレントワーキングディレクトリを表示します。
- **[3] PATH をざっと見る**: シェルがコマンドを探すフォルダ一覧の先頭部分を出力し、「コマンドを探す順序」が実際に存在することを確認します。
- **[4] REPL vs スクリプト**: 同じ計算を REPL ならどう打ったかを見せ、スクリプトとしていま実行されていることと対比させます。
- **[5] 総合判定**: 項目ごとの合否を整理した診断サマリーを出力します。

核心となるコードは `sys` と `platform` モジュールを使う部分です。`sys.version_info` でバージョンを数値として比較し、`sys.executable` で「いまこのコードを実行している Python」の正確な場所を得ます。この2行は、この先環境の問題が起きるたびに取り出して使う万能診断ツールなので、ぜひ覚えておいてください。

## 5. やってみよう

1. **(易しい)** ターミナルに `python3` と打って REPL に入り、`3 * 7`、`"こんにちは" * 3` を計算してから、`exit()` で抜けてみましょう。*(ヒント: `>>>` が見えたら成功です。Ctrl+D でも抜けられます。)*
2. **(普通)** main.py の [1] 段階で要求バージョンを (3, 10) から (3, 99) に変えて実行してみましょう。判定が「注意」に変わることを確認して、元に戻してください。*(ヒント: `REQUIRED` 変数を探しましょう。診断ロジックが実際に働いていることを確かめる実験です。)*
3. **(挑戦)** [2] 段階に「Python が何ビット環境にインストールされているか」を追加で出力してみましょう。*(ヒント: `platform.architecture()` を調べてみてください。)*

## 6. よくあるつまずき

- **`python` と `python3` の混用**: Mac では `python` が存在しないか、別のバージョンのことがあります。常に `python3` に統一しましょう(仮想環境の中では `python` も安全になります — 次のレベルで!)。
- **インストールしただけでターミナルを開き直さない**: PATH の変更は新しいターミナルウィンドウから反映されることが多いです。インストール後にコマンドが効かなければ、ターミナルを新しく開いてみましょう。
- **REPL にファイル実行コマンドを入力**: `>>>` の状態で `python3 main.py` と打つとエラーです。ファイルの実行は REPL を抜けてからシェルで行うものです。いま自分がシェル(`$`)にいるのか REPL(`>>>`)にいるのか、プロンプトで見分けましょう。
- **エラーメッセージを読まずに再インストールから始める**: 「command not found」と「SyntaxError」は原因がまったく違います。メッセージの最初の行と最後の行だけでも読めば、方向が見えてきます。
