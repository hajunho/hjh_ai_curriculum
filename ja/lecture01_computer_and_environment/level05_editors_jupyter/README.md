# Lecture 01 · Level 05 — コードエディタと Jupyter

> コードを「書く道具」であるエディタ(VS Code)と、「実験する道具」である Jupyter ノートブックの使い分けを理解し、ノートブックのセル実行方式をシミュレーションで体験します。

**難易度** ⭐⭐ / **前提** level04 / **想定時間** 35分

## 1. なぜ学ぶのか — ビジネスの視点

コードはメモ帳でも書けます。しかし実務で誰もそうしない理由は、良い道具がミスを事前に捕まえてくれて、作業速度を何倍にもしてくれるからです。Excel の代わりに電卓と紙で決算をしないのと同じ理屈です。

Python の作業道具は大きく2系統あります。プログラム(スクリプト)を作る**コードエディタ**、そしてデータをあれこれ触りながら探索する **Jupyter ノートブック(notebook)**。データアナリストの画面にはほぼ常にノートブックが、開発者の画面にはエディタが開いています。2つの使い分けがわかれば「この作業はどちらの道具でやるのが正しいか」を自分で判断でき、協業相手から送られてきた `.ipynb` ファイルの前で慌てずに済みます。特にノートブックの「セルの実行順序」の概念は、初めて使う人がいちばんよく転ぶポイントなので、このレベルで先に仕組みを身につけておきます。

## 2. たとえ話で理解する

**エディタは正式な報告書の作成道具、ノートブックは実験ノート**です。

- **VS Code のようなエディタ**は、ワープロで正式な報告書を書くのと同じです。完成した文書(スクリプト全体)を作って決裁(実行)にかける方式です。スペルチェック(文法エラーの表示)、目次ナビゲーション(関数への移動)、自動補完が強力です。成果物は、最初から最後まで順番に実行される `.py` ファイルです。
- **Jupyter ノートブック**は、実験室の実験ノートです。「この試薬を入れたら? → 結果を記録 → では温度を上げたら? → 結果を記録」のように、**1段階実行して結果を目で確認してから次の段階を決める**方式です。コードの断片(セル、cell)とその実行結果、そして説明文がひとつの文書に混ざっています。

重要な違いがひとつあります。実験ノートは**ページの順序と実験の順序がずれることがあります**。3ページ目の実験を先にやってから1ページ目に戻ってやり直すこともできますよね。ノートブックもセルをどんな順序でも実行できるのですが、すべてのセルは**ひとつの作業台(カーネル、kernel)の記憶を共有**しています。だから画面上で上にあるセルが下のセルより「後に」実行されていた場合、文書を上から下に読んだ人には結果がおかしく見えます。これがノートブック事故の 90% です。

## 3. 核心となる概念

### 3-1. 道具の選択基準

| 状況 | 合う道具 | 理由 |
|---|---|---|
| データを初めて受け取って探索 | ノートブック | 1段階ずつ結果を見ながら方向を決める |
| グラフを見ながら分析・報告資料の下書き | ノートブック | コード+結果+説明がひとつの文書に |
| 毎週回す自動化スクリプト | エディタ(.py) | 最初から最後まで順番どおり、再実行が保証される |
| 複数ファイルからなるプログラム開発 | エディタ | ファイル間の移動・検索・デバッグ |
| チームに共有する最終コード | エディタ(.py) | 実行順序が常に同じで信頼できる |

実務でよくある流れは、「ノートブックで実験 → 方法が確定したら `.py` スクリプトに整理」です。

### 3-2. VS Code の最初のセットアップ3つ

VS Code(Visual Studio Code)は無料で、事実上業界標準のエディタです。インストール後、この3つだけやっておけば大丈夫です。

1. **Python 拡張機能(extension)のインストール** — 左の拡張機能メニューで「Python」を検索してインストール。文法チェックと実行ボタンが使えるようになります。
2. **インタプリタの選択** — コマンドパレット(Cmd/Ctrl+Shift+P)で「Python: Select Interpreter」を開き、**プロジェクトの `.venv`** を指定します。level04 で学んだ「どの道具箱を使うのか」をエディタに教える手続きです。
3. **フォルダで開く** — ファイル1つではなくプロジェクトフォルダ全体を開いてこそ(File > Open Folder)、相対パスと検索がきちんと動きます。

### 3-3. ノートブックの構造: セル + カーネル

- **セル(cell)**: 数行のコードを入れる箱。Shift+Enter でそのセルだけ実行します。セルの左の `[3]` のような番号は、「このカーネルで3番目に実行された」という**実行順の番号**です。
- **カーネル(kernel)**: 裏で生きている Python のプロセス。すべてのセルがこのひとつの記憶(変数たち)を共有します。あるセルで作った変数は、別のセルからそのまま見えます。
- **再起動(restart)**: カーネルを再起動すると記憶がすべて初期化されます。「上から全部実行し直す(Restart & Run All)」が、再現性を確認する正式な手順です。

`.ipynb` ファイルは、セルとその出力が保存された JSON 文書です。VS Code の中でも開けますし、`jupyter lab` コマンドでブラウザからも開けます(どちらも pip でインストール: `pip install jupyterlab`)。

### 3-4. 順序事故(out-of-order)の正体

セル A で `price = 1000`、セル B で `price * 2` を実行したとしましょう。その後セル A を消しても、セル B は依然として動きます。カーネルの記憶に `price` が残っているからです。このノートブックを受け取った同僚が上から実行すると、`price` が無いというエラーに出会います。**画面のコードとカーネルの記憶はずれることがある** — これさえ覚えれば、ノートブック事故の大部分を理解したことになります。

## 4. 実習 — main.py

```bash
python3 main.py
```

Jupyter をインストールしなくてもノートブックの動作原理を体験できるように、**ミニノートブックシミュレータ**を作りました。

- **[1] ノートブックの構成**: 売上分析シナリオのセル4つ(データ準備 → 合計 → 平均 → 報告)を定義します。
- **[2] 順番どおり実行**: Run All のように上から実行し、セルごとに実行番号 `[n]` と出力、そして**カーネルの記憶(変数一覧)がセルを経るごとに積み上がっていく様子**を見せます。
- **[3] 順序事故の再現**: カーネルを再起動してから3番目のセルから実行して「上のセルを回さないと NameError」をわざと発生させ、続けてセルを画面の順序と違う順で実行すると結果がどうずれるかを見せます。
- **[4] 教訓の整理**: Restart & Run All がなぜ正式な手順なのかを出力でまとめます。

核心となるコードは `NotebookKernel` クラスです。`self.memory` という辞書ひとつがカーネルの記憶で、`run_cell()` は Python の組み込み関数 `exec()` でセルのコードをその記憶の上で実行します。実際の Jupyter カーネルの原理を、辞書ひとつに縮小した模型です。

## 5. やってみよう

1. **(易しい)** VS Code をインストールしてこのカリキュラムのフォルダを「フォルダで開く」で開き、この main.py を開いて実行してみましょう。*(ヒント: 右上の ▶ ボタン。インタプリタとして `.venv` を選ぶのを忘れずに。)*
2. **(普通)** main.py の `CELLS` に「売上トップの店舗を探す」セルをひとつ追加して、Run All の結果に出るようにしてみましょう。*(ヒント: `max(revenues)` を使い、前のセルで作った変数をそのまま利用できます — それがカーネルの共有記憶です。)*
3. **(挑戦)** [3] 段階を真似て、皆さんが選んだ別の実行順序(例: 4→2→3)で回すとどんなエラーやずれた結果になるかを予測し、コードで確認してみましょう。*(ヒント: `simulate_out_of_order()` の順序リストを変えるだけです。)*

## 6. よくあるつまずき

- **ノートブックのセルをばらばらに実行したまま保存・共有**: 受け取った人は再現できません。共有前に必ず「Restart & Run All」で最初から最後まできれいに回るか確認しましょう。
- **エディタのインタプリタ未指定**: ターミナルでは動くのに VS Code でだけ import エラーが出るなら、十中八九インタプリタが `.venv` ではありません。
- **すべての仕事をノートブックで**: ノートブックは実験用です。毎日回す自動化までノートブックに置くと、実行順序もバージョン管理もすべて難しくなります。確定したロジックは `.py` に移しましょう。
- **カーネルが死んでいるのにコードのせいにする**: 出力が出なければ、まずカーネルの状態(再起動が必要か)を確認しましょう。記憶が消えたカーネルでは、上のセルから実行し直す必要があります。
