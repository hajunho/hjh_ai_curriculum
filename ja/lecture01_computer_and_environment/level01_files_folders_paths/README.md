# Lecture 01 · Level 01 — ファイル・フォルダ・パスの概念

> コンピュータのすべてのデータはファイルであり、ファイルの住所がパス(path)であることを理解し、Python の pathlib でフォルダツリーを自分の手で作って探検します。

**難易度** ⭐ / **前提** level00 / **想定時間** 35分

## 1. なぜ学ぶのか — ビジネスの視点

開発を学んでいて出会うエラーのかなりの部分は、大げさなものではなく「ファイルが見つからない(FileNotFoundError)」です。データ分析をするなら CSV ファイルを読まなければならず、レポートを作ればどこかに保存しなければならず、AI モデルも結局はファイルとして保存されます。ところが、ファイルが「どこに」あるのかをコンピュータに正確に伝える方法、つまり**パス**を知らなければ、一歩も前に進めません。

実務の視点でも、パスの感覚はそのままお金になります。共有ドライブで「あのファイル、どこにありますか?」とやり取りする時間、間違ったフォルダに保存してバージョンが混乱する事故、バックアップから漏れたフォルダ — すべてパスとフォルダ構造への感覚不足から生まれます。このレベルを終えれば、どんなファイルの場所でも1行の住所で正確に表現できるようになり、Python でフォルダ構造を自動で作ったり探し回ったりできるようになります。

## 2. たとえ話で理解する

**フォルダ構造は会社ビルの住所体系**です。

東京本社のビルを想像してください。「本社ビル > 3階 > 営業部オフィス > 佐藤課長のキャビネット > 2024年契約書フォルダ > A社_契約書.pdf」。このように大きな場所から小さな場所へ段階を踏んで降りていけば、世の中のどんな書類でも正確にひとつに特定できます。コンピュータのパスがまさにこの方式です。

```
/Users/sato/Documents/contracts/2024/A社_契約書.pdf
```

先頭の `/` が「本社ビルの正面玄関(ルート、root)」で、`/` で区切られた各段階が階・オフィス・キャビネットに当たります。このように**正面玄関から住所を全部書いたものが絶対パス(absolute path)**です。

一方、社内で会話するときは「うちの部のキャビネットの 2024 フォルダにありますよ」と省略して言います。聞き手がいまどこにいるか(現在位置)をお互いに知っているからです。これが**相対パス(relative path)** — `contracts/2024/A社_契約書.pdf` のように現在位置を基準にした住所です。相対パスには特別な表記が2つあります。`.` は「いまいるこの部屋」、`..` は「ひとつ上の階(親フォルダ)」を意味します。

ファイル名の末尾の `.pdf`、`.xlsx`、`.py` のような**拡張子(extension)は、書類封筒に押された文書種別のハンコ**です。中身が何か(文書なのか、表なのか、コードなのか)を伝える約束事であり、OS はこのハンコを見てどのプログラムで開くかを決めます。

## 3. 核心となる概念

### 3-1. すべてはファイルである

コンピュータの中では、文書も写真もプログラムも、さらには設定値まで、すべてファイルです。ファイルは「名前 + 内容(0 と 1 の並び) + 場所」でできていて、フォルダ(ディレクトリ、directory)はファイルを入れる容れ物であり、別のフォルダも入れられる容れ物です。だから全体の構造は、根から枝が伸びる**ツリー(tree)構造**になります。

### 3-2. 絶対パス vs 相対パス

| 区分 | 絶対パス | 相対パス |
|---|---|---|
| 起点 | ルート(`/`)またはドライブ(`C:\`) | 現在の作業フォルダ |
| 例 | `/Users/sato/data/sales.csv` | `data/sales.csv` |
| 長所 | どこで実行しても同じファイルを指す | 短く、プロジェクトごと移動しても有効 |
| 短所 | 別のコンピュータでは壊れやすい | 「現在位置」が違うと見当違いの場所を指す |

ここでいう「現在位置」を**カレントワーキングディレクトリ(current working directory、CWD)**と呼びます。プログラムをどのフォルダから実行したかがそのまま CWD であり、相対パスはすべてここを基準に解釈されます。相対パスのエラーの 90% は、「自分が思っている現在位置」と「実際の CWD」が違うことで起きます。

### 3-3. OS ごとの違い

Mac/Linux では区切り文字が `/` で、ルートは `/` ひとつです。Windows では区切り文字が `\` で、`C:\`、`D:\` のようにドライブごとにルートがあります。この違いのせいで、パスを文字列で直接つなぎ合わせると別の OS で壊れます。Python の **pathlib** ライブラリはこの違いを自動で処理してくれるので、このカリキュラムでは最初から pathlib を標準として使います。

### 3-4. pathlib の核心5つ

```python
from pathlib import Path
p = Path("data") / "sales.csv"   # パスの組み立て: / 演算子で安全に
p.exists()                        # 存在確認
p.mkdir(parents=True, exist_ok=True)  # フォルダ作成 (途中のフォルダごと、既存でもエラーなし)
p.resolve()                       # 絶対パスに変換
p.suffix, p.stem, p.parent        # 拡張子、名前、親フォルダ
```

この5つさえ知っていれば、以降の講義のファイル操作の大部分が読めるようになります。

## 4. 実習 — main.py

```bash
python3 main.py
```

このスクリプトは、一時フォルダの中に小さな架空の会社「あさひ商事」の文書ツリーを作って探検します。

- **[1] ツリー生成**: `総務部/`、`営業部/契約書/`、`営業部/報告書/` のような部署フォルダとサンプルファイルを pathlib で作ります。
- **[2] ツリー描画**: 再帰関数でフォルダ構造をインデント付きのツリー図として出力します。ターミナルの `tree` コマンドを Python で真似たものです。
- **[3] 絶対 vs 相対**: 同じファイルを絶対パスと相対パスの2通りで表現して比較し、`..` がどう動くかを見せます。
- **[4] 拡張子の分析**: ツリー全体を探し回って(`rglob`)、拡張子ごとにファイル数を集計します。「会社の文書庫にどんな種類の書類が何枚あるか」を数えるわけです。
- **[5] パスの解剖**: パスひとつを parent / name / stem / suffix に分解して見せます。

核心となるコードは `draw_tree()` 関数です。フォルダを開けて中身を並べ、中身がフォルダなら自分自身をもう一度呼び出す**再帰(recursion)**構造で、ツリー構造を扱うもっとも自然な方法なので、この先も何度も出会います。実習が終わると一時フォルダは自動的に削除されるので、皆さんのコンピュータに痕跡は残りません。

## 6. よくあるつまずき

- **パスを文字列の足し算で組み立てる**: `"data" + "/" + "sales.csv"` は Windows で壊れることがあります。常に `Path("data") / "sales.csv"` を使いましょう。
- **CWD の勘違い**: スクリプトファイルのあるフォルダと、実行したフォルダは別のことがあります。スクリプト基準のパスが必要なら `Path(__file__).parent` を使います。
- **拡張子を消したり間違えて変える**: 拡張子は中身を変えません。`report.xlsx` を `report.csv` に名前だけ変えても CSV にはならず、むしろ開けなくなります。
- **日本語や空白を含むパス**: できればフォルダ・ファイル名は半角英小文字とアンダースコア(`sales_2024.csv`)で付ける習慣にしましょう。空白や日本語は、ターミナルやコードで引用符が必要になるなど、何かと手間がかかります。
