# Lecture 06 · Level 11 — 勾配ブースティングとモデル解釈

> 誤答ノートを繰り返し学習するブースティングで性能を引き上げ、順列重要度と個別予測の説明で「なぜ?」という質問に答える方法を学びます。
**難易度** ⭐⭐⭐⭐⭐ / **前提** level07, level08 / **想定時間** 60分

## 1. なぜ学ぶのか — ビジネスの視点

表形式データの予測における実戦最強を 1 つだけ挙げるなら、勾配ブースティング (gradient boosting) です。データ分析コンペの上位陣と、企業の解約・延滞・需要予測システムのかなりの部分がブースティング系です。sklearn の `HistGradientBoostingClassifier` 1 つで、その世界の標準技法を使えます。

しかし強いモデルほど新しい問題が生まれます。**「モデル様がこの顧客は危険だと言っていますが、なぜですか?」** フォロー担当者は根拠なしに電話をかけられませんし、審査員は根拠なしに承認を拒否できず、規制当局は説明を要求します。だからこの最後のレベルは 2 部構成です — 前半はブースティングで性能を上げる方法、後半はそのブラックボックスを再び開ける方法 (順列重要度、部分依存、個別予測の説明)。性能と説明を両方扱えて初めて、ML を組織に根付かせることができます。

## 2. 比喩で理解する

**誤答ノート勉強法**がブースティングのすべてです。ランダムフォレスト (level08) が「学生 300 人がそれぞれ勉強して投票」だとすれば、ブースティングは**1 人の学生が誤答ノートを作りながら成長していく直列のプロセス**です。

1 時間目: 最初の問題集を解いてみます。成績は平凡です。2 時間目: **間違えた問題だけを集めた誤答ノート**を作り、その部分を集中的に勉強します。3 時間目: それでも残った誤答でまた誤答ノートを作り…… これを数百回繰り返します。各時間の勉強 (小さな木 1 本) は浅くて弱いのですが、「直前までの間違いを矯正する」方向にこつこつ積み上がるので、最終的な実力はとても強くなります。

ただし、誤答ノート勉強の罠もそのまま受け継ぎます。問題集の**誤植 (ノイズ) まで暗記し始めたら**過学習です。だからブースティングには「1 時間分の反映度合いを抑える」学習率 (learning rate) や早期終了のようなブレーキが必須です — level09 の哲学がそのまま戻ってきます。

解釈の道具も比喩で押さえておきましょう。**順列重要度 (permutation importance) は「その科目の答案をシャッフルしてみる」**ことです。ある特徴量の値を無作為にかき混ぜてモデルに入れたとき、成績がガクッと落ちればその特徴量に大きく依存していたという意味で、落ちなければ、なくてもよい特徴量だったという意味です。

## 3. 核心概念

### 3.1 ブースティングの構造

予測 = 木1 + η·木2 + η·木3 + … (η=学習率)。各木は「これまでの予測が残した誤差」を当てるように学習されます (回帰の観点での残差の矯正 — 名前の gradient はこの誤差の方向を指します)。ランダムフォレストとの対比が核心です。

| | ランダムフォレスト | 勾配ブースティング |
|---|---|---|
| 木の関係 | 並列・独立 (投票) | 直列・依存 (誤答の矯正) |
| 個々の木 | 深くて強い | 浅くて弱い (深さ 3〜8) |
| 主な効果 | バリアンス (揺れ) の減少 | バイアス (系統誤差) の減少 |
| 過学習リスク | 低めの方 | **チューニングしないと高い** |
| 主なつまみ | 木の数 | 学習率 × 木の数 × 深さ |

`HistGradientBoosting` は連続値をヒストグラムの区間にまとめて高速処理する現代的な実装で、早期終了 (`early_stopping`) が内蔵されており、検証成績が伸びなければ勝手に止まります。

### 3.2 順列重要度 — より公正な重要度

level07〜08 の不純度重要度は「訓練中によく使われた度合い」なのでバイアスがありました。順列重要度は**完成したモデルをテストデータで尋問**します: 特徴量 1 つの列だけを無作為にシャッフルし (他の列はそのまま)、性能の下落幅を測ります。モデルの種類を問わずに使え、「実際の予測力への寄与」を測るので、報告用としてより正直です。注意点: 互いに相関の高い特徴量同士はお互いを肩代わりできるため、両方とも低く出ることがあります。

### 3.3 部分依存 — 特徴量 1 つの影響曲線

部分依存 (partial dependence) は、「他の条件をそのままにして、特徴量 1 つだけ値を変えていくと平均予測がどう変わるか」の曲線です。「利用日数が 0→30 に増えるとき、解約確率がどんな形で下がっていくのか」 — 係数 1 つに要約されるロジスティックと違い、ブースティングの非線形な関係 (例: 10 日を下回ると急増) をあらわにします。因果ではなく**モデルが学習した関連の形**であることは変わりません。

### 3.4 個別予測の説明 — 「この顧客はなぜ?」

全体的な傾向 (重要度・部分依存) とは別に、特定の顧客 1 人の判定根拠が必要になる場面は多いものです。実務標準は寄与度分解 (SHAP 系) のツールですが、原理は今日自分の手で実装できます: **「この顧客の特徴量を 1 つ、平均的な値に差し替えたら予測がどれだけ変わるか」**を特徴量ごとに測るのです。変化幅の大きい特徴量が、その顧客の判定の主な根拠です。この概念さえあれば、専門ツールの出力も読めるようになります。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

churn_table でブースティングモデルを作り、解釈まで完走します。

- **[1]** データの準備、訓練/テストの分割。
- **[2]** ロジスティック (level05)・ランダムフォレスト (level08)・`HistGradientBoostingClassifier` の 3 モデルのテスト AUC を並べて比較します — これまで学んだモデルたちの卒業試験です。ネタバレ: この合成データではロジスティックが勝ちます。データの本当の構造が線形の採点表だからで、「強いモデルではなく、データ構造に合ったモデルが勝つ」というのが、この比較の本当の観察ポイントです。
- **[3]** 学習率×木の数の関係をミニ実験で確認します: 学習率を下げると木がより多く必要になるものの、性能が安定する傾向。
- **[4] 順列重要度**: `permutation_importance` で特徴量別の AUC 下落幅を出力し、不純度重要度 (参考用) と順位を比較します。
- **[5] 部分依存**: `partial_dependence` で利用日数・問い合わせ数の影響曲線をテキストグラフで出力します — どの区間でリスクが急変するか読んでみてください。
- **[6] 個別予測の説明**: 高リスク顧客 1 人を選び、「特徴量を平均値に差し替えたときの解約確率の変化」を特徴量ごとに出力します。「問い合わせ 4 回→平均水準なら確率 −N%p」のような文章が、フォロー担当のトークスクリプトの根拠になります。

コードの心臓部: `HistGradientBoostingClassifier(early_stopping=True)`、`permutation_importance(..., scoring="roc_auc")`、`partial_dependence(...)`、そして [6] の `explain_one()` — 12 行の差し替え式説明器です。

## 6. よくある間違い

- **ブースティングをデフォルト設定で回して放置すること**: ランダムフォレストよりチューニングへの敏感さが高いです。最低でも学習率・早期終了・深さは検証で調整しましょう。
- **性能が良いから説明は省略すること**: 採用されないモデルの AUC は 0 と同じです。報告書には性能の表と解釈 (重要度・部分依存・事例の説明) をセットで載せましょう。
- **順列重要度と不純度重要度を混ぜて表記すること**: 2 つは定義が違い、順位も変わり得ます。どちらの重要度か明記しましょう。
- **部分依存・寄与度を因果に格上げすること**: 「問い合わせを減らせば解約が減る」ではなく「問い合わせの多い顧客をモデルが危険とみなしている」です。介入の効果は実験でしか証明できません。
- **説明の対象データに訓練セットを使うこと**: 順列重要度も性能報告もテスト (または検証) データ基準にして初めて、楽観バイアス (level04) がなくなります。
