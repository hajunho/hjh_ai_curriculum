# Lecture 06 · Level 01 — 教師あり・教師なし・強化学習

> 機械学習の 3 大学習方式を、家庭教師・自主ゼミ・犬のしつけにたとえて整理し、それぞれをおもちゃサイズの例で実際に動かしてみます。
**難易度** ⭐ / **前提** level00 / **想定時間** 30分

## 1. なぜ学ぶのか — ビジネスの視点

外部ベンダーが「弊社は教師なし学習ベースの異常検知ソリューションです」と提案してきたり、データチームが「これは教師あり学習で解く必要があるので、まずラベル付け作業が必要です」と言ってきたりしたとき、この 3 つの言葉を知らないと会話そのものが成り立ちません。もっと実質的な理由もあります。**どの方式を使うかによって、準備すべきデータとコストがまったく変わるからです。** 教師あり学習は正解ラベルを作るコストがかかり、教師なし学習は結果の解釈に人手がかかり、強化学習は試行錯誤を許容できる環境が必要です。問題をどの方式で解くかを決めた瞬間に、プロジェクト予算の大枠が決まります。

## 2. 比喩で理解する

3 つの勉強のやり方を思い浮かべてみてください。

**教師あり学習 (Supervised Learning) = 家庭教師。** 先生が問題と解答をセットで渡してくれます。「この問題の答えは 3 番だよ」。生徒は問題→正解の対応を繰り返し見てパターンを身につけ、後で解答のない新しい問題を解きます。解答 (ラベル) を作ってくれる人が必ず必要です。

**教師なし学習 (Unsupervised Learning) = 自主ゼミ。** 解答がありません。代わりに資料の山を渡され、「似たもの同士でまとめて、構造を見つけてみて」という課題を出されます。図書館で 1万冊の本を分類表なしに受け取り、似た本同士で棚を分けていく司書の仕事と同じです。まとまり自体は機械が作りますが、それぞれのまとまりに「これはミステリーのコーナーだな」と名前を付けるのは人間の役目です。

**強化学習 (Reinforcement Learning) = 犬のしつけ。** 解答も資料の山もありません。犬が「おすわり」で座ればおやつ (報酬)、よそ見をすれば無反応 (報酬なし)。犬は正解を教わったことがないのに、**試す→報酬**の繰り返しで、だんだんおやつを多くもらえる行動を見つけ出します。核心は「やってみるまで何が良いか分からない」こと、そして「すでに良さそうな行動だけを繰り返すか (活用)、新しい行動を試すか (探索)」の間の綱引きです。

## 3. 核心概念

### 3.1 3 方式を一目で比較

| | 教師あり学習 | 教師なし学習 | 強化学習 |
|---|---|---|---|
| 与えられるもの | 入力 + 正解ラベル | 入力のみ | 環境 + 報酬シグナル |
| 学ぶもの | 入力→正解の対応 | データの隠れた構造 | 報酬を最大化する行動 |
| 比喩 | 家庭教師 | 自主ゼミ | 犬のしつけ |
| 準備コスト | ラベリング作業 | 解釈作業 | 試行錯誤できる環境 |

### 3.2 業務の事例マップ

- **教師あり学習**: 解約予測 (顧客→解約するか)、売上予測 (広告費→売上)、不正取引の分類、書類の自動仕分け、需要予測。**実務の ML プロジェクトの 8 割以上がここに属します。** この講義でも level03〜09 と 11 はすべて教師あり学習です。
- **教師なし学習**: 顧客セグメンテーション (誰がどのグループかに正解がない)、新種の異常パターン検知 (過去にない不正なのでラベルがない)、文書のトピック分け、変数の圧縮 (次元削減)。level10 で扱います。
- **強化学習**: 広告予算のリアルタイム配分、レコメンド順序の最適化、ゲームやロボットの制御、そして最近では対話型 AI を人の好みに合わせて仕上げる段階でも使われます。一般企業の実務で自ら実装する機会はまれですが、概念は知っておくべきです。

### 3.3 見分ける基準は「何が与えられているか」

同じビジネス課題でも、データの状況によって方式は変わります。不正検知を例にとると — 過去の不正事例にラベルがきちんと付いているなら教師あり学習、ラベルはないが「正常な取引の群れから浮いているもの」を見つけたいなら教師なし学習、ブロック/通過の判断による損失・利益がリアルタイムのフィードバックとして返ってくるなら強化学習的な設計も可能です。**問題の種類ではなく、データとフィードバックの形が方式を決めます。**

### 3.4 教師あり学習の 2 つの枝

教師あり学習は、正解の形によって 2 つに分かれます。正解が数値 (売上額、需要量) なら**回帰 (regression)**、正解がカテゴリ (解約/継続、不正/正常) なら**分類 (classification)** です。level03 が回帰、level05 からが分類です。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

3 つのパラダイムを、それぞれ超ミニ例題で体験します。

- **[1] 教師あり学習 — 家庭教師**: 解約顧客データの正解ラベルを見せながらロジスティック回帰を訓練し、初めて見る顧客 3 人の解約可能性を予測させます。「解答を渡して教えたら、新しい問題が解けるようになる」を確認します。
- **[2] 教師なし学習 — 自主ゼミ**: 同じ種類の顧客データから**正解の列をわざと外して**、k-means に「3 グループにまとめてみて」とだけ指示します。機械が作ったグループ別の平均プロフィールが出力されたら、人間の役目 — 「このグループは優良顧客だな」と名前を付ける作業 — をやってみてください。
- **[3] 強化学習 — 犬のしつけ**: 利用率の異なるクーポン 3 種のどれが良いか分からない状態で、エージェントがクーポンを送ってみて (試行)、反応 (報酬) だけから徐々に最適なクーポンを見つけていく過程をシミュレーションします (多腕バンディット、epsilon-greedy を自前で実装)。序盤 100 回と最後の 100 回で平均報酬がどう変わるかを見てください。
- **[4]** 3 つの実験を表にまとめます。

コードで見るべきところ: [1] は `fit(X, y)` のように**正解 y を渡し**、[2] は `fit(X)` のように **y なし**で呼びます。関数シグネチャ 1 つに、2 つのパラダイムの違いがそのまま表れています。[3] はライブラリなしの 20 行ほどの純粋な Python ループです — 探索率 `epsilon` の値が学習スピードを左右します。

## 5. やってみよう

1. **(かんたん)** [3] の `EPSILON` を 0.0 に変えて実行してみてください。探索をまったくしないとどうなるでしょうか? 最初の数回の運次第で、悪いクーポンに閉じ込められる現象を観察してみましょう。(ヒント: seed を変えながら何度か)
2. **(ふつう)** [2] のクラスタ数を 3 から 2 や 5 に変えてみてください。グループのプロフィールはどう変わりますか? 「何グループが適切か」に正解がないことが、教師なし学習の特徴です。
3. **(チャレンジ)** [1] の訓練データを 2000 人から 50 人に減らしてみてください。予測はどれくらい不安定になるでしょうか? 「教師あり学習の力 = ラベル付きデータの量」であることを確かめてみましょう。

## 6. よくある間違い

- **「教師なし学習は正解が要らないからタダ」という誤解**: ラベルのコストの代わりに解釈のコストがかかります。機械が作ったグループが業務的に意味を持つかを判定するのは、やはり人間の仕事です。
- **強化学習を何にでも提案すること**: 試行錯誤 1 回のコストが大きい業務 (融資審査、医療) では、「とりあえずやってみて学ぶ」は許されません。
- **回帰と分類を混ぜて話すこと**: 「解約率を回帰で予測する」と「解約するかどうかを分類で予測する」は別の問題設計です。まず正解の形から確認しましょう。
- **パラダイムを先に決めてデータを当てはめること**: 順序が逆です。手元のデータとフィードバックの形がパラダイムを決めます。
