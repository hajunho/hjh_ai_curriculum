# Lecture 06 · Level 07 — 決定木

> 二十の質問ゲームのように問いを投げて枝分かれするモデルを作り、学習された木を人が読めるルール文として出力し、解釈します。
**難易度** ⭐⭐⭐ / **前提** level05, level06 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

ロジスティック回帰は優れていますが「採点表」モデルなので、2 つの物足りなさがあります。第一に、直線的な関係しか捉えられません — 「利用日数が 10 日未満で、なおかつ新規顧客のときだけリスクが急増する」のような条件の組み合わせパターンに弱いのです。第二に、係数・オッズ比という翻訳の段階を経ないと説明になりません。

決定木 (decision tree) は正反対の魅力を持つモデルです。学習の結果が**「もし〜なら → そうでなければ →」のルール集**そのものなので、現場の担当者や経営層にそのまま見せられます。「なぜこの顧客がリスク判定なのですか?」という質問に、「利用日数が 9 日以下で、自動決済が未設定で、契約 8 か月未満だからです」と答えられるのです。規制産業 (金融・医療) で説明可能性が要求されるとき、そしてモデルの発見を業務ルールとして逆輸入したいとき、決定木は今でも第一候補です。しかも、次の 2 つのレベル (ランダムフォレスト、ブースティング) の部品でもあります。

## 2. 比喩で理解する

**二十の質問ゲーム (Twenty Questions)** を思い浮かべてください。上級者は「それってゾウですか?」といきなり当てにいきません。「生き物ですか?」→「動物ですか?」→「四本足ですか?」のように、**1 回の質問で候補を最も大きく半分に割る質問**から投げます。

決定木の学習が、まさにこの戦略です。顧客 1,500 人が解約/継続の入り混じった状態で 1 つの部屋に集まっています。木は可能なすべての質問 (「利用日数 ≤ 9.5 か?」「契約月数 ≤ 3.5 か?」……) を試してみて、**分かれた 2 つの部屋の純度が最も高くなる質問**を選びます。そして各部屋で同じことを繰り返します。何回か枝分かれすると「ここはほぼ全員が解約顧客の部屋」「ここはほぼ全員が継続顧客の部屋」ができあがり、新しい顧客が来たら質問をたどって降りていき、たどり着いた部屋の多数決で予測します。

注意すべき点も二十の質問ゲームと同じです。質問を無制限に許すと、「もしかして田中太郎さんですか?」のような質問まで使って 1 人だけの部屋を 1,500 個作れてしまいます — 訓練データは 100% 当てられますが、新しい顧客には役に立たない丸暗記 (level04 の過学習) です。だから質問の回数 (深さ) を制限します。

## 3. 核心概念

### 3.1 不純度 — 「部屋がどれだけ混ざっているか」の点数

良い質問 = 部屋の混ざり具合 (不純度、impurity) を最も大きく減らす質問。代表的な尺度がジニ不純度 (Gini impurity) です。

```
Gini = 1 − (解約の割合² + 継続の割合²)
```

部屋が全部 1 種類なら 0 (純粋)、半々なら 0.5 (最悪)。木は各候補の質問について「質問後の 2 部屋の (サイズ加重) 平均不純度」を計算し、減少幅が最大の質問を採択します。level00 のしきい値探索と同じ原理が再帰的に繰り返されているだけです — ここでも学習は魔法ではなく探索です。

### 3.2 深さと過学習

- **深さ 1〜2**: 部屋 2〜4 個。大まかな構図しか捉えられない代わりに、絶対に過学習しません。「ビジネスルール候補の発掘」に適しています。
- **深さ 3〜5**: 実務の解釈用スイートスポット。人間が読める最後のサイズでもあります。
- **深さ無制限**: 訓練の正解率 〜100%、テストの正解率はむしろ下落。level04 の実験 A ですでに目撃した現象です。

深さのほかにも `min_samples_leaf` (部屋の最少人数 — 1 人だけの部屋を禁止) のようなブレーキ装置があります。

### 3.3 木の長所と短所

**長所**: ルールがそのまま見える / 標準化・スケーリングが不要 (しきい値比較なので単位と無関係) / 非線形・条件組み合わせパターンを捕捉 / 数値・カテゴリ混在に強い。
**短所**: **不安定** — データが少し変わると最初の質問から変わって木全体が別物になり得る / 階段状の予測なので滑らかな関係には非効率 / 単独の性能はふつうロジスティック回帰と同等か少し良い程度。この不安定性の問題を「多数の木の投票」で解決するのが、次のレベルのランダムフォレストです。

### 3.4 ルールの逆輸入という活用法

木で発見された上位の分岐 (「利用日数 ≤ 9.5 かつ自動決済未設定 → 解約率 45%」) は、モデルなしでも CRM ルールとしてすぐに使えます。モデルをデプロイしない組織でも、木の分析だけで価値が出る理由です。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

churn_table で解約予測の木を作り、解釈します。

- **[1]** データの準備と分割 (標準化が不要である点がコードで確認できます)。
- **[2]** ジニ不純度を直接計算してみます: 部屋全体の不純度 vs 「利用日数 ≤ 9.5」という質問の後の平均不純度 → 減少幅がそのまま質問の値打ちです。
- **[3]** 深さ 3 の木を学習して `export_text` でルール全文を出力し、解約率の高い葉 (leaf) の部屋上位 3 つの人数・解約率をまとめます。解約者が 15% しかいないため、`class_weight="balanced"` オプションで少数派クラスを重く扱い、解約側のルールが木に現れるようにしました — 出力されたルールを上から声に出して読みながら、リスクの部屋までの経路をたどってみてください。
- **[4]** 深さ 1, 3, 5, 10, 無制限と変えながら訓練/テストの正解率の表を出力 — 過学習の分かれ道を再確認します。
- **[5]** 特徴量の重要度 (feature importance) を出力します: 各特徴量が不純度の減少に寄与した割合。

コードの心臓部: `DecisionTreeClassifier(max_depth=3)` と `export_text(tree, feature_names=...)`。出力されたルールの木を上から下へ声に出して読んでみてください — モデルが発見したビジネスルールが、そのまま文章になります。そして [2] の `gini()` 関数 8 行が、このすべての数学の全部です。

## 5. やってみよう

1. **(かんたん)** [3] の `max_depth` を 2 に減らしてみてください。ルールはいくつに減り、テストの成績はどれだけ損をしますか? 経営層への報告用なら、深さ 2 と 3 のどちらを選びますか?
2. **(ふつう)** `min_samples_leaf=50` を指定して深さ無制限で学習してみてください。深さ制限なしでも過学習は抑えられますか? 2 つのブレーキ装置の違いを言葉で説明してみましょう。
3. **(チャレンジ)** 訓練データの seed を 7 から 8 に変えて新しいデータで深さ 3 の木を再学習し、ルールがどれだけ変わるか比較してみてください。3.3 で述べた「木の不安定性」です。この観察を覚えておくと、level08 がずっとよく理解できます。

## 6. よくある間違い

- **深い木の訓練成績に感動すること**: 深さ無制限の木の訓練正解率 100% は実力ではなく丸暗記です (level04)。
- **木のルールを永久の真理として扱うこと**: 木は不安定です。データが更新されればルールも変わり得るので、逆輸入したルールには有効期限を設けましょう。
- **不純度の重要度を因果として解釈すること**: 特徴量の重要度は「モデルがよく使った度合い」であって「原因」のランキングではありません。また、値の種類が多い特徴量が過大評価されるバイアスもあります (代替は level11 の順列重要度)。
- **木の前でスケーリングやワンホットの悩みに時間を浪費すること**: しきい値比較のモデルなので標準化は不要です。モデルごとに前処理の要求が違うことを覚えておきましょう。

## 次のレベルの予告

木 1 本は読みやすいけれど不安定です。level08 では「互いに少しずつ違う木を数百本育てて投票させる」ランダムフォレストで、解釈力の一部を差し出して性能と安定性を買う取引をしてみます。
