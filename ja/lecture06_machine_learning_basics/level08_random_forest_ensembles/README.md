# Lecture 06 · Level 08 — ランダムフォレストとアンサンブル

> 不安定な木 1 本の代わりに、互いに少しずつ違う木を数百本育てて投票させると、なぜより強くなるのか — 集団知性の原理を実験で確かめます。
**難易度** ⭐⭐⭐ / **前提** level07 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

表形式 (tabular) データの実務予測問題 — 解約、延滞、需要、コンバージョン — で「とりあえず回してみる強力な基本形」がランダムフォレスト (random forest) です。前処理にうるさくなく、ハイパーパラメータをほとんど触らなくてもそこそこの性能が出て、過学習に比較的強い。データ分析コンペと実際の企業の現場の両方で、「初回提出用モデル」の王座を長く守ってきた理由です。

ビジネスの視点でのこのレベルのもう 1 つの収穫は、**安定性**という評価軸を手に入れることです。今月のデータで作ったモデルと来月のデータで作ったモデルがまったく違うことを言い出したら、性能が良くても組織は信頼しません。「性能がどれだけ良いか」と同じくらい「結果がどれだけ揺れるか」を問う習慣を、ここで作ります。

## 2. 比喩で理解する

**牛の体重当てコンテスト**の話が有名です。祭りで 1 頭の牛の体重を数百人の観衆がそれぞれ推測したところ、個々人は大きく外しましたが、**すべての推測の平均は専門家よりも正確**でした。それぞれの間違いが互いに違う方向を向いているので、平均を取ると相殺されるからです。これが集団知性であり、アンサンブル (ensemble) の原理です。

ただし、条件があります。**参加者が互いに独立して考えること**です。全員が 1 人の答えを写したら、平均を取ってもその人の誤差がそのまま残ります。ランダムフォレストは、木同士が似通わないように 2 つの仕掛けを使います。

1. **バギング (bagging)**: 各木に、元と同じサイズのデータを**復元抽出**で引き直して渡します (ブートストラップ)。木ごとに少しずつ違う「経験」をすることになります。
2. **特徴量のランダム選択**: 各分岐で、全特徴量のうち一部だけを候補として渡します。これがないと、すべての木が最強の特徴量で最初の質問を始めてしまい、互いに似てしまいます。会議でいえば「声の大きい人が先に話すの禁止」ルールです。

こうして育てた数百本の木が、投票 (分類) または平均 (回帰) で最終的な答えを出します。

## 3. 核心概念

### 3.1 なぜ平均が分散を減らすのか

木 1 本の誤差は「系統的なバイアス + そのときどきの揺れ (バリアンス)」に分かれます。level07 で見た木の不安定性が、まさにバリアンスです。互いに独立に近い木を T 本平均すると、揺れはおよそ 1/√T に減ります — コインをたくさん投げるほど表の割合が 50% に近づくのと同じ統計の原理です。バイアスは平均では減らないので、フォレストは「深い木 (低バイアス・高バリアンス) をたくさん平均する」戦略を取ります。個々の木は過学習していても、平均すれば過学習は大きく緩和されます。

### 3.2 ランダムフォレストの主なつまみ

- `n_estimators` (木の数): 多いほど安定。性能はある地点から収束するので 100〜500 が通常。
- `max_features` (分岐あたりの特徴量候補数): 小さいほど木同士が違ってくる (多様性↑、個々の実力↓)。
- `max_depth`, `min_samples_leaf`: 木のときと同じブレーキ装置。フォレストでは緩めに置いてもよい方です。

### 3.3 特徴量の重要度と OOB

フォレストは、木々の不純度減少への寄与を平均して特徴量の重要度 (feature importance) を出します。1 本の木の重要度よりはるかに安定しているので、実務の報告によく使われます (ただし level07 で述べたバイアスへの注意は依然として有効 — より公正な順列重要度は level11 で)。おまけに、各木が復元抽出で見なかったデータ (OOB、out-of-bag) で自己検証スコアを出せるため、別途の検証セットなしでもおおよその性能推定ができます。

### 3.4 失うもの: 解釈力と軽さ

木 1 本はルールを声に出して読めましたが、木 300 本の投票はそうは読めません。モデルのサイズと予測時間も大きくなります。**「読める 1 本」と「強くて安定した森」の間の取引** — どちらを選ぶかは用途 (報告用 vs 運用) が決めます。両方欲しいときの解釈テクニックが level11 のテーマです。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

churn_table で単一の木 vs ランダムフォレストを、性能と安定性の両面から比較します。

- **[1]** データの準備。
- **[2] ミニバギングの自前実装**: sklearn のフォレストを使う前に、「復元抽出したデータで深い木を 25 本育てて投票」を 15 行で自作し、単一の深い木と比較します。平均の力がライブラリの魔法ではないことを確認する段階です。
- **[3] 性能比較**: 単一の木 (深さ制限あり/無制限) と `RandomForestClassifier` のテスト AUC・再現率を比較します。
- **[4] 安定性比較**: 無作為な分割を 12 回変えながら、単一の木とフォレストの AUC を反復測定し、平均±標準偏差で「揺れ」を比較します。フォレストの標準偏差が目に見えて小さいことが核心の観察です。
- **[5]** フォレストの特徴量重要度を、単一の木の重要度と並べて出力します — どちらがもっともらしく、安定して見えますか?

コードの心臓部: [2] の `bagged_predict()` — `rng.choice(n, n, replace=True)` でブートストラップ標本を作り、木々の確率の平均で投票する部分です。sklearn の 1 行 (`RandomForestClassifier(n_estimators=300)`) は、この原理に特徴量のランダム選択を足したものです。

## 6. よくある間違い

- **「フォレストは過学習しない」という過信**: 緩和されるだけで免疫ではありません。特にデータが少なかったりリーク特徴量があったりすると、同じようにだまされます。
- **安定性を測らず 1 回の分割で結論すること**: 1 回の測定値の差 (例: AUC 0.821 vs 0.815) は分割の運かもしれません。反復測定の平均±標準偏差で語りましょう。
- **特徴量重要度を因果・絶対順位として報告すること**: 相関の高い特徴量同士が重要度を分け合う現象 (希釈) があります。重要度が低いからといって「影響なし」ではありません。
- **解釈が必要な場でフォレストだけを差し出すこと**: 経営層には、深さ 3 の木 1 枚の方がフォレストの成績表より説得力を持つことが多いのです。用途に合ったモデルを選びましょう。
