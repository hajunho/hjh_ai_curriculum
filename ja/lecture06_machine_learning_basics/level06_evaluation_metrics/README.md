# Lecture 06 · Level 06 — 評価指標: 正解率の落とし穴

> 「正解率 98.5%」なのに不正を 1 件も捕まえられないモデルを実際に作ってみて、混同行列・適合率・再現率・F1・ROC-AUC でモデルを正しく読む方法を学びます。
**難易度** ⭐⭐⭐ / **前提** level05 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

このレベルは、ML の報告書にだまされないための最低限のリテラシーです。「正解率 98.5% の不正取引検知モデル」という報告は立派に聞こえますが、不正比率が 1.5% のデータでは、**「全部正常」と言い張るだけの張りぼてモデルでも正解率 98.5%** が出ます。実際に、数億ウォン規模のプロジェクトがこの錯覚の上で承認される、ということが起こります。

評価指標を知っている人は違う聞き方をします。「再現率は? 適合率は? そのしきい値で空振り警報は 1 日何件ですか?」 この質問を投げられるかどうかが、ML の成果物をただ消費するだけの人と、検証できる人を分けます。そして指標の選択は技術の問題ではなく、**ビジネスの損益の問題**です — 見逃した不正 1 件のコストと空振り警報 1 件のコストを知っている人が指標を選ぶべきなのです。

## 2. 比喩で理解する

**空港の保安検査場**を考えてみてください。危険物を持った乗客は 1万人のうち数人だけです。検査場が「全員通過」と叫べば正解率は 99.9% 以上 — しかしその検査場には存在する意味がありません。検査場の実力は、2 つの質問で測るべきです。

1. **危険物所持者のうち何 % を捕まえたか?** — これが再現率 (recall) です。見逃せば大事故。
2. **警報が鳴った人のうち何 % が本物だったか?** — これが適合率 (precision) です。空振り警報が頻発すると行列が伸び、警報そのものを誰も信じなくなります。

2 つの指標はシーソーの関係です。検査場の感度を最大に上げれば (すべてのベルトや腕時計に警報) 再現率は 100% ですが適合率は底をつき、感度を下げればその逆になります。どこに座るかを決めるのは機械ではなく、**見逃しのコストと空振りのコストを知る運営者**です。そして「感度をどこに置くかとは無関係に、この検査場そのものの分別力がどれだけ良いか」を測る別の指標が ROC-AUC です。

## 3. 核心概念

### 3.1 混同行列 (confusion matrix) — すべての指標の源

予測と実際の組み合わせは 4 マスしかありません。

| | 予測: 不正 | 予測: 正常 |
|---|---|---|
| **実際: 不正** | TP (よく捕まえた) | FN (見逃し — 不正被害の発生) |
| **実際: 正常** | FP (空振り警報 — 顧客の不便、調査コスト) | TN (静かに通過) |

この 4 マスから、すべての指標が生まれます。

- **正解率 (accuracy)** = (TP+TN) / 全体 — 不均衡データでは TN が圧倒して錯覚が発生
- **適合率 (precision)** = TP / (TP+FP) — 「警報のうち本物の割合」
- **再現率 (recall)** = TP / (TP+FN) — 「本物のうち捕まえた割合」
- **F1** = 適合率と再現率の調和平均 — 1 つの数字が必要なときの折衷案。調和平均なので、どちらか一方が 0 に近ければ F1 も崩れます (平均を取ったからと安心できないように設計されているのです)。

### 3.2 不均衡で正解率が壊れる理由

正解率は「多数派クラスさえ当てていれば」高くなります。不正 1.5% なら、全員正常と予測 = 正解率 98.5%。このとき再現率は 0%、適合率は定義不能 (警報 0 件) です。**不均衡データにおける正解率は、1 行目に書く指標ではなく脚注に書く指標です。**

### 3.3 ROC-AUC — しきい値と無関係な分別力

level05 で学んだとおり、モデルは確率を出し、しきい値が決定を作ります。しきい値を 0→1 へなぞると (空振り警報率, 再現率) の点が曲線を描きます。これが ROC 曲線で、その下の面積が AUC です。直感的な解釈がとても優れています: **「不正 1 件と正常 1 件を無作為に取り出したとき、モデルが不正側により高い確率を与える確率」**。0.5 ならコイン投げ、1.0 なら完璧。しきい値を決める前に「モデルそのものの格」を比較するときに使います。ただし AUC が高くても運用しきい値での適合率が低いことはあるので、最終報告には運用ポイントの混同行列を必ず添えるべきです。

### 3.4 指標はアクションから逆算する

- 調査の人員が 1 日 100 件しか処理できない → 「上位 100 件の適合率」が実質的な指標
- 見逃しコスト ≫ 空振りコスト (がん検診、不正) → 再現率を優先、適合率は下限だけ
- 空振りコスト ≫ 見逃しコスト (VIP の誤ブロック) → 適合率を優先

- **[1]** データの読み込み + 訓練/テストの分割 (不均衡を保つための `stratify` を使用)。
- **[2] 張りぼてモデル**: 無条件に「正常」を出力するモデルの正解率が約 98.5% であることを確認します。続けて混同行列を出力すると再現率 0% — 正解率の落とし穴が 4 マスの表にそのまま現れます。

- **[4] しきい値のシーソー**: しきい値 0.9→0.1 をなぞりながら、適合率と再現率が入れ替わる表を出力します。
- **[5] ROC-AUC**: 張りぼて (0.5) と本物のモデルの AUC を比較し、「無作為な不正・正常ペアで不正側の確率が高い確率」という解釈をシミュレーションで検証します。

コードの心臓部: `confusion_matrix`、`precision_score/recall_score/f1_score`、`roc_auc_score`。そして [5] の `auc_by_sampling()` — AUC の確率的定義を 1万回の無作為ペア抽出で直接確認する関数です。ライブラリの数字とほぼ一致するのを見れば、AUC はもう暗号のようには感じられなくなるはずです。

## 6. よくある間違い

- **不均衡データで正解率だけ報告すること**: このレベルが存在する理由です。ベースライン (「全部多数派クラス」モデル) の成績を必ず併記しましょう。
- **F1 だけ見て適合率/再現率を見ないこと**: F1 0.6 が「適合率 0.9 + 再現率 0.45」なのか「両方 0.6」なのかで、ビジネス上の意味はまったく違います。
- **AUC が高いから終わりだと考えること**: AUC は格を測る指標であって、運用の成績表ではありません。運用しきい値の混同行列まで見て初めて、決裁できる報告になります。
- **テストセットが不均衡を反映しない分割**: `stratify` なしで切ると、テストに不正が数件しか入らず指標が暴れます。
- **指標を先に決めずにモデリングを始めること**: level02 の定義書の項目 4 がまさにこれでした。指標は事後の選択ではなく、事前の契約です。
