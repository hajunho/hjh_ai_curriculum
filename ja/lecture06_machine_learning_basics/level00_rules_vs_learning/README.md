# Lecture 06 · Level 00 — 機械学習とは: ルール vs 学習

> 人がルールを一つひとつ書き出す方式と、データからルールを自分で見つけ出す方式を、同じ問題で直接対決させてみます。
**難易度** ⭐ / **前提** なし / **想定時間** 25分

## 1. なぜ学ぶのか — ビジネスの視点

「うちも AI を導入すべきじゃないですか?」という会議で最初に必要なのは、技術ではなく見極める力です。ある問題は Excel の数式や IF 文数行で十分ですし、ある問題は機械学習 (Machine Learning) でなければ解けません。この見極めができないと、IF 文で済む仕事に数千万円規模のプロジェクトを発注してしまったり、逆に機械学習が必要な仕事を数百個のルールで無理やり抑え込んで保守地獄に陥ったりします。

このレベルを終えると、「ルールベースで行くか、学習ベースで行くか?」という問いに自分で答えられる基準が手に入ります。そしてその基準は、この後の 11 レベル全体の出発点になります。

## 2. 比喩で理解する

**スパムフィルターを作る 2 つの方法**を想像してみてください。

方法 A — ルールのハードコーディング: 新入社員に業務マニュアルを渡すやり方です。「件名に『融資』があればスパム」「送信者がアドレス帳になくてリンクが 3 つ以上ならスパム」…… 最初はうまくいきます。ところがスパム業者が『融資』を『融◆資』に変えたら? ルールをまた追加しなければなりません。ルールが 500 個くらいになると互いに衝突し始め、誰も全体を理解できなくなります。

方法 B — 学習: 新入社員にマニュアルの代わりに、**先輩たちがスパム/正常に仕分けしておいたメール 10万通**を見せるやり方です。「実物を見て感覚をつかんでくれ」。人がルールを書かなくても、データが十分にあれば新人は『融◆資』まで自分で見抜けるようになります。新しい手口が出てきたら、新しいデータで再訓練すればよいのです。

機械学習とは、まさに方法 B のことです。従来のプログラミングが **「ルール + データ → 答え」** だとすれば、機械学習は **「データ + 答え → ルール」** です。矢印の向きが逆転したこと — これがこの講義全体で最も重要な一文です。

## 3. 核心概念

### 3.1 従来のプログラミング vs 機械学習

| | 従来のプログラミング | 機械学習 |
|---|---|---|
| 人が与えるもの | ルール(コード) + 入力 | 入力 + 正解の事例 |
| コンピュータが作るもの | 答え | ルール(モデル) |
| ルールが変わったら | コードを修正 | データで再訓練 |
| 向いている問題 | ルールが明確で少数 (税金計算、給与精算) | ルールが曖昧で無数にある (画像判別、解約予測) |

### 3.2 「学習」の正体 — 良い値を探す探索

学習 (learning) という言葉は神秘的に聞こえますが、実体は意外と素朴です。**「何かの数字 (パラメータ) をあれこれ変えながら、正解を最もよく当てる値を探す探索」**です。今日の実習では最も単純な形を使います。「取引金額が T ウォン以上なら不正と予測する」という枠を決めておき、候補の T をすべて試して、データに最も合う T を選ぶのです。人が「T = 50万ウォン」と勘で決める代わりに、データに T を決めさせる — これが学習の種です。この後学ぶ線形回帰やニューラルネットワークも、「数字が数百万個あって探索方法がもっと賢いだけ」で、本質は同じです。

### 3.3 ルールベースが勝つ場面も多い

機械学習が常に優れているわけではありません。

- **ルールが法律や制度で決まっているとき**: 消費税 10% の計算に機械学習を使ってはいけません。100% 正確なルールがすでにあるのですから。
- **データがほとんどないとき**: 正解事例 20 件では学習になりません。こういうときは専門家のルールの方が優れています。
- **間違えたとき理由を 100% 説明しなければならないとき**: ルールは追跡が容易ですが、学習されたモデルには別途の解釈作業 (level11) が必要です。

実務の王道は「ルールから始めて、ルールで手に負えなくなったところから学習へ移行する」です。

### 3.4 用語の整理

- **特徴量 (feature)**: 判断材料となる入力の列。例: 取引金額、取引時刻
- **ラベル (label)**: 当てるべき正解の列。例: 不正かどうか (0/1)
- **モデル (model)**: 学習によって得られた「ルールのかたまり」。今日はしきい値 1 個だけの超ミニモデルを作ります。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

このプログラムは、カードの不正取引データ (合成、5,000 件、不正比率 約 1.4%) を題材に、同じ分類問題を 3 つの方式で解きます。スパムフィルターと構造がまったく同じ問題です — 多数の正常の中から少数の悪いものを拾い出す、という構造です。

- **[1]** データを読み込んで構造を確認します。不正があまりに稀なため単純な正解率は錯覚を生みます。そこで成績は「不正の検知率と正常の検知率の平均 (バランススコア)」で採点します。
- **[2] 手書きルール**: 「50万ウォン以上 + 深夜なら不正」という、会議室で出てきそうな勘ベースのルールの成績を出します。捕まえたものは全部本物なのに、不正の 70% を見逃します。
- **[3] 学習 (しきい値探索)**: 特徴量を 1 つ選んですべてのしきい値を試し、データが選んだ最適なしきい値で予測します。どの特徴量・どの値が選ばれたか、出力を必ず確認してください。
- **[4] 学習 (特徴量 2 個の結合)**: 人のルールとまったく同じ形 (「金額 T 以上 かつ深夜」) を用意し、数字 T だけをデータに選ばせます。人の 50万ウォンとデータの答えがどれほど違うか見てください。
- **[5]** 3 つの方式を表で比較し、「矢印が逆転した」という核心をまとめます。

コードの心臓部は `learn_threshold()` 関数です。for 文で候補のしきい値をすべて回して点数を測る 10 行ほどの関数 — これがあなたの作る初めての学習アルゴリズムです。sklearn のようなライブラリはあえて使いませんでした。学習が魔法ではなく探索であることを、目で見るためです。

出力での注目ポイント: 人のルールは「確実なものだけ捕まえて大部分を見逃す」方向に偏っていたのに対し、学習は見逃しと空振り警報のバランスがより良い数字を見つけ出します。人はルールの「形」だけを決め、「数字」はデータが決める — この役割分担が機械学習の始まりです。

## 5. やってみよう

1. **(かんたん)** `[2]` の手書きルールで、金額の基準を 50万ウォンから 10万ウォンに変えて実行してみてください。成績はどう変わりますか? 人の勘で数字を選ぶことがなぜ不安定なのか、実感してみましょう。(ヒント: `hand_rule` 関数の数字を 1 つ直すだけ)
2. **(ふつう)** `[3]` の探索対象の特徴量リストに `tx_count_1h` (直近 1 時間の決済回数) を追加してみてください。驚きの結果が出るはずです。この合成データには、完璧に近い特徴量が隠れています — 現実のデータでこんな特徴量が見えた瞬間は、まず「リーク (leakage) ではないか?」と疑うべきです (level02 で学びます)。
3. **(チャレンジ)** 今の `learn_threshold()` は「以上 (≥) なら不正」の方向しか探索しません。「未満 (<) なら不正」の方向も一緒に探索するよう改造してみてください。`hour` (時刻) のように小さい値が危険な特徴量で効果があるはずです。(ヒント: 方向フラグを True/False で 2 回回す)

## 6. よくある間違い

- **「AI = 機械学習 = 万能」という思い込み**: ルールが明確な問題に学習を使うのは、電卓があるのにサイコロを振るようなものです。
- **学習を神秘化すること**: 「モデルが自分で考える」のではなく「数字を探索してデータに合わせる」のです。神秘化すると、結果を検証しようという発想が出てこなくなります。
- **訓練に使ったデータで成績をつけて満足すること**: 今日はわざとそうしました。これがなぜ危険なのかが level04 のテーマです。今日の成績表は「楽観的に水増しされた値」だという点だけ覚えておいてください。
- **正解データなしに学習から始めようとすること**: 方法 B は「先輩たちが仕分けしたメール 10万通」があって初めて成立します。データの準備がプロジェクトの半分以上です。
