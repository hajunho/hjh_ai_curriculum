# Lecture 03 · Level 10 — ピボット・リシェイプ・ウィンドウ演算

> Excel のピボットテーブルをコードで再現し、表の形を自由自在に変え、順位・累計・増減率でレポートを仕上げます。

**難易度** ⭐⭐⭐⭐ / **前提** level07 (level09 推奨) / **目安時間** 60分

## 1. なぜ学ぶのか — ビジネスの視点

レポートに入る表は、ほとんどが「何 × 何」という形の2次元の要約表です。店舗 × カテゴリの売上表、月 × 製品の販売表、チーム × 四半期の実績表のように。Excel を使ってきた方なら、ピボットテーブル (pivot table) で何度も作ったことがあるあの表です。

Pandas の `pivot_table` は Excel のピボットテーブルとまったく同じ仕事をしますが、3つ違います。1つ目、データが100万行あっても数秒で終わります。2つ目、コードとして残るので、来月ボタンのクリックを繰り返す必要はなく、再実行1回で済みます。3つ目、作ったピボットをもう一度分析できる形に戻す `melt` までセットで用意されています。ここに順位 (rank)、増減率 (pct_change)、累積和 (cumsum) といったウィンドウ演算を載せれば、「店舗別の順位」「累計の達成状況」のような経営報告の定番の数字がすべて出てきます。

## 2. たとえ話で理解する

**データの形を変えることは、クローゼットの整理と同じです。** 同じ服でも「引き出しに1着ずつたたんで入れる」と「ハンガーにずらりと掛ける」は用途が違います。

- **縦長フォーマット (long format)** はハンガーにずらりと掛けた状態です。1行が「1月1日、渋谷店、コーヒー、45万ウォン」のように出来事1つを記録します。機械 (コンピュータ) が扱いやすい形なので、フィルタ・グループ化・結合はすべてこの形で行います。
- **横長フォーマット (wide format)** はたんすにたたんで入れた状態です。行は店舗、列はカテゴリ、マスには合計が入った要約表ですね。人が一目で読みやすい形なので、レポートやプレゼン資料はこの形を使います。
- `pivot_table` はハンガー (long) → たんす (wide) へたたんで入れる作業、`melt` はたんす (wide) → ハンガー (long) へ取り出して掛け直す作業です。分析は long で、報告は wide で — この往復が実務のリズムです。

順位の演算は、かけっこの表彰式と同じです。記録 (売上) はすでにあり、`rank` はその記録から順位を付けてくれる審判です。全体の表彰式 (全社順位) もあり、組別の表彰式 (カテゴリ別のグループ内順位) もあります。

## 3. 核心となる考え方

### 3.1 pivot_table の4つの材料

```python
pd.pivot_table(df, index="store", columns="category",
               values="revenue", aggfunc="sum", margins=True)
```

| 引数 | Excel のピボットテーブルでの呼び名 | 意味 |
|---|---|---|
| `index` | 行エリア | 縦軸に来る項目 |
| `columns` | 列エリア | 横軸に来る項目 |
| `values` | 値エリア | マスに入れる数値 |
| `aggfunc` | 値の集計方法 | sum, mean, count など |

`margins=True` を与えると Excel の「総計」の行・列が付きます。同じ (index, columns) の組み合わせに複数の行があると `aggfunc` でまとめてくれるので、重複があってもエラーになりません (重複があるとエラーを出す `pivot` との違いです)。

### 3.2 melt — ピボットを溶かして戻す

`melt` は wide の表を long に戻します。`id_vars` (そのまま残す識別用の列) を指定すると、残りの列が「変数名 (variable) / 値 (value)」の2列に溶けていきます。なぜ戻すのでしょう? wide の表は人の目には良いのですが、フィルタ・グループ化・グラフのライブラリはほとんどが long を要求するからです。「レポート用の表を受け取ったのに、もう一度分析しなければならない」という状況で melt が救援投手になります。

### 3.3 rank — 順位を付ける

`s.rank(ascending=False)` は大きい値が1位になるように順位を付けます。同点の扱い方は `method` で決めます (既定は平均順位、`method="min"` は同順位1位の方式)。実務で本当によく使うのは **グループ内の順位** です。

```python
df.groupby("category")["revenue"].rank(ascending=False)
```

こうすると「コーヒー部門で渋谷店は何位か」のような組別の順位が出ます。groupby (level07) とウィンドウ演算が組み合わさる代表的なパターンです。

### 3.4 pct_change と cumsum — 流れを読む演算

- `monthly.pct_change()`: すぐ前の行に対する増減率。level09 で学んだあの演算を月別の表に適用すれば「前月比の成長率」になります。
- `monthly.cumsum()`: 累積和。1月から今月までに積み上がった累計売上で、「年間目標に対して今どこまで来たか」を計算するときの分子です。

こうした演算をまとめてウィンドウ演算 (window operation) と呼びます。集計 (groupby) が複数の行を1行に「縮める」のに対し、ウィンドウ演算は行数を保ったまま、各行に「周りの行を参考にした値」を付けてくれます。この違いが重要です。

### 3.5 wide と long、いつ何を使うか

| 状況 | フォーマット |
|---|---|
| フィルタ・グループ化・結合などの分析作業 | long |
| グラフライブラリへの入力 | ほとんど long |
| 人が読むレポート・ダッシュボードの表 | wide |
| CSV で他部署に渡す | long 推奨 (再分析できる) |

## 4. 実習 — main.py

実行方法:

```bash
cd lecture03_data_handling/level10_pivot_reshape_window
python3 main.py
```

出力の流れは次のとおりです。

- **[1] 店舗 × カテゴリの総売上ピボット** — `pivot_table` に `margins=True` を与えて総計まで付けた年間レポートを作ります。億ウォン単位に丸めて出力するので、どの店舗のどのカテゴリが稼ぎ頭なのかが一目で分かります (全体の合計は 46.86 億ウォンです)。
- **[2] 曜日 × 店舗の平均売上ピボット** — `aggfunc="mean"` に変えると、同じ関数がまったく違う質問 (「曜日効果は店舗ごとに違うのか?」) に答えます。曜日の順序が文字コード順に崩れるのを `reindex` で月〜日の順序に直すのもポイントです。
- **[3] melt で戻す** — [1] のピボットを long フォーマットに溶かし、wide の25マスが long の25行になることを確認して、2つのフォーマットの使いどころを比べます。
- **[4] 順位の分析** — 店舗別総売上の全社順位 (`rank`) と、カテゴリ別のグループ内での店舗順位 (`groupby` + `rank`) を求めます。全社1位の店舗が、すべてのカテゴリでも1位かどうか確かめてみてください。
- **[5] 月別の流れ** — 月別売上に `pct_change` (前月比の成長率) と `cumsum` (累計売上) を付けた月次の経営要約表を作ります。
- **[6] レポートの保存** — 完成したピボットレポートを `outputs/pivot_report.csv` に保存します。Excel で開いてみれば、あなたが手で作っていたあの表がコード1回で出てきたことを確認できます。

## 5. やってみよう

1. **(基本)** [1] のピボットで `aggfunc="sum"` を `"count"` に変えてみましょう。マスの意味が「売上の合計」から何に変わりますか? ヒント: 何件の行が入ったか、つまり販売記録の数になります。
2. **(応用)** `index=["store", "weekday"]` のように index にリストを入れて2段のピボットを作ってみましょう。ヒント: 結果は MultiIndex (多段インデックス) の表になり、Excel ピボットの「行エリアにフィールド2つ」と同じです。
3. **(挑戦)** カテゴリ別に「店舗間の売上格差」(グループ内の最大 - 最小) を求めて、格差が最も大きいカテゴリを探してみましょう。ヒント: [4] で作ったカテゴリ・店舗別の合計表に `groupby("category")["revenue"].agg(lambda s: s.max() - s.min())` を適用します。

## 6. よくある間違い

- **pivot と pivot_table の混同** — `pivot` は (行, 列) の組み合わせが重複するとエラーを出します。原本が日別データのように重複する組み合わせを持つなら、必ず `pivot_table` (集計が内蔵) を使いましょう。
- **margins の行をデータとして扱う** — `margins=True` が付けた「合計」の行・列は合計であってデータではありません。ピボットを melt したり順位を付けたりする前は、margins なしの版を使いましょう。
- **曜日・月を文字コード順のまま放置** — ピボットの行の順序は既定では辞書順なので、「土 日 月 木 水 火 金」のようになります。`reindex(["月","火",...])` で業務の順序を復元しましょう。
- **rank の向きの勘違い** — 既定値の `ascending=True` は小さい値が1位です。売上の順位はほぼ常に `ascending=False` が必要です。
- **NaN のマスを0と誤解する** — ピボットでの NaN は「その組み合わせのデータがない」ことであって「売上0」ではありません。意味を確かめたうえでだけ `fillna(0)` しましょう。
