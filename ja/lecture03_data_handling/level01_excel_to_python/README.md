# Lecture 03 · Level 01 — Excel から Python へ

> Excel で毎日やっていた合計・フィルタ・並べ替えをコードに移し、Excel の3つの限界 — 再現性・規模・自動化 — をコードがどう越えるのかを体験します。

**難易度** ⭐ / **前提** level00 / **目安時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

Excel は偉大な道具です。学びやすく、目で見ながら直せて、会社の共通語です。ところが実務でデータが大きくなり、作業が繰り返され始めると、3つの壁にぶつかります。

1. **再現性 (reproducibility)**: 先月のレポートの数字がどうやって出たのか尋ねると、「フィルタをかけて、どこかにコピーして、数式を入れて...」という記憶頼みの答えが返ってきます。クリックの順序はどこにも記録されません。担当者が変わると数字を再現できないことも珍しくありません。
2. **規模 (scale)**: Excel のシートは約104万行が物理的な限界で、実際には数十万行あたりから目に見えて遅くなります。「ファイルが開きません」は、データ実務者のよくある悲鳴です。
3. **自動化 (automation)**: 毎週月曜日に同じファイルを開いて同じピボットを作る仕事は、人間がやれば30分 + ミスの可能性、コードがやれば3秒 + 毎回同一です。

Python に移すというのは、Excel を捨てるという意味ではありません。**「クリックの手順」を「読める文書 (コード)」に変えること** です。コードはそれ自体が作業説明書なので、レビューを受けられ、再実行でき、予約実行もできます。

## 2. たとえ話で理解する

Excel の手作業は **目分量で作る味噌汁** のようなものです。その日はおいしくても、「醤油を少し、えーと…次に何を入れたっけ」なので、同じ味をもう一度出すのは困難です。コードは **分量が書かれたレシピ** です。レシピがあれば:

- 誰が作っても同じ味になります。 → **再現性**
- 1人前のレシピをそのまま100人前の鍋に適用できます。 → **規模**
- レシピを調理機械にセットしておけば、毎朝自動で出来上がります。 → **自動化**

そしてレシピに「塩 小さじ2」と書かれていれば、しょっぱいというクレームが来たときに、どこを直せばよいか正確に分かります。コードレビューが可能だということです。Excel ファイルの元に戻す (Ctrl+Z) の履歴はファイルを閉じた瞬間に消えますが、コードは残ります。

## 3. 核心となる考え方

### 3-1. CSV — Excel と Python が出会う橋

CSV (Comma-Separated Values) は、カンマで値を区切った純粋なテキストの表です。Excel でも開け、メモ帳でも開け、Python でも読めます。書式・数式・グラフはなく、**値だけ** があります。だからシステム間のデータ交換の標準のように使われています。今回の実習では売上表を CSV に保存してから読み直します。実務で「データをダウンロード」ボタンがくれるファイルの大半が、この形式です。

### 3-2. Excel の作業 ↔ Python コードの対応表

| Excel でやっていたこと | Python での対応 |
|---|---|
| `=SUM(G2:G1000)` | `sum(値のリスト)` |
| オートフィルタで「渋谷店」だけ表示 | `[r for r in rows if r["store"] == "渋谷店"]` |
| データ → 並べ替え (降順) | `sorted(rows, key=..., reverse=True)` |
| SUMIF (店舗別の合計) | 辞書に店舗ごとに累積 |
| マクロの記録 | スクリプトファイルそのもの |

この対応が頭に定着すると、「Excel ではできるのにコードではどうやるんだろう?」という質問が、「Excel のこの操作をコードに翻訳すると何になる?」に変わります。はるかに答えやすい質問です。

### 3-3. CSV の落とし穴 — すべて文字列として読まれる

`csv.DictReader` で CSV を読むと、すべての値が文字列 (str) として入ってきます。`"512000"` は数字に見えても文字列なので、そのまま `sum()` に入れることはできません。だから読んだ直後に `int()`/`float()` で変換するステップが必ず必要です。空欄 (`""`) は変換中にエラーになるので、先にふるい落とす必要があります。この「型の復元」作業を、level04 では Pandas がどれほど楽にしてくれるか比較することになります。

### 3-4. 検証可能な手順という観点

Excel の手作業の成果物は「数字」しか残りません。コードの成果物は「数字 + その数字を作った手順」が一緒に残ります。監査 (audit) や引き継ぎの場面で、この差は決定的です。今回の main.py も、欠損・マイナスの行を何件スキップしたか自ら報告するように作ってあります。良いデータコードは、自分が何を捨てたのかを常に語ってくれます。

## 4. 実習 — main.py

実行方法:

```bash
cd lecture03_data_handling/level01_excel_to_python
python3 main.py
```

スクリプトの流れは、「Excel 業務の一日」をそのままコードに翻訳したものです。

- **[1] CSV 保存**: 60日分の売上表 (1,500行) を `outputs/sales.csv` に保存します。Excel でこのファイルを直接開いてみるのも良いでしょう。
- **[2] CSV 読み込み**: `csv.DictReader` で読み直します。このとき、すべての値が文字列であることを出力で確認します。
- **[3] 型の復元 + 汚染のスキップ**: `revenue` を整数に変えつつ、空の値とマイナスはスキップして、何件スキップしたか報告します。
- **[4] SUM**: 全体の売上合計。Excel の `=SUM()` 一発と同じです。
- **[5] SUMIF**: 店舗別の合計を辞書への累積で作ります。
- **[6] オートフィルタ**: 「渋谷店 & 週末」の行だけを選び、平日と売上平均を比較します。
- **[7] 並べ替え上位5**: 売上上位5行を降順で出力します。
- **[8] 再現性の宣言**: このスクリプトを100回実行しても同じ数字が出る理由 (固定 seed + 記録された手順) を出力します。

出力では、店舗別の合計が 渋谷 < 新宿 < 大阪 < 名古屋 < 福岡 の順に大きくなること、週末の平均が平日より高いことを確認してみてください。データ生成器に仕込んだパターンが、コードで正確に浮かび上がります。

## 5. やってみよう

1. **(易しい)** [5] を参考に「カテゴリ別」の売上合計を求めてみましょう。ヒント: 累積辞書のキーを `r["category"]` に変えるだけです。
2. **(普通)** 上位5ではなく「下位5」(マイナスは除く) を抜き出してみましょう。ヒント: `reverse=True` を外すか、並べ替え結果の先頭部分を取ります。
3. **(挑戦)** 結果の要約 (店舗別の合計) を新しい CSV ファイル `outputs/summary.csv` に保存してみましょう。ヒント: `hjh_data.to_csv` は辞書のリストを受け取るので、`[{"store": s, "total": t} for ...]` の形にして渡します。

## 6. よくある間違い

- **CSV から読んだ値をそのまま計算に使う**: `"500" + "300"` は `"500300"` です。読んだ直後に必ず数値へ変換しましょう。
- **空文字列を `int()` に入れる**: 欠損は CSV に `""` として保存されますが、`int("")` は `ValueError` を出します。変換前に空の値のチェックを先に行います。
- **日本語の CSV が他のプログラムで文字化けして見える**: エンコーディング (encoding) の問題です。このカリキュラムは UTF-8 に統一しており、詳しい対処は level04 で扱います。
- **元のファイルをコードで上書きする**: 元データは読むだけにして、結果は必ず別のファイル (`outputs/`) に保存する習慣をつけましょう。Excel で元ファイルに「名前を付けて保存」を忘れるミスと同じ系統です。
