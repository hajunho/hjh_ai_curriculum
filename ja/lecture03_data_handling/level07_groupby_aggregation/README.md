# Lecture 03 · Level 07 — グループ化と集計 (groupby)

> 「店舗別の売上は? 曜日別の平均は?」— 実務の質問に対する標準解答である groupby を学びます。

**難易度** ⭐⭐⭐ / **前提** level06_missing_outliers / **目安時間** 40分

## 1. なぜ学ぶのか — ビジネスの視点

上司がデータを見て投げてくる質問は、ほぼ必ず同じ形をしています。「**~別** に見るとどう?」店舗別の売上、曜日別の平均、カテゴリ別の比率、担当者別の実績。この「~別」という日本語が、Pandas ではちょうど `groupby` 一つに対応します。

Excel ではこの仕事をピボットテーブルや SUMIF でやります。ところが条件が2つ3つに増え (「店舗別で、そのうち週末だけ、カテゴリ別に」)、毎週更新しなければならず、集計の基準がしょっちゅう変わると、手作業はすぐに限界にぶつかります。groupby はこれらの質問すべてを1行のコードに変え、来週も同じコードを再実行するだけで済みます。

このレベルを終えれば、生データから「経営陣に見せる要約表」までを一人で作れるようになります。

## 2. たとえ話で理解する

名刺500枚がごちゃ混ぜになった箱を整理すると考えてみてください。会社別に知りたいなら、こうします。

1. **分ける (Split)** — 会社名ごとに名刺を山に分けます。
2. **適用する (Apply)** — 山ごとに同じ作業をします。枚数を数えたり、役職の平均を出したり。
3. **結合する (Combine)** — 山ごとの結果を1枚の要約表にまとめます。

この3ステップが groupby の正式名称である **分割-適用-結合 (split-apply-combine)** パターンです。`df.groupby("store")["revenue"].sum()` というコードは、「店舗別に山を分けて → 各山の売上を合計して → 1つの表にまとめろ」をそのまま書き写したものです。

もう一つたとえを。`agg` は山ごとに複数の作業を **同時に** させること (「枚数も数えて平均も出せ」)、`transform` は山ごとの結果を **名刺1枚1枚に貼り戻してくれること** です。この違いは 3.4 でもう一度見ます。

## 3. 核心となる考え方

### 3.1 基本形 — グループキー、対象の列、集計関数

```python
df.groupby("store")["revenue"].sum()
#          ─┬────   ─┬───────  ─┬─
#      グループキー   対象の列   集計関数
```

結果は、グループキーがインデックス (index) になった Series です。`sum` の場所に `mean` (平均)、`count` (件数)、`median` (中央値)、`max`/`min` などを入れられます。

### 3.2 agg — 複数の集計を一度に

レポートには普通、合計・平均・件数が一緒に必要です。`agg` に名前付き集計 (named aggregation) を使えば、結果の列名まで一度に決められます。

```python
df.groupby("store").agg(
    total=("revenue", "sum"),
    avg=("revenue", "mean"),
    n=("revenue", "count"),
)
```

### 3.3 複数キー — 「店舗別、その中でカテゴリ別」

グループキーをリストで与えると階層集計になります: `df.groupby(["store", "category"])["revenue"].sum()`。結果は2段のインデックス (MultiIndex) を持ち、`reset_index()` で普通の表に戻せます。「店舗×カテゴリの組み合わせのうち、どこが稼いでいるのか」という質問の答えです。

### 3.4 agg vs transform — 要約か、元のサイズの維持か

| | 返るサイズ | 使いどころ |
|---|---|---|
| `agg` | グループの数だけ (要約表) | レポート、ランキング表 |
| `transform` | 元の行数そのまま | 派生列を作る (グループ内の比率、グループ別の穴埋め) |

たとえば「各行の売上が自分の店舗の総売上の何%か」という派生列は、`transform` でなければ作るのが面倒です。

```python
store_total = df.groupby("store")["revenue"].transform("sum")
df["share_in_store"] = df["revenue"] / store_total
```

level06 のグループ別中央値での穴埋めも、同じ原理でした。

### 3.5 並べ替えと順序 — レポートの仕上げ

- 集計結果は既定ではグループキーの文字コード順です。レポートなら `sort_values(ascending=False)` で大きい値から並べるのが普通です。
- 曜日のように **意味のある順序** を持つキーでは、文字コード順がかえって邪魔になります。`reindex(["月", "火", ...])` で望む順序を強制しましょう。

### 3.6 集計の前のクレンジングを忘れないこと

groupby の集計関数は NaN を黙って飛ばします。便利ですが、マイナスの汚染が残っていると合計はそのまま歪みます。**level06 のクレンジング → このレベルの集計** という順序が、実務パイプラインの標準です。

## 4. 実習 — main.py

実行方法:

```bash
cd lecture03_data_handling/level07_groupby_aggregation
python3 main.py
```

main.py は1年分の売上をクレンジングした後、「カフェチェーン売上分析レポート」を段階的に作ります。

- **[1] 店舗別の要約 (agg)** — 総売上・平均・件数を1つの表に。大阪・名古屋・福岡のように後ろの番号の店舗ほど売上が大きい構造が見えます (データに仕込まれた店舗規模の効果)。
- **[2] 曜日別の平均と週末効果** — `reindex` で月〜日の順序を整え、週末の平均 ÷ 平日の平均で「週末倍率」を計算します。約 1.21 倍になります。データジェネレーターには 1.25 倍の効果が仕込まれていますが、広告費の寄与分が曜日と無関係に足されるため倍率が少し薄まります — 集計結果を解釈するときは、こうした構造まで考える必要があります。
- **[3] カテゴリ別の比率** — 合計を全体で割って比率(%)を作り、降順に並べます。コーヒーが1位かどうか確かめてみてください。
- **[4] 店舗×カテゴリの複数キー** — 25通りの組み合わせのうち売上上位5つを取り出します。
- **[5] transform による派生列** — 各行の「店舗内の売上比率」を作り、店舗別の比率の合計が1になるかを検証します。
- **[6] レポートの保存** — 店舗別の要約表を `outputs/store_report.csv` に保存します。この CSV がそのまま「メールに添付するレポート」です。

コードの中で最も注目してほしいのは [2] の曜日の並べ替えです。文字コード順の罠を `reindex` 1行で解決します。

```python
weekday_order = ["月", "火", "水", "木", "金", "土", "日"]
by_weekday = df.groupby("weekday")["revenue"].mean().reindex(weekday_order)
```

## 5. やってみよう

1. **最小・最大を追加** — [1] の agg に `best=("revenue", "max")`、`worst=("revenue", "min")` を追加して、店舗別の最高・最低売上も一緒に出してみましょう。(ヒント: named aggregation はいくつでも並べられます。)
2. **曜日×カテゴリのクロス質問** — 「ドリンクの売上が最も高い曜日は?」をコードで答えてみましょう。(ヒント: 先に `df[df["category"] == "ドリンク"]` で絞ってから曜日別 groupby、最後に `idxmax()`。)
3. **広告費の効率** — 店舗別に `revenue の合計 ÷ ad_cost の合計` を計算して、「広告費1ウォンあたりの売上」が最も高い店舗を探してみましょう。(ヒント: agg で2つの列の合計をそれぞれ求めてから割ればよいのです。)

## 6. よくある間違い

- **groupby だけ書いて集計関数を付けない** — `df.groupby("store")` はまだ計算前の「グループの設計図」にすぎません。`.sum()` のような集計を付けて初めて結果が出ます。
- **集計結果が Series だということを忘れる** — 列名が消えて戸惑いがちです。表として扱いたいなら `reset_index()` を付けましょう。
- **曜日を文字コード順のままにする** — 「土, 日, 月, 木, 水, 火, 金」の順に並んだ表は、レポートとしては事故です。`reindex` で順序を指定しましょう。
- **transform のところに agg を使う** — 派生列を作ろうとしてサイズが合わないというエラーが出たら、十中八九この混同です。
- **クレンジングなしの集計** — マイナスの売上が残っていると、店舗別の合計はそのまま汚染されます。集計の前に必ず level06 の手順を通しましょう。
