実務データ分析の標準の道具は Pandas (パンダス) です。売上の CSV を開き、フィルタをかけ、店舗別に集計し、レポート用の表を作る仕事の始めから終わりまで、すべてに DataFrame があります。この先この講義のすべてのレベル (読み込み、クレンジング、集計、結合、時系列、ピボット) は、全部 DataFrame の上で繰り広げられます。つまりこのレベルは、「これから使う作業台を組み立てる時間」です。

DataFrame を知らないまま次のレベルのコードを見ると、`df.loc`、`df.dtypes`、`df["revenue"]` のような表現が暗号のように感じられます。逆に構造を一度きちんと理解すれば、初めて見る Pandas の機能も「ああ、結局は行と列に名札の付いた表を扱っているんだな」と推測できるようになります。求人票の「Pandas を使える方優遇」という文言が意味する最低条件が、まさにこのレベルの内容です。

## 2. たとえ話で理解する

Excel のブックを思い浮かべてください。

- **Series (シリーズ)** は Excel の **1列** です。たとえば「売上」の列を1本切り取ったものですが、重要な違いが1つあります。値ごとに **行の名札 (index)** が一緒に付いて回るという点です。Excel で D 列をコピーすると「3行目の値」という位置情報は消えますが、Series は名札を最後まで持ち歩きます。
- **DataFrame (データフレーム)** は、複数の Series を横に並べて貼り合わせた **シート1枚** です。すべての列が同じ行の名札 (index) を共有し、各列には列の名前 (columns) が付いています。

もう一つのたとえは **書類ファイル** です。DataFrame は見出しラベル (列名) の付いた書類ファイルの束で、各書類 (行) には受付番号 (index) が押されています。「売上の書類ファイルから受付番号100番を見せて」と言えるのは、名札の体系のおかげです。Excel は目で見てマウスで指しますが、Pandas は名札で語ります。この違いが自動化を可能にします。

## 3. 核心となる考え方

### 3.1 Series — 名札付きの1次元の値のまとまり

```python
s = pd.Series([310, 250, 480], index=["渋谷店", "新宿店", "名古屋店"])
s["名古屋店"]   # 480
```

Series は NumPy 配列に index という名札を着せたものです。だから NumPy と同じように `s.mean()`、`s * 1.1` のようなベクトル化演算がそのままできて、同時に `s["名古屋店"]` のように名前で値を呼べます。

### 3.2 DataFrame — Series の束

DataFrame の3要素は次のとおりです。

| 要素 | Excel での対応 | 確認方法 |
|---|---|---|
| 値 (values) | セルに書かれた内容 | `df.values` |
| 行の名札 (index) | 行番号 1, 2, 3... | `df.index` |
| 列の名前 (columns) | 見出し行 | `df.columns` |

`df["revenue"]` のように列名で取り出すと、その列が Series として出てきます。つまり「DataFrame から列を1本取り出すと Series、Series を複数集めると DataFrame」という往復の関係を覚えてください。

### 3.3 dtype — 列ごとに1つのデータ型

各列はデータ型 (dtype) を1つずつ持ちます。数値の列は `int64` や `float64`、文字の列は最新の Pandas では `str`、旧バージョンでは `object` と表示されます。ここで実務的に重要な事実を1つ: **数値の列に欠損値 (NaN) が混ざると、整数でも float64 になります。** 売上額が `758123.0` のように小数点付きで出てきたら、「どこかに空の値があるな」と疑う習慣をつけてください。

### 3.4 初対面の挨拶4点セット — head / info / describe / shape

初めて見るデータを受け取ったら、いつもこの順序で挨拶を交わします。

1. `df.shape` — 何行何列か (規模の把握)
2. `df.head()` — 先頭5行のプレビュー (姿かたちの把握)
3. `df.info()` — 列ごとの dtype と欠損でない値の数 (健康診断)
4. `df.describe()` — 数値列の平均・標準偏差・最小・最大 (分布の一瞥)

特に `describe()` の min にマイナスが見えたり max が異常に大きかったりしたら、外れ値 (outlier) のシグナルです。

### 3.5 新しい列を作る

```python
df["roas"] = df["revenue"] / df["ad_cost"]
```

Excel で E 列に `=C2/D2` を入力して下までドラッグしていた作業が、1行で終わります。ベクトル化演算なので、行が10万個あっても一瞬です。

### 3.6 カテゴリを数える — value_counts

文字列の構成比を見るときは `df["store"].value_counts()` を使います。Excel で COUNTIF を店舗の数だけ繰り返していた仕事が、1行です。

## 6. よくある間違い

- **`df["revenue"]` と `df[["revenue"]]` の混同** — 角かっこ1重は Series、2重は列が1本の DataFrame です。後ろに付けられる機能が互いに違います。
- **describe() だけを見て安心する** — describe は数値列しか要約しません。文字列のタイプミス (「渋谷店 」のような空白入り) は value_counts で別途確認する必要があります。
- **dtype を確認せずに計算する** — 数字に見えても dtype が object (文字) なら、合計が文字列の連結になったりエラーが出たりします。計算前の `df.dtypes` の確認は必須です。
- **info() の結果を変数に入れようとする** — `info()` は画面に出力するだけで None を返します。値が必要なら `df.dtypes`、`df.isna().sum()` を使いましょう。
