## 1. なぜ学ぶのか — ビジネスの視点

上司の質問は、たいていこんな形をしています。「先月の渋谷店の週末売上、出しておいて。」「広告費に対して効率のいいカテゴリはどこ?」これらの質問に共通する構造は、**選び出し (フィルタ)、並べ替え (ソート)、必要なものだけ取り出す (選択)** ことです。データ分析業務の時間の80%は、実はこの3動作の組み合わせです。

Excel でもフィルタボタンと並べ替えボタンで同じことはできます。しかし条件が3つ重なるだけでクリックが数十回になり、来月同じ質問をされたら最初からクリックし直しです。コードは条件を文章として書くものなので、どんなに複雑な条件でも1行で済み、来月は再実行一発で終わります。このレベルを終えれば、「言葉の業務の質問」を「条件式」に翻訳する筋肉が付きます。

## 2. たとえ話で理解する

フィルタリングは **出入口の警備員** です。DataFrame のすべての行が一列に並んでゲートを通過するのですが、警備員は行ごとに条件を検査して、通過/阻止の札 (True/False) を貼ります。この札のリストがブールマスク (boolean mask) です。`df[mask]` は「True の札をもらった行だけ入場」という意味です。

条件が複数なら、警備員を複数立てます。「社員証があり (&) かつ予約者名簿に載っている人だけ」「役員である (|) または VIP の人」。各警備員の判定をかっこで包んで結合するのが Pandas の文法です。

loc と iloc は **マンションで部屋を探す2つの方法** です。loc は「101号棟502号室」のように **名札 (ラベル)** で探し、iloc は「正門から3番目の棟、上から5番目の部屋」のように **順序 (位置)** で探します。同じ部屋でも呼び方が違い、建て替えで棟の名前が変わると (index が変わると)、loc の答えと iloc の答えが違ってくることがあります。

## 3. 核心となる考え方

### 3.1 ブールマスク — フィルタの原理

```python
mask = df["store"] == "渋谷店"   # True/False で満たされた Series
shibuya = df[mask]               # True の行だけ残す
```

比較演算 (`==`、`>`、`<=` など) を列に適用すると行数分の True/False が出てきて、それを角かっこに入れるとフィルタになります。2行をまとめて `df[df["store"] == "渋谷店"]` のように書くのが慣例です。

### 3.2 条件の結合 — &、|、~ そしてかっこ

```python
df[(df["store"] == "渋谷店") & (df["weekday"].isin(["土", "日"]))]
```

- `&` (かつ)、`|` (または)、`~` (否定) を使います。Python 文法の `and/or/not` は **使えません。**
- 各条件を必ずかっこで包みます。演算子の優先順位のせいで、かっこを外すとエラーになります。
- 複数の値のどれかに該当するかは `isin(["土", "日"])` がすっきりします。`==` を `|` でつなぐより短く、ミスも減ります。

### 3.3 loc vs iloc

| | loc | iloc |
|---|---|---|
| 基準 | 名札 (ラベル) | 整数の位置 |
| 例 | `df.loc[3, "revenue"]` | `df.iloc[3, 6]` |
| スライス | 終わりを **含む** | 終わりを **含まない** (Python の慣例) |

フィルタを通した DataFrame の index は 0,1,2... ではなく、元の表の行番号をそのまま持っています。だから `filtered.loc[0]` はエラーになることがありますが、`filtered.iloc[0]` は常に「先頭の行」を返します。この違いを知らないと、KeyError に出会ったときに長いこと迷子になります。

`df.loc[mask, ["store", "revenue"]]` のように **行の条件と列の選択を同時に** 行う形が、実務で最もよく使う文型です。

### 3.4 ソートと上位 N

```python
df.sort_values("revenue", ascending=False).head(10)   # 売上の降順で上位10
df.nlargest(10, "revenue")                            # 同じ結果を、より速く短く
df.sort_values(["store", "revenue"], ascending=[True, False])  # 複数基準
```

「上位 N」が目的なら、`nlargest`/`nsmallest` のほうが意図をはっきり表せます。

### 3.5 query — 条件を文章のように

```python
df.query("store == '渋谷店' and revenue >= 500000")
```

かっこや `&` なしで、文字列として条件を書く方法もあります。読みやすいのですが、列名に空白があると困るなどの制約があるので、基本はブールマスクで固め、query は選択肢として知っておいてください。

### 3.6 SettingWithCopyWarning — コピーへの落書き

フィルタリングした結果に値を代入すると `SettingWithCopyWarning` が出ることがあります。フィルタ結果が原本のコピーなのかビューなのかが曖昧なために出る警告です。解決の習慣は2つ: 修正が目的なら `df.loc[mask, "col"] = 値` の一文で書き、部分集合を使い続けるなら `sub = df[mask].copy()` で明示的なコピーを作りましょう。

## 6. よくある間違い

- **`and`/`or` を使う** — `(a) & (b)` が正解です。`and` を使うと "truth value is ambiguous" という有名なエラーが出ます。
- **かっこの省略** — `df[df["a"] > 1 & df["b"] < 2]` は `&` が比較より先に計算され、見当違いの結果かエラーになります。条件ごとのかっこが鉄則です。
- **フィルタ後に loc[0] を呼ぶ** — フィルタリングされた表の index は0から始まるとは限りません。先頭の行は `iloc[0]`、特定のラベルは `loc[ラベル]` と使い分けましょう。
- **代入時の二重角かっこチェーン** — `df[mask]["col"] = 値` は警告が出て、原本が変わらないことがあります。`df.loc[mask, "col"] = 値` と一度に書きましょう。
- **文字列比較の空白** — 「渋谷店 」(後ろに空白) は「渋谷店」とは別の値です。フィルタ結果が0行なら `unique()` で実際の値を確認しましょう。
