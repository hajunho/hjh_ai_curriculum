## 1. なぜ学ぶのか — ビジネスの視点

level01 で作った繰り返しのコードは、1,500行なら一瞬ですが、データが数百万行になると目に見えて遅くなります。取引ログ、センサー記録、広告クリックのデータは数百万行が当たり前です。「回しておいてコーヒーを飲みに行くコード」と「即座に答えが出るコード」の差は、実務では分析の回数を決めます。速く回れば、より多くの質問を投げかけられるのです。

NumPy (ナンパイ) は、Python で大量の数値を高速に扱う標準ライブラリです。そして次のレベルから学ぶ Pandas も、後で学ぶ scikit-learn や PyTorch も、すべて NumPy 配列の上で動いています。つまり NumPy の考え方 — **「数値1個ではなく、数値のまとまり (配列) を演算の単位にする」** — は、データ分野全体の共通文法です。ここでこの感覚を身につけておけば、以後のすべての道具が同じ原理で見えてきます。

## 2. たとえ話で理解する

コンビニで飲み物1,000本を精算するとしましょう。

- **Python の繰り返し** = 缶を1本ずつバーコードスキャナーにかざすアルバイト。1本あたりの動作は速くても、「持ち上げて → スキャンして → 置く」という準備動作が1,000回繰り返されます。
- **NumPy のベクトル演算** = 箱ごと秤に載せて一度に精算する物流倉庫。「準備動作」はたった1回で、実際の計算は機械 (最適化された C のコード) が処理します。

Python の繰り返しが遅い本当の理由は計算そのものではなく、**毎回繰り返される準備動作** (値の型確認、オブジェクトの包装ほどきなど) です。NumPy は「この箱の中は全部同じ型の数値」と約束してあるので準備動作を省略し、連続したメモリの上を機械の速度で駆け抜けます。

ブロードキャスト (broadcasting) は **判子押し** です。「すべての売上に付加価値税10%を上乗せせよ」という指示を1,000回繰り返す代わりに、`revenue * 1.1` という判子1つを配列全体に一度に押します。

## 3. 核心となる考え方

### 3-1. ndarray — 同じ型の数値の連続したまとまり

NumPy の核心のデータ構造は多次元配列 (ndarray) です。Python のリストとの決定的な違いは2つ:

1. **すべての要素が同じ型** です。この約束のおかげで、型確認なしの高速計算が可能になります。
2. **メモリ上に連続して配置** されます。CPU が先読みできるため、さらに速くなります。

```python
import numpy as np
a = np.array([1, 2, 3])
a * 10        # array([10, 20, 30]) — 繰り返しなしで全体に適用
```

### 3-2. shape と dtype — 配列の身分証

- **shape**: 配列の形。`(1500,)` は1次元1,500個、`(30, 5)` は30行5列です。エラーの大部分は shape の不一致から生まれるので、配列を受け取ったら `shape` から確認する習慣が重要です。
- **dtype**: 要素の型。`int64` (整数)、`float64` (浮動小数点数) など。欠損値 `NaN` (Not a Number) は float にしか存在できないため、欠損の混ざった整数の列が float に変わる現象をよく目にすることになります。

### 3-3. ベクトル化 — 繰り返しを演算子で置き換える

「各要素に同じことをせよ」という作業はすべて、繰り返しの代わりに配列演算で書きます。

| 繰り返しの発想 | ベクトル化の発想 |
|---|---|
| `for r in revenues: total += r` | `revenues.sum()` |
| `for r in ...: new.append(r * 1.1)` | `revenues * 1.1` |
| `for r in ...: if r > 100万: ...` | `revenues[revenues > 1_000_000]` |

最後の行がブールマスク (boolean mask) です。`revenues > 1_000_000` は True/False の配列を作り、それを角かっこに入れると True の位置の値だけが選ばれます。level05 で Pandas フィルタリングの骨格になる文法なので、ここで手になじませておいてください。

### 3-4. ブロードキャスト — 大きさが違っても合わせて計算

`配列 * 1.1` のように配列と数値1個 (スカラー) を演算すると、NumPy が数値を配列の大きさに合わせて「引き伸ばして」計算してくれます。実際にメモリをコピーするのではなく概念的に引き伸ばすだけなので、コストもかかりません。`(30, 5)` の配列に `(5,)` の配列を足すと各行に足される、というように、次元が違ってもルールが合えば自動的に拡張されます。

### 3-5. 集計関数

`sum()`、`mean()` (平均)、`std()` (標準偏差)、`min()/max()`、`round()` などが配列のメソッドとして提供されています。2次元配列では `axis=0` (列方向)/`axis=1` (行方向) で集計の方向を決めますが、これは level07 の groupby を理解する土台になります。

## 6. よくある間違い

- **リストと配列の `*` の混同**: `[1, 2] * 3` はリストの繰り返し (`[1,2,1,2,1,2]`) で、`np.array([1, 2]) * 3` は要素ごとの掛け算 (`[3, 6]`) です。まったく別の動作です。
- **None の混ざったリストをそのまま配列に変換**: dtype が `object` になり、ベクトル化の速度メリットが消えます。欠損は配列にする前に除去するか、`NaN` に統一する必要があります。
- **配列を for 文で回す**: 文法的にはできますが、NumPy を使う意味がなくなります。「繰り返しを書きたくなったら、先にベクトル演算がないか探す」を原則にしましょう。
- **`axis` の方向の勘違い**: 2次元での `sum(axis=0)` は「行たちを押しつぶして」列ごとの合計を作ります。結果の shape を常に確認してください。
