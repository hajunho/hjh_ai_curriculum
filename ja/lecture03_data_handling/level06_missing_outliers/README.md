# Lecture 03 · Level 06 — 欠損値と外れ値の処理

> 空の値と、辻褄の合わない値を見つけ出し、状況に合った処理戦略を選ぶ方法を学びます。

**難易度** ⭐⭐⭐ / **前提** level05_filter_sort_select / **目安時間** 40分

## 1. なぜ学ぶのか — ビジネスの視点

実務のデータがきれいだったことは、ほとんどありません。POS 端末が一時的に落ちて売上が記録されなかったり、返金処理がマイナスの売上として入ってきたり、担当者がうっかり0を1つ多く付けたり、ということが毎日起きています。

問題は、こうした汚染が **静かに** 分析結果を壊すことです。欠損値 (missing value) が混ざったまま平均を出すと標本が減ったまま計算され、マイナスの売上が混ざると合計が実際より小さく出ます。レポートの数字が間違っているのに何のエラーも出ない — これが最も怖いシナリオです。

だからデータアナリストたちは「分析時間の半分以上はクレンジングに使う」と言います。このレベルでは、汚染を **診断** し、複数の **処理戦略** を比較し、どの戦略がどの状況に合うかを判断する目を養います。

## 2. たとえ話で理解する

月末決算で、5つの店舗から上がってきた売上伝票の束を受け取ったと想像してください。

- ある伝票は **金額欄が空** です。 → 欠損値です。
- ある伝票には **-350,000ウォン** と書かれています。売上がマイナスのはずはないので、何かが間違っています。 → ドメインルール違反の異常値です。
- ある伝票は、普段30万ウォン前後なのに1枚だけ **9,000万ウォン** です。あり得なくはないですが、非常に怪しい。 → 統計的な外れ値 (outlier) です。

経験豊富な経理担当者は、こうした伝票をそのまま捨てません。まず **何枚おかしいか数え** (診断)、店舗に電話して **原因を尋ね** (調査)、原因が分からないときだけ **ルールに従って補正** します (処理)。たとえば金額が空の伝票は「その店舗・その品目の普段の売上」で暫定記入しておく、という具合です。

Pandas の欠損値・外れ値処理も、まったく同じ順序です。`isna()` で数え、原因を推定し、`dropna()`・`fillna()` で処理します。

## 3. 核心となる考え方

### 3-1. 欠損値はなぜ生まれるのか

欠損値の原因は大きく3系統です。

| 類型 | 例 | 処理のヒント |
|---|---|---|
| 収集の失敗 | 端末の通信エラーで記録漏れ | ランダムな欠落なら補完 (代替) が比較的安全 |
| そもそも存在しない値 | 新規店舗の「昨年の売上」 | 埋めてはいけない場合が多い |
| 入力ミス | 担当者が欄を飛ばした | 原本の確認が最善 |

原因によって正しい処理が変わるため、**「消す前に原因を問え」** が第一の原則です。

### 3-2. 診断の道具 — isna、notna、describe

- `df["revenue"].isna()` : 各値が欠損かどうかを True/False で教えてくれます。`.sum()` を付ければ欠損の数、`.mean()` を付ければ欠損の比率になります。
- `df.describe()` : 件数・平均・最小値 (min)・最大値 (max) を一度に見せてくれます。**min がマイナス** なら売上データとして辻褄が合わないので、即座に気づけます。

### 3-3. ドメインルールの異常値 — 業務知識が先

統計手法より先に適用すべきなのがドメインルール (domain rule)、つまり業務の常識です。「売上は0以上である」「年齢は150を超えない」のようなルールですね。ルールを破った値は測定エラーなので、欠損値に変えておくのが定石です。

```python
df.loc[df["revenue"] < 0, "revenue"] = np.nan
```

注意: マイナスをそのまま **削除** すると、「その日その店舗で販売があった」という事実まで消えます。値が分からないと印を付けておく (NaN) ほうが、情報の損失が少なくて済みます。

### 3-4. 統計的な外れ値 — IQR 法

ドメインルールで捕まえられない「怪しく大きい/小さい値」は、IQR (四分位範囲、Interquartile Range) で探します。

- Q1 = 下位25%の地点、Q3 = 上位75%の地点、IQR = Q3 − Q1
- 正常範囲: **[Q1 − 1.5×IQR, Q3 + 1.5×IQR]** — この外の値を外れ値の候補と見なします。

「候補」と呼ぶ理由が重要です。週末の大当たりの売上のように、**本物の現象** が外れ値として引っかかることもあるからです。IQR は自動削除の道具ではなく、**検討リストを作る道具** です。

### 3-5. 処理戦略3つ

| 戦略 | コード | 長所 | 短所 |
|---|---|---|---|
| (a) 行の削除 | `dropna()` | 単純、偽の値がない | 標本が減る、合計が小さくなる |
| (b) 全体の中央値で代替 | `fillna(med)` | 行を保存 | 店舗・品目の特性を無視 |
| (c) グループ別の中央値で代替 | `groupby().transform("median")` | 文脈を反映、最も精巧 | コードがやや複雑 |

平均ではなく **中央値 (median)** を使う理由は、平均は残っている外れ値に引きずられるのに対し、中央値はよく持ちこたえるからです。(c) は「渋谷店のコーヒーの空欄は、渋谷店のコーヒーの普段の値で埋める」という発想で、実務で最もよく使われる方式です。

核心は、**どの戦略でも統計量が変わる** という事実です。合計の指標が重要なレポートなら削除は危険で、平均の指標なら代替方式の影響は小さめです。だから戦略を変えながら結果を比較する習慣が必要です。

## 4. 実習 — main.py

実行方法:

```bash
cd lecture03_data_handling/level06_missing_outliers
python3 main.py
```

出力の流れと見どころ:

- **[1] 汚染の診断** — 欠損の数・比率、マイナスの数、`describe()` の min がマイナスであることを確認します。9,125行のうち欠損 約1%、マイナス 約0.5%が仕込んであります。
- **[2] ドメインルールの適用** — マイナスの売上を NaN に変えます。削除ではなく「値が分からない」と印を付ける点に注目してください。
- **[3] IQR の異常境界** — Q1、Q3、正常範囲と上側の外れ値の数を計算します。週末・繁忙期の売上が引っかかりうることも一緒に出力します。
- **[4] 戦略の比較** — dropna / 全体の中央値 / グループ別の中央値の3戦略でそれぞれ処理した後、行数・総売上・平均を表で比較します。dropna の総売上が目に見えて小さくなるのが観戦ポイントです。
- **[5] 前後の要約と箱ひげ図** — 処理前後の要約を出力し、箱ひげ図 (boxplot) の PNG を `outputs/` に保存します。

コードの核心部は (c) 戦略です。

```python
group_median = df.groupby(["store", "category"])["revenue"].transform("median")
df["revenue_filled"] = df["revenue"].fillna(group_median)
```

`transform` はグループ別の計算結果を **元の行数のまま** 返してくれるので、各行が自分のグループの中央値で埋められます。

## 5. やってみよう

1. **欠損比率の店舗別チェック** — 欠損が特定の店舗に集中していないか、`df[df["revenue"].isna()]["store"].value_counts()` で確認してみましょう。(ヒント: このデータはランダムな汚染なので均等に出ます。実務で1店舗に集中していたら、その店舗の機器を疑うべきです。)
2. **平均代替と中央値代替の比較** — 戦略 (b) を `mean()` に変えて、総売上・平均がどう変わるか比較してみましょう。(ヒント: マイナスを NaN に変える **前** の平均で埋めると汚染が伝播します。順序が重要です。)
3. **IQR 倍数の実験** — 1.5 の代わりに 3.0 を使うと外れ値の数はどう変わりますか? どんなレポートなら 3.0 (保守的) のほうが適切か考えてみましょう。(ヒント: 誤検知を減らしたい自動アラートシステム。)

## 6. よくある間違い

- **`df[df["revenue"] != None]` で欠損をふるい落とそうとする** — Pandas の欠損は `NaN` なので、`!= None` の比較では除去できません。必ず `isna()`/`notna()` を使いましょう。
- **NaN == NaN が False だと知らない** — NaN は自分自身とも等しくありません。比較演算の代わりに専用関数を使うべき理由です。
- **fillna の結果を変数で受けない** — `df.fillna(0)` は新しい DataFrame を返すだけで、原本を変えません。`df = df.fillna(0)` のように受け直しましょう。
- **原本の毀損** — クレンジングはコピー (`df.copy()`) で行い、元のファイルは残しておきましょう。「原本は証拠物件」です。
- **外れ値の自動削除** — IQR に引っかかったからと機械的に消すと、年末特需のような本物のシグナルを捨てることになります。必ず目で検討してから決めましょう。
