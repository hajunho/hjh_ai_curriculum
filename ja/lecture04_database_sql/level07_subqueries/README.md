# Lecture 04 · Level 07 — サブクエリ

> クエリの結果を別のクエリの材料として使うサブクエリ (スカラー・IN・相関) を学び、WITH (CTE) で複雑なクエリを読みやすい段階的な文に整理します。

**難易度** ⭐⭐⭐ / **前提** level06 / **目安時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

実務の質問には「基準そのものをデータから求める必要がある」ものがたくさんあります。
「**平均より** 高い商品は?」— 平均がいくらか先に求めなければなりません。
「**ノートパソコンを買った** 顧客のリストは?」— ノートパソコン購入の注文リストが先に必要です。
「**自分の部署の平均より** 給与が高い従業員は?」— 行ごとに基準が違います。
このような二段階の質問を一文で表現する道具がサブクエリ (subquery) です。
そして分析が 3〜4 段階に長くなったら、各段階に名前を付けて上から下へ
読めるようにする CTE (Common Table Expression、WITH 句) が協業の必需品に
なります。他人が読めるクエリを書ける人とそうでない人の差は、ここで
分かれます。

## 2. たとえ話で理解する

窓口担当者に「平均より高い商品のリストをください」と言うと、担当者は **メモを
二枚** 書きます。一枚目のメモ: 「商品価格の平均を求める」→ 答え 290,850 ウォン。二枚目の
メモ: 「価格が 290,850 ウォンを超える商品を探す」。一枚目のメモの **答えを二枚目のメモの
空欄にはめ込む** こと — これがサブクエリです。SQL ではかっこがメモの
境界線です: `WHERE price > (SELECT AVG(price) FROM products)`。

メモの答えの形によって使い方が変わります。

- 答えが **数字一つ** (平均値) → 比較演算にはめる = **スカラーサブクエリ**
- 答えが **リスト** (注文番号の集まり) → IN にはめる = **IN サブクエリ**
- 外側の行を **一つ読むたびにメモを書き直す** (その従業員の部署の平均) =
  **相関サブクエリ**

CTE はメモに **名札を付けて机に広げておくこと** です。「このメモは
『顧客別購入額』と呼ぼう」— 次の段階でテーブルのように取り出して使います。
かっこの中にかっこが重なる代わりに、料理のレシピのように 1 段目・2 段目と読めます。

## 3. 核心となる考え方

### 3-1. スカラーサブクエリ — 答えが値一つ

```sql
SELECT name, price
FROM   products
WHERE  price > (SELECT AVG(price) FROM products);
```

かっこの中が先に実行されて値一つに変わり、そのあと外側のクエリが実行される、と読めば
大丈夫です。SELECT のリストの中に入れて「全体平均」の列を並べて見せることもできます。

### 3-2. IN サブクエリ — 答えがリスト

```sql
SELECT name FROM customers
WHERE  customer_id IN (SELECT customer_id
                       FROM orders
                       WHERE status = 'キャンセル');
```

「キャンセル注文を出したことのある顧客」。かっこの中の結果 (顧客番号リスト) が IN の
リストの位置に入ります。逆 (`NOT IN`) を使うときは、リストに NULL が混ざると
全体が 0 件になる有名な落とし穴があるので、NOT IN のサブクエリには
`WHERE ... IS NOT NULL` を添える習慣をつけましょう。

### 3-3. 相関サブクエリ — 行ごとに尋ね直す

```sql
SELECT e.name, e.dept, e.salary
FROM   employees AS e
WHERE  e.salary > (SELECT AVG(e2.salary)
                   FROM   employees AS e2
                   WHERE  e2.dept = e.dept);   -- 外側の行の部署を参照!
```

内側のクエリが外側の行の値 (`e.dept`) を参照するので、**外側の行ごとに** 内側が
再実行されます。「自分の部署の平均より高い給与」のように、行ごとに基準が違う
質問の標準的な解法です。行数が非常に多いと遅くなり得る点は level09
で扱います。

### 3-4. CTE (WITH 句) — 段階に名前を付ける

```sql
WITH customer_totals AS (        -- 1 段目: 顧客別の購入額
    SELECT o.customer_id, SUM(oi.quantity * p.price) AS total
    FROM   orders o
    JOIN   order_items oi ON oi.order_id = o.order_id
    JOIN   products p     ON p.product_id = oi.product_id
    GROUP BY o.customer_id
)
SELECT c.name, t.total            -- 2 段目: 平均以上だけを選ぶ
FROM   customer_totals t
JOIN   customers c ON c.customer_id = t.customer_id
WHERE  t.total > (SELECT AVG(total) FROM customer_totals);
```

同じ中間結果 (customer_totals) を二回再利用しながら、それでも上から下へ
読めるということが核心です。WITH の中にクエリをカンマでつないで複数の段階を置く
こともできます。**「サブクエリが二回以上使われるか、かっこが二重になったら
CTE に昇格」** — 実務で通用する良い基準です。

### 3-5. FROM 句のサブクエリ

かっこで囲んだクエリを FROM の位置に置いて別名を付けると、一時テーブルのように
使えます (派生テーブル)。CTE と機能が重なりますが、読みやすさはほぼ常に CTE の
ほうが上です。他人のクエリで出会ったら「名前のない CTE なんだな」と解釈すれば
大丈夫です。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

- **[1] スカラー**: 平均より高い商品 — 基準値を先に見せてから (メモ 1)、
  それがはめ込まれた本番のクエリ (メモ 2) を実行し、二つの段階を目でつなぎます。
- **[2] IN**: 「ノートパソコン」を買ったことのある顧客リスト — order_items → orders →
  customers とつながる二重の IN サブクエリ。
- **[3] 相関**: 自分の部署の平均より給与が高い従業員 — 部署平均の表を先に
  見せて、相関サブクエリの結果と対照します。
- **[4] CTE**: 「平均以上の購入をした顧客」— customer_totals という 1 段目に名前を
  付け、2 段目で平均と比較。同じ CTE が二回再利用されることに
  注目してください。
- **[5] CTE 複数ステップ**: 月別売上 → その中で最高売上の月探しを WITH の二つの
  段階で — レポートクエリの典型的な骨格です。

## 6. よくある間違い

- **スカラーの位置に複数行を返す**: `price > (SELECT price FROM ...)` の
  かっこが複数行を返すと、エラーになるか (他の DB)、先頭の行だけが黙って使われます
  (SQLite)。スカラーの位置には集計や LIMIT 1 で「一つの値」を保証しましょう。
- **NOT IN + NULL**: リストに NULL が一つでもあると、結果が丸ごと
  0 件になります。NOT IN のサブクエリには IS NOT NULL フィルターを。
- **相関サブクエリの別名の省略**: 内と外が同じテーブルの場合、別名 (e, e2) が
  ないとどちらの列なのか絡まります。相関サブクエリでは別名が必須。
- **かっこの三重ネスト**: 読める人が自分だけになります。二重になったら CTE へ。
- **CTE を性能の道具と誤解する**: CTE は基本的に「読みやすく名前を付けること」
  です。速くなるわけではありません (速度は level09 のテーマ)。
