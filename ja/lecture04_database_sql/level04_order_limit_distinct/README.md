# Lecture 04 · Level 04 — ソート・重複排除・上位 N 件

> ORDER BY で結果を並べ替え、LIMIT で上位 N 件だけを切り出し、DISTINCT で重複を取り除きます。「最高価格の商品トップ 5」のようなランキング表を SQL 一文で作ります。

**難易度** ⭐⭐ / **前提** level03 / **目安時間** 35分

## 1. なぜ学ぶのか — ビジネスの視点

レポートの表はほとんどが **並べ替えた表** です。「売上上位 10 店舗」、「直近の
注文 20 件」、「いちばん安い見積もり 3 件」。そして会議でよく出る質問 —
「うちの顧客はどの都市にいるんでしたっけ?」— は実は **重複を除いたリスト** を
尋ねています。ORDER BY (並べ替え)、LIMIT (上位 N)、DISTINCT (重複排除) の三つの
道具さえあれば、この種の依頼のほとんどが一文で終わります。特に「トップ N」
パターンは現場の SQL で体感的にもっともよく使う形の一つなので、完全に手に
なじませておくのがおすすめです。

## 2. たとえ話で理解する

窓口担当者の作業手順を想像してください。依頼書のとおりに帳簿から
条件に合う行を選んでかごに入れたあと (FROM + WHERE)、最後に三つの
仕上げをします。

- **ORDER BY = 整列**: かごの中の行を依頼された基準 (価格順、日付順…)
  で並べ替えてトレイに載せます。同点があれば二つ目の基準でさらに
  並べ替えます — 運動会で「背の順、同じ身長なら名前の五十音順」と
  同じです。
- **LIMIT = 上から数枚だけ切り取る**: 並べたトレイの上から N 枚だけを
  手渡します。並べ替えずに切ると「ただの適当な 5 枚」になるので、**トップ N は必ず
  ORDER BY とセット** です。
- **DISTINCT = 重複したカードを捨てる**: 同じ内容のカードが何枚もあれば一枚
  だけ残します。「顧客が住んでいる都市のリスト」のように **種類** を尋ねるときに
  使います。

大事な点: この仕上げはすべて **結果のかごに対する作業** です。原本の帳簿は
まったく変わりません。

## 3. 核心となる考え方

### 3-1. ORDER BY — 昇順と降順

```sql
SELECT name, price
FROM   products
ORDER BY price DESC;   -- 高いものから (DESC = descending、降順)
```

デフォルトは昇順 (ASC、省略可能) です。日付の列を DESC で並べると「新しい順」に
なります。文字の列は辞書順 (漢字は文字コード順なので、読みの五十音順とは
限りません) で並びます。

### 3-2. 複数の並べ替え基準

```sql
ORDER BY city ASC, grade DESC
```

まず都市順に、同じ都市の中ではグレードの逆順に。カンマの順番が
優先順位です。別名や計算式も基準にできます:
`ORDER BY price - cost DESC` (粗利の大きい順)。

### 3-3. LIMIT と OFFSET

`LIMIT 5` は先頭 5 行だけ、`LIMIT 5 OFFSET 5` は 6〜10 行目を取り出します。
Web サイトの「2 ページ目」がまさに OFFSET です。注意: **LIMIT は計算を減らす
ものではなく、見せる量を減らすもの** です。並べ替えは全体に対して行われたあと、
上の部分だけが切り取られます。

### 3-4. DISTINCT — 種類を尋ねる質問

```sql
SELECT DISTINCT city FROM customers;
```

200 人の顧客の行から都市の値だけを抜くと重複だらけですが、DISTINCT が同じ値を
一度ずつだけ残します。列を二つ書くと `(city, grade)` の **組み合わせ** の重複を
取り除きます — 「都市ごとに存在するグレードの組み合わせ」のように。「何種類あるか?」まで
数える `COUNT(DISTINCT city)` は次のレベル (集計) で登場します。

### 3-5. 文の中での位置 (語順のルール)

SQL の句は順番が決まっています。

```
SELECT [DISTINCT] 列リスト
FROM   テーブル
WHERE  条件
ORDER BY 基準
LIMIT  N;
```

実行の順序は FROM → WHERE → SELECT → ORDER BY → LIMIT。「選び出して (WHERE)、
列を整えて (SELECT)、並べて (ORDER BY)、切る (LIMIT)」と覚えてください。

- **[1] 最高価格の商品トップ 5**: `ORDER BY price DESC LIMIT 5` — ランキング表の基本形。
- **[2] 粗利の大きい商品トップ 3**: 計算式 `price - cost` を並べ替えの基準に使用。
- **[3] 最新の注文 5 件**: 日付の列を DESC — 「直近の履歴」パターン。

- **[6] ページ分け**: 同じランキングのクエリに `LIMIT 5 OFFSET 5` を付けて

- **[7] 落とし穴の実演**: ORDER BY なしで LIMIT 5 だけ書くと「ただの先頭 5 行」が

3. **(チャレンジ)** 注文 (orders) テーブルに存在する状態 (status) の **種類** を

   *ヒント: SELECT DISTINCT status FROM orders — 結果は 3 種類です。*

## 6. よくある間違い

- **ORDER BY のない「トップ N」**: LIMIT だけ書くと、DB にとって都合の良い順序
  (事実上ランダム) で N 個を返すだけです。トップ N = ORDER BY + LIMIT のセット、例外なし。
- **DESC を忘れたランキング**: 「売上トップ 5」を出したのにワースト 5 が出てきたら、
  十中八九 DESC の付け忘れです。デフォルトが昇順であることを覚えておきましょう。
- **DISTINCT をどこにでも付けること**: DISTINCT は SELECT の直後に一度だけ書き、
  **選択した列の組み合わせ全体** に適用されます。`SELECT DISTINCT city, name` は
  「都市だけ重複排除」ではなく「(都市, 名前) の組み合わせの重複排除」です。
- **数字に見える文字の並べ替え**: 価格が TEXT で保存されていると '9' > '1200000'
  のような辞書順の並びが起こります。並び順がおかしいときはデータ型から確認しましょう。
- **句の順番の入れ替え**: `LIMIT 5 ORDER BY price` のように順番を変えると文法
  エラーです。WHERE → ORDER BY → LIMIT の順番を守りましょう。
