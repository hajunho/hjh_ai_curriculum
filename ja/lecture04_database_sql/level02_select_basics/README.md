# Lecture 04 · Level 02 — SELECT の基礎

> SQL の最初の一文にしてすべての始まりである SELECT を学びます。目的のテーブルから欲しい列だけを選び、列名に別名を付け、計算列を作ってみます。

**難易度** ⭐ / **前提** level01 / **目安時間** 35分

## 1. なぜ学ぶのか — ビジネスの視点

実務での SQL 利用の 9 割以上は **照会** です。データを変更するのはシステムの
仕事で、人は主に「見せて」と尋ねます。その「見せて」がまさに
SELECT (セレクト) です。SELECT の一文が自由に書けるだけで、「顧客リストを
抽出してください」と他のチームに依頼して二日待っていた仕事が、30 秒の
セルフサービスに変わります。しかも SELECT はデータを読むだけで決して変更しない
ので、初心者が思い切り練習しても事故が起きない安全な文です。

## 2. たとえ話で理解する

SELECT 文は **窓口担当者に渡す依頼書の用紙** です。文房具店の帳簿の
たとえを続けると、依頼書には二つの欄があります。

> **どの帳簿から** (FROM customers — 顧客名簿から)
> **どの項目を** (SELECT name, city — 氏名と都市の項目だけ)

読む順番が日本語と逆になる点にだけ注意してください。SQL では「SELECT 氏名, 都市
FROM 顧客名簿」と書きますが、窓口担当者は「顧客名簿から (FROM) → 氏名と都市を
(SELECT)」の順で処理します。SQL を読むときは **FROM から探して読む習慣** を
つけると、長いクエリも怖くなくなります。

別名 (alias) は依頼書の「レポートにはこの名前で書いてください」という欄です。
`price AS 販売価格` と書くと、結果表の列見出しが「販売価格」に変わります。データ
そのものはそのままで、**見える名前だけ** を変えるのです。

## 3. 核心となる考え方

### 3-1. 基本の形

```sql
SELECT 列1, 列2      -- 何を (列のリスト)
FROM   テーブル;      -- どこから
```

- 大文字と小文字は区別されませんが、慣例として予約語 (SELECT, FROM…) は大文字、
  テーブル名・列名は小文字で書きます。目に付きやすいからです。
- 文末のセミコロン (;) は「依頼書はここまで」という印です。
- `--` 以降はコメントで、実行されません。

### 3-2. すべての列: `SELECT *`

`*` は「全部」という意味です。テーブルを初めて眺めるときには便利ですが、実務の
クエリでは必要な列だけを明記するのが良い習慣です。列が数十個あるテーブルで
`*` は画面の無駄遣いですし、あとで列が追加されると結果の形が変わる原因になります。
「まず * でざっと眺め、本番のクエリは列名で」— これが実務のリズムです。

### 3-3. 別名 (AS)

```sql
SELECT name AS 商品名, price AS 販売価格
FROM   products;
```

AS は省略もできますが (`price 販売価格`)、初心者のうちは明記するほうが読み
やすくなります。別名は結果表の列見出しを変えるだけで、テーブルの実際の列名は
変わりません。

### 3-4. 計算列 (expression)

SELECT のリストには列名だけでなく **計算式** も書けます。

```sql
SELECT name,
       price,
       cost,
       price - cost AS 粗利
FROM   products;
```

行ごとに `price - cost` が計算され、新しい列のように現れます。Excel の D 列に
`=B2-C2` の数式を入れるのと同じですが、数式をコピーして貼り付ける必要がなく、
一文ですべての行に適用されます。文字列をつなぐ `||` 演算子や、四捨五入の
`ROUND()` のような関数も同じ場所に書きます。

### 3-5. 先取りで登場する LIMIT

結果が数百行になると画面からあふれるので、このレベルから `LIMIT 5` (先頭 5 行のみ)
を付けて出力を減らします。正式な説明は level04 でするので、今は「プレビュー
装置」とだけ覚えておいてください。

### 3-6. SELECT は原本を変えない

SELECT の結果は原本テーブルの **コピー画面** です。別名を付けても計算列を
作っても、hjh_shop.db の中のデータは 1 バイトも変わりません。だから照会の
練習はいくら失敗しても安全です。データを実際に変更する文 (INSERT,
UPDATE, DELETE) は level08 でトランザクションと一緒に慎重に学びます。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

main.py は毎回 `hjh_shop.db` を作り直したあと、SQL 文を先に print で
表示し、そのすぐ下に実行結果の表を出力します。**SQL> で始まる行が
主役** で、Python コードはその文を届ける実行係に過ぎません。

- **[1] 全列をざっと眺める**: `SELECT * FROM customers LIMIT 5` — テーブルへの
  最初のあいさつ。列の構成とデータの見た目を確認します。
- **[2] 必要な列だけ**: `SELECT name, city FROM customers LIMIT 5` — 依頼書に
  項目を明記する基本形。
- **[3] 別名を付ける**: products を `商品名/カテゴリ/販売価格` という日本語見出しの
  レポート風の表として出力します。
- **[4] 計算列**: `price - cost AS 粗利`、そして
  `ROUND(100.0*(price-cost)/price, 1) AS 粗利率` で行ごとに計算。
- **[5] 文字列の連結**: `name || ' (' || grade || ')'` で「佐藤翔太 (VIP)」形式の
  表示用の列を作ります。メールの差し込みなど、実務でよく使うパターンです。

各ステップで SQL 文を読むとき、FROM を先に探して → SELECT のリストを読む
練習をしてみてください。出力表の列見出しが別名のとおりに変わることも確認しましょう。

## 6. よくある間違い

- **文字列にダブルクォートを使う**: SQL では文字データをシングルクォート (`'東京'`)
  で囲みます。ダブルクォートは列名・テーブル名用なので、混ぜて使うと分かりにくい
  エラーになります。
- **列名の打ち間違い**: `SELECT nmae` のように打ち間違えると "no such column"
  エラーになります。エラーメッセージにヒントが全部あるので、怖がらずに読んでみましょう。
- **SELECT の後のカンマの抜け/余り**: `SELECT name city` はエラーにならず、city が
  name の **別名** として解釈されて予想外の結果になります。カンマを必ず確認しましょう。
- **本番クエリで `SELECT *` を使う**: ざっと眺めるときだけにして、保存して繰り返し
  使うクエリでは列名を明記しましょう。
