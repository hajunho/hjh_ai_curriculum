# Lecture 04 · Level 03 — WHERE: 条件検索

> 「全部」ではなく「条件に合うものだけ」を取り出す方法を学びます。比較演算、AND/OR、IN、LIKE、BETWEEN、NULL の扱いまで — 業務の質問 6 つを SQL に翻訳します。

**難易度** ⭐⭐ / **前提** level02 / **目安時間** 40分

## 1. なぜ学ぶのか — ビジネスの視点

実務のデータの質問には、ほぼ必ず条件が付きます。「東京在住の **VIP** 顧客」、
「**キャンセルされた** 注文」、「**第3四半期** の売上」、「**佐藤姓** の担当者」。
Excel でフィルターボタンを押してチェックボックスを選んでいた作業が、SQL では
WHERE (ウェア) の一行です。違いがあるとすれば、Excel のフィルターは毎回手で
押し直す必要がありますが、WHERE の文は **保存しておけばいつでも同じ条件を
再実行** でき、条件を言葉で説明する代わりに文そのものを同僚に渡せる点です。
「どんな条件で抽出したんですか?」という質問にクエリ一行で答えること —
それがデータコミュニケーションの正確さです。

## 2. たとえ話で理解する

WHERE は窓口担当者に渡す依頼書の **三つ目の欄** です。

> どの帳簿から (FROM) / どの項目を (SELECT) / **どの行だけを** (WHERE)

窓口担当者は帳簿を一行ずつめくりながら、各行に質問を投げかけます。「この顧客は
東京在住か? しかも VIP か?」— 答えが「真 (true)」の行だけを結果のかごに
入れます。つまり WHERE の後に来るのは **行ごとに真/偽を判定する文** です。

lecture02 で学んだ Python の if 条件式とまったく同じ役割です。
`if city == "東京" and grade == "VIP":` を SQL で書くと
`WHERE city = '東京' AND grade = 'VIP'` — 等号が一つ (=) であることと、
文字列がシングルクォートであることだけが違います。

## 3. 核心となる考え方

### 3-1. 比較演算子

`=` (等しい)、`<>` または `!=` (等しくない)、`>`、`>=`、`<`、`<=`。
Python と違って「等しい」が `==` ではなく `=` 一つです。

```sql
WHERE price >= 100000        -- 10万ウォン以上
WHERE status <> 'キャンセル'  -- キャンセルではないもの
```

### 3-2. AND / OR / NOT — 条件の組み合わせ

```sql
WHERE city = '東京' AND grade = 'VIP'          -- 両方を満たす
WHERE grade = 'VIP' OR grade = 'GOLD'          -- どちらか一方でも
```

AND は OR より先に計算されます。`A OR B AND C` は `A OR (B AND C)` と
解釈されて意図とずれやすいので、**OR が混ざったら必ずかっこを付ける習慣** を
つけましょう。

### 3-3. IN — リストのどれか

`grade IN ('VIP', 'GOLD')` は `grade='VIP' OR grade='GOLD'` の省略形です。
リストが長いほど IN のほうが圧倒的に読みやすくなります。逆は `NOT IN`。

### 3-4. LIKE — パターン検索

文字列の「〜で始まる/終わる/を含む」検索です。`%` は「任意の文字 0 個以上」、
`_` は「任意の文字ちょうど 1 個」を意味するワイルドカードです。

```sql
WHERE name LIKE '佐藤%'        -- 佐藤で始まる (佐藤姓)
WHERE name LIKE '%コーヒー%'   -- コーヒーを含む商品名
```

### 3-5. BETWEEN — 範囲

`price BETWEEN 10000 AND 100000` は `price >= 10000 AND price <= 100000` と
同じです。**両端を含む** ことを覚えておいてください。日付の文字列にもそのまま
使えるので、期間の照会の定番です:
`ordered_at BETWEEN '2025-07-01' AND '2025-09-30'` (第3四半期)。

### 3-6. NULL — 値が「ない」ことの扱い方

NULL (ヌル) は 0 でも空文字列でもなく **「記録されていない」** です。だから普通の
比較が通用しません。`manager_id = NULL` は常に偽になり、どの行も
出てきません。必ず専用の文法を使います。

```sql
WHERE manager_id IS NULL       -- 上司がいない人 (= 最高責任者)
WHERE manager_id IS NOT NULL   -- 上司がいる人
```

「なぜ = ではだめなの?」— NULL は「不明」なので、「不明 = 不明」の答えも「不明」だから
です。SQL 初心者の事故ポイント第 1 位なので、IS NULL だけは丸暗記してください。

main.py は実際の業務で出てきそうな質問 6 つを先に日本語で示し、
それを翻訳した SQL と実行結果を出力します。

- **[Q1] 「東京在住の VIP 顧客リストをください」** — `=` と AND。
- **[Q2] 「10万ウォン以上、または粗利率 50% 超の商品は?」** — OR とかっこ、
  計算式を条件に使う例。
- **[Q3] 「首都圏 (東京・横浜) または大阪の顧客のうち GOLD 以上だけ」** — IN を二回と

- **[Q4] 「佐藤姓の顧客を探してください」** — LIKE '佐藤%'。
- **[Q5] 「第3四半期 (7〜9月) のキャンセル注文の明細」** — BETWEEN + AND。

  `= NULL` と書き間違えたクエリも一緒に実行し、**0 件になる落とし穴** を見せます。

各質問で「日本語の質問 → WHERE の条件」がどう対応しているのか、下線を引くように
たどってみてください。条件を一行ずつ読みながら「この行は真か?」と自分で判定して
みるのが最高の練習です。

## 6. よくある間違い

- **`= NULL`**: 永遠に 0 件です。`IS NULL` / `IS NOT NULL` だけを覚えてください。
- **OR のかっこ省略**: `WHERE city='東京' OR city='横浜' AND grade='VIP'` は
  「東京の全員 + 横浜の VIP」になります。意図が「東京・横浜の VIP」なら
  `(city='東京' OR city='横浜') AND grade='VIP'`。
- **文字列と数値の比較**: クォートを付けた `'100' > 20` のような比較はデータ型が
  混ざって予想外の結果を生みます。数値の列はクォートなしで比較しましょう。
- **LIKE と大文字小文字**: SQLite の LIKE は英字の大文字小文字を区別しませんが、
  他の DB (例: PostgreSQL) は区別します。会社の DB で結果が違ったら、まずここを
  疑ってください。
- **BETWEEN の日付の端**: `BETWEEN '2025-07-01' AND '2025-09-30'` は 9 月
  30 日を含みます。ただし日付に時刻まで付く DB では「9 月 30 日 0 時まで」と
  解釈されることがあるので、実務では `< '2025-10-01'` 方式も覚えておきましょう。
