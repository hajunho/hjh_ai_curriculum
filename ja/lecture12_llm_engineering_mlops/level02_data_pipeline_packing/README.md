# Lecture 12 · Level 02 — 学習データパイプラインとパッキング

> 文書を `<s>...</s>` でつないで固定長に切り、uint16 バイナリシャードと memmap で「数兆トークンを流し続けるベルトコンベア」をミニチュアで作ります。

**難易度** ⭐⭐⭐ / **前提** level01 / **想定時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

LLM の事前学習で、GPU は 1 時間あたり数百円〜数千円のメーターを回しながら動いています。この高価な機械がデータを待って遊んでいる瞬間が、そのままお金の浪費です。だから大規模学習の実力差は、モデルのコードよりも **データを途切れなく、無駄なく供給するパイプライン** で決まることが多いのです。

ビジネス視点でこのレベルが答える問いは 3 つです。第一に「なぜ学習データはテキストファイルではなく、へんなバイナリで保存するのですか?」 — 毎回トークン化をやり直すと CPU がボトルネックになるので、一度トークン化した結果を機械がそのまま食べられる形で保存しておきます。第二に「数百 GB のデータをどうやってメモリに載せるのですか?」 — 載せません。memmap という手法で、必要な断片だけをその都度読みます。第三に「文書の長さがばらばらなのに、なぜ GPU は常に満杯なのですか?」 — パッキングのおかげです。この 3 つは、AI インフラの見積書とボトルネックの議論にそのまま出てくる実務概念です。

## 2. たとえ話で理解する

巻き寿司工場を想像してください。注文 (文書) は長さがばらばらです。細巻き 2 切れだけの客もいれば、10 本頼む客もいます。

**悪いやり方**: 注文ごとに弁当箱 (固定長バッチ) を 1 つずつ割り当て、空いた場所はバラン (`<pad>` トークン) で埋めます。細巻き 2 切れに大きな箱を使えば、箱の大半がバラン — GPU 演算の大部分が意味のないパディング計算に浪費されます。

**パッキング方式**: すべての注文を巻きすの上に延々とつないで巻き、1 本の超長い巻き寿司 (トークンストリーム) を作ります。注文と注文の間には仕切りのかんぴょう (`<s>`、`</s>` トークン) を挟んで境目を示します。そして箱の大きさ (block_size) ごとにトントンと切って詰めます。ある箱は 2 つの注文にまたがりますが、仕切りがあるので食べる人 (モデル) は「ここから新しい注文だな」と分かります。箱に空きはありません。

保存は大きな漬物樽 (バイナリシャード) 方式です。個包装 (文書ごとのファイル数百万個) の代わりに大樽数千個に分けて詰めれば、冷蔵庫の扉を開け閉めする回数 (ファイルを開くコスト) が減って物流が速くなります。

## 3. 核心となる概念

### 3-1. パッキング (packing): `<s> 文書1 </s> <s> 文書2 </s> ...`

すべての文書をトークン化して特殊トークンで包んだあと、1 本の長いストリームにつなぎ、block_size (実習では 64、実際は 4096〜128k) ごとに切って学習サンプルにします。長所は 2 つです。(1) パディングが 0 なので GPU の演算が全部ほんとうの学習に使われます。(2) サンプル長が均一なのでバッチ構成が単純になります。代わりに 1 つのサンプルの中に別々の文書の尻尾と頭が混ざりますが、`<s>` トークンが「新しい文書の始まり」の合図になり、モデルは文脈を切って読む方法も一緒に学びます。

### 3-2. uint16 シャード (shard)

トークン id は整数です。vocab が 65,536 より小さければ、id 1 つを 2 バイト (uint16) で保存できます。トークンあたり 2 バイト固定なのでファイルサイズの計算が即座にでき (1 億トークン = 200MB)、パースなしで丸ごと数値配列として読めます。全データを数百〜数千のシャードファイルに分けておけば、複数の GPU が別々のシャードを並列に読めますし、壊れたときはそのシャードだけ作り直せば済みます。

### 3-3. memmap — 開かずに開く技術

`np.memmap` はファイルを RAM にコピーせず、「このファイルはメモリにあることにしよう」と OS に登録するだけです。実際の読み込みは、配列の特定区間に触れた瞬間にその部分だけがディスクから上がってきます。だから 200GB のシャードでも開くのに 0 秒に近く、バッチを取り出すときに必要な数 KB だけ I/O が発生します。lecture03 で学んだ numpy の配列スライス構文がそのまま通じるのも魅力です。

### 3-4. バッチ (x, y) — 答案は 1 つずらすだけ

言語モデルの正解は「次のトークン」なので、入力 x がストリームの `[i : i+64]` なら、正解 y は `[i+1 : i+65]` です。別途のラベルファイルは要りません。データそのものが問題用紙でもあり答案でもある — これが事前学習データが「ただのテキスト」でよい理由です。

## 4. 実習 — main.py

```bash
cd lecture12_llm_engineering_mlops/level02_data_pipeline_packing
python3 main.py
```

パイプライン 7 段階が順に実行されます。`[1]` tiny_corpus を 5 文ずつまとめて 200 件の文書にします (実測 合計 19,260 文字)。日本語コーパスは文末が「。」なので、文の分割も「。」を基準にしています。`[2]` 特殊トークン 4 個 (`<s>`, `</s>`, `<pad>`, `<unk>`) + 文字で vocab を作ります (実測 56 個 = 特殊 4 + 文字 52、文字単位 — level01 の BPE に替えるとストリームはもっと短くなります)。

`[3]` `tokenize_and_pack()` がすべての文書を `<s>...</s>` で包み、**19,660 トークン** のストリーム 1 本につなぎます (文書 200 件 × 2 個の特殊トークン = ちょうど 400 トークン分の増加)。`[4]` `stream.tofile()` で `outputs/shard_000.bin` に保存します。実測でシャードは **39,320 バイト** (トークンあたり 2 バイト)、原文 UTF-8 は **50,180 バイト**。日本語は 1 文字が UTF-8 で 3 バイトなので、トークン id にすると **むしろ小さくなる** のがおもしろいところです。

`[5]` `np.memmap` で即座にロード (19,660 トークン)、`[6]` `get_batch()` がランダムな開始点 8 か所から長さ 64 の (x, y) ペアを切り出します。実測で x[0][:8] = `[27, 44, 6, 4, 16, 20, 14, 18]`、y[0][:8] = `[44, 6, 4, 16, 20, 14, 18, 17]` — y が x をきっちり 1 つずらしたものであることを出力で確認してください。

`[7]` でバッチの先頭行を文字に復元すると、実測でこうなります。

```
先生が プログラムを 直した。 夕方に 学生が カレーライスを 整理した。 朝に 会社員が プログラムを 確認した。</
```

文の途中から始まり、末尾で `</s>` が切れているのが分かります。8 行のうち **7 行** に文書境界 (`<s>`/`</s>`) が含まれています。これがまさにパッキングされた学習データの実際の姿です。

2. **(ふつう)** `[7]` を参考に、バッチ 8 行全体で `<s>` トークンの個数を数えるコードを追加してみましょう。block_size が大きくなるほど境界を含む確率がどう変わるかを確かめてください。(ヒント: `(x == stoi[BOS]).sum()` の一行で済みます。)
3. **(チャレンジ)** 文書を 2 つのシャード (`shard_000.bin`、`shard_001.bin`) に分けて保存し、バッチを取り出すときにシャードをランダムに選ぶよう直してみましょう。(ヒント: ストリーム配列を半分に切ってそれぞれ `tofile` し、`get_batch` の前で `rng.integers(0, 2)` でシャードを選びます。これがマルチ GPU データローダーの骨格です。)

## 6. よくある間違い

- **`<s>` なしでパッキングする**: 境界の印がないと、前の文書の末尾が次の文書の冒頭を予測する「偽のシグナル」になり、モデルが混乱を学習します。仕切りのかんぴょうを抜かさないでください。
- **uint16 の範囲超過**: vocab が 65,536 を超えているのに uint16 で保存すると、トークン id が静かに切り捨てられてデタラメなデータになります。保存前に `vocab_size < 65536` の検証を習慣にしましょう。(実際の大規模モデルの vocab は 10 万を超えるので uint32 を使うこともあります。)
- **memmap を丸ごとコピーする**: `np.array(mm)` のように全体を変換すると memmap の利点が消えて RAM が溢れます。常にスライスで必要な区間だけ取り出してください。
- **トークナイザーのバージョン不一致**: シャードを作ったトークナイザーと違うバージョンでデコードすると、データが丸ごと汚染されます。シャードの隣に vocab ファイルとバージョン情報を必ず一緒に保存しましょう。
