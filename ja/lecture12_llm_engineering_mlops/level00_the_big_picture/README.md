# Lecture 12 · Level 00 — モデルを作るということ — 全体マップ

> ChatGPT のようなモデルが、工場から製品が出てくるようにどんなラインを通って作られるのか。工程ごとの入力・出力・コストを一望します。

**難易度** ⭐ / **前提** なし (lecture11 の受講を推奨) / **想定時間** 30分

## 1. なぜ学ぶのか — ビジネスの視点

ここまでの講義で、皆さんは LLM (大規模言語モデル) を「使う」方法を学んできました。この講義からは視点を変えて、そのモデルが「作られる」過程をミニチュアで自分の手で再現してみます。なぜ非専攻の社会人がここまで知る必要があるのでしょうか。

第一に、意思決定のためです。「自社専用モデルを作ろう」という提案が出てきたとき、それが数十億円規模の事前学習を意味するのか、数十万円のファインチューニングを意味するのかを区別できなければ、予算もスケジュールも立てられません。実際、企業が「自社 LLM」と呼んでいるものの大半は、公開モデルの上に後工程をいくつか載せただけのものです。

第二に、協業のためです。AI チームが「いま SFT 中で、来週 DPO に入ります」と言ったとき、それが工場ラインのどの工程に当たり、何が産出されるのかを知っていれば、会話の質がまるごと変わります。

第三に、採用市場のためです。LLM エンジニアリングを「地図」レベルでも説明できる非開発職はまだ稀です。このレベルは、その地図を描いてお渡しする時間です。

## 2. たとえ話で理解する

LLM の制作は、自動車工場と驚くほどよく似ています。

- **事前学習 (Pretraining)** は製鉄所です。鉄鉱石 (ウェブの生テキスト数兆トークン) を溶鉱炉に入れて数か月溶かし、鋼 (言語の基礎体力) を取り出します。総コストの大部分はここで出ていき、一度失敗すると最初からやり直しです。
- **アニーリング (Annealing)** は熱処理工程です。学習の終盤に教科書級の高品質データだけを選んでゆっくり仕上げると、同じ鋼でもずっと硬くなります。
- **SFT (指示チューニング)** は組立ラインです。鋼の塊はまだ自動車ではないのと同じで、事前学習だけを終えたモデルは「続きを書く」ことしかできず、指示に従えません。マニュアル (指示-応答の例) の通りに組み立てて、はじめて製品の形になります。
- **選好アラインメント (DPO)** は品質検査 (QC) ラインです。2 つの回答のうち顧客が好んだ方を選び、仕上げの品質を整えます。
- **量子化 (Quantization)** は包装工程です。完成車をコンテナに積むには体積を減らさなければならないのと同様に、14GB のモデルを 4GB に圧縮して出荷できるようにします。
- **デプロイ (Serving)** は物流センターです。ここからは「作るコスト」ではなく、注文量に比例する「運用費」の世界です。

この 6 工程を順番に覚えてください。この講義の level01〜11 は、まさにこのラインをたどっていきます。

## 3. 核心となる概念

### 3-1. 二つの大きな局面: 事前学習 vs 事後学習

- **事前学習**: インターネット規模のテキストで「次のトークン当て」だけをやらせます。産出物である base モデルは言語の統計的構造を知っていますが、質問に答えるという概念を持ちません。
- **事後学習 (post-training)**: SFT と選好アラインメントをまとめて呼ぶ言い方です。データは数万〜数十万件で事前学習の数万分の一ですが、ユーザーが体感する「話の通じ具合」はほとんどここで作られます。

### 3-2. コスト感覚 — 6 × N × D の公式

学習に必要な演算量 (FLOPs) は、だいたい **6 × パラメータ数 (N) × トークン数 (D)** で近似できます。7B (70億) パラメータのモデルを 2 兆トークンで学習すると約 8.4×10²² FLOPs。H200 級 GPU 1 枚の実効演算力で割ると数万 GPU 時間、クラウド料金に換算すると億ウォン規模 (数千万円規模) になります。一方 SFT は同じ公式で計算しても数 GPU 時間、数万ウォン程度です。**工程ごとにコストが 1 万倍ずつ違う** という感覚が、このレベルの核心です。

### 3-3. チェックポイントという名の半製品

各工程の産出物は、チェックポイント (checkpoint) というファイルです。base → base-annealed → sft → chat (アラインメント完了) → int4 (量子化) の順に名前が付き、Hugging Face のようなモデルリポジトリで見かける `-base`、`-instruct`、`-int4` という接尾辞は、まさにこの工程位置を教えてくれる荷札です。

### 3-4. なぜ大半の会社は途中から始めるのか

事前学習が総コストの 95% 以上を占めるため、公開 base モデル (無料) をもらってきて SFT/DPO/量子化だけを行うのが業界の標準戦略です。この講義の実習も同じ構造です。level04 でミニ base モデルを一度作ってみた後、それ以降のレベルはすべてその上に載せる工程です。

| 工程 | データ規模 | コストの桁 |
|---|---|---|
| 事前学習 | 数兆トークン | 数億〜数千億ウォン |
| アニーリング | 数百億トークン | 数百万〜数千万ウォン |
| SFT | 数万〜数十万件 | 数万〜数百万ウォン |
| DPO | 数万ペア | 数万〜数百万ウォン |
| 量子化 | 学習なし | 数千〜数万ウォン |

## 4. 実習 — main.py

実行方法は次の通りです。

```bash
cd lecture12_llm_engineering_mlops/level00_the_big_picture
python3 main.py
```

プログラムは、仮想の 7B モデルが工場ラインの 6 工程を通過する過程をシミュレーションします。`[1]`〜`[6]` の各段階で **たとえ・入力・出力** をまず示し、学習段階であれば `train_cost()` 関数が 6 × N × D の公式で FLOPs → GPU 時間 → ドルを順に換算して出力します。loss 値が段階ごとに少しずつ下がっていく様子も真似します (シード固定)。実測では事前学習で 10.51 → 2.36 と大きく落ち、以降の工程は 2.11 → 1.89、1.89 → 1.23、1.20 → 1.08 とわずかしか動きません。これが実際の学習ログの典型的な形です。

数値の実測値も押さえておきましょう。事前学習は 8.40e+22 FLOPs = 58,923 GPU 時間 (H200 を 512 枚並べて約 4.8 日)、コストは $206,229 (約 2.9 億ウォン)。対して SFT は 1.8 GPU 時間、$6 (約 1 万ウォン) です。

最後の `[7]` のまとめで、総制作費 $211,406 (約 3.0 億ウォン) のうち事前学習が **97.6%** を占めることを確認してください。コードで注目すべき箇所は 3 つです。冒頭の仕様定数 (PARAMS、PRETRAIN_TOKENS など) は皆さんが動かして実験するハンドルであり、`train_cost()` はこの講義を通じて何度も使い回すコスト近似式であり、stages リストはこの講義全体の目次そのものです。

## 6. よくある間違い

- **「ファインチューニング = モデル制作」と混同する**: ニュースで「自社モデルを開発」という表現を見たら、どの工程から手をつけたのかを確かめましょう。大半は SFT 以降だけを行ったものです。
- **コストを工程の区別なしにひとまとめにする**: 「LLM の学習は数百億」という話は事前学習にだけ当てはまります。後工程はノートパソコン級の予算でも可能です。
- **量子化を学習の一種だと誤解する**: 量子化は作り終えたモデルの数値表現だけを変える変換作業です。新しく学ぶことがないので数時間で終わります。
- **デプロイを「完成」だと考える**: デプロイした瞬間から、コスト構造が固定費から使用量比例の運用費に変わります。見積書にサービング費用の行が抜けていたら、その見積もりは未完成です。
