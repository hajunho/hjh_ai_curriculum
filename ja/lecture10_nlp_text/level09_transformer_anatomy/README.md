# Lecture 10 · Level 09 — トランスフォーマー構造の解剖

> マルチヘッドアテンション・位置エンコーディング・残差接続・レイヤーノルムを numpy で作り、ブロックを 1 個組み立てます。
**難易度** ⭐⭐⭐⭐ / **前提** level08 / **想定時間** 60分

## 1. なぜ学ぶのか — ビジネスの視点

GPT、Claude、Gemini、翻訳機、コードアシスタント — 名前は違っても中身はすべて
トランスフォーマー (Transformer) です。2017 年に提案されたこの構造 1 つが 10 年来の
AI の標準設計図であり、「パラメータ数」「レイヤー数」「コンテキスト長」といったニュースの
スペック競争は、すべてこの設計図の部品数の話です。

部品を知れば会話が変わります。「うちのサービスに 7B モデルで足りるのか?」
「コンテキスト 128k のモデルに乗り換える価値はあるか?」といった意思決定の会議で、
トランスフォーマーの構造を知っている人は、スペックの数字がコスト・速度・品質にどう
つながるかを推論できます。このレベルはその設計図を部品単位に分解して、自分で作ってみる
時間です。学習はしません — 構造とデータの流れ (shape) だけに集中します。

## 2. たとえ話で理解する

トランスフォーマーブロックは **会議 → 整理の繰り返しで回るタスクフォース (TF) チーム** です。
トークン 1 つ 1 つがチームメンバーで、各メンバーは自分の担当情報 (ベクトル) を持っています。

1. **全体会議 (マルチヘッドアテンション)**: メンバーが互いの情報を参照して自分の考えを
   更新します。会議は 1 回ではなく **複数の分科会に分かれて同時に** 行います —
   予算分科会、日程分科会、リスク分科会が別々に集まり、それぞれの観点で議論してから
   結果を合わせます。これがマルチヘッド (multi-head) です。
2. **個人の整理時間 (フィードフォワード)**: 会議が終わると各自の席に戻り、聞いたことを
   自分のやり方で消化します。隣と相談せず、全メンバーが同じ整理のコツ (同じ重み) を使います。
3. **原本の保存 (残差接続)**: 議事録だけ残すと元の自分の意見が消えかねないので、
   「元の意見 + 会議で得たもの」を足して持ち歩きます。
4. **コンディション管理 (レイヤーノルム)**: 会議を重ねると、過熱するメンバーも
   黙り込むメンバーも出てきます。毎ステップの後に発言のトーンを標準の範囲に揃えます。

この「会議+整理」のセットがブロック 1 個で、トランスフォーマーはこのブロックを
数十回積み上げたものです。

## 3. 核心となる概念

### 3-1. 位置エンコーディング — 順序の感覚を取り戻す

アテンションはすべてのトークンを同時に見るので、**順序を知りません**。「会社が顧客を」と
「顧客が会社を」が同じ集合になってしまいます。そこで入力の埋め込みに **座席番号札** を
足します。元祖トランスフォーマーはサイン/コサインの波を使います:

$$PE_{(pos, 2i)} = \sin(pos / 10000^{2i/d}), \quad PE_{(pos, 2i+1)} = \cos(\cdot)$$

周波数の違う波を何本も重ねると、すべての位置が固有のパターンを持ち、位置間の
相対的な距離もベクトル演算で表現できます。数を 2 進数で数えると桁ごとに 0/1 が
違う周期で切り替わるのと同じ原理です。(最新のモデルは RoPE などの変形を
使いますが、「位置情報を注入する」という目的は同じです。)

### 3-2. マルチヘッドアテンション — 観点を分けて見る

1 回のアテンションは 1 種類の関係しか見られません。埋め込みをヘッド数に分割して
(例: 32 次元 → 8 次元 × 4 ヘッド)、各断片で独立にアテンションしてからつなぎ合わせると、
あるヘッドは「修飾関係」、あるヘッドは「主語-動詞関係」のように、互いに異なるパターンを
捉えられます。計算量はひと塊のアテンションとほぼ同じまま表現力が増える設計です。

### 3-3. 残差接続とレイヤーノルム — 深く積むための安全装置

- **残差接続 (residual connection)**: 出力 = 入力 + 部品(入力)。部品がまだ
  学習不足でも入力がそのまま通り抜ける近道があるので、数十層を積んでも学習
  シグナルが下の層まで届きます。lecture09 (CNN) で見たのと同じアイデアです。
- **レイヤー正規化 (layer normalization)**: 各トークンのベクトルを平均 0、分散 1 に
  揃えてから、学習可能な倍率・シフトを適用します。層を経るうちに値が暴走したり
  消滅したりするのを防ぎます。

### 3-4. エンコーダ vs デコーダ

- **エンコーダ (encoder)**: 文全体を **双方向** に見ます。理解が目的 —
  分類、検索、穴埋め (BERT 系)。
- **デコーダ (decoder)**: 各トークンが **自分より前だけ** を見るよう因果マスクをかけます。
  次のトークンの生成が目的 — GPT 系。後ろを見たら正解をカンニングすることになりますから。

部品は同じで、マスク 1 枚が運命を分けます。level10 で私たちはデコーダを
作って学習させ、level11 で 2 つの陣営の哲学を比較します。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

文 1 つ (トークン 6 個「昨日 学生 が 報告書 を 作った」、32 次元) をトランスフォーマー
ブロックに通しながら、**すべての部品の入出力 shape と役割** を出力します。学習はなく、
seed 固定の乱数重みを使います — 今日の主役は数値ではなく構造です。

- **[1] 位置エンコーディング**: サイン/コサインの表を作り、「同じ単語でも座席が
  違えば入力が変わる」ことを数値で確認します (実測: 位置 0 と 3 の入力差のノルム 2.73)。
- **[2] マルチヘッドアテンション**: 32 次元を 4 ヘッド×8 次元に分割し、各ヘッドの重み
  行列の shape (4, 6, 6) を出力し、ヘッドごとに注目パターンが違うことを見せます
  (実測: 「学生」トークンの最注目先はヘッド0=「昨日」、ヘッド1=「学生」)。
- **[3] 残差+レイヤーノルム**: 部品を通す前後のベクトルの大きさ (標準偏差) を出力して、
  正規化が値の暴走をどう防ぐかを確認します。
- **[4] フィードフォワード**: 拡張 (32→64) → 活性化 → 縮小 (64→32) の shape の流れを出力します。
- **[5] ブロックの組み立て・積層**: 部品を順につないだブロックを 2 回通して
  「ブロックを積む」の意味を確認し、パラメータ数 (ブロック 1 個 8,192 個) を集計します。
- **[6] エンコーダ vs デコーダ**: 同じ入力に因果マスクをオン/オフしたアテンション重みを
  並べて出力し、下三角の構造を目で確認します。

## 5. やってみよう

1. **(かんたん)** ヘッド数を 4 から 2 へ、8 へ変えてみましょう。全体のパラメータ数が
   変わらない理由を [2] の shape 出力から探してみましょう。
2. **(ふつう)** [1] で位置エンコーディングを足す行をコメントアウトすると、トークンの
   順序をシャッフルしてもアテンション重みの集合が同じになることを確認してみましょう。
3. **(チャレンジ)** ブロックからレイヤーノルムを外して 10 回繰り返し通し、出力の
   標準偏差を記録してみましょう。値がだんだん大きく (または小さく) なるのが観察できたら、
   なぜ深いモデルに正規化が必須なのかを身をもって理解したことになります。

## 6. よくある間違い

- **shape を見ずにコードだけ読む**: トランスフォーマー理解の王道は、各ステップの
  テンソル shape の追跡です。(トークン数, 次元) がどこでどう変わるか紙に描いてみましょう。
- **マルチヘッド = アテンションの複数回の繰り返しと誤解**: 繰り返しではなく、次元を
  分割して並列に見るのです。だから計算量はヘッド数分は増えません。
- **位置エンコーディングを飾り扱い**: これがなければトランスフォーマーは語順を
  まったく知りません。「単語集合モデル」に退化します。
- **エンコーダ/デコーダを別々の技術として暗記**: 同じ部品、マスクの違いです。構造では
  なく「何を見ることを許すか」の違いとして覚えましょう。
