# Lecture 10 · Level 07 — RNN とシーケンスモデル

> 順序を記憶しながら読むニューラルネット (RNN) で、次の文字を予測するミニ言語モデルを学習させます。
**難易度** ⭐⭐⭐⭐ / **前提** level06、lecture08 (ディープラーニング基礎) / **想定時間** 55分

## 1. なぜ学ぶのか — ビジネスの視点

ここまでの道具 (BoW、TF-IDF、埋め込み) は、単語を **袋にざっと空けて** 数えていました。
ところが言語の半分は順序です。「会社が顧客企業を買収した」と「顧客企業が会社を
買収した」は、単語の構成が同じでも意味が正反対です。順序を扱えなければ契約書の
解釈も、文章生成も、翻訳も不可能です。

RNN (再帰型ニューラルネットワーク、Recurrent Neural Network) は、順序を扱う最初の
本格的なニューラルネットです。チャットボットの自動補完、音声認識、機械翻訳の
初期の全盛期を牽引し、いまはトランスフォーマーに王座を譲りましたが — 「ここまでに
読んだ内容を状態に要約して持ち歩く」という中核アイデアとその限界 (長期依存性) を
理解してこそ、トランスフォーマーが **何を解決したのか** が分かります。このレベルは
その架け橋です。

## 2. たとえ話で理解する

RNN は **リレーメモと一緒に文書を読む社員たち** です。文書が長すぎるので、
社員 1 人が 1 単語ずつだけ読むことにしたとしましょう。1 番の社員が最初の単語を読み、
ここまでの要約を **メモ 1 枚** に書いて 2 番に渡します。2 番はそのメモと
2 番目の単語を見てメモを更新し、3 番に渡し... 最後の社員のメモが
文書全体の要約になります。

この構造の強み: 文書がどれだけ長くても、社員は「メモ + 単語 1 つ」だけ処理すれば
済みます。弱点もメモにあります。メモ用紙は大きさが決まっているので (固定サイズの
隠れ状態)、文書の前の方の内容はリレーを経るうちにだんだん薄れます。100 番目の社員の
メモに、1 番の社員が書いた内容はどれだけ残っているでしょうか? これが **長期依存性
(long-term dependency) 問題** です。

## 3. 核心となる概念

### 3-1. 再帰構造 — 数式は 1 行

RNN の本体は驚くほど単純です。時点 $t$ で:

$$h_t = \tanh(W_x x_t + W_h h_{t-1} + b)$$

$x_t$ はいま読んでいるトークン (の埋め込み)、$h_{t-1}$ は直前までのメモ (隠れ状態、
hidden state)、$h_t$ は更新されたメモです。同じ重み $W$ をすべての時点で
再利用するのがポイントです — 社員が 100 人いても「メモの更新のコツ」は 1 つです。

### 3-2. 言語モデル — 「次に来るもの」を当てるゲーム

言語モデル (language model) は「ここまでの文章を見て次のトークンを予測」する
モデルです。「今日のお昼はカレーライ___」の次に「ス」が来る確率が高いと知っていること。
この単純なゲームが重要なのは、うまくやるには文法・語彙・常識のすべてが必要だからです。
GPT の G (Generative) はまさにこのゲームのチャンピオンだという意味で、
今日は文字単位の超ミニ版を作ります。

学習方法: 「昨日 学生が」という文があれば、入力「昨日 学生」に対して正解
「日 学生が」(1 文字ずらしたもの) を当てさせます。時点ごとに次の文字を当てる
分類問題になるので、lecture08 で学んだ交差エントロピー損失で学習します。

### 3-3. 長期依存性 — リレーメモの限界

「私が昨日デパートで買った、青い箱に入った、スイス製の___」の空欄を当てるには、
文の先頭の情報が必要なことがあります。RNN は逆伝播のとき勾配が時点の数だけ
掛け算されて **消失 (vanishing)** し、遠い過去へ学習シグナルがほとんど届きません。
これを緩和した改良型が LSTM/GRU (ゲートでメモを選択的に保存) で、
根本的に解決したのが「すべての時点を直接つなぐ」アテンション (level08) です。

### 3-4. 生成 — 温度 (temperature) というダイヤル

学習済みの言語モデルで文章を作るときは、予測の確率分布から次の文字を引き、それを
また入力にくっつけて繰り返します。このとき分布をどれだけ「尖らせて」使うかを調節する
ダイヤルが温度です。低いと確率の高い文字ばかり引いて安全で単調な文章に、
高いと多彩だが突拍子もない文章になります。LLM API の temperature パラメータが
まさにこれです。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

tiny_corpus の一部 (約 2 万文字) で文字単位の RNN 言語モデルを学習します。
CPU で数秒で終わるよう小さく設計してあります。

- **[1] データ準備**: 文字の辞書を作り (実測: 文字語彙 52 種)、テキストを整数の
  シーケンスに変えます。「入力を 1 文字ずらしたものが正解」という学習ペアの構成を
  出力します (学習シーケンス 499 個)。
- **[2] モデルの組み立て**: 埋め込み → `nn.RNN` → 出力層。パラメータ数は 11,316 個です。
- **[3] 学習**: 学習前 (でたらめな文字の羅列) と学習後の生成文を比較します。
  loss が 3.57 → 0.62 → 0.37 と下がるにつれ、生成文が「言葉になっていく」過程を
  3 段階で見せます。実測の最終生成例:
  「昨日 学生が 計画書を 確認した。 夕方に 料理人が 手紙を 整理した。…」
- **[4] 次の文字の予測確認**: 「学生が 報告書を 作」の後に来る文字の確率
  上位 3 個を出力します — 実測では「っ」が 96% で 1 位に上がります。
  「カレーライ」の次は「ス」(98%)。
- **[5] 温度の実験**: 温度 0.3/1.5 の生成文を比較し、リレーメモ構造が持つ
  長期依存性の限界を整理するメモで締めくくります。実測では温度 0.3 は整った文を
  繰り返し、温度 1.5 は「告書に 会社。が 整理を。」のような崩れた文を混ぜてきます。

## 6. よくある間違い

- **文字/トークン辞書の不一致**: 学習時の文字→番号の辞書を、生成時もそのまま
  使わなければなりません。辞書を作り直すと番号が入れ替わり、意味不明な出力になります。
- **生成が変だとすぐモデルのせいにする**: 温度、プロンプト、学習量から点検しましょう。
  このミニモデルはデータが小さいので、完璧な文章を期待してはいけません — 「構造が
  できていくか」を見る実験です。
- **hidden state の初期化忘れ**: 別々の文を続けて学習するとき状態を切らないと、
  前の文の記憶が新しい文に染み込みます。
- **RNN をいま実戦投入する**: 2026 年現在、シーケンス実務のデフォルトは
  トランスフォーマーです。RNN は「なぜトランスフォーマーなのか」を理解するために学びます。

## 次のレベルの予告

どうだろう? numpy でアテンションを実装し、重みのヒートマップを描いてみます。
