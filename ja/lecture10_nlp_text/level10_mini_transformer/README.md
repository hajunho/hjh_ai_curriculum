# Lecture 10 · Level 10 — ミニトランスフォーマーを自作する

> torch で小型デコーダ (GPT 構造) を作って次のトークン予測を学習させ、生成の変化を観察します。
**難易度** ⭐⭐⭐⭐⭐ / **前提** level07, level09 / **想定時間** 70分

## 1. なぜ学ぶのか — ビジネスの視点

「GPT を自分で作ってみた」という経験は、LLM を見る目を根本から変えます。
もちろん今日作るのはパラメータ十万個ほどのおもちゃで、商用 LLM は数千億
個です。しかし **構造は同じ** です。埋め込み → デコーダブロックの積層 → 次のトークンの
確率。違うのはスケールだけです。

自分で作ってみると、こういうことが当たり前になります: LLM がなぜ一度に 1 トークンずつ
生成するのか (だから応答がストリーミングされるのか)、なぜ学習に GPU が必要なのか、
「ハルシネーション」がなぜバグではなく確率的生成の本質なのか、ファインチューニングが
何を変えるものなのか。経営会議で「LLM は所詮、次の単語当てマシン」という言葉の正確な
意味を知っている人になれます。

## 2. たとえ話で理解する

level09 までが **自動車部品の勉強** だったとすれば、今日は **組み立ててエンジンをかけ、
路上を走る** 日です。部品 (アテンション、FF、残差、レイヤーノルム) はもう全部作りました。
今日新しくやることは 3 つだけです。

1. **部品を torch で組み立てる**: numpy 版と違って自動微分が効くので、学習が
   可能になります。
2. **運転の練習 (学習)**: tiny_corpus を見せながら「次のトークン当て」を何百回も
   繰り返させます。間違えるたびに逆伝播で全部品を少しずつ調整します。
3. **走行試験 (生成)**: 学習の前・途中・後に同じプロンプトで文を生成させ、
   支離滅裂 → それらしい文へと変わっていく過程を見ます。

学習という運転練習の目標は単純です — コース (コーパス) を何周も回って
「この状況の次はこの行動」を体に刻むこと。LLM の事前学習 (pre-training) の
縮小版です。

## 3. 核心となる概念

### 3-1. GPT 構造 = デコーダだけを積んだトランスフォーマー

元祖トランスフォーマーは翻訳用だったのでエンコーダ+デコーダでしたが、GPT は **デコーダだけ** を使います。

```
トークン ID → トークン埋め込み + 位置埋め込み
       → [デコーダブロック: 因果マスク付きアテンション → FF (+残差/ノルム)] × N層
       → 最終レイヤーノルム → 線形層 → 語彙数ぶんのスコア (logits)
```

最後の線形層の出力が「次のトークンが語彙の各候補である点数」で、softmax を
通すと確率になります。今日のモデルは 2 層、64 次元、4 ヘッド — 全パラメータ約
11 万個の超小型です。

### 3-2. 並列学習の魔法 — 1 つの文で数十個の問題を同時に

RNN は文字を順番に処理するしかありませんでしたが、トランスフォーマーは因果マスクの
おかげでシーケンスの **すべての位置を同時に** 学習できます。長さ 32 のシーケンス
1 本が「1 文字目まで見て 2 文字目を当てる」「2 文字目まで見て 3 文字目を当てる」...
という 32 個の問題を 1 回の順伝播でまとめて解きます。この並列性がトランスフォーマーが
RNN を押しのけた実質的な理由の 1 つです — GPU を目いっぱい使えるからです。

### 3-3. loss が下がる = 驚きが減る

交差エントロピー損失は「正解トークンに与えた確率が低いほど」大きくなります。学習の
初期は、語彙が $V$ 種なら損失はだいたい $\ln V$ (どれかを適当に選ぶ水準) 付近から
始まります。損失が下がるということは、モデルが次のトークンに驚かなくなるということです。
言語モデルの評価指標であるパープレキシティ (perplexity) は $e^{loss}$ で、
「毎瞬間、何個の候補の間で迷っているか」と読めます。この数字が出力に一緒に印字されます。

### 3-4. 生成品質の段階

小さなモデルが学習されるにつれ、生成文はおよそこんな段階を踏みます。

1. でたらめな文字の羅列 (学習前)
2. 文字統計の模倣 — 頻出文字・短いパターンの登場
3. 文節の骨格 — 「○○が ○○を ○○た。」の文型が定着
4. それらしい文 — コーパスの文型の再組み合わせ

商用 LLM は、ここに何万倍ものデータ・モデル・計算を注いで第 5 段階 (知識・推論) まで
行ったものです。スケールが段階を作る — これが次のレベル (事前学習パラダイム) の
テーマです。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

tiny_corpus の 3 万文字で文字単位のミニ GPT を学習します。CPU で 60 秒以内に
終わるよう設計してあります (筆者環境で約 6 秒)。

- **[1] データ**: 文字辞書 (実測: 52 種) と (入力, 1 文字ずらした正解) のバッチ構成を出力します。
- **[2] モデル**: 埋め込み 64 次元、2 層、4 ヘッドのデコーダ。パラメータ数は 108,852 個です。
  アテンション・ブロックは level09 の部品の torch 版なので、コードに見覚えがあるはずです。
- **[3] 学習**: 400 ステップの間、loss とパープレキシティを定期的に出力し、3 つの時点
  (初期/中間/最終) で同じプロンプト (「昨日 」) の生成文を出力します。
  実測: loss は初期 ~3.95 (ln 52) から step 50 で 0.550 (PPL 1.7)、step 400 で
  0.351 (PPL 1.4) まで下降。最終生成例:
  「昨日 先生が 計画書を 確認した。 今日 会社員が 手紙を 整理した。…」
  loss の下降曲線は `outputs/loss_curve.png` に保存します。
- **[4] 生成テスト**: 学習済みモデルでプロンプト 3 種の書き継ぎを実演します。
  実測: 「週末に 料理人が 」→「週末に 料理人が 報告書を 確認した。 今日 会社員が
  プログラムを 作った。…」のように、文型が完全に定着した文が出ます。
- **[5] アテンションをのぞく**: 1 層目のヘッドのアテンションパターンが因果 (下三角)
  構造になっていることを確認出力します。

## 6. よくある間違い

- **小さなモデルの生成文に失望する**: 今日の目標は ChatGPT ではなく、「構造が
  学習される様子」の観察です。文型が定着すれば大成功です。
- **loss 0 を目標にする**: 言語には本質的な不確実性があるので loss は 0 になりませんし、
  なってもいけません (完全な暗記 = 過学習)。
- **コンテキスト長 (BLOCK) と生成の長さの混同**: モデルは直近 BLOCK 文字までしか
  見ません。それより長く生成すると前の方を忘れるのが正常です。
- **マスクのバグを性能向上と勘違い**: チャレンジ課題 3 のように、未来が見えると
  loss は良く見えても生成能力はありません。指標が良ければ全部良い、ではないのです。
