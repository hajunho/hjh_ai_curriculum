# Lecture 10 · Level 04 — BoW と TF-IDF

> テキストを数値ベクトルに変える標準技法を numpy で自作し、sklearn と突き合わせて検証します。
**難易度** ⭐⭐⭐ / **前提** level03、lecture03 (NumPy) / **想定時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

機械学習モデルは数値しか食べません。だからテキスト分析の関門は常に
「文書をどうやって数値ベクトルに変えるか」です。BoW と TF-IDF はこの変換の
数十年来の標準であり、いまも次のような業務の基本技として現役です。

- **文書検索**: クエリに最も近い文書を探す (TF-IDF 類似度)
- **キーワード抽出**: 「この文書を代表する単語」を自動で抜き出してタグを付ける
- **分類の入力**: 次のレベルの感情分析は、まさに TF-IDF ベクトルを入力に使います

埋め込みと LLM の時代になっても TF-IDF は死んでいません。軽くて、速くて、結果の
説明がしやすいので、「まず TF-IDF でベースライン (baseline) を作る」のが実務の
定石です。

## 2. たとえ話で理解する

**BoW (Bag of Words、単語の袋)** は、文書をすりつぶして袋に入れることです。
文の順序は捨てて、「どの単語が何回出たか」だけを数えます。文書がミキサーにかけた
ジュースだとすれば、BoW は成分表です: 配送 2 回、速い 1 回、満足 1 回...
順序を捨てたのに、成分表だけでも「このジュースが何からできているか」は案外分かります。

**TF-IDF** は、成分表に **希少価値** を掛けることです。履歴書を思い浮かべてください。
「真面目です」は全応募者が書くので判別力がなく、「半導体の歩留まり改善の経験」は
少数しか書けないのでその人を特徴づけます。TF-IDF はまさにこの直観です:

- **TF** (単語頻度): この文書にたくさん出るほど重要で、
- **IDF** (逆文書頻度): 他の文書にもありふれていれば価値を割り引く。

「たくさん出てくる (TF↑) のに、他ではあまり使われない (IDF↑) 単語」がその文書のキーワードです。

## 3. 核心となる概念

### 3-1. BoW — 文書-単語行列

文書 3 個、語彙 5 個なら 3×5 の行列を作ります。行が文書、列が単語、
マスの値が出現回数です。

| | 配送 | 迅速 | 梱包 | 価格 | 満足 |
|---|---|---|---|---|---|
| 文書1 | 2 | 1 | 0 | 0 | 1 |
| 文書2 | 0 | 0 | 1 | 2 | 1 |

この行列の 1 行が、そのままその文書のベクトルです。ほとんどのマスが 0 の
疎 (sparse) 行列になるのが特徴です。語彙が 1 万語なら文書 1 つが
1 万次元のベクトルになりますが、実際に登場する単語は数十個だけですから。

なお、日本語は分かち書きをしないので、「何を単語と数えるか」を先に決める必要が
あります。この実習では level03 で学んだ文字 2-gram を採用しています。

### 3-2. TF-IDF の式 — 今回だけ数式で

単語 $t$、文書 $d$、全文書数 $N$、単語 $t$ が現れた文書数 $df(t)$ のとき:

$$\text{tfidf}(t, d) = tf(t, d) \times \log\frac{1 + N}{1 + df(t)} + 1 \text{ 方式などの変形が複数}$$

核心は $\log$ の中の分数です。すべての文書に出る単語は $df = N$ なので
対数が 0 に近づいてスコアが割り引かれ、1 つの文書にしか出ない単語は対数が大きく
なってスコアが上がります。対数を使うのは、文書数が 10 倍になったときに重みが 10 倍に
なるのではなく、なだらかに増えるようにするためです。

注意: 教科書やライブラリごとに細部の式が少しずつ違います。sklearn の基本形は
「スムージング (+1)」と「L2 正規化」がオンになっているので、自作実装と比較するには
同じ変形を使う必要があります。main.py ではまさにこの形を再現して一致を確認します。

### 3-3. L2 正規化 — 長い文書の反則防止

長い文書はすべての単語の TF が大きいため、ベクトルが丸ごと大きくなります。文書の
長さではなく内容で比較するために、各文書ベクトルの長さを 1 に揃えます (L2 正規化)。
正規化したベクトル同士の内積がそのままコサイン類似度 (cosine similarity) になり、
「2 つの文書がどれくらい似た話題か」を 0〜1 の数値で測れます。

### 3-4. BoW の限界 — 順序を捨てた代償

「品質が良い」と「品質が良いとは言えない」は、BoW の世界ではかなり近いベクトルです
(数トークンの差)。語順・文脈・否定を扱えないこの限界が、level06 の埋め込みと
level07 以降のシーケンスモデルが登場する理由です。道具の限界を知って使えば、
道具は依然として優秀です。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

- **[1] BoW を手作業で**: ミニ文書 3 件 (形態素解析済みを想定した空白区切り) で
  語彙辞書と文書-単語行列を numpy で作り、表として出力します。疎性 (0 の割合 60%) も
  確認します。
- **[2] TF-IDF の自作実装**: sklearn の基本形と同じ式 (スムージング IDF + L2
  正規化) を numpy で実装します。コードは 10 行あまりがすべてです。
- **[3] sklearn との突き合わせ検証**: 同じデータと同じトークナイザーを
  `TfidfVectorizer(analyzer=tokenize)` に渡し、2 つの行列の最大誤差を出力します。
  実測は `1.11e-16` で一致 — 「ライブラリの中で何が起きているか」を検証で証明する瞬間です
  (文書 80 件、語彙 226 種)。
- **[4] SAMPLE_DOCS のキーワード抽出**: 社内規定・製品マニュアル 5 件から文書ごとの
  TF-IDF 上位 5 トークンを抽出します。実測では休暇の文書に「休暇 (0.26)」「年次 (0.26)」、
  経費の文書に「出張 (0.46)」「経費 (0.19)」、保証の文書に「保証 (0.38)」が上がる一方、
  「暇は」「張が」のような単語境界をまたぐ 2-gram ノイズも混ざります —
  文字 n-gram 方式の限界がそのまま見える、正直な結果です。
- **[5] 文書類似度**: コサイン類似度行列を出力します。最も似ているペアは
  休暇 <-> 経費 (0.15) で、全体的に類似度は低め。文書同士で重なる単語自体が
  少ないからです。「文字が同じでなければ似ていると認めない」TF-IDF の本質的な限界が
  現れる場面であり、level06 の埋め込みが必要な理由でもあります。

## 6. よくある間違い

- **正規化を忘れて類似度計算**: 正規化なしで内積を取ると、長い文書が無条件で類似度
  1 位になります。
- **自作実装とライブラリの式が違うのを「バグ」と誤解**: TF-IDF には変形が
  たくさんあります。比較するときは公式ドキュメントで正確な式を確認しましょう。
- **学習データで作った語彙辞書を新しいデータで作り直す**: 語彙辞書と IDF は
  学習時点で固定し、新しい文書にはそのまま適用します。毎回作り直すと
  ベクトルの次元が変わってモデルが壊れます。
- **ストップワード処理なしでキーワード抽出**: 「います」「ます」由来の断片が上位を
  覆います。level01 の前処理は、ここでも前提条件です。
