# Lecture 10 · Level 02 — 正規表現

> パターン 1 つで文書の山から電話番号・メール・金額を自動抽出する「検索条件式」を学びます。
**難易度** ⭐⭐ / **前提** level01 / **想定時間** 40分

## 1. なぜ学ぶのか — ビジネスの視点

「この契約書 30 件から、契約金額と担当者の連絡先だけ抜き出して Excel にまとめて」。
こういう仕事を手作業でやると半日、正規表現 (regular expression) でやると
5 分です。正規表現は「電話番号らしい見た目のもの」「金額らしい見た目のもの」を 1 行の
パターンで表現し、コンピュータに代わりに探させる技術です。

NLP パイプラインの中でも出番は多く、level01 の URL 除去はすでに正規表現でしたし、
個人情報のマスキング (電話番号を 090-****-**** に)、日付の標準化、ログのパースまで —
テキストを扱う場所ならどこにでも登場します。Excel の検索/置換が懐中電灯なら、
正規表現はサーチライトです。

## 2. たとえ話で理解する

正規表現は **不動産の検索条件式** のようなものです。「駅近 & 2 部屋以上 & 家賃
8 万円以下」と条件をかければ数千件の物件から条件に合うものだけが絞り込まれるように、
正規表現は「数字 2〜3 個 - 数字 3〜4 個 - 数字 4 個」という条件をかけて、テキストから
電話番号だけを絞り込みます。

条件式を構成する部品は 3 種類しかありません。

- **何を**: どの文字を探すか — `\d` (数字)、`[一-龯]` (漢字)、`.` (任意の 1 文字)
- **いくつ**: 何回繰り返すか — `+` (1 個以上)、`*` (0 個以上)、`{3}` (ちょうど 3 個)
- **どこで**: 位置の条件 — `^` (行頭)、`$` (行末)、`\b` (単語境界)

この 3 つの部品の組み合わせがすべてです。複雑に見えるパターンも、分解すれば
「何を・いくつ・どこで」の並びです。

## 3. 核心となる概念

### 3-1. 基本文法のミニ表

| パターン | 意味 | 例 |
|---|---|---|
| `\d` | 数字 1 個 | `\d\d\d` = 数字 3 個 |
| `\d{2,3}` | 数字 2〜3 個 | 03 または 052 |
| `[一-龯]+` | 漢字 1 文字以上 | 「田中誠」 |
| `a|b` | a または b | `円|ドル` |
| `?` | あってもなくてもよい | `-?` = ハイフンは任意 |
| `( )` | グループ化・部分抽出 | `(\d+)円` で数字だけ |
| `\.` | ピリオドそのもの | `.` は特殊文字なので `\` が必要 |

### 3-2. 実務の 3 大パターン — 電話番号・メール・金額

**電話番号**: `0\d{1,2}-?\d{3,4}-?\d{4}`
— 0 で始まる固定/携帯番号、ハイフンはあってもなくてもマッチ。

**メール**: `[\w.]+@[\w.-]+\.[a-z]{2,}`
— @ の前に英数字とドット、後ろにドメインとトップレベルドメイン (2 文字以上)。
(参考: メール形式の国際標準を 100% カバーする正規表現は長すぎるので、
実務ではこの程度の「十分に良い」パターンを使います。)

**金額**: `\d{1,3}(?:,\d{3})+円?|\d+万\s?円|\d+円`
— 「1,200,000円」「350万円」「9900円」のような複数の表記を `|` でつなぎます。
日本語の金額は表記が多様なので、パターンも枝分かれが必要です。

### 3-3. Python re モジュールの 4 つの動詞

| 関数 | すること | いつ使うか |
|---|---|---|
| `re.search(p, s)` | 最初のマッチ 1 個を探す | 存在確認 |
| `re.findall(p, s)` | すべてのマッチをリストで | 一括抽出 |
| `re.sub(p, r, s)` | マッチを置換 | マスキング・整形 |
| `re.compile(p)` | パターンの再利用準備 | 繰り返し使うとき |

グループ `( )` を使うと `findall` はグループの内側だけを返します。「全体をマッチさせつつ
抽出は一部だけ」というときに便利で、グループは使うが抽出からは外したいときは
`(?: )` (非キャプチャグループ) を使います。

### 3-4. 貪欲 (greedy) マッチング — 正規表現最大の罠

`*` と `+` は基本的に **できるだけ長く** つかみます。`"<田中> <佐藤>"` に対して
`<.*>` は `<田中>` ではなく文字列全体 `<田中> <佐藤>` をつかみます。
「できるだけ短く」が欲しければ `<.*?>` のように `?` を付けます (控えめマッチング)。
置換結果が不自然に塊ごと消えていたら、十中八九、貪欲マッチングが原因です。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

架空の社内文書 (発注確認メール、取引先連絡網、精算のお知らせ — コード内で直接
書き下ろした創作テキスト) を材料に、4 つの実習をします。

- **[1] 文法ウォーミングアップ**: `\d+`、`[一-龯]+`、`{n}` 繰り返しなどの基本部品を
  短い例文で 1 つずつ確認します。各パターンが何を捕まえたかを並べて出力します。
  漢字の塊だけを拾うと「日出荷」のようにくっつくことも見えて、正規表現の限界の予告になります。
- **[2] 情報抽出**: 文書 3 件から電話番号・メール・金額を `findall` で一括
  抽出し、文書ごとに整理して出力します。手で拾っていた作業が数行で終わります。
- **[3] 個人情報マスキング**: `re.sub` とグループ参照で電話番号の真ん中の桁を
  `****` に変えます (実測: 3 件マスキング)。公開資料を作るとき、そのまま使える実務パターンです。
- **[4] 貪欲マッチング事故の再現**: `<.*>` と `<.*?>` の結果を比較して、貪欲マッチングが
  どうやってデータを塊ごと飲み込むかを目で確認します。

コードで注目してほしいのは `PATTERNS` 辞書です。パターンを名前付きで 1 か所に
まとめておくと、後で「金額パターンだけ直す」といったメンテナンスが楽になります。

## 6. よくある間違い

- **`.` `+` `?` を文字そのものとして探そうとして失敗**: 特殊文字を探すときは `\.` のように
  エスケープするか、`re.escape()` を使いましょう。
- **貪欲マッチングの放置**: `".*"` で置換したら文の半分が消えた、という事故。
  短くつかみたいなら `.*?`。
- **パターンの過剰設計**: 世の中のあらゆる電話番号形式を 1 つのパターンに詰め込もうとして、
  誰も読めないパターンになります。「自分たちのデータに実際に現れる形式」だけをカバーし、
  例外はログに残して後から追加する方が得策です。
- **文字範囲の誤解**: `[一-龯]` は漢字だけ、`[ぁ-ん]` はひらがなだけです。「ｗｗ」のような
  半角カナ・記号は範囲外なので、必要なら NFKC 正規化 (level01) を先に通しましょう。

## 次のレベルの予告
