# Lecture 10 · Level 05 — テキスト分類の実習: レビューの感情分析

> TF-IDF + ロジスティック回帰で感情分析器を作り、モデルが根拠にしたトークンを係数から解釈します。
**難易度** ⭐⭐⭐ / **前提** level04、lecture06 (ロジスティック回帰) / **想定時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

「今回のキャンペーンの後、お客様の反応はどう?」という質問に、レビュー 3,000 件を
1 件ずつ読むわけにはいきません。感情分析 (sentiment analysis) はレビューをポジティブ/
ネガティブに自動分類し、「ポジティブ比率の推移」「ネガティブレビューの主要因の単語」を
ダッシュボードにできるようにしてくれます。VOC 分析、ブランドモニタリング、CS チケットの
優先順位付け — テキスト分類は、企業で最もよく使われる NLP の応用です。

このレベルのもう 1 つの目標は **説明可能性** です。「モデルが 87% 当てます」では
報告が終わりません。「なぜこのレビューをネガティブと見たのか?」に答えられて初めて、
現場が結果を信頼します。ロジスティック回帰はトークンごとの係数を開いて見られるので、
この問いに正確に答えられる、実務で愛される出発点です。

## 2. たとえ話で理解する

感情分析器は **採点基準表を持った添削の先生** です。先生の基準表には
単語ごとに点数が書いてあります: 「親切」+3 点、「満足」+2 点、「がっかり」-4 点、
「故障」-3 点... レビューが届くと、登場した単語の点数を合計し、合計が
0 より大きければポジティブ、小さければネガティブと判定します。

ロジスティック回帰 (logistic regression) がまさにこの構造です。違いはただ
1 つ — **基準表の点数を人間が決めるのではなく、正解ラベル付きのレビューデータから
モデルが自力で見つけ出す** ことです。学習が終わった後に基準表 (係数) を開いてみれば、
「モデルがどのトークンをポジ/ネガの証拠として学んだか」がそのまま見えます。
level00 で手作りしていたキーワードルールを、今度はデータが作ってくれるのです。

## 3. 核心となる概念

### 3-1. パイプラインの全体図

```
レビューテキスト → [トークン化・ベクトル化: TF-IDF] → 数値ベクトル → [ロジスティック回帰] → ポジティブ確率
```

新しく学ぶ部品はありません。level04 の TF-IDF がテキストをベクトルに変え、
lecture06 で学んだロジスティック回帰がベクトルを分類します。NLP 実務のかなりの部分が、
こうした「既存部品の組み立て」です。なお日本語は分かち書きがないので、
トークン化には level03-04 と同じ文字 2-gram を使います。

### 3-2. 学習/評価の分離 — 試験問題を事前に見せない

全データを学習用と評価用に分けます (lecture06 level04 の復習)。
テキストで特に重要なルール: **TF-IDF の語彙辞書と IDF は学習データだけで
作り、評価データには適用するだけ** にします。評価データまで入れて語彙を
作ると未来の情報が漏れること (データリーク) になり、本番性能を水増ししてしまいます。
sklearn の `fit_transform` (学習用) と `transform` (評価用) の使い分けがまさにこれです。

### 3-3. 係数の解釈 — モデルの採点基準表を開く

学習済みロジスティック回帰の係数 (coefficient) はトークンごとに 1 つずつあります。

- 係数が大きな正の数 → そのトークンがあるとポジティブ確率が上がる (ポジティブの証拠)
- 係数が大きな負の数 → ネガティブの証拠
- 0 付近 → 判定にほぼ無関係なトークン

係数の上位/下位を抜き出すと、「素晴(らしい)、満足」と「悪す(ぎ)、二度(と)」が
両側に並びます。このリスト自体が優れた報告書の材料です — 「ネガティブレビューを
牽引する最大要因は配送遅延関連の表現」というように。

### 3-4. 確率で読む — 確信度まで活用する

ロジスティック回帰は 0/1 ではなく **ポジティブである確率** を返します。0.98 は確実な
ポジティブ、0.52 は微妙なレビューです。実務ではこの確信度で仕事を分けます:
確実なものは自動処理、0.4〜0.6 の微妙なものだけ人間がレビュー。こうすれば
チェック人員を大きく減らしながら品質を守れます。

### 3-5. このモデルの限界

単語の袋ベースなので、「良くない」の否定のニュアンスが「良」の断片と別々に計算され、
皮肉 (「良いと聞いて買ったのに…」) は相変わらず苦手です。学習データになかった表現も
扱えません。それでも均質なドメイン (1 つの EC サイトのレビュー) ではこの単純なモデルが
驚くほどよく動き、より複雑なモデルを使うかどうかは「このベースラインをどれだけ上回るか」で
決めるのが定石です。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

- **[1] データ準備**: hjh_data.review_corpus の 600 件を読み込み、ポジ/ネガ比率
  (300/300) を確認して、学習 480 件 / 評価 120 件に分割します (seed 固定)。
- **[2] ベクトル化**: 学習データだけで TfidfVectorizer (文字 2-gram の analyzer) を
  fit し、語彙サイズを出力します (実測: 226 種)。評価データは transform のみです。
- **[3] 学習と評価**: ロジスティック回帰を学習し、精度と混同行列を出力します。
  実測の評価精度は 100.0% (混同行列: 誤分類 0 件) — 合成データはテンプレートが
  規則的なので、現実のレビューよりずっと簡単な問題になっています。
- **[4] 採点基準表の公開**: 係数の上位 8 個 (ポジティブの証拠: 素晴、晴ら、満足系の
  断片など) と下位 8 個 (ネガティブの証拠: 悪す、二度、度と など) を表で出力します。
  モデルが何を学んだのかを目で確認する、核心の場面です。
- **[5] 新しいレビューの判定**: 学習にない文 4 つを入れて、ポジティブ確率と判定根拠の
  トークン (その文の中で寄与が大きいトークン) を一緒に出力します。実測では
  「スタッフが親切で梱包も丁寧…」がポジティブ 90% (根拠: 満足など)、
  「配送に一週間もかかって…」がネガティブ (ポジ確率 6%、根拠: 週間・間も) と、
  4 件すべて正しく判定されます。「なぜそう判断したか」に答えるレポート形式です。

## 6. よくある間違い

- **評価データまで fit**: `fit_transform` を全データにかけるとデータリークです。
  学習にだけ fit、評価は transform。
- **精度だけ見て終わり**: クラス比率が偏った現実のデータでは、混同行列とクラス別の
  指標 (lecture06 level06) を必ず一緒に見ましょう。
- **係数の解釈を因果に拡大**: 「親切の係数が大きい」は「親切という単語がポジティブな
  レビューによく出た」ということであって、親切キャンペーンをすれば売上が上がるという
  因果の証明ではありません。
- **学習ドメインの外でそのまま使う**: EC サイトのレビューで学習したモデルをアプリストアの
  レビューにそのまま使うと、性能がガクッと落ちます。ドメインが変わったら再学習が基本です。

## 次のレベルの予告

共起行列と SVD で自作して学びます。
