**難易度** ⭐⭐⭐⭐ / **前提** level01、level06 / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

実務で本当にお金がかかっている分類問題は、ほとんどが不均衡 (imbalanced) です。不正取引 1.5%、設備故障 0.5%、重大不良 2%、不正請求 1% — 捕まえるべき対象ほど珍しいのです。ところが珍しいものを捕まえる問題に標準設定をそのまま使うと、モデルは「全部正常」と答える怠け者の最適解に落ち着きます。精度 98.5%、不正の検出 0 件 — 数字は華やかなのに何もしないモデルの誕生です。

このレベルの目標は 2 つです。第一に、怠け者のモデルを起こす 3 つの手法 (重み付け、リサンプリング、しきい値) を手に入れること。第二に、再現率と適合率が**交換関係**にあるという事実を、表と曲線で体得すること。「再現率 90% にしてください」という要求に「それなら適合率がこれだけ下がり、調査チームの業務が何倍にもなります」と答えられて初めて、実現可能な目標の交渉が始まります。

## 2. たとえ話で理解する

干し草の山から針を探す作業です。干し草 5,000 束に針が 75 本。調査員 (モデル) に「間違いの数を減らせ」とだけ指示すると、最も楽な戦略は**何も拾わないこと**です (誤答 75 個だけ、正答率 98.5%)。調査員を動かす方法は 3 つあります。

- **重み付け (class_weight)**: 「針を 1 本見逃したら罰点 65 倍」と罰点表を書き換えます。調査員は針を見逃すのが怖くなり、怪しければ拾うようになります。
- **リサンプリング (resampling)**: 訓練用の干し草の山を操作します。針をコピーして増やす (オーバーサンプリング) か、干し草を減らして (アンダーサンプリング)、針がありふれた世界で練習させます。試験 (テスト) は元の比率で受けます。
- **しきい値 (threshold) 調整**: 調査員の「疑いスコア」が 50 点以上のときだけ拾っていたのを、20 点以上なら拾うように基準を下げます。たくさん拾うので針は多く見つかりますが (再現率↑)、干し草もたくさん拾ってしまいます (適合率↓)。

どの方法にもタダ飯はありません。多く捕まえれば空振りも増える — この交換関係を目で見る道具が PR 曲線です。

## 3. 核心となる概念

### 3.1 なぜ精度が無意味になるのか

陽性 1.5% では、「全部陰性」と予測しても精度は 98.5% です。だから不均衡問題の基本指標は再現率・適合率・PR-AUC です。ROC-AUC も使われますが、陽性が極端に珍しいと ROC 曲線は甘めに見える傾向があるため、**PR 曲線 (precision-recall curve)** の方が正直です。

### 3.2 3 つの手法の比較

| 手法 | やること | 長所 | 注意点 |
|---|---|---|---|
| class_weight="balanced" | 損失関数で少数クラスのミスに大きな罰点 | 1 行で完了、データ不変 | 対応しているモデルのみ |
| オーバーサンプリング | 学習データの少数クラスを複製 | どのモデルにも適用可能 | **分割後、学習データにだけ!** 同じサンプルの繰り返しで過学習の危険 |
| しきい値調整 | predict_proba の基準線を移動 | モデルの再学習が不要、運用中に調節可能 | 検証データで決めること (テストで決めるとリーク) |

SMOTE (少数クラスを補間して合成サンプルを作る手法) という発展型も広く使われます。専用パッケージが必要なのでここでは概念だけ押さえ、実習は単純複製のオーバーサンプリングで原理を確認します。

### 3.3 リサンプリングの黄金律

リサンプリングは**必ず学習/テスト分割の後に、学習データにだけ**適用します。分割前にオーバーサンプリングすると、同じサンプルのコピーが学習とテストの両側に入り込み、性能が大きく水増しされます (リーケージの変種)。またテストデータの比率は絶対に操作しません — 試験は現実世界の比率で受けるべきです。

### 3.4 PR 曲線の読み方

しきい値を 1.0 から 0.0 まで下げながら (再現率, 適合率) の点を打つと PR 曲線になります。右へ行くほど (再現率↑) 曲線が下がる (適合率↓) 形が、交換関係の可視化です。曲線の下の面積 (PR-AUC、平均適合率) がモデルの総合点で、**どの点で運用するか**はモデルではなくビジネス (調査の人員、誤検知のコスト) が決めます。この「運用点の設計」は level10〜11 のテーマです。

`fraud_table` の 5,000 件 (不正 約 1.5%) でロジスティック回帰を 4 通りの方式で訓練・評価します。

- [1] 基本設定: 精度 99% 台という華やかな数字の裏で、不正の約 3 割を見逃していることを確認します。
- [2] class_weight="balanced": 再現率が跳ね上がる代わりに適合率が下がるのを観察します。
- [3] 手動オーバーサンプリング (学習データにだけ少数クラスを複製): 重み付けと似た効果であることを確認します。
- [4] しきい値調整: 同じモデルでしきい値 0.9→0.1 をなぞりながら、再現率/適合率/アラート件数の表を出力します。
- [5] PR 曲線をテキストで要約し (PR-AUC)、「調査チームは 1 日 15 件しか処理できない」という制約の下でどのしきい値が合理的かを計算します。

観察ポイント: [2] と [3] の結果が似ていること (どちらも「罰点表の書き換え」の変形)、そして [4] の表で再現率と適合率が逆方向に動くこと。表のどの行を選ぶかは技術ではなく経営の問題である、という感覚を持ち帰ってください。

## 6. よくある間違い

- **精度で成果を報告する**: 不均衡問題において精度は基本的に禁句です。再現率/適合率/PR-AUC で語りましょう。
- **分割前のリサンプリング**: 最もよくあり、最も目立たないリーケージです。リサンプリングはパイプラインの観点で「学習時にのみ」適用されるべきです。
- **しきい値をテストデータでチューニングする**: しきい値もハイパーパラメータです。検証データで決めて、テストは封印しましょう。
- **再現率 100% の要求をそのまま受け入れる**: 再現率 100% は「全取引ブロック」でも達成できます。必ず適合率 (またはアラート件数) の条件とセットで目標を決めましょう。
- **不均衡 = 無条件にリサンプリングという公式**: しきい値調整だけで十分な場合も多くあります。単純な方法から試しましょう。
