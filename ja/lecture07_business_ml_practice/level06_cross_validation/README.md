# Lecture 07 · Level 06 — 交差検証 — 信頼できる性能評価

> 単一分割のスコアがどれほど「運まかせ」かを実験で確かめ、5-fold 交差検証で平均±標準偏差の性能レポートを作る方法、そして時系列データの分割の注意点を学びます。
**難易度** ⭐⭐⭐ / **前提** level05、lecture06 level04 / **想定時間** 35分

## 1. なぜ学ぶのか — ビジネスの視点

外注業者が「AUC 0.87 達成」と報告してきました。この数字をどこまで信じるべきでしょうか? データの切り方次第で同じモデルのスコアが 0.83 にも 0.90 にもなるなら、小数第 2 位の競争には意味がありません。そして実際、それくらい揺れます。特にサンプルが小さいほど、不均衡が激しいほど、スコアの揺らぎは大きくなります。

交差検証 (cross-validation, CV) は、この揺らぎを正面から測定する方法です。結果の報告が「0.87」から **「0.86 ± 0.02」** に変わった瞬間、2 つのモデルの差が本物なのか偶然なのかを判断できるようになります。意思決定者にとって、これは「この改善にさらに予算を使うべきか」を分ける情報です。そして検収する側にとっては、たったひとつの質問 — 「その数字、何回測ったものですか?」 — でレポートの信頼度を推し量ることができます。

## 2. たとえ話で理解する

新商品の試食評価を考えてみてください。お客さま**一組**にだけ聞いて「満足度 90%!」と報告したらどうでしょう? その組がたまたま甘党だったら、数字は完全に歪みます。常識的な解決策は**複数の組に順番に聞いて、平均とばらつきを一緒に報告する**ことです。

5-fold 交差検証がまさにこの方式です。データを 5 つに分け、毎回 4 つで勉強 (学習) し、残りの 1 つで試験 (検証) を受けます。担当を入れ替えながら 5 回試験を受けるとスコアが 5 つ得られ、その**平均**が実力の推定値、**標準偏差**が「運の大きさ」です。データ全体が 1 回ずつ試験問題として使われるので、どれか 1 つの偶然の特性に振り回されません。

ただし、時系列データには例外的なルールがひとつ付きます。模試 (過去) で勉強して本試験 (未来) を受けるべきであって、**本試験の問題で勉強して模試を受けて**はいけません。無作為にシャッフルして分割すると、未来のデータで過去を予測する試験ができてしまいます。

## 3. 核心となる概念

### 3.1 単一分割の分散 — スコアは確率変数である

`train_test_split(random_state=n)` の n を変えるだけでスコアが変わります。スコアは固定された真理値ではなく、**分割という偶然が混ざった確率変数**です。main.py の [1] では、30 通りの異なる分割で同じモデルを評価し、スコアの分布 (最小〜最大の幅) を直接見ます。この幅こそ、皆さんがこれまで見てきた「単一スコア」たちの隠れた誤差範囲です。

### 3.2 k-fold 交差検証

- **k=5 または 10** が慣例。データが非常に少なければ k を大きくし (極端なケースは LOO)、大きければ 5 で十分です。
- 分類問題は **StratifiedKFold**: 各ピースのクラス比率 (解約率 18%) を元データと同じに保ちます。不均衡データでは特に重要です。
- 報告形式: `平均 ± 標準偏差`。2 つのモデルを比較して、平均の差が標準偏差より小さければ「差なし」が正直な結論です。
- コスト: 学習を k 回行うので時間が k 倍。その対価として信頼を買います。

### 3.3 最終モデルと最終テスト

交差検証は「この方法 (モデル+前処理+ハイパーパラメータ) が平均的にどれだけ良いか」を測る手続きです。方法が決まったら、**最終モデルは全学習データで学習し直します**。そしてハイパーパラメータの選択まで CV でやったなら、最後の発表用スコアは CV に一度も使っていない**封印されたテストセット**で測るのが定石です (選ぶのに使ったものさしで測ると、スコアが甘くなります)。

### 3.4 時系列分割 — TimeSeriesSplit

時間の順序があるデータ (売上、株価、トラフィック) に無作為の k-fold を使うと、「未来で過去を予測する」リーケージが生まれます。特に移動平均・前日売上のようなラグ (lag) 特徴量があると、検証ピースの情報が学習ピースの特徴量に直接入り込んでいて、スコアが大きく水増しされます。解決策は `TimeSeriesSplit`: 学習区間が常に検証区間より前に来るように切ります (1〜3 月で学習→4 月を検証、1〜4 月で学習→5 月を検証、…)。main.py の [4] では、同じ売上予測問題のスコアが無作為分割でどれだけ水増しされて見えるかを比較します。

## 6. よくある間違い

- **一度測ったスコアでモデルを選ぶ**: 0.87 vs 0.86 の勝負は分割の運でひっくり返ります。比較は必ず CV で。
- **CV スコアを「テストスコア」として報告する**: ハイパーパラメータを CV で選んだなら、CV スコアはすでに少し甘めのスコアです。最終報告は封印テストで。
- **時系列に shuffle=True**: 移動平均・ラグ特徴量のあるデータを無作為にシャッフルすると、スコアが静かに水増しされます。時間軸があれば、まず TimeSeriesSplit から検討してください。
- **不均衡データにそのまま KFold**: あるフォールドには解約者がほとんどいないかもしれません。分類は StratifiedKFold が既定値です。
- **CV でも前処理リーケージを放置する**: スケーリング・エンコーディングを CV の外で先に済ませると、フォールド同士がのぞき見し合います。パイプラインごと渡しましょう (level05)。
