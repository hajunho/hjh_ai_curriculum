# Lecture 07 · Level 10 — 実践 3: 不正取引検知

> 正解ラベルで学ぶ教師あり学習と、ラベルなしで「異常さ」を探す IsolationForest を同じデータで対決させ、調査チームのアラート予算に合わせた運用しきい値を設計します。
**難易度** ⭐⭐⭐⭐ / **前提** level07 / **想定時間** 55分

## 1. なぜ学ぶのか — ビジネスの視点

カード会社・銀行・EC・保険 — お金が流れる場所には必ず不正利用があり、それをふるい落とす検知システムがあります。このシステム設計には、他の問題にはない悩みが 2 つあります。

第一に、**ラベルの限界**。不正のラベルは「摘発された不正」しか含みません。まだ誰も見たことのない新種の手口はラベルに存在しないため、ラベルで学んだ教師ありモデルは新種に弱いことがあります。だから実務の検知システムは、ラベルで学ぶモデルと、ラベルなしで「普段との違い」を探す教師なしモデルを**並行**させることが多いのです。第二に、**運用予算**。アラートは人間が調査します。調査チームが 1 日 20 件を処理できるなら、モデルがどれだけ優秀でも、アラートは 1 日 20 件前後に設計されなければなりません。しきい値は統計ではなく、人員計画から生まれます。

このレベルは、この 2 つの悩みをコードで体験する実践です。

## 2. たとえ話で理解する

デパートの保安チームに 2 人の職員がいるとしましょう。

- **ベテラン職員 (教師あり学習)**: 過去の万引き犯の写真帳を丸ごと覚えています。写真帳にある手口は神業のように捕まえますが、写真帳にない新しい手口は見逃すことがあります。
- **新人職員 (教師なし、異常検知)**: 写真帳はありませんが、「普通のお客さまの行動」を長く観察してきました。誰であれ普段のパターンと大きく違えば — 深夜に、おかしな動線で、大きな品物を — とりあえず注目します。新種の手口も捕まえられますが、単に風変わりな無実のお客さまもよく指名してしまいます (誤検知↑)。

2 人の職員を一緒に立たせるのが実務の答えです。そして保安室が 1 日に確認できる CCTV アラート数 (予算) に合わせて「どれくらい敏感に反応するか」を調節します。感度 (しきい値) を決めるのは 2 人の職員ではなく、保安室長の仕事です。

## 3. 核心となる概念

### 3.1 IsolationForest — 「孤立しやすい点」が異常値

IsolationForest (孤立の森) はデータを無作為な基準で繰り返し切り分け、**何回で単独に孤立するか**を測ります。正常なデータは似た隣人が多いので何度も切らないと孤立しませんが、異常値は離れ小島にいるので数回で孤立します。早く孤立するほど異常スコアが高くなります。正解ラベルをまったく使わない**教師なし (unsupervised)** の方法なので、ラベルがない (新規サービス) か、ラベルが当てにならない (新種の手口) 状況で真価を発揮します。`contamination` パラメータは「全体のうち異常値がこの程度の比率だろう」という仮定で、アラート比率を調節するつまみです。

### 3.2 教師あり vs 教師なし — 公正な比較法

両アプローチとも、結局は取引ごとに**疑いスコア**を出します。比較は「同じテストデータで、同じアラート件数を許したときに不正を何件捕まえるか」(precision@K, recall@K) で行うのが公正です。一般的な結果: ラベルが十分で手口が安定していれば教師あり学習の圧勝、ラベルが不十分だったり手口が変化したりすると差が縮まり、教師なしが保険の役割を果たします。

### 3.3 アラート予算ベースのしきい値設計

運用しきい値を決める実務の手順は、性能曲線ではなく予算から出発します。

1. 調査チームの処理量を確認: 1 日 K 件
2. 1 日の取引量 N を推定 → アラート率の目標 = K/N
3. 検証データの疑いスコアの分布で、上位 K/N 分位点をしきい値に設定
4. そのしきい値での期待再現率・適合率を報告して合意

「しきい値 0.83」ではなく「1 日 20 件のアラート、うち約 60% が本物、全不正の約 70% をカバー」が運用の言葉です。予算を増やすと再現率がどれだけ上がるか (限界効用) を併せて報告すれば、調査人員増員の根拠資料になります。

### 3.4 並行運用の実際

実務構成の例: ① 教師ありモデルのスコアが高ければ即アラート (主力)、② 教師ありのスコアは低いのに教師なしのスコアだけ高い取引は「新種疑い」の別キューで少量サンプル調査、③ 調査結果が新しいラベルとなって教師ありモデルを再学習する好循環。main.py の [5] が ② のアイデアをデモします。

## 4. 実習 — main.py

```bash
python3 main.py
```

`fraud_table` の 5,000 件 (不正 約 1.5%) で 2 つのアプローチを比較し、運用設計を行います。

- [1] データ分割。特徴量は level07 と同じ仮定 (履歴集計システムの不在) の下、level03 の派生特徴量 (log_amount, is_night など) を再利用します。
- [2] 教師あり学習: ロジスティック回帰 (class_weight 適用) で疑いスコアを作ります。
- [3] 教師なし: IsolationForest を**ラベルなしで**学習し、異常スコアを作ります。
- [4] 同じアラート予算 (テスト 1,500 件中 20 件) で、2 つのアプローチが捕まえた不正数・適合率・再現率を比較します。
- [5] 2 つのスコアのクロス表: 教師ありモデルは低く見たのに教師なしが高く見た「新種疑いゾーン」の取引を確認します。
- [6] アラート予算を 10〜60 件に変えながら再現率がどう変わるか (限界効用) を表で出力し、予算増員の報告文を作ってみます。

観察ポイント: [4] でラベルを使った教師あり学習が先行すること (ラベルは強力です)、それでも [5] で教師なしが別の視点を提供すること、[6] で予算を増やすほど再現率の増加幅が縮むこと (限界効用の逓減) です。

## 6. よくある間違い

- **教師なしモデルを精度系の指標だけで評価する**: ラベルなしで学んだとしても、評価はラベルで行えます (過去のデータにはラベルがあるので)。ただしラベル自体が不完全である点を忘れないでください — 「誤検知」に見えたアラートが、実は未摘発の不正かもしれません。
- **contamination を性能チューニングの対象と誤解する**: この値はアラート比率の仮定にすぎません。順位 (スコア) はほぼそのままなので、運用のアラート数は予算ベースの分位点で別途設計しましょう。
- **しきい値を一度決めて放置する**: 取引パターンと不正の手口は変わり続けます。アラート率・適合率を週次でモニタリングし、しきい値を再調整する運用ループが必須です。
- **教師あり vs 教師なしを勝者総取りで結論づける**: 目的が違います。教師ありは「知っている手口を最大効率で」、教師なしは「知らない手口の早期警報」。レポートにも役割分担として書きましょう。
- **ブロックとアラートを混同する**: スコアが高いからと即座に取引をブロックすると、誤検知 1 件が顧客離れにつながります。等級別の対応 (ブロック/追加認証/事後調査) を設計しましょう。
