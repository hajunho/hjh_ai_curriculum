# Lecture 07 · Level 02 — 探索的データ分析 (EDA) の手順

> 「とりあえずグラフでも描いてみよう」ではなく、仮説の設定→検証のサイクルと、単変量→二変量→時間の順序で進める EDA の手順を身につけます。
**難易度** ⭐⭐ / **前提** level00、lecture05 / **想定時間** 40分

## 1. なぜ学ぶのか — ビジネスの視点

モデリングの失敗の多くは、EDA (Exploratory Data Analysis、探索的データ分析) を飛ばしたか、いい加減に済ませたところから始まります。解約率が 18% だと知らずに精度で評価する、欠損が集中している区間を知らないまま平均を取る、明らかなリーク変数を特徴量に入れてしまう — こうした事故はすべてここで起こります。

実務での EDA には 2 つの役割があります。第一に**リスクの除去**: データの落とし穴 (欠損、外れ値、不均衡、リーケージ) をモデリングの前に発見します。第二に**仮説の生産**: 「カスタマーセンターへの問い合わせが多い顧客は解約しやすい」といった発見はそれ自体が現場に報告する価値があり、次のレベルの特徴量エンジニアリングの材料になります。モデルなしで EDA レポートだけで終わるプロジェクトも多くありますが、それは失敗ではなく立派な成果です。

## 2. たとえ話で理解する

EDA は**健康診断**です。病院は患者を手術台 (モデル) に乗せる前に、決まった順序で検査を行います。

1. **基礎問診 (データ概要)**: 身長・体重・年齢 — 行数、列の型、欠損の割合。
2. **項目別検査 (単変量)**: 血圧、血糖値をひとつずつ — 各変数の分布をひとつずつ見ます。
3. **関連検査 (二変量)**: 「血圧と体重の関係」 — 変数とターゲット、変数どうしの関係を見ます。
4. **経過観察 (時間)**: 昨年の数値と比較 — 時間に伴う変化・トレンドを見ます。

そして医師は検査の前に**所見の仮説**を立てます。「腹痛ならまず胃腸を疑う」のと同じように、「利用日数が少なければ解約が多いはずだ」という仮説を先に書き、それをデータで確認するのです。仮説なしにグラフを何十枚も描くのは、症状も聞かずに全身 MRI から撮るようなものです。高くつくうえに、偶然出た信号にだまされやすくなります。

## 3. 核心となる概念

### 3.1 仮説の設定 → 検証のサイクル

EDA の単位作業は「①仮説を文章で書く → ②その仮説を確認できる最小限の表/グラフを作る → ③判定 (支持/棄却/保留) を書く → ④新しい仮説が生まれたら繰り返す」です。ポイントは**グラフより文章が先**であること。文章があって初めてどのグラフを描くべきかが決まり、レポートにもそのまま転記できます。

### 3.2 単変量 → 二変量 → 時間の順序

- **単変量 (univariate)**: 変数 1 つの分布。平均・中央値・標準偏差・最小値・最大値、ヒストグラム。ここで欠損・外れ値・歪み (偏った分布) を捕まえます。ターゲット変数の比率 (解約率 18%) も必ずこの段階で確認します。
- **二変量 (bivariate)**: 変数 × ターゲット。分類問題なら「ターゲットのグループ別平均比較」が最強の一手です。解約顧客と残留顧客の `usage_days_30d` の平均が大きく違えば、その変数は有望な特徴量です。数値型どうしは相関係数 (correlation) を見ます。
- **時間 (temporal)**: 時間軸のあるデータなら、トレンド・季節性・急変区間を見ます。churn_table には時間軸がないため今回の実習では省きますが、level08 (売上予測) では主役になります。

### 3.3 EDA で必ず捕まえるべき 4 大落とし穴

| 落とし穴 | 症状 | その後の対処 |
|---|---|---|
| 欠損 | 特定の列/区間に集中する空欄 | 削除・補完の戦略を決定 (lecture03) |
| 外れ値 | マイナスの売上、常識外れの最大値 | 原因を確認して削除/修正 |
| 不均衡 | ターゲット比率 18%、1.5% | 評価指標・重みの再設計 (level07) |
| リーク疑い | ターゲットとの相関 0.95 のような怪しい変数 | 生成時点を確認して除外 (level03) |

### 3.4 相関係数の読み方

相関 +0.3 なら「弱い正の関係」、±0.7 以上なら「強い関係」程度に読みつつ、2 つのことを覚えておいてください。第一に、相関は因果ではありません (アイスクリームの売上と水難事故)。第二に、高すぎる相関は喜ぶことではなく**疑うこと**です。ターゲットと相関 0.9 の変数は、たいてい「正解を先に知らないと作れない変数」(リーケージ) です。

### 3.5 EDA レポートの形

EDA の成果物はグラフ集ではなく、**判定付きの文章リスト**です。良い形式: 「仮説 → 根拠 (表/図の番号) → 判定 → モデリングへの示唆」の 4 列の表。例: 「利用日数が少ないほど解約が多い → 図2 → 支持 → 主要特徴量の候補」。こう整理すれば、EDA がそのまま特徴量リスト (level03) と経営報告の下書きになります。

## 4. 実習 — main.py

```bash
python3 main.py
```

`churn_table` の 2,000 人に対する自動 EDA レポートを生成します。

- [1] 仮説 3 つを先に文章として出力します (検証前)。
- [2] 基礎問診: 行/列、型、欠損、ターゲット比率。
- [3] 単変量: 数値型変数ごとの要約統計表。
- [4] 二変量: 解約/残留グループ別の平均比較表と「差の倍率」、そしてターゲットとの相関係数ランキング。
- [5] 仮説の判定: [1] の各仮説に支持/棄却を出力します。
- [6] 図 2 枚を `outputs/` に保存します: ① 主要変数の解約/残留別の分布比較、② 相関行列のヒートマップ。

コードの核心部は `df.groupby("churned")[cols].mean()` の 1 行です。二変量分析の 8 割がこの groupby 比較であることを目で確認してください。ヒートマップは `df.corr()` の結果を `imshow` で描いただけです。

## 6. よくある間違い

- **グラフを何十枚も目的なく量産する**: 仮説の文章がないグラフは、レポートの段階で全部切り捨てられます。文章が先、グラフは証拠として。
- **ターゲット比率を確認せずにモデリングを始める**: 不均衡を知らないと、以後のすべての評価が歪みます。EDA の最優先確認項目です。
- **平均だけ見て分布を見ない**: 平均が同じでも分布の形が違えばまったく別のデータです。要約表とヒストグラムはセットです。
- **EDA で見たことをテストデータにまで適用してルールをチューニングする**: テストデータは EDA でも封印が原則です。全データで EDA をしたなら、その事実をレポートに明記しましょう。

## 次のレベルの予告

EDA で発見した「解約顧客は利用日数が少なく問い合わせが多い」といった洞察は、そのまま特徴量の材料になります。level03 では元の列を組み合わせて派生特徴量を作り、それがモデルの性能をどれだけ引き上げるかを実験で証明します。
