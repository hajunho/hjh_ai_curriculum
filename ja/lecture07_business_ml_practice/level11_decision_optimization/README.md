# Lecture 07 · Level 11 — モデルを意思決定へ: コスト・収益の最適化

> 解約確率に期待価値の計算を重ねて「誰にクーポンを配るか」の利益最大化しきい値を求め、キャンペーン ROI シミュレーションで講義を締めくくります。
**難易度** ⭐⭐⭐⭐⭐ / **前提** level01、level09 / **想定時間** 60分

## 1. なぜ学ぶのか — ビジネスの視点

モデルの出力は確率で、会社が欲しいのは利益です。この間をつなぐ最後の橋が**意思決定の最適化**です。同じモデルでも「確率 50% 以上にクーポン」と「確率 22% 以上にクーポン」では、年間利益の差が数千万ウォンになることがあります。つまり、しきい値ひとつが、そこそこのモデル改善よりもお金になるのです。

驚くべきことに、最適しきい値はモデルの性能と無関係に、**ビジネス単価だけで理論値が導けます**。介入コスト C、顧客価値 V、介入成功率 s があれば、損益分岐確率は `p* = C/(V×s)` — 算数 1 行です。このレベルを終えると、皆さんはデータチームから受け取った確率ファイルをもとに「どこまで介入するか」を自分で計算し、キャンペーン企画書に期待 ROI を数字で書けるようになります。これがこの講義 12 レベルの終着点です。

## 2. たとえ話で理解する

傘売りの悩みと同じです。天気予報 (モデル) が「明日の降水確率 30%」と言っています。露店を開くべきでしょうか? 答えは確率だけでは決められません。**開いたのに雨が降らなければ失うお金 (コスト C) と、開いて雨が降れば稼げるお金 (収益 R)** にかかっています。場所代が 1 万ウォンで、雨の日の純収益が 10 万ウォンなら、確率が 10% を超えるだけで開くのが得です (期待値 0.1×10 万 = 1 万 > 場所代)。場所代が 5 万ウォンなら、確率 50% は超えないといけません。

クーポンキャンペーンもまったく同じです。解約確率 p の顧客にクーポンを配る期待利益は `p×(V×s) − C`。これがプラスになる顧客にだけ配ればよいのです。予報官 (モデル) の仕事は確率を正確に作るところまでで、商売人 (意思決定者) の仕事はその確率に値札を掛けることです。2 つの役割をつなげなければ、どれだけ正確な予報もお金になりません。

## 3. 核心となる概念

### 3.1 期待価値 (expected value) の計算

解約確率 p の顧客に介入 (クーポン+相談、コスト C) すると:

- その顧客が本当に解約予定である確率 p → 成功率 s で引き留めて V を守る: 期待収益 `p × V × s`
- 解約予定でない確率 (1−p) → クーポンを使うだけで得るものなし
- コストは確実に出ていく: `−C`

したがって**介入の期待利益 = p×V×s − C**。介入しなければ 0。ゆえに `p×V×s − C > 0`、すなわち **p > C/(V×s) ≡ p\*** の顧客にだけ介入するのが利益を最大化します。V=179,000ウォン、s=30%、C=12,000ウォンなら p\* = 12,000/53,700 ≈ **22.3%**。しきい値 0.5 は何の根拠もない慣習にすぎません。

### 3.2 理論値と実験値のクロスチェック

main.py は 2 つの方向から最適しきい値を求めます。① 理論: p\* = C/(V×s)。② 実験: テストデータでしきい値を 0→1 になぞりながら実現利益を計算し、最大点を探す。両者が近ければ計算を信頼でき、大きく違えばモデルの確率が**キャリブレーション (calibration、確率の較正)** できていない兆候です (確率 70% と言った顧客たちが実際には 40% しか解約しない、など)。較正のずれた確率は期待価値計算の材料に使えないため、実務ではキャリブレーション曲線の点検がこの計算の前提条件です。

### 3.3 キャンペーン ROI への翻訳

経営報告の最終形はしきい値ではなく ROI です: `ROI = 純利益 / 投入コスト`。「リスク上位 1,240 名にクーポン費用 1,488 万ウォンを使えば、期待純利益 1,900 万ウォン、ROI 128%」のように書きます。ここに保守的/基本/楽観シナリオ (s を 20/30/40% に) を付ければ企画書の完成です。

### 3.4 この計算の限界 — 2 つの正直な注釈

第一に、s (介入成功率) は過去のキャンペーンや A/B テストから来るべき数字です。推定なら、シナリオで幅を持たせて報告しましょう。第二に、このモデルは「解約確率が高い人」を選びますが、理想的には「クーポンを配って初めて心変わりする人」(説得可能な顧客) を選ぶべきです。どうせ残る人と、どうせ離れる人に使うクーポンは無駄になります。これを直接モデリングするアップリフトモデリング (uplift modeling) という発展テーマがあることだけ知っておいてください — 対照群の実験データが必要で、この講義の範囲を超えます。

## 4. 実習 — main.py

```bash
python3 main.py
```

- [1] `churn_table` で解約モデルを訓練し、テスト顧客の解約確率を得ます。
- [2] ビジネス単価 (V, C, s) から理論の損益分岐確率 p\* を計算します。
- [3] しきい値 0→1 をなぞりながらテストデータの実現利益を計算し、最適しきい値を探します。
- [4] 戦略比較表: 何もしない / 全員クーポン / 慣習 (0.5) / 理論 p\* / 実験最適 — 5 つの戦略の利益を並べて見ます。
- [5] 利益曲線の PNG を `outputs/` に保存します (理論 p\* と実験最適点を表示)。
- [6] 最適しきい値ベースのキャンペーン ROI を 10 万顧客規模・シナリオ 3 種 (s=20/30/40%) に拡張し、報告文を出力します。

核心の観察点: [4] でのしきい値 0.5 (慣習) と最適しきい値の利益差、そして理論 p\* が実験最適とどれだけ近いかです。モデルはそのままで意思決定だけを変えて利益が何倍にもなる — それがこのレベルのすべてです。

## 6. よくある間違い

- **しきい値 0.5 を神聖視する**: 0.5 はライブラリの既定値にすぎず、コスト構造が対称のときにだけ正当化されます。実務の問題のコストはほぼ常に非対称です。
- **較正されていない確率で期待価値を計算する**: class_weight やリサンプリングを使ったモデルの確率は上振れしがちです。順位は有効でも絶対値には調整が必要です — main.py の [3] のように実験最適と理論値をクロスチェックするか、キャリブレーションを適用しましょう。
- **テストデータでしきい値を選び、同じデータで利益も報告する**: しきい値の選択は検証データ、最終的な利益の推定は封印されたテストで、と分離するのが定石です。
- **s を楽観的に決めつける**: 成功率 30% と 15% では、キャンペーンの黒字/赤字が分かれます。必ずシナリオの幅で報告し、実際のキャンペーンでは対照群で s を実測しましょう。
- **モデル改善だけに予算を使い、意思決定の設計を放置する**: AUC を 0.01 上げるより、しきい値を動かす方がはるかに安くて速い場合が多いのです。順序は意思決定の最適化が先、モデル改善はその次。
