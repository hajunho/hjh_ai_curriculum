# Lecture 09 · Level 01 — ピクセル・チャンネル・画像演算

> 明るさ調整は足し算、コントラストは掛け算、反転は引き算 — 画像編集アプリのボタンたちを numpy の算数で自分の手で作ってみます。
**難易度** ⭐⭐ / **前提** level00 / **想定時間** 30分

## 1. なぜ学ぶのか — ビジネスの視点

ビジョン AI のプロジェクトで、モデリングより先に出会う仕事が**前処理 (preprocessing)** です。店舗の防犯カメラは昼と夜で明るさが違い、スキャンした書類はコントラストが弱く、カメラごとに解像度もバラバラです。こういう画像をそのままモデルに入れると、性能が大きく揺れます。実務のパイプラインの最初の段階は、いつでも「明るさの正規化、サイズの統一、関心領域の切り出し」といった画像演算です。

これらの演算は Photoshop の専売特許ではありません。level00 で見たとおり画像は数字の表なので、**明るさ調整 = 全セルへの足し算、コントラスト調整 = 全セルへの掛け算**です。Excel で列全体に `+10` を入れるのと同じ仕事です。この感覚が身につくと、「前処理は何をされましたか?」という質問を投げかけ、その答えを理解できるようになります。

## 2. たとえ話で理解する

**舞台の照明コンソール**を思い浮かべてください。

- **マスターフェーダーを上げる** → 舞台全体が均一に明るくなる = すべてのピクセルに同じ数を**足す**
- **ディマーの倍率を上げる** → 明るい所はもっと明るく、暗い所は少しだけ明るく、差が開く = すべてのピクセルに同じ数を**掛ける** (コントラスト)
- **ネガフィルム** → 明るかった所が暗くなり、暗かった所が明るくなる = `1 - ピクセル値` (反転)

そしてカラー。舞台照明は赤・緑・青の 3 台の照明を重ねてあらゆる色を作ります。カラー画像も同じです。**赤の明るさの表、緑の明るさの表、青の明るさの表** — 白黒画像 3 枚を重ねたものが RGB カラー画像です。この 1 枚 1 枚を**チャンネル (channel)** と呼びます。

## 3. 核心となる概念

### 3.1 チャンネル — カラーは白黒 3 枚

カラー画像は `(高さ, 幅, 3)` の配列です。`img[:, :, 0]` が赤チャンネル、`[..., 1]` が緑、`[..., 2]` が青。ピクセル 1 つは数字 3 個 (R, G, B) の束で、(1, 0, 0) は純粋な赤、(1, 1, 0) は黄色、(1, 1, 1) は白です。白黒への変換は 3 チャンネルの加重平均です (人の目は緑に敏感なので、`0.299R + 0.587G + 0.114B` を慣例として使います)。

### 3.2 ピクセル演算の 4 兄弟

| 演算 | 式 | 照明コンソールのたとえ | 注意点 |
|---|---|---|---|
| 明るさ (brightness) | `img + b` | マスターフェーダー | 1.0 を超えた分は切り落とす (clip) 必要あり |
| コントラスト (contrast) | `(img - 0.5) * a + 0.5` | ディマーの倍率 | 中心 0.5 を基準に広げる |
| 反転 (invert) | `1 - img` | ネガフィルム | — |
| クリッピング (clip) | `np.clip(img, 0, 1)` | 安全リミッター | 演算後は必ず確認 |

コントラストで先に `- 0.5` をする理由: 単に `img * 2` をすると、全体が明るくなるだけです。中間の明るさ (0.5) を軸に上下へ広げてこそ、「暗い所はもっと暗く、明るい所はもっと明るく」になります。

### 3.3 幾何演算 — クロップとリサイズ

- **クロップ (crop)**: 関心領域だけを切り出すこと。numpy のスライシングそのものです — `img[y0:y1, x0:x1]`。Excel で表の一部の範囲をコピーするのと同じです。
- **リサイズ (resize)**: 大きさを変えること。最もシンプルな方法は**最近傍法 (nearest neighbor)** — 新しい座標から最も近い元のピクセル値を持ってきます。拡大するとピクセルが階段のようにギザギザに見えますが、それがこの方法の正直な限界です (実務のライブラリは周囲のピクセルを混ぜる補間を使います)。

### 3.4 正規化 — モデルに入れる前の最後の関門

ディープラーニングのモデルは入力の数字の範囲に敏感です。そのため学習の前に、画像を「平均 0 付近、似たスケール」にそろえてあげます。最もよくある 2 つは、0〜255 を 0〜1 に割ることと、`(img - 平均) / 標準偏差` です。「撮影条件を同じにそろえられないなら、コードでそろえる」 — これが正規化の実務的な意味です。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

このプログラムは numpy だけで RGB 画像を作り、画像演算のすべてを 1 枚の比較パネル PNG にまとめます。

- **[1]** numpy で 48×48 の RGB 画像を**自分で描きます** (空のグラデーション + 赤い四角形 + 黄色い円)。ダウンロードも画像ファイルもなく、配列操作だけでカラーの絵ができることを、まず確認します。
- **[2]** R/G/B チャンネルを 1 枚ずつに分離し、各チャンネルでどの物体が明るく見えるかを出力します。赤い四角形は R チャンネルで明るく、B チャンネルで暗くなります — 「赤い」の正体が数字として現れます。
- **[3]** 明るさ (+0.25)、コントラスト (×1.8)、反転、白黒変換をそれぞれ適用し、演算前後のピクセル値の統計 (min/mean/max) を表として出力します。clip をしなかったときに値が 1.0 を超えることも、わざと見せます。
- **[4]** クロップ (四角形の部分だけ) と最近傍リサイズ (48→96 の拡大、48→16 の縮小) を自分で実装します。拡大版の階段状のギザギザを PNG で確認してください。
- **[5]** 原画像・チャンネル 3 枚・演算結果を 3×4 の格子の比較パネルとして `outputs/pixel_ops.png` に保存します。

コードの核心部は `resize_nearest()` です。`np.linspace` で「新しい画像の各ピクセルが元画像のどの座標を参照するか」というインデックス配列を作り、ファンシーインデックス 1 行 `img[yy][:, xx]` でリサイズを終わらせます。ループなしで配列のインデックスだけで幾何演算ができてしまう — これが numpy 流の考え方です。

## 6. よくある間違い

- **clip を忘れる**: `img + 0.5` のあと値が 1.4 になっても、numpy はエラーを出しません。保存や表示の段階で色がおかしく飛んでから気づくことになります。ピクセル演算のあとは習慣的に `np.clip` しましょう。
- **整数画像でのオーバーフロー**: 0〜255 の uint8 配列で 200+100 をすると、300 ではなく 44 になります (あふれます)。float に変換して計算し、最後に戻すのが安全です。
- **チャンネル順序の混同**: この講義は RGB の順ですが、一部のライブラリ (OpenCV など) は BGR の順を使います。青っぽく写った顔写真の 90% はチャンネル順序のバグです。
- **リサイズで情報が復活するという思い込み**: 16×16 を 96×96 に拡大しても、情報は増えません。大きく見えるだけです。存在しないディテールは作られません。

## 次のレベルの予告

ここまでの演算は、ピクセル 1 つ 1 つを**独立に**変えていました。ところが「ここは物体の境界線なのか?」という質問は、隣のピクセルとの**関係**を見なければ答えられません。隣り合うピクセルを一緒に見る演算 — 畳み込み (convolution) が level02 の主役です。
