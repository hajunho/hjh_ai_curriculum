# Lecture 09 · Level 04 — プーリングと特徴の階層

> 「だいたいどのあたりにあったか」だけを残して細かい位置は捨てる要約演算 — プーリングがなぜ CNN を丈夫にするのかを feature map で確認します。
**難易度** ⭐⭐⭐ / **前提** level03 / **想定時間** 35分

## 1. なぜ学ぶのか — ビジネスの視点

不良検査のカメラの前で、製品は毎回 1〜2mm ずつずれて置かれます。書類のスキャンは少し傾き、店頭の陳列写真の商品は少しずつ違う位置にあります。ピクセル座標に敏感なシステムなら、この「わずかなずれ」ごとに誤作動するでしょう。実世界のビジョンシステムに必須の資質は**位置が少し変わっても同じ判断を下すこと**であり、CNN でこの資質を担う部品がプーリング (pooling) です。

もう 1 つ。「ディープラーニングは層が深いほど良い」という言葉の実際の意味 — **前の層は点や線のような低次の特徴を、後ろの層は部品や形のような高次の特徴を見る** — を理解すると、「うちの課題には何層必要か?」という質問に感覚が生まれます。微細な傷の検出では前の層の特徴が重要で、製品の種類の分類では後ろの層の特徴が重要です。

## 2. たとえ話で理解する

**地域ごとの要約報告**を思い浮かべてください。全国 200 店舗の日次指標を本社がすべて見るわけにはいかないので、エリアごとにまとめて「関東エリアの最高売上店舗: 520 万円」のように**エリアごとに代表値 1 つ**だけを上げます。個々の店舗の細かい順位は消えますが、「関東のどこかに大ヒット店舗がある」という核心は残ります。

**マックスプーリング (max pooling)** がまさにこれです。特徴マップを 2×2 のエリアに分け、エリアごとに**最大値 1 つ**だけを残します。「このエリアのどこかで縦のエッジが強く検出された」という情報は保たれ、「正確にどのピクセルだったか」は捨てられます。だから物体が 1〜2 ピクセル動いても、プーリング後の結果はほとんど同じです — 要約報告は、店舗が隣のブロックに引っ越しても変わりませんから。

特徴の階層は**会社の報告体制**と同じです。現場の担当者 (1 層) は生データの細部 (ピクセルの明暗の変化 = エッジ) を見て、チームリーダー (2 層) は担当者の報告の組み合わせ (エッジの並び = 角・曲線) を見て、役員 (3 層) はチームリーダーの報告の組み合わせ (部品の配置 = 「丸い輪郭を持つ物体」) を見ます。上に行くほど**抽象的で、広い範囲を代表する**ようになります。

## 3. 核心となる概念

### 3.1 マックスプーリングの演算

`MaxPool2d(kernel_size=2, stride=2)`: 2×2 の窓を重ならないようにずらしながら、窓の中の最大値を取ります。出力は縦横が半分、チャンネル数はそのまま。**パラメータが 0 個**だという点が重要です — 学ぶものが何もない、固定の要約規則です。

平均プーリング (average pooling) は最大値の代わりに平均を取ります。「最も強い証拠」(max) vs 「全体的な傾向」(mean) の違いで、分類 CNN の中間層には max が、最後の要約 (グローバル平均プーリング) には mean がよく使われます。

### 3.2 プーリングがもたらす 3 つの効果

1. **移動に対する頑健性 (translation robustness)**: 入力が 1〜2 ピクセル動いても、エリアの最大値はほぼ保たれます。main.py で実験として確認します。
2. **計算量・サイズの削減**: 縦横が半分 = 次の層の計算が 1/4。Flatten のサイズも減るので、後段の Linear のパラメータが激減します。
3. **視野 (受容野、receptive field) の拡大**: プーリング後の 1 ピクセルは元画像のより広い領域を代表するので、同じ 3×3 のカーネルでも後ろの層ではより大きなパターンを見ることになります。

### 3.3 stride 畳み込み vs プーリング

level03 の TinyCNN は stride=2 の畳み込みでサイズを減らしました。プーリングと stride 畳み込みはどちらも「空間の縮小」の手段で、前者は固定規則・パラメータ 0、後者は学習される縮小です。古典的な構造 (例: VGG 系の設計慣行) は `Conv-Conv-MaxPool` のブロックを、近年の構造は stride 畳み込みを好んで使います。どちらも読めれば十分です。

### 3.4 特徴の階層 — なぜ生まれるのか

設計者が「1 層目はエッジを見なさい」と指示したことは一度もありません。構造がそうさせるのです。1 層目のカーネルは元のピクセルの 3×3 しか見られないので明暗の変化 (エッジ) 以上のものは見えず、2 層目は 1 層目の結果の 3×3 — つまり元画像換算でより広い領域のエッジの組み合わせ — を見ることになり、プーリングを経るごとにこの視野が指数的に広がります。**低次→高次の階層は、局所性+積み上げ+プーリングの必然的な結果**です。

### 3.5 失うものもある

プーリングは位置情報を捨てます。分類 (「何であるか」) には有利ですが、正確な位置が重要な課題 — 物体検出 (level09)、セグメンテーション (level10) — ではこの損失が問題になり、位置を復元する別の仕掛けが必要になります。「要約報告だけでは店舗の住所は分からない」という限界を覚えておいてください。

## 6. よくある間違い

- **プーリングにパラメータがあると思い込む**: MaxPool は学ぶものが何もない固定規則です。モデルサイズの計算では 0 として数えます。
- **プーリングがチャンネル方向にも適用されると勘違いする**: プーリングは空間 (H, W) だけを減らします。チャンネル数はそのままです。
- **とにかくプーリングをたくさん入れる**: 毎層プーリングすると位置情報が早すぎるうちに消えてしまい、小さな物体・微細な欠陥がまったく見えなくなります。縮小は課題が許す分だけ。
- **「後ろの層のほうが賢い」という誤解**: 後ろの層はより抽象的なだけです。微細な傷の検出のように、低次の特徴こそが答えである課題もたくさんあります。課題と層の水準を合わせることが設計です。
