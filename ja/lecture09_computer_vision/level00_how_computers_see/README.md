# Lecture 09 · Level 00 — コンピュータが画像を見る仕組み

> 一枚の写真がコンピュータの中では数字の格子にすぎないことを、図形画像をテキストアートで出力しながら自分の目で確かめます。
**難易度** ⭐ / **前提** なし (lecture03 level02 の NumPy 基礎があると楽です) / **想定時間** 25分

## 1. なぜ学ぶのか — ビジネスの視点

「AI が写真を見て不良品を見つける」と聞くと、コンピュータが人間のように「見ている」と想像しがちです。しかしコンピュータにとって画像は、最初から最後まで**数字の表**です。この事実を知らないと、ビジョン AI のプロジェクトで的外れな判断をしてしまいます。「なぜ解像度を落とすんですか? 画質がいい方がいいでしょう?」(数字が 4 倍に増えれば計算も 4 倍になります)、「照明が少し暗くても平気ですよね?」(すべての数字がまるごと小さくなり、モデルは混乱します) — こうした質問に自分で答えるには、「画像は数字である」という出発点が必要です。

Excel に慣れている方なら、むしろ有利です。画像一枚は**セルごとに明るさの数字が書き込まれたスプレッドシート一枚**とまったく同じものだからです。このレベルを終えると「画像処理」とは要するに「表の計算」であることが分かり、その感覚が lecture09 全体の土台になります。

## 2. たとえ話で理解する

**モザイク壁画**を思い浮かべてください。遠くから見ると人の顔ですが、近づいてみると小さな単色タイルが数千枚、格子状に張られているだけです。顔はタイルの中にはありません。**タイルの並び方の中に**あります。

デジタル画像はまさにこれです。タイル 1 枚が**ピクセル (pixel)**、タイルの色が**ピクセル値 (数字)**、タイルの枚数が**解像度 (resolution)** です。16×16 の画像はタイル 256 枚のモザイク、スマートフォンの写真 (4000×3000) はタイル 1,200 万枚のモザイクです。

もう一つのたとえは**座席表**です。ホールの座席表で「3 列 7 番」と言って席を探すのと同じように、画像でも `img[3, 7]` でピクセル 1 つをつまみ出します。行 (row) が先、列 (column) が後 — Excel の「行、列」と同じ順序だという点だけ覚えておけば大丈夫です。

## 3. 核心となる概念

### 3.1 白黒画像 = 2 次元の数字配列

白黒 (グレースケール、grayscale) 画像は `高さ × 幅` の形をした 2 次元配列です。各マスの数字が明るさです。

- 0.0 = 完全な黒、1.0 = 完全な白、0.5 = 中間のグレー (0〜255 の整数で表すこともあります)
- この講義の図形画像は 16×16、値が 0.0〜1.0 の float 配列です。

つまり、下の左側の「絵」と右側の「数字の表」はまったく同じものです。

```
■ □        1.0  0.0
□ ■        0.0  1.0
```

### 3.2 解像度 — タイル枚数のトレードオフ

解像度が高いほど細かく写りますが、数字の個数は縦×横に比例して爆発します。16×16 は 256 個、32×32 は 1,024 個 (4 倍)、1024×1024 は 100 万個を超えます。ディープラーニングでは入力の数字 1 つ 1 つが計算量なので、実務では「課題を解ける最小の解像度」を見つけることが重要な設計判断になります。不良検査で傷が 3 ピクセル分に写る解像度であれば十分で、それ以上はコストです。

### 3.3 明るさ — 数字の大きさ

画像の「明るい/暗い」は、単に数字が大きいか小さいかにすぎません。照明が半分に暗くなれば、すべてのピクセル値がおおよそ半分になります。同じ図形でも明るさが違えば数字の配列は大きく変わるので、ビジョンシステムを構築するときは「撮影条件の固定」がデータ品質の半分を占めます。(明るさをコードで調整する方法は level01 で扱います。)

### 3.4 カラーはどうなるのか — 予告

カラー画像は、赤・緑・青 (RGB) の明るさの表 3 枚を重ねたものです。つまり `高さ × 幅 × 3` の配列です。このレベルでは白黒だけを扱い、チャンネル (channel) の話は level01 で本格的に始めます。

### 3.5 今日使うデータ — 自分で描いた図形

この講義では有名なデータセットをダウンロードしません。`common/hjh_data.py` の `shape_images()` が numpy でその場で描いてくれる 16×16 の白黒図形 (四角形・円・三角形の 3 クラス) を使います。位置と大きさがランダムでノイズも混ざっているので、小さいながら「本物の分類問題」の性質をすべて備えています。

## 4. 実習 — main.py

実行:

```bash
python3 main.py
```

このプログラムは、図形画像を 3 つの表現 — 数字の表、テキストアート、PNG — で見せ、それらが「同じデータ」であることを確認させます。

- **[1]** `shape_images()` で図形画像を作り、配列の形 (shape)・値の範囲・クラス構成を出力します。
- **[2]** 画像 1 枚を**小数の数字の格子**としてそのまま出力します。画面を埋め尽くす 0.0 と 1.0 の間に、図形の輪郭が見えるか探してみてください。
- **[3]** 同じ画像を**テキストアート**として出力します。明るさの区間ごとに ` .:-=#@` のような文字を割り当てると、数字の格子が突然「絵」として読めるようになります。数字→文字の規則を 1 つ変えただけで人の目に図形が見える — これが「画像は数字である」の体験版です。
- **[4]** 解像度のたとえ: 16×16 の画像を 8×8、4×4 へと粗くしながら (2×2 ブロックの平均)、テキストアートで比較します。タイルが減るとどこかの時点で円と四角形が区別できなくなる — その境目を目で確かめてください。
- **[5]** クラスごとの図形サンプル 9 枚を `outputs/shapes_grid.png` に保存します。ファイルを開いてみてください — ここまでテキストで見てきたものと同じ配列です。

コードの核心部は `to_ascii()` 関数です。`int(v * (len(chars) - 1))` の 1 行で、明るさ 0〜1 を文字のインデックスに変換します。レンダリングとは結局「数字を見やすい記号に変える規則」にすぎないことを示す、5 行の関数です。

## 5. やってみよう

1. **(易しい)** `[3]` の文字パレット `" .:-=+*#@"` を逆順にひっくり返して実行してみましょう。図形が反転 (ネガ) して見えます。なぜそうなるのかを一文で説明してみてください。(ヒント: 暗いピクセルにどの文字が割り当てられるか)
2. **(中くらい)** `[4]` のブロック平均の代わりに、ブロックの**最大値**で縮小するように変えてみましょう。図形がより太く生き残ります。この方式の名前が、level04 で学ぶ「マックスプーリング」です。(ヒント: `block.mean()` → `block.max()`)
3. **(挑戦)** `shape_images(size=32)` で解像度を上げてテキストアートを出力してみましょう。ターミナルが狭いと行が折り返されます。1 ピクセルにつき文字 2 個 (`chars[idx] * 2`) を使うと縦横比が自然になる理由も考えてみてください。(ヒント: ターミナルの文字は縦に長いです)

## 6. よくある間違い

- **`img[x, y]` だと勘違いする**: NumPy の画像は `img[行, 列]` つまり `img[y, x]` の順序です。横座標を先に書くと、画像が 90 度回転したようなバグに出会います。
- **値の範囲の混同**: 0〜1 の float 画像と 0〜255 の整数画像を混ぜて使うと、画面が真っ白か真っ黒になります。配列を受け取ったらまず `min/max` を出力する習慣をつけましょう。
- **解像度 = 品質という思い込み**: 解像度はコストです。課題が要求する分だけ使うのが実務の基本です。
- **「コンピュータは図形を知っている」と考える**: 今の段階のコンピュータにあるのは、0.0 と 1.0 の配列だけです。数字の配列から「図形」という意味を取り出すことが、この講義の残り 11 レベルでやる仕事です。

## 次のレベルの予告

画像が数字なら、画像編集はつまり算数です。明るくする = 足し算、コントラストを上げる = 掛け算、反転 = 引き算。level01 では RGB カラーチャンネルも含めて、画像演算を numpy で自分の手でやってみます。
