# Lecture 09 · Level 02 — 畳み込み (Convolution) を理解する

> CNN の心臓である畳み込みを numpy でゼロから実装し、3×3 カーネルが図形のエッジを見つけ出す瞬間を目で確かめます。
**難易度** ⭐⭐⭐ / **前提** level01 / **想定時間** 40分

## 1. なぜ学ぶのか — ビジネスの視点

画像 AI 関連の技術文書・提案書・論文要約には、必ず「畳み込み (convolution)」「カーネル (kernel)」「フィルタ (filter)」という単語が出てきます。この単語をブラックボックスのままにしておくと、「CNN が特徴を抽出します」という説明が呪文のように聞こえ、検証できない話になってしまいます。

畳み込みの実体は驚くほど小さいものです。**小さな数字の板 (カーネル) を画像の上で滑らせ、重なったマス同士を掛けて足す。** このたった 1 つの演算が、ぼかし・シャープ化・エッジ検出といった古典的な画像処理と、最新の CNN の特徴抽出の両方を担っています。今日これをループで自分で書いてみれば、この後どんな CNN 構造に出会っても「結局あの掛け算と足し算を層状に積んだものだ」と読めるようになります。

## 2. たとえ話で理解する

**ハンコを押しながら書類を点検する**場面を想像してください。3×3 マスの透明な検査ハンコがあります。ハンコにはマスごとに重みの数字が書かれています。このハンコを大きな書類 (画像) の左上から右下まで、1 マスずつずらしながら押していきます。1 回押すたびにやることはただ 1 つ — **ハンコのマスの数字 × 書類のマスの数字を 9 組すべて掛けて合計し**、その合計を新しい書類の対応する位置に書き込むことです。

肝心なのは、ハンコに**どんな数字を刻むか**です。

- すべてのマスが 1/9 のハンコ → 周囲 9 マスの平均 = **ぼかし (blur)**
- 左の列が -1、右の列が +1 のハンコ → 「右は左より明るいか?」を測る検査 = **垂直エッジ検出**

つまりカーネルは**「この地域で何を探すか」が刻まれた検査ハンコ**であり、出力 (特徴マップ) は**検査結果の地図** — 「探しているパターンがどこにどれだけ強く現れたか」の表です。

## 3. 核心となる概念

### 3.1 演算の定義

入力画像 `I`、`k×k` のカーネル `K` に対して、出力の (y, x) の値は、カーネルをその位置に重ねて要素ごとの積をすべて足したものです。

```
out[y, x] = Σ_i Σ_j  I[y+i, x+j] * K[i, j]
```

コードにすればループ 2 つと `(patch * K).sum()` の 1 行です。main.py の `conv2d()` がまさにこの形です。

### 3.2 エッジ検出カーネルの読み方

垂直エッジのカーネル (ソーベル系) を読んでみましょう。

```
-1  0  +1
-2  0  +2
-1  0  +1
```

このカーネルの出力値 = (右の 3 マスの明るさの和) − (左の 3 マスの明るさの和)。左右の明るさが同じなら 0、**左が暗く右が明るい縦の境界線**では大きな正の値、逆向きの境界線では大きな負の値が出ます。これを 90 度回せば水平エッジのカーネルになります。「カーネル = 何に反応するかが書かれたパターン検出器」という文はここから出てきます。

### 3.3 出力サイズ・パディング・ストライド

- ハンコが書類の外に出ることはできないので、`n×n` の画像に `k×k` のカーネルを押すと、出力は `(n-k+1)×(n-k+1)` に**縮みます**。16×16 に 3×3 なら 14×14 です。
- サイズを保ちたければ、端に 0 の縁を巻いてから押します — **パディング (padding)**。
- 1 マスずつではなく 2 マスずつ飛ばして押すと、出力が半分のサイズになります — **ストライド (stride)**。計算量の節約と要約の効果があります。(式と層の設計は level03 で扱います。)

### 3.4 なぜ画像には畳み込みなのか

画像の 2 つの性質とぴったり噛み合うからです。

1. **局所性**: 「境界線かどうか?」は周囲の数ピクセルだけを見れば判断できます。3×3 のカーネルで十分な質問がたくさんあります。
2. **位置不変性**: 左上の縦の境界線と右下の縦の境界線は、同じパターンです。1 つのカーネルを画像全体で再利用する畳み込みは「同じ検査をすべての位置で実施する」ので、位置ごとに別々に学ぶ必要がありません。これが CNN が MLP より圧倒的にパラメータが少ない理由です (level05 で性能として確認します)。

### 3.5 手で刻んでいたカーネルは、今は学習で

古典的な画像処理では、専門家がソーベルやラプラシアンのようなカーネルを**手で設計**していました。CNN の革新はただ 1 つ — **カーネルの中の数字をデータに決めさせたこと**です。lecture06 level00 の「人間は規則の形だけを決め、数字はデータが決める」が、画像の世界で再現されたわけです。今日は手で刻んだカーネルで原理を確認し、level03 から学習されるカーネルへ移ります。

## 5. やってみよう

1. **(易しい)** `[3]` の垂直エッジカーネルの符号をすべて反転して実行してみましょう。特徴マップの明るい所と暗い所が入れ替わります。絶対値 (エッジ強度) には影響がないのはなぜか、説明してみてください。(ヒント: (+) と (−) の対称性)
2. **(中くらい)** 斜めエッジのカーネルを自分で設計してみましょう。三角形の斜辺で最も強く反応すれば成功です。(ヒント: `[[0,1,2],[-1,0,1],[-2,-1,0]]` のような形から出発)
3. **(挑戦)** `conv2d()` に `stride` 引数を追加して、stride=2 で図形を処理してみましょう。出力サイズが半分になってもエッジの大まかな位置は残っていることを PNG で確認してください。(ヒント: `range(0, H-k+1, stride)`)

## 6. よくある間違い

- **掛けてから足すことを「平均」と勘違いする**: 畳み込みは和 (sum) です。平均カーネルは、カーネルの値そのものを 1/9 にすることで実現しているのであって、演算が平均なのではありません。
- **負の出力に戸惑う**: エッジカーネルの出力が負になるのは正常です (方向の情報です)。そのまま imshow すると真っ黒に見えることがあるので、絶対値か対称的なカラーマップで見ましょう。
- **出力サイズが縮むことを忘れる**: 層を積んでいくと、3×3 のカーネルが毎層 2 ピクセルずつ削り取って、いつの間にか画像が消えてしまいます。なぜパディングを使うのかは、ここから出てきます。
- **カーネルは大きいほど良いという思い込み**: 7×7 を 1 つ使うより、3×3 を 2 層にした方が、同じ視野をより少ないパラメータでカバーできます。現代の CNN が 3×3 を標準として使う理由です。
