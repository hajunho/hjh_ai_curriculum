## 1. なぜ学ぶのか — ビジネスの視点

ビジョンモデルの導入を検討していると、「バックボーンは○○ネットで、3×3 コンブの 32 チャンネルから始めて…」といった話を聞くことになります。構造の説明書が読めないと、モデルの大きさ (コスト)、速度 (応答時間)、必要な解像度 (カメラの仕様) を自分で見積もれず、すべてベンダーの言葉に依存することになります。

CNN の構造読解の核心スキルは、たった 2 つです。**(1) 層を通るときデータの形 (shape) がどう変わるか、(2) 各層のパラメータが何個か。** この 2 つを計算できれば、どんな構造図も見積書のように読めます。今日はこの計算法を身につけ、コードで検算します。

## 2. たとえ話で理解する

CNN の 1 層は**検査ハンコを何本も持った検査チーム**です。

level02 ではハンコ (カーネル) が 1 本でした。実際の Conv2d 層はハンコを**何本も**持ちます。垂直エッジのハンコ、水平エッジのハンコ、丸い角のハンコ… ハンコが 16 本なら、検査結果の地図 (特徴マップ) も 16 枚できます。この「地図が何枚か」が**出力チャンネル (out_channels)** です。

次の層の検査チームは、元の画像ではなく**前のチームが作った地図 16 枚の束**を検査します。だから次の層のハンコは、16 枚を同時に貫いて見る立体的なハンコ (3×3×16) になります。これが**入力チャンネル (in_channels)** の意味です。層が深くなるにつれて、「エッジの地図の組み合わせ」→「角・曲線の地図」→「図形の部品の地図」へと検査内容が高次になっていきます。

最後に、地図をすべて見たうえで最終判定を下す**決裁ライン**が必要です。地図を一列に伸ばして (Flatten) 普通のニューラルネットワーク (Linear) に渡すと、「この証拠の組み合わせなら円 (circle) だ」という結論が出ます。

## 3. 核心となる概念

### 3.1 Conv2d の 5 大設定値

`nn.Conv2d(in_channels, out_channels, kernel_size, stride, padding)`

| 設定 | たとえ | 効果 |
|---|---|---|
| in_channels | 検査する地図の束の枚数 | 入力チャンネル数と必ず一致させる |
| out_channels | ハンコ (質問) の本数 | 出力の地図の枚数 = 表現力 |
| kernel_size | ハンコの大きさ | 一度に見る近傍の範囲 |
| stride | ハンコの移動の歩幅 | 2 なら出力の縦横が半分 |
| padding | 書類の端の余白 | 1 なら 3×3 カーネルでサイズ維持 |

### 3.2 出力サイズの公式 — この講義で最も頻繁に使う式

```
out = (in + 2*padding - kernel) / stride + 1
```

例: 入力 16、kernel 3、padding 1、stride 1 → (16+2-3)/1+1 = **16** (維持)。
stride 2 に変えると → (16+2-3)/2+1 = **8** (半分)。層を設計するたびにこの式で最後まで追跡してこそ、Flatten の直前のサイズ (= Linear 層の入力サイズ) が分かります。

### 3.3 パラメータ数の計算 — モデルの見積りを出す

- **Conv2d**: `out_ch × (in_ch × k × k) + out_ch` (最後の項はバイアス)。例: 1→8 チャンネルの 3×3 なら 8×9+8 = **80 個**。
- **Linear**: `out × in + out`。例: 256→3 なら 3×256+3 = **771 個**。

注目すべき点: Conv 層のパラメータは**画像の大きさとは無関係**です。ハンコは画像が大きくなっても同じハンコですから。一方で Flatten 後の Linear は画像の大きさに正比例します。だから CNN のパラメータの大半が後段の Linear に集まることがよくあり、それを減らすこと (プーリング、グローバル平均) が level04 のテーマにつながります。

### 3.4 活性化関数と層の積み上げ

畳み込みは掛け算と足し算だけの線形演算なので、間に非線形 (ReLU) を挟まないと、何層積んでも 1 層と同じになってしまいます (lecture08 level02 の復習)。そのため基本ブロックは `Conv → ReLU` であり、典型的な小型 CNN はこんな姿をしています。

```
入力 (1, 16, 16)
Conv(1→8, 3x3, pad 1) + ReLU     → (8, 16, 16)
Conv(8→16, 3x3, pad 1, stride 2) + ReLU → (16, 8, 8)
Conv(16→32, 3x3, pad 1, stride 2) + ReLU → (32, 4, 4)
Flatten                           → (512,)
Linear(512→3)                     → (3,)  # クラスのスコア
```

チャンネルは増やし (8→16→32)、空間は減らす (16→8→4) という流れ — 「場所の情報は要約し、意味の情報は豊かに」が CNN 設計の基本リズムです。

### 3.5 バッチ次元

PyTorch の画像テンソルは `(バッチ, チャンネル, 高さ, 幅)` の 4 次元です。画像 32 枚を一度に処理するなら `(32, 1, 16, 16)`。shape エラーの大半はこの 4 次元の規約を破ったことで起きるので、「B-C-H-W」の順序を口に馴染ませておいてください。

## 6. よくある間違い

- **Flatten サイズの計算ミス**: Linear 層の in_features が合わず `mat1 and mat2 shapes cannot be multiplied` というエラーが出るのは、CNN 入門の第 1 位のエラーです。いつも公式で最後まで追跡しましょう。
- **チャンネルの鎖を切る**: 前の層の out_channels ≠ 次の層の in_channels なら即エラーです。チャンネルはリレーのバトンです。
- **4 次元規約の違反**: `(16,16)` の画像をそのまま入れると失敗します。`unsqueeze` でバッチ・チャンネルの次元を作り、`(1,1,16,16)` にして入れる必要があります。
- **パラメータ数と計算量の混同**: Conv 層はパラメータは少ないものの、すべての位置で繰り返し計算するので計算量 (FLOPs) は大きくなりえます。「軽い」が必ず「速い」とは限りません。
