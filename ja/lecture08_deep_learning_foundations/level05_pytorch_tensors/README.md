## 1. なぜ学ぶのか — ビジネスの視点

level00〜04 でニューラルネットワークの原理を numpy ですべて実装しました。ここからは実務の言語に乗り換える番です。PyTorch は研究と産業の両方で最も広く使われているオープンソースのディープラーニングフレームワークで、以降のコンピュータビジョン・NLP・LLM 講義のコードはすべて PyTorch で書かれています。協力会社のモデルコードをレビューするときも、社内のデータサイエンティストと話すときも、求人票を読むときも、PyTorch は共通語です。そしてその共通語の「名詞」がテンソルです。テンソルの形 (shape)・データ型 (dtype)・装置 (device) の 3 つを読めるようになれば、初めて見るディープラーニングのコードでもデータの流れを追えるようになります。

## 2. たとえ話で理解する

**テンソル = エクセルシートの一般化 + 2 つの超能力。**

- 数字ひとつ (スカラー) はセル 1 個、ベクトルは 1 列、行列はシート 1 枚。テンソルはさらに進んで「シート何枚かの束」(3 次元)、「束の束」(4 次元) まで自然に拡張したものです。例: モノクロ画像 100 枚は (100, 16, 16) のテンソル。
- numpy 配列もここまでは同じです。テンソルの超能力は次の 2 つです。
  1. **自動微分**: 計算の過程を自分で帳簿に記録しておき、あとで微分 (責任の追跡) を自動でやってくれます。level04 で手作業だったことがタダになります。
  2. **GPU への引っ越し**: `.to('cuda')` の 1 行で計算場所を CPU から GPU に移します。引っ越しトラック 1 台で、同じ荷物 (データ) がはるかに大きな作業場で回り始めます。

**device は「どの机の上で働くか」** です。CPU の机、NVIDIA GPU の机 (cuda)、アップルシリコン GPU の机 (mps)。大事な規則がひとつ — 同じ机の上にある素材同士でしか演算できません。CPU テンソルと GPU テンソルを混ぜるとエラーになります。

## 3. 核心となる概念

### 3-1. テンソルの 3 属性: shape, dtype, device

エラーメッセージの 90% は、この 3 つのどれかが合っていないことから生じます。見慣れないテンソルに出会ったら、反射的に `x.shape, x.dtype, x.device` を確認する習慣をつけてください。

### 3-2. 形の変更とブロードキャスト

- `reshape` / `view` はデータを動かさず「見る窓」だけを変えます。要素 12 個は (3,4) とも (2,6) とも見られます。
- ブロードキャスト: (3,1) + (4,) のように形が違っても、規則 (後ろの次元から順に 1 か同じなら拡張) に合えば自動で伸ばして計算します。numpy と規則は同一です。

### 3-3. numpy との関係 — 共有 vs コピー

| 方法 | 動作 | 注意 |
|---|---|---|
| `torch.from_numpy(arr)` | **メモリ共有** (同じ紙を一緒に見る) | 片方を直すと他方も変わる |
| `t.numpy()` | **メモリ共有** (CPU テンソルのみ) | 上と同じ |
| `torch.tensor(arr)` | **コピー**を作る | 安全だがメモリは 2 倍 |

共有は速いのですが、「遠くで値が変わる」事故の原因にもなります。実習 [5] で自分の目で確かめます。

### 3-4. dtype — 精度とメモリの取引

float32 (4 バイト) が既定値です。float16 (2 バイト) はメモリを半分・速度を 2 倍にする代わりに、小数の下の桁を失います。この取引が level11 の混合精度 (mixed precision) 学習につながります。

### 3-5. なぜ numpy のままではいけないのか

「numpy でも level04 でニューラルネットワークを全部作れたのに、わざわざ乗り換える必要がありますか?」よい質問です。小さな実習なら numpy で十分です。ただし (1) 重みが数百万個になると微分を手で書くのはほぼ不可能で、(2) CPU だけでは学習時間が数百倍に伸び、(3) 検証済みの層 (layer)・オプティマイザ・データローダーといった部品を再利用できません。PyTorch はこの 3 つの問題をそれぞれ autograd、device、nn モジュールで解決します。つまり numpy が「手計算 + 紙の帳簿」なら、PyTorch は「会計システム」です。原理は同じでも、規模が変われば道具を変える必要があります。

### 3-6. この実習の限界について

今回のレベルのテンソルは、まだ「微分の機能を切った」状態です。`requires_grad` のスイッチを入れた瞬間からが本当のディープラーニングで、それが次のレベルです。

## 6. よくある間違い

- **整数テンソルでニューラルネットワークの計算をすること。** `torch.tensor([1, 2])` は int64 になります。重みの計算には float が必要なので、`[1.0, 2.0]` か `dtype=torch.float32` を明示してください。
- **共有とコピーの混同。** `from_numpy` で作ったテンソルを修正したら元の numpy 配列まで変わってしまう「幽霊バグ」になります。確信が持てないときは `clone()` してください。
- **device の不一致。** `RuntimeError: Expected all tensors to be on the same device` — モデルは GPU、データは CPU にあるときに出ます。データとモデルを同じ机へ移してください。
- **`view` の失敗にうろたえること。** 転置などでメモリが連続でなくなると `view` は拒否します。そのときは `reshape` か `contiguous().view()` を使えば大丈夫です。
