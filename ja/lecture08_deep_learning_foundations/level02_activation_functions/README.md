# Lecture 08 · Level 02 — 活性化関数

> 層をいくら積んでも非線形の活性化がなければ結局線形モデル 1 個と同じになるという事実を行列積で数値的に証明し、sigmoid/tanh/ReLU の形と勾配を図で比較しながら、勾配消失と死んだ ReLU の問題を理解します。

**難易度** ⭐⭐ / **前提** level01_perceptron_from_scratch / **想定時間** 50分

## 1. なぜ学ぶのか — ビジネスの視点

level00〜01 で私たちは 2 つのことを確認しました。直線 1 本 (線形モデル) では XOR のような絡み合った問題は解けず、座標変換 (隠れ表現) を経ると解ける、ということです。すると「線形変換を何層も積めばいいのでは?」という考えが自然に浮かびます。このレベルの最初の結論は冷徹です。線形の層は 100 個積んでも、数学的に線形の層 1 個と完全に同じです。層の間に非線形 (nonlinear) な関数、すなわち活性化関数 (activation function) を挟み込んで初めて、「深さ」が意味を持ちます。

実務でこの知識は 2 つの場面で役立ちます。第一に、ディープラーニングの道具を使うとき、ReLU、sigmoid といった名前が設定画面やコード例のあちこちに登場しますが、それぞれの性格を知っていれば、既定値がなぜそうなっているのか理解でき、むやみに変えなくなります。第二に、「モデルの学習が進まない」という報告を受けたとき、原因候補として勾配消失 (vanishing gradient) や死んだ ReLU (dead ReLU) といった診断用語を聞き取れるようになります。今日学ぶ内容は、ディープラーニングの歴史で実際に流れを変えた部品交換の物語でもあります。

## 2. たとえ話で理解する

決裁ラインを考えてみてください。担当者、課長、本部長が順に検討する 3 段階の決裁です。ところが 3 人とも「受け取った点数に一定の比率を掛けていくらか足して上へ回す」だけの機械的な仕事しかしないとしたらどうでしょう? 担当者が 2 倍にし、課長が 0.5 倍にし、本部長が 3 倍にするなら、3 段階を合わせた効果は結局「3 倍」という掛け算 1 回と同じです。ハンコが 3 つ押されただけで、判断は 1 回しか起きていないのです。これが線形の層だけを積んだニューラルネットワークの姿です。

決裁に意味があるためには、各段階に判断がなければなりません。「基準未満ならここで差し戻す」「一定金額以上は別トラックへ回す」のように条件によって違う反応をした瞬間、3 段階の決裁は掛け算 1 回に圧縮できない本物の 3 段階になります。活性化関数がまさにこの「判断」です。ReLU は「マイナスの点数は 0 に切り捨てる」きっぱりした差し戻し担当者であり、sigmoid はどんな点数も 0〜1 の確信度に言い換える慎重な報告者です。

勾配消失はこう例えられます。sigmoid 担当者は、点数がとても大きくてもとても小さくても、返事がほとんど「1 に近いです」または「0 に近いです」で固まってしまいます。この状態では入力を少し変えても反応がほとんど変わらず、「どちらの方向に直せば良くなりますか?」という質問 (勾配) に事実上無回答になります。フィードバックが層をさかのぼるほど小さくなり、下の層まで届かなくなること、それが勾配消失です。

## 3. 核心となる概念

### 3.1 なぜ非線形が必要か — 線形の合成は線形

行列で書けば 1 行です。3 つの層がそれぞれ W1, W2, W3 という行列の掛け算なら、全体は `y = W3 @ (W2 @ (W1 @ x)) = (W3 @ W2 @ W1) @ x` です。行列積には結合法則が成り立つので `W3 @ W2 @ W1` を先に掛けて 1 枚の行列 W にでき、3 層のネットワークは 1 層のネットワークと完全に同じになります。層の間に非線形関数 f を挟むと `W3 @ f(W2 @ f(W1 @ x))` となってこの圧縮が不可能になり、そこで初めて深さが表現力を生みます。実習ではこの 2 つのケースを数字で直接比較します。

### 3.2 代表的な活性化関数の比較

| 関数 | 式 | 出力範囲 | 特徴 |
|------|-----|-----------|------|
| sigmoid | 1/(1+e^-z) | (0, 1) | 確率のように解釈可能。両端で飽和 |
| tanh | (e^z - e^-z)/(e^z + e^-z) | (-1, 1) | 0 中心なので sigmoid より有利。やはり飽和 |
| ReLU | max(0, z) | [0, ∞) | 計算が安く、正の区間の勾配が 1。現代の既定値 |
| Leaky ReLU | z<0 で 0.01z | (-∞, ∞) | 負の区間にも小さな勾配を残す |

飽和 (saturation) とは、入力が大きくなったり小さくなったりしたときに出力が平らになる現象です。sigmoid の勾配は最大でも 0.25 (z=0) で、z=5 になっただけで約 0.0066 まで急落します。

### 3.3 勾配消失と死んだ ReLU

学習は「出力の誤差を各層の勾配と掛け合わせながら逆向きに伝える」方式で行われます (詳しい原理は後のレベルで扱います)。勾配が最大 0.25 の sigmoid を 10 層に挟むと、伝わる信号は最大に見積もっても 0.25 の 10 乗、約 100 万分の 1 のレベルまで縮みます。下の層は事実上、学習を止めてしまいます。これが深いニューラルネットワークが長い間うまくいかなかった核心の理由であり、正の区間で勾配が常に 1 の ReLU がこの問題を大きく緩和して標準になりました。

ただし ReLU にも弱点があります。あるニューロンの加重和がデータの全区間でマイナスになってしまうと、出力も 0、勾配も 0 で、二度と更新されません。これが死んだ ReLU です。負の区間に 0.01 のような小さな勾配を残しておく Leaky ReLU は、この危険を減らそうとする変種です。

- **[3]** 飽和を数字で確認します。sigmoid'(0)=0.25 が sigmoid'(5) でどこまで縮むか、その値を 10 層分掛けるといくつになるかを出力して勾配消失を体感し、死んだ ReLU と Leaky ReLU の違いも数値で見せます。

コードの核心部は `linear_stack_vs_single` 関数 (結合法則の確認) と `relu_breaks_linearity` 関数 (加法性の崩壊の確認) です。図のコードは関数ごとに色を固定して割り当て、導関数は近似ではなく解析的な公式で計算します。

## 6. よくある間違い

- **「層をたくさん積んだから複雑なモデルだ」と信じること。** 活性化関数がなければ 100 層も 1 層です。深さは非線形とセットのときにだけ意味を持ちます。
- **sigmoid を隠れ層の既定値として使うこと。** sigmoid は出力層で確率を表現するときには今でも有用ですが、深い隠れ層に使うと勾配消失を自ら招きます。隠れ層の既定値は ReLU 系です。
- **死んだ ReLU をデータの問題と誤解すること。** 学習中に一部のニューロンの出力が常に 0 になるのはよくある現象で、学習率が大きすぎたり初期化が悪いときにひどくなります。Leaky ReLU や学習率の調整が処方箋です。
- **導関数を数値微分だけで確認すること。** ReLU のように折れ点 (z=0) のある関数は、その点で数値微分が曖昧な値を出します。解析的な公式と併用して確認する習慣が安全です。
- **浮動小数点誤差 1e-15 を「違う」と読むこと。** [4] の最大誤差は 0 ではなくごく小さな数になることがありますが、これはコンピュータの小数計算の限界であり、2 つの計算が異なるという意味ではありません。
