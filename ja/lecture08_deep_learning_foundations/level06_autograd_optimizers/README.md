## 1. なぜ学ぶのか — ビジネスの視点

ディープラーニングが産業全体に広がった決定的な理由のひとつが自動微分 (automatic differentiation) です。もし微分を手で書かなければならないとしたら、層をひとつ変えるたびに数学専攻の人が逆伝播のコードを再導出する必要があったでしょう。autograd のおかげで「モデル構造を変える実験」が数分単位で可能になり、それがそのまま企業の実験速度 (iteration speed) になりました。実務の観点で、このレベルの収穫は 2 つです。ひとつ目、どの PyTorch 学習コードを開いても必ず出てくる 5 段階ループ (zero_grad → forward → loss → backward → step) が読めるようになります。ふたつ目、「オプティマイザは何を使うんですか?」という実務の定番質問に、根拠を持って答えられるようになります。

## 2. たとえ話で理解する

**autograd = 法人カードの自動記録。** level04 の numpy 逆伝播は「手書きの帳簿」でした。支出 (計算) があるたびに自分で書き込み、決算 (微分) のときに帳簿を逆にめくって責任を配分しました。autograd は法人カードです。`requires_grad=True` のカードで決済 (演算) すれば履歴が自動で記録され、`backward()` を呼んだ瞬間に決算 — つまり全パラメータについての責任追跡 (微分) — が自動で終わります。level04 で数値微分によって検証したとおり、この自動決算は数学的に正確です。

**オプティマイザ = 下山の戦略。** 勾配 (どちらが下り坂か) は autograd が教えてくれます。その情報をもとに「どう歩くか」が戦略です。

- **SGD**: 基本の歩き。勾配 × 学習率の分だけ移動。単純で正直です。
- **SGD + モメンタム**: 慣性のある歩き。同じ方向が続くと加速がついて、浅いくぼみを通り過ぎます。
- **Adam**: スマートウォッチをつけた登山家。方向の移動平均 (モメンタム) に加えて、パラメータごとに地形の険しさを記録して歩幅を個別に調節します。急な軸は慎重に、なだらかな軸は大股で。

## 3. 核心となる概念

### 3-1. requires_grad と backward

```
x = torch.tensor(2.0, requires_grad=True)   # 記録開始
y = x**2 + 3*x                              # 計算グラフがこっそり作られる
y.backward()                                # グラフを逆向きにたどって微分
x.grad                                      # dy/dx = 7.0
```

PyTorch は演算のたびに「何から何を作ったか」のグラフ (計算グラフ) を記録します。`backward()` はこのグラフを出力から入力の方向へ — まさに level04 の逆伝播と同じように — さかのぼりながら連鎖律を適用します。

### 3-2. 勾配は累積する — zero_grad が存在する理由

`backward()` は `grad` に値を**足します** (上書きしません)。2 回呼べば 7 + 7 = 14 になります。だから学習ループの各ステップの 1 行目が `opt.zero_grad()` なのです。これを忘れると過去のステップの勾配が積み上がり続け、loss が乱れる「幽霊バグ」になります。

### 3-3. 標準の 5 段階学習ループ

```
opt.zero_grad()      # 1. 帳簿を白紙に
p = model(X)         # 2. 順伝播
loss = loss_fn(p, y) # 3. 採点
loss.backward()      # 4. 逆伝播 (level04 の 30 行)
opt.step()           # 5. 重みの更新 (level03 の x -= lr*grad)
```

以降どのレベル・どの講義でも、この 5 行の骨格は変わりません。

### 3-4. オプティマイザは状態を持つ

SGD は勾配だけを見て歩きますが、モメンタムや Adam は「これまでの移動の記録」を内部に保存します。Adam はパラメータ 1 個あたり移動平均を 2 個 (方向、大きさ) 保持するので、モデルパラメータの約 2 倍のメモリを追加で使います。小型モデルでは無視できる量ですが、数十億パラメータのモデルではこのオプティマイザの状態が GPU メモリの大きな割合を占めます — level11 のメモリ見積もりでこの数字がまた登場します。

### 3-5. SGD vs Adam — いつ何を

| | SGD(+モメンタム) | Adam |
|---|---|---|
| 歩幅 | 全パラメータ共通 | パラメータごとに自動調節 |
| 学習率への敏感さ | 高い (チューニング必須) | 低い (既定値 0.001 でおおむね無難) |
| 典型的な用途 | ビジョンモデルの最終性能の詰め | 最初の試行の既定値、NLP/LLM の標準 |

実務のコツ: **まず Adam で始めて**素早くベースラインを作り、性能を詰める段階で SGD+モメンタム+スケジュール (level10) を試します。

## 6. よくある間違い

- **zero_grad の忘れ。** 最もよくある間違いの第 1 位です。loss が下がっていたのに乱れ始めたら、まずこれを確認してください。
- **`loss.backward()` を 2 回呼ぶこと。** 計算グラフは backward のあと既定で解放されます。同じグラフにもう一度呼ぶと RuntimeError — ループでは毎ステップ forward からやり直します。
- **評価コードで記録を無駄にすること。** 推論だけのときは `with torch.no_grad():` で帳簿の記録を切らないと、メモリと時間が無駄になります (次のレベルで使います)。
- **`.item()` なしで loss をリストに保存すること。** テンソルをそのまま集めると計算グラフまで抱え込んでメモリが漏れます。数値だけ必要なら `loss.item()` です。
