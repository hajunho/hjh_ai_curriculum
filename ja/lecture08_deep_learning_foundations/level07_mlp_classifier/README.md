# Lecture 08 · Level 07 — MLP 分類モデルを作る

> nn.Module で自分だけの多層パーセプトロン (MLP) を組み立て、サブスク解約データでロジスティック回帰と真っ向勝負させます。結果は予想と違うかもしれません。

**難易度** ⭐⭐⭐ / **前提** level06 (autograd・オプティマイザ)、lecture06 level05 (ロジスティック回帰) / **想定時間** 55分

## 1. なぜ学ぶのか — ビジネスの視点

ここで初めて、ディープラーニングを「おもちゃの問題 (XOR)」ではなく**ビジネスデータ**に適用します。サブスクリプションサービスの解約予測は、マーケティング予算の配分に直結する代表的な実務課題です。同時にこのレベルは、大事な現実感覚を植えつけてくれます — 表 (テーブル) 形式のデータでは、ディープラーニングが単純なロジスティック回帰に常に勝つわけではない、ということ。「うちもディープラーニングを導入しましょう」という会議で、あなたは「まず単純なモデルと比較実験をしてみませんか」と言える人になります。また、PyTorch 実務コードの標準骨格である `nn.Module` クラスの書き方は、以降すべての講義 (CNN、Transformer) の基礎文法です。

## 2. たとえ話で理解する

**nn.Module = レゴの組立説明書。** モデルクラスは 2 つの部分に分かれます。

- `__init__`: **部品箱を開ける段階。** 必要なブロック (Linear 層、ReLU、Sigmoid) を宣言して箱に入れておきます。このとき各 Linear ブロックの中の重みが自動で作られ、`model.parameters()` でオプティマイザにまとめて渡せるようになります。
- `forward`: **組み立ての手順書。** 入力が来たらブロックをどの順に通すかを書きます。`model(X)` と呼べば PyTorch が自動で forward を実行します。

**ロジスティック回帰 = 隠れ層 0 個のニューラルネットワーク。** lecture06 で学んだロジスティック回帰は、実は `Linear(6,1) + Sigmoid` — つまり最も小さいニューラルネットワークです。ニューラルネットワークは、ロジスティック回帰の「手前」に特徴量を加工する隠れ層 (自動フィーチャーエンジニアリング班) を付けただけのものです。ですから今回の対決は、「特徴量加工の班を新しく採用したら成果は上がるのか?」という実験でもあります。

## 3. 核心となる概念

### 3-1. 隠れ層の設計感覚

- **幅**: 入力 6 個 → 16 → 8 → 1 のように、だんだん狭くなるじょうご型が無難な出発点です。
- **深さ**: 表データなら隠れ層 1〜2 層で十分な場合がほとんどです。層を増やすほど表現力は増えますが、過学習と学習の難しさも増えます (level09)。
- **パラメータ数の感覚**: ロジスティック回帰 7 個 vs MLP 257 個。パラメータは 37 倍でも、性能が 37 倍になるわけではありません。

### 3-2. 標準化とデータリーク

特徴量の単位がまちまちだと (契約月数 1〜60、月額料金 9,900〜29,900 KRW)、勾配降下がふらつきます。そこで平均 0、標準偏差 1 に標準化します。ただし、**平均・標準偏差は学習データだけで計算**しなければなりません。テストデータを混ぜて計算すると、試験問題を先に見たのと同じ (データリーク) になります。`customer_id` を特徴量から外したのも同じ理屈 — 意味のない識別子は過学習の材料にしかなりません。

### 3-3. model.eval() と no_grad

- `model.eval()`: 「いまは試験時間」モードへの切り替え。ドロップアウト (level09) のような学習専用の動作をオフにします。
- `torch.no_grad()`: 評価中は微分の帳簿への記録を切って、メモリと時間を節約します。

この 2 つは役割が違うので、評価のときは**両方**使うのが標準です。

### 3-4. 不均衡データでの成績表の読み方

解約率が 13〜18% なら、「全員が継続」と答えるだけで正解率 85% 前後が出ます。ですから正解率だけを見てはいけません。解約 (陽性) クラスの**適合率** (解約と答えたもののうち本当だった割合) と**再現率** (本当の解約のうち捕まえられた割合) を一緒に見ます。lecture06 level06 の「正解率の罠」そのままです。

### 3-5. では表データには何を使うのか

実務感覚で整理すると、こうなります。表形式データの第 1 候補はロジスティック回帰と木 (ツリー) 系 (lecture06 のランダムフォレスト、ブースティング) です。ニューラルネットワークが表データで明確に有利になるのは、(1) 特徴量どうしの相互作用が複雑でデータが非常に多いとき、(2) 画像やテキストのような非構造データと表を一緒に入れるとき、(3) 埋め込み (embedding) で ID 型の特徴量 (商品 ID など) を圧縮表現する必要があるときです。「まず単純なモデルでベースラインを作り、ニューラルネットワークはそのベースラインを超えて初めて採用」が健全なプロセスです。

## 4. 実習 — main.py

実行:

```bash
cd lecture08_deep_learning_foundations/level07_mlp_classifier
python3 main.py
```

出力の順序:

- **[1]** churn_table の 2000 件を 75:25 に分けて標準化します。「全員が継続と答える」ベースライン (約 87%) を先に出力します。
- **[2]〜[3]** ロジスティック回帰 (パラメータ 7 個) と MLP (257 個) を同じ条件 (Adam、800 エポックの full-batch) で学習します。MLP の train loss のほうが低く下がります (表現力が大きいので当然です)。
- **[4]** テスト性能: 正解率はどちらもベースライン近く (0.85〜0.87) で、再現率はどちらも低いままです。train loss の優位がテストの優位につながらない — これが核心の観察です。
- **[5]** MLP のしきい値を 0.5 → 0.3 に下げると、正解率をわずかに譲って再現率が 0.09 → 0.24 に跳ね上がります。モデルを再学習しなくても、ビジネスの目的 (解約顧客を取りこぼさない) に合わせて調整できるのです。
- **[6]** 解釈: このデータの解約ルールはほぼ線形なので、MLP の利点は小さいです。「ディープラーニングが常に勝つわけではない」ことをデータで確認します。

コードで見るべきところは `ChurnMLP` クラスです。`__init__` の部品宣言と `forward` の組み立て — この 2 マス構造が、すべての PyTorch モデルの骨格です。

3. **(挑戦)** しきい値を 0.1〜0.9 まで走らせて、適合率・再現率の表を作ってみましょう。「解約顧客を 1 人取りこぼすと 5 万 KRW の損失、クーポン送付 1 件に 5 千 KRW」という仮定で、総コストが最小になるしきい値を探してみてください。*ヒント: for 文で evaluate(threshold=...) を繰り返せば大丈夫です。*

## 6. よくある間違い

- **forward を直接呼ぶこと。** `model.forward(X)` ではなく `model(X)` と呼んでください。後者はフック (hook) などの内部手続きを正しく通ります。
- **標準化の統計量を全データで計算すること。** よくあるデータリークです。必ず学習セットだけで計算してテストに適用します。
- **BCELoss とロジットの混用。** モデルの末尾に Sigmoid を置いたなら BCELoss、置いていないなら BCEWithLogitsLoss です。混ぜると静かに性能が壊れます (後者のほうが数値的に安定なので実務では好まれます)。
- **train loss だけを見て勝者を判定すること。** 表現力の大きいモデルは train loss ならほぼ必ず勝ちます。判定は必ずテスト/検証の性能で。
