# Lecture 08 · Level 03 — 損失関数と勾配降下法

> モデルの学習とは「採点表 (損失関数) のスコアが下がる方向へ少しずつ移動すること」だということを、1 変数関数の上で目で確かめます。

**難易度** ⭐⭐⭐ / **前提** level02 (活性化関数) / **想定時間** 45分

## 1. なぜ学ぶのか — ビジネスの視点

ディープラーニングのプロジェクト会議で最もよく出てくる言葉が「loss が下がりません」「学習率を下げてみましょう」です。損失関数 (loss function) と勾配降下法 (gradient descent) を知らないと、この会話に加われません。逆にこの 2 つさえ知っていれば、開発会社から届いた学習ログを見て「loss が跳ねているのを見ると、学習率が大きいのでは?」と言えるようになります。モデルの種類が何であれ — 解約予測の MLP でも、チャットボット用の LLM でも — 学習の骨格はすべて「損失を定義し、勾配に沿って降りる」のひとつです。ここで学ぶ原理は、以降のすべてのレベルで一度も変わることなく再利用されます。

## 2. たとえ話で理解する

**霧のかかった山を下山する。** 濃い霧の中、山の中腹に立っていると想像してください。地図もなく、頂上も谷も見えません。唯一分かるのは**足元の傾斜** — どちらが下り坂かだけです。合理的な戦略はひとつです。下り坂の方向へ一歩歩き、また足元を確認して、もう一歩。これが勾配降下法のすべてです。

- **山の高さ** = 損失 (loss)。モデルがどれだけ間違えたかのスコアです。低いほど良い。
- **現在位置** = モデルのパラメータ (重み) の値。
- **足元の傾斜** = 勾配 (gradient)。微分が教えてくれます。
- **歩幅** = 学習率 (learning rate)。このレベルの主役です。

歩幅が短すぎると、日が暮れても谷にたどり着けません。歩幅が大きすぎると谷をひょいと飛び越えて反対側の崖へ、さらに高いところへ — かえって山を「登って」しまいます。実習でこの 3 つのケースをすべて再現します。

## 3. 核心となる概念

### 3-1. 損失関数 = モデルの採点表

損失関数は「モデルの予測が正解からどれだけ遠いか」を数字ひとつに要約します。問題のタイプによって標準の採点表が異なります。

| 問題 | 損失関数 | 直感 |
|---|---|---|
| 回帰 (売上予測) | MSE (平均二乗誤差) | 誤差を二乗して平均。大きなミスに大きな罰点 |
| 二値分類 (解約の有無) | 二値クロスエントロピー (binary cross-entropy) | 「正解に割り当てた確率」が低いほど大きな罰点 |
| 多クラス分類 (図形 3 種) | クロスエントロピー | 上と同じ、クラスが複数 |

なぜ分類に MSE を使わないのでしょう? 確率出力 (0〜1) に MSE を使うと、間違えたときの罰点が十分に急峻でなく、学習が遅くなります。クロスエントロピーは「正解の確率を 0.01 と予測」した場合の罰点を幾何級数的に大きくし、確信に満ちた誤答を強く矯正します。

### 3-2. 勾配 = 足元の傾斜計

勾配 (微分) は「今の位置で x をほんの少し大きくしたら損失がどれだけ変わるか」です。勾配が正なら右が上り坂なので左へ、負なら右へ移動します。更新式はこの 1 行です。

```
x_new = x_old - 学習率 × 勾配
```

マイナスが付く理由: 勾配は「上り坂の方向」を指すので、下山するには逆へ行かなければなりません。

### 3-3. 学習率 — 最も重要なダイヤル

| 学習率 | 症状 | ログで見える姿 |
|---|---|---|
| 小さすぎ | 収束にいつまでもかかる | loss がとてもゆっくり、しかし着実に減少 |
| 適度 | 数ステップで谷に到着 | loss が速く落ちてから平らになる |
| 大きすぎ | 谷を跳び越え続ける | loss が振動または爆発 (NaN) |

実務のコツ: 最初は 0.1、0.01、0.001 のように 10 倍間隔でざっと試し、最も速く安定的に下がる値の近くを使います。

### 3-4. 数値微分 — 微分の検算機

微分の公式を手で実装すると間違えやすいものです。そこで `(f(x+h) - f(x-h)) / 2h` (中央差分) で「ほんの少し動かしてみて実際の変化量を測る」検算をします。次のレベル (誤差逆伝播) では、この検算テクニックが核心の道具になります。

コードの核心部は `gradient_descent()` 関数のたった 1 行、`x = x - lr * grad_f(x)` です。ディープラーニングフレームワークのオプティマイザも、本質はこの 1 行の高級な変形です。

## 5. やってみよう

1. **(易しい)** 学習率を 0.15 の代わりに 0.05、0.3 に変えて実行してみましょう。何ステップで谷に到着するか比較してみてください。*ヒント: `settings` リストの数字を変えるだけです。*

## 6. よくある間違い

- **学習率を一度決めて最後まで変えないこと。** 学習が進まないときは、モデル構造よりまず学習率を疑ってください。10 倍単位で調節します。
- **符号のミス。** `x + lr * grad` と書くと山を登ります。loss が着実に「増加」するなら、十中八九、符号か学習率の問題です。
- **局所最小値恐怖症。** 「谷がいくつもあったらどうしよう?」という心配は 1〜2 次元の直感です。実際の高次元ニューラルネットワークでは局所最小値より鞍点・平坦な区間が問題であり、たいていは「十分に良い」谷にたどり着きます。
- **loss の値そのものを性能と勘違いすること。** loss は下山の進行状況にすぎず、ビジネスの性能 (精度・再現率) は別に測る必要があります。

## 次のレベルの予告

勾配を「変数 1 個」で計算する方法を学びました。ところがニューラルネットワークには重みが数千〜数十億個あります。すべての重みの勾配を一度に、効率よく計算するアルゴリズムが**誤差逆伝播 (backpropagation)** です。level04 では numpy だけで誤差逆伝播をゼロから実装し、XOR 問題を自分の手で解いてみます。
