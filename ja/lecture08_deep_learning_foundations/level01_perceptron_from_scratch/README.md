## 1. なぜ学ぶのか — ビジネスの視点

巨大な言語モデルも、結局はとても単純な部品数十億個の組み合わせです。その部品のひとつがパーセプトロン (perceptron)、すなわち人工ニューロンです。部品 1 個の動作を正確に理解すれば、この後に出てくる「層を積む」「重みを学習する」「モデルが収束する」といった言葉が、もう魔法のようには聞こえなくなります。

実務の観点でこのレベルの本当の収穫は、学習 (learning) という言葉の実体を見ることです。AI が学習するというのは神秘的なことではなく、「予測して、間違えた分だけ数字を少し直し、また予測する」という繰り返しの作業です。この感覚があれば、協力会社が「モデルを再学習しました」と報告してきたときに、何をどれだけやったという意味なのか、なぜ学習に時間がかかるのか、なぜある種の問題はいくら学習してもだめなのか (XOR のように) を判断できるようになります。最後の失敗のデモは特に重要です。道具の限界を知っている人だけが、道具を正しく選べるからです。

## 2. たとえ話で理解する

パーセプトロンは会議での加重投票のようなものです。ひとつの議案について、複数の出席者が賛成 (1) または反対 (0) の意見を出します。ただし全員の発言権が同じとは限りません。チームリーダーの意見には重み 3、新人の意見には重み 0.5 が付く、といった具合です。各意見に発言権を掛けて全部足した値が可決ラインを超えれば議案は可決、超えなければ否決です。ここで出席者たちの意見が入力 (x)、発言権が重み (w)、基準線を調整する値がバイアス (b) です。

では学習とは何でしょうか? この会議体が下した決定を、後で結果と突き合わせることです。可決したのに結果が悪かったなら (正解 0、予測 1)、賛成票を投じた人たちの発言権を少し減らします。否決したのに実は良い議案だったなら (正解 1、予測 0)、賛成していた人たちの発言権を少し増やします。決定が正しかったなら何も変えません。この単純な人事調整を議案 (データ) ごとに繰り返すと、発言権の配分が少しずつ「良い決定を下す配分」へ移っていきます。これがパーセプトロンの学習規則のすべてです。

ひとつ先にお伝えしておくと、この会議体は委員会が 1 つだけの単層構造なので、level00 で見た直線 1 本の限界をそのまま受け継ぎます。XOR のように直線で分けられない問題の前では、発言権をいくら調整しても永遠に結論が行ったり来たりします。

## 3. 核心となる概念

### 3.1 パーセプトロンの計算

入力 x1, x2 に対して、パーセプトロンは 2 段階で計算します。

1. 加重和: `z = w1*x1 + w2*x2 + b`
2. ステップ関数 (step function): `z >= 0` なら 1、そうでなければ 0 を出力

level00 の線形モデルと計算式は同じです。違いは係数の求め方です。level00 では最適な直線を公式 (最小二乗法) と全数探索で見つけましたが、パーセプトロンはデータを 1 件ずつ見ながら漸進的に見つけていきます。

### 3.2 パーセプトロンの学習規則

データ (x, 正解 y) を 1 つ見て予測 p を出したとき、更新は次の 1 行です。

```
w <- w + lr * (y - p) * x
b <- b + lr * (y - p)
```

ここで lr は学習率 (learning rate) で、一度にどれだけ大きく直すかを決める歩幅です。`(y - p)` は 0 (正解)、+1 (1 なのに 0 と予測)、-1 (0 なのに 1 と予測) の 3 つの値しか取らないため、正解ならそのまま、間違えたら間違えた方向の逆へ押すルールだと分かります。データ全体を一周することをエポック (epoch) と呼び、1 エポックの間に一度も間違えなければ学習が収束 (convergence) したことになります。

### 3.3 収束定理とその限界

パーセプトロンには有名な保証がひとつあります。データが直線 (高次元では超平面) で分けられる問題なら、この規則は有限回の修正のうちに必ず収束します。AND と OR がこれに該当します。逆に XOR のように直線で分けられない問題では、収束は原理的に不可能です。どんな重みでも間違える点が最低 1 つ残り、その点を直そうとする更新が別の点をまた間違えさせて、重みが永遠に振動します。実習ではこの振動を数字で直接見ることになります。

## 4. 実習 — main.py

実行方法は次のとおりです。

```bash
cd lecture08_deep_learning_foundations/level01_perceptron_from_scratch
python3 main.py
```

出力は 4 段階です。

- **[1]** 約 30 行の `Perceptron` クラスを紹介し、初期の重み (シード固定の乱数) を見せます。
- **[2]** AND の学習: エポックごとに `w1, w2, b` とそのエポックの誤分類 (間違えた予測) 数を 1 行ずつ出力します。誤分類が 0 になった瞬間に収束を宣言し、最終的な真理値表の検証を見せます。
- **[3]** OR の学習: 同じ過程を繰り返します。AND より速く、または同じくらいで収束する様子が見られます。
- **[4]** XOR の学習: エポック上限 (25 回) まで回しても誤分類が 0 になりません。重みがエポックの中であちこち直されては結局元の場所へ戻る振動 (循環) に囚われ、精度が 50% にとどまる様子を見せます。最後に「構造を変えなければならない」という結論で締めくくります。

コードで注目すべき場所は `fit` メソッドの中の更新 2 行です。3.2 節の数式が numpy のコードにそのまま移されています。また `errors == 0` のときに早期終了する部分は、「収束」の定義をコードとして書いたものです。出力で重みがエポックごとにどう動くか追ってみると、学習とは結局、3 つの数字が落ち着き先を見つけていく過程であることが目に見えます。

## 5. やってみよう

1. **(易しい)** 学習率 `lr` を 0.1 から 0.5 に、さらに 0.01 に変えて実行してみましょう。収束までにかかるエポック数はどう変わりますか? ヒント: 歩幅が大きいと速く動きますが行き過ぎることがあり、小さいと安定しますが時間がかかります。このデータは小さいので差が目立たないかもしれません。
2. **(普通)** `Perceptron` の初期化のシードを 7 から別の値に変えて何度か実行してみましょう。最終的な重みが実行のたびに違うのに、真理値表は全部正解します。「正解の直線はひとつではない」という事実を確認し、それでも再現性のためにシードを固定する理由を考えてみてください。
3. **(挑戦)** NAND (両方 1 のときだけ 0) を学習させるコードを [3] の後に追加してみましょう。そして手作りした 2 つのパーセプトロンの出力、つまり NAND の結果と OR の結果を新しい入力として 3 つ目のパーセプトロンに AND を学習させると、全体が XOR になります。ヒント: level00 の隠れ表現と同じ構造です。パーセプトロンを 3 個つなぐと 2 層のニューラルネットワークになります。

## 6. よくある間違い

- **XOR の失敗を見てコードのバグを疑うこと。** 誤分類が 0 に落ちないのはバグではなく、このレベルの核心の結果です。単層構造の数学的限界です。
- **エポックと更新回数を混同すること。** エポック 1 回はデータ 4 件をすべて一周することで、更新はそのうち間違えた件数だけ起こります。
- **学習率を大きくすれば必ず速くなると考えること。** この例は小さいので目立ちませんが、実戦では大きすぎる学習率が発散 (値が跳ねて永遠に収束できない) の主犯です。
- **重みの初期値をすべて 0 にすること。** パーセプトロン 1 個なら 0 から始めても学習できますが、後の多層ニューラルネットワークではニューロンが全員まったく同じに動いて学習が壊れます。今のうちから小さな乱数で初期化する習慣をつける理由です。
- **ステップ関数の境界 (`z = 0`) の処理を忘れること。** `>=` か `>` かによって境界上の点の分類が変わるので、実装と説明を一致させる必要があります。
