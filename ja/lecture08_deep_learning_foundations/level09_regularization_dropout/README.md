# Lecture 08 · Level 09 — 過学習を防ぐテクニック

> わざと過学習の事故を起こしたうえで、ドロップアウト・weight decay・早期終了という 3 つの処方が検証性能をどれだけ回復させるかを、統制された実験で比較します。

**難易度** ⭐⭐⭐⭐ / **前提** level08 (学習ループ・バッチ・エポック) / **想定時間** 60分

## 1. なぜ学ぶのか — ビジネスの視点

過学習 (overfitting) は、ディープラーニングのプロジェクトが失敗する経路の第 1 位です。開発段階の成績表は華やかなのに、リリース後に性能が崩れる事故 — 「デモではうまくいったんですけどね」の正体は、たいていこれです。恐ろしいのは、過学習が静かにやって来ることです。train の指標だけを見ていると、すべてが良さそうに見えます。このレベルを終えると、皆さんは (1) 学習曲線から過学習を早期に発見し、(2) 状況に合った処方を選び、(3) 「このモデルの性能の数字は信じていいんですか?」という質問に検証体制の観点から答えられるようになります。lecture06 level09 で木モデルの過学習を見たなら、今回はニューラルネットワーク版 + ニューラルネットワーク固有の処方 (ドロップアウト) です。

## 2. たとえ話で理解する

**過学習 = 過去問の丸暗記。** 学習データ 120 件、モデルのパラメータ 4,700 個。問題 120 問をパラメータ 4,700 個で勉強するのは、試験範囲全体を理解する代わりに過去問 120 問の答えをまるごと暗記するのと同じです。過去問 (train) は 100 点、本番 (valid) は転落します。

3 つの処方もすべて「暗記できないように邪魔すること」です。

- **ドロップアウト (dropout) = ランダム欠勤トレーニング。** 訓練のたびにチームメンバー (ニューロン) の半分がランダムに欠勤します。「あの案件は佐藤さんしか分からない」式の特定ニューロンへの依存 (共適応) が不可能になり、全員がお互いをカバーできる一般的な知識を身につけます。本番 (評価) のときは全員出勤します — これが `model.train()`/`model.eval()` の切り替えの正体です。
- **weight decay = 大きな重みへの課税。** 特定の入力ひとつに極端に依存する (重みが大きい) 答案ほど税金がかかります。モデルは「複数の根拠を少しずつ反映する」穏当な答案を好むようになります。
- **早期終了 (early stopping) = 成績の頂点で下山。** 模試 (valid) の点数が下がり始めたら、まだ勉強 (エポック) が残っていても、その時点の実力を最終版として採用します。

## 3. 核心となる概念

### 3-1. 過学習の条件: データに対して過剰な容量

パラメータ数 ≫ データ数のとき、モデルはデータを「理解」する代わりに「保存」できるようになります。実習の train 正解率 100% は自慢ではなく警告です — 解約するかどうかには本質的なランダム性があるので、正直なモデルなら train でも 100% は出ないからです。

### 3-2. ドロップアウトの動作

- 学習時: 各ニューロンの出力を確率 p で 0 にし、残った出力を 1/(1-p) 倍に補正 (信号全体の大きさを保つ)。
- 評価時: 何も切りません。`model.eval()` を忘れると評価のときも欠勤させてしまい、性能を削ります。
- 効果の別の解釈: 毎回違う部分ネットワークを学習させるので、たくさんの小さなモデルのアンサンブル (lecture06 level08) に近いものになります。

### 3-3. weight decay の動作

損失に重みの二乗和 × λ を足す L2 正則化と (SGD においては) 同等です。PyTorch では `optim.Adam(..., weight_decay=3e-2)` の引数ひとつで済みます。λ が大きいと過少適合に振れてしまうので (実習で train 正解率が 0.89 に下がったのがその兆し)、検証性能を見て調節します。

### 3-4. 早期終了の動作

エポックごとに valid loss を測り、最低記録が更新されたらモデルを保存します。一定エポック (patience) の間に更新がなければ中断し、保存版に戻ります。ほぼ無料 (追加の学習コスト 0) でありながら効果が大きいので、実務では事実上の標準装備です。

### 3-5. 処方の選び方ガイド

| 状況 | 第 1 候補の処方 |
|---|---|
| 何はともあれまず | 早期終了 (コスト 0、副作用が少ない) |
| 大きなネットワーク、データ不足 | ドロップアウト + weight decay の併用 |
| 差が激しく、予算がある | データ収集・データ拡張 (根本治療) |
| train の性能さえ低い | 過学習ではない — 正則化を緩めて容量・学習率を再検討 |

## 6. よくある間違い

- **評価のときに `model.eval()` を忘れること。** ドロップアウトがオンのまま評価されて、性能がばらつきます。逆に、学習を再開するときに `model.train()` に戻すのも忘れないでください。
- **早期終了の基準を train loss にすること。** train loss はほぼ必ず下がり続けるので、永遠に止まりません。基準は必ず valid です。
- **テストセットで早期終了すること。** valid で止める時点を選び、最終報告は手を付けていないテストで — そうしないとテストが実質的に学習に参加したことになります。
- **処方を全部最大にかけること。** ドロップアウト 0.5 + 強い weight decay + 早すぎる終了を一度にかけると、過少適合へ直行します。ひとつずつ入れて曲線で確認してください。

## 次のレベルの予告

過学習の次によくある事故は、「学習が不安定でうまくいかない」ケースです。level10 では、学習率を時間に応じて調節するスケジュール (warmup、cosine decay)、暴走する勾配を切り落とすグラディエントクリッピング、層ごとに目盛りを合わせ直すバッチ正規化で、学習を安定させる方法を実験します。
