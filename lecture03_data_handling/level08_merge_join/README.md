# Lecture 03 · Level 08 — 병합과 조인 (merge·concat)

> 매출표 + 지점정보표 + 목표표, 흩어진 표들을 이어 붙여 "목표 달성률"이라는 답을 만듭니다.

**난이도** ⭐⭐⭐ / **선행** level07_groupby_aggregation / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

표 하나로 끝나는 분석은 거의 없습니다. 매출은 POS 시스템에, 지점 정보(지역·개점연도·담당자)는 총무팀 명부에, 올해 목표는 기획팀 문서에 있습니다. "지점별 목표 달성률을 지역별로 보여 주세요"라는 흔한 요청 하나에 이미 표 세 개가 필요합니다.

엑셀에서는 VLOOKUP으로 이 일을 합니다. 그런데 VLOOKUP은 열 하나씩만 끌어오고, 키가 중복되면 첫 번째 것만 조용히 가져오며, 못 찾은 값은 #N/A로 흩어집니다. 판다스의 `merge`는 표 전체를 한 번에 잇고, 못 찾은 키·중복 키를 **검증하는 도구**까지 제공합니다. 데이터베이스의 JOIN과 같은 개념이라, 여기서 배운 감각은 lecture04의 SQL로 그대로 이어집니다.

병합은 강력한 만큼 사고도 가장 많이 나는 단계입니다. 행이 소리 없이 불어나거나 사라진 보고서는 병합 실수에서 나옵니다. 이번 레벨의 절반은 그 함정을 피하는 법입니다.

## 2. 비유로 이해하기

동창회 명단 만들기를 생각해 보세요. 손에는 두 장의 명단이 있습니다. **A: 졸업앨범 명단**(이름, 반), **B: 연락처 명단**(이름, 전화번호). 이름을 키(key)로 두 명단을 합치는 방법이 네 가지 있습니다.

- **inner(교집합)** — 양쪽 모두에 있는 사람만. "연락 가능한 확실한 동창"만 남습니다.
- **left(왼쪽 기준)** — 졸업앨범의 전원을 유지하고, 연락처가 없는 사람은 빈칸. "전원 명단 + 아는 연락처"입니다.
- **right(오른쪽 기준)** — 연락처 명단 전원 기준. left의 좌우 반대입니다.
- **outer(합집합)** — 어느 한쪽에라도 있으면 전부. "졸업앨범에 없는데 연락처엔 있는 사람"(전학생?)까지 드러나 **데이터 불일치를 찾는 용도**로 좋습니다.

그리고 함정 하나: 연락처 명단에 "김철수"가 **두 줄** 있다면? 합친 명단에 김철수가 두 줄 생깁니다. 앨범에도 두 줄, 연락처에도 두 줄이면 2×2=4줄이 됩니다. 이것이 병합의 최대 사고, **키 중복 폭발**입니다.

`concat`은 전혀 다른 작업입니다. 1반 명단 밑에 2반 명단을 **세로로 이어 붙이는 것**, 즉 옆으로 잇기(merge)가 아니라 아래로 쌓기입니다.

## 3. 핵심 개념

### 3-1. merge 기본형

```python
pd.merge(left_df, right_df, on="store", how="left")
```

- `on` : 양쪽 표에서 이름이 같은 키 열. 이름이 다르면 `left_on="store"`, `right_on="지점명"`처럼 따로 지정합니다.
- `how` : 결합 방식. `inner`(기본값), `left`, `right`, `outer`.

### 3-2. how 4종 선택 가이드

| how | 남는 행 | 대표 상황 |
|---|---|---|
| inner | 양쪽에 다 있는 키 | 확실한 데이터만으로 계산할 때 |
| left | 왼쪽 표 전부 | **기준 표가 정해져 있을 때 (실무 기본값)** |
| right | 오른쪽 표 전부 | left와 대칭 (표 순서를 바꿔 left로 쓰는 게 보통) |
| outer | 어느 쪽이든 있는 키 | 두 표의 불일치를 점검할 때 |

실무 감각: "매출표에 지점 정보를 **붙인다**"처럼 기준이 분명하면 left, "두 명부가 서로 맞는지 **감사한다**"면 outer입니다.

### 3-3. indicator=True — 병합 검증 습관

`pd.merge(..., how="outer", indicator=True)`를 쓰면 `_merge` 열이 생겨 각 행이 `both` / `left_only` / `right_only` 중 어디서 왔는지 표시됩니다. `value_counts()` 한 줄로 "짝 없는 키가 몇 개인지" 즉시 감사할 수 있습니다. 병합 후 이 검증을 습관으로 만들면 사고의 대부분을 예방합니다.

### 3-4. 키 중복 함정 — 행 수 폭발

오른쪽 표에 같은 키가 k번 나오면, 왼쪽의 해당 행은 k배로 불어납니다(카티전 곱, Cartesian product). 목표표에 강남점이 실수로 두 줄 들어 있으면, 병합 후 강남점 매출이 **두 번 집계**되어 총액이 뻥튀기됩니다. 예방책은 두 가지입니다.

1. 병합 전 `right_df["store"].duplicated().sum()`으로 중복 확인, 필요하면 `drop_duplicates()`.
2. 병합 전후 `len()` 비교 — 행 수가 예상과 다르면 즉시 멈추고 원인 조사.

### 3-5. concat — 쌓기

```python
pd.concat([first_half, second_half], ignore_index=True)
```

같은 구조의 표를 세로로 잇습니다(월별 파일 12개 합치기 등). `ignore_index=True`가 없으면 원래 인덱스가 그대로 남아 0,1,2,...,0,1,2,... 처럼 중복됩니다. 참고로 DataFrame에는 `join` 메서드도 있는데, 인덱스를 키로 쓰는 merge의 축약형이라 개념은 동일합니다.

## 4. 실습 — main.py

실행 방법:

```bash

```

시나리오: 매출표(집계) + 지점정보표 + 목표표를 병합해 목표 달성률 순위를 만듭니다. 지점정보표에는 일부러 **부산점이 빠져 있고**, 대신 매출표에 없는 **신규 "판교점"**이 들어 있습니다.

- **[1] 지점별 실적 집계** — level07의 groupby로 연간 총매출 표를 만듭니다 (5행).
- **[2] 보조 표 준비** — store_info(4개 지점 + 판교점)와 targets를 dict로 만듭니다.
- **[3] how 비교** — 같은 두 표를 inner/left/outer로 병합해 행 수가 4/5/6으로 달라지는 것을 확인하고, `indicator`로 `left_only`(부산점), `right_only`(판교점)를 찾아냅니다.
- **[4] 달성률 계산** — 목표표를 병합해 `달성률 = 실적/목표`를 만들고 내림차순 순위를 출력합니다.
- **[5] 키 중복 함정 시연** — 목표표에 강남점 중복 행을 주입하고 병합하면 행이 5→6으로 불어나며 총실적이 뻥튀기되는 것을 눈으로 확인한 뒤, `drop_duplicates`로 예방합니다.
- **[6] concat** — 상반기/하반기 집계를 세로로 쌓아 merge와의 차이를 확인합니다.

코드 핵심부는 [3]의 검증 패턴입니다.

```python
audit = pd.merge(perf, store_info, on="store", how="outer", indicator=True)
print(audit["_merge"].value_counts())
```

## 6. 자주 하는 실수

- **how를 생략하고 기본값(inner)인 걸 모르는 것** — 짝 없는 행이 소리 없이 사라집니다. 병합 전후 행 수를 반드시 비교하세요.
- **키 열의 표기 불일치** — "강남점" vs "강남 점"(공백), "GANGNAM" vs "gangnam"(대소문자)은 다른 키입니다. 병합 전 `str.strip()` 등으로 정규화하세요.
- **중복 키 방치** — 행 수 폭발과 이중 집계의 원인 1위입니다. `duplicated()` 확인 또는 `validate=` 인자를 쓰세요.
- **merge 할 일을 concat으로(또는 반대로)** — 열을 옆으로 붙이는 건 merge, 행을 아래로 쌓는 건 concat입니다. concat으로 옆에 붙이면 인덱스 기준으로 엉뚱하게 정렬될 수 있습니다.
- **suffixes 방치** — 양쪽 표에 같은 이름의 비(非)키 열이 있으면 `_x`, `_y`가 붙습니다. 어느 쪽이 어느 표인지 `suffixes=("_실적", "_목표")`처럼 명시하면 사고를 줄입니다.
