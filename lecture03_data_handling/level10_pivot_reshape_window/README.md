# Lecture 03 · Level 10 — 피벗·리셰이프·윈도우 연산

> 엑셀 피벗 테이블을 코드로 재현하고, 표의 모양을 자유자재로 바꾸며, 순위·누적·증감률로 리포트를 완성합니다.

**난이도** ⭐⭐⭐⭐ / **선행** level07 (level09 권장) / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

보고서에 들어가는 표는 대부분 "무엇 × 무엇" 형태의 2차원 요약표입니다. 지점 × 카테고리 매출표, 월 × 제품 판매표, 팀 × 분기 실적표처럼요. 엑셀 사용자라면 피벗 테이블(pivot table)로 수없이 만들어 봤을 그 표입니다.

Pandas의 `pivot_table`은 엑셀 피벗 테이블과 똑같은 일을 하지만 세 가지가 다릅니다. 첫째, 데이터가 100만 행이어도 몇 초 만에 끝납니다. 둘째, 코드로 남기 때문에 다음 달에 버튼 클릭을 반복할 필요 없이 재실행 한 번이면 됩니다. 셋째, 만든 피벗을 다시 분석 가능한 형태로 되돌리는 `melt`까지 세트로 제공합니다. 여기에 순위(rank), 증감률(pct_change), 누적합(cumsum) 같은 윈도우 연산을 얹으면 "지점별 순위", "누적 달성 현황" 같은 경영 보고의 단골 숫자가 전부 나옵니다.

## 2. 비유로 이해하기

**데이터의 모양 바꾸기는 옷장 정리와 같습니다.** 같은 옷이라도 "서랍마다 한 벌씩 개어 넣기"와 "옷걸이에 쭉 걸기"는 용도가 다릅니다.

- **긴 포맷(long format)**은 옷걸이에 쭉 건 상태입니다. 한 행이 "1월 1일, 강남점, 커피, 45만 원"처럼 사건 하나를 기록합니다. 기계(컴퓨터)가 다루기 좋은 모양이라, 필터·그룹화·병합이 전부 이 모양에서 이뤄집니다.
- **넓은 포맷(wide format)**은 서랍장에 개어 넣은 상태입니다. 행은 지점, 열은 카테고리, 칸에는 합계가 들어간 요약표지요. 사람이 한눈에 읽기 좋은 모양이라, 보고서와 발표 자료는 이 모양을 씁니다.
- `pivot_table`은 옷걸이(long) → 서랍장(wide)으로 개어 넣는 일, `melt`는 서랍장(wide) → 옷걸이(long)로 도로 꺼내 거는 일입니다. 분석은 long으로, 보고는 wide로 — 이 왕복이 실무 리듬입니다.

순위 연산은 달리기 시상식과 같습니다. 기록(매출)은 이미 있고, `rank`는 그 기록으로 등수를 매겨 주는 심판입니다. 전체 시상식(전사 순위)도 있고, 조별 시상식(카테고리별 그룹 내 순위)도 있습니다.

## 3. 핵심 개념

### 3-1. pivot_table의 네 가지 재료

```python
pd.pivot_table(df, index="store", columns="category",
               values="revenue", aggfunc="sum", margins=True)
```

| 인자 | 엑셀 피벗 테이블에서의 이름 | 뜻 |
|---|---|---|
| `index` | 행 영역 | 세로 축에 올 항목 |
| `columns` | 열 영역 | 가로 축에 올 항목 |
| `values` | 값 영역 | 칸에 채울 숫자 |
| `aggfunc` | 값 요약 방식 | sum, mean, count 등 |

`margins=True`를 주면 엑셀의 "총합계" 행·열이 붙습니다. 같은 (index, columns) 조합에 여러 행이 있으면 `aggfunc`로 뭉쳐 주기 때문에, 중복이 있어도 에러가 나지 않습니다(중복이 있으면 에러를 내는 `pivot`과의 차이입니다).

### 3-2. melt — 피벗을 도로 녹이기

`melt`는 wide 표를 long으로 되돌립니다. `id_vars`(그대로 둘 식별자 열)를 지정하면 나머지 열들이 "변수 이름(variable) / 값(value)" 두 컬럼으로 녹아내립니다. 왜 되돌릴까요? wide 표는 사람 눈에는 좋지만, 필터·그룹화·그래프 라이브러리는 대부분 long을 요구하기 때문입니다. "보고서용 표를 받았는데 다시 분석해야 하는" 상황에서 melt가 구원투수입니다.

### 3-3. rank — 순위 매기기

`s.rank(ascending=False)`는 큰 값이 1등이 되도록 순위를 매깁니다. 동점 처리 방식은 `method`로 정합니다(기본은 평균 순위, `method="min"`은 공동 1등 방식). 실무에서 진짜 자주 쓰는 것은 **그룹 내 순위**입니다.

```python
df.groupby("category")["revenue"].rank(ascending=False)
```

이렇게 하면 "커피 부문에서 강남점은 몇 등인가"처럼 조별 등수가 나옵니다. groupby(level07)와 윈도우 연산이 결합하는 대표 패턴입니다.

### 3-4. pct_change와 cumsum — 흐름을 읽는 연산

- `monthly.pct_change()`: 바로 앞 행 대비 증감률. level09에서 배운 그 연산을 월별 표에 적용하면 "전월 대비 성장률"이 됩니다.
- `monthly.cumsum()`: 누적합. 1월부터 이번 달까지 쌓인 누적 매출로, "연간 목표 대비 현재 몇 % 왔나"를 계산할 때의 분자입니다.

이런 연산들을 통틀어 윈도우 연산(window operation)이라 부릅니다. 집계(groupby)가 여러 행을 한 행으로 "줄이는" 반면, 윈도우 연산은 행 수를 유지한 채 각 행에 "주변 행을 참고한 값"을 붙여 줍니다. 이 차이가 중요합니다.

### 3-5. wide와 long, 언제 무엇을 쓰나

| 상황 | 포맷 |
|---|---|
| 필터·그룹화·병합 등 분석 작업 | long |
| 그래프 라이브러리 입력 | 대부분 long |
| 사람이 읽는 보고서·대시보드 표 | wide |
| CSV로 다른 팀에 전달 | long 권장 (재분석 가능) |

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture03_data_handling/level10_pivot_reshape_window
python3 main.py
```

출력 흐름은 다음과 같습니다.

- **[1] 지점 × 카테고리 총매출 피벗** — `pivot_table`에 `margins=True`를 주어 총합계까지 붙인 연간 리포트를 만듭니다. 억 단위로 반올림해 출력하므로, 어느 지점의 어느 카테고리가 효자인지 한눈에 보입니다.
- **[2] 요일 × 지점 평균 매출 피벗** — `aggfunc="mean"`으로 바꾸면 같은 함수가 전혀 다른 질문("요일 효과가 지점마다 다른가?")에 답합니다. 요일 순서가 가나다순으로 흐트러지는 것을 `reindex`로 월~일 순서로 바로잡는 것도 포인트입니다.
- **[3] melt로 되돌리기** — [1]의 피벗을 long 포맷으로 녹여, wide 25칸이 long 25행이 되는 것을 확인하고 두 포맷의 쓰임새를 비교합니다.
- **[4] 순위 분석** — 지점별 총매출 전사 순위(`rank`)와, 카테고리별 그룹 내 지점 순위(`groupby` + `rank`)를 구합니다. 전사 1등 지점이 모든 카테고리에서 1등인지 확인해 보세요.
- **[5] 월별 흐름** — 월별 매출에 `pct_change`(전월 대비 성장률)와 `cumsum`(누적 매출)을 붙인 월간 경영 요약표를 만듭니다.
- **[6] 리포트 저장** — 완성된 피벗 리포트를 `outputs/pivot_report.csv`로 저장합니다. 엑셀에서 열어 보면 여러분이 손으로 만들던 그 표가 코드 한 번에 나온 것을 확인할 수 있습니다.

## 5. 직접 해보기

1. **(기본)** [1]의 피벗에서 `aggfunc="sum"`을 `"count"`로 바꿔 보세요. 칸의 의미가 "매출 합계"에서 무엇으로 바뀌나요? 힌트: 행이 몇 건 들어갔는지, 즉 판매 기록 수가 됩니다.
2. **(응용)** `index=["store", "weekday"]`처럼 index에 리스트를 넣어 2단 피벗을 만들어 보세요. 힌트: 결과는 MultiIndex(다중 인덱스) 표가 되며, 엑셀 피벗의 "행 영역에 필드 2개"와 같습니다.
3. **(도전)** 카테고리별로 "지점 간 매출 격차"(그룹 내 최대 - 최소)를 구해, 격차가 가장 큰 카테고리를 찾아 보세요. 힌트: [4]에서 만든 카테고리·지점별 합계 표에 `groupby("category")["revenue"].agg(lambda s: s.max() - s.min())`를 적용합니다.

## 6. 자주 하는 실수

- **pivot과 pivot_table 혼동** — `pivot`은 (행, 열) 조합이 중복되면 에러를 냅니다. 원본이 일별 데이터처럼 중복 조합을 가지면 반드시 `pivot_table`(집계 내장)을 쓰세요.
- **margins 행을 데이터로 취급** — `margins=True`가 붙인 "All" 행·열은 합계이지 데이터가 아닙니다. 피벗을 melt하거나 순위를 매기기 전에는 margins 없는 버전을 쓰세요.
- **요일·월을 가나다순으로 방치** — 피벗의 행 순서는 기본이 사전순이라 "금목수월일토화"처럼 됩니다. `reindex(["월","화",...])`로 업무 순서를 복원하세요.
- **rank의 방향 착각** — 기본값 `ascending=True`는 작은 값이 1등입니다. 매출 순위는 거의 항상 `ascending=False`가 필요합니다.
- **NaN 칸을 0으로 오해** — 피벗에서 NaN은 "그 조합의 데이터가 없음"이지 "매출 0"이 아닙니다. 의미를 확인한 뒤에만 `fillna(0)` 하세요.
