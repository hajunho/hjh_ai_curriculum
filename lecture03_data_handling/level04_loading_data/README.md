## 1. 왜 배우나 — 비즈니스 관점

분석 업무의 첫 관문은 언제나 "파일 열기"입니다. 전산팀이 뽑아 준 CSV, 거래처가 보낸 엑셀, 시스템이 토해 낸 JSON — 형식도 인코딩도 제각각인 파일을 DataFrame으로 무사히 들여오는 것이 모든 분석의 0단계입니다. 그리고 이 단계에서 놀랄 만큼 많은 시간이 사라집니다. 한글이 `ê°•ë‚¨` 처럼 깨지고, "1,234"라는 숫자가 문자로 읽히고, 결측이 "-"로 적혀 있어 평균 계산이 통째로 틀어집니다.

`read_csv`의 옵션 몇 개만 알면 이 문제의 90%가 옵션 한 줄로 해결됩니다. 반대로 모르면 파일을 엑셀로 열어 손으로 고치는 수작업으로 돌아가게 되고, 그 순간 재현성(reproducibility)이 사라집니다. "파일을 손대지 않고 코드로 해결한다"가 이번 레벨의 철칙입니다.

## 2. 비유로 이해하기

CSV 파일을 읽는 일은 **해외 소포를 통관시키는 일**과 비슷합니다. 소포(파일)는 발송국의 규칙대로 포장되어 있습니다. 언어(인코딩)가 다르고, 물건 목록의 구분 방식(구분자)이 다르고, "없음"을 표기하는 관습(결측 표기)이 다릅니다. 통관 신고서(read_csv 옵션)에 "이 소포는 cp949라는 언어로 쓰였고, 항목은 세미콜론으로 구분되며, '-'는 빈칸이라는 뜻입니다"라고 정확히 적어 주면 소포는 문제없이 통과합니다. 신고서를 대충 쓰면? 세관(판다스)이 내용물을 엉뚱하게 해석하거나 아예 반송(에러)합니다.

인코딩은 특히 **자물쇠와 열쇠** 비유가 정확합니다. cp949로 잠근 파일은 cp949 열쇠로만 열립니다. utf-8 열쇠를 꽂으면 자물쇠가 부서지는 게 아니라 "이 열쇠 아닌데요"라는 오류(UnicodeDecodeError)가 납니다. 열쇠를 바꿔 끼우면 그만입니다.

## 3. 핵심 개념

### 3.1 read_csv 필수 옵션 지도

```python
pd.read_csv(
    "sales.csv",
    sep=",",              # 구분자. 세미콜론 파일이면 ";"
    encoding="utf-8",     # 한글 깨지면 "cp949" 시도
    na_values=["-", ""],  # 이 표기들을 결측(NaN)으로 인식
    thousands=",",        # "1,234" 를 숫자 1234 로
    parse_dates=["date"], # 날짜 열을 진짜 날짜형으로
    usecols=["date", "revenue"],  # 필요한 열만
    nrows=1000,           # 앞 1000행만 (대용량 미리보기)
    dtype={"zipcode": str},       # 우편번호처럼 0으로 시작하는 값 보호
)
```

전부 외울 필요는 없습니다. "이런 문제는 옵션으로 풀 수 있다"는 지도만 머리에 있으면, 필요할 때 찾아 쓰면 됩니다.

### 3.2 한국 실무의 최대 복병 — 인코딩

인코딩(encoding)은 글자를 컴퓨터의 숫자로 바꾸는 규칙입니다. 국제 표준은 utf-8이지만, 한국의 오래된 시스템과 엑셀 기본 CSV 저장은 cp949(euc-kr 계열)를 씁니다. 증상과 처방은 두 가지뿐입니다.

| 증상 | 처방 |
|---|---|
| `UnicodeDecodeError` 발생 | `encoding="cp949"` 로 다시 읽기 |
| 오류는 없는데 한글이 외계어 | 반대 인코딩으로 다시 읽기 |

내가 저장할 때는 항상 `encoding="utf-8"`(엑셀에서 열 파일은 `utf-8-sig`)로 저장하는 습관을 들이면 미래의 동료를 구할 수 있습니다.

### 3.3 숫자가 문자로 읽히는 사고

전산 시스템이 "1,234,000"처럼 콤마 넣은 숫자를 내보내면 판다스는 이를 문자(object)로 읽습니다. 그 순간 `sum()`은 문자열 이어붙이기가 되거나 오류가 납니다. `thousands=","` 옵션이면 한 줄 해결입니다. 마찬가지로 결측을 "-", "없음", "N/A" 등으로 적어 놓은 파일은 `na_values` 옵션으로 결측 표기 목록을 알려 주면 됩니다.

### 3.4 JSON — 시스템 간 택배 상자

JSON은 웹 시스템끼리 데이터를 주고받는 표준 형식입니다. 표 데이터라면 보통 **records 형태**(행 하나 = 딕셔너리 하나의 리스트)로 옵니다.

```json
[{"store": "강남점", "revenue": 512000},
 {"store": "홍대점", "revenue": 430000}]
```

이 형태는 `pd.read_json(path)` 또는 `json.load()` 후 `pd.DataFrame()`으로 바로 표가 됩니다. 반대로 중첩(nested)된 JSON은 `pd.json_normalize()`로 평평하게 펴야 합니다.

### 3.5 엑셀 파일은 개념만

`pd.read_excel("report.xlsx", sheet_name="1월")` 로 엑셀도 읽을 수 있습니다(openpyxl 패키지 필요). 다만 엑셀 파일은 시트·서식·병합 셀 때문에 사고가 잦아서, 실무에서는 **가능하면 CSV로 받아라**가 정석입니다. 병합 셀이 있는 보고서용 엑셀은 `header=2`, `skiprows` 같은 옵션으로 표 부분만 도려내야 합니다.

### 3.6 저장 — to_csv / to_json

```python
df.to_csv("out.csv", index=False, encoding="utf-8-sig")
df.to_json("out.json", orient="records", force_ascii=False)
```

`index=False`를 빼먹으면 이름 없는 번호 열이 파일에 끼어들어, 다음 사람이 읽을 때 `Unnamed: 0` 열이 생깁니다. `force_ascii=False`는 JSON 안의 한글을 사람이 읽을 수 있게 유지합니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture03_data_handling/level04_loading_data
python3 main.py
```

main.py는 문제 있는 파일을 **일부러 만들어서** 옵션으로 해결하는 시나리오 4개를 시연합니다. 생성되는 파일은 모두 `outputs/` 폴더에 저장됩니다.

- **[1]** `hjh_data.sales_table` 30일치를 utf-8 CSV로 저장하고 `read_csv`로 되읽어, 저장 전과 dtype이 어떻게 달라지는지 확인합니다.
- **[2]** "1,234" 콤마 숫자·"-" 결측·세미콜론 구분자가 뒤섞인 골칫덩이 CSV를 직접 만들고, 옵션 없이 읽었을 때 dtype이 전부 object로 망가지는 모습 → `sep=";", thousands=",", na_values="-"`로 복구되는 모습을 비교합니다.
- **[3]** cp949로 저장된 한글 CSV를 utf-8로 읽다가 `UnicodeDecodeError`가 나는 장면을 try/except로 안전하게 보여 주고, `encoding="cp949"`로 해결합니다.
- **[4]** records 형태 JSON을 저장했다가 `pd.read_json`으로 되읽어, JSON ↔ DataFrame 왕복을 확인합니다.

출력에서 눈여겨볼 부분: [2]에서 옵션 적용 전후의 `dtypes` 비교, [3]에서 에러 메시지의 실제 생김새입니다. 실무에서 이 메시지를 만나면 반갑게 "인코딩 문제구나" 하고 알아볼 수 있어야 합니다.

## 6. 자주 하는 실수

- **깨진 한글을 손으로 고치기** — 파일을 엑셀로 열어 저장하면 그 순간 원본이 변형됩니다. 원본은 절대 건드리지 말고 읽는 쪽 옵션으로 해결하세요.
- **`index=False` 누락** — to_csv 기본값은 index를 파일에 쓰는 것이라, 되읽으면 `Unnamed: 0` 열이 생깁니다.
- **dtype 확인 생략** — 읽자마자 계산부터 하면 문자로 읽힌 숫자 때문에 결과가 조용히 틀립니다. 읽은 직후 `df.dtypes` 확인은 통관 후 검수와 같습니다.
- **우편번호·사번을 숫자로 읽기** — "01234"가 1234로 변해 앞의 0이 사라집니다. `dtype={"zipcode": str}`로 보호하세요.
- **엑셀 CSV의 utf-8 착각** — 한국 엑셀이 저장한 CSV는 대개 cp949입니다. "CSV니까 utf-8이겠지"라고 가정하지 마세요.
