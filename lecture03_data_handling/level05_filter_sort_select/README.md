## 1. 왜 배우나 — 비즈니스 관점

상사의 질문은 대부분 이렇게 생겼습니다. "지난달 강남점 주말 매출 좀 뽑아 줘." "광고비 대비 효율 좋은 카테고리가 어디야?" 이 질문들의 공통 구조는 **골라내고(필터), 줄 세우고(정렬), 필요한 것만 꺼내는(선택)** 것입니다. 데이터 분석 업무 시간의 80%는 사실 이 세 동작의 조합입니다.

엑셀에서도 필터 버튼과 정렬 버튼으로 같은 일을 할 수 있습니다. 하지만 조건이 3개만 겹쳐도 클릭이 수십 번이 되고, 다음 달에 같은 질문을 받으면 처음부터 다시 클릭해야 합니다. 코드는 조건을 글로 적는 것이므로, 아무리 복잡한 조건도 한 줄이고, 다음 달에는 재실행 한 번이면 끝납니다. 이번 레벨을 마치면 "말로 된 업무 질문"을 "조건식"으로 번역하는 근육이 생깁니다.

## 2. 비유로 이해하기

필터링은 **출입문의 보안 요원**입니다. DataFrame의 모든 행이 한 줄로 서서 문을 통과하는데, 보안 요원은 행마다 조건을 검사해 통과/차단 딱지(True/False)를 붙입니다. 이 딱지의 목록이 불리언 마스크(boolean mask)입니다. `df[mask]`는 "True 딱지 받은 행만 입장"이라는 뜻입니다.

조건이 여러 개면 보안 요원을 여러 명 세웁니다. "사원증 있고(&) 그리고 예약자 명단에 있는 사람만", "임원이거나(|) 또는 VIP인 사람". 각 요원의 판정을 괄호로 감싸 결합하는 것이 판다스의 문법입니다.

loc와 iloc은 **아파트에서 집을 찾는 두 가지 방법**입니다. loc은 "101동 502호"처럼 **이름표(라벨)** 로 찾고, iloc은 "정문에서 세 번째 동, 위에서 다섯 번째 집"처럼 **순서(위치)** 로 찾습니다. 같은 집이라도 부르는 방식이 다르고, 재건축으로 동 이름이 바뀌면(index가 바뀌면) loc의 답과 iloc의 답이 달라질 수 있습니다.

## 3. 핵심 개념

### 3.1 불리언 마스크 — 필터의 원리

```python
mask = df["store"] == "강남점"   # True/False 로 채워진 Series
gangnam = df[mask]               # True 인 행만 남김
```

비교 연산(`==`, `>`, `<=` 등)을 열에 적용하면 행 수만큼의 True/False가 나오고, 이를 대괄호에 넣으면 필터가 됩니다. 두 줄을 합쳐 `df[df["store"] == "강남점"]`처럼 쓰는 것이 관례입니다.

### 3.2 조건 결합 — &, |, ~ 그리고 괄호

```python
df[(df["store"] == "강남점") & (df["weekday"].isin(["토", "일"]))]
```

- `&`(그리고), `|`(또는), `~`(부정)을 씁니다. 파이썬 문법의 `and/or/not`은 **쓸 수 없습니다.**
- 각 조건을 반드시 괄호로 감싸야 합니다. 연산자 우선순위 때문에 괄호를 빼면 오류가 납니다.
- 값 여러 개 중 하나에 해당하는지는 `isin(["토", "일"])`이 깔끔합니다. `==`를 `|`로 잇는 것보다 짧고 실수도 적습니다.

### 3.3 loc vs iloc

| | loc | iloc |
|---|---|---|
| 기준 | 이름표(라벨) | 정수 위치 |
| 예 | `df.loc[3, "revenue"]` | `df.iloc[3, 6]` |
| 슬라이스 | 끝 **포함** | 끝 **제외** (파이썬 관례) |

필터를 거친 DataFrame은 index가 0,1,2...가 아니라 원본의 행 번호를 그대로 들고 있습니다. 그래서 `filtered.loc[0]`은 오류가 날 수 있지만 `filtered.iloc[0]`은 항상 "첫 행"을 줍니다. 이 차이를 모르면 KeyError를 만났을 때 한참 헤맵니다.

`df.loc[mask, ["store", "revenue"]]`처럼 **행 조건과 열 선택을 동시에** 하는 형태가 실무에서 가장 많이 쓰는 문형입니다.

### 3.4 정렬과 상위 N

```python
df.sort_values("revenue", ascending=False).head(10)   # 매출 내림차순 상위 10
df.nlargest(10, "revenue")                            # 같은 결과, 더 빠르고 짧게
df.sort_values(["store", "revenue"], ascending=[True, False])  # 다중 기준
```

"상위 N"이 목적이면 `nlargest`/`nsmallest`가 의도를 더 분명히 드러냅니다.

### 3.5 query — 조건을 문장처럼

```python
df.query("store == '강남점' and revenue >= 500000")
```

괄호와 `&` 없이 문자열로 조건을 쓰는 방법도 있습니다. 읽기 좋지만 열 이름에 공백이 있으면 곤란해지는 등 제약이 있어, 기본기는 불리언 마스크로 다지고 query는 선택지로 알아 두세요.

### 3.6 SettingWithCopyWarning — 복사본에 쓴 낙서

필터링한 결과에 값을 대입하면 `SettingWithCopyWarning`이 뜰 때가 있습니다. 필터 결과가 원본의 복사본인지 뷰인지 애매해서 나오는 경고입니다. 해결 습관은 두 가지입니다: 수정 목적이면 `df.loc[mask, "col"] = 값` 한 문장으로 쓰고, 부분집합을 계속 쓸 것이라면 `sub = df[mask].copy()`로 명시적 복사본을 만드세요.

## 6. 자주 하는 실수

- **`and`/`or`를 쓰는 것** — `(a) & (b)`가 맞습니다. `and`를 쓰면 "truth value is ambiguous"라는 유명한 오류가 납니다.
- **괄호 생략** — `df[df["a"] > 1 & df["b"] < 2]`는 `&`가 비교보다 먼저 계산되어 엉뚱한 결과나 오류가 됩니다. 조건마다 괄호가 철칙입니다.
- **필터 후 loc[0] 호출** — 필터링된 표의 index는 0부터 시작하지 않을 수 있습니다. 첫 행은 `iloc[0]`, 특정 라벨은 `loc[라벨]`로 구분하세요.
- **대입할 때 이중 대괄호 체인** — `df[mask]["col"] = 값`은 경고가 나고 원본이 안 바뀔 수 있습니다. `df.loc[mask, "col"] = 값`으로 한 번에 쓰세요.
- **문자열 비교의 공백** — "강남점 "(뒤 공백)은 "강남점"과 다른 값입니다. 필터 결과가 0행이면 `unique()`로 실제 값을 확인하세요.
