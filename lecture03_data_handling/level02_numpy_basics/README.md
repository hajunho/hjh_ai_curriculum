## 1. 왜 배우나 — 비즈니스 관점

level01에서 만든 반복문 코드는 1,500행에서는 순식간이지만, 데이터가 수백만 행이 되면 눈에 띄게 느려집니다. 거래 로그, 센서 기록, 광고 클릭 데이터는 수백만 행이 기본입니다. "돌려 놓고 커피 마시고 오는 코드"와 "즉시 답이 나오는 코드"의 차이는 실무에서 분석의 횟수를 결정합니다. 빨리 돌면 더 많은 질문을 던질 수 있습니다.

넘파이(NumPy)는 파이썬에서 대량의 숫자를 빠르게 다루는 표준 라이브러리입니다. 그리고 다음 레벨부터 배우는 판다스(Pandas), 나중에 배울 사이킷런(scikit-learn)과 파이토치(PyTorch)까지 전부 NumPy 배열 위에서 동작합니다. 즉 NumPy의 사고방식 — **"숫자 하나가 아니라 숫자 묶음(배열)을 연산의 단위로 삼는다"** — 은 데이터 분야 전체의 공통 문법입니다. 여기서 이 감각을 익혀 두면 이후 모든 도구가 같은 원리로 보입니다.

## 2. 비유로 이해하기

편의점에서 음료수 1,000캔을 계산한다고 해 봅시다.

- **파이썬 반복문** = 캔을 하나씩 바코드 스캐너에 찍는 아르바이트생. 한 캔당 동작은 빠르지만, "집고 → 찍고 → 내려놓고"라는 준비 동작이 1,000번 반복됩니다.
- **NumPy 벡터 연산** = 박스째 저울에 올려 한 번에 계산하는 물류 창고. "준비 동작"이 단 한 번이고, 실제 계산은 기계(최적화된 C 코드)가 처리합니다.

파이썬 반복문이 느린 진짜 이유는 계산 자체가 아니라 **매번 반복되는 준비 동작**(값의 타입 확인, 객체 포장 풀기 등)입니다. NumPy는 "이 박스 안은 전부 같은 타입의 숫자"라고 약속해 두었기 때문에 준비 동작을 생략하고, 연속된 메모리 위를 기계 속도로 달립니다.

브로드캐스팅(broadcasting)은 **도장 찍기**입니다. "모든 매출에 부가세 10%를 얹어라"는 지시를 1,000번 반복하는 대신, `revenue * 1.1`이라는 도장 하나를 배열 전체에 한 번에 찍습니다.

## 3. 핵심 개념

### 3-1. ndarray — 같은 타입 숫자의 연속 묶음

NumPy의 핵심 자료구조는 다차원 배열(ndarray)입니다. 파이썬 리스트와의 결정적 차이 두 가지:

1. **모든 원소가 같은 타입**입니다. 이 약속 덕분에 타입 확인 없이 고속 계산이 가능합니다.
2. **메모리에 연속으로 배치**됩니다. CPU가 예측하며 미리 읽어 올 수 있어 더 빨라집니다.

```python
import numpy as np
a = np.array([1, 2, 3])
a * 10        # array([10, 20, 30]) — 반복문 없이 전체에 적용
```

### 3-2. shape 과 dtype — 배열의 신분증

- **shape**: 배열의 모양. `(1500,)`은 1차원 1,500개, `(30, 5)`는 30행 5열입니다. 에러의 대부분은 shape 불일치에서 나오므로, 배열을 받으면 `shape`부터 확인하는 습관이 중요합니다.
- **dtype**: 원소의 타입. `int64`(정수), `float64`(실수) 등. 결측값 `NaN`(Not a Number)은 float에만 존재할 수 있어서, 결측이 섞인 정수 열이 float로 변하는 현상을 자주 보게 됩니다.

### 3-3. 벡터화 — 반복문을 연산자로 대체

"각 원소에 같은 일을 하라"는 모든 작업은 반복문 대신 배열 연산으로 씁니다.

| 반복문 사고 | 벡터화 사고 |
|---|---|
| `for r in revenues: total += r` | `revenues.sum()` |
| `for r in ...: new.append(r * 1.1)` | `revenues * 1.1` |
| `for r in ...: if r > 100만: ...` | `revenues[revenues > 1_000_000]` |

마지막 줄이 불리언 마스크(boolean mask)입니다. `revenues > 1_000_000`은 True/False 배열을 만들고, 그것을 대괄호에 넣으면 True 위치의 값만 골라집니다. level05에서 판다스 필터링의 뼈대가 되는 문법이므로 여기서 손에 익혀 두세요.

### 3-4. 브로드캐스팅 — 크기가 달라도 맞춰서 계산

`배열 * 1.1`처럼 배열과 숫자 하나(스칼라)를 연산하면, NumPy가 숫자를 배열 크기에 맞게 "늘려서" 계산해 줍니다. 실제로 메모리를 복사하는 것이 아니라 개념적으로 늘리는 것이라 비용도 없습니다. `(30, 5)` 배열에 `(5,)` 배열을 더하면 각 행마다 더해지는 식으로, 차원이 달라도 규칙이 맞으면 자동으로 확장됩니다.

### 3-5. 집계 함수

`sum()`, `mean()`(평균), `std()`(표준편차), `min()/max()`, `round()` 등이 배열 메서드로 제공됩니다. 2차원 배열에서는 `axis=0`(열 방향)/`axis=1`(행 방향)로 집계 방향을 정하는데, 이는 level07의 groupby를 이해하는 밑돌이 됩니다.

## 6. 자주 하는 실수

- **리스트와 배열의 `*` 혼동**: `[1, 2] * 3`은 리스트 반복(`[1,2,1,2,1,2]`)이고, `np.array([1, 2]) * 3`은 원소별 곱(`[3, 6]`)입니다. 완전히 다른 동작입니다.
- **None이 섞인 리스트를 그대로 배열로 변환**: dtype이 `object`가 되어 벡터화의 속도 이점이 사라집니다. 결측은 배열로 만들기 전에 제거하거나 `NaN`으로 통일해야 합니다.
- **배열을 for문으로 돌리기**: 문법적으로는 되지만 NumPy를 쓰는 의미가 없어집니다. "반복문을 쓰고 싶어지면 벡터 연산이 없는지 먼저 찾는다"를 원칙으로 삼으세요.
- **`axis` 방향 착각**: 2차원에서 `sum(axis=0)`은 "행들을 눌러서" 열별 합계를 만듭니다. 결과의 shape을 항상 확인하세요.
