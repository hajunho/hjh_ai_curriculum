> 비어 있는 값과 말이 안 되는 값을 찾아내고, 상황에 맞는 처리 전략을 고르는 법을 배웁니다.

**난이도** ⭐⭐⭐ / **선행** level05_filter_sort_select / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

실무 데이터는 깨끗한 적이 거의 없습니다. POS 단말기가 잠시 꺼져서 매출이 기록되지 않았거나, 환불 처리가 음수 매출로 들어왔거나, 담당자가 실수로 0을 하나 더 붙였거나 하는 일이 매일 일어납니다.

문제는 이런 오염이 **조용히** 분석 결과를 망친다는 점입니다. 결측치(missing value)가 섞인 채 평균을 내면 표본이 줄어든 채 계산되고, 음수 매출이 섞이면 합계가 실제보다 작게 나옵니다. 보고서 숫자가 틀렸는데 아무 에러도 나지 않는 것, 이것이 가장 무서운 시나리오입니다.

그래서 데이터 분석가들은 "분석 시간의 절반 이상은 정제에 쓴다"고 말합니다. 이번 레벨에서는 오염을 **진단**하고, 여러 **처리 전략**을 비교하고, 어떤 전략이 어떤 상황에 맞는지 판단하는 눈을 기릅니다.

## 2. 비유로 이해하기

월말 결산을 하는데 지점 다섯 곳에서 올라온 매출 전표 뭉치를 받았다고 상상해 보세요.

- 어떤 전표는 **금액 칸이 비어** 있습니다. → 결측치입니다.
- 어떤 전표에는 **-350,000원**이라고 적혀 있습니다. 매출이 음수일 수는 없으니 뭔가 잘못됐습니다. → 도메인 규칙 위반 이상치입니다.
- 어떤 전표는 평소 30만 원 안팎인데 혼자 **9,000만 원**입니다. 불가능하진 않지만 몹시 수상합니다. → 통계적 이상치(outlier)입니다.

경험 많은 경리 담당자는 이런 전표를 그냥 버리지 않습니다. 먼저 **몇 장이나 이상한지 세어 보고**(진단), 지점에 전화해 **원인을 물어보고**(조사), 원인을 알 수 없을 때만 **규칙에 따라 보정**합니다(처리). 예를 들어 금액이 빈 전표는 "그 지점·그 품목의 평소 매출"로 잠정 기입해 두는 식입니다.

판다스의 결측치·이상치 처리도 완전히 같은 순서입니다. `isna()`로 세어 보고, 원인을 추정하고, `dropna()`·`fillna()`로 처리합니다.

## 3. 핵심 개념

### 3-1. 결측치는 왜 생기나

결측치의 원인은 크게 세 갈래입니다.

| 유형 | 예시 | 처리 힌트 |
|---|---|---|
| 수집 실패 | 단말기 통신 오류로 기록 누락 | 무작위 누락이면 채우기(대체)가 비교적 안전 |
| 애초에 없는 값 | 신규 지점의 "작년 매출" | 채우면 안 되는 경우가 많음 |
| 입력 실수 | 담당자가 칸을 건너뜀 | 원본 확인이 최선 |

원인에 따라 올바른 처리가 달라지기 때문에, **"지우기 전에 원인을 물어라"**가 첫 번째 원칙입니다.

### 3-2. 진단 도구 — isna, notna, describe

- `df["revenue"].isna()` : 각 값이 결측인지 True/False로 알려 줍니다. `.sum()`을 붙이면 결측 개수, `.mean()`을 붙이면 결측 비율이 됩니다.
- `df.describe()` : 개수·평균·최솟값(min)·최댓값(max)을 한 번에 보여 줍니다. **min이 음수**라면 매출 데이터로서 말이 안 되므로 즉시 눈치챌 수 있습니다.

### 3-3. 도메인 규칙 이상치 — 업무 지식이 먼저

통계 기법보다 먼저 적용해야 하는 것이 도메인 규칙(domain rule), 즉 업무 상식입니다. "매출은 0 이상이다", "나이는 150을 넘을 수 없다" 같은 규칙이지요. 규칙을 어긴 값은 측정 오류이므로 결측치로 바꿔 두는 것이 정석입니다.

```python
df.loc[df["revenue"] < 0, "revenue"] = np.nan
```

주의: 음수를 그냥 **삭제**하면 "그날 그 지점에 판매가 있었다"는 사실까지 사라집니다. 값만 모른다고 표시(NaN)해 두는 편이 정보 손실이 적습니다.

### 3-4. 통계적 이상치 — IQR 방법

도메인 규칙으로 못 잡는 "수상하게 크거나 작은 값"은 IQR(사분위 범위, Interquartile Range)로 찾습니다.

- Q1 = 하위 25% 지점, Q3 = 상위 75% 지점, IQR = Q3 − Q1
- 정상 범위: **[Q1 − 1.5×IQR, Q3 + 1.5×IQR]** — 이 밖의 값을 이상치 후보로 봅니다.

"후보"라고 부르는 이유가 중요합니다. 주말 대박 매출처럼 **진짜 현상**이 이상치로 잡히기도 하기 때문입니다. IQR은 자동 삭제 도구가 아니라 **검토 목록을 만드는 도구**입니다.

### 3-5. 처리 전략 세 가지

| 전략 | 코드 | 장점 | 단점 |
|---|---|---|---|
| (a) 행 삭제 | `dropna()` | 단순, 가짜 값 없음 | 표본이 줄어듦, 합계가 작아짐 |
| (b) 전체 중앙값 대체 | `fillna(med)` | 행 보존 | 지점·품목 특성 무시 |
| (c) 그룹별 중앙값 대체 | `groupby().transform("median")` | 맥락 반영, 가장 정교 | 코드가 약간 복잡 |

평균이 아니라 **중앙값(median)**을 쓰는 이유는, 평균은 남아 있는 이상치에 끌려가지만 중앙값은 잘 버티기 때문입니다. (c)는 "강남점 커피의 빈칸은 강남점 커피의 평소 값으로 채운다"는 발상으로, 실무에서 가장 많이 쓰는 방식입니다.

핵심은 **어느 전략이든 통계량이 달라진다**는 사실입니다. 합계 지표가 중요한 보고서라면 삭제는 위험하고, 평균 지표라면 대체 방식의 영향이 작습니다. 그래서 전략을 바꿔 가며 결과를 비교해 보는 습관이 필요합니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture03_data_handling/level06_missing_outliers
python3 main.py
```

출력 흐름과 볼거리:

- **[1] 오염 진단** — 결측 개수·비율, 음수 개수, `describe()`의 min이 음수인 것을 확인합니다. 9,125행 중 결측 약 1%, 음수 약 0.5%가 심어져 있습니다.
- **[2] 도메인 규칙 적용** — 음수 매출을 NaN으로 바꿉니다. 삭제가 아니라 "값을 모른다"로 표시하는 점에 주목하세요.
- **[3] IQR 이상 경계** — Q1, Q3, 정상 범위와 상단 이상치 개수를 계산합니다. 주말·성수기 매출이 걸릴 수 있음을 함께 출력합니다.
- **[4] 전략 비교** — dropna / 전체 중앙값 / 그룹별 중앙값 세 전략으로 각각 처리한 뒤 행 수·총매출·평균을 표로 비교합니다. dropna의 총매출이 눈에 띄게 작아지는 것이 관전 포인트입니다.
- **[5] 전/후 요약과 상자그림** — 처리 전후 요약을 출력하고, 상자그림(boxplot) PNG를 `outputs/`에 저장합니다.

코드 핵심부는 (c) 전략입니다.

```python
group_median = df.groupby(["store", "category"])["revenue"].transform("median")
df["revenue_filled"] = df["revenue"].fillna(group_median)
```

`transform`은 그룹별 계산 결과를 **원래 행 수 그대로** 돌려주기 때문에, 각 행이 자기 그룹의 중앙값으로 채워집니다.

2. **평균 대체와 중앙값 대체 비교** — 전략 (b)를 `mean()`으로 바꿔 총매출·평균이 어떻게 달라지는지 비교해 보세요. (힌트: 음수를 NaN으로 바꾸기 **전**의 평균으로 채우면 오염이 전파됩니다. 순서가 중요합니다.)
3. **IQR 배수 실험** — 1.5 대신 3.0을 쓰면 이상치 개수가 어떻게 변하나요? 어떤 보고서라면 3.0(보수적)이 더 적절할지 생각해 보세요. (힌트: 오탐을 줄이고 싶은 자동 알림 시스템.)

## 6. 자주 하는 실수

- **`df[df["revenue"] != None]`으로 결측을 거르려는 것** — 판다스의 결측은 `NaN`이라 `!= None` 비교로는 걸러지지 않습니다. 반드시 `isna()`/`notna()`를 쓰세요.
- **NaN == NaN이 False라는 사실을 모르는 것** — NaN은 자기 자신과도 같지 않습니다. 비교 연산 대신 전용 함수를 써야 하는 이유입니다.
- **fillna 결과를 변수에 안 받는 것** — `df.fillna(0)`은 새 DataFrame을 돌려줄 뿐 원본을 바꾸지 않습니다. `df = df.fillna(0)`처럼 다시 담으세요.
- **원본 훼손** — 정제는 복사본(`df.copy()`)에서 하고 원본 파일은 남겨 두세요. "원본은 증거물"입니다.
- **이상치 자동 삭제** — IQR에 걸렸다고 기계적으로 지우면 연말 특수 같은 진짜 신호를 버리게 됩니다. 반드시 눈으로 검토 후 결정하세요.
