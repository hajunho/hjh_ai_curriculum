# Lecture 03 · Level 09 — 시계열 데이터 다루기

> 매출을 "시간 축 위에 올려서" 추세·계절성·성장률을 읽어 내는 법을 배웁니다.

**난이도** ⭐⭐⭐⭐ / **선행** level07 (그룹화·집계) / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

경영진이 던지는 질문의 절반은 시간에 관한 것입니다. "지난주보다 얼마나 늘었나?", "이번 달 추세가 꺾인 건가, 원래 이런 계절인가?", "주말 효과를 빼고 보면 진짜 성장하고 있나?" 같은 질문이지요. 이 질문들은 모두 데이터를 날짜 순서로 세워 놓아야만 답할 수 있습니다.

이렇게 시간 순서가 의미를 가지는 데이터를 시계열(time series)이라고 부릅니다. 매출, 방문자 수, 재고, 주가, 서버 트래픽 — 실무 데이터의 대부분이 사실 시계열입니다. 그런데 시계열은 다루는 방법이 조금 특별합니다. 행의 순서를 함부로 섞으면 안 되고, "일별 → 주별"처럼 시간 단위를 바꾸는 연산이 필요하며, "전주 대비"처럼 과거의 자기 자신과 비교하는 계산이 핵심이기 때문입니다. Pandas는 이런 작업을 위한 전용 도구인 `to_datetime`, `resample`, `rolling`, `shift`를 제공합니다. 이 네 가지만 익혀도 주간 보고서의 핵심 숫자를 전부 코드로 뽑을 수 있습니다.

## 2. 비유로 이해하기

**시계열 분석은 체중 기록 관리와 같습니다.** 매일 아침 체중을 기록한다고 해 봅시다.

- 하루하루 숫자는 들쭉날쭉합니다. 어제 회식을 했으면 오늘 1kg 늘어 보이지요. 그래서 우리는 "최근 7일 평균"을 봅니다. 이것이 바로 이동평균(rolling mean)입니다. 하루짜리 소음을 지우고 진짜 추세만 남기는 돋보기입니다.
- "매일 기록은 너무 많으니 주 단위로 요약해서 보자"라고 하면, 일기장을 주간 요약으로 바꾸는 셈입니다. 이것이 리샘플링(resample)입니다.
- "지난주 평균보다 이번 주는 몇 % 변했지?"라고 비교하는 것이 `shift`(한 칸 밀기)와 `pct_change`(증감률)입니다. 지난주의 나와 이번 주의 나를 나란히 세워 비교하는 것이지요.

한 가지 더. 체중 수첩의 날짜가 "2월 31일"이라고 적혀 있다면 어떨까요? 사람은 웃고 넘기지만 컴퓨터는 멈춥니다. 현실 데이터에는 이런 잘못된 날짜 문자열이 정말로 섞여 들어옵니다. 시계열 분석의 첫 단추는 언제나 "날짜가 진짜 날짜인지" 확인하는 일입니다.

## 3. 핵심 개념

### 3-1. 문자열은 날짜가 아니다 — to_datetime

CSV에서 읽은 `"2025-03-15"`는 그냥 글자입니다. 글자인 채로 정렬하면 사전 순서로 섞이고, 빼기 연산도 안 됩니다. `pd.to_datetime()`으로 날짜 타입(datetime64)으로 변환해야 비로소 "며칠 차이인가", "무슨 요일인가" 같은 계산이 가능해집니다.

이때 `errors` 옵션이 중요합니다.

| 옵션 | 동작 | 언제 쓰나 |
|---|---|---|
| `errors="raise"` (기본) | 잘못된 날짜를 만나면 즉시 에러 | 오염이 없다고 확신할 때 |
| `errors="coerce"` | 잘못된 날짜를 NaT(Not a Time, 날짜의 결측치)로 바꿈 | 현실 데이터 대부분 |

`coerce`로 변환한 뒤 `isna().sum()`으로 NaT 개수를 세면 "날짜 오염이 몇 건인지" 진단이 끝납니다. level06에서 결측치를 진단하던 습관을 날짜에도 그대로 적용하는 것입니다.

### 3-2. DatetimeIndex와 dt 접근자

날짜 컬럼을 인덱스로 올리면(DatetimeIndex) `resample` 같은 시계열 전용 기능이 열립니다. 인덱스로 올리지 않은 날짜 컬럼에서는 `dt` 접근자로 부품을 꺼냅니다. `df["date"].dt.month`는 월, `.dt.dayofweek`는 요일 번호를 돌려줍니다.

### 3-3. resample — 시간 단위 바꾸기

`daily.resample("W").sum()`은 일별 데이터를 주(week) 단위 상자에 나눠 담고 상자마다 합계를 구합니다. `"W"`는 주, `"ME"`는 월말(month end) 기준 월 단위입니다. groupby의 시간판이라고 생각하면 정확합니다. 실제로 내부 동작도 "시간 구간으로 그룹을 나눔 → 각 그룹에 집계 함수 적용"으로 level07의 분할-적용-결합과 같습니다.

### 3-4. rolling — 이동평균으로 소음 제거

`daily.rolling(7).mean()`은 "오늘 포함 최근 7일 평균"을 매일 계산합니다. 창문(window)을 하루씩 밀며 평균을 내기 때문에 이동평균이라 부릅니다. 우리 카페 데이터처럼 주말마다 매출이 튀는 경우, 7일 창을 쓰면 요일 효과가 정확히 한 주기씩 포함되어 출렁임이 사라지고 계절 추세만 남습니다. 처음 6일은 7개를 채울 수 없어 NaN이 되는 것이 정상입니다.

### 3-5. shift와 pct_change — 과거의 나와 비교

`weekly.shift(1)`은 시리즈를 한 칸 아래로 밀어 "지난주 값"을 이번 주 행 옆에 가져다 놓습니다. 그러면 성장률은 `(이번 주 - 지난주) / 지난주`로 계산되지요. 이 계산을 한 줄로 해 주는 것이 `weekly.pct_change()`입니다. 첫 행은 비교할 과거가 없으므로 NaN이 됩니다.

### 3-6. 시계열의 함정 두 가지

첫째, 정렬되지 않은 날짜입니다. 여러 파일을 이어 붙인 데이터는 날짜가 뒤죽박죽인 경우가 많은데, 그 상태로 `shift`를 쓰면 "지난주"가 아니라 "그냥 윗줄"과 비교하게 됩니다. `sort_index()`가 먼저입니다. 둘째, 빠진 날짜입니다. 휴무일이 행 자체로 없으면 이동평균 창이 실제로는 7일보다 긴 기간을 덮게 됩니다. `resample("D")`로 빈 날짜를 채워 확인하는 습관이 필요합니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture03_data_handling/level09_time_series
python3 main.py
```

출력 흐름은 다음과 같습니다.

- **[1] 날짜 오염 진단** — `sales_table`의 `date` 컬럼을 `to_datetime(errors="coerce")`로 변환해 봅니다. 이 데이터의 날짜는 "31일씩 12달"이라는 잘못된 규칙으로 찍혀 있어 `2025-02-31` 같은 달력에 없는 날짜가 섞여 있습니다. coerce가 이런 값을 NaT로 바꾼 개수를 세어 오염 규모를 확인한 뒤, 신뢰할 수 있는 `day_index`(개장 후 경과일)에 `pd.to_timedelta`를 더해 올바른 날짜를 새로 만듭니다. "원본의 어떤 컬럼을 믿을 것인가"를 판단하는 과정 자체가 실무입니다.
- **[2] 일별 시계열 만들기** — 전 지점·전 카테고리 매출을 날짜별로 합쳐 DatetimeIndex를 가진 일별 시리즈로 만들고, `dt` 접근자로 월을 뽑아 봅니다.
- **[3] resample** — 주간 합계와 월간 합계를 구합니다. 첫 주와 마지막 주는 7일을 다 못 채운 "부분 주"라서 값이 작게 나오는 것도 확인합니다.
- **[4] rolling(7)** — 일별 매출 위에 7일 이동평균을 겹쳐, 주말 출렁임이 지워지고 계절 추세가 드러나는 것을 봅니다.
- **[5] 전주 대비 성장률** — 주간 매출에 `pct_change`를 적용해 성장률 상위 3주와 하위 3주를 뽑습니다. `shift`로 같은 계산을 직접 재현해 두 방법이 일치함을 검증합니다.
- **[6] 그래프 저장** — 일별 매출(연한 선)과 7일 이동평균(굵은 선)을 `outputs/daily_trend.png`로 저장합니다. 이동평균이 왜 "추세를 읽는 안경"인지 눈으로 확인해 보세요.

2. **(응용)** 커피 카테고리만 골라 일별 시계열을 만들고 14일 이동평균을 그려 보세요. 힌트: `df[df["category"] == "커피"]`로 먼저 거른 뒤 [2]와 같은 과정을 반복하면 됩니다.
3. **(도전)** 주간 매출의 "전년 동기 대비"를 흉내 내 봅시다. 데이터가 1년뿐이므로 `shift(4)`로 "4주 전 대비 성장률"을 구하고, `pct_change(periods=4)`와 같은지 확인해 보세요.

## 6. 자주 하는 실수

- **문자열인 채로 정렬·비교하기** — `"2025-9-2"`는 문자열 정렬에서 `"2025-10-1"`보다 뒤로 갑니다. 시계열 작업 전 `to_datetime` 변환이 무조건 첫 단계입니다.
- **coerce 결과를 확인하지 않기** — `errors="coerce"`는 편리하지만 조용히 데이터를 NaT로 지웁니다. 변환 직후 NaT 개수를 세지 않으면 데이터가 사라진 줄도 모릅니다.
- **resample 전에 인덱스를 안 만들기** — `resample`은 DatetimeIndex(또는 `on=` 지정)가 필요합니다. "Only valid with DatetimeIndex" 에러가 나면 인덱스부터 확인하세요.
- **pct_change의 첫 NaN을 버그로 착각하기** — 비교할 과거가 없는 구간의 NaN은 정상입니다. 억지로 0으로 채우면 "성장률 0%"라는 거짓 정보가 됩니다.
- **부분 주·부분 월을 그대로 보고하기** — 기간의 양 끝 상자는 날짜를 다 못 채웠을 수 있습니다. 보고서에 넣기 전에 잘라 내거나 각주를 다세요.
