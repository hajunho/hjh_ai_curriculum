# Lecture 03 · Level 07 — 그룹화와 집계 (groupby)

> "지점별 매출은? 요일별 평균은?" — 실무 질문의 표준 답안인 groupby를 배웁니다.

**난이도** ⭐⭐⭐ / **선행** level06_missing_outliers / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

상사가 데이터를 보고 던지는 질문은 거의 항상 같은 모양입니다. "**~별**로 보면 어때?" 지점별 매출, 요일별 평균, 카테고리별 비중, 담당자별 실적. 이 "~별"이라는 한국어가 판다스에서는 정확히 `groupby` 하나에 대응합니다.

엑셀에서는 이 일을 피벗 테이블이나 SUMIF로 합니다. 그런데 조건이 두세 개로 늘고("지점별로, 그중에서도 주말만, 카테고리별로"), 매주 갱신해야 하고, 집계 기준이 자주 바뀌면 수작업은 금방 한계에 부딪힙니다. groupby는 이 모든 질문을 한 줄짜리 코드로 바꾸고, 다음 주에도 같은 코드를 다시 실행하기만 하면 됩니다.

이번 레벨을 마치면 원시 데이터에서 "경영진에게 보여줄 요약표"까지 혼자 만들 수 있게 됩니다.

## 2. 비유로 이해하기

명함 500장이 뒤섞인 상자를 정리한다고 생각해 보세요. 회사별로 알고 싶다면 이렇게 합니다.

1. **나누기(Split)** — 회사 이름별로 명함을 더미로 나눕니다.
2. **적용하기(Apply)** — 더미마다 같은 작업을 합니다. 장수를 세거나, 직급 평균을 내거나.
3. **합치기(Combine)** — 더미별 결과를 한 장의 요약표로 모읍니다.

이 세 단계가 groupby의 공식 명칭인 **분할-적용-결합(split-apply-combine)** 패턴입니다. `df.groupby("store")["revenue"].sum()`이라는 코드는 "지점별로 더미를 나누고 → 각 더미의 매출을 합산하고 → 한 표로 합쳐라"를 그대로 옮긴 것입니다.

비유 하나 더: `agg`는 더미마다 여러 작업을 **동시에** 시키는 것("장수도 세고 평균도 내라"), `transform`은 더미별 결과를 **명함 한 장 한 장에 도로 붙여 주는 것**입니다. 이 차이는 3-4절에서 다시 봅니다.

## 3. 핵심 개념

### 3-1. 기본형 — 그룹 키, 대상 열, 집계 함수

```python
df.groupby("store")["revenue"].sum()
#          ─┬────   ─┬───────  ─┬─
#        그룹 키    대상 열    집계 함수
```

결과는 그룹 키가 인덱스(index)가 된 Series입니다. `sum` 자리에 `mean`(평균), `count`(개수), `median`(중앙값), `max`/`min` 등을 넣을 수 있습니다.

### 3-2. agg — 여러 집계를 한 번에

보고서에는 보통 합계·평균·건수가 같이 필요합니다. `agg`에 이름 있는 집계(named aggregation)를 쓰면 결과 열 이름까지 한 번에 정합니다.

```python
df.groupby("store").agg(
    total=("revenue", "sum"),
    avg=("revenue", "mean"),
    n=("revenue", "count"),
)
```

### 3-3. 다중 키 — "지점별, 그 안에서 카테고리별"

그룹 키를 리스트로 주면 계층 집계가 됩니다: `df.groupby(["store", "category"])["revenue"].sum()`. 결과는 두 단계 인덱스(MultiIndex)를 가지며, `reset_index()`로 평범한 표로 되돌릴 수 있습니다. "지점×카테고리 조합 중 어디가 돈을 버는가" 같은 질문의 답입니다.

### 3-4. agg vs transform — 요약이냐, 원본 크기 유지냐

| | 반환 크기 | 쓰임새 |
|---|---|---|
| `agg` | 그룹 수만큼 (요약표) | 보고서, 순위표 |
| `transform` | 원본 행 수 그대로 | 파생 열 만들기 (그룹 내 비중, 그룹별 채우기) |

예를 들어 "각 행의 매출이 자기 지점 총매출의 몇 %인가"라는 파생 열은 `transform`이 아니면 만들기 번거롭습니다.

```python
store_total = df.groupby("store")["revenue"].transform("sum")
df["share_in_store"] = df["revenue"] / store_total
```

level06의 그룹별 중앙값 채우기도 같은 원리였습니다.

### 3-5. 정렬과 순서 — 리포트의 마무리

- 집계 결과는 기본적으로 그룹 키의 가나다순입니다. 보고서라면 `sort_values(ascending=False)`로 큰 값부터 줄 세우는 게 보통입니다.
- 요일처럼 **의미 있는 순서**가 있는 키는 가나다순이 오히려 방해가 됩니다. `reindex(["월", "화", ...])`로 원하는 순서를 강제하세요.

### 3-6. 집계 전 정제를 잊지 말 것

groupby의 집계 함수는 NaN을 조용히 건너뜁니다. 편리하지만, 음수 오염이 남아 있으면 합계가 그대로 왜곡됩니다. **level06의 정제 → 이번 레벨의 집계** 순서가 실무 파이프라인의 표준입니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture03_data_handling/level07_groupby_aggregation
python3 main.py
```

main.py는 1년치 매출을 정제한 뒤 "카페 체인 매출 분석 리포트"를 단계별로 만듭니다.

- **[1] 지점별 요약(agg)** — 총매출·평균·건수를 한 표로. 부산·수원 같은 뒤 번호 지점이 매출이 큰 구조가 보입니다(데이터에 심어진 지점 규모 효과).
- **[2] 요일별 평균과 주말 효과** — `reindex`로 월~일 순서를 잡고, 주말 평균 ÷ 평일 평균으로 "주말 배율"을 계산합니다. 약 1.2배가 나옵니다. 데이터 생성기에는 1.25배 효과가 심어져 있지만 광고비 기여분이 요일과 무관하게 더해져 배율이 조금 희석됩니다 — 집계 결과를 해석할 때는 이런 구조까지 생각해야 합니다.
- **[3] 카테고리별 비중** — 합계를 전체로 나눠 비중(%)을 만들고 내림차순 정렬합니다. 커피가 1위인지 확인해 보세요.
- **[4] 지점×카테고리 다중 키** — 25개 조합 중 매출 상위 5개를 뽑습니다.
- **[5] transform 파생 열** — 각 행의 "지점 내 매출 비중"을 만들고, 지점별 비중 합이 1이 되는지 검증합니다.
- **[6] 리포트 저장** — 지점별 요약표를 `outputs/store_report.csv`로 저장합니다. 이 CSV가 곧 "메일에 첨부할 보고서"입니다.

코드에서 가장 눈여겨볼 부분은 [2]의 요일 정렬입니다. 가나다순 함정을 `reindex` 한 줄로 해결합니다.

```python
weekday_order = ["월", "화", "수", "목", "금", "토", "일"]
by_weekday = df.groupby("weekday")["revenue"].mean().reindex(weekday_order)
```

2. **요일×카테고리 교차 질문** — "음료 매출이 가장 높은 요일은?" 을 코드로 답해 보세요. (힌트: 먼저 `df[df["category"] == "음료"]`로 거른 뒤 요일별 groupby, 마지막에 `idxmax()`.)
3. **광고비 효율** — 지점별로 `revenue 합 ÷ ad_cost 합`을 계산해 "광고비 1원당 매출"이 가장 높은 지점을 찾아 보세요. (힌트: agg로 두 열의 합을 각각 구한 뒤 나누면 됩니다.)

## 6. 자주 하는 실수

- **groupby만 쓰고 집계 함수를 안 붙이는 것** — `df.groupby("store")`는 아직 계산 전인 "그룹 설계도"일 뿐입니다. `.sum()` 같은 집계를 붙여야 결과가 나옵니다.
- **집계 결과가 Series라는 걸 잊는 것** — 열 이름이 사라져 당황하기 쉽습니다. 표로 다루고 싶으면 `reset_index()`를 붙이세요.
- **요일을 가나다순으로 두는 것** — "금, 목, 수, 월, 일, 토, 화" 순서의 표는 보고서 사고입니다. `reindex`로 순서를 지정하세요.
- **transform 자리에 agg를 쓰는 것** — 파생 열을 만드는데 크기가 안 맞는다는 에러가 나면 십중팔구 이 혼동입니다.
- **정제 없이 집계** — 음수 매출이 남아 있으면 지점별 합계가 그대로 오염됩니다. 집계 전에 반드시 level06 절차를 거치세요.
