# Lecture 03 · Level 01 — 엑셀에서 파이썬으로

> 엑셀에서 매일 하던 합계·필터·정렬을 코드로 옮겨 보고, 엑셀의 세 가지 한계 — 재현성·규모·자동화 — 를 코드가 어떻게 넘는지 체험합니다.

**난이도** ⭐ / **선행** level00 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

엑셀은 위대한 도구입니다. 배우기 쉽고, 눈으로 보면서 고칠 수 있고, 회사의 공용어입니다. 그런데 실무에서 데이터가 커지고 작업이 반복되기 시작하면 세 가지 벽에 부딪힙니다.

1. **재현성(reproducibility)**: 지난달 보고서 숫자가 어떻게 나왔는지 물으면 "필터 걸고, 어디 복사해서, 수식 넣고..."라는 기억에 의존한 답이 돌아옵니다. 클릭의 순서는 어디에도 기록되지 않습니다. 담당자가 바뀌면 숫자를 다시 만들 수 없는 경우도 흔합니다.
2. **규모(scale)**: 엑셀 시트는 약 104만 행이 물리적 한계이고, 실제로는 수십만 행부터 눈에 띄게 느려집니다. "파일이 안 열려요"는 데이터 실무자의 흔한 비명입니다.
3. **자동화(automation)**: 매주 월요일마다 같은 파일을 열어 같은 피벗을 만드는 일은, 사람이 하면 30분 + 실수 가능성이고, 코드가 하면 3초 + 매번 동일합니다.

파이썬으로 옮긴다는 것은 엑셀을 버린다는 뜻이 아닙니다. **"클릭의 절차"를 "읽을 수 있는 문서(코드)"로 바꾸는 것**입니다. 코드는 그 자체가 작업 설명서라서, 검토받을 수 있고, 재실행할 수 있고, 예약 실행할 수 있습니다.

## 2. 비유로 이해하기

엑셀 수작업은 **손맛으로 끓이는 찌개**와 같습니다. 그날은 맛있지만, "간장 조금, 어… 그다음 뭐 넣었더라"라서 같은 맛을 다시 내기 어렵습니다. 코드는 **계량이 적힌 레시피**입니다. 레시피가 있으면:

- 누가 끓여도 같은 맛이 납니다. → **재현성**
- 1인분 레시피를 그대로 100인분 솥에 적용할 수 있습니다. → **규모**
- 레시피를 조리 기계에 넣어 두면 매일 아침 자동으로 끓습니다. → **자동화**

그리고 레시피에 "소금 2스푼"이라고 적혀 있으면, 짜다는 컴플레인이 왔을 때 어디를 고칠지 정확히 알 수 있습니다. 코드 리뷰가 가능하다는 뜻입니다. 엑셀 파일의 실행 취소(Ctrl+Z) 기록은 파일을 닫는 순간 사라지지만, 코드는 남습니다.

## 3. 핵심 개념

### 3-1. CSV — 엑셀과 파이썬이 만나는 다리

CSV(Comma-Separated Values)는 쉼표로 값을 구분한 순수 텍스트 표입니다. 엑셀에서도 열리고, 메모장에서도 열리고, 파이썬에서도 읽힙니다. 서식·수식·차트는 없고 **값만** 있습니다. 그래서 시스템 간 데이터 교환의 표준처럼 쓰입니다. 이번 실습에서는 매출표를 CSV로 저장했다가 다시 읽습니다. 실무에서 "데이터 내려받기" 버튼이 주는 파일이 대부분 이 형식입니다.

### 3-2. 엑셀 작업 ↔ 파이썬 코드 대응표

| 엑셀에서 하던 일 | 파이썬 대응 |
|---|---|
| `=SUM(G2:G1000)` | `sum(값 리스트)` |
| 자동 필터로 "강남점"만 보기 | `[r for r in rows if r["store"] == "강남점"]` |
| 데이터 → 정렬 (내림차순) | `sorted(rows, key=..., reverse=True)` |
| SUMIF(지점별 합계) | 딕셔너리에 지점별로 누적 |
| 매크로 기록 | 스크립트 파일 그 자체 |

이 대응이 머리에 자리 잡으면 "엑셀로는 하겠는데 코드로는 어떻게 하지?"라는 질문이 "엑셀의 이 동작을 코드로 번역하면 뭐지?"로 바뀝니다. 훨씬 답하기 쉬운 질문입니다.

### 3-3. CSV의 함정 — 전부 문자열로 읽힌다

`csv.DictReader`로 CSV를 읽으면 모든 값이 문자열(str)로 들어옵니다. `"512000"`은 숫자처럼 보여도 문자열이라 `sum()`에 바로 넣을 수 없습니다. 그래서 읽은 직후 `int()`/`float()`로 변환하는 단계가 반드시 필요합니다. 빈 칸(`""`)은 변환하다 에러가 나므로 먼저 걸러야 합니다. 이 "타입 복원" 작업은 level04에서 판다스가 얼마나 편하게 해 주는지 비교하게 됩니다.

### 3-4. 검증 가능한 절차라는 관점

엑셀 수작업의 결과물은 "숫자"만 남습니다. 코드의 결과물은 "숫자 + 그 숫자를 만든 절차"가 함께 남습니다. 감사(audit)나 인수인계 상황에서 이 차이는 결정적입니다. 이번 main.py도 결측·음수 행을 몇 건 건너뛰었는지 스스로 보고하도록 만들었습니다. 좋은 데이터 코드는 자신이 무엇을 버렸는지 항상 말해 줍니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture03_data_handling/level01_excel_to_python
python3 main.py
```

스크립트의 흐름은 "엑셀 업무의 하루"를 그대로 코드로 번역한 것입니다.

- **[1] CSV 저장**: 60일치 매출표(1,500행)를 `outputs/sales.csv`로 저장합니다. 엑셀에서 이 파일을 직접 열어 봐도 좋습니다.
- **[2] CSV 읽기**: `csv.DictReader`로 다시 읽습니다. 이때 모든 값이 문자열임을 출력으로 확인합니다.
- **[3] 타입 복원 + 오염 건너뛰기**: `revenue`를 정수로 바꾸되, 빈 값과 음수는 건너뛰고 몇 건 건너뛰었는지 보고합니다.
- **[4] SUM**: 전체 매출 합계. 엑셀의 `=SUM()` 한 방과 같습니다.
- **[5] SUMIF**: 지점별 합계를 딕셔너리 누적으로 만듭니다.
- **[6] 자동 필터**: "강남점 & 주말" 행만 골라 평일과 매출 평균을 비교합니다.
- **[7] 정렬 상위 5**: 매출 상위 5행을 내림차순으로 출력합니다.
- **[8] 재현성 선언**: 이 스크립트를 100번 실행해도 같은 숫자가 나오는 이유(고정 seed + 기록된 절차)를 출력합니다.

출력에서 지점별 합계가 강남 < 홍대 < 부산 < 대전 < 수원 순으로 커지는 것, 주말 평균이 평일보다 높은 것을 확인해 보세요. 데이터 생성기에 심어 둔 패턴이 코드로 정확히 드러납니다.

## 6. 자주 하는 실수

- **CSV에서 읽은 값을 바로 계산에 사용**: `"500" + "300"`은 `"500300"`입니다. 읽은 직후 반드시 숫자로 변환하세요.
- **빈 문자열을 `int()`에 넣음**: 결측이 CSV에 `""`로 저장되는데, `int("")`는 `ValueError`를 냅니다. 변환 전에 빈 값 검사를 먼저 합니다.
- **한글 CSV를 다른 프로그램에서 깨진 글자로 봄**: 인코딩(encoding) 문제입니다. 이 커리큘럼은 UTF-8로 통일하며, 자세한 대처는 level04에서 다룹니다.
- **원본 파일을 코드로 덮어씀**: 원본은 읽기만 하고, 결과는 반드시 다른 파일(`outputs/`)에 저장하는 습관을 들이세요. 엑셀에서 원본 위에 "다른 이름으로 저장"을 잊는 실수와 같은 계열입니다.
