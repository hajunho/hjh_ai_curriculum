# Lecture 03 · Level 00 — 데이터란 무엇인가 — 표의 구조

> 데이터 분석의 출발점인 "표"를 해부합니다. 행은 사례, 열은 속성이라는 원리만 잡으면 엑셀도 파이썬도 같은 언어로 보입니다.

## 1. 왜 배우나 — 비즈니스 관점

회사에서 오가는 정보의 대부분은 결국 표로 정리됩니다. 매출 보고서, 고객 명단, 재고 현황, 근태 기록 — 형식은 달라도 전부 "여러 건의 사례를 같은 항목으로 기록한 것"입니다. 데이터 분석 도구가 엑셀이든, 파이썬이든, SQL이든, BI 대시보드든 상관없이 모두 이 표 구조 위에서 움직입니다.

그래서 표의 구조를 정확히 이해하는 것은 특정 도구를 배우는 것보다 먼저입니다. "이 표에서 행 하나는 무엇을 의미하는가?"라는 질문에 답할 수 있으면, 어떤 도구를 쓰든 절반은 시작한 것입니다. 반대로 이 질문에 답하지 못한 채 함수부터 외우면, 숫자는 나오는데 그 숫자가 무엇을 세었는지 모르는 상태가 됩니다. 실무에서 잘못된 보고의 상당수가 여기서 나옵니다.

이번 레벨에서는 아직 판다스(Pandas)나 넘파이(NumPy)를 쓰지 않습니다. 파이썬의 기본 재료인 딕셔너리(dictionary)와 리스트(list)만으로 표를 직접 만져 보면서, 도구가 감춰 버리기 쉬운 표의 본질을 손으로 확인합니다.

## 2. 비유로 이해하기

표는 **아파트 우편함 벽**과 비슷합니다. 우편함 하나하나(값)는 "몇 동 몇 호"라는 두 좌표로 정확히 지정됩니다. 표도 마찬가지로 "몇 번째 행, 어떤 열"이라는 두 좌표만 있으면 어떤 값이든 꺼낼 수 있습니다.

조금 더 업무에 가까운 비유는 **직원 인사기록 카드철**입니다.

- 카드 한 장 = **행(row)**. 직원 한 명이라는 "사례" 하나를 통째로 담습니다.
- 카드에 인쇄된 빈칸(이름, 부서, 입사일...) = **열(column)**. 모든 카드가 같은 빈칸을 갖습니다.
- 빈칸의 제목 목록 = **스키마(schema)**. "우리 카드에는 어떤 항목이 어떤 형식으로 적히는가"라는 약속입니다.

중요한 것은 카드철의 규칙입니다. 어떤 카드는 "입사일" 칸이 있고 어떤 카드는 없다면, 카드철 전체를 입사일 순으로 정렬할 수 없습니다. 표의 힘은 **모든 행이 같은 열 구조를 공유한다**는 약속에서 나옵니다. 이 약속이 있는 데이터를 정형 데이터라고 부르고, 약속이 없는 자유로운 기록(예: 고객이 남긴 리뷰 문장)을 비정형 데이터라고 부릅니다.

## 3. 핵심 개념

### 3-1. 행 = 사례, 열 = 속성

- **행(row, record)**: 관찰한 사례 하나. "2025년 1월 3일, 강남점, 커피 카테고리의 하루 매출"처럼 세상에서 일어난 일 한 건입니다.
- **열(column, attribute/변수)**: 모든 사례에 공통으로 기록하는 항목. 날짜, 지점, 카테고리, 매출액 같은 것입니다. 통계에서는 변수(variable)라고도 부릅니다.

표를 받으면 가장 먼저 물어야 할 질문이 있습니다. **"이 표의 행 하나는 무엇 한 건인가?"** 같은 매출 데이터라도 행이 "거래 1건"인 표와 "지점·카테고리별 하루 합계"인 표는 전혀 다르게 다뤄야 합니다. 이 단위를 그레인(grain, 낟알)이라고 부르기도 합니다.

### 3-2. 스키마 — 열의 이름과 타입의 약속

스키마는 두 가지를 정합니다.

1. 열의 **이름**: `date`, `store`, `revenue`처럼 어떤 항목이 있는가.
2. 열의 **타입(type)**: 각 항목이 문자열인가, 정수인가, 날짜인가.

타입이 중요한 이유는 연산이 타입에 따라 달라지기 때문입니다. `"100" + "200"`은 문자열 이어붙이기라 `"100200"`이 되고, `100 + 200`은 `300`이 됩니다. 실무 사고의 단골 원인입니다.

### 3-3. 정형 vs 비정형

| 구분 | 정형 데이터 | 비정형 데이터 |
|---|---|---|
| 형태 | 행·열이 고정된 표 | 자유 텍스트, 이미지, 음성 |
| 예 | 매출 대장, 회원 명단 | 고객 리뷰, 상담 녹취, 사진 |
| 집계 | `SUM`, 평균이 바로 가능 | 먼저 구조를 뽑아내야 가능 |

비정형이 열등한 것이 아닙니다. 정보량은 오히려 많습니다. 다만 **집계하려면 먼저 표로 바꾸는 작업**(예: 리뷰 → 긍정/부정 열)이 필요할 뿐입니다. 이후 강의(자연어 처리)에서 그 변환을 다룹니다.

### 3-4. 파이썬에서 표를 표현하는 가장 소박한 방법

딕셔너리 리스트(list of dicts)입니다.

```python
table = [
    {"store": "강남점", "revenue": 500000},
    {"store": "홍대점", "revenue": 420000},
]
```

- 리스트의 원소 하나 = 행 하나
- 딕셔너리의 키(key) = 열 이름

판다스의 DataFrame도 결국 이 구조를 훨씬 빠르고 편하게 만든 것입니다. 원형을 손으로 만져 두면 level03부터 배우는 판다스가 "마법"이 아니라 "편의 기능"으로 보입니다.

### 3-5. 결측 — 칸이 비어 있다는 사실도 정보다

현실 데이터에는 값이 기록되지 못한 칸이 반드시 있습니다. 파이썬에서는 `None`으로 표현합니다. "0"과 "비어 있음"은 완전히 다릅니다. 매출 0원은 "팔리지 않았다"는 사실이고, `None`은 "얼마 팔렸는지 모른다"는 상태입니다. 이 구분은 level06에서 본격적으로 다루지만, 표를 처음 볼 때부터 몇 칸이 비었는지 세는 습관을 들이는 것이 좋습니다.

## 4. 실습 — main.py

실행 방법:

```bash

```

이 스크립트는 가상 카페 체인 30일치 매출표(750행)를 만들어 다음을 수행합니다.

- **[1] 표의 크기**: 행 수(사례 수)와 열 이름(스키마)을 출력합니다. `rows[0].keys()`가 곧 열 목록입니다.
- **[2] 미리보기**: `hjh_data.head`로 표의 앞부분을 봅니다. 표를 받으면 무조건 먼저 눈으로 보는 습관입니다.
- **[3] 행 하나 해부**: 첫 행을 꺼내 "이 표의 행 하나 = 특정 날짜·지점·카테고리의 하루 매출"임을 확인합니다.
- **[4] 열 추출**: 리스트 컴프리헨션으로 `revenue` 열만 뽑아 열이 "같은 속성의 값 모음"임을 봅니다.
- **[5] 조건으로 행 찾기**: 강남점 커피 행만 골라 세어 봅니다. 필터의 원형입니다.
- **[6] 미니 스키마 요약**: 열마다 등장한 타입과 결측(`None`) 개수를 직접 세어 출력합니다. 판다스 `info()`가 해 주는 일을 손으로 만드는 셈입니다.
- **[7] 정형 vs 비정형**: 같은 정보를 자유 문장(비정형)으로 쓴 예와 비교하며, 문장에는 `SUM`을 걸 수 없음을 확인합니다.

출력에서 특히 `revenue` 열에 `None`이 몇 건인지, 그리고 음수 매출이 몇 건 섞여 있는지 눈여겨보세요. 일부러 오염시켜 둔 값이며, 이후 레벨에서 계속 만나게 됩니다.

## 6. 자주 하는 실수

- **행의 의미를 확인하지 않고 합계부터 구한다**: 이 표에서 `sum(revenue)`는 "카테고리별 일 매출의 총합"입니다. 행이 거래 건이라고 착각하면 "거래 750건"이라는 잘못된 보고가 나옵니다.
- **`None`과 0을 섞는다**: `None`이 섞인 리스트에 `sum()`을 바로 걸면 `TypeError`가 납니다. 에러가 나서 다행인 경우입니다. 몰래 0으로 바꾸면 평균이 왜곡됩니다.
- **열 이름 오타**: `rows[0]["revenu"]`처럼 키를 잘못 쓰면 `KeyError`가 납니다. 열 이름은 항상 `keys()`로 먼저 확인하세요.
- **타입을 눈으로 판단**: 화면에 `123`으로 보여도 실제로는 문자열 `"123"`일 수 있습니다. `type()`으로 확인하는 습관이 필요합니다.
