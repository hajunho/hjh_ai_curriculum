# Lecture 07 · Level 07 — 处理不平衡数据

> 在 5,000 笔交易只有 1.5% 是欺诈的数据里抓欺诈 — 学习 class_weight、重采样、阈值调整，以及用 PR 曲线读懂取舍。
**难度** ⭐⭐⭐⭐ / **先修** level01、level06 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

实际工作中真正押着钱的分类问题几乎全是不平衡 (imbalanced) 的。欺诈交易 1.5%、设备故障 0.5%、严重次品 2%、骗保 1% — 越是要抓的对象越稀有。可是在抓稀有事件的问题上照搬标准设置，模型就会躺进"全部判正常"这个偷懒的最优解。准确率 98.5%、欺诈检出 0 笔 — 一个数字光鲜却什么都不干的模型就此诞生。

这一关的目标有两个。第一，拿到唤醒懒惰模型的三种手段 (权重、重采样、阈值)。第二，通过表格和曲线，把召回率与精确率是**互相交换的关系**这件事刻进身体里。面对"给我做到召回率 90%"的要求，你得能回一句"那样精确率会掉到这个程度，调查团队的工作量要翻好几倍"，可行的目标谈判才算开始。

## 2. 用比喻来理解

草垛里找针。5,000 把干草里混着 75 根针。只对检查员 (模型) 下令"减少出错次数"，最省事的策略就是**什么都不捡** (只错 75 次，正确率 98.5%)。让检查员动起来的方法有三种。

- **权重 (class_weight)**: 把罚分表改成"漏一根针罚 65 倍"。检查员现在怕漏针，见到可疑的就捡。
- **重采样 (resampling)**: 动手脚改练习用的草垛。把针复制变多 (过采样) 或把草挪走一些 (欠采样)，让检查员在一个针很常见的世界里练习。考试 (测试) 仍按真实比例进行。
- **阈值 (threshold) 调整**: 原本"可疑分数"50 分以上才捡，现在降到 20 分就捡。捡得多，针找到得也多 (召回率↑)，但捡进来的草也多 (精确率↓)。

哪种方法都没有免费午餐。多抓就必然多误报 — 把这笔交换摆到眼前的工具，就是 PR 曲线。

## 3. 核心概念

### 3.1 为什么准确率会失效

正类 1.5% 时，"全判负类"的准确率是 98.5%。所以不平衡问题的基本指标是召回率·精确率·PR-AUC。ROC-AUC 也有人用，但正类极稀有时 ROC 曲线倾向于给出偏松的印象，**PR 曲线 (precision-recall curve)** 更诚实。

### 3.2 三种手段对比

| 手段 | 做什么 | 优点 | 注意点 |
|---|---|---|---|
| class_weight="balanced" | 在损失函数里对少数类失误重罚 | 一行搞定，数据不动 | 仅限支持它的模型 |
| 过采样 | 复制训练数据中的少数类 | 任何模型都适用 | **划分之后、只对训练数据!** 重复样本有过拟合风险 |
| 阈值调整 | 移动 predict_proba 的判定线 | 不用重训模型，运营中可随时调 | 必须用验证数据定 (用测试集定就是泄漏) |

还有个广为使用的进化版叫 SMOTE (对少数类做插值合成新样本)。它需要专门的包，这里只记住概念，实战用简单的复制式过采样验证原理。

### 3.3 重采样的黄金法则

重采样**必须在训练/测试划分之后、只施加在训练数据上**。划分前就过采样，同一样本的副本会同时进入训练和测试两边，性能被严重吹胀 (泄漏的变种)。另外，测试数据的比例绝对不许动 — 考试必须按真实世界的比例来。

### 3.4 怎么读 PR 曲线

把阈值从 1.0 一路降到 0.0，逐点描出 (召回率, 精确率)，就得到 PR 曲线。越往右 (召回率↑) 曲线越往下走 (精确率↓)，这正是取舍的可视化。曲线下面积 (PR-AUC, 平均精确率) 是模型的综合得分，而**在哪个点运营**不由模型决定，由业务 (调查人力、误报成本) 决定。这个"运营点设计"是 level10~11 的主题。

用 `fraud_table` 的 5,000 笔交易 (欺诈约 1.5%) 以四种方式训练·评估逻辑回归。

- [1] 默认设置: 确认在准确率 99% 这个光鲜数字的背后，约 30% 的欺诈被漏掉。
- [2] class_weight="balanced": 观察召回率起飞、精确率下沉。
- [3] 手动过采样 (只对训练数据复制少数类): 确认效果和加权类似。
- [4] 阈值调整: 用同一个模型从阈值 0.9 扫到 0.1，输出召回率/精确率/告警笔数表。
- [5] 用文字总结 PR 曲线 (PR-AUC)，并在"调查团队一天只能处理 15 单"的约束下计算合理的阈值。

观察要点: [2] 和 [3] 的结果差不多 (都是"改罚分表"的变体); [4] 的表里召回率与精确率反向而行。至于选表里的哪一行，那不是技术问题，是经营问题 — 请把这份直觉带走。

## 5. 动手试试

1. **(简单)** 给 [4] 的阈值清单加上 0.05。召回率能涨到多少、告警膨胀到多少单? 从调查团队人力成本的角度评价一下。
2. **(普通)** 换换过采样的倍数 (把少数类复制到 2 倍/10 倍/70 倍)。观察从哪个点开始效果停滞，并用"复制不会增加信息"这个视角解释。
3. **(挑战)** 故意写一段在划分**之前**过采样的错误代码，看性能被吹胀多少。提示: 在整个 df 上复制欺诈行后再 train_test_split — 副本混进测试集，召回率·精确率会涨到不真实的高度。

## 6. 常见错误

- **用准确率汇报成果**: 不平衡问题里准确率基本是违禁词。用召回率/精确率/PR-AUC 说话。
- **划分前重采样**: 最常见也最不显眼的泄漏。从流水线的视角看，重采样应当"仅在训练时"生效。
- **用测试数据调阈值**: 阈值也是超参数。用验证数据定，测试集封存。
- **照单全收"召回率 100%"的要求**: 召回率 100% 靠"拦截全部交易"也能达成。目标必须连同精确率 (或告警笔数) 约束一起定。
- **把"不平衡 = 必须重采样"当公式**: 很多时候光调阈值就够了。从简单的方法试起。
