# Lecture 07 · Level 02 — 探索性数据分析 (EDA) 的步骤

> 不是"先随便画几张图看看"，而是把"提出假设→验证"的循环和"单变量→双变量→时间"的顺序练成肌肉记忆。
**难度** ⭐⭐ / **先修** level00、lecture05 / **预计时间** 40分钟

## 1. 为什么要学 — 从业务视角出发

相当一部分建模失败，起点都是跳过了 EDA (Exploratory Data Analysis, 探索性数据分析) 或者做得潦草。不知道流失率是 18% 就用准确率评估、不知道缺失集中在哪个区间就直接求平均、把一眼就该识破的泄漏变量塞进特征 — 这些事故全都发生在这里。

在实际工作中，EDA 承担两种角色。第一，**排雷**: 在建模之前发现数据里的陷阱 (缺失、异常值、不平衡、泄漏)。第二,**生产假设**: 像"客服来电多的客户更容易流失"这样的发现，本身就值得向业务方汇报，也会成为下一关特征工程的原材料。很多项目根本没做模型、只交付一份 EDA 报告就收尾 — 那不叫失败，那是出色的成果。

## 2. 用比喻来理解

EDA 就是**体检**。医院在把病人推上手术台 (模型) 之前，会按固定顺序做检查。

1. **基础问诊 (数据概览)**: 身高、体重、年龄 — 行数、列类型、缺失比例。
2. **逐项检查 (单变量)**: 血压、血糖一项项看 — 逐个查看每个变量的分布。
3. **关联检查 (双变量)**: "血压和体重的关系" — 看变量与目标、变量与变量之间的关系。
4. **随访观察 (时间)**: 和去年的数值对比 — 看随时间的变化与趋势。

而且医生在检查之前会先立**初步诊断假设**。就像"腹痛先怀疑肠胃"一样，先写下"使用天数少的客户流失应该更多"这句假设，再用数据去核实。没有假设就狂画几十张图，等于不听主诉直接做全身 MRI — 又贵，又容易被偶然冒出来的信号骗到。

## 3. 核心概念

### 3.1 提出假设 → 验证的循环

EDA 的基本工作单元是: "①把假设写成一句话 → ②做出能验证它的最简表格/图 → ③写下判定 (支持/否决/存疑) → ④产生新假设就再来一轮"。要点是**先有句子，后有图**。有了句子才知道该画哪张图，句子也能原封不动搬进报告。

### 3.2 单变量 → 双变量 → 时间的顺序

- **单变量 (univariate)**: 单个变量的分布。平均、中位数、标准差、最小值、最大值、直方图。缺失、异常值、偏态 (歪斜的分布) 都在这一步抓出来。目标变量的比例 (流失率 18%) 也必须在这一步确认。
- **双变量 (bivariate)**: 变量 × 目标。分类问题里最有杀伤力的一招是"按目标分组比平均"。如果流失客户和留存客户的 `usage_days_30d` 平均差异很大，这个变量就是有前途的特征。数值变量之间则看相关系数 (correlation)。
- **时间 (temporal)**: 数据带时间轴时，看趋势、季节性和突变区间。churn_table 没有时间轴，本次实战略过，但它在 level08 (销售预测) 里是主角。

### 3.3 EDA 必须抓住的四大陷阱

| 陷阱 | 症状 | 后续处理 |
|---|---|---|
| 缺失 | 空值集中在特定列/区间 | 决定删除·填补策略 (lecture03) |
| 异常值 | 负数销售额、离谱的最大值 | 查明原因后删除/修正 |
| 不平衡 | 目标比例 18%、1.5% | 重新设计评估指标·权重 (level07) |
| 疑似泄漏 | 与目标相关系数 0.95 之类的可疑变量 | 确认生成时间点后剔除 (level03) |

### 3.4 怎么读相关系数

相关 +0.3 大致读作"弱正相关"，±0.7 以上读作"强相关"，但要记住两件事。第一，相关不是因果 (冰淇淋销量和溺水事故)。第二，相关高得离谱不是喜事，而是**要起疑心的事**。与目标相关 0.9 的变量，多半是"必须先知道答案才造得出来的变量" (泄漏)。

### 3.5 EDA 报告长什么样

EDA 的产出物不是一摞图，而是**带判定的句子清单**。好的格式是四列表: "假设 → 证据 (表/图编号) → 判定 → 对建模的启示"。例: "使用天数越少流失越多 → 图2 → 支持 → 核心特征候选"。这样整理下来，EDA 就直接变成特征清单 (level03) 和管理层汇报的初稿。

## 4. 实战 — main.py

```bash
python3 main.py
```

对 `churn_table` 的 2,000 名客户生成一份自动 EDA 报告。

- [1] 先把 3 条假设以句子形式输出 (验证之前)。
- [2] 基础问诊: 行/列、类型、缺失、目标比例。
- [3] 单变量: 各数值变量的汇总统计表。
- [4] 双变量: 流失/留存分组平均对比表和"差异倍率"，以及与目标的相关系数排行。
- [5] 假设判定: 对 [1] 的每条假设输出支持/否决。
- [6] 往 `outputs/` 保存 2 张图: ① 主要变量按流失/留存分组的分布对比，② 相关矩阵热力图。

代码的核心是 `df.groupby("churned")[cols].mean()` 这一行。双变量分析的八成就是这个 groupby 对比 — 请亲眼确认。热力图不过是把 `df.corr()` 的结果用 `imshow` 画出来而已。

## 6. 常见错误

- **漫无目的地生产几十张图**: 没有假设句子的图，在报告里全会被砍掉。先写句子，图只是证据。
- **没确认目标比例就开始建模**: 不知道不平衡的存在，之后所有评估都会失真。这是 EDA 的第一优先检查项。
- **只看平均不看分布**: 平均一样、分布形状不同，就是完全不同的数据。汇总表和直方图是一套的。
- **把 EDA 里看到的规律调到测试数据上**: 原则上测试数据在 EDA 阶段也要封存。如果用全量数据做了 EDA，请在报告里写明这一事实。
