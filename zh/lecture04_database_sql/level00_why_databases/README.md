# Lecture 04 · Level 00 — 为什么需要数据库

> 亲手用模拟程序体验一遍"Excel 文件传来传去"制造的三重灾难 (并发修改、数据一致性、权限)，再看看数据库是怎么解决这些问题的。

**难度** ⭐ / **先修** 无 (有 lecture02 水平的 Python 阅读能力即可) / **预计时间** 30分钟

## 1. 为什么要学 — 业务视角

你在公司里大概收到过这样的消息：
"别看《客户名单_最终版.xlsx》了，请以《客户名单_最终版_真最终_v3.xlsx》为准。"
从文件开始被传来传去的那一刻起，**哪个才是真的**就没人说得清了。
两个人同时改同一个文件，其中一个人的工作会悄无声息地消失；
同一个客户在不同表里写法不同，销售合计每次算出来都不一样；
一份带着薪资信息的文件，只因一封"供参考"的邮件就传遍了全公司。

数据库 (Database, DB) 就是为了解决这些问题而生的工具。
它不是"比 Excel 更难的东西"，而是"防止 Excel 传阅事故的东西" ——
想通了这一点，你就会开始明白为什么每一套公司系统背后都有一个数据库。

## 2. 打个比方

**Excel 传阅 = 把账本复印后分头保管**。想象一下财务部把总账拿去复印，
销售部、市场部各拿一份回去自己改。一个月后，三本账上的数字全都对不上。
想搞清楚谁是对的，就只能加班把三本账一行一行地核对。

**数据库 = 保险柜里的原始账本 + 柜台职员**。账本原件只有一本，锁在保险柜里。
谁都不能直接翻账本，而是向柜台职员 (DBMS，数据库管理系统)
提出**请求**："请把 3 号客户的地址改一下"、"请给我看这个月的销售额"。
柜台职员让请求排成一队按顺序处理 (解决并发修改)，
拒绝任何违反账本规则的记录 (保证一致性)，
并核对请求人的权限，只给他看该看的部分 (权限管理)。

跟这位柜台职员说话所用的标准语言，就是 SQL (Structured Query Language，
结构化查询语言)，也是这整门课要学的内容。

## 3. 核心概念

### 3-1. 并发修改问题 (Lost Update)

小王和李经理各自打开同一个 Excel 副本，改了不同的单元格再先后保存 ——
**后保存的那个人的文件会整个获胜**。先保存的人的修改会消失得无影无踪。
这叫更新丢失 (lost update)。最可怕的是**它连报错都没有**，
数据就在无人察觉中丢掉了。

数据库把修改请求集中到一处按顺序处理：改不同行的两个请求都会生效；
改同一行的请求则通过锁 (lock) 保证先后顺序。

### 3-2. 一致性问题 (Integrity)

Excel 的单元格里什么都能填。数量栏填"三个"，日期栏填"大概周一"，
同一个客户被登记成"华彩有限公司"和"华彩公司"两条 ——
这些几乎无法阻止。这就是每次汇总数字都不一样的原因。

数据库在建表时会**先声明规则**："数量只能是整数"、"客户编号不许重复"、
"订单里的客户编号必须真实存在于客户名单中"。
违反这些规则 (约束条件, constraint) 的数据，连保存这一步都过不去。

### 3-3. 权限问题 (Access Control)

Excel 文件一旦被复制就彻底失控。为了一列薪资数据，要么整个文件都不能发，
要么只能拜托对方"这一列就当没看见吧"——完全不现实。
数据库可以针对每个用户在柜台上设置权限："这张表只许查询"、
"这一列干脆看不见"。原件从头到尾都不会离开保险柜。

### 3-4. 那么什么时候该用数据库

| 场景 | Excel | 数据库 |
|---|---|---|
| 一个人用的一次性计算 | ✅ 最合适 | 大材小用 |
| 多人修改同一份数据 | ❌ 事故预定 | ✅ |
| 几十万行以上 | ❌ 变慢/到极限 | ✅ |
| 有规则的数据 (订单、会员、库存) | ❌ 会被污染 | ✅ |
| 含敏感信息 | ❌ 泄露风险 | ✅ 权限管理 |

这不是说 Excel 是坏工具，而是说：需要**多人、长期、按规则**维护的
数据原件，不适合放在 Excel 里。实际工作中的最强组合是
"原件放数据库，分析和报表用 SQL 取出来交给 Excel/Python"。

## 4. 动手练习 — main.py

运行:

```bash
python3 main.py
```

这个关卡的 main.py 不懂 SQL 也能读。它分四步用 Python 模拟重现
"Excel 式"的事故，最后与数据库方式做对比。

- **[1] 并发修改事故**: 小王和李经理各自复制同一个"文件"(字典列表)，
  改了不同的条目后先后"保存"。请在输出里亲眼确认小王的修改消失了 ——
  而且连一行报错都没有。
- **[2] 一致性污染**: 用一份"同一客户写法不同、录了两次"的名单按往来单位
  汇总，本该是一家的单位被拆成两家，报表就错了。
- **[3] 权限缺失**: 展示"把文件整个发出去的那一刻，薪资列也跟着出去了"的场景。
- **[4] 数据库方式**: 用 Python 内置的 sqlite3 创建真正的数据库
  `hjh_shop.db`，验证两个连接 (相当于两位用户) 分别修改不同的行时
  **两边的修改都被安全保留**，以及错误数据 (文字型数量)
  **在保存环节就被拒绝**。

请注意输出中的对比: [1] 的最后一张表里只剩李经理的修改，
而 [4] 的表里两个人的修改都在。同样的剧本，不同的结局 ——
这个差异就是整门课的出发点。

## 6. 常见误区

- **把"数据库 = 大号 Excel"**: 核心差异不在容量，而在*柜台 (请求处理)*
  的存在。规则检查、顺序保证、权限管理全都发生在柜台。
- **想彻底抛弃 Excel**: 一次性分析和报表，Excel 依然是王者。
  只需把原件保管和多人修改交给数据库就好。
- **"我们公司用共享网盘，没这问题"**: 就算是支持协同编辑的在线表格，
  一致性规则、精细权限、海量数据这些也解决不了。问题只解决了一半。
- **去搜索"怎么安装 sqlite3"**: SQLite 是 Python 内置的，
  `import sqlite3` 一行就够。这整门课没有任何需要安装的东西。
