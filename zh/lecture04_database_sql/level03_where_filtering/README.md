# Lecture 04 · Level 03 — WHERE: 条件查询

> 学习不要"全部"、只取"符合条件的那部分"的方法。比较运算、AND/OR、IN、LIKE、BETWEEN、NULL 处理 — 把 6 个业务问题翻译成 SQL。

**难度** ⭐⭐ / **先修** level02 / **预计时间** 40分钟

## 1. 为什么要学 — 业务视角

工作中的数据问题几乎全都带条件: "住在北京的 **VIP** 客户"、
"**已取消**的订单"、"**三季度**的销售额"、"**姓王**的负责人"。
在 Excel 里点筛选按钮、勾复选框的活儿，在 SQL 里就是 WHERE 一行。
区别在于: Excel 的筛选每次都得动手再点一遍，而 WHERE 语句**存下来就能
随时用同样的条件重跑**；而且不用费口舌解释筛选条件，
把语句直接发给同事就行。当别人问"你是按什么条件取的数？"时，
用一行查询作答 — 这就是数据沟通的精确性。

## 2. 打个比方

WHERE 是递给柜台职员的申请单上的**第三栏**。

> 从哪本账本 (FROM) / 要哪些项目 (SELECT) / **只要哪些行** (WHERE)

柜台职员一行一行地翻账本，对每一行发问: "这位客户住北京吗？
而且是 VIP 吗？" — 只有答案为"真 (true)"的行才被放进结果篮子。
也就是说，WHERE 后面跟的是**对每一行判定真/假的语句**。

它和 lecture02 学过的 Python if 条件式扮演一模一样的角色。
`if city == "北京" and grade == "VIP":` 写成 SQL 就是
`WHERE city = '北京' AND grade = 'VIP'` — 区别只有等号是一个 (=)、
字符串用单引号这两点。

## 3. 核心概念

### 3-1. 比较运算符

`=` (等于)、`<>` 或 `!=` (不等于)、`>`、`>=`、`<`、`<=`。
和 Python 不同，"等于"不是 `==` 而是一个 `=`。

```sql
WHERE price >= 100000        -- 10万韩元以上
WHERE status <> '已取消'      -- 不是已取消的
```

### 3-2. AND / OR / NOT — 条件组合

```sql
WHERE city = '北京' AND grade = 'VIP'          -- 两个都满足
WHERE grade = 'VIP' OR grade = 'GOLD'          -- 满足一个就行
```

AND 比 OR 先计算。`A OR B AND C` 会被解释成 `A OR (B AND C)`，
很容易和本意跑偏。请养成习惯: **只要混进了 OR，就无条件加括号**。

### 3-3. IN — 名单中的任意一个

`grade IN ('VIP', 'GOLD')` 是 `grade='VIP' OR grade='GOLD'` 的缩写。
名单越长，IN 的可读性优势越压倒性。反义是 `NOT IN`。

### 3-4. LIKE — 模式匹配

对字符串做"以~开头/结尾/包含"的搜索。`%` 表示"任意 0 个以上的字符"，
`_` 表示"任意正好 1 个字符"，它们叫通配符。

```sql
WHERE name LIKE '王%'      -- 以王开头 (姓王)
WHERE name LIKE '%咖啡%'   -- 名称里含有咖啡的商品
```

### 3-5. BETWEEN — 范围

`price BETWEEN 10000 AND 100000` 等价于
`price >= 10000 AND price <= 100000`。记住它**包含两端**。
日期字符串也能直接用，是期间查询的常客:
`ordered_at BETWEEN '2025-07-01' AND '2025-09-30'` (三季度)。

### 3-6. NULL — 怎么对付"没有值"

NULL 既不是 0 也不是空字符串，而是**"没有记录"**。
所以普通的比较对它不管用。`manager_id = NULL` 永远为假，
一行都查不出来。必须用专用语法。

```sql
WHERE manager_id IS NULL       -- 没有上级的人 (= 最高负责人)
WHERE manager_id IS NOT NULL   -- 有上级的人
```

"为什么 = 不行？" — 因为 NULL 的含义是"不知道"，
"不知道 = 不知道"的答案还是"不知道"。这是 SQL 新手事故榜第一名，
IS NULL 这一条请务必背下来。

## 6. 常见误区

- **`= NULL`**: 永远 0 条。只记 `IS NULL` / `IS NOT NULL`。
- **OR 忘加括号**: `WHERE city='北京' OR city='上海' AND grade='VIP'`
  会变成"北京全体 + 上海的 VIP"。如果本意是"北京、上海的 VIP"，
  要写 `(city='北京' OR city='上海') AND grade='VIP'`。
- **字符串和数字比较**: 像 `'100' > 20` 这种带引号的比较会因为
  数据类型混杂得出离谱的结果。数字列比较时不要加引号。
- **LIKE 的大小写**: SQLite 的 LIKE 不区分英文大小写，
  但别的数据库 (如 PostgreSQL) 区分。在公司数据库里结果对不上时，
  先怀疑这一点。
- **BETWEEN 的日期端点**: `BETWEEN '2025-07-01' AND '2025-09-30'`
  包含 9 月 30 日。但如果数据库的日期带时刻，可能被解释成
  "到 9 月 30 日 0 点为止"，所以实战中也要会 `< '2025-10-01'` 这种写法。
