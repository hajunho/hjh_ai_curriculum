# Lecture 09 · Level 00 — 计算机是怎么"看"图像的

> 一张照片在计算机里只是一张数字网格 — 我们把图形图像打印成文本艺术，亲眼确认这件事。
**难度** ⭐ / **先修** 无 (有 lecture03 level02 的 NumPy 基础会更轻松) / **预计时间** 25分钟

## 1. 为什么要学 — 从业务视角出发

听到"AI 看照片就能抓出不良品"，人们很容易想象计算机像人一样在'看'。但对计算机来说，图像从头到尾都是一张**数字表**。不知道这个事实，在视觉 AI 项目里就会做出奇怪的判断。"干嘛要降分辨率? 画质好不是更好吗?" (数字多了 4 倍，计算量也是 4 倍)、"光线暗一点也没关系吧?" (所有数字整体变小，模型会犯糊涂) —— 要想自己回答这类问题，就得有"图像是数字"这个出发点。

熟悉 Excel 的人反而更有优势。因为一张图像和**每个单元格里写着亮度数字的一张电子表格**完全是同一回事。这一关结束后你会明白"图像处理"就等于"表格计算"，而这种直觉是整个 lecture09 的地基。

## 2. 用比喻来理解

想象一幅**马赛克壁画**。远看是一张人脸，走近了看，只是几千块小小的单色瓷砖排成的格子。人脸不在某一块瓷砖里，人脸在**瓷砖的排列之中**。

数字图像正是如此。一块瓷砖就是**像素 (pixel)**，瓷砖的颜色就是**像素值 (数字)**，瓷砖的数量就是**分辨率 (resolution)**。16×16 的图像是 256 块瓷砖的马赛克，手机照片 (4000×3000) 是 1,200 万块瓷砖的马赛克。

另一个比喻是**座位表**。就像在演出场馆的座位表上用"3 排 7 号"找座位，在图像里我们也用 `img[3, 7]` 取出一个像素。行 (row) 在前，列 (column) 在后 —— 只要记住这和 Excel 的"行、列"顺序一样就够了。

## 3. 核心概念

### 3.1 黑白图像 = 二维数字数组

黑白 (grayscale) 图像是形状为 `高 × 宽` 的二维数组。每个格子里的数字就是亮度。

- 0.0 = 纯黑，1.0 = 纯白，0.5 = 中灰 (也常用 0~255 的整数来表示)
- 本课程的图形图像是 16×16、取值 0.0~1.0 的 float 数组。

也就是说，下面左边的"图画"和右边的"数字表"是完全相同的东西。

```
■ □        1.0  0.0
□ ■        0.0  1.0
```

### 3.2 分辨率 — 瓷砖数量的取舍

分辨率越高越精细，但数字的个数会按宽×高的比例爆炸式增长。16×16 是 256 个，32×32 是 1,024 个 (4 倍)，1024×1024 超过 100 万个。在深度学习里，每一个输入数字都是计算量，所以实务中"找到能解决任务的最小分辨率"是一个重要的设计决策。在不良检测里，只要划痕能看成 3 个像素大小的分辨率就够了，再往上就是成本。

### 3.3 亮度 — 数字的大小

图像的"亮/暗"无非就是数字大还是小。光线暗了一半，所有像素值大致都会变成一半。同样的图形，亮度不同数字数组就会差很多，所以搭建视觉系统时，"固定拍摄条件"占了数据质量的一半。(用代码调节亮度的方法在 level01 讲。)

### 3.4 彩色怎么办? — 预告

彩色图像是红、绿、蓝 (RGB) 三张亮度表叠在一起。也就是 `高 × 宽 × 3` 的数组。这一关只讲黑白，通道 (channel) 的故事在 level01 正式展开。

### 3.5 今天用的数据 — 亲手画的图形

本课程不下载著名数据集。我们用 `common/hjh_data.py` 里的 `shape_images()`，它用 numpy 当场画出 16×16 的黑白图形 (正方形、圆形、三角形，3 个类别)。位置和大小随机，还混入了噪声，所以虽然小，却具备"真正的分类问题"该有的全部性质。

## 4. 实战 — main.py

运行:

```bash
python3 main.py
```

这个程序用三种方式 —— 数字表、文本艺术、PNG —— 展示它们是"同一份数据"。

- **[1]** 用 `shape_images()` 生成图形图像，并输出数组的形状 (shape)、取值范围、类别构成。
- **[2]** 把一张图像原样输出成**小数数字网格**。在满屏的 0.0 和 1.0 之间，找找看图形的轮廓在哪里。
- **[3]** 把同一张图像输出成**文本艺术**。按亮度区间分配 ` .:-=#@` 这样的字符，数字网格就突然能被读成"图画"了。只改了一条数字→字符的规则，人眼就看见了图形 —— 这就是"图像是数字"的体验版。
- **[4]** 分辨率比喻: 把 16×16 图像糊成 8×8、4×4 (2×2 块取平均)，用文本艺术做对比。瓷砖一少，到某个临界点圆和正方形就再也分不开了，请用眼睛确认这个点。
- **[5]** 把每个类别的图形样本共 9 张保存为 `outputs/shapes_grid.png`。打开文件看看 —— 和你刚才用文本看的是同一个数组。

代码的核心是 `to_ascii()` 函数。`int(v * (len(chars) - 1))` 一行就把亮度 0~1 换成了字符索引。这个五行的小函数说明: 所谓渲染，归根结底就是"把数字换成好看的符号的规则"。

## 5. 动手试试

1. **(简单)** 把 `[3]` 的字符调色板 `" .:-=+*#@"` 倒过来再运行。图形会看起来像反相 (负片)。请用一句话解释为什么。(提示: 想想暗像素被分配到了哪个字符)
2. **(普通)** 把 `[4]` 的块平均改成取块的**最大值**来缩小。图形会更粗地活下来。这种做法的名字就是 level04 要学的"最大池化"。(提示: `block.mean()` → `block.max()`)
3. **(挑战)** 用 `shape_images(size=32)` 提高分辨率再打印文本艺术。终端窄的话行会折行。也想一想为什么每像素打两个字符 (`chars[idx] * 2`) 宽高比就自然了。(提示: 终端的字符是竖长的)

## 6. 常见错误

- **误写成 `img[x, y]`**: NumPy 图像是 `img[行, 列]` 也就是 `img[y, x]` 的顺序。先写横坐标，你就会遇到图像像转了 90 度一样的 bug。
- **取值范围搞混**: 把 0~1 的 float 图像和 0~255 的整数图像混着用，画面会一片惨白或一片漆黑。拿到数组先打印 `min/max`，把这个习惯养起来。
- **以为分辨率 = 质量**: 分辨率是成本。任务要多少就用多少，这是实务的基本功。
- **以为"计算机认识图形"**: 现阶段的计算机手里只有 0.0 和 1.0 的数组。从数字数组里把"图形"这个意义抽出来，正是这门课剩下 11 关要做的事。
