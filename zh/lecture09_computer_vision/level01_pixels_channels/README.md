# Lecture 09 · Level 01 — 像素、通道与图像运算

> 调亮度是加法，调对比度是乘法，反相是减法 — 我们用 numpy 的算术亲手做出修图 App 上的那些按钮。
**难度** ⭐⭐ / **先修** level00 / **预计时间** 30分钟

## 1. 为什么要学 — 从业务视角出发

在视觉 AI 项目里，比建模更早遇到的活儿是**预处理 (preprocessing)**。门店监控白天黑夜亮度不同，扫描文档对比度偏弱，每台相机的分辨率还各不相同。这样的图像直接塞给模型，性能就会剧烈晃动。实务流水线的第一步永远是"亮度归一化、尺寸统一、裁出感兴趣区域"这类图像运算。

这些运算不是 Photoshop 的专利。正如 level00 所见，图像就是数字表，所以**调亮度 = 给所有单元格做加法，调对比度 = 给所有单元格做乘法**。这和在 Excel 里给整列填 `+10` 是同一件事。有了这种感觉，你才能问出"预处理你们做了什么?"并听懂对方的回答。

## 2. 用比喻来理解

想象一下**舞台灯光控制台**。

- **把总推子往上推** → 整个舞台均匀变亮 = 给所有像素**加**同一个数
- **把调光倍率加大** → 亮的更亮，暗的只亮一点，差距被拉开 = 给所有像素**乘**同一个数 (对比度)
- **负片胶卷** → 原来亮的变暗，原来暗的变亮 = `1 - 像素值` (反相)

再说彩色。舞台灯光是把红、绿、蓝三台灯叠起来调出各种颜色。彩色图像也一样。**红色亮度表、绿色亮度表、蓝色亮度表** —— 三张黑白图像叠起来就是 RGB 彩色图像。其中的每一张就叫做一个**通道 (channel)**。

## 3. 核心概念

### 3.1 通道 — 彩色就是三张黑白

彩色图像是 `(高, 宽, 3)` 的数组。`img[:, :, 0]` 是红色通道，`[..., 1]` 是绿色，`[..., 2]` 是蓝色。一个像素就是 3 个数字 (R, G, B) 的组合，(1, 0, 0) 是纯红，(1, 1, 0) 是黄色，(1, 1, 1) 是白色。灰度转换就是三个通道的加权平均 (人眼对绿色敏感，所以惯例用 `0.299R + 0.587G + 0.114B`)。

### 3.2 像素运算四兄弟

| 运算 | 公式 | 灯光控制台比喻 | 注意 |
|---|---|---|---|
| 亮度 (brightness) | `img + b` | 总推子 | 超过 1.0 的部分要截断 (clip) |
| 对比度 (contrast) | `(img - 0.5) * a + 0.5` | 调光倍率 | 以中心 0.5 为轴向两边拉开 |
| 反相 (invert) | `1 - img` | 负片胶卷 | — |
| 截断 (clip) | `np.clip(img, 0, 1)` | 安全限幅器 | 运算后必查 |

对比度里为什么要先 `- 0.5`: 直接 `img * 2` 只会让整体变亮而已。必须以中间亮度 (0.5) 为轴上下拉开，才能做到"暗的更暗，亮的更亮"。

### 3.3 几何运算 — 裁剪与缩放

- **裁剪 (crop)**: 只切出感兴趣区域。它就是 numpy 切片本身 —— `img[y0:y1, x0:x1]`。和在 Excel 里复制表格的一部分范围是一回事。
- **缩放 (resize)**: 改变尺寸。最简单的办法是**最近邻 (nearest neighbor)** —— 在新坐标上取离它最近的原始像素值。放大时像素会显出台阶般的棱角，那就是这个方法诚实的局限 (实务库会用混合周围像素的插值)。

### 3.4 归一化 — 送进模型前的最后一道关

深度学习模型对输入数字的范围很敏感。所以训练前要把图像调成"均值在 0 附近、尺度相近"。最常见的两种做法是把 0~255 除成 0~1，以及 `(img - 均值) / 标准差`。"拍摄条件对不齐，那就用代码对齐" —— 这就是归一化在实务上的含义。

## 4. 实战 — main.py

运行:

```bash
python3 main.py
```

这个程序只用 numpy 造出 RGB 图像，并把所有图像运算汇总成一张对比图 PNG。

- **[1]** 用 numpy **亲手画**一张 48×48 的 RGB 图像 (天空渐变 + 红色方块 + 黄色圆)。先确认一件事: 不下载、也没有图片文件，仅靠操作数组就能出彩色画面。
- **[2]** 把 R/G/B 通道逐张分离，输出每个通道里哪个物体看起来亮。红色方块在 R 通道上亮、在 B 通道上暗 —— "红"的真身用数字显形了。
- **[3]** 分别施加亮度 (+0.25)、对比度 (×1.8)、反相、灰度转换，并把运算前后的像素值统计 (min/mean/max) 输出成表。也故意展示不做 clip 时数值会超过 1.0。
- **[4]** 亲手实现裁剪 (只取方块部分) 和最近邻缩放 (48→96 放大、48→16 缩小)。请在 PNG 里确认放大版的台阶现象。
- **[5]** 把原图、3 张通道和各运算结果做成 3×4 的对比网格，保存到 `outputs/pixel_ops.png`。

代码的核心是 `resize_nearest()`。用 `np.linspace` 造出"新图像每个像素该参考原图哪个坐标"的索引数组，再靠花式索引一行 `img[yy][:, xx]` 就把缩放搞定。不用循环、只靠数组索引就完成几何运算 —— 这就是 numpy 式的思维方式。

## 6. 常见错误

- **忘了 clip**: `img + 0.5` 之后即使值变成 1.4，numpy 也不会报错。只有到了保存、显示的环节才会发现颜色诡异地跳了。像素运算之后，习惯性地 `np.clip`。
- **整数图像上的溢出**: 在 0~255 的 uint8 数组上做 200+100，结果不是 300 而是 44 (溢出)。先转成 float 计算、最后再转回来才安全。
- **通道顺序搞混**: 本课程用 RGB 顺序，但部分库 (OpenCV 等) 用 BGR 顺序。人脸照片变蓝的情况 90% 是通道顺序的 bug。
- **以为缩放能让信息复活**: 把 16×16 放大到 96×96，信息不会增加。只是看起来大了。不存在的细节造不出来。
