# Lecture 10 · Level 00 — 计算机处理语言为什么难

> 明明算数飞快的计算机，为什么一碰到句子就犯迷糊？亲手跑几个失败案例，体感一下问题有多大。
**难度** ⭐ / **先修** 无 (有 lecture02 的字符串基础更好) / **预计时间** 25分钟

## 1. 为什么要学 — 业务视角

公司数据的大头不是表格，而是**文字**。客户评论、客服记录、邮件、合同、
会议纪要 — 业界常说，全部数据的 80% 以上都是这类非结构化文本。
销售表用 Excel 求个和就行，但"客户是不是对物流很不满？"这种问题，
只有读了文字才能回答。人读不过来，想让计算机代劳，
计算机却根本不'理解'文字。

这一关的目标，是在学技术之前**先准确认识问题的大小**。
曾经以为"往搜索框里敲个词不就行了？"的人，亲眼看过简单字符串匹配
在哪儿、怎么塌掉之后，后面 11 关要学的工具为什么必须存在，
自然就想通了。

## 2. 打个比方

对计算机来说，语言就像**给一个一句中文都不会的外籍新员工塞一本词典，
就让他去接客服电话**。

这位新员工查词典 (字符串匹配) 的本事是满分的。文档里有没有"退款"两个字，
0.001 秒就能找到。可是:

- 客户写"把钱退给我"，他就找不到了。词典里没有'退款'和'把钱退回来'
  是同一个意思的连线。(**同义词问题**)
- "苹果发布会"里的苹果是水果还是公司，他分不清。
  同样的字可以有好几个意思，这件事他根本不知道。(**歧义问题**)
- 碰上"物流挺快，哈哈，再也不买了"这种前后文反转的句子，
  他只看到'挺快'就归成了好评。(**上下文问题**)
- "yyds"、"性价比拉满"这类词，词典里压根没有。(**新词问题**)

接下来要学的 NLP (自然语言处理, Natural Language Processing)，
就是教这位新员工从'查词典'升级到'从统计中学会词的用法'的全过程。

## 3. 核心概念

### 3-1. 歧义 (ambiguity) — 同样的字，不同的意思

中文里"苹果"既是能吃的水果，也是一家手机公司。"打"字更是能打车、
打饭、打电话、打瞌睡。人看一眼句子就自动分清了，但在字符串匹配眼里，
两个"苹果"是完全相同的字节序列。

| 句子 | 人的理解 | 字符串匹配的理解 |
|---|---|---|
| 苹果又发布了新款手机 | 苹果(公司) | 发现"苹果" (无法区分) |
| 这苹果又脆又甜 | 苹果(水果) | 发现"苹果" (无法区分) |

区分意思的线索不在字上，而在**周边的词 (上下文)** 里。有"发布/手机"
就是公司，有"脆/甜"就是水果。这个直觉 — *词的意思由周边的词决定* —
正是 level06 词嵌入的理论根基 (分布假说)。

### 3-2. 上下文与反话 — 部分之和不等于整体

句子里有个"好"字，不代表就是好评。

- "质量很好" → 好评
- "说是很好才买的，结果彻底失望" → 差评
- "不好" → 差评 (只差一个字)

逐个数单词的方式 (level04 的 BoW) 在这里露出短板，
而看顺序和上下文的模型 (level07 RNN、level08 注意力) 负责补上。

### 3-3. 中文没有空格 — 词的边界要自己找

英文单词之间有空格，句子天然就切好了。中文却是**连续的汉字流**:
"配送和服务都满意"里，"配送"、"和"、"服务"之间没有任何缝隙。
计算机想按词统计，就必须先回答"词从哪儿切到哪儿"——这一步叫
分词 (word segmentation)，是中文 NLP 独有的第一道关卡。

不分词直接用子字符串匹配，会闹出经典笑话: 在"配送和服务都满意"里
搜"和服"，居然能搜到 — 匹配横跨了"和|服"的词边界，凭空捞出一件
日本和服。反过来，切分本身也有歧义: "南京市长江大桥"是
"南京市|长江大桥"还是"南京|市长|江大桥"？这就是 level03 要正面
处理的问题。作为对照，韩语走的是另一个极端 — 词后面粘着助词、
词尾不断变形 ("배송이/배송은/배송을"都是'配送')，所以韩语 NLP 的
第一关是形态素分析。语言不同，第一道坎不同，但"先把句子切对"
这个需求是共通的。

### 3-4. 语言在不停地出生

2015 年的词典里没有"内卷"也没有"yyds"。规则手册编得再全，
语言变得比手册快。所以现代 NLP 掉转方向，不再让人写规则，
而是**从数据中学习模式** (lecture06 学过的机器学习哲学)，
还发明了把生词拆成碎片来处理的子词方法 (level03)。

## 4. 动手练习 — main.py

运行:

```bash
python3 main.py
```

main.py 先搭一个"简单字符串匹配客服机器人"，再故意把它弄塌给你看。

- **[1] 同义词失败**: 搜"退款"关键词漏掉"把钱退给我"的现场。
  6 条真实退款请求能找到几条，输出命中率 (实测 2/6, 33%)。
- **[2] 歧义失败**: 摆出 6 个含"苹果"的句子，字符串匹配对它们一视同仁，
  但靠周边词提示可以把 公司/水果 全部分对 (6/6)。
- **[3] 情感关键词的背叛**: 用"好/满意"关键词判定好评的规则，
  把差评句 ("说是很好才买的，结果彻底失望") 判错的混淆案例，逐条输出 (6 条错 3 条)。
- **[4] 无词边界实验**: 按空格切分的精确匹配在中文里检出 0 条，
  子字符串包含却把"重新配送"、"免费配送"都拽进来，还会跨词边界
  在"配送和服务"里搜出"和服"。
- **[5] 路线图**: 最后打印每种失败在这门课的第几关得到解决。

核心代码是一行函数 `keyword_match(text, keywords)`。这个简单函数
能撑到哪儿、又在哪儿塌掉，就是这一关的全部内容。

## 5. 自己动手试试

1. **(简单)** 往 `AMBIGUOUS_SENTENCES` 里加 2 个含"小米"(谷物/公司) 的句子，
   并补全提示词词典 (`CONTEXT_HINTS`)，看看能不能区分。
   提示: "熬小米粥"的线索是'熬'和'粥'。
2. **(中等)** 给 [3] 的好评关键词规则加一条"附近有否定词就反转"的规则
   (例如句子里出现'不'、'失望'、'坏'就判差评)。观察准确率是否上升，
   以及仍然判错的是哪些句子。
3. **(挑战)** 用自己的话写 3 行: 为什么规则加得再多也到不了 100%？
   提示: 每加一条规则，就会冒出这条规则的新例外 —
   这就是规则方法的本质极限。

## 6. 常见误区

- **"搜索不是挺好用的吗?"** — 谷歌和公司内部搜索好用，是因为背后跑着
  分词、同义词词典和嵌入。那不是纯粹的字符串匹配。
- **把子字符串包含 (`in`) 当万能**: "配送"会匹配到"重新配送"、"配送费"，
  甚至"和服"能匹配进"配送和服务"。抓得宽就混进杂物，抓得窄就漏掉目标。
- **忘记大小写、全角半角**: "AS申请"、"as 申请"、"ＡＳ申请"是三个
  不同的字符串。下一关 (预处理) 正面处理。
- **以为中文和英文 NLP 难度一样**: 英文靠空格切分就能凑合，
  中文跳过分词这一步，后面的统计和检索质量会大打折扣。
