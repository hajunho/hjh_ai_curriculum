# Lecture 10 · Level 01 — 文本预处理基础

> 把脏乱的评论文本一步一步洗成可分析的状态，亲手搭出一条清洗流水线。
**难度** ⭐⭐ / **先修** level00 / **预计时间** 35分钟

## 1. 为什么要学 — 业务视角

文本分析项目里，时间的大头不花在建模上，而花在**打扫**上。
客户留下的评论里混着表情符号、重复字符 ("好好好好好")、URL、全角字符
("ＧＯＯＤ")、简繁混写 ("满意" / "滿意")、还有中英混排的大小写 ("GOOD" / "good")。
照原样去统计，"满意"和"滿意"就成了两个不同的词，整张统计表全盘走偏。

预处理不炫技，但效果实打实。同一个模型，预处理质量不同，分类准确率上下浮动
好几个百分点是常事；更重要的是，它把**统计结果做到能写进报告的程度**。
毕竟谁也没法交一份"本月提及最多的关键词: 哈哈哈哈"的周报。

## 2. 打个比方

预处理就是**下锅之前的备菜**。从菜市场买回来的蔬菜 (原始文本) 带着泥
(特殊符号)，个头参差不齐 (全角/半角、简繁异形)，还挂着不吃的根和老叶
(停用词)。不管最后做哪道菜 (做什么分析)，备菜的顺序几乎总是一样:
先洗 → 再修 → 统一大小 → 扔掉不能用的部分。

关键在于**备菜方式随菜而变**。熬汤的小鱼要去头，做小炒的就整条下锅。
同理，做情感分析时 "！！！" 可能是宝贵的信号 (情绪强度)，一刀切删掉就亏了；
做关键词统计时删掉才对。世上没有"标准预处理"，只有"贴合目的的预处理"。

## 3. 核心概念

### 3-1. 规范化 (normalization) — 让相同的东西长得相同

把只是写法不同、意思相同的东西并成一个。

| 处理 | 例子 |
|---|---|
| 全角转半角 (NFKC) | "ＧＯＯＤ！"、"１２３" → "GOOD!"、"123" |
| 英文小写化 | "GOOD"、"Good" → "good" |
| 简繁异形字统一 | "滿意"、"價格" → "满意"、"价格" |
| 空白整理 | "物流　　很快 " → "物流 很快" (全角空格、连续空格、首尾空格) |
| 重复字符压缩 | "好好好好好"、"哈哈哈哈" → "好好"、"哈哈" |
| 特殊符号处理 | "★★★好评" → "好评" (但保留与否要看目的) |

英文靠小写化 (lowercasing) 解决的问题，中文这边主要是**全角/半角**和
**简繁异形字**，再加上情绪性的重复字符。

### 3-2. 停用词 (stopword) 移除 — 扔掉没有信号的词

"的"、"了"、"很"、"非常"、"这个" 这类字词几乎每句都出现，
所以完全没有区分文档的能力。它们叫停用词，统计和检索时要排除掉。

两点提醒:
- 停用词表**因领域而异**。购物评论里"商品"实际上就是停用词，一般新闻里却不是。
- 做情感分析时，把"不"、"没"这类否定词当停用词删掉，
  "不满意"就变成了"满意"。删什么，永远要和目的一起决定。

### 3-3. 中文特别要小心的地方 — 没有空格

照搬英文预处理教程，到中文这儿必然翻车。因为英文教程的每一步都默认
"`text.split()` 就能拿到词"，而中文一整句是连续的汉字流，
`split()` 只会还你一整块。

于是有两个直接后果:

1. **停用词只能靠字符串替换来删**，而这会伤到词的内部。
   这一关的代码删掉"的"以后，"评分是我的真实感受"变成了
   "评分是我实感受" — "真实"被咬掉一个字。这就是没有词边界的代价。
2. **词频统计没法直接做**。本关退一步，用"相邻两个汉字" (二元组, bigram)
   粗略代替词来统计。这招能用，但"是我"、"我实"这种跨词边界的垃圾组合
   一定会混进来 (第 4 节输出里看得很清楚)。

真正的解法是分词 (word segmentation)，level03 正面处理。
作为对照，韩语的坑长在另一头 — 韩语句子有空格，但词尾粘着助词
("배송이/배송은/배송을" 都是'物流')，所以韩语预处理的重头戏是把助词剥下来。
中文是**没有边界**，韩语是**边界处粘着东西**，方向正好相反。

### 3-4. 用流水线的方式思考

预处理是一串**有固定顺序**的步骤。顺序一变，结果就变。
比如先把特殊符号删掉，URL 删除规则 ("以 http 开头…") 就失效了；
先把标点换成空格，靠标点定位金额区间的规则也就没了依据。
所以实务中把每一步做成小函数，按顺序串成一条流水线，任何文本都走同一条路。
这样还能随时把"走到第 3 步的中间结果"掏出来看，调试非常轻松。

## 4. 动手练习 — main.py

运行:

```bash
python3 main.py
```

- **[1] 制造脏评论**: 给 hjh_data 的评论故意掺上表情符号、URL、重复字符、
  全角字母、繁体异形字、杂乱空白，造出 8 条"很现实"的脏评论 (seed 固定)。
- **[2] 逐步清洗**: 挑 1 条样本，展示它通过流水线 6 步
  (半角化·小写·去URL → 异形字统一 → 特殊符号清理 → 重复字符压缩 →
  标点转空格 → 停用词删除) 时每一步的 before/after，文本一点点变干净的过程一览无余。
- **[3] 全部一次清洗**: 8 条全部过流水线，原文与结果并排对比。
- **[4] 前后词频对比**: 同一批评论，取二字组合频次 top8 做预处理前后对照，
  再单独打印异形字被拆成两份统计的现场。

实测输出 (节选):

```
第1步 半角化·小写·去URL    -> '★★★ 店里環境非常舒适  评分是我的真实感受。 哈哈哈哈哈good!'
第2步 异形字统一          -> '★★★ 店里环境非常舒适  评分是我的真实感受。 哈哈哈哈哈good!'
第3步 特殊符号清理         -> '    店里环境非常舒适  评分是我的真实感受。 哈哈哈哈哈good '
第4步 重复字符压缩         -> '  店里环境非常舒适  评分是我的真实感受。 哈哈good '
第5步 标点转空格          -> '店里环境非常舒适 评分是我的真实感受 哈哈good'
第6步 停用词删除          -> '店里环境舒适 评分是我实感受 哈哈good'
```

```
预处理前                  | 预处理后
----------------------------------------------
哈哈         16次           | 评分         4次
评分         4次           | 分是         4次
分是         4次           | 是我         4次
是我         4次           | 我实         4次
我的         4次           | 实感         4次

异形字被拆成两份统计的现场 (为看清差距，这里用 100 条样本):
  预处理前 满意=1 / 滿意=5  ->  预处理后 满意=6
  预处理前 包装=6 / 包裝=5  ->  预处理后 包装=11
```

预处理前噪声 "哈哈" 以 16 次霸占榜首；处理完之后它降到 4 次，
"满意"和"包装"也各自从被劈成两半 (1+5、6+5) 合并成了 6 次和 11 次。
同时请注意榜单里的 "分是"、"是我"、"我实" — 这些正是没有分词、
硬用二元组代替词的代价，level03 会把它们清掉。

代码的核心是 `PIPELINE = [(步骤名, 函数), ...]` 这个列表。每一步都是
字符串进、字符串出的纯函数，所以想换顺序、想抽掉某一步做实验，
只要改这个列表就行。

## 6. 常见误区

- **一律全删**: 条件反射式地删掉特殊符号和表情符号，情绪信号就一起没了。
  "删除 / 保留 / 替换"这三个选项，每次都要称一称。
- **从别的领域抄停用词表**: 把新闻用停用词表搬到评论上，
  里面塞满"记者"、"报道"这种用不上的词，真正该删的"商品"反而没有。
- **迷信字符串替换式的停用词删除**: 删"的"会把"真实"咬成"实"，
  删"了"会伤到"了解"。正确做法是先分词再按词删 (level03)。
- **忘记全角与简繁**: "ＡＳ申请"、"AS申请"、"as申请" 是三个不同的字符串，
  "满意"和"滿意"也是。NFKC + 异形字映射要在流水线最前面就做掉。
- **覆盖原始数据**: 用预处理结果覆盖原始列，规则一改就回不去了。
  原文永远单独留一份。
