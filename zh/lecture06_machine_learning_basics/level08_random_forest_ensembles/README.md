# Lecture 06 · Level 08 — 随机森林与集成学习

> 不押注一棵不稳定的树，而是养几百棵彼此略有差异的树来投票 —— 为什么这样更强? 用实验验证集体智慧的原理。

**难度** ⭐⭐⭐ / **先修** level07 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

在表格 (tabular) 数据的实战预测问题 —— 流失、逾期、需求、转化 —— 上，"先跑一把再说的强力基本功"就是随机森林 (random forest)。它对预处理不挑剔，超参数几乎不用调也有不错的性能，对过拟合相对抗打。这就是它在数据分析竞赛和真实企业现场都长期坐稳"第一次提交用模型"宝座的原因。

从业务视角看，这一关的另一个收获是拿到**稳定性**这条评价轴。用这个月数据建的模型和用下个月数据建的模型说的话完全不一样，性能再好组织也不会信。"性能有多好"之外再养成掂量"结果晃得有多厉害"的习惯，就从这里开始。

## 2. 用比喻来理解

**猜牛体重大赛**的故事很有名。集市上几百名观众各自猜一头牛的重量，个人错得离谱，但**所有猜测的平均值比专家还准**。因为每个人的失误方向各不相同，一平均就相互抵消。这就是集体智慧，也是集成 (ensemble) 的原理。

不过有个前提: **参赛者必须相互独立地思考**。全场都抄一个人的答案，平均下来那个人的误差原封不动。随机森林用两个机关防止树们长得太像。

1. **装袋 (bagging)**: 给每棵树发一份与原始数据同样大小、**有放回抽样**重抽的数据 (自助法/bootstrap)。每棵树都经历略有不同的"人生阅历"。
2. **特征随机挑选**: 每次分叉只把全部特征中的一部分给它当候选。没有这个机关，所有的树都会用最强的那个特征开第一问，长得越来越像。换成开会打个比方，就是"嗓门大的人禁止先发言"的规则。

这样养出的几百棵树，用投票 (分类) 或平均 (回归) 给出最终答案。

## 3. 核心概念

### 3-1. 为什么平均能降方差

一棵树的误差可拆成"系统性偏差 + 每次的晃动 (方差)"。level07 看到的树的不稳定性正是方差。把接近相互独立的 T 棵树取平均，晃动大约按 1/√T 缩小 —— 和掷硬币次数越多正面比例越贴近 50% 是同一条统计原理。偏差不会被平均消掉，所以森林采用"把深树 (低偏差·高方差) 大量取平均"的策略。个体树尽管过拟合，平均后过拟合被大幅缓解。

### 3-2. 随机森林的主要旋钮

- `n_estimators` (树的数量): 越多越稳。性能到某个点后收敛，100~500 是常规。
- `max_features` (每次分叉的特征候选数): 越小树彼此越不像 (多样性↑、个体实力↓)。
- `max_depth`、`min_samples_leaf`: 和单棵树一样的刹车。在森林里可以放松一些。

### 3-3. 特征重要性与 OOB

森林把各棵树的不纯度下降贡献取平均，得到特征重要性 (feature importance)。它比一棵树的重要性稳定得多，实战汇报里常用 (不过 level07 提的偏差警告依然有效 —— 更公正的置换重要性在 level11)。附赠一条: 每棵树可以拿自己有放回抽样时没抽到的数据 (OOB, out-of-bag) 自打验证分，不留验证集也能大致估计性能。

### 3-4. 失去的东西: 解释力、体量

一棵树的规则能念出声，300 棵树的投票念不了。模型体积和预测耗时也变大。**"读得懂的一棵树"和"强壮稳定的森林"之间的交易** —— 选哪个由用途 (汇报用 vs 运营用) 决定。两个都想要时的解释技术，是 level11 的主题。

## 6. 常见错误

- **过度相信"森林不会过拟合"**: 只是缓解，不是免疫。数据少或存在泄漏特征时照样上当。
- **不量稳定性、凭一次划分下结论**: 一次测量的差异 (例: AUC 0.821 vs 0.815) 可能只是划分的运气。要用重复测量的平均±标准差说话。
- **把特征重要性当因果、当绝对排名汇报**: 相关性高的特征之间会互相分走重要性 (稀释)。重要性低不等于"没有影响"。
- **在需要解释的场合只掏出森林**: 对管理层，一张深度 3 的树常常比森林成绩单更有说服力。按用途挑模型。
