# Lecture 06 · Level 11 — 梯度提升与模型解释

> 用反复研读错题本的提升法把性能推上去，再用置换重要性和单条预测解释，学会回答"为什么?"。

**难度** ⭐⭐⭐⭐⭐ / **先修** level07, level08 / **预计时间** 60分钟

## 1. 为什么要学 — 从业务视角出发

表格数据预测的实战最强者只挑一个的话，就是梯度提升 (gradient boosting)。数据分析竞赛的领奖台和企业的流失、逾期、需求预测系统，相当一部分是提升家族。sklearn 的 `HistGradientBoostingClassifier` 一个类就能用上这个领域的标准技术。

但模型越强，新问题越大。**"模型大人说这位客户有风险，为什么呢?"** 客服不能没有依据就打电话，审核员不能没有依据就拒批，监管机构会要求解释。所以这最后一关分两部分 —— 前半是用提升法拉性能，后半是重新打开这个黑箱的方法 (置换重要性、部分依赖、单条预测解释)。性能和解释能一起端上桌，ML 才能在组织里落地生根。

## 2. 用比喻来理解

**错题本学习法**就是提升的全部。随机森林 (level08) 是"300 个学生各自复习后投票"，提升则是**一个学生靠错题本一轮轮成长的串行过程**。

第 1 节课: 先做一遍习题集，成绩平平。第 2 节课: 把**做错的题抄成错题本**，专攻那部分。第 3 节课: 还错的题再抄一本错题本…… 如此重复几百次。每节课的学习 (一棵小树) 又浅又弱，但因为始终朝着"纠正此前失误"的方向层层堆叠，最终实力非常强。

不过错题本学习法的陷阱也照单全收。一旦开始把习题集的**错别字 (噪声) 也背下来**，就是过拟合。所以提升必须配"每节课只吸收一小部分"的学习率 (learning rate) 和早停这些刹车 —— level09 的哲学原样回归。

解释工具也先用比喻立住。**置换重要性 (permutation importance) 是"把某一科的答题卡打乱再看成绩"**: 把某个特征的值随机洗牌后喂给模型，成绩暴跌，说明模型重度依赖它；不跌，说明没它也行。

## 3. 核心概念

### 3-1. 提升的结构

预测 = 树1 + η·树2 + η·树3 + … (η=学习率)。每棵树都学着去命中"此前预测留下的误差" (回归视角的残差校正 —— 名字里的 gradient 指的就是这个误差方向)。与随机森林的对照是关键。

| | 随机森林 | 梯度提升 |
|---|---|---|
| 树之间的关系 | 并行·独立 (投票) | 串行·依赖 (纠错) |
| 单棵树 | 深而强 | 浅而弱 (深度 3~8) |
| 主要效果 | 降低方差(晃动) | 降低偏差(系统性误差) |
| 过拟合风险 | 偏低 | **不调参就偏高** |
| 主要旋钮 | 树的数量 | 学习率 × 树数 × 深度 |

`HistGradientBoosting` 是把连续值分箱进直方图快速处理的现代实现，内置早停 (`early_stopping`)，验证成绩不涨就自动收手。

### 3-2. 置换重要性 — 更公正的重要性

level07~08 的不纯度重要性是"训练中被用得多的程度"，有偏。置换重要性则是**拿测试数据审问训练完的模型**: 只把一个特征的列随机洗牌 (其余照旧)，量性能的下跌幅度。它不挑模型种类，量的是"对实际预测力的贡献"，用于汇报更诚实。注意: 相关性高的特征能互相顶替，可能双双偏低。

### 3-3. 部分依赖 — 单个特征的影响曲线

部分依赖 (partial dependence) 是"其他条件不动，只把一个特征的值扫一遍时，平均预测怎么变"的曲线。"使用天数从 0→30 时流失概率沿什么形状下降" —— 不同于用一个系数概括的逻辑回归，它能揭示提升模型学到的非线性关系 (例: 10 天以下骤增)。它依然是**模型学到的关联的形状**，不是因果。

### 3-4. 单条预测解释 — "这位客户为什么?"

在整体趋势 (重要性、部分依赖) 之外，经常需要某一位客户的判定依据。实务标准是贡献度分解 (SHAP 系) 工具，但原理今天就能亲手实现: **"把这位客户的某个特征换成平均水平，预测变多少"** —— 逐特征地量。变化幅度大的特征，就是这位客户被判定的主要依据。有了这个概念，专业工具的输出你也读得懂。

代码核心: `HistGradientBoostingClassifier(early_stopping=True)`、`permutation_importance(..., scoring="roc_auc")`、`partial_dependence(...)`，以及 [6] 的 `explain_one()` —— 12 行的换值解释器。

## 6. 常见错误

- **提升模型用默认设置跑完就撒手**: 它比随机森林对调参更敏感。至少学习率、早停、深度要用验证调一调。
- **性能好就省略解释**: 不被采纳的模型，AUC 等于 0。报告里要把性能表和解释 (重要性、部分依赖、案例说明) 成套端出。
- **置换重要性和不纯度重要性混着标**: 两者定义不同，排名也可能不同。写明用的是哪种重要性。
- **把部分依赖、贡献度擢升为因果**: 不是"让客户少来电就能降流失"，而是"模型把来电多的客户看得危险"。干预效果只能靠实验证明。
- **拿训练集做解释对象**: 置换重要性和性能汇报要以测试 (或验证) 数据为准，才没有乐观偏差 (level04)。
