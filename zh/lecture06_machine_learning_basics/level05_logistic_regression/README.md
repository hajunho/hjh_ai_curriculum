# Lecture 06 · Level 05 — 逻辑回归: 分类的起点

> 做一个不止回答"流失/不流失"，而是回答"流失概率 73%"的模型，并把它的系数翻译成业务语言。

**难度** ⭐⭐⭐ / **先修** level03, level04 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

实战分类问题的答案，往往**概率**比是/否有用得多。"这位客户会流失"不如"流失概率 73%"，原因在于: 有了概率才能排**优先级**。回访人力一天只够打 50 个电话，那就从风险概率最高的 50 人打起。有了概率才能算**期望损益**: "流失概率 30% × 客户终身价值 40 万韩元 = 期望损失 12 万韩元 > 优惠券成本 1 万韩元 → 发券是划算的买卖。"

逻辑回归 (logistic regression) 是输出概率的分类模型的标准款，至今仍是金融风控评分等"解释责任"沉重的场合的首选模型。因为它的每一个系数都能被解读。

## 2. 用比喻来理解

想象一位**用风险评分表工作的保险核保员**。核保员逐项打分: 使用天数少就 +风险分，客服来电多就 +风险分，设了自动扣款就 −风险分…… 把各项分数加总得到总分。到这里为止，和线性回归的"加权求和"一模一样。

问题是总分可能是 −5 分也可能是 +12 分，而我们要的答案是 0~100% 的概率。所以再让总分过一个**换算漏斗**，把分数变成概率。这个漏斗就是 Sigmoid (S 形) 函数。总分很低就压到 0% 附近，0 分正好 50%，很高就压到 100% 附近。也就是说，**逻辑回归 = 线性评分表 + 概率漏斗**。理解了 level03，新东西只有一个漏斗。

## 3. 核心概念

### 3-1. Sigmoid: 分数 → 概率

```
z = a₁x₁ + a₂x₂ + … + b        (线性分数, 和 level03 同一个形状)
p = 1 / (1 + e^(−z))            (Sigmoid: 把 z 压进 0~1)
```

Sigmoid 是一条 S 形曲线。z=0 时 p=0.5，z 到 ±4 左右时 p 已经贴到 0.98/0.02。学习就是寻找让"训练数据中正确答案的概率最大"的系数 a (最大似然法)；和线性回归不同，它没有闭式公式，要靠迭代优化 —— sklearn 会替你搞定。

### 3-2. 系数解读: 优势比

系数 aᵢ 为 + 表示该特征越大流失概率越高，为 − 则越低。要解读到大小，需要几率 (odds) 的概念。几率 = p/(1−p)，即"流失对留存的赔率"。**特征 xᵢ 每增加 1 个单位，几率就变成原来的 e^(aᵢ) 倍。** 例: 来电次数的系数是 0.5，则 e^0.5 ≈ 1.65，即"每多来电 1 次，流失几率变 1.65 倍"。报告里按惯例写这个倍数 (优势比, odds ratio)。

注意: 各特征单位不一 (月 vs 韩元) 时不能直接比较系数大小。像今天实战那样先标准化 (均值 0、标准差 1)，系数就成了"该特征移动 1 个标准差"的效应，互相之间才可比。

### 3-3. 阈值: 概率 → 决策

模型给概率，决策由人用阈值 (threshold) 来下。默认的 0.5 只是个毫无依据的惯例。调低阈值 (例: 0.3)，被判为风险的客户变多，**漏掉的流失者变少但白跑的回访变多**；调高则相反。阈值不是模型问题，而是**成本与收益的业务决策** —— 应该由知道一次回访的成本和失去一位客户的代价的人来定。

### 3-4. 明明叫"回归"为什么是分类

名字的由来是"对对数几率 (log-odds) 做线性回归"。容易混淆的考试常客: 逻辑回归是**分类模型**。

## 6. 常见错误

- **扔掉概率只汇报 0/1**: 等于丢掉逻辑回归最大的优点。优先级和期望损益都来自概率。
- **不标准化就比较系数大小**: "月费的系数最小所以不重要" —— 可能只是因为它的单位是韩元 (数万量级) 才显得小。
- **把系数当因果解读**: "让客户设自动扣款就能降流失"是因果主张。也可能是愿意设自动扣款的客户本来忠诚度就高 (level03 的相关≠因果再登场)。
- **把阈值 0.5 奉为神圣**: 0.5 只是默认值，按成本结构调整才是正常操作。
- **只用准确率一项汇报性能**: 流失率 15% 的数据上准确率会造成错觉。这正是下一关的主题。
