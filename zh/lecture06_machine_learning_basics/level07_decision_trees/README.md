# Lecture 06 · Level 07 — 决策树

> 做一个像玩"二十个问题"那样层层提问、开枝散叶的模型，并把学到的树打印成人能读懂的规则语句来解读。

**难度** ⭐⭐⭐ / **先修** level05, level06 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

逻辑回归很出色，但作为"评分表"模型有两个遗憾。其一，它只能抓直线式的关系 —— 对"使用天数不足 10 天且同时是新客户时风险才骤增"这类条件组合的模式很弱。其二，要经过系数、优势比这道翻译工序才能解释。

决策树 (decision tree) 是魅力恰好相反的模型。学习的结果本身就是**"如果~就→ 否则→"的规则集**，可以原样拿给业务人员和管理层看。面对"为什么这位客户被判为高风险?"，你可以回答"因为使用天数不超过 9 天、没设自动扣款、入网不满 8 个月"。在被要求可解释性的受监管行业 (金融、医疗)，以及想把模型的发现反向输入为业务规则时，决策树至今仍是第一候选。而且它还是接下来两关 (随机森林、提升) 的零件。

## 2. 用比喻来理解

想想**"二十个问题"游戏**。高手不会上来就猜"是大象吗?"，而是先问"是生物吗?" → "是动物吗?" → "四条腿吗?" —— **用一个问题就能把候选劈掉最大一块的问题**先问。

决策树的学习正是这个策略。1,500 名流失/留存混杂的客户挤在一个房间里。树把所有可能的问题 ("使用天数 ≤ 9.5 吗?"、"入网月数 ≤ 3.5 吗?"……) 全试一遍，选出**分开后两个房间纯度提升最大的问题**，然后在每个房间里重复同样的事。劈几刀之后，就出现了"这间几乎全是流失客户"、"这间几乎全是留存客户"的房间；新客户来了，顺着问题走到底，用所到房间的多数票做预测。

要小心的地方也和二十个问题一样。如果允许无限提问，它能问出"请问您是王志明先生吗?"这样的问题，造出 1,500 个单人房间 —— 训练数据 100% 全对，对新客户却毫无用处的死记硬背 (level04 的过拟合)。所以要限制提问次数 (深度)。

## 3. 核心概念

### 3-1. 不纯度 — 给"房间有多混杂"打分

好问题 = 能把房间的混杂程度 (不纯度, impurity) 降得最多的问题。代表性度量是基尼不纯度 (Gini impurity)。

```
Gini = 1 − (流失比例² + 留存比例²)
```

房间里全是一种人就是 0 (纯净)，一半一半就是 0.5 (最糟)。树对每个候选问题计算"提问后两个房间的 (按人数加权) 平均不纯度"，采纳降幅最大的问题。这不过是 level00 的阈值搜索被递归地重复 —— 在这里学习也不是魔法，是搜索。

### 3-2. 深度与过拟合

- **深度 1~2**: 2~4 个房间。只抓大局，但绝不过拟合。适合"挖掘业务规则候选"。
- **深度 3~5**: 实战解读用的甜点区。也是人还能读得动的最后尺寸。
- **深度无限制**: 训练准确率 ~100%，测试准确率反而下降。level04 实验 A 里已经目睹过。

深度之外还有 `min_samples_leaf` (房间的最少人数 — 禁止单人房) 之类的刹车。

### 3-3. 树的优缺点

**优点**: 规则一目了然 / 不需要标准化、缩放 (阈值比较与单位无关) / 能抓非线性与条件组合模式 / 数值与类别混合也不怵。
**缺点**: **不稳定** —— 数据稍微一变，第一问就可能换掉，整棵树面目全非 / 阶梯式预测，对平滑关系效率低 / 单打独斗的性能通常与逻辑回归相当或略好。用"多棵树投票"解决这个不稳定问题的，就是下一关的随机森林。

### 3-4. 规则反向输入这种用法

树里发现的头部分支 ("使用天数 ≤ 9.5 且未设自动扣款 → 流失率 45%") 不用部署模型也能直接当 CRM 规则用。这就是为什么不上线模型的组织，光做树分析也能产出价值。

## 4. 实战 — main.py

运行:

```bash
python3 main.py
```

用 churn_table 建一棵流失预测树并解读它。

- **[1]** 数据准备与划分 (代码里能看出不需要标准化这一点)。
- **[2]** 手算基尼不纯度: 整个房间的不纯度 vs 问过"使用天数 ≤ 9.5"之后的平均不纯度 → 降幅就是问题的价值。
- **[3]** 训练一棵深度 3 的树，用 `export_text` 打印规则全文，再汇总流失率最高的前 3 个叶子 (leaf) 房间的人数和流失率。因为流失者只占 15%，我们用 `class_weight="balanced"` 加重少数类的分量，让流失侧的规则在树里显形 —— 请把打印出的规则从上往下念出声，追一追通往高危房间的路径。
- **[4]** 把深度换成 1、3、5、10、无限制，输出训练/测试准确率表 —— 再次确认过拟合的岔路口。
- **[5]** 输出特征重要性 (feature importance): 每个特征对不纯度下降的贡献比例。

代码核心: `DecisionTreeClassifier(max_depth=3)` 和 `export_text(tree, feature_names=...)`。把打印出的规则树从上往下念出声 —— 模型发现的业务规则直接就是句子。另外 [2] 的 `gini()` 函数 8 行，就是这一切数学的全部。

## 5. 动手试试

1. **(简单)** 把 [3] 的 `max_depth` 减到 2。规则剩几条? 测试成绩损失多少? 如果是给管理层汇报，深度 2 和 3 你选哪个?
2. **(普通)** 设 `min_samples_leaf=50`、深度不限制训练一次。没有深度限制也能压住过拟合吗? 用自己的话说说两种刹车的区别。
3. **(挑战)** 把训练数据的 seed 从 7 改成 8，用新数据重新训练深度 3 的树，比较规则变了多少。这就是 3-3 说的"树的不稳定性"。记住这个观察，level08 会好懂得多。

## 6. 常见错误

- **被深树的训练成绩感动**: 深度无限制树的训练准确率 100% 不是实力，是死记硬背 (level04)。
- **把树的规则当永恒真理**: 树是不稳定的。数据一更新规则就可能变，反向输入的规则要设有效期。
- **把不纯度重要性解读成因果**: 特征重要性是"模型用得多的程度"，不是"原因"排行。取值种类多的特征还会被高估 (更公正的替代是 level11 的置换重要性)。
- **在树面前纠结缩放、独热编码浪费时间**: 阈值比较模型不需要标准化。记住: 不同模型的预处理要求不同。
