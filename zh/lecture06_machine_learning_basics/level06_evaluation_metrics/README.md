# Lecture 06 · Level 06 — 评估指标: 准确率的陷阱

> 亲手造一个"准确率 98.5%"却一笔欺诈都抓不到的模型，然后学会用混淆矩阵、精确率、召回率、F1、ROC-AUC 正确地读懂模型。

**难度** ⭐⭐⭐ / **先修** level05 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

这一关是不被 ML 报告忽悠的最低限度的读写能力。"准确率 98.5% 的异常交易检测模型"听着很气派，但在欺诈比例 1.5% 的数据上，**硬说"全都正常"的空壳模型也有 98.5% 的准确率**。现实中确实发生过数百万级的项目就建立在这种错觉上被批准的事。

懂评估指标的人问法不一样: "召回率呢? 精确率呢? 在那个阈值下每天误报几笔?" 能不能提出这些问题，区分了只会消费 ML 成果的人和能够验证它的人。而且指标选择不是技术问题，是**业务盈亏问题** —— 应该由知道漏掉 1 笔欺诈的代价和 1 次误报的代价的人来选指标。

## 2. 用比喻来理解

想想**机场安检口**。1 万名旅客里携带危险品的只有几个人。安检口只要喊"全员通过"，准确率就在 99.9% 以上 —— 但那个安检口就没有存在的意义了。安检口的本事要用两个问题来量。

1. **携带危险品的人里抓住了百分之几?** —— 这是召回率 (recall)。漏掉就是大事故。
2. **响过警报的人里百分之几是真的?** —— 这是精确率 (precision)。误报频繁，队伍越排越长，警报本身也没人信了。

这两个指标是跷跷板关系。把安检灵敏度开到最大 (皮带手表全报警)，召回率 100% 但精确率见底；调低灵敏度则相反。坐在跷跷板哪一头，不由机器决定，而由**知道漏检成本和误报成本的运营者**决定。另外还有一个指标，衡量"不管灵敏度定在哪，这台安检机本身的分辨力有多好" —— 那就是 ROC-AUC。

## 3. 核心概念

### 3-1. 混淆矩阵 (confusion matrix) — 一切指标的源头

预测与实际的组合只有 4 格。

| | 预测: 欺诈 | 预测: 正常 |
|---|---|---|
| **实际: 欺诈** | TP (抓对了) | FN (漏掉 — 发生欺诈损失) |
| **实际: 正常** | FP (误报 — 客户不便、排查成本) | TN (安静放行) |

所有指标都从这 4 格来。

- **准确率 (accuracy)** = (TP+TN) / 全部 — 不平衡数据上 TN 一家独大，造成错觉
- **精确率 (precision)** = TP / (TP+FP) — "警报中真货的比例"
- **召回率 (recall)** = TP / (TP+FN) — "真货中被抓住的比例"
- **F1** = 精确率与召回率的调和平均 — 需要单个数字时的折中。因为是调和平均，两者只要有一个接近 0，F1 就会崩掉 (设计上就不让你靠平均蒙混过关)。

### 3-2. 不平衡数据上准确率为什么失灵

准确率只要"多数类猜得好"就能升高。欺诈占 1.5% 的话，全预测正常 = 准确率 98.5%。此时召回率 0%，精确率无法定义 (警报 0 笔)。**在不平衡数据上，准确率不是写在第一行的指标，而是写在脚注里的指标。**

### 3-3. ROC-AUC — 与阈值无关的分辨力

level05 讲过: 模型给概率，阈值产生决策。把阈值从 0 扫到 1，(误报率, 召回率) 的点会画出一条曲线，这就是 ROC 曲线，曲线下面积是 AUC。它有一个非常好的直觉解释: **"随机抽 1 笔欺诈和 1 笔正常，模型给欺诈那笔更高概率的概率"**。0.5 等于掷硬币，1.0 是完美。它用于在定阈值之前比较"模型本身的档次"。不过 AUC 高不代表运营阈值下的精确率也高，所以最终报告要附上运营点位的混淆矩阵。

### 3-4. 指标要从行动倒推

- 排查人力一天只能处理 100 笔 → "前 100 笔的精确率"才是实质指标
- 漏检成本 ≫ 误报成本 (癌症筛查、欺诈) → 召回率优先，精确率只设下限
- 误报成本 ≫ 漏检成本 (误拦 VIP) → 精确率优先

## 6. 常见错误

- **在不平衡数据上用准确率汇报**: 这正是本关存在的理由。务必把基线 ("全预测多数类"的模型) 一起汇报。
- **只看 F1 不看精确率/召回率**: F1 0.6 是"精确率 0.9+召回率 0.45"还是"两个都 0.6"，业务含义完全不同。
- **AUC 高就觉得完事了**: AUC 量的是档次，不是运营成绩单。看到运营阈值下的混淆矩阵，报告才够得上拍板。
- **划分时没保持不平衡比例**: 不加 `stratify` 切分，测试集里欺诈只有寥寥几笔，指标会大幅波动。
- **不先定指标就开始建模**: level02 说明书的第 4 项就是它。指标是事前契约，不是事后挑选。
