# Lecture 06 · Level 00 — 机器学习是什么: 规则 vs 学习

> 让"人把规则一条条写死"和"机器自己从数据中找规则"这两种方式，在同一个问题上正面较量一次。

**难度** ⭐ / **先修** 无 / **预计时间** 25分钟

## 1. 为什么要学 — 从业务视角出发

在"咱们是不是也该上 AI 了?"这样的会议上，最先需要的不是技术，而是分辨能力。有些问题用 Excel 公式或几行 IF 语句就够了，有些问题不用机器学习 (Machine Learning) 根本解不开。分不清这两类，就会为一个 IF 语句能搞定的事立项花掉几十万，或者反过来，用几百条规则硬堵一个本该学习解决的问题，最后陷入维护地狱。

学完这一关，面对"走规则路线还是学习路线?"这个问题，你会有一套自己能回答的判断标准。而这套标准，是后面 11 关全部内容的出发点。

## 2. 用比喻来理解

想象一下**做垃圾邮件过滤器的两种方法**。

方法 A — 规则硬编码: 相当于给新员工发一本工作手册。"标题里有'贷款'就是垃圾邮件"、"发件人不在通讯录且链接超过 3 个就是垃圾邮件"…… 起初很顺利。可垃圾邮件发送者把'贷款'改成'贷◆款'呢? 又得加一条规则。等规则攒到 500 条左右，它们开始互相打架，没有人能看懂全貌了。

方法 B — 学习: 不给新员工手册，而是把**前辈们已经标注好垃圾/正常的 10 万封邮件**摊给他看。"自己看，找感觉。"没有人写规则，但只要数据够多，新员工连'贷◆款'都能自己识别出来。出现新招数，就用新数据再训练一遍。

机器学习就是方法 B。传统编程是 **"规则 + 数据 → 答案"**，机器学习是 **"数据 + 答案 → 规则"**。箭头的方向反了 — 这是整门课里最重要的一句话。

## 3. 核心概念

### 3-1. 传统编程 vs 机器学习

| | 传统编程 | 机器学习 |
|---|---|---|
| 人提供什么 | 规则(代码) + 输入 | 输入 + 正确答案的样例 |
| 计算机产出什么 | 答案 | 规则(模型) |
| 规则变了怎么办 | 改代码 | 用新数据重新训练 |
| 适合的问题 | 规则明确且数量少 (算税、算工资) | 规则模糊且多到写不完 (识图、流失预测) |

### 3-2. "学习"的真面目 — 寻找好数值的搜索

"学习" (learning) 这个词听起来很神秘，实体却出人意料地朴素: **"把某个数字 (参数) 换来换去地试，找出最能命中正确答案的那个值"**。今天的实战用的是最简单的形式: 先定一个框架 —— "交易金额大于等于 T 韩元就判为欺诈"，然后把候选 T 全部试一遍，选出与数据最吻合的 T。不是由人拍脑袋定 T=50 万韩元，而是让数据来定 T —— 这就是学习的种子。后面要学的线性回归、神经网络，也不过是"数字有几百万个、搜索方法更聪明"而已，本质相同。

### 3-3. 规则路线赢的情况也很多

机器学习并不总是更优。

- **规则由法律或政策明文规定时**: 增值税按 10% 计算这种事绝不能用机器学习。已经有 100% 准确的规则了。
- **数据几乎没有时**: 20 条正确答案的样例学不出东西。这时专家写的规则更好。
- **出错时必须 100% 说清原因时**: 规则容易追溯，学习出来的模型则需要额外的解释工作 (level11)。

实战的正统打法是: "先用规则起步，从规则扛不住的地方开始换成学习"。

### 3-4. 术语整理

- **特征 (feature)**: 作为判断材料的输入列。例: 交易金额、交易时刻
- **标签 (label)**: 要预测的答案列。例: 是否欺诈 (0/1)
- **模型 (model)**: 学习得到的"规则集合体"。今天我们做一个只有一个阈值的超迷你模型。

## 4. 实战 — main.py

运行:

```bash
python3 main.py
```

这个程序拿一份银行卡异常交易数据 (合成，5,000 笔，欺诈比例约 1.4%)，用三种方式解同一个分类问题。它和垃圾邮件过滤器的结构一模一样 —— 从大量正常里挑出少数坏的。

- **[1]** 载入数据并查看结构。欺诈太稀少，单纯的准确率会造成错觉，所以成绩用"欺诈命中率与正常命中率的平均值 (均衡分)"来打。
- **[2] 手工规则**: 给"50 万韩元以上 + 凌晨时段就是欺诈"这条会议室里常见的、凭感觉定的规则打分。抓到的全是真欺诈，但漏掉了 70% 的欺诈。
- **[3] 学习 (阈值搜索)**: 挑一个特征，把所有阈值试一遍，用数据选出的最优阈值来预测。一定看看输出里选中了哪个特征、哪个值。
- **[4] 学习 (两个特征组合)**: 保持和人工规则完全相同的形状 ("金额 ≥ T 且是凌晨")，只把数字 T 交给数据来定。看看人拍的 50 万韩元和数据给出的答案差多远。
- **[5]** 把三种方式列表对比，并总结"箭头反了"这个核心。

代码的核心是 `learn_threshold()` 函数: 用 for 循环把候选阈值全部跑一遍、逐个打分的 10 行小函数 —— 这就是你亲手实现的第一个学习算法。我们故意没有用 sklearn 之类的库，就是为了让你亲眼看到: 学习不是魔法，是搜索。

输出里值得注意的点: 人工规则偏向"只抓十拿九稳的、大部分都放过",而学习找到了漏抓与误报之间更平衡的数字。人只定规则的"形状"，"数字"由数据来定 —— 这种分工就是机器学习的起点。

## 5. 动手试试

1. **(简单)** 把 `[2]` 手工规则里的金额标准从 50 万韩元改成 10 万韩元再运行。成绩怎么变了? 感受一下"凭人的感觉挑数字"为什么让人不安。(提示: 只需改 `hand_rule` 函数里的一个数字)
2. **(普通)** 往 `[3]` 的搜索特征列表里加上 `tx_count_1h` (最近 1 小时刷卡次数)。你会看到惊人的结果。这份合成数据里藏着一个近乎完美的特征 —— 换成真实数据，看到这种特征的那一刻，你要先怀疑"是不是泄漏 (leakage)?" (level02 会讲)。
3. **(挑战)** 现在的 `learn_threshold()` 只搜索"大于等于 (≥) 就是欺诈"这一个方向。把它改成同时搜索"小于 (<) 就是欺诈"的方向。对 `hour` (时刻) 这种"值越小越危险"的特征会有效果。(提示: 用 True/False 的方向标志跑两轮)

## 6. 常见错误

- **"AI = 机器学习 = 万能"的错觉**: 对规则明确的问题用学习，等于放着计算器不用去掷骰子。
- **把学习神秘化**: 不是"模型自己会思考"，而是"搜索数字去拟合数据"。一旦神秘化，你就不会想到去验证结果。
- **用训练过的数据打分然后满意收工**: 今天我们是故意这么做的。这为什么危险，正是 level04 的主题。此刻只需记住: 今天的成绩单是"被乐观夸大的数字"。
- **没有标注数据就想先开始学习**: 方法 B 的前提是"前辈们分好类的 10 万封邮件"。数据准备占项目的一半以上。
