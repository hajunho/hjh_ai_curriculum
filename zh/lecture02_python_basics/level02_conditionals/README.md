# Lecture 02 · Level 02 — 条件语句: 让计算机做判断

> if/elif/else 就是把"如果是 A 就……，其他情况里如果是 B 就……，都不是就……"这样的公司审批规定搬进代码。
**难度** ⭐ / **先修** level01 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

公司里相当多的工作就是"按规定做判断"。出差费用 15 万韩元以下由组长审批，
超过就要部门负责人审批。库存跌到安全线以下就下订单。客户等级是 VIP 就再打个折。
这类判断让人来做，一天几百笔就会累，而且每个经办人的标准还会飘。

学会条件语句 (conditional)，就能把规定手册搬进代码，**把判断本身自动化**。
只要一次写准确，无论 1 笔还是 10 万笔，都按同一个标准立刻判完。
这一关的实战正是一个"出差费用自动审批判定器"。如果你用过 Excel 的 `IF` 函数，
那你已经懂一半了，而在 Python 里可以写得好读得多。

## 2. 用比喻来理解

**审批规定比喻。** 假设公司的费用规定是这么写的。

> 1. 金额在 5 万韩元以下: 自动批准
> 2. 其他情况下，金额在 15 万韩元以下且有发票: 组长审批
> 3. 其他情况下，金额在 50 万韩元以下: 部门负责人审批
> 4. 以上都不符合: 驳回并要求说明

这份文件的结构就是条件语句本身。"如果 (if)" — "其他情况下如果 (elif)" —
"都不是 (else)"。还有一条重要规则: 就像读审批规定时从上往下读，
**在第一条命中的条款处停下**一样，Python 也是从上往下检查，
只执行第一个为真 (True) 的那一个分支，然后就跳出去。一笔 7 万韩元的费用，
一旦命中第 2 条，第 3 条、第 4 条就根本不会去读。

## 3. 核心概念

### 3.1 if / elif / else 的基本骨架

```python
if amount <= 50000:
    result = "自动批准"
elif amount <= 150000 and has_receipt:
    result = "组长审批"
elif amount <= 500000:
    result = "部门负责人审批"
else:
    result = "驳回"
```

- 条件后面要加冒号 (`:`)，要执行的行用**缩进 (indentation)** 4 个空格写在里层。
  Python 靠缩进来区分"这个条件管到哪儿为止"。语法靠的是缩进而不是括号，
  这是 Python 的一大特点。
- `elif` 想接多少条都行，`else` 只能有一个放在最后，也可以省略。
- 从上往下检查，**只执行第一个为真的分支**。所以条件的顺序
  就等于规定的优先级。

### 3.2 比较运算符 — 制造真/假的工具

| 运算符 | 含义 | 例子 | 结果 |
|---|---|---|---|
| `==` | 相等 | `grade == "VIP"` | True/False |
| `!=` | 不相等 | `status != "已取消"` | True/False |
| `<` `<=` `>` `>=` | 比大小 | `amount <= 150000` | True/False |

比较式的结果永远是布尔值 (bool)，也就是 `True` 或 `False`。
**千万不要混淆 `=` (赋值) 和 `==` (比较)。** 在条件的位置上写 `=` 会报语法错误。

### 3.3 逻辑运算符 — 组合条件

规定通常是好几个条件的组合。

- `and` : 两个都为真才为真。"15 万韩元以下**并且**有发票"
- `or` : 有一个为真就为真。"是高管**或者**是海外出差"
- `not` : 把真/假反过来。"**没有**发票的话" → `not has_receipt`

`and` 比 `or` 先算，所以混着用时请用括号把意图写明白。
`(a or b) and c` 和 `a or (b and c)` 是完全不同的两套规定。

### 3.4 Python 独有的便利写法

```python
if 50000 < amount <= 150000:     # 像数学那样连起来比较区间
if grade in ("VIP", "VVIP"):     # 是不是几个值当中的一个
if has_receipt:                  # 不需要写 == True
```

`in` 是问"这个值在不在这个列表里"的运算符，在判定等级、类别时特别好用。

### 3.5 嵌套与可读性

if 里面再套 if 的嵌套 (nesting) 也是可以的，但一旦套到三层以上，规定手册就变成迷宫了。
用 `and` 把条件合起来，或者先把例外情况筛掉 (early return，level05 会讲)，
写得平一点更好读。判断标准是"第一次看这份规定手册的新人能不能看懂"。

## 6. 常见错误

- **混淆 `=` 和 `==`** — `if grade = "VIP":` 会是 `SyntaxError`。判断永远用 `==`。
- **缩进不一致** — 同一个代码块里有的行 4 个空格、有的行 3 个空格，就会报
  `IndentationError`。相信编辑器的自动缩进，别把 Tab 和空格混着用。
- **条件顺序出错** — 把 `if amount <= 500000` 放到最上面，连 5 万韩元的也全都变成
  "部门负责人审批"了。窄 (严格) 的条件放上面，宽的条件放下面。
- **滥用 `else` 给规定留窟窿** — 最后的 `else` 意思是"以上所有条款都不符合"。
  在那儿放个"批准"，所有没预料到的情况就全被批准了。原则上 else 里要放安全的默认值
  (驳回、挂起、转人工确认)。
- **用 `==` 比较 float** — 因为 level01 讲的误差，`0.1 + 0.2 == 0.3` 是 False。
  请用区间比较，或者 `round` 之后再比。
