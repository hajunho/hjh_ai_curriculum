# Lecture 02 · Level 00 — 编程到底是什么

> 编程就是把一件事的流程写下来，写到计算机不会产生任何误解的程度; 而这个流程，用顺序、分支、循环三种形式就能全部表达出来。
**难度** ⭐ / **先修** 无 (学完 lecture01 level03 会更好) / **预计时间** 30分钟

## 1. 为什么要学 — 从业务视角出发

在公司里，我们每天都在制定和遵守各种"流程": 新员工入职清单、月末结算步骤、
客户投诉处理手册 — 全都是流程文件。编程 (programming) 就是把这样的流程文件，
改写成不是给人读、而是给计算机读并执行的形式。

只有一点不同。人看手册时，就算写得有点含糊，也会"自己补上"再理解;
计算机只做字面上写了的事。所以学编程能带来两种能力。
第一，能把重复性工作整块交给计算机。第二，你会养成毫无含糊地设计流程的思维，
连那些根本不写代码的业务文档也会跟着变清楚。
这一关我们先不背语法，而是抓住"程序到底是什么"这幅大图。

## 2. 用比喻来理解

**菜谱比喻。** 想一想煮泡面的步骤。"烧开 550 毫升水 → 下面饼和调料包 →
煮 4 分 30 秒。"从上到下依次执行。这就是**顺序 (sequence)**。

菜谱里也有岔路。"想吃辣就加一把小米辣，不想吃就不加。"
根据条件走不同的路，这就是**分支 (branch)**。

而"不停搅拌，直到面条煮软"这种把同一个动作做很多次的，就是**循环 (loop)**。

说来惊人，世界上所有的程序都是这三者的组合。工资计算系统也好，
手机游戏也好，聊天机器人也好，归根结底都是把顺序、分支、循环堆得非常多、非常精巧而已。
以后每遇到一个新语法，只要问自己"它是让这三样里的哪一样变轻松的工具?"，
你就不会迷路。

**业务手册比喻。** 想象一下在咖啡店打工第一天拿到的点单处理手册。
"接单 → 计算应付金额 → 是积分会员就累计积分 → 做饮品 →
一直震动叫号器，直到顾客来取。"把这份手册翻译成计算机的语言，
那就是程序。这一关实战里的 main.py 做的正是这件事。

## 3. 核心概念

### 3.1 程序 = 数据 + 流程

程序由两部分构成。作为加工对象的**数据 (data)** — 下单数量、单价、
顾客姓名 — 以及加工这些原料的**流程 (procedure)** — 计算、判断、输出等一系列步骤。
用 Excel 来打比方，单元格里的值是数据，公式和宏是流程。

### 3.2 顺序 — 从上到下

Python 代码在没有特殊指示时，会从第一行依次执行到最后一行。
顺序一变，结果也会变。就像"先打折再算增值税"和"先算增值税再打折"
算出来的金额是两个数一样。

### 3.3 分支 — 按条件走不同的路

"如果是这样就 A，否则就 B。"在 Python 里用 `if` 这个词来写。
详细语法留到 level02 学，今天只要抓住"这里是程序自己做判断的地方"这个概念就够了。

### 3.4 循环 — 同一件事做很多次

"对列表里的每一笔订单都做某件事。"在 Python 里用 `for` 这个词来写。
人重复 100 次就会累、会出错，计算机重复 100 万次品质也完全一样。
自动化的收益大部分就来自这里。

### 3.5 为什么对计算机必须写得精确

你跟新人说"你大概整理一下汇报给我"，总还是能拿到点东西的，
因为他会用经验和常识把空白填上。计算机没有这份常识。
只写"汇总销售额"，它不知道该用哪个文件、哪一列、按什么口径去加，
于是就停住了。所以编程有一半的工作是"把我脑子里的流程一步不漏、
毫不含糊地用话讲清楚"。写代码之前先用中文给流程编上号写一遍
(这个习惯叫写伪代码 (pseudocode))，那么即使你还不会语法，
程序的设计其实已经做完了。

### 3.6 编程语言与 Python

计算机能听懂的流程记法叫编程语言 (programming language)。
其中 Python 的语法最接近英文句子，非计算机专业的人学起来最省力，
而且它是数据分析和 AI 领域的标准语言，所以整套课程都用它。

## 4. 实战 — main.py

运行方法:

```bash
cd lecture02_python_basics/level00_what_is_programming
python3 main.py
```

main.py 是把咖啡店"美式咖啡点单处理"流程翻译成代码的演示。
输出分四段。数据里的金额沿用了韩元 (KRW) 计价。

- **[1] 顺序**: 展示接单 → 计算金额 → 打印小票是如何从上到下执行的。
- **[2] 分支**: 根据是不是积分会员，返积分的提示语会不一样。代码里 `if is_member:` 那一段就是岔路口。
- **[3] 循环**: 用一个 `for` 循环处理 3 笔订单。关键在于订单变成 300 笔，代码也一模一样。
- **[4] 小结**: 打印出今天的结论 — "所有程序都是顺序、分支、循环的组合"。

你还没学语法，所以别想着把代码全部看懂。
看到 `cup_price * quantity` 这种地方心里冒出"咦? 这我看得懂"就算成功了。
跟着注释 (以 # 开头的中文说明) 找一找哪几行是顺序、哪几行是分支、哪几行是循环就行。

## 5. 动手试试

1. **改改数值** — 打开 main.py，把 `cup_price = 4500` 换成别的值再运行一次。
   输出的金额有什么变化? (提示: 数据一变，同样的流程也会给出不同的结果。)
2. **体验分支** — 把 `is_member = True` 改成 `False` 再运行，看看输出里
   少了哪一行。(提示: `if` 下面缩进的那行不会被执行了。)
3. **把日常工作拆成流程** — 挑一件你每周都做的事 (比如写周报)，
   在纸上写出顺序、分支、循环分别出现在哪里。
   (提示: 一旦出现"直到……为止"、"只有……的情况下"这类说法，那儿就是。)

## 6. 常见错误

- **从背语法开始** — 语法只是工具。先用话把"我想自动化的是什么流程"理清楚，
  这个习惯重要得多。
- **指望计算机自己看着办** — 计算机只做字面上写了的事。
  哪怕你心里想"当然是含税的啊"，代码里没写它就不会算。
- **想一次就写出完美的程序** — 实际工作中的程序也是先做一小段流程、
  跑一下确认、再一点点加大做出来的。多按运行键。
- **把报错当成失败** — 报错信息是计算机向你提的问题。
  level07 会教你怎么读，现在只要不害怕它就够了。
