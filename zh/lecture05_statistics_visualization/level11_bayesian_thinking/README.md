# Lecture 05 · Level 11 — 贝叶斯思维与不确定性沟通

> 贝叶斯做的不是"标准答案"，而是"信念的账本"。每来一笔证据，余额就更新一次。
**难度** ⭐⭐⭐⭐⭐ / **先修** level10 / **预计时间** 70分钟

## 1. 为什么要学 — 业务视角

level09~10 的 p 值是一门别扭到需要专门训练的语言。把
"在没有差异的假设下，出现这么大差异的偶然概率是 3%" 原样说给管理层，
回来的问题只有一个：**"所以 B 方案更好的概率到底是多少？"**——
p 值答不了这个问题，而贝叶斯 (Bayesian) 方法正面作答：
"以当前数据为准，B 方案更优的概率是 92%。"

贝叶斯思维的骨架其实在 level06 就见过了 (疾病检测悖论：
先验概率 × 证据)。这一关把它扩展到连续问题——转化率估计与 A/B 比较——
最后以"如何向决策者讲述不确定的结果"收尾。这门沟通技术，
说不定比统计技术本身更重要。

## 2. 用类比来理解

贝叶斯更新是**相亲之后的印象更新**。见面之前我们也不是白纸——
介绍人的话、资料照片，构成**先验信念 (prior)**。第一次见面 (证据,
evidence) 感觉不错，好感上升，但还谈不上确信。见面次数越多 (数据积累)，
信念的分布越收越窄，到某个时刻，介绍人的话 (先验) 几乎失去影响力。
**后验信念 (posterior) = 先验信念 × 证据**——而且今天的后验信念，
就是明天的先验信念。

不确定性沟通是**天气预报的语言**。气象台不说"明天下雨/不下雨"，
而说"降水概率 70%"。这是好的汇报，不是因为它从不出错，而是因为
**它让听的人自己去权衡带伞的成本和淋湿的成本**。"B 方案更优的概率 92%，
万一劣势，预期损失是每月 300 万韩元"——这才是给决策者的汇报格式。

## 3. 核心概念

### 3.1 看待概率的两种视角

- **频率学派 (frequentist)**：概率 = 长期重复的比例。参数是固定的未知数，
  概率只附着在数据 (抽样) 上。→ 置信区间、p 值
- **贝叶斯学派**：概率 = 信念的程度。给参数本身赋予概率分布，
  每看一批数据就更新一次分布。→ 后验分布、更优概率

两者不是敌人，是用途不同的工具。提交监管、发论文时频率学派惯例强势；
连续的商业决策、早期监控则更适合贝叶斯的说法。

### 3.2 转化率的 Beta 分布更新

对转化率这种 0~1 之间的值的信念，用 Beta 分布 (Beta distribution) 表达。
Beta(α, β) 可以粗略读作"见过成功 α-1 次、失败 β-1 次时的信念"。
更新规则简单得惊人。

> 先验 Beta(α, β) + 观测 (转化 s, 未转化 f) → 后验 Beta(α+s, β+f)

- 一无所知的起点：Beta(1, 1) — 0~1 一律平等的平坦分布
- 观测到 100 名访客中转化 3 名 → Beta(4, 98)：峰在 3% 附近，还很宽
- 访问到 10,000 名后 → 峰窄得像针："现在相当有把握了"

分布的**宽度就是不确定性的大小**。不用点估计 ("转化率 3%")，
而用分布 ("在 2.1~4.2% 之间的某处，3% 附近最像") 来思考——
这是贝叶斯思维的核心习惯。

### 3.3 计算 "B 方案更优的概率"

有了 A、B 各自的后验分布，从两个分布里抽几万对随机数，
数出 **B 样本大于 A 样本的比例**就行。这就是蒙特卡洛 (Monte Carlo)
式的更优概率 P(B > A)。不用公式，level06 的"造出来数一数"在这里
照样管用。附赠：从同一批样本里还能免费得到"B 比 A 好几个百分点"
的分布 (预期改善幅度、损失风险)。

### 3.4 怎么向管理层讲不确定性

1. **用提问的语言回答**：不说 "p=0.03"，说 "B 方案更好的概率 92%"。
2. **用区间说话**：不说"转化率 3.4%"，说 "3.1~3.7% (最可信的值 3.4%)"。
3. **连着决策一起说**："92% 的把握 + 错了时每月损失 300 万韩元 +
   再等一周每组能多 5 千样本"——现在拍板还是再等，是管理层的事；
   分析师的事是把这三个数字给准。
4. **敢说不知道**：分布还很宽时，"现在下判断为时尚早，
   还需要 n 名样本" 是唯一诚实的汇报。

"真实值落在这个区间里的概率是 95%" 的区间 (对比 level08：
置信区间不允许这么说)。代价是必须把先验信念这个假设摆到明面上。

## 5. 亲手试试

1. **(简单)** 把 [1] 的先验从 Beta(1,1) 换成带着"业界平均 3% 左右"信息的
   Beta(3, 97)。初期 (100 名) 阶段的分布有什么不同？为什么到 10,000 名后
   差异几乎消失？
2. **(中等)** 在 [2] 里把 B 的转化数从 668 降到 640，看 P(B>A) 怎么变。
   遇到 60~70% 这种不上不下的概率时，按 3.4 的格式亲手写一段汇报。
3. **(挑战)** 实现"预期损失降到 0.02 个百分点以下就上线"的决策规则，
   模拟访客每累积 5,000 名评估一次规则。贝叶斯监控是怎么缓解
   peeking 问题的？(提示：概率的'解释'不同，所以每次看含义都还在，
   但决策规则依然要事先定好。)

## 6. 常见错误

- **藏起先验信念**：先验分布不是见不得人的假设，而是必须写明的输入。
  在报告里加一行"先验: 无信息 Beta(1,1)"。
- **把 P(B>A)=92% 误读成"8% 的概率是灾难"**：剩下 8% 的大部分是
  "B 稍微差一点点"。把更优概率和预期损失放在一起看，
  才能看清风险的大小。
- **只取点、不看分布**：只提取后验分布的平均值来用，
  贝叶斯就白做了。宽度 (可信区间) 才是核心信息。
- **样本明明够了还怪先验**：数据攒多了，合理的先验们会收敛到
  几乎相同的后验。先验之争吵得越久，多半说明数据不够。
- **把不确定性汇报当成不自信**：说"92%"的分析师，长期比说"确定没问题"
  的分析师更受信任。后者错一次，信用就清零。
