# Lecture 05 · Level 10 — A/B 测试的设计与解读

> A/B 测试是把相关变成因果的机器。但只有守规矩时它才运转。
**难度** ⭐⭐⭐⭐ / **先修** level09 / **预计时间** 65分钟

## 1. 为什么要学 — 业务视角

"把购买按钮从绿色换成橙色，转化率会涨吗？" 历史数据回答不了这个问题——
换按钮的同时促销活动八成也变了 (混杂变量, level05)。答案只有实验：
把访客**随机**对半分，一半看旧方案 (A)、一半看新方案 (B)，
比较转化率——这就是 A/B 测试。随机分配把季节、星期、客群倾向等
一切混杂变量公平地撒到两边，剩下的差异就只有按钮颜色的因果效应和偶然。
偶然再用 level09 的检验筛掉。

科技公司每年跑成千上万个 A/B 测试，在电商、金融、游戏行业它也早已是
标准流程。但比知道流程更重要的，是**知道怎么把它搞砸**。尤其是
"结果看着不错就提前收工" (peeking)，是人们怀着善意犯下的最常见舞弊。

## 2. 用类比来理解

A/B 测试的规矩和**抛硬币打赌**一样。说好"抛 100 次定胜负"，
就得抛满 100 次。可要是对方边抛边看比分，趁自己领先的瞬间大喊
"停！我赢了"呢？就算硬币公平，抛掷过程中某一方短暂领先的时刻
几乎必然出现。**看着结果挑收盘时点，偶然就摇身变成了实力。**
这就是 peeking (偷看) 的真面目。

样本量设计是**挑望远镜**。想看清远处的小招牌 (小效应)，
就需要大望远镜 (大样本)。肉眼看不见不等于招牌不存在；
样本不足而不显著，也不等于没有效应。实验之前算一算
"要看到这个大小的效应需要多少人"，这就是检验力分析。

## 3. 核心概念

### 3.1 设计流程 — 实验前要定的 4 件事

1. **指标**：拿什么定胜负 (转化率、客单价、复访率——主指标只能一个)
2. **最小关注效应 (MDE)**：差几个百分点才算有商业意义 (例: +0.5 个百分点)
3. **样本量**：想以 80% 的检验力抓住那个效应，每组需要多少人
4. **终止规则**：样本攒满后，**只检验一次**

把这四条在实验前写进文档钉死，说是 A/B 测试的全部也不为过。
剩下的照搬 level09 的检验。

### 3.2 转化率比较的检验

转化是"做了/没做"的二元数据。每组 n 人、转化率 p̂_A、p̂_B 时，
用 z 检验检验两个比例之差。原理与 t 检验相同 (差异 ÷ 标准误)，
实战中我们不用 scipy、亲手计算。标准误里含有 p̂(1-p̂)/n，
所以转化率越低、差异越小，需要的样本就暴涨。

### 3.3 检验力与样本量的手感

检验力 (power) 是"真有效应时能抓住它的概率"。惯例目标是 80%。
大致的手感：

| 基准转化率 | 想检测的差异 | 每组所需样本(大致) |
|---|---|---|
| 3% | +1.0 个百分点 | 约 5 千人 |
| 3% | +0.5 个百分点 | 约 1 万 9 千人 |
| 3% | +0.2 个百分点 | 约 11 万人 |

差异减半，样本约需 4 倍 (√n 的经济学, level07)。
"一天就能出结果吧？"——这张表就是回答。

### 3.4 peeking — 为什么不能偷看

每天盯着 p 值，等 p < 0.05 的瞬间就收工，会怎么样？
就算按显著性水平 5% 设计，实际的第一类错误率 (没有效应却结论"有")
会蹿到 20~30%。因为检验做得次数多了，总有一天碰巧迈过门槛
(多重比较问题的时间版)。p 值是以"在约定的时点只看一次"为前提造出的工具。

对策有三：(1) 攒满约定的样本前不看；(2) 非要中途确认，
就按次数把门槛收紧 (序贯检验设计)；(3) 贝叶斯监控 (level11)。
实务里最容易做到的是 (1)——仅仅在仪表盘上藏起 p 值，
组织的误报就会变少。

## 4. 实战 — main.py

```bash
python3 main.py
```

搭一个转化率 A/B 测试模拟器，跑三个实验。(图内文字为英文。)

- [1] **有效应的情形**：A=3.0%、B=3.6%，每组 2 万人。输出观测转化率、
  差异的 z 检验 p 值和判定。
- [2] **无效应的情形 (A/A 测试)**：A=B=3.0%。看看检验在"无差异"世界里
  的行为。
- [3] **第一类错误率验证**：把无效应的测试重复 2,000 次，
  确认 p < 0.05 出现的比例是否如设计般在 5% 附近。
- [4] **peeking 实验**：在同样 2,000 次无效应测试中，模拟"每攒 1,000 人
  看一次 p，只要有一次 p < 0.05 就宣布胜利、立即收工"的政策。
  数一数假阳性率翻了几倍。
- [5] `outputs/peeking.png`：几条无效应测试的 p 值轨迹。
  那些短暂跌破 0.05 线又弹回来的轨迹，就是"偷看就上钩的瞬间"。

[4] 的输出——"诚实检验 4.9% vs peeking 24.0%"——请记住这组数字。
当会上有人说"中期结果不错，提前结束吧"，就是掏出它的时候。

## 5. 亲手试试

1. **(简单)** 把 [1] 的每组样本从 2 万人减到 3 千人。同样 0.6 个百分点的
   效应还能显著地抓住吗？和 3.3 表的手感对得上吗？
2. **(中等)** 把 [4] 的确认周期从 1,000 人缩到 200 人 (偷看得更勤)，
   假阳性率怎么变？跑一遍验证。
3. **(挑战)** 做一个简易样本量计算器：输入基准转化率 p 和目标差异 d，
   用近似式 "每组 n ≈ 16 × p(1-p) / d²" 重现 3.3 的表。
   (提示：这个近似式是显著性水平 5%、检验力 80% 双侧检验的惯用估算。)

## 6. 常见错误

- **破坏随机分配**：上午访客给 A、下午给 B——这不是 A/B 测试，
  是上午/下午对比。分配必须按用户粒度用随机数。
- **看完结果再挑指标**：转化率没涨但停留时长涨了所以算成功——
  这是先射箭再画靶。主指标事先只定一个。
- **提前收工 (peeking)**：本关的主题。"看着不错就早点结束"
  是假阳性制造机。
- **滥切分群**：整体没效应，却翻遍 20 个分群找到"对 30 多岁女性显著"——
  总有一个是碰巧撞上的。分群分析只能用作下一次实验的假设。
- **统计显著 = 上线决定**：就算显著，效应大小抵不过运营成本就没有
  上线的理由。请把效应大小、置信区间和 p 值一起汇报。
