# Lecture 05 · Level 00 — 用数字概括现实意味着什么

> 统计是"概括"与"推断"的技术。概括很方便，但一定会丢掉些什么。
**难度** ⭐ / **先修** 完成 lecture03 / **预计时间** 30分钟

## 1. 为什么要学 — 业务视角

公司里流转的数字几乎全是概括。"本月平均客单价 18,400 韩元"、
"客户满意度 4.2 分"、"每家门店日均销售额 320 万韩元"。原始数据有几万行，
到了报告里却被压缩成一行。问题在于，这个压缩过程会丢失信息。同样是
"平均 4.2 分"，大部分人打 4 分的店，和 5 分与 1 分各占一半的店，
是完全不同的两种局面。后者可能此刻正有什么事在严重出错。

学统计 (statistics) 的理由有两个。第一，把数据**概括**后传达给别人；
第二，只看一部分数据 (样本) 就对整体做出**推断 (inference)**。
这门课的前半部分 (level00~04) 讲概括，后半部分 (level06~11) 讲推断。
本关卡是整个旅程的起点，让你亲身体会"概括丢掉了什么"。

## 2. 用类比来理解

概括就像**简历**。把一个人的十年浓缩成一张 A4 纸，就是简历。
招聘负责人靠简历可以快速比较 100 个候选人，但只看简历就拍板录用，
也常常栽跟头。因为纸上没写的东西——协作态度、危机应对——
实际上往往更重要。

平均数这个数字，就是数据的简历。它很方便，但如果不追问"平均数背后
是什么样的数据"，就会做出错误的录用，也就是错误的决策。所以擅长统计的人
的第一个习惯不是计算，而是**怀疑**："这个概括，到底多大程度上代表了原始数据？"

再打一个比方。地图是对现实的概括。地铁线路图会歪曲实际的距离和方向，
但用来换乘却是最好的地图。也就是说，**好的概括，是"按照目的"挑选了
该丢什么再去丢的概括**。只要你知道丢掉的是什么，概括就是强大的工具。

## 3. 核心概念

### 3.1 描述统计与推断统计

- **描述统计 (descriptive statistics)**：对手头的数据做概括和描绘。
  平均数、中位数、方差、直方图都属于这一类。
- **推断统计 (inferential statistics)**：通过样本去推测整体 (总体)。
  民意调查、A/B 测试、置信区间属于这一类。

Excel 的 AVERAGE 是描述统计；"凭这 500 人的问卷结果，能代表全体客户的
倾向吗？"则是推断统计的问题。

### 3.2 相同的平均数，不同的现实

这是本次实战的核心实验。我们造出 4 组平均数都恰好是 100 的数据。

| 数据 | 形状 | 业务场景示例 |
|---|---|---|
| A | 均匀聚集在 100 附近 | 靠回头客的稳定销售额 |
| B | 60 档和 140 档两个群 | 工作日客人和周末客人截然不同的店 |
| C | 大多在 80 档，带一个极端值 | 平时安静，偶尔来一单大合同 |
| D | 在 40~160 之间大范围散开 | 销售额全凭运气的店 |

只看平均数，这四家店是同一家店。但备货计划、人员排班、
现金流管理策略应该完全不同。仅凭平均数这一个概括，
这些差异完全看不出来。

### 3.3 怀疑概括的三个问题

1. **离散程度**：数值是聚在平均数附近，还是散得很开？(→ level01 方差)
2. **形状**：是一整团，还是好几群，还是偏向一边？(→ level02 分布)
3. **极端值**：是不是少数几个值在拖着概括走？(→ level01 中位数)

这三个问题，也正是这门课前半部分的目录。

### 3.4 当概括被人为操纵时

概括不只会因失误而失真，也会被有意扭曲。"平均年薪 5,000 万韩元的公司"
这条招聘广告背后，可能藏着几位高管的天价年薪；"90% 的客户表示满意"
这句广告词背后，可能藏着挑选问卷受访者的小动作。学统计既是制造数字的技术，
也是不被别人制造的数字欺骗的防身术。在这门课里，你会养成一个习惯：
时刻追问"这个概括是怎么算出来的"。

## 4. 实战 — main.py

```bash
python3 main.py
```

代码会生成 4 组平均数都是 100 的虚构销售数据 (A~D)，然后：

- [1] 计算每组数据的平均数，确认"从概括上看一模一样"；
- [2] 把最小值、最大值、中位数摆在一起，揭开概括背后的差异；
- [3] 用文本直方图 (星号图) 画出四组数据的形状；
- [4] 最后用输出说明："哪家店该增加夜班人手" 这类判断，
  光靠概括值是做不出来的。

核心代码是 `ascii_hist()` 函数。它把数值分进区间 (bin) 里计数，
按个数打印 `*`。虽然我们还没学 matplotlib，但直方图的原理
(分区间、数频次) 在这里已经全部登场。请在输出中亲眼比较：
A~D 的星号形状差别有多大，而平均数为什么却一模一样。

## 5. 亲手试试

1. **(简单)** 把 `make_datasets()` 里数据 C 的极端值 (1200) 改成 3000
   再运行。要把平均数拉回 100，其余的值得怎么变？(提示：代码不会自动校正，
   所以平均数会被带偏。目的就是观察一个极端值的影响力。)
2. **(中等)** 把你工作中的 10 个真实数字 (例如最近 10 天的步数、支出额)
   放进列表，套用 `summarize()` 和 `ascii_hist()`。如果平均数和中位数
   不一样，请解释为什么。
3. **(挑战)** 亲自设计并添加第五组数据 E："平均数相同但中位数差很多"。
   (提示：构造"大量小值 + 少数大值"的结构，就能在保住平均数的同时
   压低中位数。)

## 6. 常见错误

- **只凭一个平均数下结论**："平均数涨了所以变好了" 只是一半的事实。
  也可能是一个极端值拉上去的。
- **不概括，直接甩原始数据**：另一个极端同样是问题。把几万行原样上报，
  没有人会读。正确做法是概括，同时说明丢掉了什么。
- **以"统计太难"为由只靠直觉**：本关卡用到的工具只有加法、除法和
  打星号。统计的一半，就是这种"踏实的观察"。
