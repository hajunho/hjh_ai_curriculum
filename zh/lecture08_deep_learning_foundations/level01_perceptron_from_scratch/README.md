# Lecture 08 · Level 01 — 亲手实现感知机

> 用大约 30 行 numpy 亲手实现神经网络的最小单元感知机，按轮次 (epoch) 观察"每错一次就改一点权重"这条学习规则如何解开 AND/OR，又如何在 XOR 上失败。

**难度** ⭐⭐ / **先修** level00_why_neural_networks / **预计时间** 50分钟

## 1. 为什么要学 — 从业务视角出发

再庞大的语言模型，说到底也是几十亿个极其简单的零件拼起来的。那一个零件就是感知机 (perceptron)，也就是人工神经元。把一个零件的动作彻底搞懂，后面出现的"叠层"、"学习权重"、"模型收敛"这些话就不再像魔法了。

从实战角度看，这一关真正的收获是看清学习 (learning) 这个词的实体。AI 会学习并不神秘，它就是"预测一下，按错的程度把数字改一点，再预测一下"的重复劳动。有了这个手感，当合作方汇报"我们重新训练了模型"时，你就能判断这话意味着做了什么、做了多少，为什么训练要花时间，为什么有些问题再怎么训练也不行 (像 XOR 那样)。最后那段失败演示尤其重要 —— 只有知道工具极限的人，才能把工具选对。

## 2. 用比喻来理解

感知机就像会议上的加权投票。一个议案摆在桌上，多位参会者投赞成 (1) 或反对 (0)。只是每个人的话语权并不一样: 组长的意见权重是 3，新人的意见权重是 0.5。把每份意见乘上话语权全部加起来，超过通过线就是议案通过，没超过就是否决。这里参会者的意见是输入 (x)，话语权是权重 (w)，调节基准线高低的那个值是偏置 (b)。

那学习又是什么? 就是过后把这个会议体做出的决定拿去和实际结果对账。通过了但结果不好 (标签 0，预测 1)，就把当初投赞成那些人的话语权稍微削一点。否决了但事后发现是个好议案 (标签 1，预测 0)，就把投赞成的人的话语权稍微抬一点。决定对了就什么都不改。把这套简单的人事调整对着每个议案 (数据) 反复做下去，话语权的分配就会一点点挪向"能做出好决定的分配"。这就是感知机学习规则的全部。

有一件事得先说清: 这个会议体只有一个委员会，是单层结构，所以它把 level00 里那条直线的极限原封不动继承了下来。面对 XOR 这种直线切不开的问题，话语权再怎么调，结论也永远来回摇摆。

## 3. 核心概念

### 3.1 感知机的计算

对输入 x1、x2，感知机分两步算。

1. 加权和: `z = w1*x1 + w2*x2 + b`
2. 阶跃函数 (step function): `z >= 0` 就输出 1，否则输出 0

计算式和 level00 的线性模型一样。差别在求系数的方式。level00 里我们用公式 (最小二乘) 和穷举找最优直线，而感知机是一条一条看数据，渐进地找过去。

### 3.2 感知机学习规则

看完一条数据 (x, 标签 y) 并给出预测 p 之后，更新就是下面这一行。

```
w <- w + lr * (y - p) * x
b <- b + lr * (y - p)
```

这里 lr 是学习率 (learning rate)，也就是一次改多大的步幅。`(y - p)` 只有 0 (答对)、+1 (本该 1 却预测成 0)、-1 (本该 0 却预测成 1) 三个取值，所以这条规则就是: 对了就不动，错了就朝着错的反方向推一把。把全部数据走一遍叫一个轮次 (epoch)；一个轮次里一次都没错，就说训练收敛 (convergence) 了。

### 3.3 收敛定理及其极限

感知机有一个著名的保证: 只要数据是能被一条直线 (高维里是超平面) 分开的问题，这条规则必定在有限次修正内收敛。AND 和 OR 就属于这类。反过来，像 XOR 这种直线分不开的问题，收敛在原理上就不可能 —— 无论权重取什么值，总至少剩下一个点是错的，而修这个点的更新又会把别的点弄错，于是权重永远在振荡。实战里我们会用数字亲眼看到这个振荡。

## 4. 实战 — main.py

运行方式如下。

```bash
cd lecture08_deep_learning_foundations/level01_perceptron_from_scratch
python3 main.py
```

输出分四步。

- **[1]** 介绍那个约 30 行的 `Perceptron` 类，并展示初始权重 (固定种子的随机数)。
- **[2]** AND 训练: 每个轮次输出一行 `w1, w2, b` 和该轮次的误分类 (错误预测) 个数。误分类变成 0 的那一刻宣布收敛，并展示最终的真值表验证。
- **[3]** OR 训练: 重复同样的过程。可以看到它比 AND 更快或差不多快地收敛。
- **[4]** XOR 训练: 跑到轮次上限 (25 次) 误分类也不会变成 0。权重在一个轮次里被推来推去最后又回到原地，陷在振荡 (循环) 里，准确率停在 50%。最后以"必须改结构"这个结论收尾。

代码里值得盯的地方是 `fit` 方法里的那两行更新。3.2 节的公式被原样搬成了 numpy 代码。另外 `errors == 0` 时提前退出的那部分，就是把"收敛"的定义写成了代码。跟着输出去看权重每个轮次怎么挪，你会看见: 训练说到底就是三个数字慢慢各就各位的过程。

## 5. 动手试试

1. **(简单)** 把学习率 `lr` 从 0.1 改成 0.5，再改成 0.01 运行看看。收敛所需的轮次数变化如何? 提示: 步幅大走得快但可能走过头，步幅小稳当但要走很久。这份数据很小，差别可能没那么明显。
2. **(普通)** 把 `Perceptron` 初始化的种子从 7 换成别的值，多跑几次。最终权重每次都不一样，但真值表全都对。请确认"正确的直线不止一条"这个事实，并想一想为了可复现还是要固定种子的理由。
3. **(挑战)** 在 [3] 后面加一段训练 NAND (只有两个都是 1 时才为 0) 的代码。然后把这两个手工做出来的感知机的输出 —— 也就是 NAND 的结果和 OR 的结果 —— 当作新输入，让第三个感知机去学 AND，整体就成了 XOR。提示: 这和 level00 的隐藏表示是同一个结构。三个感知机接起来就是一个 2 层神经网络。

## 6. 常见错误

- **看到 XOR 失败就怀疑代码有 bug。** 误分类掉不到 0 不是 bug，而是这一关的核心结论。这是单层结构的数学极限。
- **把轮次和更新次数搞混。** 1 个轮次是把 4 条数据全部走一遍，而更新只在其中出错的那几条上发生。
- **以为学习率一味调大就会更快。** 这个例子太小看不太出来，但实战中大学习率正是发散 (数值乱跳、永远收敛不了) 的罪魁祸首。
- **把权重初值全设成 0。** 单个感知机从 0 开始也能学，但到了后面的多层神经网络，神经元会全部一模一样地动，训练就坏掉了。这就是从现在起要养成用小随机数初始化的习惯的理由。
- **忘了处理阶跃函数的边界 (`z = 0`)。** 用 `>=` 还是 `>`，会改变边界上的点归到哪一类，所以实现和说明必须一致。
