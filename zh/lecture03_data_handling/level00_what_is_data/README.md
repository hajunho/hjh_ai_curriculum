# Lecture 03 · Level 00 — 数据到底是什么 — 表格的结构

> 把数据分析的起点"表"拿来解剖一遍。只要抓住"行是事例、列是属性"这条原理，Excel 和 Python 在你眼里就会变成同一种语言。

**难度** ⭐ / **先修** 无 (学完 lecture02 Python 基础就足够) / **预计时间** 40分钟

## 1. 为什么要学 — 从业务视角出发

公司里流转的信息，绝大部分最终都会被整理成表。销售报表、客户名单、库存清单、考勤记录 — 格式各异，但本质上全都是"把多条事例按同样的项目记录下来"。不管分析工具是 Excel、Python、SQL 还是 BI 看板，它们全都跑在这套表结构之上。

所以，准确理解表的结构，比学某个具体工具更靠前。只要你能回答"这张表里的一行代表什么?"，那么无论用哪种工具，你都已经起步了一半。反过来，没回答出这个问题就先去背函数，结果就是数字出来了，你却不知道这个数字数的是什么。实际工作中相当多的错误汇报，源头就在这里。

本关还不会用到 Pandas 或 NumPy。我们只用 Python 最基础的材料 — 字典 (dictionary) 和列表 (list) — 亲手摸一遍表，用手确认那些容易被工具藏起来的表格本质。

## 2. 用比喻来理解

表很像**单元楼的信箱墙**。每一个信箱 (值) 都由"几号楼几零几"这两个坐标精确定位。表也一样，只要有"第几行、哪一列"这两个坐标，任何值都能取出来。

再换一个离工作更近的比喻: **员工人事档案卡册**。

- 一张卡 = **行 (row)**。把"某位员工"这一个事例整体装进去。
- 卡上印好的空格 (姓名、部门、入职日……) = **列 (column)**。所有卡片都有同样的空格。
- 空格标题的清单 = **表结构 (schema)**。也就是"我们这套卡片上，哪些项目要按什么格式填"这个约定。

关键在于卡册的规矩。如果有的卡片有"入职日"这一格、有的没有，那整个卡册就没法按入职日排序。表的力量来自于**所有行共享同一套列结构**这个约定。有这个约定的数据叫结构化数据，没有约定的自由记录 (比如客户留下的评论句子) 叫非结构化数据。

## 3. 核心概念

### 3-1. 行 = 事例，列 = 属性

- **行 (row, record)**: 观测到的一个事例。像"2025年1月3日、朝阳店、咖啡品类的当日销售额"这样，是世界上发生过的一件事。
- **列 (column, attribute / 变量)**: 对所有事例都共同记录的项目。日期、门店、品类、销售额之类。统计学里也叫变量 (variable)。

拿到一张表，最该先问的问题是: **"这张表的一行是一件什么事?"** 同样是销售数据，行是"1 笔交易"的表和行是"各门店各品类的当日合计"的表，处理方式完全不同。这个单位有时也叫粒度 (grain)。

### 3-2. 表结构 (schema) — 关于列名和类型的约定

schema 规定两件事。

1. 列的**名字**: 像 `date`、`store`、`revenue` 这样，都有哪些项目。
2. 列的**类型 (type)**: 每个项目是字符串、整数，还是日期。

类型之所以重要，是因为运算会随类型改变。`"100" + "200"` 是字符串拼接，得到 `"100200"`; 而 `100 + 200` 得到 `300`。这是实际工作中事故的常客。

### 3-3. 结构化 vs 非结构化

| 区分 | 结构化数据 | 非结构化数据 |
|---|---|---|
| 形态 | 行列固定的表 | 自由文本、图像、语音 |
| 例子 | 销售流水账、会员名单 | 客户评论、客服录音、照片 |
| 聚合 | `SUM`、平均可以直接做 | 得先把结构抽出来才行 |

非结构化并不是"低等"。信息量反而更大。只不过**要聚合就得先变成表** (例如: 评论 → 好评/差评 列)。这个转换过程会在后面的自然语言处理课里讲。

### 3-4. 在 Python 里表示表的最朴素方法

就是字典列表 (list of dicts)。

```python
table = [
    {"store": "朝阳店", "revenue": 500000},
    {"store": "海淀店", "revenue": 420000},
]
```

- 列表的一个元素 = 一行
- 字典的键 (key) = 列名

Pandas 的 DataFrame 说到底也就是把这个结构做得更快、更方便而已。先亲手摸过原型，从 level03 开始学的 Pandas 在你眼里就不再是"魔法"，而是"便利功能"。

### 3-5. 缺失 — 格子是空的，这件事本身也是信息

现实数据里一定会有没能记上值的格子。Python 里用 `None` 表示。"0"和"空着"是完全不同的两件事。销售额 0 元说明"没卖出去"，而 `None` 是"不知道卖了多少"这个状态。这个区分在 level06 会正式展开，但从第一次看表起就养成数一数有几格是空的这个习惯，是有好处的。

## 6. 常见错误

- **没确认行的含义就先求合计**: 这张表里 `sum(revenue)` 是"各品类当日销售额的总和"。要是误以为行是交易笔数，就会汇报出"交易 750 笔"这种错误结论。
- **把 `None` 和 0 混在一起**: 对混了 `None` 的列表直接 `sum()` 会抛 `TypeError`。这属于"报错反而是好事"的情况。偷偷换成 0，平均值就被扭曲了。
- **列名打错**: 像 `rows[0]["revenu"]` 这样写错键会抛 `KeyError`。列名永远先用 `keys()` 确认一遍。
- **靠眼睛判断类型**: 屏幕上显示 `123`，实际可能是字符串 `"123"`。要养成用 `type()` 确认的习惯。
