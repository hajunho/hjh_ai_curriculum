## 1. 为什么要学 — 从业务视角出发

level01 里写的循环代码，在 1,500 行时是一瞬间的事，但数据到了几百万行就会明显变慢。交易日志、传感器记录、广告点击数据，几百万行是常态。"跑起来去喝杯咖啡再回来的代码"和"立刻出答案的代码"，这个差别在实际工作中决定了你能分析几次。跑得快，你就能多问几个问题。

NumPy 是 Python 里快速处理大批数字的标准库。而且从下一关开始学的 Pandas、以后要学的 scikit-learn 和 PyTorch，全都跑在 NumPy 数组之上。也就是说，NumPy 的思维方式 — **"把运算的单位从一个数字换成一堆数字 (数组)"** — 是整个数据领域的通用语法。在这里养成这个感觉，后面所有工具在你眼里都会是同一套原理。

## 2. 用比喻来理解

假设要在便利店结算 1,000 罐饮料。

- **Python 循环** = 一罐一罐往条码枪上扫的店员。每罐的动作很快，但"拿起 → 扫 → 放下"这套准备动作要重复 1,000 次。
- **NumPy 向量运算** = 整箱上秤一次称完的物流仓库。"准备动作"只有一次，真正的计算交给机器 (优化过的 C 代码) 处理。

Python 循环慢的真正原因不是计算本身，而是**每次都要重复的准备动作** (检查值的类型、拆开对象的包装等)。NumPy 事先约定好了"这箱里全是同一类型的数字"，所以它跳过准备动作，在连续的内存上以机器速度狂奔。

广播 (broadcasting) 就是**盖章**。"给所有销售额加 10% 增值税"这条指令，不必重复 1,000 遍，而是把 `revenue * 1.1` 这一个章一次盖遍整个数组。

## 3. 核心概念

### 3-1. ndarray — 同一类型数字的连续一坨

NumPy 的核心数据结构是多维数组 (ndarray)。和 Python 列表有两个决定性的差别:

1. **所有元素同一类型**。正因为有这个约定，才能不检查类型就高速计算。
2. **在内存里连续排列**。CPU 可以预测着提前读进来，于是更快。

```python
import numpy as np
a = np.array([1, 2, 3])
a * 10        # array([10, 20, 30]) — 不用循环就作用于全体
```

### 3-2. shape 和 dtype — 数组的身份证

- **shape**: 数组的形状。`(1500,)` 是一维 1,500 个，`(30, 5)` 是 30 行 5 列。大部分报错都出自 shape 不一致，所以拿到数组先看 `shape` 这个习惯很重要。
- **dtype**: 元素的类型。`int64` (整数)、`float64` (浮点) 等。缺失值 `NaN` (Not a Number) 只可能存在于 float 里，所以你会经常看到混了缺失的整数列变成 float 这个现象。

### 3-3. 向量化 — 用运算符替掉循环

所有"对每个元素做同一件事"的活儿，都用数组运算而不是循环来写。

| 循环式思维 | 向量化思维 |
|---|---|
| `for r in revenues: total += r` | `revenues.sum()` |
| `for r in ...: new.append(r * 1.1)` | `revenues * 1.1` |
| `for r in ...: if r > 100万: ...` | `revenues[revenues > 1_000_000]` |

最后一行就是布尔掩码 (boolean mask)。`revenues > 1_000_000` 会造出一个 True/False 数组，把它放进方括号里，就只挑出 True 位置上的值。这是 level05 里 Pandas 筛选的骨架语法，所以在这里就把它练熟。

### 3-4. 广播 — 尺寸不同也能对齐计算

像 `数组 * 1.1` 这样，数组和一个数字 (标量) 做运算时，NumPy 会把这个数字"拉长"到数组的尺寸再计算。实际上并不复制内存，只是概念上拉长，所以也没有成本。给 `(30, 5)` 的数组加一个 `(5,)` 的数组，就会变成每一行都加一遍 — 维度不同，只要规则对得上就会自动扩展。

### 3-5. 聚合函数

`sum()`、`mean()` (平均)、`std()` (标准差)、`min()/max()`、`round()` 等都以数组方法的形式提供。二维数组里用 `axis=0` (沿列方向) / `axis=1` (沿行方向) 决定聚合方向，这是理解 level07 groupby 的垫脚石。

## 6. 常见错误

- **混淆列表和数组的 `*`**: `[1, 2] * 3` 是列表重复 (`[1,2,1,2,1,2]`)，而 `np.array([1, 2]) * 3` 是逐元素乘 (`[3, 6]`)。完全是两码事。
- **把混了 None 的列表直接转成数组**: dtype 会变成 `object`，向量化的速度优势就没了。缺失必须在造数组之前去掉，或者统一成 `NaN`。
- **用 for 循环遍历数组**: 语法上能跑，但用 NumPy 的意义就没了。请把"一想用循环，就先找找有没有对应的向量运算"当成原则。
- **搞错 `axis` 方向**: 二维里 `sum(axis=0)` 是"把行压下去"，得到各列的合计。永远确认一下结果的 shape。
