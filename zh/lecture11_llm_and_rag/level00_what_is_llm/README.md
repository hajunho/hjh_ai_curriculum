# Lecture 11 · Level 00 — LLM 是什么：超大号"下一个词预测器"

> 用一个迷你模型亲手体验一件事：ChatGPT、Claude 这些大规模语言模型 (LLM) 实际在做的，就是"猜下一个词"。

**难度** ⭐ / **先修** lecture02 (Python 基础) / **预计时间** 30分钟

## 1. 为什么要学 — 业务视角

如今公司里每天都会冒出好几遍这样的问题："这事能不能用 AI 搞定？"可如果不知道 LLM (Large Language Model，大规模语言模型) 擅长什么、不擅长什么，就会犯两种错误。一种是高估——觉得"AI 会自己搞定一切"，不加核对就把它的输出粘进报告；另一种是低估——觉得"不就是个聊天机器人嘛"，把业务自动化的机会白白放过。

在这一关把 LLM 的原理浓缩成一句话记住，之后所有判断都会变简单：**LLM 是一台"根据前文预测下一个词出现概率"的机器**。从这一句话出发，LLM 的强项 (流畅的写作、总结、翻译) 和弱项 (无法核实事实、缺少最新信息、幻觉) 全都能推导出来。懂得工具原理的人，才能驾驭工具。

## 2. 打个比方

想象一下**手机输入法联想功能的超大号版本**。你打出"新年快"，键盘就会提示"乐"。如果这个联想功能 (1) 读过的不是几个词，而是几百万本书的文字；(2) 记住的不是前一两个词，而是几万个词的上下文；(3) 一次提示的不是一个词，而是一整段话——那它就是 LLM。

**参数 (parameter) 就是经验值**。就像游戏角色经验值越高能打越难的副本一样，参数 (模型通过训练调整出来的数字) 越多，能记住的语言模式就越微妙。新员工 (小模型) 只会处理手册里写过的事，而二十年的老师傅 (大模型) 面对没见过的情况也能靠"类似的经验"举一反三。

不过老师傅也有软肋。**离职的员工不知道离职之后公司发生的事。**LLM 同样不知道训练结束时点 (知识截止时间, knowledge cutoff) 之后的事。而当记忆模糊时，他会一本正经地说"应该是那样吧"——这就是幻觉 (hallucination)。

## 3. 核心概念

### 3.1 按 token 逐个生成

LLM 不会一口气生成整句话。它先预测一个 token (词元，词的碎片)，把它接到输入后面，再预测下一个 token。一段 100 个词的回答，就是把这个过程重复了几百次。API 按"token 计费"的原因、回答越长越慢的原因，都在这里。

### 3.2 概率分布与抽样

每一步，模型都会为"接下来可能出现的所有 token"排一张概率表。比如"昨天 开发者"之后是"把程序 31%、把报告 20%、..."这样一个分布。如果永远只挑第 1 名 (贪心式选择)，答案就一成不变、非常单调；按概率抽签 (抽样)，每次就会得到略有不同、更多样的答案。同一个问题 ChatGPT 每次回答都不一样，原因就在这里。

### 3.3 n-gram 语言模型 — 今天的实验材料

神经网络时代之前的语言模型就是一张简单的统计表。n-gram 模型记录的是"前面 (n-1) 个词是这些时，下一个词曾经是什么"。

| 上下文 (前2个词) | 下一个词候选 | 次数 |
|---|---|---|
| 昨天 开发者 | 把程序 | 87 |
| 昨天 开发者 | 把报告 | 45 |

真实的 LLM 就是把这张"表"换成了神经网络，让它对表里没有的上下文也能举一反三。原理不变：**用过去文本的统计来预测下一个词。**

### 3.4 两个与生俱来的局限

1. **知识截止时间**: 训练数据里没有的，它就不知道。咱们公司的规章制度、昨天的新闻、客户数据库——统统不知道。(解决方案就是本课后半部分的 RAG。)
2. **幻觉**: 它学会的是"说得流畅"，而不是"只说事实"。只要一个组合在统计上够顺口，即使不是事实它也会自信满满地说出来。

## 4. 动手练习 — main.py

运行:

```bash
cd lecture11_llm_and_rag/level00_what_is_llm
python3 main.py
```

输出解读:

- **[1]~[2]** 用 `hjh_data.tiny_corpus()` 的中文迷你语料 (约 3.3 万字符、8,000 个词) 建立 bigram/trigram 统计表。这个"造表"过程就是训练。语料本身已按词分好 (bigram 上下文 20 种、trigram 上下文 100 种)。
- **[3]** 展示"上班族"之后各个词的概率分布柱状图 (第 1 名是"把计划书" 23.0%)。LLM 每生成一个 token，内部做的正是这件事。
- **[4]** 同一个开头 ("今天 厨师")，抽样生成 3 句各不相同的句子，而贪心式选择永远生成同一句 ("今天 厨师 把信 整理好了。")。
- **[5]** 确认生成的 20 句里混着训练数据中**从未出现过的新组合** (本次运行为 1 句)。语法没错，但没有任何事实保证——这就是幻觉的微缩模型。
- **[6]** 把语料里不存在的词 ("新员工") 当上下文，概率分布干脆是空的。这就是知识截止时间的微缩模型。

代码的核心是三段式结构: `build_ngram_model` (上下文→下一个词计数)、`next_word_distribution` (计数→概率)、`generate` (概率→抽签→循环)。LLM 的骨架也是如此，只是把计数表换成了神经网络。

## 6. 常见误区

- **误以为"LLM 是先搜索再回答的"** — 裸的 LLM 什么都不搜索，它只是用训练时见过的统计来生成。给它接上搜索是另一门技术 (RAG, level08)。
- **"它说得那么笃定，应该是真的吧"** — 那只说明这个 token 概率排第一，不代表它是事实。流畅 ≠ 准确。
- **同一个问题答案不同就以为出故障了** — 这是抽样的正常表现。需要可复现时，把 temperature 调低 (更接近贪心式选择) 即可。
- **不固定随机种子就做实验** — 今天的代码用 `random.Random(42)` 固定了种子。想对比实验结果，请永远固定种子。
