# Lecture 01 · Level 02 — 终端第一步

> 学会不用鼠标、只靠键盘命令给计算机派活的终端基本命令 (pwd, ls, cd, mkdir, cp, mv, rm)。

**难度** ⭐ / **先修** level01 / **预计时间** 40分钟

## 1. 为什么要学 — 从业务视角出发

从现在起，本课程的所有实战都从在终端里输入 `python3 main.py` 开始。和开发者协作、登录云服务器、安装 AI 工具的时候，屏幕上出现的都不是可以点的按钮，而是一个一闪一闪的光标。害怕终端，你就会每次都在它面前停下来。

终端强大的原因在于: **用"话"派出去的活可以被记录、可以被重复**。用鼠标建 100 个文件夹要点 100 次，在终端里一行就够。而且这一行存下来之后，下个月还能照跑，接手的同事也能照跑。重复工作自动化 (level08) 的起点就在这里。

## 2. 用比喻来理解

**GUI (图形界面) 是用手势派活，终端是用话派活**。

假设要让下属整理文件。用手势的话，你得亲自走到文件柜前，"这个，放那边"地一个个指 (鼠标点击、拖拽)。用话的话，一句"把 3 层文件柜里 2023 年的文件全部搬到库房"就完事了，而且这条指示还能写成文档，让人每个月照着重复执行。

终端命令的结构也和真实的指令很像。

```
cp  report.txt  backup/
动词    宾语        地点
"复制, report.txt, 到 backup 文件夹"
```

命令是动词，后面跟的是宾语和状语 (选项)。像 `ls -l` 里的 `-l` 这种以 `-` 开头的，是起"详细点"、"全部"这类状语作用的**选项 (option)**。

还有一点: 终端里永远存在"我现在站的位置"，也就是 level01 学过的**当前工作目录 (CWD)**。所有命令都以你现在所站的房间为基准执行。所以终端操作的第一习惯就是先确认"我现在在哪?"。

## 3. 核心概念

### 3-1. 七个保命命令

| 命令 | 含义 | 比喻 |
|---|---|---|
| `pwd` | 打印当前位置 (print working directory) | "这里是几层哪个房间?" |
| `ls` | 列出当前文件夹内容 (list) | "这屋里有什么?" |
| `cd 文件夹` | 移动位置 (change directory) | "去那个房间" |
| `mkdir 文件夹` | 创建文件夹 (make directory) | "装个新文件柜" |
| `cp 源 目标` | 复制 (copy) | "复印一份放那边" |
| `mv 源 目标` | 移动或重命名 (move) | "搬过去。同屋内就是换标签" |
| `rm 文件` | 删除 (remove) | "进碎纸机。**不进回收站，立即销毁**" |

常用组合: `cd ..` (上一层)、`cd ~` (回我的主目录)、`ls -l` (详细列表)、`mkdir -p a/b/c` (连中间层级一次建好)。

### 3-2. macOS 和 Windows 的差异

- **macOS**: 打开自带的"终端"应用即可。它和 Linux 同属 Unix 一系，上面的命令原样通用。开发服务器绝大多数是 Linux，所以 Mac 用户学到的东西在服务器上直接就能用。
- **Windows**: 传统的"命令提示符 (cmd)"命令不一样 (`ls` 换成 `dir`，`cp` 换成 `copy`)。近年 **PowerShell** 已支持 `ls`、`cd` 等相当一部分命令; 做开发的标准选择是安装 **WSL (Windows Subsystem for Linux)**，在 Windows 里使用 Linux 终端。本课程的命令以 macOS/Linux (含 WSL) 为准。

| 用途 | macOS/Linux/WSL | Windows cmd |
|---|---|---|
| 列表 | `ls` | `dir` |
| 复制 | `cp` | `copy` |
| 移动 | `mv` | `move` |
| 删除 | `rm` | `del` |
| 路径分隔符 | `/` | `\` |

### 3-3. 名叫 Shell 的翻译官

在终端窗口里真正负责解析并执行命令的程序叫 **Shell (壳)**。macOS 的默认 Shell 是 zsh，Linux 上主要是 bash。记成"终端是窗口，Shell 是窗口里听得懂指令的翻译官"就行。以后遇到 `.sh` 文件 (Shell 脚本) 时，那就是要递给这位翻译官的一沓指令单。

### 3-4. 危险命令警告

`rm` 不经过回收站，直接删除。尤其 `rm -rf 文件夹` 会把文件夹连同里面的一切不可逆地抹掉。实际工作中，删除前先用 `ls` 确认目标、用通配符 (`*.txt` 这类模式) 前再多读一遍的习惯，能避免事故。

## 4. 实战 — main.py

```bash
python3 main.py
```

在操作真正的终端之前，先用 Python 写的**迷你 Shell 模拟器**安全地练习。脚本会在临时文件夹里搭一个小小的练习办公室，把预先编排好的场景命令一行行按"输入 → 执行 → 结果"展示出来。

- **[1] 准备练习场**: 在临时文件夹里铺几个示例文件。就算失手，对你的电脑也毫无影响。
- **[2] 执行场景**: 按 `pwd → ls → mkdir backup → cp → cd → mv(改名) → rm` 的顺序，把一项真实业务 (报告备份和整理) 用命令处理完。每条命令都附有"这一步做了什么"的中文解说。
- **[3] 确认最终状态**: 展示整理完的文件夹结构，并对比一下同样的活如果用鼠标要点多少次。

核心代码是 `MiniShell` 类。它把 `cwd` (当前位置) 作为状态揣在身上，由 `cmd_ls`、`cmd_cd` 这样的方法用 pathlib 实现各条命令。也就是说，我们用代码验证了 **Shell 干的活归根结底就是"记住当前位置、代为调用文件系统函数"**。用模拟器熟悉流程后，请打开真正的终端把同样的命令亲手敲一遍。

## 5. 动手试试

1. **(简单)** 打开真正的终端，依次敲 `pwd`、`ls`、`cd Documents` (或任何存在的文件夹)、`cd ..`。每条命令之后用 `pwd` 看看位置怎么变。*(提示: 迷路了就 `cd ~` 回主目录。)*
2. **(普通)** 在 main.py 的 `SCENARIO` 列表里加上 `mkdir archive` 和 `mv 会议纪要.txt archive` 两条命令，让会议纪要移动到 archive 文件夹。*(提示: 照着现有场景条目的格式写即可。)*
3. **(挑战)** 给 `MiniShell` 加一条 `cat 文件` 命令 (打印文件内容)。*(提示: 写一个 `cmd_cat` 方法、用 `read_text()` 即可。观察其他 `cmd_` 方法是怎么被注册的。)*

## 6. 常见错误

- **不确认当前位置就执行命令**: 在错误的文件夹里建文件、删文件的事故元凶。请像条件反射一样先敲 `pwd` 和 `ls`。
- **带空格的名字直接输入**: `cd My Documents` 会被解析成 "My" 和 "Documents" 两个宾语。必须像 `cd "My Documents"` 这样加引号。
- **把 `rm` 当成回收站**: 终端的删除是立即且永久的。在重要文件夹里，先用 `mv` 挪到别处而不是直接 `rm`，也是一种安全技巧。
- **命令不灵就慌了**: 大多是打错字 (命令对拼写极其严格)，或者在 Windows cmd 里敲了 macOS/Linux 命令。养成把报错信息原文读一遍的习惯，它是最好的老师。
