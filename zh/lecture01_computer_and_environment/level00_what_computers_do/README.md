# Lecture 01 · Level 00 — 计算机到底是一台做什么的机器

> 计算机归根结底是一台"接收输入 → 进行计算 → 给出输出"的机器；CPU、内存和存储设备像公司里的部门一样分工协作。本关就是要理解这件事。

**难度** ⭐ / **先修** 无 / **预计时间** 30分钟

## 1. 为什么要学 — 从业务视角出发

在接下来的整个课程里，我们会让计算机替我们干无数的活: 整理数据、画图表，之后还要训练 AI 模型。可是，如果派活的一方对干活的一方的情况一无所知，麻烦就来了。比如"为什么这个任务 1 秒就完事，那个任务却要一个小时?"、"为什么程序一关，正在做的内容就没了?"、"提示内存不足的报错到底是什么意思?" — 这些问题你将无法自己回答。

职场上也是一样。把活外包给供应商时，哪怕只是大致了解对方公司的组织结构和工作方式，你也能明白报价和排期为什么是那个样子。计算机就是我们每天委托干活的"供应商"。只要对它的内部结构有一个整体印象，之后各关卡里会遇到的术语 (CPU、内存、磁盘、进程) 就不再陌生。

这一关的目标只有一个: 把**计算机是一台不断重复"输入 → 计算 → 输出"的机器**这幅大图刻进脑子里。

## 2. 用比喻来理解

把计算机想象成一家小公司。

- **CPU (中央处理器) 是业务骨干**。它是公司里唯一真正做计算、做判断的存在。速度快得惊人，但一次只能做非常小的事 (加法、比较之类)。作为补偿，这些小事它每秒能处理几十亿次。相当于一位 0.0000001 秒就能批完一份文件的超高速职员。
- **内存 (RAM) 是这位职员的办公桌**。摊开当前正在处理的文件的地方。桌上的文件伸手就能拿到，所以非常快; 但一下班 (断电)，桌面就被清得干干净净。也就是说，**内存快，但是易失的**。"没保存就关机，文档飞了"的事故说的就是这个。
- **存储设备 (SSD/HDD) 是文件档案库**。永久保管文件的地方。走到档案库把文件找出来需要时间 (比内存慢几百到几千倍)，但断电后内容仍然保留。"保存文件"这个动作，就是把桌上的文件正式归档进档案库。
- **输入设备 (键盘、鼠标) 是客户接待窗口**，**输出设备 (显示器、打印机) 是成果寄送部门**。

任务的处理流程和公司的业务流程一模一样: 订单从接待窗口进来 (输入)，从档案库取出需要的资料摊到桌上 (存储设备 → 内存)，职员进行计算 (CPU)，把结果寄给客户 (输出)，再把记录归档 (内存 → 存储设备)。你打开 Excel、输入公式、保存文件的过程，正是这个流程。

## 3. 核心概念

### 3-1. 输入 → 计算 → 输出 (IPO 模型)

所有程序无一例外都由这三步构成。这叫 IPO (Input-Process-Output) 模型。

| 步骤 | 在 Excel 中的例子 | 在本关实战中的例子 |
|---|---|---|
| 输入 (Input) | 往单元格里录入销售数字 | 订单列表数据 |
| 计算 (Process) | SUM、AVERAGE 公式 | 用 Python 计算合计与平均 |
| 输出 (Output) | 屏幕上显示结果、保存文件 | 屏幕输出 + 保存文件 |

以后不管看到多复杂的 AI 程序，只要拆成"输入是什么、做了什么计算、输出是什么"三块来看，就已经理解一半了。

### 3-2. 计算机为什么只认 0 和 1

CPU 靠电信号工作。它只能可靠地区分"有电流 / 无电流"两种状态，所以一切信息都用 0 和 1 (二进制, binary) 来表示。一个 0 或 1 叫一个比特 (bit)，8 个一组叫一个字节 (byte)。文字、照片、视频、Excel 文件，最终都是一串 0 和 1。"1MB、1GB"这些容量单位，就是把字节按一百万个、十亿个来数。

### 3-3. 速度的层级 — 为什么有些任务慢

在"办公桌 (内存) vs 档案库 (存储设备)"的比喻里，关键在于**速度差距**。记住大致的量级就够了。

- CPU 内部计算: 每秒几十亿次
- 读内存: 比 CPU 计算慢几十到几百倍
- 读 SSD: 比内存又慢几百倍
- 从互联网下载: 比 SSD 还要慢几十倍以上

所以程序慢的时候，原因大多不是"计算太多"，而是"频繁往返档案库 (磁盘) 或外部 (网络)"。这个直觉在后面的大规模数据课程里还会再次登场。

### 3-4. 程序与进程

档案库里保管的业务手册 (以文件形式保存的程序) 本身什么也不会做。只有职员把手册摊到桌上、真正开工，业务才会推进。这种**正在运行的程序叫作进程 (process)**。就像同一本手册可以让多位职员同时照着干活一样，把一个程序 (比如 Chrome) 打开好几个，就会产生好几个进程。

## 4. 实战 — main.py

在终端里进入本文件夹后运行。(对终端还不熟悉的话，level02 会详细讲，现在先照着做即可。)

```bash
python3 main.py
```

这个脚本把一项小小的"咖啡连锁总部销售汇总业务"比作计算机公司的组织分工来处理。数据里的金额沿用了韩元 (KRW) 计价。

- **[1] 输入**: 各门店的订单数据进来 (接待窗口)。
- **[2] 存储设备 → 内存**: 把数据存进临时文件 (档案库) 再读回来，演示"存了就留下、内存会挥发"的差别。
- **[3] 计算**: 扮演 CPU，计算合计、平均和销售额最高的门店。同一个计算重复 100 万次也用不了 1 秒 — 我们会实际计时验证。
- **[4] 输出**: 以人读起来舒服的报表形式打印到屏幕。
- **[5] 二进制初体验**: 展示 "AI" 这两个字符实际是以怎样的 0/1 存储的。

代码里值得留意的是 `process_orders()` 函数: 接收输入 (orders 列表)、做计算 (合计、平均)、给出输出 (返回字典) — IPO 模型原封不动地装进了一个函数里。还不懂 Python 语法也没关系，只要顺着 `#` 后面的中文注释读，流程就一目了然。

## 6. 常见错误

- **把"已保存"和"正在编辑"混为一谈**: 编辑文档期间，内容只在办公桌 (内存) 上。必须点保存按钮才会归档到档案库 (磁盘)。代码也一样，改完文件要先保存再运行，改动才会生效。
- **把容量和速度混为一谈**: "内存 16GB"和"SSD 512GB"都是存储空间，但角色不同。内存是桌面大小 (能同时摊开的工作量)，SSD 是档案库大小 (能保管的总量)。
- **误以为计算机很聪明**: 计算机只做你吩咐的事，而且完全按字面执行。之后课程里遇到报错时，请养成先怀疑"我的指令哪里含糊了"而不是"计算机出毛病了"的习惯。
