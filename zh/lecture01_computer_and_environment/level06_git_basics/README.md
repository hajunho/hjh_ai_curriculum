# Lecture 01 · Level 06 — Git — 版本管理的概念

> 用审批和时间旅行的比喻理解终结"最终版_真最终版.xlsx"的工具 Git 的核心概念 (快照、提交、分支)，并用真实的 git 命令实战。

**难度** ⭐⭐ / **先修** level02 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

你一定见过这样的文件夹: `方案_v1.docx`、`方案_v2_修改.docx`、`方案_最终.docx`、`方案_最终_真最终(领导意见版).docx`。哪个才是真正的最终版、v2 改了什么、是谁改的，没人说得清。要是不小心把文件覆盖了，过去就永远消失了。

开发界 20 年前就解决了这个问题。那个工具就是 **Git**。Git 把文件的全部变更历史记录在案，让你随时可以回到过去的任何一个时间点，并且能在 1 分钟内追查出什么内容、在什么时候、被谁、为什么改动。不只是代码，文档、配置、数据流水线 — 如今"一切被创造出来的东西"的履历管理标准都是它。AI 项目也不例外，模型代码、实验配置的历史全都管理在 Git 之上。不懂 Git，和开发团队协作时一半的对话你都听不懂。

## 2. 用比喻来理解

**提交是审批盖章，仓库是审批档案柜，分支是平行宇宙的时间旅行**。

- **仓库 (repository)**: 附属于项目文件夹的一只看不见的审批档案柜 (`.git` 文件夹)。`git init` 就是宣布"本文件夹开始做履历管理"、把档案柜装上。
- **提交 (commit)**: 给此刻整个文件夹的状态拍张照 (快照, snapshot)，连同审批章一起放进档案柜的动作。章上盖有编号 (哈希)、日期、经办人，以及**审批事由 (提交信息)**。不再是"另存 v1、v2 文件"，而是"把同一份文件的状态按时间点保管"。
- **暂存 (staging)**: 提交审批之前，**挑选要放上审批夹的文件**的步骤。用 `git add` 声明"这次审批只包含这几个文件"。不是桌上的全部文件，只有挑中的才盖章。
- **分支 (branch)**: 开一个平行宇宙。正传剧情 (main 分支) 原封不动，"要不试试改改价格策略?"这类实验在分岔出去的宇宙里进行。实验成功就并回正传 (merge)，失败就只废弃那个宇宙，正传毫发无损。
- **检出/时间旅行**: 可以把文件夹状态回退到档案柜里任何一个盖章的时间点。"回到上周二的状态看看"只是一行命令。

## 3. 核心概念

### 3-1. 三个空间

Git 操作就是在三个空间之间搬运。

```
工作文件夹(办公桌)  --git add-->  暂存区(审批夹)  --git commit-->  仓库(档案柜)
```

| 空间 | 比喻 | 状态 |
|---|---|---|
| 工作文件夹 (working directory) | 正在编辑的办公桌 | 可随意修改，尚未记录 |
| 暂存区 (staging area) | 审批夹 | 将进入下次提交的候选 |
| 仓库 (repository) | 审批档案柜 | 盖过章的永久记录 |

`git status` 是显示"现在桌上和审批夹里有什么"的万能确认命令。

### 3-2. 必备命令七条

```bash
git init                       # 装档案柜 (每个文件夹一次)
git status                     # 查看当前状态 (随时!)
git add 文件 或 .              # 放上审批夹
git commit -m "事由"           # 盖章 (信息必填)
git log --oneline              # 查审批历史
git branch 名字 / git switch 名字   # 开平行宇宙 / 移动过去
git diff                       # 比较哪里变了
```

在第一次使用的电脑上，要先登记刻在章上的名字: `git config --global user.name "名字"`、`git config --global user.email "邮箱"`。

### 3-3. 好提交的诀窍

- **小步、勤提交**: 别把一整天的活攒着盖一次章，而是每个有意义的单位 (一个功能、一处修改) 就盖一次。回退会容易得多。
- **信息要写"为什么"**: "修改"这种信息还不如没有。要写成"修正折扣率计算错误 (10%→15%)"这样，让未来的自己读得懂事由。
- **提交是抹不掉的安全网**: 提交过的东西，无论犯什么错都能找回来。"先提交再说"是最好的备份习惯。

### 3-4. .gitignore — 不记录的东西

临时文件、`.venv` 文件夹、密钥文件 (level09) 不放进档案柜。在项目根目录的 `.gitignore` 文件里写上排除清单，Git 就会当那些文件不存在。

如果你的电脑装了 git，这个脚本会**在临时文件夹里建一个真正的仓库、自动实战整个流程**。(没装 git 的话，会用概念模拟展示同样的流程，并给出安装指引。)

- **[3] 修改与 diff**: 改价后用 `git diff` 确认"哪里变了"，做第二次提交。
- **[4] 查历史**: 用 `git log` 查看章一个个摞起来的审批历史。
- **[5] 分支实验**: 在 `experiment` 分支 (平行宇宙) 里大胆改价，切回 main 后**看到文件内容恢复原样** — 时间旅行的实感时刻。

## 6. 常见错误

- **不 add 就 commit**: 审批夹是空的，就没有可盖章的文件。出现 "nothing to commit" 时先用 `git status` 查审批夹状态。
- **不带提交信息就提交**: 漏掉 `-m "信息"` 会弹出一个陌生的编辑器界面让人手足无措 (逃生口令: `:q!` 加回车)。养成永远带 `-m` 的习惯。
- **不管三七二十一 `git add .`**: 这是把密钥、超大文件也塞进档案柜的事故捷径。add 之前用 `git status` 看看要上去的是什么。
- **删除或移动 `.git` 文件夹**: 这个文件夹就是档案柜本身。删了它，全部历史就没了。
