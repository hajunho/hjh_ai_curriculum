# Lecture 01 · Level 05 — 代码编辑器与 Jupyter

> 分清"写代码的工具"编辑器 (VS Code) 和"做实验的工具"Jupyter 笔记本各自的用途，并通过模拟器体验笔记本的单元格执行方式。

**难度** ⭐⭐ / **先修** level04 / **预计时间** 35分钟

## 1. 为什么要学 — 从业务视角出发

代码用记事本也能写。但实际工作中没有人这么干，因为好工具能提前拦住失误，还能把工作速度提高好几倍。就像做年度结算时没人放着 Excel 不用、非要用计算器加纸笔一样。

Python 的作业工具大体分两路: 制作程序 (脚本) 的**代码编辑器**，以及把数据翻来覆去把玩、做探索的 **Jupyter 笔记本 (notebook)**。数据分析师的屏幕上几乎永远开着笔记本，开发者的屏幕上则是编辑器。分得清两者的用途，你就能自己判断"这个活该用哪个工具"，收到合作方发来的 `.ipynb` 文件时也不会发懵。尤其是笔记本的"单元格执行顺序"概念，是新手摔得最多的地方，这一关我们提前把原理练熟。

## 2. 用比喻来理解

**编辑器是写正式报告的工具，笔记本是实验记录本**。

- **VS Code 这类编辑器**就像用文字处理软件写正式报告。做出一份完整文档 (整个脚本)、提交审批 (运行) 的方式。拼写检查 (语法错误提示)、目录导航 (函数跳转)、自动补全都很强大。产出物是从头到尾按顺序执行的 `.py` 文件。
- **Jupyter 笔记本**是实验室的实验记录本。"加这种试剂会怎样? → 记录结果 → 那升温呢? → 记录结果" — **执行一步、亲眼确认结果、再决定下一步**的方式。代码片段 (单元格, cell)、它的运行结果和说明文字混排在同一份文档里。

有一个重要差别: 实验记录本的**页码顺序和实验顺序可以不一致**。你可以先做第 3 页的实验，再翻回第 1 页重做。笔记本也一样，单元格可以按任意顺序执行，而所有单元格**共享同一张工作台 (内核, kernel) 的记忆**。于是，如果画面上靠上的单元格其实比下面的"更晚"执行，那么把文档从上往下读的人看到的结果就会很奇怪。笔记本事故的 90% 都是这个。

## 3. 核心概念

### 3-1. 工具选择标准

| 场景 | 合适的工具 | 理由 |
|---|---|---|
| 刚拿到数据做探索 | 笔记本 | 一步步看结果、定方向 |
| 边看图边分析、写报告初稿 | 笔记本 | 代码+结果+说明在同一份文档里 |
| 每周要跑的自动化脚本 | 编辑器 (.py) | 从头到尾按顺序执行，保证可重跑 |
| 开发由多个文件组成的程序 | 编辑器 | 文件间跳转、搜索、调试 |
| 分享给团队的最终代码 | 编辑器 (.py) | 执行顺序永远一致，值得信赖 |

实际工作的常见流程是"在笔记本里做实验 → 方法定下来后整理成 `.py` 脚本"。

### 3-2. VS Code 首次配置三件事

VS Code (Visual Studio Code) 免费，而且是事实上的行业标准编辑器。装好后只要做三件事。

1. **安装 Python 扩展 (extension)** — 在左侧扩展菜单里搜索 "Python" 安装。语法检查和运行按钮就有了。
2. **选择解释器** — 打开命令面板 (Cmd/Ctrl+Shift+P)，运行 "Python: Select Interpreter"，指定**项目的 `.venv`**。这是把 level04 学的"用哪只工具箱"告诉编辑器的步骤。
3. **按文件夹打开** — 不要只开一个文件，而是打开整个项目文件夹 (File > Open Folder)，相对路径和搜索才能正常工作。

### 3-3. 笔记本的结构: 单元格 + 内核

- **单元格 (cell)**: 装几行代码的盒子。Shift+Enter 只执行这一格。单元格左边的 `[3]` 这类编号是"在这个内核里第 3 个被执行"的**执行序号**。
- **内核 (kernel)**: 在幕后一直活着的 Python 进程。所有单元格共享它这一份记忆 (变量们)。这一格里创建的变量，别的格里照样能看到。
- **重启 (restart)**: 重启内核，记忆全部清零。"从头全部重跑 (Restart & Run All)"是检验可复现性的标准流程。

`.ipynb` 文件是把单元格及其输出存起来的 JSON 文档。在 VS Code 里能打开，用 `jupyter lab` 命令也能在浏览器里打开 (两者都用 pip 安装: `pip install jupyterlab`)。

### 3-4. 乱序事故 (out-of-order) 的真面目

假设在单元格 A 里执行了 `price = 1000`，在单元格 B 里执行了 `price * 2`。之后就算把单元格 A 删掉，单元格 B 依然能跑 — 因为内核的记忆里还留着 `price`。可拿到这份笔记本的同事从上往下执行时，就会撞上"没有 price"的报错。**画面上的代码和内核的记忆可能对不上** — 记住这一点，笔记本事故你就理解了一大半。

## 4. 实战 — main.py

```bash
python3 main.py
```

为了不装 Jupyter 也能体验笔记本的工作原理，我们做了一个**迷你笔记本模拟器**。

- **[1] 笔记本构成**: 定义销售分析场景的 4 个单元格 (准备数据 → 合计 → 平均 → 汇报)。
- **[2] 按顺序执行**: 像 Run All 一样从上往下跑，逐格展示执行序号 `[n]`、输出，以及**内核记忆 (变量列表) 随单元格一路累积的样子**。
- **[3] 重现乱序事故**: 重启内核后从第 3 格开始执行，故意触发"不跑上面的格子就 NameError"; 接着按与画面不同的顺序执行，看结果怎么错位。
- **[4] 总结教训**: 用输出说明为什么 Restart & Run All 是标准流程。

核心代码是 `NotebookKernel` 类。一个叫 `self.memory` 的字典就是内核的记忆，`run_cell()` 用 Python 内置的 `exec()` 在这份记忆之上执行单元格代码。这是把真实 Jupyter 内核的原理浓缩成一个字典的模型。

## 6. 常见错误

- **单元格执行得乱七八糟就保存、分享**: 收件人无法复现。分享前务必用 "Restart & Run All" 确认从头到尾能干净地跑完。
- **编辑器没指定解释器**: 终端里能跑、只有 VS Code 里报 import 错误的话，八九不离十是解释器没选 `.venv`。
- **什么活都用笔记本干**: 笔记本是实验用的。连每天要跑的自动化也放在笔记本里，执行顺序和版本管理都会变得困难。定下来的逻辑请搬到 `.py`。
- **内核死了却怪代码**: 没有输出时先看内核状态 (要不要重启)。记忆没了的内核，得从上面的格子重新执行。
