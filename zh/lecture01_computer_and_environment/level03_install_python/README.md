# Lecture 01 · Level 03 — 安装 Python 与第一次运行

> 确认自己电脑上的 Python，理解交互式 (REPL) 运行和脚本运行的区别，并用一个自检脚本给环境做体检。

**难度** ⭐ / **先修** level02 / **预计时间** 35分钟

## 1. 为什么要学 — 从业务视角出发

Python 是整个课程体系的通用语言。数据分析、自动化、AI — 我们要学的一切都跑在 Python 之上。Python 之所以成为全球办公自动化和 AI 的标准语言，理由很简单: 语法接近英语句子、容易上手，而且全世界的人做好的现成工具 (包) 数量压倒性地多。

可是出乎意料的是，很多初学者第一节课就不是倒在代码上，而是倒在**安装和运行**上。"敲了 python 说找不到"、"明明装了却跑起来是另一个版本"、"公司电脑上装了两个，分不清哪个是哪个" — 全都是家常便饭。这一关就是跨过这道门槛的时间。只要能自己诊断出电脑上装了哪个 Python、装在哪、是什么版本，以后再遇到环境问题也不会慌。

## 2. 用比喻来理解

安装 Python 相当于**给公司聘一位能干的翻译官**。我们写的 Python 代码是人类读起来舒服的语言，而计算机只听得懂 0 和 1 (机器语言)。名为 Python 解释器 (interpreter) 的翻译官，把我们的指令一行行翻译成机器语言。

给翻译官派活有两种方式。

- **交互式 (REPL)** — 和翻译官面对面坐着，**一句一句即时对话**。在终端里只敲 `python3`，就会出现 `>>>` 提示符; 敲 `2 + 3`，立刻回答 `5`。像用计算器一样做轻量实验时很合适。REPL 是 Read (读)-Eval (算)-Print (答)-Loop (循环) 的缩写。
- **脚本 (script) 运行** — 把指示**整理成文件、整份递交**。把指令写进 `main.py` 这样的文件里，用 `python3 main.py` 递过去，它就从上到下全部执行。因为可以保存、重跑、共享，实际工作大多用这种方式。

即时对话 (REPL) 用来试想法，书面指示 (脚本) 用来干正事 — 记住这个区分就够了。

## 3. 核心概念

### 3-1. 先确认，再安装

在重新安装之前，先确认是不是已经有了。在终端里:

```bash
python3 --version    # 例: Python 3.12.9
which python3        # macOS/Linux: 可执行文件的位置 (Windows 用 where python)
```

版本在 3.10 以上就足够完成本课程。如果没有，可以从 python.org 官网下载安装包; macOS 也可以用 Homebrew (`brew install python`); Windows 用官方安装包时，要点是别忘了勾选 **"Add Python to PATH"**。

### 3-2. Python 2 和 3，以及一台电脑上的多个 Python

由于历史原因，命令存在 `python` 和 `python3` 两种。老的 Python 2 早已停止支持，所以**我们永远以 `python3`** 为准。另外，一台电脑上装着好几个 Python 是常见且正常的 (操作系统内置的、自己装的等等)。关键在于"我现在这条命令运行的到底是**哪个** Python"，答案就是 `which python3` 和 `sys.executable`。让多个 Python 共存又不打架的正式解法，就是下一关的虚拟环境。

### 3-3. PATH — 计算机查找命令的顺序

在终端敲 `python3` 时，Shell 会按顺序翻一份**叫 PATH 的文件夹清单**，寻找叫这个名字的程序。用公司打比方，就是"找翻译官时按顺序走访的部门名单"。"command not found" 意味着这份名单里哪儿都没有; 如果跑起来的是不对的版本，说明名单靠前的位置有另一个 Python。PATH 是环境变量的一种，level09 会更详细地讲。

### 3-4. 脚本运行的惯例

- Python 文件的扩展名是 `.py`。
- 文件顶部用三个双引号 (`"""..."""`) 包起来的段落是**文档字符串 (docstring)** — 说明这个文件是干什么的文档。
- `if __name__ == "__main__":` 是"只有这个文件被直接运行时才执行下面的内容"的惯用写法。现在只需理解为"正文从这里开始的标记"即可，原理在讲模块的课程 (lecture02) 里展开。

## 4. 实战 — main.py

```bash
python3 main.py
```

这个脚本会打印一份**我的 Python 环境体检表**。

- **[1] 核对翻译官身份**: Python 版本、可执行文件的真实位置 (`sys.executable`)，并判定版本是否在 3.10 以上。
- **[2] 确认工作地点**: 显示操作系统种类 (macOS/Windows/Linux)、处理器类型、当前工作目录。
- **[3] 扫一眼 PATH**: 打印 Shell 查找命令的文件夹清单的前几项，验证"查找命令的顺序"确实存在。
- **[4] REPL vs 脚本**: 展示同一个计算在 REPL 里会怎么敲，并与"此刻正以脚本方式运行"作对比。
- **[5] 综合判定**: 用通过/注意标记逐项整理出诊断摘要。

核心代码是使用 `sys` 和 `platform` 模块的部分。用 `sys.version_info` 把版本当数字比较，用 `sys.executable` 拿到"正在运行这段代码的 Python"的准确位置。这两行是以后每次遇到环境问题都会掏出来用的万能诊断工具，请务必记住。

## 5. 动手试试

1. **(简单)** 在终端敲 `python3` 进入 REPL，算一算 `3 * 7`、`"你好" * 3`，再用 `exit()` 退出来。*(提示: 看到 `>>>` 就成功了。Ctrl+D 也能退出。)*
2. **(普通)** 把 main.py 第 [1] 步的要求版本从 (3, 10) 改成 (3, 99) 再运行。确认判定变成"注意"后改回原样。*(提示: 找 `REQUIRED` 变量。这是验证诊断逻辑真的在工作的实验。)*
3. **(挑战)** 给第 [2] 步额外输出"Python 装在多少位的环境里"。*(提示: 查一下 `platform.architecture()`。)*

## 6. 常见错误

- **`python` 和 `python3` 混着用**: 在 macOS 上 `python` 可能不存在或是另一个版本。请统一用 `python3` (在虚拟环境里 `python` 也会变得安全 — 下一关见!)。
- **装完不重开终端**: PATH 的变更常常要从新终端窗口才生效。装完发现命令不灵，先试试新开一个终端。
- **在 REPL 里敲运行文件的命令**: 在 `>>>` 状态下敲 `python3 main.py` 会报错。运行文件要先退出 REPL、回到 Shell 里做。看提示符分清自己是在 Shell (`$`) 还是 REPL (`>>>`)。
- **不读报错信息就直接重装**: "command not found" 和 "SyntaxError" 的原因完全不同。只读报错的第一行和最后一行，方向就出来了。
