# Lecture 01 · Level 08 — 用 Shell 脚本自动化重复工作

> 学会把每周手工做的文件整理、批量改名交给一个脚本一次搞定的自动化思维方式，并用 Python 实战文件批量整理。

**难度** ⭐⭐⭐ / **先修** level02 / **预计时间** 45分钟

## 1. 为什么要学 — 从业务视角出发

想象这样一项工作: 每周一，从共享文件夹里下载堆积的几十个各门店销售文件，把文件名改成统一规则，按月份分类到文件夹里，再把过期文件挪进存档区。一次 20 分钟，一年就是 17 个小时。而且人会出错 — 把某个文件放错文件夹，或者把名字里的日期敲错。

自动化的盈亏计算很简单: **"重复次数 × 节省时间 > 编写自动化的时间"就稳赚**，附赠的是失误归零。这一关的第一场实战就是"文件批量整理"。文件整理是办公室重复劳动的最大公约数，这里练熟的模式 (取得清单 → 应用规则 → 批量执行 → 汇报结果) 以后在数据预处理、报表生成、邮件群发等一切自动化里都能原样复用。

## 2. 用比喻来理解

**脚本是写给新人的工作手册**。

能干的前辈不会只用嘴给新人派活，而是写一份手册: "1) 打开收件文件夹 2) 在文件名前加日期 3) 放进各门店的文件夹 4) 汇报完成清单。"手册写得好，谁来做、做多少遍，结果都一样。

脚本 (script) 就是这份手册。只不过执行者不是新人而是计算机，所以 (1) 指示稍有含糊它就会停下或干出离谱的事; (2) 作为回报，只要写准一次，让它做一万遍也毫无怨言、毫无差错。

写手册的语言有两种。**Shell 脚本 (.sh)** 是把 level02 学的终端命令 (cp、mv 等) 按顺序写进文件 — "用终端语言写的手册"。**Python 脚本 (.py)** 是用 Python 写同样的事。简单的命令罗列用 Shell 更简洁; 一旦掺进条件、异常、数据加工，Python 就有压倒性优势。本课程的标准是"两三行用 Shell，再多就用 Python"。

## 3. 核心概念

### 3-1. Shell 脚本最小语法

```bash
#!/bin/bash                      # 第 1 行: 这份手册的执行者是 bash
mkdir -p archive                 # 按顺序写命令
mv report_*.csv archive/         # * 通配符: 匹配模式的所有文件
echo "整理完成: $(date)"         # 汇报进度
```

用 `bash cleanup.sh` 运行。`*` (任意字符串)、`?` (单个字符) 这类**通配符 (wildcard)** 能一把抓住"匹配模式的全部"，这是批量处理的核心。

### 3-2. 自动化脚本的四步模式

任何自动化的骨架都一样。

1. **收集**: 取得目标清单 — `Path.glob("*.csv")`
2. **判断**: 给每个目标应用规则 — 解析文件名、决定分类
3. **执行**: 移动/修改/创建 — `rename`、`mkdir`
4. **汇报**: 记录做了什么 — 输出日志、汇总表

其中最重要的习惯是**空跑 (dry run)** — 锁住第 3 步的执行，只打印"打算做什么"的彩排。与其错搬了 500 个文件再后悔，不如搬之前先用眼睛检查计划表，这才是专业做法。

### 3-3. 用 Python 操作文件的核心工具

| 工具 | 做的事 |
|---|---|
| `Path.glob("*.csv")` / `rglob` | 按模式收集文件清单 (含子文件夹用 rglob) |
| `path.rename(新路径)` | 移动兼改名 (Shell 的 mv) |
| `shutil.copy2(源, 目标)` | 复制 (Shell 的 cp，保留修改时间) |
| `path.mkdir(parents=True, exist_ok=True)` | 创建文件夹 (Shell 的 mkdir -p) |
| `re.match(模式, 名字)` | 用正则表达式解析文件名 |

**正则表达式 (regular expression)** 是一门"字符模式检索语言"。例如 `r"(\d{4})-(\d{2})"` 表示"4 位数字-2 位数字" (年-月)。从文件名里抽取日期、门店名这类信息时非常强大，现在知道"有这么个工具"就够了。

### 3-4. 安全装置设计

自动化有多快，闯祸就有多快。至少要有三道安全装置: **(1) 把空跑模式设为默认**，**(2) 用移动代替删除** (先挪进 quarantine 隔离文件夹)，**(3) 留执行日志** (什么时候把什么搬到了哪)。守住这三条，自动化事故的大头就防住了。

## 4. 实战 — main.py

```bash
python3 main.py
```

在临时文件夹里复现一个**乱成一团的共享文件夹**，展示自动整理脚本收拾它的全过程。

- **[1] 制造烂摊子**: 用固定 seed 的随机数生成 `销售报告_朝阳_2024-03.csv`、`sales_pudong_2024-04.csv`、`备忘录.txt`、`演示文稿.pptx` 等命名规则五花八门的 14 个文件。
- **[2] 收集与判断**: 用正则表达式从文件名解析出年月和门店，为每个文件制定"该送去哪"的分类计划。解析不了的文件去 `_待核查` 文件夹。
- **[3] 空跑**: 执行前只打印移动计划表 — "打算做什么"的彩排。
- **[4] 真正执行**: 按计划建文件夹、批量移动并统一文件名 (`门店_年-月.csv` 格式)。
- **[5] 汇报结果**: 展示整理后的文件夹树和处理摘要 (整理 n 件、需核查 n 件)，并对比手工做要花多长时间。

核心代码是把 `plan_moves()` 和 `execute_moves()` 分开。**把制定计划和执行拆成两个函数**，空跑就白送了，测试也更容易。这个结构是实际工作中自动化的标准设计。

## 6. 常见错误

- **不空跑就批量执行**: 几百个文件搬错之后，回滚要费好几倍的劲。守住"打印计划表 → 眼睛检查 → 执行"的顺序。
- **覆盖同名文件**: 移动目的地有同名文件时会被悄悄覆盖、数据消失。移动前需要检查存在性 (`exists()`) 或给名字加编号。
- **在自动化脚本里硬编码绝对路径**: 写死 `/Users/我的名字/...` 的脚本到同事电脑上当场暴毙。目标文件夹要做成参数或配置传入。
- **给一次性代码过度投资**: 不会重复的事直接手工做更快。先算自动化的盈亏账。
