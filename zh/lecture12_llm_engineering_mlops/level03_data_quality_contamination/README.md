# Lecture 12 · Level 03 — 数据质量、去重与污染检查

> 垃圾进，垃圾出 —— 用 n-gram 亲手揪出训练数据里的重复文档和"考题泄露(污染)"。

**难度** ⭐⭐⭐⭐ / **先修** level02 / **预计时间** 50分钟

## 1. 为什么要学 — 业务视角

做大语言模型 (LLM) 的公司，投入人力和钱最多的地方出乎意料地不是模型代码，而是**数据清洗**。模型架构随论文公开，各家差别不大；但"放进去的是什么数据、洗得多干净"才是各家的商业机密，也是实力差距的真正来源。行业里那句老话 GIGO (Garbage In, Garbage Out) —— 垃圾进，垃圾出 —— 到了 LLM 时代反而更狠了。因为模型只会学数据里有的东西。

质量问题中对业务冲击最大的两件事，就是这一关的主题。第一是**重复 (duplication)**。从网上爬来的数据里，同一篇文章往往被复制了几百遍。反复学同一份文档，模型会把它整段背下来(死记)，失去学习多样表达的机会，还白烧训练成本 (GPU 小时 = 钱)。第二是**基准污染 (benchmark contamination)**。用来评测模型的考题混进了训练数据，模型拿分靠的就不是"实力"而是"背考试宝典"。相信一个被污染的基准分数就引入模型的公司，会在真实业务里被达不到预期的表现打个措手不及。如果你是负责评估模型引入的实务人员，就得有本事问出这一句: "这个分数做过污染检查吗？"

## 2. 打个比方

**去重就像整理新员工培训资料。** 想象培训资料文件夹里躺着 200 份内容一模一样、只有文件名不同的手册。新人把培训时间的绝大部分花在把同一份手册读 200 遍上。那份手册他能背得一字不差，可其他业务压根没学到。培训负责人该做什么很清楚 —— 同样的资料只留一份。

**基准污染就是考题泄露。** 某培训机构广告"我们的通过率 98%"，结果一查，教材里直接印着历年真题连答案。这个通过率能证明机构的教学水平吗？不能。因为学生(模型)不是理解了题目，而是背下了答案。在 LLM 世界里，把全网整片爬下来时，连贴着基准题目和答案的博客、论坛帖子一起卷进来，是真实会发生的事。所以认真的模型团队一定会做训练数据与评测题之间的**重叠检查 (overlap check)**。

可是几十亿份文档怎么互相比对？整篇按字比较又慢，还会漏掉"只改了一个字的近似复制品"。这里要用的工具叫**指纹 (fingerprint)**。就像人的指纹一样，把文档切碎成一堆小片 (n-gram) 的集合当作它的指纹，指纹重叠得多的两篇文档，内容基本上也就是一样的。

## 3. 核心概念

### 3-1. n-gram 与 shingle

n-gram 就是把文本切成长度为 n 的连续碎片。"今天会议"按字符 2-gram 切，得到"今天"、"天会"、"会议"。从一篇文档里抽出的 n-gram 集合叫 shingle 集合 (瓦片集合)。核心直觉是: **文档只改一点点，绝大多数 n-gram 还是原样留着。** 所以两篇文档的 n-gram 集合重叠得多，就是"几乎一样的文档"。

### 3-2. 杰卡德相似度 (Jaccard similarity)

两个集合 A、B 重叠多少，用杰卡德相似度来量。

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

交集 (两边都有的碎片) 大小除以并集 (两边至少一边有的碎片) 大小。完全相同是 1，毫无重叠是 0。实务上通常 0.7~0.8 以上就判为"近似重复 (near-duplicate)"，只留一份。

| 情况 | 杰卡德值 (大致) | 判定 |
|---|---|---|
| 完全复制品 | 1.0 | 重复 — 删除 |
| 只改了一两个词的复制品 | 0.7~0.95 | 近似重复 — 删除 |
| 同主题的另一篇文章 | 0.1~0.3 | 保留 |
| 不相干的文章 | 0.0~0.05 | 保留 |

### 3-3. 大规模场景下用 MinHash — 只讲概念

文档上了几十亿，所有配对 (几十亿 × 几十亿) 是比不完的。真实流水线用一种叫 **MinHash/LSH** 的技术，先把"杰卡德值可能很高的配对"筛成候选再精比。做法是把 shingle 集合压缩成几个哈希数字当摘要，只对摘要相近的文档做精细比较。这一关文档才几十份，所以老老实实比了所有配对，但原理 (shingle + 杰卡德) 和大规模方案完全一致。

### 3-4. 污染检查 — 考题在教材里吗

污染检查的方向是反的。去重找的是"训练数据内部"的重叠，污染检查找的是"评测题与训练数据之间"的重叠。方法很朴素 —— 把基准题目切成 n-gram，数一数这些碎片在训练语料里出现了多少。题目的 n-gram 中有相当比例 (例如 30% 以上) 原样躺在语料里，就打上"疑似泄露"的旗标。确认污染后有两种应对: 还没开始训练，就把那份文档从数据里剔除 (去污染 / decontamination)；已经训练完了，就把被污染的题目从评测中排除，单独汇报一个"干净分数"。

### 3-5. 污染抬高分数的机制

模型是能把训练数据里的句子整段背下来的。泄露的题目对它来说是"见过的句子"，把答案照着续写下去就行，正确率于是异常地高。这一关我们用一个"只会答背过的题的假想模型"来模拟这个效果 —— 亲眼看看含泄露题的分数和剔除后的分数能差出多少。

## 4. 动手练习 — main.py

运行方式:

```bash
cd lecture12_llm_engineering_mlops/level03_data_quality_contamination
python3 main.py
```

输出分五步。

- **[1] 构建语料** —— 用 `hjh_data.tiny_corpus()` 的句子造 24 份文档，并故意埋进 1 份"完全复制品"、1 份"只改一个词的近似复制品"，以及 1 份整段混入基准题目的"泄露文档"。
- **[2] 重复检测** —— 计算所有文档配对的杰卡德相似度，报告超过阈值 (0.7) 的配对。本次运行精准抓到了埋下的两份: 文档 2 ↔ 15 相似度 **1.000** (完全重复)，文档 5 ↔ 19 相似度 **0.765** (近似重复)。请留意近似重复那一对 —— 整份文档里只把"做好了"换成了"完成了"这一处，杰卡德就从 1.0 掉到 0.765。中文没有空格，一个字的改动会同时破坏 5 个字符 5-gram，所以掉幅比空格分词的语言更明显。
- **[3] 去重** —— 从抓到的配对里丢掉后出现的那份: 24 份 → **22 份** (丢弃 15、19)。
- **[4] 污染检查** —— 对 6 道基准题各算一遍"题目 n-gram 出现在语料中的比例"。只有第 3 题 (三角形内角和) 命中 **100.0%** 被标为"★疑似泄露"，其余 5 题都是 0.0%。10-gram 这么长，除了整段照搬几乎不可能凑巧命中 —— 这就是把 n 调大换来的精确度。
- **[5] 分数吹胀演示** —— 用只会答背过题的假想模型对比含污染/剔除后的基准分数。本次运行: 含污染 **33.3%** (2/6 —— 泄露的第 3 题自动答对，第 5 题瞎猜蒙对)，干净分数 **20.0%** (1/5)。一道泄露的题就把分数抬高了 13 个百分点。

代码的核心是三个函数。`char_ngrams(text, n)` 从字符串造出字符 n-gram 集合，`jaccard(a, b)` 算两个集合的杰卡德相似度，`contamination_ratio(question, corpus_grams, n)` 求题目 n-gram 被语料 n-gram 集合包含的比例。三个函数加起来不到 10 行 —— 大规模流水线的骨架也就站在这么朴素的原理上。

## 5. 自己动手试试

1. **阈值实验** —— 把 `DUP_THRESHOLD` 从 0.7 降到 0.3 再运行。不是重复的文档也开始被抓了吗？(提示: 这些文档是用同一批词料造出来的，阈值一低，"同主题的另一篇文章"也会中枪。阈值就是精确率与召回率之间的取舍。)
2. **n 大小实验** —— 把 `char_ngrams` 的 n 从 5 减到 2，杰卡德值整体会怎么变？反过来加到 12 呢？(提示: n 越小，常见碎片越多，所有配对的相似度都会升高；n 越大，就只抓得住精确照搬。中文一个字就承载很多信息，n=2 时"把报"这类碎片满地都是，误报会比英文更凶。)
3. **造一个更刁钻的泄露** —— 把塞进泄露文档的基准题目换个语序、或者把"是多少度"改成"等于几度"，看看现在的检查器会不会漏掉。漏了的话怎么补？(提示: 可以把 n 调小、比较前先去掉空格和标点，或者并用词级 n-gram。真实团队也被"改写过的污染"折腾得头疼。)

## 6. 常见误区

- **等训练完了才想起去重** —— 重复必须在训练前清掉。模型一旦背下来，想把死记的部分抽出来实际上没有办法。
- **只检查完全一致** —— 靠哈希比对，只差一个字就漏。想抓住近似重复，必须走 n-gram + 相似度这条路。
- **无条件相信基准分数** —— 养成习惯: 汇报材料上的分数做过污染检查吗？有没有单独汇报干净分数？
- **n-gram 的 n 随手一定** —— 太小就误报 (常见表达全中枪)，太大就漏报 (稍微改过的复制品抓不到)。得按数据特性用实验定。中文没有空格、字符信息密度高，合适的 n 通常比英文小一些。
- **把"重复"一概当成坏事** —— 高质量数据有时是故意多学几遍 (多 epoch) 的。真正的问题是"非预期、不受控"的重复。
