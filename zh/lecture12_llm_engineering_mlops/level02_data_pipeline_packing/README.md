# Lecture 12 · Level 02 — 训练数据流水线与打包 (Packing)

> 把文档用 `<s>...</s>` 首尾相接、按固定长度切块，再配上 uint16 二进制分片和 memmap，把"让数万亿 token 川流不息的传送带"做成微缩版。

**难度** ⭐⭐⭐ / **先修** level01 / **预计时间** 50分钟

## 1. 为什么要学 — 业务视角

LLM 预训练时，GPU 是挂着"每小时几十到几百块钱"计价器在转的。这台昂贵的机器凡是停下来等数据的每一秒，都是在烧钱。所以大规模训练的功力高下，往往不在模型代码，而在**能不能不间断、不浪费地喂数据的流水线**。

从业务角度看，这一关回答三个问题。第一，"训练数据为什么不存成文本文件，而是奇怪的二进制？" —— 因为每次都重新分词会让 CPU 变成瓶颈，所以把分词结果存成机器可以直接下咽的格式。第二，"几百 GB 的数据怎么装进内存？" —— 不装。用一种叫 memmap 的技巧，用到哪块读哪块。第三，"文档长短不一，GPU 为什么总能被塞满？" —— 靠打包 (packing)。这三件事会原封不动地出现在 AI 基础设施的报价单和瓶颈讨论里。

## 2. 打个比方

想象一家灌香肠的作坊。订单 (文档) 长短不一: 有客人只要两小节，有客人要十整根。

**笨办法**: 每张订单配一个固定大小的包装盒 (固定长度批次)，空出来的地方塞泡沫填充物 (`<pad>` token)。两小节香肠配一个大盒子，盒里几乎全是泡沫 —— GPU 的大部分算力就浪费在毫无意义的 padding 计算上。

**打包法**: 把所有订单在灌肠机上连续灌成一条超长香肠 (token 流)，订单与订单之间拧一个结 (`<s>`、`</s>` token) 标记边界，然后按盒子长度 (block_size) 咔咔切段装盒。有的盒子会跨两张订单，但有结在，吃的人 (模型) 就知道"从这里起是新订单"。盒子里没有一点空隙。

存储用的是大缸腌菜式 (二进制分片): 与其做几百万个独立小包装 (每篇文档一个文件)，不如分装进几千口大缸 —— 开冰箱门的次数 (打开文件的开销) 骤减，物流就快了。

## 3. 核心概念

### 3-1. 打包 (packing): `<s> 文档1 </s> <s> 文档2 </s> ...`

把所有文档分词后用特殊 token 包裹，接成一条长流，再按 block_size (实战里是 64，真实模型是 4096~128k) 切成训练样本。好处有二: (1) padding 为零，GPU 的算力全部花在真正的学习上；(2) 样本长度统一，组批次变得简单。代价是同一个样本里会混进不同文档的尾巴和脑袋，但 `<s>` token 就是"新文档开始"的信号，模型会顺带学会在这里切断上下文。

### 3-2. uint16 分片 (shard)

token id 是整数。只要 vocab 小于 65,536，一个 id 就能用 2 字节 (uint16) 存。每 token 固定 2 字节，文件大小一口气就能算出来 (1 亿 token = 200MB)，而且不需要解析、直接整块读成数字数组。把全部数据拆成几百到几千个分片文件，多张 GPU 就能并行读不同的分片；哪个分片坏了，只需重做那一个。

### 3-3. memmap — "不打开就打开"的技术

`np.memmap` 不把文件复制进 RAM，只是向操作系统登记"就当这个文件已经在内存里了"。真正的读取发生在你碰到数组某一段的瞬间，只有那一段才从磁盘上来。所以 200GB 的分片打开也近乎 0 秒，取批次时只有需要的几 KB 产生 I/O。lecture03 学过的 numpy 切片语法在这里原样适用，也是它讨人喜欢的地方。

### 3-4. 批次 (x, y) — 答案就是右移一格

语言模型的标准答案是"下一个 token"，所以输入 x 若是流的 `[i : i+64]`，答案 y 就是 `[i+1 : i+65]`。不需要单独的标签文件。数据本身既是考卷又是答案 —— 这就是预训练数据"只要是文本就行"的原因。

2. **(中等)** 参考 `[7]`，加几行代码统计整个批次 8 行里 `<s>` token 的总数。看看 block_size 越大，含边界的概率怎么变。(提示: 一行 `(x == stoi[BOS]).sum()` 就够。)
3. **(挑战)** 把流拆成两个分片 (`shard_000.bin`、`shard_001.bin`) 分别保存，并把取批次的代码改成随机挑一个分片再取。(提示: 把流数组一分为二各自 `tofile`，在 `get_batch` 之前用 `rng.integers(0, 2)` 挑分片。这就是多 GPU 数据加载器的骨架。)

## 6. 常见误区

- **不加 `<s>` 就打包**: 没有边界标记，上一篇文档的结尾就成了预测下一篇开头的"假信号"，模型会把混乱学进去。别忘了拧那个结。
- **超出 uint16 范围**: vocab 超过 65,536 还用 uint16 存，token id 会被悄悄截断变成错误数据。存之前养成检查 `vocab_size < 65536` 的习惯。(真实大模型 vocab 常超 10 万，会改用 uint32。)
- **把 memmap 整个复制**: `np.array(mm)` 这种整体转换会让 memmap 的优势归零、RAM 爆掉。永远用切片只取需要的区间。
- **分词器版本不一致**: 用与制作分片时不同版本的分词器去解码，整批数据就废了。分片旁边务必同时保存 vocab 文件和版本信息。
