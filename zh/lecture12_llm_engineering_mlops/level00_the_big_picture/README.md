# Lecture 12 · Level 00 — 造一个模型意味着什么 — 全景地图

> ChatGPT 这样的模型像工厂出产品一样要走过哪些生产线？这一关帮你把各阶段的输入、产出、成本一眼看清。

**难度** ⭐ / **先修** 无 (建议先学 lecture11) / **预计时间** 30分钟

## 1. 为什么要学 — 业务视角

在之前的课程里，你学的是怎么"用"LLM (大语言模型)。从这门课开始视角反转：我们把模型"被造出来"的过程做成微缩版亲手复现。为什么非科班的职场人也要懂到这一步？

第一，为了做决策。当有人提议"我们做一个自己公司专用的模型"时，如果分不清这句话指的是几亿元级的预训练，还是几千块钱级的微调，预算和排期都无从谈起。实际上，企业口中的"自研 LLM"绝大多数只是在公开模型上叠加了后面几道工序而已。

第二，为了协作。当 AI 团队说"现在在跑 SFT，下周进 DPO"时，如果你知道这对应工厂流水线的哪道工序、产出的是什么，对话的质量会完全不同。

第三，为了就业市场。能把 LLM 工程哪怕在"地图"层面讲清楚的非开发岗位，如今依然稀缺。这一关就是帮你把这张地图画出来。

## 2. 打个比方

LLM 的制造过程和汽车工厂惊人地相似。

- **预训练 (Pretraining)** 是炼钢厂。把铁矿石 (来自互联网的数万亿 token 原始文本) 投进高炉熔炼几个月，炼出钢材 (语言的基本功)。整个成本的绝大部分都花在这里，而且一旦炼砸就得从头再来。
- **退火 (Annealing)** 是热处理工序。训练收尾阶段只挑教科书级的高质量数据慢慢收官，同样的钢材会变得坚硬许多。
- **SFT (指令微调)** 是装配线。钢锭还不是汽车；只做完预训练的模型也只会"续写"，听不懂指令。要按手册 (指令-回答示例) 组装起来，才算有了产品的样子。
- **偏好对齐 (DPO)** 是质检 (QC) 线。在两个回答里挑出客户更喜欢的那个，打磨出厂品质。
- **量化 (Quantization)** 是包装工序。就像整车装进集装箱前要压缩体积，把 14GB 的模型压成 4GB 才好发货。
- **部署 (Serving)** 是物流中心。从这里开始，花的不再是"制造成本"，而是与订单量成正比的"运营费"。

请按顺序记住这六道工序。这门课的 level01~11 正是沿着这条流水线走的。

## 3. 核心概念

### 3-1. 两大阶段: 预训练 vs 后训练

- **预训练**: 用互联网规模的文本，只让模型做"猜下一个 token"。产出的 base 模型懂语言的统计结构，但完全没有"回答问题"这个概念。
- **后训练 (post-training)**: SFT 与偏好对齐的合称。数据量只有几万到几十万条，是预训练的万分之一，但用户体感的"听得懂人话"大多是在这里炼成的。

### 3-2. 成本直觉 — 6 × N × D 公式

训练所需的计算量 (FLOPs) 可以用 **6 × 参数量(N) × token 数(D)** 来近似。一个 7B (70 亿) 参数的模型用 2 万亿 token 训练，约 8.4×10²² FLOPs。除以一张 H200 级 GPU 的实效算力，得到数万 GPU 小时；换算成云服务账单大约是数亿韩元 (KRW) 的量级。而 SFT 用同一个公式算出来只有几个 GPU 小时、账单不过几万韩元。**每往后一道工序，成本就差着上万倍** —— 这个直觉是本关的核心。

### 3-3. 名叫"检查点"的半成品

每道工序的产出物是一个叫检查点 (checkpoint) 的文件。命名依次是 base → base-annealed → sft → chat (对齐完成) → int4 (量化)。你在 Hugging Face 等模型仓库看到的 `-base`、`-instruct`、`-int4` 后缀，正是标记这道工序位置的标签。

### 3-4. 为什么大多数公司从中间开工

因为预训练占总成本的 95% 以上，所以"领一个公开的 base 模型 (免费)，只做 SFT/DPO/量化"是业界的标准策略。这门课的实战也是同样的结构: level04 亲手造一次迷你 base 模型，之后的关卡全部是叠加在它之上的工序。

| 阶段 | 数据规模 | 成本量级 |
|---|---|---|
| 预训练 | 数万亿 token | 数亿~数千亿韩元 |
| 退火 | 数百亿 token | 数百万~数千万韩元 |
| SFT | 数万~数十万条 | 数万~数百万韩元 |
| DPO | 数万对 | 数万~数百万韩元 |
| 量化 | 无需训练 | 数千~数万韩元 |

## 4. 动手练习 — main.py

运行方式如下。

```bash
cd lecture12_llm_engineering_mlops/level00_the_big_picture
python3 main.py
```

程序模拟一个假想的 7B 模型走完工厂流水线 6 道工序的过程。`[1]`~`[6]` 每个阶段都会先展示**比喻、输入、产出**；如果是训练阶段，`train_cost()` 函数会用 6 × N × D 公式依次换算出 FLOPs → GPU 小时 → 美元并打印。程序还会模拟 loss 逐步下降的样子 (固定随机种子): 预训练阶段从 10.5 一路降到 2.4 附近，之后的阶段只小幅移动 —— 这正是真实训练日志的典型形状。

在最后的 `[7]` 汇总里，请确认制造总成本 (实测 $211,406，约 3.0 亿韩元) 中预训练占了 97.6%。代码里值得细看的有三处: 顶部的规格常量 (PARAMS、PRETRAIN_TOKENS 等) 是留给你拧的实验旋钮；`train_cost()` 是整门课都会反复用到的成本近似式；stages 列表本身就是这门课的目录。

## 5. 自己动手试试

1. **(简单)** 把 PARAMS 改成 70e9 (70B) 再运行。观察总成本变成几倍、预训练占比怎么变。(提示: 公式与 N 成正比，所以训练成本恰好是 10 倍。)
2. **(中等)** 把 GPU_PRICE 改成你熟悉的云厂商价格，再把 MFU (实效效率) 从 0.4 降到 0.25。同一个模型，报价能差出多少？(提示: MFU 就是 GPU_FLOPS 常量里的 0.40。工程报价每家公司都不一样，原因就在这两个变量。)
3. **(挑战)** 在 stages 列表的部署之前加一道"安全评估 (Red-teaming)"工序。亲手编写它的输入、产出、比喻，流水线的结构就会长在你手上。(提示: 参考 tokens=None 的阶段，就能轻松加入不训练的工序。)

## 6. 常见误区

- **把"微调"当成"造模型"**: 看到新闻里"自研模型"的说法时，先问一句"从哪道工序开始做的"。大多数只做了 SFT 之后的部分。
- **谈成本不分阶段**: "训练 LLM 要几个亿"只对预训练成立。后面的工序用笔记本级预算就能做。
- **把量化误当成一种训练**: 量化只是把做好的模型换一种数字表示的转换作业。它不学任何新东西，所以几个小时就能完成。
- **把部署当成"大功告成"**: 从部署那一刻起，成本结构就从固定成本变成随用量增长的运营费。一份报价单里如果没有服务 (serving) 成本这一行，那它就是不完整的。
