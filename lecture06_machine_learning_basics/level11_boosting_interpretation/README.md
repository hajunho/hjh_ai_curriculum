# Lecture 06 · Level 11 — 그래디언트 부스팅과 모델 해석

> 오답노트를 반복 학습하는 부스팅으로 성능을 끌어올리고, 순열 중요도와 개별 예측 설명으로 "왜?"라는 질문에 답하는 법을 배웁니다.
**난이도** ⭐⭐⭐⭐⭐ / **선행** level07, level08 / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

표 데이터 예측의 실전 최강자를 하나만 꼽으라면 그래디언트 부스팅(gradient boosting)입니다. 데이터 분석 대회 상위권과 기업의 이탈·연체·수요 예측 시스템 상당수가 부스팅 계열입니다. sklearn의 `HistGradientBoostingClassifier` 하나로 그 세계의 표준 기법을 쓸 수 있습니다.

하지만 강한 모델일수록 새 문제가 생깁니다. **"모델님이 이 고객을 위험하다는데, 왜죠?"** 상담원은 근거 없이 전화를 걸 수 없고, 심사역은 근거 없이 승인을 거절할 수 없으며, 규제기관은 설명을 요구합니다. 그래서 이 마지막 레벨은 두 부분입니다 — 전반부는 부스팅으로 성능을 올리는 법, 후반부는 그 블랙박스를 다시 여는 법(순열 중요도, 부분의존, 개별 예측 설명). 성능과 설명을 함께 다룰 수 있어야 ML을 조직에 안착시킬 수 있습니다.

## 2. 비유로 이해하기

**오답노트 공부법**이 부스팅의 전부입니다. 랜덤포레스트(level08)가 "학생 300명이 각자 공부해 투표"라면, 부스팅은 **한 명의 학생이 오답노트를 만들며 성장하는 직렬 과정**입니다.

1교시: 첫 문제집을 풀어 봅니다. 성적은 평범합니다. 2교시: **틀린 문제만 모은 오답노트**를 만들어 그 부분을 집중 공부합니다. 3교시: 그래도 남은 오답으로 또 오답노트를 만들고… 이것을 수백 번 반복합니다. 각 교시의 공부(작은 트리 하나)는 얕고 약하지만, "직전까지의 실수를 교정하는" 방향으로 차곡차곡 쌓이므로 최종 실력은 매우 강해집니다.

단, 오답노트 공부의 함정도 그대로 물려받습니다. 문제집의 **오타(잡음)까지 외우기 시작하면** 과적합입니다. 그래서 부스팅에는 "한 교시에 반영하는 정도를 줄이는" 학습률(learning rate)과 조기 종료 같은 브레이크가 필수입니다 — level09의 철학이 그대로 돌아옵니다.

해석 도구도 비유로 잡아 둡시다. **순열 중요도(permutation importance)는 "그 과목 답안지를 뒤섞어 보기"**입니다. 어떤 특징의 값을 무작위로 섞어 모델에 넣었을 때 성적이 뚝 떨어지면 그 특징에 크게 의존했다는 뜻이고, 안 떨어지면 없어도 되는 특징이었다는 뜻입니다.

## 3. 핵심 개념

### 3.1 부스팅의 구조

예측 = 트리1 + η·트리2 + η·트리3 + … (η=학습률). 각 트리는 "지금까지의 예측이 남긴 오차"를 맞히도록 학습됩니다(회귀 관점의 잔차 교정 — 이름의 gradient가 이 오차 방향을 뜻합니다). 랜덤포레스트와의 대비가 핵심입니다.

| | 랜덤포레스트 | 그래디언트 부스팅 |
|---|---|---|
| 트리 관계 | 병렬·독립 (투표) | 직렬·의존 (오답 교정) |
| 개별 트리 | 깊고 강함 | 얕고 약함 (깊이 3~8) |
| 주 효과 | 분산(요동) 감소 | 편향(체계적 오차) 감소 |
| 과적합 위험 | 낮은 편 | **튜닝 안 하면 높음** |
| 주요 손잡이 | 트리 수 | 학습률 × 트리 수 × 깊이 |

`HistGradientBoosting`은 연속값을 히스토그램 구간으로 묶어 빠르게 처리하는 현대적 구현으로, 조기 종료(`early_stopping`)가 내장되어 검증 성적이 안 오르면 알아서 멈춥니다.

### 3.2 순열 중요도 — 더 공정한 중요도

level07~08의 불순도 중요도는 "훈련 중 많이 쓰인 정도"라 편향이 있었습니다. 순열 중요도는 **완성된 모델을 테스트 데이터로 심문**합니다: 특징 하나의 열만 무작위로 섞어(다른 열은 그대로) 성능 하락폭을 잽니다. 모델 종류와 무관하게 쓸 수 있고, "실제 예측력 기여"를 재므로 보고용으로 더 정직합니다. 주의점: 서로 상관 높은 특징들은 서로를 대신할 수 있어 둘 다 낮게 나올 수 있습니다.

### 3.3 부분의존 — 특징 하나의 영향 곡선

부분의존(partial dependence)은 "다른 조건을 그대로 둔 채 특징 하나만 값을 바꿔 가면 평균 예측이 어떻게 변하나"의 곡선입니다. "이용일수가 0→30으로 늘 때 이탈 확률이 어떤 모양으로 떨어지는가" — 계수 하나로 요약되던 로지스틱과 달리, 부스팅의 비선형 관계(예: 10일 아래에서 급증)를 드러냅니다. 인과가 아니라 **모델이 학습한 연관의 모양**임은 여전합니다.

### 3.4 개별 예측 설명 — "이 고객은 왜?"

전체 경향(중요도·부분의존)과 별개로, 특정 고객 한 명의 판정 근거가 필요할 때가 많습니다. 실무 표준은 기여도 분해(SHAP 계열) 도구지만, 원리는 오늘 직접 구현해 볼 수 있습니다: **"이 고객의 특징 하나를 평균적인 값으로 바꿔치기하면 예측이 얼마나 변하나"**를 특징마다 재는 것입니다. 변화폭이 큰 특징이 그 고객 판정의 주된 근거입니다. 이 개념만 있으면 전문 도구의 출력도 읽을 수 있습니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

churn_table로 부스팅 모델을 만들고 해석까지 완주합니다.

- **[1]** 데이터 준비, 훈련/테스트 분리.
- **[2]** 로지스틱(level05)·랜덤포레스트(level08)·`HistGradientBoostingClassifier` 세 모델의 테스트 AUC를 나란히 비교합니다 — 지금까지 배운 모델들의 졸업 시험입니다. 스포일러: 이 합성 데이터에서는 로지스틱이 이깁니다. 데이터의 진짜 구조가 선형 점수표라서인데, "강한 모델이 아니라 데이터 구조에 맞는 모델이 이긴다"는 것이 이 비교의 진짜 관찰 포인트입니다.
- **[3]** 학습률×트리 수의 관계를 미니 실험으로 확인합니다: 학습률을 낮추면 트리가 더 많이 필요하지만 성능이 안정되는 경향.
- **[4] 순열 중요도**: `permutation_importance`로 특징별 AUC 하락폭을 출력하고, 불순도 중요도(참고용)와 순위를 비교합니다.
- **[5] 부분의존**: `partial_dependence`로 이용일수·문의 수의 영향 곡선을 텍스트 그래프로 출력합니다 — 어느 구간에서 위험이 급변하는지 읽어 보세요.
- **[6] 개별 예측 설명**: 고위험 고객 1명을 골라 "특징 하나를 평균값으로 바꿨을 때 이탈 확률 변화"를 특징별로 출력합니다. "문의 4회→평균 수준이면 확률 −N%p" 같은 문장이 상담 스크립트의 근거가 됩니다.

코드 핵심부: `HistGradientBoostingClassifier(early_stopping=True)`, `permutation_importance(..., scoring="roc_auc")`, `partial_dependence(...)`, 그리고 [6]의 `explain_one()` — 12줄짜리 바꿔치기 설명기입니다.

## 6. 자주 하는 실수

- **부스팅을 기본 설정으로 돌리고 방치**: 랜덤포레스트보다 튜닝 민감도가 높습니다. 최소한 학습률·조기 종료·깊이는 검증으로 만지세요.
- **성능이 좋으니 설명은 생략**: 채택되지 않는 모델의 AUC는 0과 같습니다. 보고서에는 성능 표와 해석(중요도·부분의존·사례 설명)을 세트로 담으세요.
- **순열 중요도와 불순도 중요도를 혼용 표기**: 둘은 정의가 다르고 순위도 다를 수 있습니다. 어떤 중요도인지 명시하세요.
- **부분의존·기여도를 인과로 승격**: "문의를 줄이면 이탈이 준다"가 아니라 "문의 많은 고객을 모델이 위험하게 본다"입니다. 개입 효과는 실험으로만 증명됩니다.
- **설명 대상 데이터를 훈련 세트로 쓰기**: 순열 중요도·성능 보고는 테스트(또는 검증) 데이터 기준이어야 낙관 편향(level04)이 없습니다.
