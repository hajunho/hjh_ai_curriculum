# Lecture 06 · Level 07 — 결정트리

> 스무고개처럼 질문을 던져 가지를 치는 모델을 만들고, 학습된 트리를 사람이 읽을 수 있는 규칙 문장으로 출력해 해석합니다.
**난이도** ⭐⭐⭐ / **선행** level05, level06 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

로지스틱 회귀는 훌륭하지만 "점수표" 모델이라 두 가지 아쉬움이 있습니다. 첫째, 직선적인 관계만 잡습니다 — "이용일수가 10일 미만이면서 동시에 신규 고객일 때만 위험이 급증"같은 조건 결합 패턴에 약합니다. 둘째, 계수·오즈비라는 번역 단계를 거쳐야 설명이 됩니다.

결정트리(decision tree)는 정반대의 매력을 가진 모델입니다. 학습 결과가 **"만약 ~면 → 아니면 →"의 규칙 모음** 그 자체라서, 현업 담당자·경영진에게 그대로 보여 줄 수 있습니다. "왜 이 고객이 위험 판정인가요?"라는 질문에 "이용일수 9일 이하이고, 자동결제 미설정이고, 가입 8개월 미만이라서요"라고 답할 수 있는 것입니다. 규제 산업(금융·의료)에서 설명 가능성이 요구될 때, 그리고 모델의 발견을 업무 규칙으로 역수입하고 싶을 때 결정트리는 지금도 1순위 후보입니다. 게다가 다음 두 레벨(랜덤포레스트, 부스팅)의 부품이기도 합니다.

## 2. 비유로 이해하기

**스무고개**를 떠올려 보세요. 고수는 "그거 코끼리예요?"라고 바로 찍지 않습니다. "생물인가요?" → "동물인가요?" → "네 발인가요?" 처럼, **한 번의 질문으로 후보를 가장 크게 반토막 내는 질문**부터 던집니다.

결정트리 학습이 정확히 이 전략입니다. 고객 1,500명이 이탈/유지가 뒤섞인 채 한 방에 모여 있습니다. 트리는 가능한 모든 질문("이용일수 ≤ 9.5인가?", "가입 개월 ≤ 3.5인가?"…)을 시험해 보고, **나뉜 두 방의 순도가 가장 높아지는 질문**을 고릅니다. 그리고 각 방에서 같은 일을 반복합니다. 몇 번 갈라지고 나면 "여긴 거의 다 이탈 고객인 방", "여긴 거의 다 유지 고객인 방"이 만들어지고, 새 고객이 오면 질문을 따라 내려가 도착한 방의 다수결로 예측합니다.

주의할 점도 스무고개와 같습니다. 질문을 무한정 허용하면 "혹시 김철수 님이세요?" 같은 질문까지 써서 한 명짜리 방 1,500개를 만들 수 있습니다 — 훈련 데이터는 100% 맞히지만 새 고객에겐 쓸모없는 암기(level04의 과적합)입니다. 그래서 질문 횟수(깊이)를 제한합니다.

## 3. 핵심 개념

### 3.1 불순도 — "방이 얼마나 섞여 있나"의 점수

좋은 질문 = 방의 섞임(불순도, impurity)을 가장 많이 줄이는 질문. 대표 척도가 지니 불순도(Gini impurity)입니다.

```
Gini = 1 − (이탈 비율² + 유지 비율²)
```

방이 전부 한 종류면 0(순수), 반반이면 0.5(최악). 트리는 각 후보 질문에 대해 "질문 후 두 방의 (크기 가중) 평균 불순도"를 계산해, 감소폭이 최대인 질문을 채택합니다. level00의 임계값 탐색과 같은 원리가 재귀적으로 반복되는 것뿐입니다 — 여기서도 학습은 마법이 아니라 탐색입니다.

### 3.2 깊이와 과적합

- **깊이 1~2**: 방 2~4개. 큰 그림만 잡는 대신 절대 과적합하지 않음. "비즈니스 규칙 후보 발굴"에 적합.
- **깊이 3~5**: 실무 해석용 스위트 스폿. 사람이 읽을 수 있는 마지막 크기이기도 합니다.
- **깊이 무제한**: 훈련 정확도 ~100%, 테스트 정확도는 오히려 하락. level04 실험 A에서 이미 목격한 현상입니다.

깊이 외에도 `min_samples_leaf`(방의 최소 인원 — 한 명짜리 방 금지) 같은 제동 장치가 있습니다.

### 3.3 트리의 장단점

**장점**: 규칙이 그대로 보인다 / 표준화·스케일링 불필요(임계값 비교라 단위 무관) / 비선형·조건 결합 패턴 포착 / 수치·범주 혼합에 강함.
**단점**: **불안정** — 데이터가 조금 바뀌면 첫 질문부터 바뀌어 트리 전체가 달라질 수 있음 / 계단식 예측이라 매끄러운 관계엔 비효율 / 단독 성능은 보통 로지스틱과 비슷하거나 약간 나은 정도. 이 불안정성 문제를 "여러 트리의 투표"로 해결하는 것이 다음 레벨의 랜덤포레스트입니다.

### 3.4 규칙 역수입이라는 활용법

트리에서 발견된 상위 분기("이용일수 ≤ 9.5 그리고 자동결제 미설정 → 이탈률 45%")는 모델 없이도 CRM 규칙으로 바로 쓸 수 있습니다. 모델을 배포하지 않는 조직에서도 트리 분석만으로 가치가 나오는 이유입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

churn_table로 이탈 예측 트리를 만들고 해석합니다.

- **[1]** 데이터 준비와 분리 (표준화가 필요 없다는 점이 코드에서 확인됩니다).
- **[2]** 지니 불순도를 직접 계산해 봅니다: 전체 방의 불순도 vs "이용일수 ≤ 9.5" 질문 후의 평균 불순도 → 감소폭이 곧 질문의 값어치.
- **[3]** 깊이 3 트리를 학습하고 `export_text`로 규칙 전문을 출력한 뒤, 이탈률이 높은 잎(leaf) 방 상위 3개의 인원·이탈률을 요약합니다. 이탈자가 15%뿐이라 `class_weight="balanced"` 옵션으로 소수 클래스를 무겁게 취급해 이탈 쪽 규칙이 트리에 드러나게 했습니다 — 출력된 규칙을 위에서부터 소리 내어 읽으며 위험 방까지의 경로를 추적해 보세요.
- **[4]** 깊이 1, 3, 5, 10, 무제한으로 바꿔 가며 훈련/테스트 정확도 표를 출력 — 과적합의 갈림길을 다시 확인합니다.
- **[5]** 특징 중요도(feature importance)를 출력합니다: 각 특징이 불순도 감소에 기여한 비율.

코드 핵심부: `DecisionTreeClassifier(max_depth=3)`와 `export_text(tree, feature_names=...)`. 출력된 규칙 트리를 위에서 아래로 소리 내어 읽어 보세요 — 모델이 발견한 비즈니스 규칙이 그대로 문장이 됩니다. 그리고 [2]의 `gini()` 함수 8줄이 이 모든 것의 수학 전부입니다.

## 5. 직접 해보기

1. **(쉬움)** [3]의 `max_depth`를 2로 줄여 보세요. 규칙이 몇 개로 줄고, 테스트 성적은 얼마나 손해 보나요? 경영진 보고용이라면 깊이 2와 3 중 무엇을 고르겠습니까?
2. **(보통)** `min_samples_leaf=50`을 주고 깊이 무제한으로 학습해 보세요. 깊이 제한 없이도 과적합이 억제되나요? 두 제동 장치의 차이를 말로 설명해 보세요.
3. **(도전)** 훈련 데이터의 seed를 7에서 8로 바꿔 새 데이터로 깊이 3 트리를 다시 학습하고, 규칙이 얼마나 달라지는지 비교해 보세요. 3.3에서 말한 "트리의 불안정성"입니다. 이 관찰을 기억해 두면 level08이 훨씬 잘 이해됩니다.

## 6. 자주 하는 실수

- **깊은 트리의 훈련 성적에 감동하기**: 깊이 무제한 트리의 훈련 정확도 100%는 실력이 아니라 암기입니다(level04).
- **트리 규칙을 영구 진리로 취급**: 트리는 불안정합니다. 데이터가 갱신되면 규칙도 달라질 수 있으니, 역수입한 규칙에는 유효기간을 두세요.
- **불순도 중요도를 인과로 해석**: 특징 중요도는 "모델이 많이 써먹은 정도"이지 "원인" 순위가 아닙니다. 또 값의 종류가 많은 특징이 과대평가되는 편향도 있습니다(대안은 level11의 순열 중요도).
- **트리 앞에서 스케일링·원핫 고민에 시간 낭비**: 임계값 비교 모델이라 표준화가 필요 없습니다. 모델마다 전처리 요구가 다름을 기억하세요.
