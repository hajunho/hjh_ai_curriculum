# Lecture 06 · Level 04 — 학습·검증·테스트 분리

> "공부한 문제로 시험 보면 누구나 만점"이라는 당연한 사실이 왜 ML에서 대형 사고가 되는지, 실험으로 직접 증명합니다.
**난이도** ⭐⭐ / **선행** level03 / **예상 시간** 35분

## 1. 왜 배우나 — 비즈니스 관점

"저희 모델 정확도 97%입니다"라는 보고를 받았을 때 던져야 할 첫 질문은 단 하나입니다. **"그 97%, 어떤 데이터로 잰 겁니까?"** 훈련에 쓴 데이터로 쟀다면 그 숫자는 거의 확실히 부풀려져 있고, 실제 서비스에 배포하는 순간 성능이 뚝 떨어집니다. 이 함정은 ML 실무 사고 원인 1위를 다투며, 악의 없이도 일어납니다 — 만드는 사람이 분리 원칙을 모르면 자연스럽게 저지르게 되기 때문입니다.

데이터 분리는 코드 한 줄짜리 기술이지만, 이것을 아는 사람과 모르는 사람은 ML 결과물을 읽는 능력이 근본적으로 다릅니다. 외주 검수, 사내 보고 검증, 자기 자신의 실험 모두에서 이 레벨이 안전벨트가 됩니다.

## 2. 비유로 이해하기

**기출문제를 통째로 외운 수험생**을 떠올려 보세요. 작년 기출 100문제를 답까지 통째로 암기한 학생은, 그 100문제로 모의고사를 보면 100점입니다. 하지만 이 100점은 실력이 아니라 암기력의 증명일 뿐입니다. 실력을 재려면 **그 학생이 한 번도 본 적 없는 새 문제**로 시험을 봐야 합니다.

모델도 똑같습니다. 훈련 데이터는 "공부한 기출문제"이고, 훈련 성적은 항상 실력보다 후하게 나옵니다. 그래서 데이터 일부를 처음부터 떼어 금고에 넣어 두고(테스트 세트), 마지막에 단 한 번 꺼내 실력을 잽니다.

그런데 함정이 하나 더 있습니다. 모델을 만들다 보면 "설정을 이리저리 바꿔 가며 어떤 게 좋은지 고르는" 단계가 필요합니다. 이때 테스트 세트로 자꾸 채점하면서 고르면, **시험지를 슬쩍슬쩍 훔쳐보며 공부 방향을 정하는 셈**이 됩니다. 직접 외우진 않았어도 시험에 유리한 쪽으로 조금씩 오염됩니다. 그래서 고르는 용도의 세 번째 묶음, 검증(validation) 세트를 따로 둡니다. 요약하면 — **훈련 세트는 교과서, 검증 세트는 모의고사, 테스트 세트는 수능**입니다. 수능은 인생에 한 번만 봅니다.

## 3. 핵심 개념

### 3.1 3분할의 역할

| 세트 | 비유 | 용도 | 사용 횟수 |
|---|---|---|---|
| 훈련(train) | 교과서 | 모델의 파라미터 학습 | 무제한 |
| 검증(valid) | 모의고사 | 설정(하이퍼파라미터) 선택, 모델 비교 | 여러 번 |
| 테스트(test) | 수능 | 최종 실력 보고 | **마지막에 1번** |

관행적 비율은 60:20:20이나 70:15:15. 데이터가 적으면 교차검증(cross-validation) — 검증 세트를 번갈아 바꿔 여러 번 재는 방법 — 으로 검증을 보강합니다.

### 3.2 낙관 편향은 "우연 암기" 때문에 생긴다

훈련 데이터에는 진짜 패턴과 우연한 잡음이 섞여 있습니다. 유연한 모델일수록 잡음까지 외워 버리는데, 잡음은 그 데이터에만 있는 우연이라 새 데이터에선 도움이 안 됩니다. 그래서 **모델이 유연할수록(예: 깊은 트리) 훈련 성적과 실전 성적의 간격이 벌어집니다.** 오늘 실험 [2]에서 이 간격을 숫자로 확인합니다. 이 현상의 이름이 과적합(overfitting)이며, level09에서 본격적으로 다룹니다.

### 3.3 테스트 훔쳐보기도 실험으로 증명된다

더 미묘한 것이 [3] 실험입니다. 설정 후보 여러 개를 **테스트 세트 성적으로 골랐을 때**와 **검증 세트로 고르고 테스트는 마지막 1번만 썼을 때**를 비교하면, 전자의 최종 보고 성적이 체계적으로 부풀려집니다. 여러 후보 중 "그 시험지에서 우연히 잘 본 놈"을 고르게 되기 때문입니다. 후보가 많을수록 부풀림도 커집니다 — 동전 던지기도 100명이 하면 누군가는 10연속 앞면이 나오는 것과 같은 원리입니다.

### 3.4 분리할 때 지킬 것

- **분리는 모든 작업보다 먼저**: 정규화·특징 선택 등 데이터를 "보는" 작업을 분리 전에 전체 데이터로 하면 그 자체가 누설입니다. 스케일러도 훈련 세트로만 `fit` 합니다.
- **무작위로, seed 고정으로**: 정렬된 채 앞 70%를 자르면 편향됩니다(예: 가입일 순 정렬 데이터). 단, 시계열 예측은 예외로 **시간 순서대로** 잘라야 합니다 — 미래로 훈련하고 과거를 맞히는 건 반칙이니까요.
- **같은 고객의 행이 양쪽에 흩어지지 않게**: 한 고객의 데이터가 훈련과 테스트에 모두 있으면 "본 적 없는 문제"가 아닙니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

sklearn의 합성 분류 데이터(`make_classification`)로 두 가지 함정을 실험으로 증명합니다.

- **[1]** 데이터 1,000건을 만들어 60:20:20으로 3분할합니다 (`train_test_split` 2번).
- **[2] 실험 A — 자기 채점의 낙관 편향**: 결정트리를 얕은 것부터 깊은 것까지 학습시키며 훈련 성적과 테스트 성적을 나란히 출력합니다. 깊어질수록 훈련 정확도는 100%로 치닫고 테스트 정확도는 오히려 떨어지는 것, 즉 간격(gap)이 벌어지는 것을 확인하세요.
- **[3] 실험 B — 시험지 훔쳐보기**: k-최근접이웃 모델의 설정 k 후보 15개를 놓고, (a) 테스트로 고른 경우 vs (b) 검증으로 고르고 테스트는 1번만 쓴 경우를 서로 다른 무작위 분할 30회에 걸쳐 반복합니다. (a)의 보고 성적이 실제 실력보다 평균적으로 얼마나 부풀려지는지 통계로 출력합니다.
- **[4]** 두 실험의 교훈을 요약합니다.

주목할 출력: 실험 B에서 "테스트로 고른 성적"과 "새 데이터 성적"의 차이가 + 방향으로 일관되게 나타납니다. 부풀림은 우연이 아니라 **구조적**이라는 것이 핵심입니다.

## 6. 자주 하는 실수

- **훈련 성적을 보고서에 쓰기**: "훈련 정확도 99%"는 성과가 아니라 경고 신호일 수 있습니다.
- **테스트 세트로 여러 번 채점하며 모델을 고르기**: 고르는 순간 그건 검증 세트가 된 것이고, 최종 성적을 잴 깨끗한 데이터는 사라진 것입니다.
- **분리 전에 전체 데이터로 전처리**: 스케일링·결측 대체·특징 선택 모두 훈련 세트 기준으로 fit 하고 나머지에 transform만 해야 합니다.
- **시계열을 무작위로 섞어 자르기**: 내일을 맞히는 모델을 만들면서 모레 데이터로 훈련하는 반칙이 됩니다.
- **seed를 고정하지 않아 결과 재현 불가**: 분할이 바뀌면 성적도 바뀝니다. 보고한 숫자는 재현 가능해야 합니다.
