# Lecture 06 · Level 05 — 로지스틱 회귀: 분류의 시작

> "이탈한다/안 한다"를 넘어 "이탈 확률 73%"로 답하는 모델을 만들고, 그 계수를 비즈니스 언어로 번역합니다.
**난이도** ⭐⭐⭐ / **선행** level03, level04 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

실무 분류 문제의 답은 예/아니오보다 **확률**일 때 훨씬 쓸모 있습니다. "이 고객은 이탈합니다"보다 "이탈 확률 73%"가 나은 이유: 확률이 있어야 **우선순위**를 매길 수 있습니다. 상담 인력이 하루 50명분뿐이라면 위험 확률 상위 50명부터 전화하면 됩니다. 확률이 있어야 **기대손익 계산**도 됩니다. "이탈 확률 30% × 고객 생애가치 40만 원 = 기대손실 12만 원 > 쿠폰 비용 1만 원 → 쿠폰 발송이 남는 장사."

로지스틱 회귀(logistic regression)는 확률을 내는 분류 모델의 표준이자, 지금도 금융권 신용평가 등 "설명 책임"이 무거운 현장에서 1순위로 쓰이는 모델입니다. 계수 하나하나가 해석되기 때문입니다.

## 2. 비유로 이해하기

**위험 점수표를 쓰는 보험 심사역**을 상상해 보세요. 심사역은 항목별로 점수를 매깁니다. 이용일수가 적으면 +위험점수, 문의 전화가 많으면 +위험점수, 자동결제를 걸어 놨으면 −위험점수… 항목 점수를 다 더해 총점을 냅니다. 여기까지가 선형회귀와 똑같은 "가중합"입니다.

문제는 총점이 −5점일 수도 +12점일 수도 있는데, 우리가 원하는 답은 0~100% 확률이라는 것. 그래서 총점을 확률로 바꿔 주는 **변환 깔때기**를 하나 통과시킵니다. 이 깔때기가 시그모이드(sigmoid) 함수입니다. 총점이 아주 낮으면 0% 근처, 0점이면 딱 50%, 아주 높으면 100% 근처로 눌러 담습니다. 즉 **로지스틱 회귀 = 선형 점수표 + 확률 깔때기**입니다. level03을 이해했다면 새로 배울 것은 깔때기 하나뿐입니다.

## 3. 핵심 개념

### 3.1 시그모이드: 점수 → 확률

```
z = a₁x₁ + a₂x₂ + … + b        (선형 점수, level03과 동일한 모양)
p = 1 / (1 + e^(−z))            (시그모이드: z를 0~1 사이로)
```

시그모이드는 S자 곡선입니다. z=0에서 p=0.5, z가 ±4쯤 되면 p는 이미 0.98/0.02에 붙습니다. 학습은 "훈련 데이터의 정답 확률이 최대가 되도록" 계수 a들을 찾는 과정인데(최대우도법), 선형회귀와 달리 닫힌 공식이 없어 반복 최적화로 풉니다 — sklearn이 알아서 해 줍니다.

### 3.2 계수 해석: 오즈비

계수 aᵢ가 +이면 그 특징이 클수록 이탈 확률이 올라가고, −이면 내려갑니다. 크기까지 해석하려면 오즈(odds) 개념이 필요합니다. 오즈 = p/(1−p), "이탈 대 유지의 배당률"입니다. **특징 xᵢ가 1 단위 늘면 오즈가 e^(aᵢ)배가 됩니다.** 예: 문의 횟수의 계수가 0.5라면 e^0.5 ≈ 1.65, 즉 "문의 1회 늘 때마다 이탈 오즈 1.65배". 보고서에는 이 배수(오즈비, odds ratio)로 쓰는 것이 관례입니다.

주의: 특징들의 단위가 제각각이면(개월 vs 원) 계수 크기를 직접 비교할 수 없습니다. 오늘 실습처럼 표준화(평균 0, 표준편차 1)한 뒤의 계수는 "그 특징이 1 표준편차 움직일 때"의 효과라 서로 비교 가능해집니다.

### 3.3 임계값: 확률 → 결정

모델은 확률을 주고, 결정은 사람이 임계값(threshold)으로 내립니다. 기본값 0.5는 아무 근거 없는 관례일 뿐입니다. 임계값을 낮추면(예: 0.3) 더 많은 고객을 위험으로 분류해 **놓치는 이탈자는 줄지만 헛수고 상담은 늘고**, 높이면 반대가 됩니다. 임계값은 모델 문제가 아니라 **비용 대비 편익의 비즈니스 결정**입니다 — 상담 1건 비용과 고객 1명 상실 비용을 아는 사람이 정해야 합니다.

### 3.4 왜 "회귀"인데 분류인가

이름의 유래는 "로그 오즈(log-odds)를 선형회귀한다"이기 때문입니다. 헷갈리기 쉬운 시험 단골 포인트: 로지스틱 회귀는 **분류 모델**입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

churn_table(구독 고객 2,000명)로 이탈 확률 모델을 만듭니다.

- **[1]** 데이터를 불러와 특징 6개/정답 1개로 나누고, level04에서 배운 대로 훈련/테스트를 분리합니다. `customer_id`는 일부러 뺍니다(의미 없는 열).
- **[2]** 시그모이드 깔때기의 모양을 숫자로 확인합니다: z가 −4, −2, 0, 2, 4일 때 확률이 어떻게 되나.
- **[3]** 표준화 + 로지스틱 회귀를 학습하고 테스트 성적(정확도·재현율)을 냅니다.
- **[4]** 계수 표를 출력하고 오즈비로 번역합니다. "문의 1 표준편차 증가 → 이탈 오즈 N배" 같은 문장이 자동 생성됩니다. 데이터 생성기에 심어 둔 진짜 신호(이용일수↓, 문의↑, 자동결제−)와 방향이 일치하는지 확인하세요.
- **[5]** 고객 3명의 예측 확률을 뽑고, 임계값을 0.5 → 0.3으로 바꿀 때 재현율과 정밀도가 어떻게 맞바뀌는지 보여 줍니다.

코드 핵심부: `Pipeline([("scaler", StandardScaler()), ("clf", LogisticRegression())])`. 파이프라인을 쓰면 스케일러가 훈련 세트로만 fit 되어 level04의 누설 규칙이 자동으로 지켜집니다. 계수는 `model.named_steps["clf"].coef_`에서 꺼냅니다.

## 6. 자주 하는 실수

- **확률을 버리고 0/1만 보고하기**: 로지스틱 회귀의 최대 장점을 버리는 셈입니다. 우선순위·기대손익은 확률에서 나옵니다.
- **표준화 없이 계수 크기 비교**: "월 요금 계수가 제일 작으니 중요하지 않다" — 단위가 원(수만 단위)이라 작아 보일 뿐일 수 있습니다.
- **계수를 인과로 해석**: "자동결제를 걸게 하면 이탈이 준다"는 인과 주장입니다. 자동결제를 거는 성향의 고객이 원래 충성도가 높은 것일 수 있습니다(level03의 상관≠인과 재방문).
- **임계값 0.5를 신성시**: 0.5는 기본값일 뿐, 비용 구조에 따라 조정하는 것이 정상입니다.
- **정확도 하나로 성능 보고**: 이탈률 15% 데이터에서 정확도는 착시를 일으킵니다. 바로 다음 레벨의 주제입니다.
