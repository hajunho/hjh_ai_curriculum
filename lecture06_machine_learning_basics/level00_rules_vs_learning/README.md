# Lecture 06 · Level 00 — 머신러닝이란: 규칙 vs 학습

> 사람이 규칙을 일일이 적는 방식과, 데이터에서 규칙을 스스로 찾아내는 방식을 같은 문제로 직접 겨루게 해 봅니다.
**난이도** ⭐ / **선행** 없음 / **예상 시간** 25분

## 1. 왜 배우나 — 비즈니스 관점

"우리도 AI 도입해야 하지 않나요?"라는 회의에서 가장 먼저 필요한 것은 기술이 아니라 구분 능력입니다. 어떤 문제는 엑셀 수식이나 IF 문 몇 줄로 충분하고, 어떤 문제는 머신러닝(Machine Learning)이 아니면 풀리지 않습니다. 이 구분을 못 하면 IF 문으로 될 일에 수천만 원짜리 프로젝트를 발주하거나, 반대로 머신러닝이 필요한 일을 규칙 수백 개로 틀어막다가 유지보수 지옥에 빠집니다.

이 레벨이 끝나면 "규칙 기반으로 갈까, 학습 기반으로 갈까?"라는 질문에 스스로 답할 수 있는 기준이 생깁니다. 그리고 그 기준은 이후 11개 레벨 전체의 출발점이 됩니다.

## 2. 비유로 이해하기

**스팸 필터를 만드는 두 가지 방법**을 상상해 보세요.

방법 A — 규칙 하드코딩: 신입사원에게 업무 매뉴얼을 주는 방식입니다. "제목에 '대출'이 있으면 스팸", "발신자가 주소록에 없고 링크가 3개 이상이면 스팸"… 처음엔 잘 됩니다. 그런데 스팸 발송자가 '대출'을 '대◆출'로 바꾸면? 규칙을 또 추가해야 합니다. 규칙이 500개쯤 되면 서로 충돌하기 시작하고, 아무도 전체를 이해하지 못하게 됩니다.

방법 B — 학습: 신입사원에게 매뉴얼 대신 **선배들이 스팸/정상으로 분류해 둔 메일 10만 통**을 보여 주는 방식입니다. "직접 보고 감을 잡아라." 사람이 규칙을 적지 않아도, 데이터가 충분하면 신입은 '대◆출'까지 알아서 걸러 냅니다. 새로운 수법이 나오면 새 데이터로 다시 훈련하면 됩니다.

머신러닝이란 정확히 방법 B입니다. 전통 프로그래밍이 **"규칙 + 데이터 → 답"**이라면, 머신러닝은 **"데이터 + 답 → 규칙"**입니다. 화살표의 방향이 뒤집힌 것, 이것이 이 강의 전체에서 가장 중요한 한 문장입니다.

## 3. 핵심 개념

### 3.1 전통 프로그래밍 vs 머신러닝

| | 전통 프로그래밍 | 머신러닝 |
|---|---|---|
| 사람이 주는 것 | 규칙(코드) + 입력 | 입력 + 정답 사례 |
| 컴퓨터가 만드는 것 | 답 | 규칙(모델) |
| 규칙이 바뀌면 | 코드 수정 | 데이터로 재훈련 |
| 잘 맞는 문제 | 규칙이 명확·소수 (세금 계산, 급여 정산) | 규칙이 모호·무수히 많음 (사진 판별, 이탈 예측) |

### 3.2 "학습"의 정체 — 좋은 값을 찾는 탐색

학습(learning)이라는 말이 신비롭게 들리지만, 실체는 의외로 소박합니다. **"어떤 숫자(파라미터)를 이리저리 바꿔 보면서, 정답을 가장 잘 맞히는 값을 찾는 탐색"**입니다. 오늘 실습에서는 가장 단순한 형태를 씁니다. "거래 금액이 T원 이상이면 사기로 예측"이라는 틀을 두고, 후보 T를 전부 시도해 데이터와 가장 잘 맞는 T를 고르는 것입니다. 사람이 T=50만 원이라고 감으로 정하는 대신, 데이터가 T를 정하게 하는 것 — 이것이 학습의 씨앗입니다. 이후 배울 선형회귀·신경망도 "숫자가 수백만 개이고 탐색 방법이 더 영리할 뿐" 본질은 같습니다.

### 3.3 규칙 기반이 이기는 경우도 많다

머신러닝이 항상 우월한 것은 아닙니다.

- **규칙이 법이나 정책으로 정해져 있을 때**: 부가세 10% 계산에 머신러닝을 쓰면 안 됩니다. 100% 정확한 규칙이 이미 있으니까요.
- **데이터가 거의 없을 때**: 정답 사례 20건으로는 학습이 안 됩니다. 이럴 땐 전문가의 규칙이 낫습니다.
- **틀렸을 때 이유를 100% 설명해야 할 때**: 규칙은 추적이 쉽고, 학습된 모델은 별도의 해석 작업(level11)이 필요합니다.

실무의 정석은 "규칙으로 시작해서, 규칙이 감당 못 하는 지점부터 학습으로 넘어가기"입니다.

### 3.4 용어 정리

- **특징(feature)**: 판단 재료가 되는 입력 열. 예: 거래 금액, 거래 시각
- **레이블(label)**: 맞혀야 할 정답 열. 예: 사기 여부(0/1)
- **모델(model)**: 학습으로 얻어진 "규칙 덩어리". 오늘은 임계값 하나짜리 초미니 모델을 만듭니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

이 프로그램은 카드 이상거래 데이터(합성, 5,000건, 사기 비율 약 1.4%)를 놓고 같은 분류 문제를 세 방식으로 풉니다. 스팸 필터와 구조가 똑같은 문제입니다 — 다수의 정상 속에서 소수의 나쁜 것을 골라내기.

- **[1]** 데이터를 불러와 구조를 확인합니다. 사기가 워낙 드물어 단순 정확도는 착시를 일으키므로, 성적은 "사기 적중률과 정상 적중률의 평균(균형 점수)"으로 매깁니다.
- **[2] 수제 규칙**: "50만 원 이상 + 새벽이면 사기"라는, 회의실에서 나올 법한 감(感) 기반 규칙의 성적을 냅니다. 잡은 건 전부 진짜인데 사기의 70%를 놓칩니다.
- **[3] 학습(임계값 탐색)**: 특징 하나를 골라 모든 임계값을 시험하고, 데이터가 고른 최적 임계값으로 예측합니다. 어떤 특징·어떤 값이 뽑혔는지 출력을 꼭 확인하세요.
- **[4] 학습(두 특징 결합)**: 사람 규칙과 똑같은 모양("금액 T 이상 그리고 새벽")을 두고 숫자 T만 데이터가 고르게 합니다. 사람의 50만 원과 데이터의 답이 얼마나 다른지 보세요.
- **[5]** 세 방식을 표로 비교하고, "화살표가 뒤집혔다"는 핵심을 요약합니다.

코드 핵심부는 `learn_threshold()` 함수입니다. for 문으로 후보 임계값을 전부 돌며 점수를 재는 10줄짜리 함수 — 이것이 여러분이 만드는 첫 학습 알고리즘입니다. sklearn 같은 라이브러리를 일부러 쓰지 않았습니다. 학습이 마법이 아니라 탐색임을 눈으로 보기 위해서입니다.

출력에서 주목할 점: 사람 규칙은 "확실한 것만 잡고 대부분 놓치는" 쪽으로 치우쳐 있었고, 학습은 놓침과 헛경보의 균형이 더 좋은 숫자를 찾아냅니다. 사람은 규칙의 "모양"만 정해 주고 "숫자"는 데이터가 정한다 — 이 역할 분담이 머신러닝의 시작입니다.

## 5. 직접 해보기

1. **(쉬움)** `[2]`의 수제 규칙에서 금액 기준을 50만 원에서 10만 원으로 바꿔 실행해 보세요. 성적이 어떻게 변하나요? 사람 감으로 숫자를 고르는 일이 왜 불안한지 느껴 보세요. (힌트: `hand_rule` 함수의 숫자 하나만 수정)
2. **(보통)** `[3]`의 탐색 특징 목록에 `tx_count_1h`(최근 1시간 결제 횟수)를 추가해 보세요. 놀라운 결과가 나올 겁니다. 이 합성 데이터에는 완벽에 가까운 특징이 숨어 있습니다 — 현실 데이터라면 이런 특징이 보이는 순간 "누설(leakage) 아닌가?"부터 의심해야 합니다(level02에서 배웁니다).
3. **(도전)** 지금 `learn_threshold()`는 "이상(≥)이면 사기" 방향만 탐색합니다. "미만(<)이면 사기" 방향도 함께 탐색하도록 고쳐 보세요. `hour`(시각)처럼 작은 값이 위험한 특징에서 효과가 있을 것입니다. (힌트: 방향 플래그를 True/False 두 번 돌리기)

## 6. 자주 하는 실수

- **"AI = 머신러닝 = 만능"이라는 착각**: 규칙이 명확한 문제에 학습을 쓰는 것은 계산기가 있는데 주사위를 굴리는 격입니다.
- **학습을 신비화하기**: "모델이 스스로 생각한다"가 아니라 "숫자를 탐색해 데이터에 맞춘다"입니다. 신비화하면 결과를 검증할 생각을 못 하게 됩니다.
- **훈련에 쓴 데이터로 성적을 매기고 만족하기**: 오늘은 일부러 그렇게 했습니다. 이것이 왜 위험한지가 level04의 주제입니다. 오늘의 성적표는 "낙관적으로 부풀려진 값"이라는 점만 기억해 두세요.
- **정답 데이터 없이 학습부터 하려는 것**: 방법 B는 "선배들이 분류해 둔 메일 10만 통"이 있어야 성립합니다. 데이터 준비가 프로젝트의 절반 이상입니다.
