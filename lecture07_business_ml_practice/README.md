# Lecture 07 — 비즈니스 머신러닝 실전

> lecture06에서 배운 모델들을 "회사에서 실제로 돌아가는 프로젝트"로 완성하는 강의입니다.
> 문제 정의부터 피처 설계, 검증, 그리고 모델의 답을 돈이 되는 의사결정으로 바꾸는 마지막 단계까지 다룹니다.

## 이 강의에서 배우는 것

- 데이터 프로젝트가 실제로 흘러가는 순서와, 실패하는 프로젝트의 공통 패턴
- "재현율 1%p 개선"을 "연 매출 몇 원"으로 번역하는 방법 — 경영진과 대화하는 언어
- 탐색적 데이터 분석(EDA)을 감이 아니라 절차로 수행하는 워크플로
- 피처 엔지니어링, 범주형 인코딩, 스케일링·파이프라인 — 모델보다 성능을 더 좌우하는 준비 작업
- 교차검증과 불균형 데이터 처리 — 성능 숫자를 "믿을 수 있게" 만드는 기술
- 실전 3종 세트: 매출 수요 예측, 고객 이탈 예측, 이상거래 탐지
- 모델 확률을 비용·수익 계산에 넣어 최적 의사결정(누구에게 쿠폰을 줄까)을 뽑는 방법

## 선행 강의

- **lecture03 — 데이터 다루기** (Pandas DataFrame, 결측치 처리)
- **lecture05 — 통계와 시각화** (분포, 상관, 그래프 읽기)
- **lecture06 — 머신러닝 입문** (회귀/분류, 학습·검증 분리, 평가지표) — 특히 level04, 06은 꼭 먼저 보세요.

## 빠른 경로 (시간이 없다면 이 5개만)

1. **level00** — 프로젝트 전체 지도를 먼저 봐야 나머지가 자리를 잡습니다
2. **level01** — ML 지표를 돈으로 번역하는 법: 이 강의의 심장
3. **level06** — 교차검증: 성능 숫자에 속지 않는 최소한의 방어
4. **level09** — 이탈 예측 완결 프로젝트: 앞의 모든 조각이 조립되는 곳
5. **level11** — 확률을 의사결정으로: 실무에서 가장 티 나게 쓰이는 기술

## 이 강의가 실무에서 쓰이는 장면

- **분기 사업 계획**: 다음 주·다음 달 매출을 요일·계절 효과까지 넣어 예측하고 재고·인력을 준비 (level08)
- **CRM 캠페인**: 이탈 위험 상위 고객 명단과 고객별 추천 액션을 뽑아 마케팅팀에 전달 (level09, 11)
- **리스크·감사 부서**: 하루 알람 처리량(예산)에 맞춰 이상거래 탐지 임계값을 설계 (level07, 10)
- **데이터팀 협업·발주 검수**: "정확도 95%"라는 보고서에서 데이터 누설·단일 분할의 함정을 찾아내는 질문 (level03~06)
- **경영진 보고**: 혼동행렬 대신 "이 모델로 연 4억 원의 이탈 손실을 막을 수 있습니다"로 말하기 (level01, 11)

## 진행 팁

- 모든 레벨은 `main.py`를 직접 실행하면서 읽도록 설계되어 있습니다. 숫자가 노트와 같은지 확인해 보세요(seed 고정).
- 실행: 저장소 루트의 가상환경으로 `python3 main.py` (환경 설정은 루트 `SETUP.md` 참고)
- 데이터는 전부 `common/hjh_data.py`가 합성 생성합니다(카페 매출, 구독 이탈, 카드 거래). 인터넷 연결이 필요 없습니다.
- level00~07이 부품, level08~11이 완성품입니다. 부품 레벨을 건너뛰었다면 실전 레벨에서 막힐 때 되돌아오세요.
