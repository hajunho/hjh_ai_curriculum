# Lecture 07 · Level 02 — 탐색적 데이터 분석(EDA) 절차

> "일단 그래프나 그려 보자"가 아니라, 가설 수립→검증 사이클과 단변량→이변량→시간 순서로 진행하는 EDA 절차를 몸에 붙입니다.
**난이도** ⭐⭐ / **선행** level00, lecture05 / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

모델링 실패의 상당수는 EDA(Exploratory Data Analysis, 탐색적 데이터 분석)를 건너뛰었거나 대충 한 데서 시작됩니다. 이탈률이 18%인 줄 모르고 정확도로 평가하고, 결측이 몰려 있는 구간을 모른 채 평균을 내고, 자명한 누설 변수를 피처로 넣는 사고가 전부 여기서 납니다.

실무에서 EDA는 두 가지 역할을 합니다. 첫째, **위험 제거**: 데이터의 함정(결측, 이상치, 불균형, 누설)을 모델링 전에 발견합니다. 둘째, **가설 생산**: "고객센터 문의가 많으면 이탈하더라" 같은 발견은 그 자체로 현업에 보고할 가치가 있고, 다음 레벨의 피처 엔지니어링 재료가 됩니다. 모델 없이 EDA 보고서만으로 끝나는 프로젝트도 많으며, 그것은 실패가 아니라 훌륭한 성과입니다.

## 2. 비유로 이해하기

EDA는 **건강검진**입니다. 병원은 환자를 수술대(모델)에 올리기 전에 정해진 순서로 검진합니다.

1. **기초 문진(데이터 개요)**: 키·몸무게·나이 — 행 수, 컬럼 타입, 결측 비율.
2. **항목별 검사(단변량)**: 혈압, 혈당을 하나씩 — 각 변수의 분포를 하나씩 봅니다.
3. **연관 검사(이변량)**: "혈압과 체중의 관계" — 변수와 타깃, 변수끼리의 관계를 봅니다.
4. **경과 관찰(시간)**: 작년 수치와 비교 — 시간에 따른 변화·추세를 봅니다.

그리고 의사는 검사 전에 **소견 가설**을 세웁니다. "복부 통증이면 우선 위장을 의심"처럼, "이용일수가 적으면 이탈이 많을 것"이라는 가설을 먼저 적고 데이터로 확인하는 것입니다. 가설 없이 그래프를 수십 장 그리는 것은 증상도 안 듣고 전신 MRI부터 찍는 것과 같습니다. 비싸고, 우연히 나온 신호에 속기 쉽습니다.

## 3. 핵심 개념

### 3.1 가설 수립 → 검증 사이클

EDA의 단위 작업은 "①가설을 문장으로 적는다 → ②그 가설을 확인할 최소한의 표/그래프를 만든다 → ③판정(지지/기각/보류)을 적는다 → ④새 가설이 생기면 반복"입니다. 포인트는 **그래프보다 문장이 먼저**라는 것. 문장이 있어야 어떤 그래프를 그릴지 정해지고, 보고서에도 그대로 옮길 수 있습니다.

### 3.2 단변량 → 이변량 → 시간 순서

- **단변량(univariate)**: 변수 하나의 분포. 평균·중앙값·표준편차·최솟값·최댓값, 히스토그램. 여기서 결측·이상치·왜곡(치우친 분포)을 잡습니다. 타깃 변수의 비율(이탈률 18%)도 반드시 이 단계에서 확인합니다.
- **이변량(bivariate)**: 변수 × 타깃. 분류 문제라면 "타깃 그룹별 평균 비교"가 가장 강력한 한 방입니다. 이탈 고객과 잔류 고객의 `usage_days_30d` 평균이 크게 다르면 그 변수는 유망한 피처입니다. 수치형끼리는 상관계수(correlation)를 봅니다.
- **시간(temporal)**: 시간 축이 있는 데이터라면 추세·계절성·급변 구간을 봅니다. churn_table에는 시간 축이 없어 이번 실습에서는 생략하지만, level08(매출 예측)에서 주인공이 됩니다.

### 3.3 EDA에서 꼭 잡아야 할 4대 함정

| 함정 | 증상 | 이후 조치 |
|---|---|---|
| 결측 | 특정 컬럼/구간에 몰린 빈칸 | 제거·대체 전략 결정 (lecture03) |
| 이상치 | 음수 매출, 상식 밖 최대값 | 원인 확인 후 제거/수정 |
| 불균형 | 타깃 비율 18%, 1.5% | 평가지표·가중치 재설계 (level07) |
| 누설 의심 | 타깃과 상관 0.95 같은 수상한 변수 | 생성 시점 확인 후 제외 (level03) |

### 3.4 상관계수를 읽는 법

상관 +0.3이면 "약한 양의 관계", ±0.7 이상이면 "강한 관계"쯤으로 읽되, 두 가지를 기억하세요. 첫째, 상관은 인과가 아닙니다(아이스크림 판매와 익사 사고). 둘째, 지나치게 높은 상관은 기뻐할 일이 아니라 **의심할 일**입니다. 타깃과 상관 0.9인 변수는 대개 "정답을 미리 알아야 만들 수 있는 변수"(누설)입니다.

### 3.5 EDA 보고서의 형태

EDA의 산출물은 그래프 모음이 아니라 **판정이 달린 문장 목록**입니다. 좋은 형식: "가설 → 근거(표/그림 번호) → 판정 → 모델링에 주는 시사점" 4열짜리 표. 예: "이용일수가 적을수록 이탈 많음 → 그림2 → 지지 → 핵심 피처 후보". 이렇게 정리하면 EDA가 그대로 피처 목록(level03)과 경영 보고의 초안이 됩니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

`churn_table` 2,000명에 대한 자동 EDA 리포트를 생성합니다.

- [1] 가설 3개를 먼저 문장으로 출력합니다 (검증 전).
- [2] 기초 문진: 행/열, 타입, 결측, 타깃 비율.
- [3] 단변량: 수치형 변수별 요약 통계표.
- [4] 이변량: 이탈/잔류 그룹별 평균 비교표와 "차이 배율", 그리고 타깃과의 상관계수 순위.
- [5] 가설 판정: [1]의 가설 각각에 지지/기각을 출력합니다.
- [6] 그림 2장을 `outputs/`에 저장합니다: ① 주요 변수의 이탈/잔류별 분포 비교, ② 상관 행렬 히트맵.

코드 핵심부는 `df.groupby("churned")[cols].mean()` 한 줄입니다. 이변량 분석의 8할이 이 groupby 비교라는 것을 눈으로 확인하세요. 히트맵은 `df.corr()` 결과를 `imshow`로 그린 것뿐입니다.

## 6. 자주 하는 실수

- **그래프 수십 장을 목적 없이 생산**: 가설 문장이 없는 그래프는 보고서에서 전부 잘려 나갑니다. 문장 먼저, 그래프는 증거로.
- **타깃 비율을 확인하지 않고 모델링 시작**: 불균형을 모르면 이후 모든 평가가 왜곡됩니다. EDA 1순위 확인 항목입니다.
- **평균만 보고 분포를 안 봄**: 평균이 같아도 분포 모양이 다르면 전혀 다른 데이터입니다. 요약표와 히스토그램은 세트입니다.
- **EDA에서 본 것을 테스트 데이터에까지 적용해 규칙 튜닝**: 테스트 데이터는 EDA에서도 봉인이 원칙입니다. 전체 데이터로 EDA를 했다면 그 사실을 보고서에 명시하세요.
