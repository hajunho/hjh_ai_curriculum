# Lecture 07 · Level 08 — 실전 1: 매출 수요 예측

> 카페 체인 1년치 매출로 "다음 주 일별 매출"을 예측하는 전체 파이프라인을 만듭니다. 요일·계절·이동평균 피처와 시간 기반 분할이 주인공입니다.
**난이도** ⭐⭐⭐⭐ / **선행** level03, level06 / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

"다음 주 매출이 얼마나 될까?"는 모든 업종의 공통 질문입니다. 답에 따라 발주량, 근무 스케줄, 현금 흐름 계획이 달라집니다. 예측이 10% 빗나가면 재고 폐기나 품절, 인력 과잉이나 대기 행렬로 곧장 비용이 됩니다.

수요 예측은 분류가 아니라 **회귀(regression)**이고, 데이터에 **시간 축**이 있다는 점에서 지금까지의 문제와 성격이 다릅니다. 시간 축이 있으면 두 가지가 바뀝니다. 첫째, 피처의 주력이 "요일·계절·최근 추세" 같은 시간 파생 피처가 됩니다. 둘째, 검증 규칙이 바뀝니다 — 반드시 과거로 학습하고 미래로 시험 봐야 합니다(level06 [4]에서 본 함정). 이 레벨은 이 두 가지를 갖춘 **끝까지 완주하는 첫 실전 프로젝트**입니다.

## 2. 비유로 이해하기

경험 많은 카페 점장의 머릿속을 옮겨 봅시다. 점장은 다음 주 발주량을 정할 때 대략 이렇게 생각합니다.

1. "요즘 하루 평균 얼마나 팔리지?" → **이동평균**(최근 추세)
2. "다음 주 토요일은 평소 토요일만큼 팔리겠지" → **요일 효과**
3. "여름이 오고 있으니 음료가 늘 거야" → **계절 효과**
4. "어제 갑자기 많이 팔렸으면 내일도 좀 이어지려나?" → **전일 매출(lag)**

머신러닝 수요 예측은 이 네 가지 직감을 각각 숫자 컬럼으로 만들어 모델에게 주는 것입니다. 모델이 마법으로 미래를 보는 게 아니라, **점장의 직감을 피처로 번역해 일관되게, 대량으로, 매일 자동으로** 적용하는 것 — 그것이 본질입니다. 그래서 이 레벨의 코드 대부분은 모델이 아니라 피처 만들기에 쓰입니다.

## 3. 핵심 개념

### 3.1 시계열 피처의 3대장

- **달력 피처**: 요일(원핫 또는 주말 플래그), 월, 공휴일 여부. 반복되는 패턴을 담습니다.
- **시차(lag) 피처**: `lag_1`(전일), `lag_7`(일주일 전 같은 요일). "최근에 어땠나"를 담습니다.
- **이동평균(rolling mean)**: 최근 7일 평균, 28일 평균. 잡음을 걸러낸 추세를 담습니다.

주의: lag·이동평균은 반드시 **예측 시점 이전의 값만** 쓰도록 `shift(1)` 후 계산해야 합니다. 오늘 매출 예측에 오늘 매출이 포함된 이동평균을 쓰면 정답을 베끼는 누설입니다.

### 3.2 계절성을 숫자로 — sin/cos 변환

"연중 몇 번째 날(1~365)"을 그대로 넣으면 12월 31일(365)과 1월 1일(1)이 극과 극으로 떨어져 보입니다. `sin(2π·day/365)`, `cos(2π·day/365)` 두 컬럼으로 바꾸면 연말과 연초가 자연스럽게 이웃이 되는 원형 달력이 됩니다. 요일도 같은 방식이 가능하지만, 종류가 7개뿐이라 원핫이 더 흔합니다.

### 3.3 시간 기반 분할과 기준선

- **분할**: 마지막 몇 주를 테스트(=다가올 주 상황 재현), 그 이전을 학습으로. 무작위 분할은 금지입니다. 평가 구간이 너무 짧으면(예: 7일) 순위가 운에 좌우되므로, 실무에서는 여러 주에 걸친 백테스트로 평가합니다.
- **기준선(baseline)**: 모델이 넘어야 할 최소선. 수요 예측의 관례적 기준선은 ① "어제와 같다"(naive), ② "지난주 같은 요일과 같다"(seasonal naive)입니다. 이 단순 규칙을 못 이기는 모델은 배포할 이유가 없습니다. 실무 보고서에도 반드시 기준선 대비 개선율로 말하세요.

### 3.4 평가지표 — MAE와 MAPE

- **MAE**(평균 절대 오차): "평균적으로 하루 N원 빗나감". 단위가 원이라 직관적입니다.
- **MAPE**(평균 절대 백분율 오차): "평균 N% 빗나감". 규모가 다른 지점끼리 비교할 때 유용하지만, 실제값이 0에 가까우면 폭발하므로 주의합니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

- [1] `sales_table` 1년치를 정제(결측·음수 제거)하고 일별 총매출로 집계합니다.
- [2] 피처 생성: 요일 원핫, 주말 플래그, 계절 sin/cos, lag_7(지난주 같은 요일), 7일/28일 이동평균(모두 7일 전 기준 — 예측 시점에 알 수 있는 값만).
- [3] 시간 기반 분할: 마지막 4주(28일)를 평가 구간으로 봉인합니다. 7일만으로는 운이 많이 섞이기 때문에, 매주 예측을 갱신하는 운영을 가정한 4주 백테스트로 평가합니다.
- [4] 기준선 2종(어제와 같다 / 지난주 같은 요일)과 RandomForest 회귀의 MAE·MAPE를 4주 백테스트에서 비교합니다.
- [5] '다음 주'(마지막 7일)의 예측 vs 실제를 일별로 출력하고, 최근 8주 흐름과 예측 구간을 그린 PNG를 `outputs/`에 저장합니다.
- [6] 피처 중요도로 "모델이 무엇을 보고 예측했는지"를 확인합니다.

관찰 포인트: 기준선(특히 seasonal naive)이 생각보다 강하다는 것, 그리고 모델의 개선분이 어디서 오는지(요일+추세의 결합)입니다. PNG에서 예측선이 실제의 요일 리듬을 따라가는지 확인해 보세요.

3. **(도전)** 전체 매출 대신 "음료 카테고리만"의 일별 매출로 같은 파이프라인을 돌려 보세요. 계절 sin/cos의 중요도가 확 올라갈 것입니다 — 여름 음료 성수기라는 도메인 지식과 일치하는지 확인하세요.

## 6. 자주 하는 실수

- **무작위 분할로 검증**: 시계열의 제1 금기. 점수는 좋아 보이는데 실전에서 무너집니다. 분할은 언제나 시간 순.
- **이동평균에 오늘 포함**: `rolling(7).mean()`을 `shift(1)` 없이 쓰면 오늘 값이 오늘 피처에 들어갑니다. 조용한 누설의 단골.
- **기준선 없이 "MAE 50만 원" 보고**: 그 숫자가 좋은지 나쁜지 아무도 모릅니다. "어제와 같다 대비 -23%"처럼 상대 개선으로 보고하세요.
- **먼 미래를 한 방에 예측**: lag 피처는 하루 앞 예측용입니다. 7일 앞을 예측하려면 예측값을 다시 입력으로 쓰는 재귀 방식이나 7일 전 lag만 쓰는 직접 방식 중 하나를 명시적으로 설계해야 합니다(main.py는 lag_7·이동평균 등 "7일 전까지의 정보만" 쓰는 직접 방식입니다).
- **명절·프로모션 무시**: 실제 데이터에서 가장 큰 오차는 특수일에서 납니다. 특수일 달력을 피처로 넣는 것이 실무 정확도의 절반입니다.
