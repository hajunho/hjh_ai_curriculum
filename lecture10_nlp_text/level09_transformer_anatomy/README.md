# Lecture 10 · Level 09 — 트랜스포머 구조 해부

> 멀티헤드 어텐션·포지셔널 인코딩·잔차 연결·레이어놈을 numpy 로 만들어 블록 하나를 조립합니다.
**난이도** ⭐⭐⭐⭐ / **선행** level08 / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

GPT, Claude, Gemini, 번역기, 코드 어시스턴트 — 이름은 달라도 내부는 모두
트랜스포머(Transformer)입니다. 2017년 제안된 이 구조 하나가 10년째 AI 의
표준 설계도이고, "파라미터 수", "레이어 수", "컨텍스트 길이" 같은 뉴스 속
스펙 경쟁은 전부 이 설계도의 부품 수 이야기입니다.

부품을 알면 대화가 달라집니다. "우리 서비스에 7B 모델이면 충분한가?",
"컨텍스트 128k 모델로 갈아탈 가치가 있나?" 같은 의사결정 회의에서, 트랜스포머
구조를 아는 사람은 스펙 숫자가 비용·속도·품질에 어떻게 연결되는지 추론할 수
있습니다. 이 레벨은 그 설계도를 부품 단위로 분해해 직접 만들어 보는
시간입니다. 학습은 하지 않습니다 — 구조와 데이터 흐름(shape)에만 집중합니다.

## 2. 비유로 이해하기

트랜스포머 블록은 **회의 → 정리의 반복으로 굴러가는 태스크포스(TF)팀**입니다.
토큰 하나하나가 팀원이고, 각 팀원은 자기 담당 정보(벡터)를 들고 있습니다.

1. **전체 회의(멀티헤드 어텐션)**: 팀원들이 서로의 정보를 참조해 자기 생각을
   갱신합니다. 회의를 한 번이 아니라 **여러 분과로 나눠 동시에** 합니다 —
   예산 분과, 일정 분과, 리스크 분과가 따로 모여 각자의 관점으로 논의한 뒤
   결과를 합칩니다. 이것이 멀티헤드(multi-head)입니다.
2. **개인 정리 시간(피드포워드)**: 회의가 끝나면 각자 자리로 돌아가 들은 것을
   자기 방식으로 소화합니다. 옆 사람과 상의 없이, 모든 팀원이 같은 정리
   요령(같은 가중치)을 씁니다.
3. **원본 보존(잔차 연결)**: 회의록만 남기면 원래 내 의견이 사라질 수 있으니,
   "원래 의견 + 회의에서 얻은 것"을 더해서 갖고 갑니다.
4. **컨디션 관리(레이어놈)**: 회의를 거듭하면 어떤 팀원은 과열되고 어떤
   팀원은 침묵합니다. 매 단계 후 발언 톤을 표준 범위로 맞춰 줍니다.

이 "회의+정리" 세트가 블록 하나이고, 트랜스포머는 이 블록을 수십 번 쌓은
것입니다.

## 3. 핵심 개념

### 3-1. 포지셔널 인코딩 — 순서 감각 되찾기

어텐션은 모든 토큰을 동시에 보므로 **순서를 모릅니다**. "회사가 고객을"과
"고객이 회사를"이 같은 집합입니다. 그래서 입력 임베딩에 **자리 번호표**를
더해 줍니다. 원조 트랜스포머는 사인/코사인 파동을 씁니다:

$$PE_{(pos, 2i)} = \sin(pos / 10000^{2i/d}), \quad PE_{(pos, 2i+1)} = \cos(\cdot)$$

주파수가 다른 파동 여러 개를 겹치면 모든 위치가 고유한 패턴을 갖고, 위치 간
상대적 거리도 벡터 연산으로 표현됩니다. 숫자를 이진수로 세면 자리마다 0/1이
다른 주기로 바뀌는 것과 같은 원리입니다. (최신 모델들은 RoPE 등 변형을
쓰지만 "위치 정보를 주입한다"는 목적은 같습니다.)

### 3-2. 멀티헤드 어텐션 — 관점을 나눠서 보기

한 번의 어텐션은 한 가지 관계밖에 못 봅니다. 임베딩을 헤드 수만큼 쪼개
(예: 32차원 → 8차원 × 4헤드) 각 조각에서 독립적으로 어텐션한 뒤 이어붙이면,
어떤 헤드는 "수식 관계", 어떤 헤드는 "주어-동사 관계"처럼 서로 다른 패턴을
잡을 수 있습니다. 계산량은 한 덩어리 어텐션과 거의 같으면서 표현력이 늘어나는
설계입니다.

### 3-3. 잔차 연결과 레이어놈 — 깊게 쌓기 위한 안전장치

- **잔차 연결(residual connection)**: 출력 = 입력 + 부품(입력). 부품이 아직
  덜 학습됐어도 입력이 그대로 통과하는 지름길이 있어, 수십 층을 쌓아도 학습
  신호가 아래층까지 전달됩니다. lecture09(CNN)에서 본 것과 같은 아이디어입니다.
- **레이어 정규화(layer normalization)**: 각 토큰 벡터를 평균 0, 분산 1로
  맞춘 뒤 학습 가능한 배율·이동을 적용합니다. 층을 거치며 값이 폭주하거나
  소멸하는 것을 막습니다.

### 3-4. 인코더 vs 디코더

- **인코더(encoder)**: 문장 전체를 **양방향**으로 봅니다. 이해가 목적 —
  분류, 검색, 빈칸 채우기(BERT 계열).
- **디코더(decoder)**: 각 토큰이 **자기 앞쪽만** 보도록 인과 마스크를 씁니다.
  다음 토큰 생성이 목적 — GPT 계열. 뒤를 보면 정답을 컨닝하게 되니까요.

부품은 같고, 마스크 하나가 운명을 가릅니다. level10 에서 우리는 디코더를
만들어 학습시키고, level11 에서 두 진영의 철학을 비교합니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

문장 하나(토큰 6개, 32차원)를 트랜스포머 블록에 통과시키며 **모든 부품의
입출력 shape 와 역할**을 출력합니다. 학습은 없고 seed 고정 난수 가중치를
씁니다 — 오늘의 주인공은 숫자가 아니라 구조입니다.

- **[1] 포지셔널 인코딩**: 사인/코사인 표를 만들고 "같은 단어라도 자리가
  다르면 입력이 달라짐"을 수치로 확인합니다.
- **[2] 멀티헤드 어텐션**: 32차원을 4헤드×8차원으로 쪼개 각 헤드의 가중치
  행렬 shape 를 출력하고, 헤드별 주목 패턴이 서로 다름을 보여 줍니다.
- **[3] 잔차+레이어놈**: 부품 통과 전후의 벡터 크기(표준편차)를 출력해
  정규화가 값의 폭주를 어떻게 막는지 확인합니다.
- **[4] 피드포워드**: 확장(32→64)→활성화→축소(64→32)의 shape 흐름을 출력합니다.
- **[5] 블록 조립·적층**: 부품을 순서대로 연결한 블록을 2번 통과시켜
  "블록을 쌓는다"의 의미를 확인하고, 파라미터 수를 집계합니다.
- **[6] 인코더 vs 디코더**: 같은 입력에 인과 마스크를 켜고 끈 어텐션 가중치를
  나란히 출력해 하삼각형 구조를 눈으로 확인합니다.

## 5. 직접 해보기

1. **(쉬움)** 헤드 수를 4에서 2로, 8로 바꿔 보세요. 전체 파라미터 수가
   변하지 않는 이유를 [2]의 shape 출력에서 찾아보세요.
2. **(보통)** [1]에서 포지셔널 인코딩을 더하지 않도록 주석 처리하면, 토큰
   순서를 뒤섞어도 어텐션 가중치 집합이 똑같아지는 것을 확인해 보세요.
3. **(도전)** 블록 안의 레이어놈을 빼고 블록을 10번 반복 통과시키며 출력의
   표준편차를 찍어 보세요. 값이 점점 커지거나 작아지는 것이 관찰되면, 왜
   깊은 모델에 정규화가 필수인지 몸으로 이해한 것입니다.

## 6. 자주 하는 실수

- **shape 를 안 보고 코드만 읽기**: 트랜스포머 이해의 왕도는 각 단계의 텐서
  shape 추적입니다. (토큰 수, 차원)이 어디서 어떻게 변하는지 종이에 그려 보세요.
- **멀티헤드 = 어텐션 여러 번 반복이라고 오해**: 반복이 아니라 차원을 쪼개
  병렬로 보는 것입니다. 그래서 계산량이 헤드 수만큼 늘지 않습니다.
- **포지셔널 인코딩을 장식으로 취급**: 이것이 없으면 트랜스포머는 어순을
  전혀 모릅니다. "단어 집합 모델"로 퇴화합니다.
- **인코더/디코더를 별개 기술로 암기**: 같은 부품, 마스크 차이입니다. 구조가
  아니라 "무엇을 보게 허용하는가"의 차이로 기억하세요.
