# Lecture 10 · Level 10 — 미니 트랜스포머 직접 구현

> torch 로 소형 디코더(GPT 구조)를 만들어 다음 토큰 예측을 학습시키고 생성 변화를 관찰합니다.
**난이도** ⭐⭐⭐⭐⭐ / **선행** level07, level09 / **예상 시간** 70분

## 1. 왜 배우나 — 비즈니스 관점

"GPT 를 직접 만들어 봤다"는 경험은 LLM 을 보는 눈을 완전히 바꿉니다.
물론 오늘 만드는 것은 파라미터 수십만 개짜리 장난감이고, 상용 LLM 은 수천억
개입니다. 하지만 **구조는 같습니다**. 임베딩 → 디코더 블록 적층 → 다음 토큰
확률. 스케일만 다릅니다.

직접 만들어 보면 이런 것들이 당연해집니다: LLM 이 왜 한 번에 한 토큰씩
생성하는지(그래서 응답이 스트리밍되는지), 왜 학습에 GPU 가 필요한지,
"환각"이 왜 버그가 아니라 확률적 생성의 본질인지, 파인튜닝이 무엇을 바꾸는
것인지. 경영 회의에서 "LLM 은 어차피 다음 단어 맞히기 기계"라는 말의 정확한
의미를 아는 사람이 됩니다.

## 2. 비유로 이해하기

level09 까지가 **자동차 부품 공부**였다면 오늘은 **조립해서 시동 걸고 도로
주행**입니다. 부품(어텐션, FF, 잔차, 레이어놈)은 이미 다 만들어 봤습니다.
오늘 새로 하는 일은 세 가지뿐입니다.

1. **부품을 torch 로 조립**: numpy 버전과 달리 자동 미분이 되므로 학습이
   가능해집니다.
2. **운전 연습(학습)**: tiny_corpus 를 보여 주며 "다음 토큰 맞히기"를 수천 번
   반복시킵니다. 틀릴 때마다 역전파로 전 부품을 조금씩 조정합니다.
3. **주행 시험(생성)**: 학습 전·중·후에 같은 프롬프트로 문장을 생성시켜
   횡설수설 → 그럴듯한 문장으로 변해 가는 과정을 봅니다.

학습이라는 운전 연습의 목표는 단순합니다 — 코스(말뭉치)를 수없이 돌며
"이 상황 다음엔 이 행동"을 몸에 새기는 것. LLM 사전학습(pre-training)의
축소판입니다.

## 3. 핵심 개념

### 3-1. GPT 구조 = 디코더만 쌓은 트랜스포머

원조 트랜스포머는 번역용이라 인코더+디코더였지만, GPT 는 **디코더만** 씁니다.

```
토큰 ID → 토큰 임베딩 + 위치 임베딩
       → [디코더 블록: 인과 마스크 어텐션 → FF (+잔차/놈)] × N층
       → 최종 레이어놈 → 선형층 → 어휘 크기만큼의 점수(logits)
```

마지막 선형층의 출력이 "다음 토큰이 어휘의 각 후보일 점수"이고, softmax 를
거치면 확률이 됩니다. 오늘 모델은 2층, 64차원, 4헤드 — 전체 파라미터 약
십만 개 수준의 초소형입니다.

### 3-2. 병렬 학습의 마법 — 한 문장에서 수십 개의 문제를 동시에

RNN 은 글자를 순서대로 처리해야 했지만, 트랜스포머는 인과 마스크 덕분에
시퀀스의 **모든 위치를 동시에** 학습할 수 있습니다. 길이 32짜리 시퀀스
하나가 "1번째까지 보고 2번째 맞히기", "2번째까지 보고 3번째 맞히기"...
32개의 문제를 한 번의 순전파로 모두 풉니다. 이 병렬성이 트랜스포머가 RNN 을
밀어낸 실질적 이유 중 하나입니다 — GPU 를 꽉 채워 쓸 수 있으니까요.

### 3-3. 손실이 내려간다 = 놀라움이 줄어든다

교차 엔트로피 손실은 "정답 토큰에 준 확률이 낮을수록" 큽니다. 학습 초기엔
어휘가 $V$ 종이면 손실이 대략 $\ln V$ (아무 데나 찍기) 근처에서 시작합니다.
손실이 내려간다는 것은 모델이 다음 토큰에 덜 놀란다는 뜻입니다. 언어모델
평가지표인 퍼플렉시티(perplexity)는 $e^{loss}$ 로, "매 순간 몇 개 후보
사이에서 고민하는가"로 읽을 수 있습니다. 이 숫자가 출력에 함께 찍힙니다.

### 3-4. 생성 품질의 단계

작은 모델이 학습되며 생성문은 대략 이런 단계를 밟습니다.

1. 무작위 글자 나열 (학습 전)
2. 글자 통계 모방 — 자주 나오는 글자·짧은 패턴 등장
3. 어절 골격 — "○○이 ○○를 ○○다." 문형이 잡힘
4. 그럴듯한 문장 — 말뭉치 문형의 재조합

상용 LLM 은 여기서 수만 배의 데이터·모델·계산을 부어 5단계(지식·추론)까지
간 것입니다. 스케일이 단계를 만든다 — 이것이 다음 레벨(사전학습 패러다임)의
주제입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

tiny_corpus 3만 자로 글자 단위 미니 GPT 를 학습합니다. CPU 에서 60초 안에
끝나도록 설계했습니다 (필자 환경 기준 약 20~40초).

- **[1] 데이터**: 글자 사전과 (입력, 한 글자 민 정답) 배치 구성을 출력합니다.
- **[2] 모델**: 임베딩 64차원, 2층, 4헤드 디코더. 파라미터 수와 층 구성을
  출력합니다. 어텐션·블록은 level09 부품의 torch 판이라 코드가 낯익을 겁니다.
- **[3] 학습**: 400 스텝 동안 loss 와 퍼플렉시티를 주기적으로 찍고, 세 시점
  (초기/중간/최종)에 같은 프롬프트("어제 ")의 생성문을 출력합니다.
  loss 하강 곡선은 `outputs/loss_curve.png` 로 저장합니다.
- **[4] 생성 시험**: 학습 완료 모델로 프롬프트 3종에 이어쓰기를 시연합니다.
- **[5] 어텐션 들여다보기**: 1층 헤드들의 어텐션 패턴이 인과(하삼각) 구조인지
  확인 출력합니다.

## 6. 자주 하는 실수

- **작은 모델의 생성문에 실망**: 오늘의 목표는 ChatGPT 가 아니라 "구조가
  학습되는 것"의 관찰입니다. 문형이 잡히면 대성공입니다.
- **loss 0 을 목표로 삼기**: 언어에는 본질적 불확실성이 있어 loss 는 0이 될
  수 없고, 되어서도 안 됩니다(완전 암기 = 과적합).
- **컨텍스트 길이(BLOCK)와 생성 길이 혼동**: 모델은 최근 BLOCK 글자까지만
  봅니다. 그보다 길게 생성하면 앞부분을 잊는 것이 정상입니다.
- **마스크 버그를 성능 향상으로 착각**: 3번 도전 과제처럼, 미래가 보이면
  loss 는 좋아 보여도 생성 능력은 없습니다. 지표가 좋다고 다 좋은 게 아닙니다.
