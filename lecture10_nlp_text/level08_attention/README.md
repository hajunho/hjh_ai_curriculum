# Lecture 10 · Level 08 — 어텐션 메커니즘

> "어디를 얼마나 주목할지"를 계산하는 어텐션을 numpy 로 구현하고 가중치를 히트맵으로 봅니다.
**난이도** ⭐⭐⭐⭐ / **선행** level06, level07 / **예상 시간** 55분

## 1. 왜 배우나 — 비즈니스 관점

지금 세상을 움직이는 AI — 챗봇, 번역기, 코드 생성기, 이미지 생성기까지 —
의 심장에는 전부 같은 부품이 들어 있습니다. 어텐션(attention)입니다.
2017년 "Attention Is All You Need"라는 논문 제목 그대로, 이 부품 하나가
RNN 의 릴레이 메모를 대체하며 트랜스포머 시대를 열었습니다.

비전공자가 어텐션을 알아야 하는 실질적 이유는 두 가지입니다. 첫째, **LLM 의
동작과 한계가 여기서 설명됩니다**. 컨텍스트 길이 제한이 왜 있는지(어텐션
비용은 길이의 제곱), 프롬프트에서 중요한 정보를 앞뒤에 배치하라는 조언이
왜 나오는지 — 전부 어텐션의 성질입니다. 둘째, **설명 가능성**입니다.
어텐션 가중치를 열어 보면 "모델이 어느 단어를 보고 판단했는지"의 단서를
시각적으로 확인할 수 있습니다.

## 2. 비유로 이해하기

어텐션은 **회의에서 발언자마다 주목도를 다르게 배분하는 것**입니다.
10명이 발언한 회의에서 결론 메모를 쓸 때, 우리는 10명의 말을 똑같이 반영하지
않습니다. 지금 쓰려는 문장과 관련 깊은 발언에 귀를 크게 열고(가중치 크게),
무관한 발언은 흘려듣습니다(가중치 작게). 최종 메모는 "발언들의 가중 평균"이
됩니다.

이 과정을 기계로 만들려면 세 가지가 필요합니다. 회의로 계속 비유하면:

- **Query(질의)**: 내가 지금 알고 싶은 것. "예산 관련해서 누가 뭐라 했지?"
- **Key(키)**: 각 발언자의 명찰 — "저는 예산 담당입니다", "저는 홍보 담당입니다".
  질의와 명찰을 대조해 관련도를 매깁니다.
- **Value(값)**: 각 발언자가 실제로 한 말의 내용. 관련도만큼 섞어서 가져갑니다.

질의(Q)를 모든 키(K)와 대조해 주목도 점수를 만들고, 그 비율로 값(V)들을
가중 평균한다 — 이것이 어텐션의 전부입니다. RNN 과 달리 **몇 번째 발언이든
직접 접근**하므로, 릴레이를 거치며 정보가 흐려지는 문제가 사라집니다.

## 3. 핵심 개념

### 3-1. Scaled Dot-Product Attention — 공식 한 줄 해부

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

한 조각씩 읽어 봅시다.

1. $QK^\top$ — 질의와 모든 키의 내적. 내적은 "방향이 비슷할수록 큰 값"이므로
   관련도 점수표가 됩니다. (level06 에서 배운 유사도가 여기서 재등장합니다.)
2. $\div \sqrt{d_k}$ — 벡터 차원이 크면 내적 값이 커져 softmax 가 한쪽으로
   쏠립니다(포화). 차원의 제곱근으로 나눠 점수의 스케일을 맞춥니다.
   'scaled'라는 이름의 유래입니다.
3. $\text{softmax}$ — 점수를 합이 1인 확률(주목도 배분표)로 바꿉니다.
   "예산 담당 60%, 기획 30%, 나머지 10%"처럼요.
4. $\times V$ — 주목도만큼 값 벡터들을 가중 평균. 이것이 어텐션의 출력입니다.

### 3-2. Q, K, V 는 어디서 오나

셀프 어텐션(self-attention)에서는 같은 문장의 토큰 임베딩 $X$ 에 서로 다른
행렬 $W_Q, W_K, W_V$ 를 곱해 셋을 모두 만듭니다. 같은 사람이 회의에서
질문자도 되고 답변자도 되는 셈입니다. 이 행렬들이 **학습되는 파라미터**라서,
모델은 훈련 과정에서 "무엇을 물어보고 무엇을 명찰에 쓸지"를 스스로 익힙니다.
오늘 실습은 학습 없이 구조만 보므로 seed 고정 난수 행렬을 씁니다.

### 3-3. 어텐션 가중치 행렬 — 읽는 법

토큰이 $n$ 개면 가중치는 $n \times n$ 행렬입니다. $i$ 행 $j$ 열은 "토큰 $i$ 가
토큰 $j$ 를 얼마나 참고했나"입니다. 각 행의 합은 항상 1입니다(softmax 덕분).
히트맵으로 그리면 모델의 '시선 처리'가 보입니다. 예를 들어 "눈이 침침해서
안과에 갔다"에서 '눈' 행이 '침침'과 '안과' 열에 밝다면, '눈'의 표현이 그
단어들을 참고해 만들어졌다는 뜻입니다 — level00 의 중의성 문제를 어텐션이
어떻게 다루는지가 이 그림 한 장에 있습니다.

### 3-4. 비용 — 왜 컨텍스트가 길면 비싼가

모든 토큰이 모든 토큰을 보므로 계산량과 메모리가 $n^2$ 으로 늘어납니다.
토큰 1,000개면 100만 칸, 10,000개면 1억 칸. LLM 의 컨텍스트 길이 제한과
"긴 입력은 요금이 더 나가는" 구조의 근본 원인입니다.

  로 구현합니다. 핵심 함수는 5줄입니다.
- **[2] 장난감 예제로 수치 확인**: 토큰 3개짜리 초미니 예제에서 점수 행렬 →

  셀프 어텐션을 계산합니다. 같은 '눈'이 문장에 따라 다른 단어에 주목하는 것을
  수치로 확인합니다.
- **[4] 히트맵 PNG**: 두 문장의 어텐션 가중치를 히트맵으로 `outputs/` 에

- **[5] 비용 체감**: 토큰 수 10/100/1000/10000 에 대한 가중치 행렬 크기를

3. **(도전)** 마스크(mask)를 추가해 보세요: 각 토큰이 자기보다 뒤의 토큰을

## 6. 자주 하는 실수

- **어텐션 가중치 = 완전한 설명이라고 믿기**: 가중치는 유용한 단서지만 모델
  판단의 전부는 아닙니다. 여러 층·여러 헤드가 얽히면 해석이 흐려집니다.
- **softmax 방향 착각**: 가중치 행렬은 행 방향으로 합이 1입니다. 열 합이 1이
  아니에요. 히트맵을 읽을 때 "행이 주목하는 쪽"임을 기억하세요.
- **스케일링 생략**: 차원이 커지면 softmax 가 포화되어 기울기가 죽습니다.
  √d 나누기는 장식이 아닙니다.
- **Q·K·V 를 신비화**: 셋 다 "입력 X 에 행렬 하나 곱한 것"입니다. 역할이
  다르도록 서로 다른 행렬을 곱했을 뿐입니다.
