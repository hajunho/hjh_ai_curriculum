# Lecture 10 · Level 05 — 텍스트 분류 실습: 리뷰 감성 분석

> TF-IDF + 로지스틱 회귀로 감성 분석기를 만들고, 모델이 근거로 삼은 단어를 계수로 해석합니다.
**난이도** ⭐⭐⭐ / **선행** level04, lecture06(로지스틱 회귀) / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

"이번 프로모션 이후 고객 반응이 어때?"라는 질문에 리뷰 3,000건을 일일이 읽을
수는 없습니다. 감성 분석(sentiment analysis)은 리뷰를 긍정/부정으로 자동
분류해 "긍정 비율 추이", "부정 리뷰의 주요 원인 단어"를 대시보드로 만들 수
있게 해 줍니다. VOC 분석, 브랜드 모니터링, CS 티켓 우선순위 지정 — 텍스트
분류는 기업에서 가장 많이 쓰이는 NLP 응용입니다.

이 레벨의 또 하나의 목표는 **설명 가능성**입니다. "모델이 87% 맞춘다"로는
보고가 끝나지 않습니다. "왜 이 리뷰를 부정으로 봤나?"에 답할 수 있어야
현업이 결과를 신뢰합니다. 로지스틱 회귀는 단어별 계수를 열어 볼 수 있어서
이 답을 정확하게 줄 수 있는, 실무에서 사랑받는 출발점입니다.

## 2. 비유로 이해하기

감성 분석기는 **채점 기준표를 가진 첨삭 선생님**입니다. 선생님의 기준표에는
단어마다 점수가 적혀 있습니다: "친절" +3점, "만족" +2점, "실망" -4점,
"고장" -3점... 리뷰가 들어오면 등장한 단어들의 점수를 합산하고, 합계가
0보다 크면 긍정, 작으면 부정으로 판정합니다.

로지스틱 회귀(logistic regression)가 정확히 이 구조입니다. 다른 점은 단
하나 — **기준표의 점수를 사람이 정하지 않고, 정답이 달린 리뷰 데이터에서
모델이 스스로 알아낸다**는 것입니다. 학습이 끝난 뒤 기준표(계수)를 열어 보면
"모델이 어떤 단어를 긍정/부정의 증거로 배웠는지"가 그대로 보입니다.
level00 에서 손으로 만들던 키워드 규칙을, 이제는 데이터가 만들어 줍니다.

## 3. 핵심 개념

### 3-1. 파이프라인 전체 그림

```
리뷰 텍스트 → [토큰화·벡터화: TF-IDF] → 숫자 벡터 → [로지스틱 회귀] → 긍정 확률
```

새로 배우는 부품은 없습니다. level04 의 TF-IDF 가 텍스트를 벡터로 바꾸고,
lecture06 에서 배운 로지스틱 회귀가 벡터를 분류합니다. NLP 실무의 상당수가
이런 "기존 부품의 조립"입니다.

### 3-2. 학습/평가 분리 — 시험 문제를 미리 보여 주지 않기

전체 데이터를 학습용과 평가용으로 나눕니다(lecture06 level04 복습).
텍스트에서 특히 중요한 규칙: **TF-IDF 의 어휘 사전과 IDF 는 학습 데이터로만
만들고, 평가 데이터에는 적용만** 해야 합니다. 평가 데이터까지 넣어 어휘를
만들면 미래 정보가 새는 것(데이터 누수)이고, 실전 성능을 부풀리게 됩니다.
sklearn 의 `fit_transform`(학습용)과 `transform`(평가용) 구분이 바로 이것입니다.

### 3-3. 계수 해석 — 모델의 채점 기준표 열어 보기

학습된 로지스틱 회귀의 계수(coefficient)는 단어마다 하나씩입니다.

- 계수가 큰 양수 → 그 단어가 있으면 긍정 확률이 올라감 (긍정의 증거)
- 계수가 큰 음수 → 부정의 증거
- 0 근처 → 판정에 거의 무관한 단어

계수 상위/하위 단어를 뽑아 보면 "빨라서, 친절, 만족"과 "실망, 고장, 느려"가
양쪽에 정렬됩니다. 이 목록 자체가 훌륭한 보고서 재료입니다 — "부정 리뷰를
이끄는 최다 요인은 배송 지연 관련 표현"처럼요.

### 3-4. 확률로 읽기 — 확신도까지 활용하기

로지스틱 회귀는 0/1 이 아니라 **긍정일 확률**을 내놓습니다. 0.98 은 확실한
긍정, 0.52 는 애매한 리뷰입니다. 실무에서는 이 확신도로 업무를 나눕니다:
확실한 것은 자동 처리, 0.4~0.6 구간의 애매한 것만 사람이 검토. 이렇게 하면
검토 인력을 크게 줄이면서 품질을 지킬 수 있습니다.

### 3-5. 이 모델의 한계

단어 가방 기반이므로 "안 좋아요"의 '안'이 '좋아요'와 별개 토큰으로 계산되고,
반어("좋다고 해서 샀는데…")는 여전히 어렵습니다. 훈련 데이터에 없던 표현도
못 다룹니다. 그래도 균질한 도메인(한 쇼핑몰의 리뷰)에서는 이 단순한 모델이
놀랄 만큼 잘 동작하며, 더 복잡한 모델을 쓸지는 "이 기준선을 얼마나 이기는가"로
결정하는 것이 정석입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1] 데이터 준비**: hjh_data.review_corpus 600건을 불러 긍/부정 비율을
  확인하고 학습 480건 / 평가 120건으로 분리합니다 (seed 고정).
- **[2] 벡터화**: 학습 데이터로만 TfidfVectorizer 를 fit 하고, 어휘 크기를
  출력합니다. 평가 데이터는 transform 만 합니다.
- **[3] 학습과 평가**: 로지스틱 회귀를 학습하고 정확도와 혼동 행렬을
  출력합니다.
- **[4] 채점 기준표 공개**: 계수 상위 8개(긍정 증거)와 하위 8개(부정 증거)
  단어를 표로 출력합니다. 모델이 무엇을 배웠는지 눈으로 확인하는 핵심 장면입니다.
- **[5] 새 리뷰 판정**: 학습에 없던 문장 4개를 넣어 긍정 확률과 판정 근거
  단어(그 문장에서 계수가 큰 단어)를 함께 출력합니다. "왜 그렇게 판단했나"에
  답하는 리포트 형식입니다.

## 6. 자주 하는 실수

- **평가 데이터까지 fit**: `fit_transform` 을 전체 데이터에 걸면 데이터
  누수입니다. 학습에만 fit, 평가는 transform.
- **정확도만 보고 끝내기**: 클래스 비율이 기울어진 실제 데이터에서는 혼동
  행렬과 클래스별 지표(lecture06 level06)를 꼭 함께 보세요.
- **계수 해석을 인과로 확대**: "친절 계수가 크다"는 "친절이라는 단어가 긍정
  리뷰에 자주 나왔다"이지, 친절 캠페인을 하면 매출이 오른다는 인과 증명이
  아닙니다.
- **훈련 도메인 밖에서 그대로 사용**: 쇼핑몰 리뷰로 학습한 모델을 앱스토어
  리뷰에 그대로 쓰면 성능이 뚝 떨어집니다. 도메인이 바뀌면 재학습이 기본입니다.
