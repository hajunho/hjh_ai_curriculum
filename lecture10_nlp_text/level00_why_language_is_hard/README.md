# Lecture 10 · Level 00 — 컴퓨터가 언어를 다루는 어려움

> 숫자는 잘 다루는 컴퓨터가 왜 문장 앞에서는 헤매는지, 실패 사례를 직접 돌려 보며 체감합니다.
**난이도** ⭐ / **선행** 없음 (lecture02 의 문자열 기초가 있으면 좋습니다) / **예상 시간** 25분

## 1. 왜 배우나 — 비즈니스 관점

회사 데이터의 대부분은 표가 아니라 **글**입니다. 고객 리뷰, 상담 기록, 이메일, 계약서,
회의록 — 업계에서는 전체 데이터의 80% 이상이 이런 비정형 텍스트라고 말합니다.
매출 표는 엑셀로 합계를 내면 되지만, "고객이 배송에 불만이 많은가?"라는 질문은
글을 읽어야 답할 수 있습니다. 사람이 다 읽기엔 너무 많고, 컴퓨터에게 시키자니
컴퓨터는 글을 '이해'하지 못합니다.

이 레벨의 목표는 기술을 배우기 전에 **문제의 크기를 정확히 아는 것**입니다.
"검색창에 단어만 넣으면 되는 거 아냐?"라고 생각했던 분이, 단순 문자열 매칭이
어디서 어떻게 무너지는지 직접 확인하고 나면, 이후 11개 레벨에서 배울 도구들이
왜 필요한지 저절로 납득됩니다.

## 2. 비유로 이해하기

컴퓨터에게 언어란, **한국어를 한 마디도 모르는 외국인 신입사원에게 사전 한 권만
쥐여 주고 고객 상담을 시키는 것**과 같습니다.

이 신입사원은 사전 찾기(문자열 매칭)는 완벽합니다. "환불"이라는 글자가 문서에
있는지 0.001초 만에 찾아냅니다. 그런데:

- 고객이 "돈 돌려주세요"라고 쓰면 못 찾습니다. 사전에 '환불'과 '돈 돌려주기'가
  같은 뜻이라는 연결이 없기 때문입니다. (**동의어 문제**)
- "눈이 아프다"가 몸의 눈인지, 눈(雪)을 너무 봐서인지 구분하지 못합니다.
  같은 글자가 여러 뜻을 가질 수 있다는 사실 자체를 모릅니다. (**중의성 문제**)
- "배송 빠르네요 ㅎㅎ 다신 안 삽니다"처럼 앞뒤 문맥이 뒤집는 문장에서는
  '빠르네요'만 보고 칭찬으로 분류합니다. (**문맥 문제**)
- "존맛탱", "가심비" 같은 말은 사전에 아예 없습니다. (**신조어 문제**)

앞으로 배울 NLP(자연어처리, Natural Language Processing)는 이 신입사원에게
'사전 찾기'를 넘어 '말의 쓰임새'를 통계적으로 가르치는 과정입니다.

## 3. 핵심 개념

### 3-1. 중의성(ambiguity) — 같은 글자, 다른 뜻

한국어 "눈"은 신체의 눈(eye)이기도 하고 하늘에서 내리는 눈(snow)이기도 합니다.
"밤"은 시간(night)이자 먹는 밤(chestnut)입니다. 사람은 문장을 보는 순간
자동으로 구분하지만, 문자열 매칭에게 두 "눈"은 완전히 동일한 바이트열입니다.

| 문장 | 사람의 해석 | 문자열 매칭의 해석 |
|---|---|---|
| 눈이 펑펑 내린다 | 눈(snow) | "눈" 발견 (구분 불가) |
| 눈이 침침하다 | 눈(eye) | "눈" 발견 (구분 불가) |

뜻을 가르는 단서는 글자가 아니라 **주변 단어(문맥)** 에 있습니다. "내린다"가 오면
snow, "침침하다"가 오면 eye. 이 직관 — *단어의 뜻은 주변 단어가 결정한다* — 은
level06 워드 임베딩의 이론적 뿌리(분포 가설)가 됩니다.

### 3-2. 문맥과 반어 — 부분의 합이 전체가 아니다

"좋다"라는 단어가 있다고 긍정 리뷰가 아닙니다.

- "품질이 좋다" → 긍정
- "품질이 좋다고 해서 샀는데 완전 실망" → 부정
- "안 좋다" → 부정 (겨우 두 글자 차이)

단어를 낱개로 세는 방식(level04 의 BoW)은 이 지점에서 한계를 드러내고,
순서와 문맥을 보는 모델(level07 RNN, level08 어텐션)이 그 한계를 메웁니다.

### 3-3. 한국어는 교착어 — 단어가 변신한다

영어는 단어 사이가 공백으로 깔끔하게 나뉘고 형태 변화가 적습니다.
한국어는 **교착어(agglutinative language)** 라서 어근 뒤에 조사와 어미가
착착 달라붙으며 표면 형태가 계속 바뀝니다.

"먹다"라는 하나의 동사가 실제 문장에서는 이렇게 나타납니다:
먹었다, 먹는다, 먹었습니다, 먹고, 먹어서, 먹으니까, 먹었는데요...

컴퓨터 입장에서 이들은 전부 **서로 다른 문자열**입니다. "먹다"로 검색하면
"먹었습니다"는 안 잡힙니다. 명사도 마찬가지입니다 — "배송이", "배송은",
"배송을", "배송도"는 모두 '배송'이라는 같은 개념이지만 문자열로는 4종류입니다.
이것이 한국어 NLP 에서 형태소 분석(level03)이 필수인 이유입니다.

### 3-4. 언어는 계속 태어난다

2015년의 사전에는 "가심비"도 "갓생"도 없었습니다. 어떤 규칙집을 만들어도
언어는 그 규칙집보다 빨리 변합니다. 그래서 현대 NLP 는 규칙을 사람이 적는 대신
**데이터에서 패턴을 학습**하는 쪽(lecture06 에서 배운 머신러닝의 철학)으로
방향을 틀었고, 모르는 단어도 조각으로 쪼개 다루는 서브워드 방식(level03)을
발명했습니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

main.py 는 "단순 문자열 매칭 상담봇"을 만들어 놓고 일부러 무너뜨리는 시연입니다.

- **[1] 동의어 실패**: "환불" 키워드 검색이 "돈 돌려주세요"를 놓치는 장면.
  6건의 실제 환불 요청 중 몇 건을 찾는지 적중률을 출력합니다.
- **[2] 중의성 실패**: '눈'이 든 문장 6개를 놓고, 문자열 매칭은 전부 동일하게
  취급하지만 주변 단어 힌트로는 eye/snow 가 갈린다는 것을 보여 줍니다.
- **[3] 감성 키워드의 배신**: "좋다/최고" 키워드로 긍정을 판정하는 규칙이
  부정 문장("좋다고 해서 샀는데 실망")을 오분류하는 혼동 사례를 표로 출력합니다.
- **[4] 교착어 실험**: "배송" 정확히 일치 검색 vs 부분 포함 검색이 조사 붙은
  형태("배송이", "배송은"...)를 어떻게 다르게 처리하는지, 그리고 부분 포함조차
  "재배송"같은 다른 단어를 끌어들이는 부작용을 보여 줍니다.

핵심 코드는 `keyword_match(text, keywords)` 한 줄짜리 함수입니다. 이 단순한
함수가 어디까지 통하고 어디서 무너지는지가 이 레벨의 전부입니다. 마지막 출력
[5]에서는 각 실패가 이 강의의 몇 레벨에서 해결되는지 로드맵을 인쇄합니다.

   이것이 규칙 기반 접근의 본질적 한계입니다.

## 6. 자주 하는 실수

- **"검색 잘 되던데?"** — 구글이나 사내 검색이 잘 되는 것은 뒤에서 형태소 분석,
  동의어 사전, 임베딩이 돌고 있기 때문입니다. 순수 문자열 매칭이 아닙니다.
- **부분 문자열 포함(`in`)을 만능으로 여기기** — "배송"이 "재배송", "배송비"에도
  걸립니다. 넓게 잡으면 엉뚱한 것이 들어오고, 좁게 잡으면 필요한 것을 놓칩니다.
- **대소문자·공백을 잊기** — "AS신청"과 "as 신청"과 "A/S 신청"은 모두 다른
  문자열입니다. 다음 레벨(전처리)에서 정면으로 다룹니다.
- **한국어와 영어 NLP 를 같은 난이도로 생각하기** — 공백 분리로 어지간히 되는
  영어와 달리, 한국어는 조사·어미 처리를 건너뛰면 성능이 크게 떨어집니다.
