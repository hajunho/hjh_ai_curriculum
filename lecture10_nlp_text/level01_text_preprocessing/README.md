# Lecture 10 · Level 01 — 텍스트 전처리 기초

> 지저분한 리뷰 텍스트를 분석 가능한 상태로 만드는 정제 파이프라인을 단계별로 만듭니다.
**난이도** ⭐⭐ / **선행** level00 / **예상 시간** 35분

## 1. 왜 배우나 — 비즈니스 관점

텍스트 분석 프로젝트에서 시간의 대부분은 모델링이 아니라 **청소**에 들어갑니다.
고객이 남긴 리뷰에는 이모티콘, 반복 문자("좋아요오오오"), URL, 전각 문자,
대소문자 섞인 영어("AS", "as", "A/S")가 뒤섞여 있습니다. 이걸 그대로 세면
"좋아요"와 "좋아요오오"가 다른 단어로 집계되어 통계가 전부 어긋납니다.

전처리는 화려하지 않지만 효과는 확실합니다. 같은 모델이라도 전처리 품질에 따라
분류 정확도가 몇 %p 씩 오르내리는 일이 흔하고, 무엇보다 **집계 결과를 보고서에
쓸 수 있는 수준**으로 만들어 줍니다. "이번 달 최다 언급 키워드: ㅋㅋㅋㅋ" 같은
리포트를 낼 수는 없으니까요.

## 2. 비유로 이해하기

전처리는 **요리 전의 재료 손질**입니다. 시장에서 사 온 채소(원본 텍스트)에는
흙(특수문자)이 묻어 있고, 크기가 제각각(대소문자·전각/반각)이고, 먹지 않는
뿌리와 겉잎(불용어)이 붙어 있습니다. 어떤 요리(분석)를 하든 손질은 거의 항상
같은 순서로 진행됩니다: 씻고 → 다듬고 → 크기를 맞추고 → 못 쓰는 부분을 버린다.

중요한 것은 **손질은 요리에 따라 달라진다**는 점입니다. 국물용 멸치는 머리를
떼지만 볶음용은 그대로 씁니다. 마찬가지로 감성 분석에서는 "!!!" 가 소중한
신호(강한 감정)일 수 있어서 무조건 지우면 안 되고, 키워드 집계에서는 지우는 게
맞습니다. "표준 전처리"란 없고 "목적에 맞는 전처리"만 있습니다.

## 3. 핵심 개념

### 3-1. 정규화(normalization) — 같은 것은 같게 만들기

표기만 다르고 뜻이 같은 것들을 하나로 모읍니다.

| 처리 | 예시 |
|---|---|
| 소문자화 | "AS센터", "as센터" → "as센터" |
| 공백 정리 | "배송  이  " → "배송 이" (연속 공백, 앞뒤 공백 제거) |
| 반복 문자 축약 | "좋아요오오오", "ㅋㅋㅋㅋㅋ" → "좋아요오", "ㅋㅋ" |
| 특수문자 처리 | "★강추★" → "강추" (단, 목적에 따라 보존 여부 결정) |

영어의 소문자화(lowercasing)에 해당하는 한국어 작업이 반복 문자 축약과
자모 표현 정리("ㅎㅎㅎ", "ㅠㅠㅠ")입니다.

### 3-2. 불용어(stopword) 제거 — 신호가 없는 단어 버리기

"그리고", "정말", "너무" 같은 단어는 거의 모든 문장에 나오기 때문에 문서를
구분하는 힘이 없습니다. 이런 단어를 불용어라 부르고, 집계나 검색에서 제외합니다.

주의할 점 두 가지:
- 불용어 목록은 **도메인마다 다릅니다**. 쇼핑 리뷰에서 "상품"은 사실상 불용어지만
  일반 뉴스에서는 아닙니다.
- 감성 분석에서 "안", "못" 같은 부정어를 불용어로 지우면 "안 좋아요"가
  "좋아요"가 되어 버립니다. 뭘 지울지는 항상 목적과 함께 결정합니다.

### 3-3. 한국어에서 특히 조심할 점 — 조사

영어 전처리 튜토리얼을 그대로 따라 하면 한국어에서 사고가 납니다.
가장 큰 함정이 조사입니다. "배송이 빠르다"를 공백으로 나누면 "배송이"라는
어절이 나오는데, 여기서 조사 "이"를 떼지 않으면 "배송이/배송은/배송을"이
서로 다른 단어로 집계됩니다.

이 레벨에서는 자주 나오는 조사("이/가/은/는/을/를/도/에/의/로" 등)를 어절
끝에서 떼어 내는 **간이 규칙**을 사용합니다. 이 규칙은 "구두쇠"의 '쇠'처럼
조사가 아닌 글자를 오인하는 한계가 있으며(6장 참고), 제대로 된 해법인 형태소
분석은 level03 에서 다룹니다. 오늘은 "조사를 처리해야 집계가 맞는다"는 감각을
잡는 것이 목표입니다.

### 3-4. 파이프라인으로 생각하기

전처리는 단계들의 **정해진 순서**입니다. 순서가 바뀌면 결과가 달라집니다.
예를 들어 특수문자를 먼저 지우면 URL 제거 규칙("http 로 시작…")이 동작하지
않게 됩니다. 그래서 실무에서는 각 단계를 작은 함수로 만들고, 순서대로 이어붙인
파이프라인을 만들어 어떤 텍스트든 같은 순서로 통과시킵니다. 이렇게 하면
"3단계까지 처리한 결과"를 중간에서 꺼내 볼 수 있어 디버깅도 쉽습니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1] 오염 리뷰 생성**: hjh_data 의 리뷰에 이모티콘·URL·반복문자·잡공백을
  일부러 입혀 "현실적인" 지저분한 리뷰 8건을 만듭니다 (seed 고정).
- **[2] 단계별 정제**: 샘플 1건이 pipeline 의 5단계(소문자화·URL 제거 →
  특수문자 정리 → 반복 축약 → 공백 정리 → 불용어/조사 처리)를 통과할 때마다
  before/after 를 출력합니다. 텍스트가 점점 깨끗해지는 과정이 한눈에 보입니다.
- **[3] 전체 일괄 처리**: 8건 전부를 파이프라인에 통과시켜 원본→결과를 비교합니다.
- **[4] 전처리 전후 단어 집계 비교**: 같은 리뷰 뭉치로 단어 빈도 상위 8개를
  전처리 전/후로 뽑아 비교합니다. 전처리 전에는 "배송이"와 "배송은"이 따로 집계되던
  것이 후에는 "배송"으로 합쳐지는 것을 확인합니다.

코드의 핵심은 `PIPELINE = [(단계이름, 함수), ...]` 리스트입니다. 각 단계는
문자열을 받아 문자열을 돌려주는 순수 함수라서, 순서를 바꾸거나 단계를 빼는
실험을 리스트 수정만으로 할 수 있습니다.

## 5. 직접 해보기

1. **(쉬움)** `STOPWORDS` 에 "정말", "너무" 를 추가하고 [4]의 빈도 상위권이
   어떻게 바뀌는지 확인해 보세요.
2. **(보통)** 파이프라인에서 `collapse_repeats` 단계를 주석 처리하고 실행해
   "좋아요오오"가 집계를 어떻게 오염시키는지 확인한 뒤 되돌려 보세요.
3. **(도전)** 감정 신호 보존 버전을 만들어 보세요: "!"와 "ㅠ"를 지우는 대신
   각각 `<느낌표>` `<슬픔>` 토큰으로 치환하는 단계를 추가합니다.
   힌트: `re.sub(r"!+", " <느낌표> ", text)` 패턴을 응용하면 됩니다.

## 6. 자주 하는 실수

- **무조건 다 지우기**: 특수문자·이모티콘을 반사적으로 삭제하면 감정 신호가
  사라집니다. "지운다/보존한다/치환한다" 세 선택지를 항상 저울질하세요.
- **불용어 목록을 다른 도메인에서 복사**: 뉴스용 불용어를 리뷰에 쓰면 "기자",
  "보도" 같은 엉뚱한 단어가 들어 있고 정작 "상품"은 없습니다.
- **간이 조사 제거를 과신**: "구두쇠 → 구두", "사자 → 사"처럼 단어 끝 글자를
  조사로 오인할 수 있습니다. 간이 규칙은 어디까지나 임시 방편입니다 (level03 참고).
- **원본을 덮어쓰기**: 전처리 결과로 원본 컬럼을 덮어쓰면 규칙을 고쳤을 때
  되돌릴 수 없습니다. 원본은 항상 따로 보관하세요.
