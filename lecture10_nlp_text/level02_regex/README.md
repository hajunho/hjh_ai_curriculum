# Lecture 10 · Level 02 — 정규표현식

> 패턴 하나로 문서 더미에서 전화번호·이메일·금액을 자동 추출하는 검색 조건식을 배웁니다.
**난이도** ⭐⭐ / **선행** level01 / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

"이 계약서 30건에서 계약 금액과 담당자 연락처만 뽑아서 엑셀로 정리해 줘."
이런 업무를 손으로 하면 반나절, 정규표현식(regular expression, 정규식)으로 하면
5분입니다. 정규표현식은 "전화번호처럼 생긴 것", "금액처럼 생긴 것"을 한 줄의
패턴으로 표현해 컴퓨터가 대신 찾게 하는 기술입니다.

NLP 파이프라인 안에서도 쓰임이 많습니다. level01 의 URL 제거가 이미 정규식이었고,
개인정보 마스킹(전화번호를 010-****-**** 로), 날짜 표준화, 로그 파싱까지 —
텍스트를 다루는 곳이면 어디든 등장합니다. 엑셀의 찾기/바꾸기가 손전등이라면
정규식은 서치라이트입니다.

## 2. 비유로 이해하기

정규표현식은 **부동산 검색 조건식**과 같습니다. "역세권 & 방 2개 이상 & 월세
80 이하"라고 조건을 걸면 매물 수천 건에서 조건에 맞는 것만 걸러지듯,
정규식은 "숫자 3개 - 숫자 4개 - 숫자 4개"라는 조건을 걸어 텍스트에서
전화번호만 걸러 냅니다.

조건식을 이루는 부품은 세 종류뿐입니다.

- **무엇을**: 어떤 글자를 찾나 — `\d`(숫자), `[가-힣]`(한글), `.`(아무 글자)
- **몇 개나**: 몇 번 반복되나 — `+`(1개 이상), `*`(0개 이상), `{3}`(정확히 3개)
- **어디서**: 위치 조건 — `^`(줄 시작), `$`(줄 끝), `\b`(단어 경계)

이 세 부품의 조합이 전부입니다. 복잡해 보이는 패턴도 뜯어 보면
"무엇을 · 몇 개나 · 어디서"의 나열입니다.

## 3. 핵심 개념

### 3-1. 기본 문법 미니 표

| 패턴 | 뜻 | 예 |
|---|---|---|
| `\d` | 숫자 하나 | `\d\d\d` = 숫자 3개 |
| `\d{2,3}` | 숫자 2~3개 | 02 또는 031 |
| `[가-힣]+` | 한글 1글자 이상 | "홍길동" |
| `a|b` | a 또는 b | `원|달러` |
| `?` | 있어도 없어도 됨 | `-?` = 하이픈 선택 |
| `( )` | 그룹 묶기·부분 추출 | `(\d+)원` 에서 숫자만 |
| `\.` | 마침표 그 자체 | `.`는 특수문자라 `\` 필요 |

### 3-2. 실무 3대 패턴 — 전화번호·이메일·금액

**전화번호**: `0\d{1,2}-?\d{3,4}-?\d{4}`
— 0으로 시작하는 지역/휴대 번호, 하이픈은 있어도 없어도 매칭.

**이메일**: `[\w.]+@[\w.-]+\.[a-z]{2,}`
— @ 앞에 문자·점, 뒤에 도메인과 최상위 도메인(2글자 이상).
(참고: 이메일 형식의 국제 표준을 100% 커버하는 정규식은 지나치게 길어서,
실무에서는 이 정도의 "충분히 좋은" 패턴을 씁니다.)

**금액**: `\d{1,3}(?:,\d{3})+원?|\d+만\s?원|\d+원`
— "1,200,000원", "350만 원", "9900원" 같은 여러 표기를 `|`로 이어 붙입니다.
한국어 금액은 표기가 다양해 패턴도 여러 갈래가 필요합니다.

### 3-3. 파이썬 re 모듈의 4가지 동사

| 함수 | 하는 일 | 언제 |
|---|---|---|
| `re.search(p, s)` | 첫 매칭 1개 찾기 | 있는지 확인 |
| `re.findall(p, s)` | 모든 매칭 리스트 | 일괄 추출 |
| `re.sub(p, r, s)` | 매칭을 치환 | 마스킹·정제 |
| `re.compile(p)` | 패턴 재사용 준비 | 반복 사용 시 |

그룹 `( )` 을 쓰면 `findall` 이 그룹 안쪽만 돌려줍니다. "전체는 매칭하되
추출은 일부만" 할 때 유용하고, 그룹은 쓰되 추출에서 빼려면 `(?: )` (비캡처
그룹)를 씁니다.

### 3-4. 탐욕(greedy) 매칭 — 정규식 최대의 함정

`*` 와 `+` 는 기본적으로 **최대한 길게** 잡습니다. `"<민수> <영희>"` 에서
`<.*>` 는 `<민수>` 가 아니라 문자열 전체 `<민수> <영희>` 를 잡습니다.
"가능한 짧게"를 원하면 `<.*?>` 처럼 `?` 를 붙입니다(게으른 매칭).
치환 결과가 이상하게 뭉텅이로 사라졌다면 십중팔구 탐욕 매칭 때문입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

가상의 사내 문서(발주 확인 메일, 거래처 연락망, 정산 공지 — 코드 안에서 직접
작성한 창작 텍스트)를 재료로 4가지 실습을 합니다.

- **[1] 문법 워밍업**: `\d+`, `[가-힣]+`, `{n}` 반복 등 기본 부품을 짧은 예제로
  하나씩 확인합니다. 각 패턴이 무엇을 잡았는지 나란히 출력합니다.
- **[2] 정보 추출**: 문서 3건에서 전화번호·이메일·금액을 `findall` 로 일괄
  추출해 문서별로 정리해 출력합니다. 손으로 뽑던 일이 몇 줄로 끝납니다.
- **[3] 개인정보 마스킹**: `re.sub` 과 그룹 참조로 전화번호 가운데 자리를
  `****` 로 바꿉니다. 공개 자료 만들 때 바로 쓰는 실무 패턴입니다.
- **[4] 탐욕 매칭 사고 재현**: `<.*>` 와 `<.*?>` 의 결과를 비교해 탐욕 매칭이
  어떻게 데이터를 뭉텅이로 잡아먹는지 눈으로 확인합니다.

코드에서 눈여겨볼 부분은 `PATTERNS` 딕셔너리입니다. 패턴을 이름과 함께 한곳에
모아 두면, 나중에 "금액 패턴만 고치기" 같은 유지보수가 쉬워집니다.

## 6. 자주 하는 실수

- **`.` `+` `?` 를 글자 그대로 찾으려다 실패**: 특수문자를 찾을 땐 `\.` 처럼
  이스케이프하거나 `re.escape()` 를 쓰세요.
- **탐욕 매칭 방치**: `".*"` 로 치환했더니 문장 절반이 사라지는 사고.
  짧게 잡으려면 `.*?`.
- **패턴 과잉 설계**: 세상 모든 전화번호 형식을 한 패턴에 담으려다 아무도 못
  읽는 패턴이 됩니다. "우리 데이터에 실제로 나오는 형식"만 커버하고, 예외는
  로그로 남겨 나중에 추가하는 편이 낫습니다.
- **한글 범위 오해**: `[가-힣]` 은 완성형 음절만 잡습니다. "ㅋㅋ", "ㅠㅠ" 같은
  자모는 `[ㄱ-ㅎㅏ-ㅣ]` 를 따로 추가해야 합니다.
