# Lecture 10 · Level 07 — RNN 과 시퀀스 모델

> 순서를 기억하며 읽는 신경망(RNN)으로 다음 글자 예측 미니 언어모델을 학습시킵니다.
**난이도** ⭐⭐⭐⭐ / **선행** level06, lecture08(딥러닝 기초) / **예상 시간** 55분

## 1. 왜 배우나 — 비즈니스 관점

지금까지의 도구(BoW, TF-IDF, 임베딩)는 단어를 **봉지에 쏟아 넣고** 셌습니다.
그런데 언어의 절반은 순서입니다. "회사가 고객을 인수했다"와 "고객이 회사를
인수했다"는 단어 구성이 같아도 뜻이 정반대입니다. 순서를 다루지 못하면 계약서
해석도, 문장 생성도, 번역도 불가능합니다.

RNN(순환 신경망, Recurrent Neural Network)은 순서를 다루는 첫 번째 본격적인
신경망입니다. 챗봇의 자동완성, 음성 인식, 기계번역의 초기 전성기를 이끌었고,
지금은 트랜스포머에게 왕좌를 넘겼지만 — "이전까지 읽은 내용을 상태로 요약해
들고 간다"는 핵심 아이디어와 그 한계(장기 의존성)를 이해해야, 트랜스포머가
**무엇을 해결한 것인지**를 알 수 있습니다. 이 레벨은 그 징검다리입니다.

## 2. 비유로 이해하기

RNN 은 **릴레이 메모와 함께 문서를 읽는 사원들**입니다. 문서가 너무 길어서
사원 한 명이 한 단어씩만 읽기로 했다고 합시다. 1번 사원이 첫 단어를 읽고
지금까지의 요약을 **메모 한 장**에 적어 2번에게 넘깁니다. 2번은 그 메모와
두 번째 단어를 보고 메모를 갱신해 3번에게 넘기고... 마지막 사원의 메모가
문서 전체의 요약이 됩니다.

이 구조의 강점: 문서가 아무리 길어도 사원들은 "메모 + 단어 하나"만 처리하면
됩니다. 약점도 메모에 있습니다. 메모지는 크기가 정해져 있어서(고정 크기 은닉
상태), 문서 앞부분의 내용은 릴레이를 거치며 점점 흐려집니다. 100번째 사원의
메모에 1번 사원이 적은 내용이 얼마나 남아 있을까요? 이것이 **장기 의존성
(long-term dependency) 문제**입니다.

## 3. 핵심 개념

### 3-1. 순환 구조 — 수식은 한 줄

RNN 의 본체는 놀랄 만큼 단순합니다. 시점 $t$ 에서:

$$h_t = \tanh(W_x x_t + W_h h_{t-1} + b)$$

$x_t$ 는 지금 읽는 토큰(의 임베딩), $h_{t-1}$ 은 직전까지의 메모(은닉 상태,
hidden state), $h_t$ 는 갱신된 메모입니다. 같은 가중치 $W$ 를 모든 시점에
재사용하는 것이 핵심입니다 — 사원이 100명이어도 "메모 갱신 요령"은 하나입니다.

### 3-2. 언어모델 — "다음에 올 것"을 맞히는 게임

언어모델(language model)은 "지금까지의 글을 보고 다음 토큰을 예측"하는
모델입니다. "오늘 점심은 김치___" 다음에 '찌개'가 올 확률이 높다고 아는 것.
이 단순한 게임이 중요한 이유는, 잘하려면 문법·어휘·상식이 전부 필요하기
때문입니다. GPT 의 G(Generative)가 바로 이 게임의 챔피언이라는 뜻이고,
오늘 우리는 글자 단위의 초미니 버전을 만듭니다.

학습 방법: 문장 "어제 학생이"가 있으면 입력 "어제 학생"에 대해 정답
"제 학생이"(한 글자씩 민 것)를 맞히게 합니다. 시점마다 다음 글자를 맞히는
분류 문제가 되어, lecture08 에서 배운 교차 엔트로피 손실로 학습합니다.

### 3-3. 장기 의존성 — 릴레이 메모의 한계

"내가 어제 백화점에서 산, 파란 상자에 담긴, 스위스제 ___" 에서 빈칸을 맞히려면
문장 맨 앞의 정보가 필요할 수 있습니다. RNN 은 역전파 때 기울기가 시점 수만큼
곱해지며 **소실(vanishing)** 되어, 먼 과거로 학습 신호가 거의 전달되지
않습니다. 이를 완화한 개량형이 LSTM/GRU(게이트로 메모를 선택적으로 보존)이며,
근본적으로 해결한 것이 "모든 시점을 직접 연결"하는 어텐션(level08)입니다.

### 3-4. 생성 — 온도(temperature)라는 다이얼

학습된 언어모델로 글을 만들 때는 예측 확률분포에서 다음 글자를 뽑고, 그것을
다시 입력에 붙여 반복합니다. 이때 분포를 얼마나 "뾰족하게" 쓸지 조절하는
다이얼이 온도입니다. 낮으면 가장 확률 높은 글자만 뽑아 안전하고 단조로운 글,
높으면 다양하지만 엉뚱한 글이 나옵니다. LLM API 의 temperature 파라미터가
정확히 이것입니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

tiny_corpus 일부(약 2만 자)로 글자 단위 RNN 언어모델을 학습합니다.
CPU 에서 몇 초면 끝나도록 작게 설계했습니다.

- **[1] 데이터 준비**: 글자 사전을 만들고 (어휘 수십 종), 텍스트를 정수
  시퀀스로 바꿉니다. "입력을 한 글자 민 것이 정답"인 학습쌍 구성을 출력합니다.
- **[2] 모델 조립**: 임베딩 → `nn.RNN` → 출력층. 파라미터 수를 출력합니다.
- **[3] 학습**: 학습 전(무작위 글자 나열)과 학습 후의 생성문을 비교합니다.
  loss 가 내려가면서 생성문이 "말이 되어 가는" 과정을 3단계로 보여 줍니다.
- **[4] 다음 글자 예측 확인**: "학생이 보고서를 만들" 뒤에 올 글자의 확률
  상위 3개를 출력합니다 — '었'이 1위로 올라오는지 확인합니다.
- **[5] 온도 실험**: 온도 0.3/1.5 의 생성문을 비교하고, 릴레이 메모 구조가
  가진 장기 의존성 한계를 정리하는 메모로 마무리합니다.

## 6. 자주 하는 실수

- **글자/토큰 사전 불일치**: 학습 때의 글자→번호 사전을 생성 때도 그대로
  써야 합니다. 사전을 다시 만들면 번호가 뒤섞여 헛소리가 나옵니다.
- **생성이 이상하다고 바로 모델 탓**: 온도, 프롬프트, 학습량부터 점검하세요.
  이 미니 모델은 데이터가 작아 완벽한 문장을 기대하면 안 됩니다 — "구조가
  잡혀 가는가"를 보는 실험입니다.
- **hidden state 초기화 잊기**: 서로 다른 문장을 이어 학습할 때 상태를 끊지
  않으면 앞 문장의 기억이 새 문장에 새어 듭니다.
- **RNN 을 지금 실전에 투입**: 2026년 현재 시퀀스 실무의 기본값은
  트랜스포머입니다. RNN 은 "왜 트랜스포머인가"를 이해하기 위해 배웁니다.
