# Lecture 10 · Level 03 — 토큰화와 한국어의 특수성

> 문장을 어떤 단위로 쪼갤 것인가 — 공백·음절·n-gram·형태소·서브워드 전략을 직접 만들어 비교합니다.
**난이도** ⭐⭐⭐ / **선행** level01, level02 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

모든 텍스트 분석은 "문장을 무슨 단위로 셀 것인가"라는 결정에서 시작합니다.
이 단위를 토큰(token)이라 하고, 쪼개는 작업을 토큰화(tokenization)라 합니다.
토큰화를 어떻게 하느냐에 따라 검색 품질, 분류 정확도, 키워드 통계가 전부
달라집니다. 사내 검색에서 "배송"을 쳤는데 "배송이 늦다"가 안 나온다면
십중팔구 토큰화 문제입니다.

그리고 이것은 LLM 요금 고지서와도 직결됩니다. GPT 계열 API 는 토큰 수로
과금하는데, 같은 내용이라도 한국어는 영어보다 토큰이 많이 나오는 경향이
있습니다. 왜 그런지가 바로 이 레벨의 마지막 주제(서브워드)에서 밝혀집니다.

## 2. 비유로 이해하기

토큰화는 **김밥을 써는 일**입니다. 같은 김밥 한 줄도 어떻게 써느냐에 따라
쓸모가 달라집니다.

- **통째로**(문장 단위): 들고 다니긴 좋지만 나눠 먹기 어렵습니다.
- **한 입 크기**(어절/단어 단위): 대부분의 경우 적당합니다.
- **아주 잘게**(음절/문자 단위): 누구나 먹을 수 있지만 김밥 맛(의미)이 흩어집니다.
- **재료별로 해체**(형태소 단위): 단무지 따로 당근 따로 — 손은 가장 많이 가지만
  "이 김밥에 뭐가 들었나"를 정확히 알 수 있습니다.

영어는 재료 사이에 칼집(공백)이 미리 나 있는 김밥이라 썰기 쉽습니다.
한국어는 재료(어근)와 포장(조사·어미)이 붙어 말린 김밥이라, 칼집만 따라 썰면
포장까지 같이 씹게 됩니다.

## 3. 핵심 개념

### 3-1. 공백 토큰화 — 영어의 기본, 한국어의 함정

영어 "I love this product" 는 공백으로 나누면 거의 끝납니다.
한국어 "배송이 빨라서 좋았어요"를 공백으로 나누면 "배송이/빨라서/좋았어요" —
어절은 나오지만 "배송"과 "배송이"가 다른 토큰이 되는 문제(level00 에서 확인)가
그대로 남습니다. 한국어 어휘의 형태 변화 때문에 공백 토큰화만으로는 어휘
집합(vocabulary)이 불필요하게 커지고, 같은 개념이 흩어집니다.

### 3-2. 음절 토큰화와 n-gram — 단순하지만 의외로 강한

음절(문자) 단위로 쪼개면 "배/송/이/빨/라/서" — 미등록 단어(신조어) 문제가
사라집니다. 어떤 단어든 음절로는 항상 쪼개지니까요. 대신 토큰 하나의 의미가
너무 옅어집니다. '배' 한 글자는 배(ship)인지 배(pear)인지 배송의 일부인지
알 수 없습니다.

절충안이 **n-gram**: 연속한 n 개 음절을 겹쳐 가며 묶는 방식입니다.
"배송이" 의 2-gram 은 "배송, 송이". 의미 덩어리("배송")가 우연히 포착되면서도
미등록 단어에 강해서, 한국어 검색 엔진들이 오래 써 온 실전 기법입니다.
대신 토큰 수가 크게 늘고 "송이"같은 무의미한 조각도 섞입니다.

### 3-3. 형태소 분석 — 뜻의 최소 단위로 해체하기

형태소(morpheme)는 뜻을 가진 가장 작은 말의 단위입니다.
"배송이 빨라서 좋았어요"를 형태소로 나누면:

```
배송(명사) + 이(조사) + 빠르(형용사 어간) + 아서(어미) + 좋(형용사 어간) + 았(선어말어미) + 어요(어미)
```

이렇게 하면 "배송이/배송은/배송을"이 전부 "배송"으로 모이고, "빨라서/빠르고/
빠릅니다"가 "빠르-"로 모입니다. 집계·검색·분류 품질이 한 단계 올라갑니다.
실무에서는 형태소 분석기(Kiwi, MeCab 계열 등 오픈소스)가 대규모 사전과 통계
모델로 이 일을 합니다. 이 레벨에서는 그 원리를 체감하기 위해 소형 어휘 사전과
조사·어미 목록으로 **미니 규칙 기반 분석기**를 직접 만듭니다. 장난감이지만
"사전 + 규칙 + 가장 긴 일치 우선"이라는 실제 분석기의 뼈대는 같습니다.

### 3-4. 서브워드(BPE) — 최신 LLM 의 선택

형태소 분석은 언어마다 사전과 문법 규칙을 만들어야 합니다. 서브워드(subword)
방식은 발상을 뒤집습니다: 언어학 지식 없이, **데이터에서 자주 붙어 나오는 글자
쌍을 반복해서 병합**해 토큰 목록을 만듭니다. 이것이 BPE(Byte Pair Encoding)
알고리즘입니다.

1. 모든 단어를 음절로 쪼개 놓고 시작합니다.
2. 말뭉치에서 가장 자주 이웃하는 글자 쌍을 찾아 하나로 병합합니다. (예: "배"+"송" → "배송")
3. 원하는 어휘 크기가 될 때까지 2를 반복합니다.

자주 나오는 말은 긴 토큰 하나로, 드문 말은 짧은 조각 여러 개로 표현됩니다.
신조어도 조각으로는 항상 표현 가능하므로 미등록 단어 문제가 사라집니다.
GPT 계열이 이 방식을 쓰며, 학습 데이터에 한국어가 적으면 한국어 병합 규칙이
덜 만들어져 **같은 문장도 토큰이 잘게 쪼개지고 요금이 늘어나는** 현상이
생깁니다.

## 4. 실습 — main.py

실행:

```bash
python3 main.py
```

- **[1] 토큰화 4종 비교**: 같은 리뷰 문장을 공백/음절/2-gram/미니 형태소
  분석기로 쪼개 토큰 목록과 개수를 나란히 출력합니다.
- **[2] 미니 형태소 분석기 내부**: 소형 사전(명사·어간)과 조사·어미 목록으로
  어절을 "가장 긴 일치 우선"으로 해체하는 과정을 보여 줍니다.
- **[3] 어휘 크기 실험**: hjh_data 리뷰 60건을 전략별로 토큰화해 어휘 집합
  크기와 "배송 계열 어절이 몇 개의 토큰으로 흩어지는지"를 비교합니다.
  형태소 방식이 어휘를 얼마나 압축하는지 숫자로 확인합니다.
- **[4] 미니 BPE 학습**: 리뷰 말뭉치에서 BPE 병합 규칙을 40회 학습하며,
  병합이 진행될수록 "배송", "포장" 같은 의미 단위가 저절로 생겨나는 과정을
  단계별로 출력합니다. 마지막에 처음 보는 단어("초고속배송")가 조각으로
  표현되는 것을 확인합니다.

   줄지만 어휘 크기는 커집니다 — 이 트레이드오프가 실제 토크나이저 설계의

## 6. 자주 하는 실수

- **영어 튜토리얼의 `split()` 을 한국어에 그대로 사용**: 동작은 하지만 조사가
  붙은 어절이 전부 다른 토큰이 되어 성능이 조용히 나빠집니다. 에러가 안 나서
  더 위험합니다.
- **미니 규칙 분석기를 실전에 투입**: 이 레벨의 분석기는 교육용입니다. 실무는
  검증된 형태소 분석기를 쓰되, 오늘 배운 원리로 그 출력을 점검할 수 있어야
  합니다.
- **토큰화와 전처리 순서 혼동**: 특수문자 정리(level01) 전에 토큰화하면
  "좋아요!!!" 같은 토큰이 생깁니다. 정제 → 토큰화 순서를 지키세요.
- **어휘 크기를 확인하지 않기**: 토큰화 전략을 바꿨으면 어휘 집합 크기와 상위
  빈도 토큰을 꼭 눈으로 확인하세요. 이상한 토큰이 상위권에 있다면 전략이 잘못된
  것입니다.
