# Lecture 01 · Level 11 — 원격 서버·클라우드·GPU 환경

> ssh 로 남의 컴퓨터를 빌려 쓰는 개념, GPU 가 AI 에 필수인 이유(병렬성), 클라우드 비용 감각을 배우고, 병렬 계산의 효과를 코드로 확인합니다.

**난이도** ⭐⭐⭐⭐ / **선행** level02, level10 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

내 노트북으로 AI 모델을 학습시키면 며칠이 걸리는 작업이, 클라우드 GPU 서버에서는 몇 시간에 끝납니다. 그래서 AI 프로젝트의 실제 작업은 거의 전부 **원격 서버**에서 일어납니다. 개발자들이 "서버에 접속해서", "GPU 인스턴스를 띄워서", "A100 8장으로 이틀 돌렸어요" 같은 말을 하는 이유입니다.

비전공자에게 이 레벨이 중요한 이유는 **비용** 때문입니다. 클라우드 GPU 는 시간당 과금이라, "며칠 돌리느냐"가 바로 예산이 됩니다. 고성능 GPU 서버는 시간당 수만 원대여서, 잘못 계획한 실험 하나가 수백만 원을 태울 수 있고, 반대로 개념을 아는 관리자는 "더 작은 GPU 로 짧게 실험해 보고 확정하자"는 판단으로 예산을 지킵니다. 이 레벨을 마치면 AI 프로젝트 견적서의 "GPU 비용" 항목을 읽을 수 있고, 병렬성이라는 GPU 의 본질을 코드로 체감하게 됩니다.

## 2. 비유로 이해하기

### 원격 서버 = 장비 좋은 공유 오피스

내 사무실(노트북)의 장비가 부족할 때, 회사는 장비 좋은 **공유 오피스의 자리를 시간 단위로 빌립니다**. 이것이 클라우드(cloud)입니다. 아마존(AWS)·구글(GCP)·마이크로소프트(Azure) 같은 회사가 거대한 건물(데이터센터)에 컴퓨터 수십만 대를 놓고 시간 단위로 빌려줍니다. 빌린 컴퓨터 한 대를 **인스턴스(instance)**라고 부릅니다.

**ssh(Secure Shell)는 그 공유 오피스로 연결되는 보안 전용 전화선**입니다. `ssh 계정@서버주소` 한 줄이면 원격 컴퓨터의 터미널이 내 화면에 나타나고, level02 에서 배운 명령들이 **그대로** 통합니다(원격 서버는 대부분 리눅스입니다 — 터미널을 배워 둔 보람이 여기서 옵니다). 파일을 보낼 때는 택배 서비스인 `scp`(secure copy)를 씁니다: `scp 파일 계정@서버:/경로`. 비밀번호 대신 **열쇠 파일(ssh 키)**로 출입하는 것이 표준이며, 이 열쇠 역시 level09 의 원칙대로 코드·저장소에 넣지 않습니다.

### CPU 와 GPU = 박사 4명과 아르바이트생 4천 명

- **CPU** 는 **박사급 전문가 몇 명**(코어 4~16개)입니다. 어떤 복잡한 문제든 풀 수 있고 개별 속도도 빠르지만, 인원이 적습니다.
- **GPU(그래픽처리장치)** 는 **단순 계산 아르바이트생 수천 명**입니다. 한 명 한 명은 단순한 산수만 하지만, 수천 명이 **동시에** 계산합니다.

봉투에 전단지 넣기 100만 장을 시킨다면 누가 이길까요? 압도적으로 아르바이트생 군단입니다. 그리고 AI 학습이 바로 이런 일입니다 — 수백만 개의 숫자를 곱하고 더하는 **단순 계산의 무한 반복**(행렬 곱셈). 원래 게임 화면의 픽셀 수백만 개를 동시에 칠하려고 만든 GPU 가, 같은 구조의 계산인 AI 학습에 딱 맞았던 것입니다. 핵심 단어는 **병렬성(parallelism)** — 일을 쪼개 여러 일꾼이 동시에 하는 것입니다.

## 3. 핵심 개념

### 3-1. 원격 작업의 기본 흐름

```bash
ssh myname@203.0.113.10       # 1) 보안 전화선으로 서버 접속
git clone <저장소주소>         # 2) 코드는 GitHub 를 경유해 가져오고 (level07!)
scp data.csv myname@서버:~/    # 3) 데이터 파일은 scp 로 직접 전송
python3 train.py               # 4) 서버의 터미널에서 실행 (level02 명령 그대로)
```

주의할 점 하나: ssh 접속이 끊기면 실행 중이던 프로그램도 함께 죽습니다. 그래서 실무에서는 접속이 끊겨도 작업이 계속되게 하는 도구(tmux, nohup 등)를 함께 씁니다 — "이런 도구가 필요해지는 이유"까지만 알아 두면 충분합니다.

### 3-2. 왜 AI 는 GPU 인가 — 숫자로 보기

AI 모델의 학습은 본질적으로 행렬 곱셈(수많은 곱하기·더하기)의 반복입니다. 이 계산은 서로 **의존성이 없어서** 1만 개로 쪼개 1만 명에게 동시에 시킬 수 있습니다. CPU 코어 8개 대 GPU 코어 수천 개의 병렬성 차이가, 실전에서 "며칠 대 몇 시간"의 차이를 만듭니다. 반대로 쪼갤 수 없는 일(앞 단계의 결과가 있어야 다음 단계를 하는 일)은 GPU 가 오히려 느립니다. **"쪼갤 수 있는 일인가"가 GPU 활용의 판단 기준**입니다.

### 3-3. 클라우드 비용 감각

클라우드 과금의 3원칙만 기억하세요.

1. **시간당 과금**: 인스턴스는 켜져 있는 동안 계속 과금됩니다. **끄는 것을 잊는 것**이 초보자 지출 사고 1위입니다.
2. **GPU 등급 차이가 큼**: 실습용 소형 GPU(시간당 수백~수천 원)와 최상급 학습용 GPU(시간당 수만 원)는 수십 배 차이입니다. 실험은 작은 장비로, 확정된 학습만 큰 장비로.
3. **부대 비용**: 저장 용량, 데이터 전송(특히 데이터센터 밖으로 나가는 트래픽)에도 요금이 붙습니다.

간단 견적 연습: 시간당 3만 원짜리 GPU 인스턴스로 48시간 학습하면 144만 원. 사전 실험을 시간당 1천 원짜리로 두 번(각 3시간) 해서 설정 실수를 미리 잡으면 6천 원으로 144만 원짜리 재실험을 예방하는 셈입니다.

### 3-4. 병렬화의 한계 — 암달의 법칙 감각

일의 일부는 반드시 순차적입니다(데이터 읽기, 결과 취합 등). 전체의 20%가 순차 작업이면, 일꾼을 무한히 늘려도 5배 이상 빨라질 수 없습니다. 이를 암달의 법칙(Amdahl's law)이라 부릅니다. "일꾼을 2배로 늘리면 2배 빨라진다"가 항상 성립하지는 않는다는 감각 — 인력 투입과 마감의 관계와 똑같습니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

GPU 없이, 여러분 CPU 의 코어 몇 개만으로 **병렬성의 효과**를 직접 측정합니다.

- **[1] 일감 준비**: "소수(prime) 개수 세기"라는 쪼개기 좋은 계산 일감을 만듭니다. seed 고정으로 매번 같은 일감입니다.
- **[2] 혼자 일하기**: 한 명(단일 프로세스)이 전체 구간을 처리하는 시간을 잽니다.
- **[3] 나눠 일하기**: 구간을 여러 조각으로 쪼개 여러 일꾼(멀티프로세스)에게 동시에 맡기고 시간을 잽니다.
- **[4] 성적표**: 두 방식의 시간·배속을 비교하고, 코어 수만큼 정확히 비례하지 않는 이유(일꾼 소집 비용, 순차 구간)를 해설합니다.
- **[5] GPU 로의 확장**: "이 원리에서 일꾼이 수천 명이 되면 GPU"라는 연결, 그리고 클라우드 견적 예시를 출력합니다.

핵심 코드는 `concurrent.futures.ProcessPoolExecutor` 사용부입니다. `executor.map(작업함수, 조각들)` 한 줄로 "일감을 나눠 동시에 시키기"가 됩니다. 여기서 **일감을 쪼갤 수 있었기에 병렬화가 가능했다**는 점이 GPU·AI 로 이어지는 핵심 통찰입니다.

## 6. 자주 하는 실수

- **인스턴스 끄기를 잊음**: 클라우드 지출 사고 1위입니다. 작업 종료 = 인스턴스 중지를 한 세트로 습관화하고, 예산 알림을 설정하세요.
- **처음부터 최고급 GPU**: 설정 실수·코드 버그는 작은 장비에서도 똑같이 발견됩니다. 실험은 싸게, 본 학습만 비싸게.
- **ssh 키를 저장소에 커밋**: 열쇠 파일(`id_rsa` 등)이 유출되면 서버 전체가 열립니다. level09 원칙은 키 파일에도 적용됩니다.
- **모든 작업에 병렬화 시도**: 쪼갤 수 없는 순차 작업은 병렬화해도 빨라지지 않고 코드만 복잡해집니다. "쪼갤 수 있는가"를 먼저 물으세요.
