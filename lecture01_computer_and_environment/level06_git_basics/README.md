# Lecture 01 · Level 06 — Git: 버전 관리의 개념

> "최종_진짜최종.xlsx" 를 끝내는 도구 Git 의 핵심 개념(스냅샷·커밋·브랜치)을 결재와 시간여행에 비유해 이해하고, 실제 git 명령으로 실습합니다.

**난이도** ⭐⭐ / **선행** level02 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

이런 폴더를 본 적이 있을 것입니다. `제안서_v1.docx`, `제안서_v2_수정.docx`, `제안서_최종.docx`, `제안서_최종_진짜최종(부장님반영).docx`. 어느 것이 진짜 최종인지, v2 에서 무엇이 바뀌었는지, 누가 바꿨는지 아무도 모릅니다. 실수로 파일을 덮어쓰면 과거는 영영 사라집니다.

개발 세계는 이 문제를 20년 전에 해결했습니다. 그 도구가 **Git(깃)** 입니다. Git 은 파일들의 변경 이력을 전부 기록해 두어, 언제든 과거의 어느 시점으로 돌아갈 수 있고, 무엇이·언제·누구에 의해·왜 바뀌었는지 1분 안에 추적할 수 있게 해 줍니다. 코드만이 아니라 문서·설정·데이터 파이프라인까지, 오늘날 "만들어지는 모든 것"의 이력 관리 표준입니다. AI 프로젝트도 예외가 아니어서, 모델 코드·실험 설정의 이력이 전부 Git 위에서 관리됩니다. Git 을 모르면 개발팀과의 협업 대화 절반이 들리지 않습니다.

## 2. 비유로 이해하기

**커밋은 결재 도장, 저장소는 결재 서류함, 브랜치는 평행우주 시간여행**입니다.

- **저장소(repository)**: 프로젝트 폴더에 딸린 보이지 않는 결재 서류함(`.git` 폴더)입니다. `git init` 은 "이 폴더의 이력 관리를 시작합니다"라며 서류함을 설치하는 것입니다.
- **커밋(commit)**: 지금 이 순간의 폴더 전체 상태를 사진 찍어(스냅샷, snapshot) 결재 도장과 함께 서류함에 보관하는 행위입니다. 도장에는 일련번호(해시), 날짜, 담당자, 그리고 **결재 사유(커밋 메시지)**가 찍힙니다. "v1, v2 파일을 따로 만드는" 대신 "같은 파일의 상태를 시점별로 보관"하는 것입니다.
- **스테이징(staging)**: 결재 올리기 전, **결재판에 올릴 서류를 고르는 단계**입니다. `git add` 로 "이번 결재에는 이 파일들만 포함"이라고 선별합니다. 책상 위 서류 전부가 아니라 고른 것만 도장을 받습니다.
- **브랜치(branch)**: 평행우주를 하나 여는 것입니다. 본편 이야기(main 브랜치)는 그대로 두고, "가격 정책을 바꿔 보면 어떨까?" 같은 실험을 분기된 우주에서 진행합니다. 실험이 성공하면 본편에 합치고(merge), 실패하면 그 우주만 폐기하면 본편은 무사합니다.
- **체크아웃/시간여행**: 서류함의 어느 도장 시점으로든 폴더 상태를 되돌려 볼 수 있습니다. "지난주 화요일 상태로 돌아가 보자"가 명령 한 줄입니다.

## 3. 핵심 개념

### 3-1. 세 개의 공간

Git 작업은 세 공간 사이의 이동입니다.

```
작업 폴더(책상)  --git add-->  스테이징(결재판)  --git commit-->  저장소(서류함)
```

| 공간 | 비유 | 상태 |
|---|---|---|
| 작업 폴더(working directory) | 지금 편집 중인 책상 | 자유롭게 수정 가능, 아직 기록 아님 |
| 스테이징 영역(staging area) | 결재판 | 다음 커밋에 포함될 후보 |
| 저장소(repository) | 결재 서류함 | 도장 찍힌 영구 기록 |

`git status` 는 "지금 책상과 결재판에 뭐가 있나"를 보여주는 만능 확인 명령입니다.

### 3-2. 필수 명령 7가지

```bash
git init                       # 서류함 설치 (폴더당 한 번)
git status                     # 현재 상태 확인 (수시로!)
git add 파일 또는 .            # 결재판에 올리기
git commit -m "사유"           # 도장 찍기 (메시지 필수)
git log --oneline              # 결재 이력 조회
git branch 이름 / git switch 이름   # 평행우주 만들기 / 이동
git diff                       # 무엇이 달라졌나 비교
```

처음 쓰는 컴퓨터에서는 도장에 새길 이름을 등록해야 합니다: `git config --global user.name "이름"`, `git config --global user.email "메일"`.

### 3-3. 좋은 커밋의 요령

- **작게, 자주**: 하루치를 몰아서 한 번 찍지 말고, 의미 있는 단위(기능 하나, 수정 하나)마다 찍습니다. 되돌리기가 쉬워집니다.
- **메시지는 "왜"를**: "수정" 같은 메시지는 없느니만 못합니다. "할인율 계산식 오류 수정(10%→15%)"처럼, 미래의 자신이 읽고 이해할 사유를 적습니다.
- **커밋은 지워지지 않는 안전망**: 커밋해 둔 것은 어떤 실수를 해도 되찾을 수 있습니다. "일단 커밋"이 최고의 백업 습관입니다.

### 3-4. .gitignore — 기록하지 않을 것들

임시 파일, `.venv` 폴더, 비밀키 파일(level09)은 서류함에 넣지 않습니다. 프로젝트 루트의 `.gitignore` 파일에 제외 목록을 적어 두면 Git 이 그 파일들을 없는 셈 칩니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

이 스크립트는 여러분 컴퓨터에 git 이 설치되어 있으면, **임시 폴더에 진짜 저장소를 만들어 전체 흐름을 자동 실습**합니다. (git 이 없으면 같은 흐름을 개념 시뮬레이션으로 보여주고, 설치 방법을 안내합니다.)

- **[1] 서류함 설치**: `git init` 으로 저장소를 만들고 실습용 이름·메일을 등록합니다.
- **[2] 첫 결재**: 가격표 파일을 만들어 `add → commit` 으로 첫 도장을 찍습니다.
- **[3] 수정과 diff**: 가격을 바꾼 뒤 `git diff` 로 "무엇이 달라졌나"를 확인하고 두 번째 커밋을 합니다.
- **[4] 이력 조회**: `git log` 로 도장들이 쌓인 결재 이력을 봅니다.
- **[5] 브랜치 실험**: `experiment` 브랜치(평행우주)에서 가격을 과감히 바꾸고, main 으로 돌아오면 **파일 내용이 원래대로 보이는 것**을 확인합니다 — 시간여행의 실감 포인트입니다.

핵심 코드는 `run_git()` 함수입니다. 파이썬의 `subprocess.run()` 으로 실제 git 명령을 실행하고 출력을 받아옵니다. 즉 여러분이 터미널에 칠 명령을 파이썬이 대신 쳐 주며 해설을 붙이는 구조입니다. 출력에서 `$ git ...` 줄이 "여러분이 직접 칠 명령"이니, 실습 후 빈 폴더에서 같은 순서로 손으로 쳐 보면 완벽합니다.

## 6. 자주 하는 실수

- **add 없이 commit**: 결재판이 비어 있으면 도장 찍을 서류가 없습니다. "nothing to commit" 이 나오면 `git status` 로 결재판 상태부터 확인하세요.
- **커밋 메시지 없이 커밋 시도**: `-m "메시지"` 를 빼면 낯선 편집기 화면이 열려 당황하게 됩니다(빠져나오기: `:q!` 후 Enter). 항상 `-m` 을 붙이는 습관을 들이세요.
- **모든 파일을 무조건 `git add .`**: 비밀키·대용량 파일까지 서류함에 들어가는 사고의 지름길입니다. `git status` 로 무엇이 올라가는지 보고 add 하세요.
- **`.git` 폴더 삭제·이동**: 이 폴더가 서류함 그 자체입니다. 지우면 이력 전체가 사라집니다.
