# Lecture 01 · Level 05 — 코드 에디터와 Jupyter

> 코드를 "쓰는 도구"인 에디터(VS Code)와 "실험하는 도구"인 Jupyter 노트북의 쓰임새를 구분하고, 노트북의 셀 실행 방식을 시뮬레이션으로 체험합니다.

**난이도** ⭐⭐ / **선행** level04 / **예상 시간** 35분

## 1. 왜 배우나 — 비즈니스 관점

코드는 메모장으로도 쓸 수 있습니다. 하지만 실무에서 아무도 그렇게 하지 않는 이유는, 좋은 도구가 실수를 미리 잡아 주고 작업 속도를 몇 배로 만들어 주기 때문입니다. 엑셀 대신 계산기와 종이로 결산을 하지 않는 것과 같은 이치입니다.

파이썬 작업 도구는 크게 두 갈래입니다. 프로그램(스크립트)을 만드는 **코드 에디터**, 그리고 데이터를 이리저리 만져 보며 탐색하는 **Jupyter 노트북(notebook)**. 데이터 분석가의 화면에는 거의 항상 노트북이, 개발자의 화면에는 에디터가 떠 있습니다. 둘의 쓰임새를 구분할 줄 알면 "이 작업은 어떤 도구로 하는 게 맞나"를 스스로 판단할 수 있고, 협업 상대가 보내온 `.ipynb` 파일 앞에서 당황하지 않게 됩니다. 특히 노트북의 "셀 실행 순서" 개념은 처음 쓰는 사람들이 가장 많이 넘어지는 지점이라, 이 레벨에서 미리 원리를 익혀 둡니다.

## 2. 비유로 이해하기

**에디터는 정식 보고서 작성 도구, 노트북은 실험 노트**입니다.

- **VS Code 같은 에디터**는 워드프로세서로 정식 보고서를 쓰는 것과 같습니다. 완성된 문서(스크립트 전체)를 만들어 결재(실행)에 올리는 방식입니다. 맞춤법 검사(문법 오류 표시), 목차 탐색(함수 이동), 자동 완성이 강력합니다. 결과물은 처음부터 끝까지 순서대로 실행되는 `.py` 파일입니다.
- **Jupyter 노트북**은 실험실의 실험 노트입니다. "이 시약을 넣으면? → 결과 기록 → 그럼 온도를 올리면? → 결과 기록"처럼, **한 단계 실행하고 결과를 눈으로 확인한 뒤 다음 단계를 결정**하는 방식입니다. 코드 조각(셀, cell)과 그 실행 결과, 그리고 설명 글이 한 문서에 섞여 있습니다.

중요한 차이가 하나 있습니다. 실험 노트는 **페이지 순서와 실험 순서가 다를 수 있습니다**. 3페이지 실험을 먼저 하고 1페이지로 돌아가 다시 할 수도 있죠. 노트북도 셀을 아무 순서로나 실행할 수 있는데, 모든 셀은 **하나의 작업대(커널, kernel)의 기억을 공유**합니다. 그래서 화면상 위에 있는 셀이 아래 셀보다 "나중에" 실행됐다면, 문서를 위에서 아래로 읽은 사람에게는 결과가 이상하게 보입니다. 이것이 노트북 사고의 90%입니다.

## 3. 핵심 개념

### 3-1. 도구 선택 기준

| 상황 | 어울리는 도구 | 이유 |
|---|---|---|
| 데이터를 처음 받아 탐색 | 노트북 | 한 단계씩 결과를 보며 방향 결정 |
| 그래프 보며 분석·보고 자료 초안 | 노트북 | 코드+결과+설명이 한 문서에 |
| 매주 돌릴 자동화 스크립트 | 에디터(.py) | 처음부터 끝까지 순서대로, 재실행 보장 |
| 여러 파일로 된 프로그램 개발 | 에디터 | 파일 간 이동·검색·디버깅 |
| 팀에 공유할 최종 코드 | 에디터(.py) | 실행 순서가 항상 동일해 신뢰 가능 |

실무의 흔한 흐름은 "노트북에서 실험 → 방법이 확정되면 `.py` 스크립트로 정리"입니다.

### 3-2. VS Code 첫 세팅 3가지

VS Code(Visual Studio Code)는 무료이고 사실상 업계 표준인 에디터입니다. 설치 후 딱 세 가지만 해 두면 됩니다.

1. **Python 확장(extension) 설치** — 왼쪽 확장 메뉴에서 "Python" 검색·설치. 문법 검사와 실행 버튼이 생깁니다.
2. **인터프리터 선택** — 명령 팔레트(Cmd/Ctrl+Shift+P)에서 "Python: Select Interpreter" 를 열어 **프로젝트의 `.venv`** 를 지정합니다. level04 에서 배운 "어느 도구상자를 쓸 것인가"를 에디터에게 알려주는 절차입니다.
3. **폴더로 열기** — 파일 하나가 아니라 프로젝트 폴더 전체를 열어야(File > Open Folder) 상대경로와 검색이 제대로 동작합니다.

### 3-3. 노트북의 구조: 셀 + 커널

- **셀(cell)**: 코드 몇 줄을 담는 상자. Shift+Enter 로 그 셀만 실행합니다. 셀 왼쪽의 `[3]` 같은 번호는 "이 커널에서 3번째로 실행됨"이라는 **실행 순번**입니다.
- **커널(kernel)**: 뒤에서 살아 있는 파이썬 프로세스. 모든 셀이 이 하나의 기억(변수들)을 공유합니다. 셀에서 만든 변수는 다른 셀에서 그대로 보입니다.
- **재시작(restart)**: 커널을 재시작하면 기억이 전부 초기화됩니다. "위에서부터 전부 다시 실행(Restart & Run All)"이 재현성을 확인하는 정석 절차입니다.

`.ipynb` 파일은 셀들과 그 출력이 저장된 JSON 문서입니다. VS Code 안에서도 열리고, `jupyter lab` 명령으로 브라우저에서도 엽니다(둘 다 pip 으로 설치: `pip install jupyterlab`).

### 3-4. 순서 사고(out-of-order)의 정체

셀 A 에서 `price = 1000`, 셀 B 에서 `price * 2` 를 실행했다고 합시다. 그 후 셀 A 를 지워도 셀 B 는 여전히 동작합니다. 커널의 기억에 `price` 가 남아 있기 때문입니다. 이 노트북을 받은 동료가 위에서부터 실행하면 `price` 가 없다는 에러를 만납니다. **화면의 코드와 커널의 기억이 어긋날 수 있다** — 이것만 기억하면 노트북 사고의 대부분을 이해한 것입니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

Jupyter 를 설치하지 않고도 노트북의 동작 원리를 체험하도록, **미니 노트북 시뮬레이터**를 만들었습니다.

- **[1] 노트북 구성**: 매출 분석 시나리오의 셀 4개(데이터 준비 → 합계 → 평균 → 보고)를 정의합니다.
- **[2] 순서대로 실행**: Run All 처럼 위에서부터 실행하며, 셀마다 실행 순번 `[n]` 과 출력, 그리고 **커널 기억(변수 목록)이 셀을 거치며 쌓여 가는 모습**을 보여줍니다.
- **[3] 순서 사고 재현**: 커널을 재시작한 뒤 3번 셀부터 실행해 "위 셀을 안 돌리면 NameError" 를 일부러 발생시키고, 이어서 셀을 화면 순서와 다르게 실행하면 결과가 어떻게 어긋나는지 보여줍니다.
- **[4] 교훈 정리**: Restart & Run All 이 왜 정석인지 출력으로 정리합니다.

핵심 코드는 `NotebookKernel` 클래스입니다. `self.memory` 라는 딕셔너리 하나가 커널의 기억이고, `run_cell()` 은 파이썬 내장 함수 `exec()` 로 셀 코드를 그 기억 위에서 실행합니다. 실제 Jupyter 커널의 원리를 딕셔너리 하나로 축소한 모형입니다.

## 6. 자주 하는 실수

- **노트북 셀을 뒤죽박죽 실행한 채 저장·공유**: 받는 사람은 재현할 수 없습니다. 공유 전에 반드시 "Restart & Run All" 로 처음부터 끝까지 깨끗이 도는지 확인하세요.
- **에디터의 인터프리터 미지정**: 터미널에서는 되는데 VS Code 에서만 import 에러가 나면 십중팔구 인터프리터가 `.venv` 가 아닌 것입니다.
- **모든 일을 노트북으로**: 노트북은 실험용입니다. 매일 돌릴 자동화까지 노트북에 두면 실행 순서·버전 관리가 모두 어려워집니다. 확정된 로직은 `.py` 로 옮기세요.
- **커널이 죽었는데 코드 탓하기**: 출력이 안 나오면 먼저 커널 상태(재시작 필요 여부)를 확인하세요. 기억이 사라진 커널에는 위 셀부터 다시 실행해야 합니다.
