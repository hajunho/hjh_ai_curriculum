# Lecture 01 · Level 08 — 셸 스크립트로 반복 작업 자동화

> 매주 손으로 하던 파일 정리·이름 변경을 스크립트 한 번으로 끝내는 자동화의 사고방식을 배우고, 파이썬으로 파일 일괄 정리를 실습합니다.

**난이도** ⭐⭐⭐ / **선행** level02 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

이런 업무를 떠올려 보세요. 매주 월요일, 공유 폴더에 쌓인 지점별 매출 파일 수십 개를 내려받아, 파일명을 규칙에 맞게 고치고, 월별 폴더로 분류하고, 지난 파일은 보관함으로 옮기는 일. 한 번에 20분, 1년이면 17시간입니다. 게다가 사람은 실수합니다 — 파일 하나를 엉뚱한 폴더에 넣거나, 이름의 날짜를 잘못 칩니다.

자동화의 손익계산은 단순합니다. **"반복 횟수 × 절약 시간 > 자동화 제작 시간"이면 무조건 이득**이고, 덤으로 실수가 0 이 됩니다. 이 레벨은 그 첫 실전으로 "파일 일괄 정리"를 다룹니다. 파일 정리는 사무직 반복 업무의 최대공약수이고, 여기서 익힌 패턴(목록 얻기 → 규칙 적용 → 일괄 실행 → 결과 보고)은 나중에 데이터 전처리·보고서 생성·메일 발송 등 모든 자동화에 그대로 재사용됩니다.

## 2. 비유로 이해하기

**스크립트는 신입에게 주는 업무 매뉴얼**입니다.

유능한 선배는 신입에게 일을 말로만 시키지 않고 매뉴얼을 써 줍니다. "1) 받은 파일함을 연다 2) 파일명 앞에 날짜를 붙인다 3) 지점별 폴더에 넣는다 4) 완료 목록을 보고한다." 매뉴얼이 좋으면 누가 해도, 몇 번을 해도 같은 결과가 나옵니다.

스크립트(script)가 바로 이 매뉴얼입니다. 다만 실행자가 신입이 아니라 컴퓨터라서, (1) 지시가 조금이라도 모호하면 멈추거나 엉뚱한 일을 하고, (2) 대신 한 번 정확히 써 두면 1만 번을 시켜도 불평도 실수도 없습니다.

매뉴얼을 쓰는 언어는 두 가지가 있습니다. **셸 스크립트(.sh)** 는 level02 에서 배운 터미널 명령(cp, mv 등)을 파일에 순서대로 적은 것 — "터미널 언어로 쓴 매뉴얼"입니다. **파이썬 스크립트(.py)** 는 같은 일을 파이썬으로 쓴 것입니다. 간단한 명령 나열은 셸이 간결하고, 조건·예외·데이터 가공이 끼면 파이썬이 압도적으로 유리합니다. 이 커리큘럼에서는 "두세 줄이면 셸, 그 이상은 파이썬"을 기준으로 삼습니다.

## 3. 핵심 개념

### 3-1. 셸 스크립트 최소 문법

```bash
#!/bin/bash                      # 1행: 이 매뉴얼의 실행자는 bash
mkdir -p archive                 # 명령을 순서대로 적는다
mv report_*.csv archive/         # * 와일드카드: 패턴에 맞는 모든 파일
echo "정리 완료: $(date)"        # 진행 보고
```

`bash cleanup.sh` 로 실행합니다. `*`(아무 글자열), `?`(한 글자) 같은 **와일드카드(wildcard)**가 "패턴에 맞는 전부"를 잡아 주는 것이 일괄 처리의 핵심입니다.

### 3-2. 자동화 스크립트의 4단계 패턴

어떤 자동화든 뼈대는 같습니다.

1. **수집**: 대상 목록을 얻는다 — `Path.glob("*.csv")`
2. **판단**: 각 대상에 규칙을 적용한다 — 파일명 해석, 분류 결정
3. **실행**: 옮기고/바꾸고/만든다 — `rename`, `mkdir`
4. **보고**: 무엇을 했는지 기록한다 — 로그 출력, 요약표

이 중 가장 중요한 습관이 **드라이런(dry run)** — 3단계 실행을 잠그고 "무엇을 할 예정인지"만 출력해 보는 예행연습입니다. 파일 500개를 잘못 옮기고 나서 후회하는 것보다, 옮기기 전에 계획표를 눈으로 검증하는 것이 프로의 방식입니다.

### 3-3. 파이썬으로 파일 다루기 핵심 도구

| 도구 | 하는 일 |
|---|---|
| `Path.glob("*.csv")` / `rglob` | 패턴으로 파일 목록 수집 (하위 폴더 포함은 rglob) |
| `path.rename(새경로)` | 이동 겸 이름 변경 (셸의 mv) |
| `shutil.copy2(원본, 대상)` | 복사 (셸의 cp, 수정시각 보존) |
| `path.mkdir(parents=True, exist_ok=True)` | 폴더 생성 (셸의 mkdir -p) |
| `re.match(패턴, 이름)` | 정규표현식으로 파일명 해석 |

**정규표현식(regular expression)**은 "글자 패턴 검색 언어"입니다. 예컨대 `r"(\d{4})-(\d{2})"` 는 "숫자 4개-숫자 2개"(연-월)를 뜻합니다. 파일명에서 날짜·지점명 같은 정보를 뽑아낼 때 강력하며, 지금은 "이런 도구가 있다" 수준이면 충분합니다.

### 3-4. 안전장치 설계

자동화는 빠른 만큼 사고도 빠릅니다. 최소 안전장치 세 가지: **(1) 드라이런 모드**를 기본값으로, **(2) 삭제 대신 이동**(quarantine 폴더로 치워 두기), **(3) 실행 로그 남기기**(무엇을 언제 옮겼는지). 이 세 가지만 지켜도 자동화 사고의 대부분을 예방합니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

임시 폴더에 **어질러진 공유 폴더**를 재현해 놓고, 자동 정리 스크립트가 치우는 전 과정을 보여줍니다.

- **[1] 난장판 생성**: `매출보고_강남_2024-03.csv`, `sales_busan_2024-04.csv`, `메모.txt`, `발표자료.pptx` 등 이름 규칙이 제각각인 파일 14개를 seed 고정 난수로 만듭니다.
- **[2] 수집·판단**: 정규표현식으로 파일명에서 연월·지점을 해석하고, 파일마다 "어디로 보낼지" 분류 계획을 세웁니다. 해석 불가능한 파일은 `_검토필요` 폴더행입니다.
- **[3] 드라이런**: 실행 전에 이동 계획표만 출력합니다 — "무엇을 할 예정인가"의 예행연습.
- **[4] 실제 실행**: 계획대로 폴더를 만들고 파일을 일괄 이동·이름 통일(`지점_연-월.csv` 형식)합니다.
- **[5] 결과 보고**: 정리 후 폴더 트리와 처리 요약(정리 n건, 검토 필요 n건), 그리고 손으로 했다면 걸렸을 시간을 비교합니다.

핵심 코드는 `plan_moves()` 와 `execute_moves()` 의 분리입니다. **계획 세우기와 실행을 별개 함수로 나누면** 드라이런이 공짜로 생기고, 테스트도 쉬워집니다. 이 구조는 실무 자동화의 표준 설계입니다.

## 6. 자주 하는 실수

- **드라이런 없이 일괄 실행**: 파일 수백 개가 잘못 옮겨진 뒤에는 되돌리기가 몇 배 힘듭니다. 계획표 출력 → 눈 검증 → 실행 순서를 지키세요.
- **같은 이름 파일 덮어쓰기**: 이동 대상에 동명 파일이 있으면 조용히 덮어써 데이터가 사라질 수 있습니다. 이동 전 존재 확인(`exists()`) 또는 이름에 번호 붙이기가 필요합니다.
- **자동화 스크립트에 절대경로 하드코딩**: `/Users/내이름/...` 이 박혀 있으면 동료 컴퓨터에서 즉사합니다. 대상 폴더는 인자나 설정으로 받게 만드세요.
- **한 번 쓰고 버릴 코드에 과투자**: 반복되지 않을 일은 그냥 손으로 하는 것이 빠릅니다. 자동화 손익계산을 먼저 하세요.
