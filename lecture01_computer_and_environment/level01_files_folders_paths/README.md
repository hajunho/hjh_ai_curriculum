# Lecture 01 · Level 01 — 파일·폴더·경로의 개념

> 컴퓨터의 모든 데이터는 파일이고, 파일의 주소가 경로(path)라는 것을 이해하고, 파이썬 pathlib 으로 폴더 트리를 직접 만들고 탐색합니다.

**난이도** ⭐ / **선행** level00 / **예상 시간** 35분

## 1. 왜 배우나 — 비즈니스 관점

개발을 배우다 만나는 에러의 상당수는 거창한 것이 아니라 "파일을 못 찾겠다(FileNotFoundError)"입니다. 데이터 분석을 하려면 CSV 파일을 읽어야 하고, 보고서를 만들면 어딘가에 저장해야 하며, AI 모델도 결국 파일로 저장됩니다. 그런데 파일이 "어디에" 있는지를 컴퓨터에게 정확히 알려주는 방법, 즉 **경로**를 모르면 한 발짝도 나가지 못합니다.

실무 관점에서도 경로 감각은 곧바로 돈이 됩니다. 공유 드라이브에서 "그 파일 어디 있어요?"를 주고받는 시간, 잘못된 폴더에 저장해 버전이 꼬이는 사고, 백업에서 빠진 폴더 — 모두 경로와 폴더 구조에 대한 감각 부족에서 옵니다. 이 레벨을 마치면 여러분은 어떤 파일의 위치든 한 줄의 주소로 정확히 표현할 수 있게 되고, 파이썬으로 폴더 구조를 자동으로 만들거나 뒤질 수 있게 됩니다.

## 2. 비유로 이해하기

**폴더 구조는 회사 건물의 주소 체계**입니다.

서울 본사 건물을 상상해 보세요. "본사 건물 > 3층 > 영업팀 사무실 > 김 과장 캐비닛 > 2024년 계약서 폴더 > A사_계약서.pdf". 이렇게 큰 곳에서 작은 곳으로 단계를 밟아 내려가면 세상 어떤 서류든 정확히 하나로 특정됩니다. 컴퓨터의 경로가 정확히 이 방식입니다.

```
/Users/kim/Documents/contracts/2024/A사_계약서.pdf
```

맨 앞의 `/` 가 "본사 건물 정문(루트, root)"이고, `/` 로 구분된 각 단계가 층·사무실·캐비닛에 해당합니다. 이렇게 **정문에서부터 전체 주소를 다 적은 것이 절대경로(absolute path)**입니다.

반면 사내에서 대화할 때는 "우리 팀 캐비닛의 2024 폴더에 있어요"라고 줄여 말합니다. 듣는 사람이 지금 어디 있는지(현재 위치)를 서로 알기 때문입니다. 이것이 **상대경로(relative path)** — `contracts/2024/A사_계약서.pdf` 처럼 현재 위치를 기준으로 한 주소입니다. 상대경로에는 특별한 표기가 두 개 있습니다. `.` 은 "지금 이 방", `..` 은 "한 층 위(부모 폴더)"를 뜻합니다.

파일 이름 끝의 `.pdf`, `.xlsx`, `.py` 같은 **확장자(extension)는 서류 봉투에 찍힌 문서 종류 도장**입니다. 내용물이 무엇인지(문서인지, 표인지, 코드인지)를 알려 주는 약속이며, 운영체제는 이 도장을 보고 어떤 프로그램으로 열지 결정합니다.

## 3. 핵심 개념

### 3-1. 모든 것은 파일이다

컴퓨터 안에서 문서, 사진, 프로그램, 심지어 설정값까지 전부 파일입니다. 파일은 "이름 + 내용(0과 1의 나열) + 위치"로 이루어지고, 폴더(디렉터리, directory)는 파일을 담는 그릇이자 또 다른 폴더를 담을 수 있는 그릇입니다. 그래서 전체 구조는 뿌리에서 가지가 뻗는 **트리(tree) 구조**가 됩니다.

### 3-2. 절대경로 vs 상대경로

| 구분 | 절대경로 | 상대경로 |
|---|---|---|
| 시작점 | 루트(`/`) 또는 드라이브(`C:\`) | 현재 작업 폴더 |
| 예시 | `/Users/kim/data/sales.csv` | `data/sales.csv` |
| 장점 | 어디서 실행해도 같은 파일을 가리킴 | 짧고, 프로젝트를 통째로 옮겨도 유효 |
| 단점 | 다른 컴퓨터에선 깨지기 쉬움 | "현재 위치"가 다르면 엉뚱한 곳을 가리킴 |

여기서 "현재 위치"를 **현재 작업 디렉터리(current working directory, CWD)**라고 부릅니다. 프로그램을 어느 폴더에서 실행했는지가 곧 CWD 이고, 상대경로는 전부 여기를 기준으로 해석됩니다. 상대경로 에러의 90%는 "내가 생각한 현재 위치"와 "실제 CWD"가 달라서 생깁니다.

### 3-3. 운영체제별 차이

맥/리눅스는 구분자가 `/` 이고 루트가 `/` 하나입니다. 윈도우는 구분자가 `\` 이고 `C:\`, `D:\` 처럼 드라이브별 루트가 있습니다. 이 차이 때문에 경로를 문자열로 직접 이어 붙이면 다른 운영체제에서 깨집니다. 파이썬의 **pathlib** 라이브러리는 이 차이를 자동으로 처리해 주므로, 이 커리큘럼에서는 처음부터 pathlib 을 표준으로 사용합니다.

### 3-4. pathlib 핵심 5가지

```python
from pathlib import Path
p = Path("data") / "sales.csv"   # 경로 조합: / 연산자로 안전하게
p.exists()                        # 존재 확인
p.mkdir(parents=True, exist_ok=True)  # 폴더 생성 (중간 폴더까지, 있어도 에러 없음)
p.resolve()                       # 절대경로로 변환
p.suffix, p.stem, p.parent        # 확장자, 이름, 부모 폴더
```

이 다섯 가지만 알면 이후 강의의 파일 작업 대부분을 읽을 수 있습니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

이 스크립트는 임시 폴더 안에 작은 가상 회사 "한빛상사"의 문서 트리를 만들고 탐색합니다.

- **[1] 트리 생성**: `총무팀/`, `영업팀/계약서/`, `영업팀/보고서/` 같은 부서 폴더와 샘플 파일들을 pathlib 으로 만듭니다.
- **[2] 트리 그리기**: 재귀 함수로 폴더 구조를 들여쓰기된 트리 그림으로 출력합니다. 터미널의 `tree` 명령을 파이썬으로 흉내 낸 것입니다.
- **[3] 절대 vs 상대**: 같은 파일을 절대경로와 상대경로 두 방식으로 표현해 비교하고, `..` 이 어떻게 동작하는지 보여줍니다.
- **[4] 확장자 분석**: 트리 전체를 뒤져(`rglob`) 확장자별로 파일 수를 집계합니다. "회사 문서고에 어떤 종류 서류가 몇 장인가"를 세는 셈입니다.
- **[5] 경로 해부**: 경로 하나를 parent / name / stem / suffix 로 분해해 보여줍니다.

핵심 코드는 `draw_tree()` 함수입니다. 폴더를 열어 내용물을 나열하고, 내용물이 폴더면 자기 자신을 다시 호출하는 **재귀(recursion)** 구조인데, 트리 구조를 다루는 가장 자연스러운 방법이라 이후에도 자주 만나게 됩니다. 실습이 끝나면 임시 폴더는 자동으로 삭제되므로 여러분 컴퓨터에 흔적이 남지 않습니다.

## 6. 자주 하는 실수

- **경로를 문자열 덧셈으로 조합**: `"data" + "/" + "sales.csv"` 는 윈도우에서 깨질 수 있습니다. 항상 `Path("data") / "sales.csv"` 를 쓰세요.
- **CWD 를 착각**: 스크립트 파일이 있는 폴더와 실행한 폴더는 다를 수 있습니다. 스크립트 기준의 경로가 필요하면 `Path(__file__).parent` 를 사용합니다.
- **확장자를 지우거나 잘못 바꿈**: 확장자는 내용물을 바꾸지 않습니다. `report.xlsx` 를 `report.csv` 로 이름만 바꾼다고 CSV 가 되지 않으며, 오히려 열리지 않게 됩니다.
- **한글·공백이 든 경로**: 가능하면 폴더·파일명은 영문 소문자와 밑줄(`sales_2024.csv`)로 짓는 습관을 들이세요. 공백과 한글은 터미널·코드에서 따옴표 처리 등 잔손이 많이 갑니다.
