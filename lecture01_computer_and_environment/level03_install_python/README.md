# Lecture 01 · Level 03 — 파이썬 설치와 첫 실행

> 내 컴퓨터의 파이썬을 확인하고, 대화형(REPL) 실행과 스크립트 실행의 차이를 이해하며, 자가진단 스크립트로 환경을 점검합니다.

**난이도** ⭐ / **선행** level02 / **예상 시간** 35분

## 1. 왜 배우나 — 비즈니스 관점

파이썬(Python)은 이 커리큘럼 전체의 공용어입니다. 데이터 분석, 자동화, AI — 우리가 배울 모든 것이 파이썬 위에서 돌아갑니다. 파이썬이 세계적으로 업무 자동화와 AI 의 표준 언어가 된 이유는 단순합니다. 문법이 영어 문장에 가까워 배우기 쉽고, 전 세계 사람들이 만들어 둔 도구(패키지)가 압도적으로 많기 때문입니다.

그런데 의외로 많은 입문자가 첫 시간에 코드가 아니라 **설치와 실행**에서 좌절합니다. "python 을 쳤는데 없다고 나온다", "분명 설치했는데 다른 버전이 실행된다", "회사 컴퓨터엔 두 개가 깔려 있는데 뭐가 뭔지 모르겠다" — 전부 흔한 일입니다. 이 레벨은 그 진입 장벽을 넘는 시간입니다. 내 컴퓨터에 어떤 파이썬이, 어디에, 몇 버전으로 있는지 스스로 진단할 수 있으면, 앞으로 환경 문제를 만나도 당황하지 않게 됩니다.

## 2. 비유로 이해하기

파이썬 설치는 **회사에 유능한 통역사를 채용하는 일**입니다. 우리가 쓰는 파이썬 코드는 사람이 읽기 좋은 언어이고, 컴퓨터는 0과 1(기계어)만 알아듣습니다. 파이썬 인터프리터(interpreter)라는 통역사가 우리의 지시문을 한 줄씩 기계어로 통역해 줍니다.

통역사에게 일을 시키는 방식은 두 가지입니다.

- **대화형(REPL)** — 통역사와 마주 앉아 **한 마디씩 즉석 대화**하는 방식입니다. 터미널에 `python3` 만 치면 `>>>` 프롬프트가 나타나고, `2 + 3` 을 치면 즉시 `5` 라고 답합니다. 계산기처럼 가볍게 실험할 때 좋습니다. REPL 은 Read(읽고)-Eval(계산하고)-Print(답하고)-Loop(반복)의 약자입니다.
- **스크립트(script) 실행** — 지시사항을 **문서로 정리해 통째로 전달**하는 방식입니다. `main.py` 같은 파일에 지시문을 적어 두고 `python3 main.py` 로 넘기면 위에서부터 순서대로 전부 실행합니다. 보관·재실행·공유가 되므로 실제 업무는 대부분 이 방식입니다.

즉석 대화(REPL)는 아이디어 실험용, 문서 지시(스크립트)는 정식 업무용 — 이 구분만 기억하면 됩니다.

## 3. 핵심 개념

### 3-1. 설치 확인이 먼저다

새로 설치하기 전에, 이미 있는지부터 확인합니다. 터미널에서:

```bash
python3 --version    # 예: Python 3.12.9
which python3        # 맥/리눅스: 실행 파일의 위치 (윈도우는 where python)
```

버전이 3.10 이상이면 이 커리큘럼 진행에 충분합니다. 없다면 python.org 공식 사이트의 설치 파일을 받거나, 맥은 Homebrew(`brew install python`), 윈도우는 공식 설치 파일에서 **"Add Python to PATH" 체크**를 잊지 않는 것이 요점입니다.

### 3-2. python 2 와 3, 그리고 여러 개의 파이썬

역사적인 이유로 명령이 `python` 과 `python3` 두 가지가 존재합니다. 옛 파이썬 2는 이미 지원이 끝났으므로 **우리는 항상 `python3`** 를 기준으로 합니다. 또 한 컴퓨터에 파이썬이 여러 개 설치되어 있는 것은 흔하고 정상입니다(운영체제 내장용, 직접 설치한 것 등). 중요한 것은 "지금 내 명령이 **어느** 파이썬을 실행하는가"이며, 그 답이 `which python3` 와 `sys.executable` 입니다. 여러 파이썬이 공존해도 꼬이지 않게 하는 정식 해법이 다음 레벨의 가상환경입니다.

### 3-3. PATH — 컴퓨터가 명령을 찾는 순서

터미널에 `python3` 를 치면 셸은 **PATH 라는 폴더 목록**을 앞에서부터 뒤지며 그 이름의 프로그램을 찾습니다. 회사로 치면 "통역사를 찾을 때 순서대로 방문하는 부서 목록"입니다. "command not found" 는 그 목록 어디에도 없다는 뜻이고, 엉뚱한 버전이 실행된다면 목록 앞쪽에 다른 파이썬이 있다는 뜻입니다. PATH 는 환경변수의 하나로, level09 에서 더 자세히 다룹니다.

### 3-4. 스크립트 실행의 관례

- 파이썬 파일의 확장자는 `.py` 입니다.
- 파일 상단의 큰따옴표 세 개(`"""..."""`)로 감싼 문단은 **독스트링(docstring)** — 이 파일이 무엇인지 설명하는 문서입니다.
- `if __name__ == "__main__":` 은 "이 파일이 직접 실행될 때만 아래를 수행하라"는 관례적 표기입니다. 지금은 "본문 시작 표시"라고만 이해해도 충분하며, 모듈을 배우는 강의(lecture02)에서 원리를 다룹니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

이 스크립트는 **내 파이썬 환경 건강검진표**를 출력합니다.

- **[1] 통역사 신원 확인**: 파이썬 버전, 실행 파일의 실제 위치(`sys.executable`), 그리고 버전이 3.10 이상인지 판정합니다.
- **[2] 근무지 확인**: 운영체제 종류(맥/윈도우/리눅스), 프로세서 종류, 현재 작업 디렉터리를 보여줍니다.
- **[3] PATH 훑어보기**: 셸이 명령을 찾는 폴더 목록의 앞부분을 출력해, "명령을 찾는 순서"가 실제로 존재함을 확인합니다.
- **[4] REPL vs 스크립트**: 같은 계산을 REPL 에서라면 어떻게 쳤을지 보여주고, 스크립트로는 지금 실행되고 있음을 대비시킵니다.
- **[5] 종합 판정**: 항목별 통과 여부를 ✅/⚠️ 로 정리한 진단 요약을 출력합니다.

핵심 코드는 `sys` 와 `platform` 모듈 사용부입니다. `sys.version_info` 로 버전을 숫자로 비교하고, `sys.executable` 로 "지금 이 코드를 실행 중인 파이썬"의 정확한 위치를 얻습니다. 이 두 줄은 앞으로 환경 문제가 생길 때마다 꺼내 쓰는 만능 진단 도구이니 꼭 기억해 두세요.

## 5. 직접 해보기

1. **(쉬움)** 터미널에 `python3` 를 쳐서 REPL 에 들어가 `3 * 7`, `"안녕" * 3` 을 계산해 보고, `exit()` 로 나와 보세요. *(힌트: `>>>` 가 보이면 성공입니다. Ctrl+D 로도 나갈 수 있습니다.)*
2. **(보통)** main.py 의 [1] 단계에서 요구 버전을 (3, 10) 에서 (3, 99) 로 바꿔 실행해 보세요. 판정이 ⚠️ 로 바뀌는 것을 확인하고 원래대로 되돌리세요. *(힌트: `REQUIRED` 변수를 찾으세요. 진단 로직이 실제로 일하고 있음을 확인하는 실험입니다.)*
3. **(도전)** [2] 단계에 "파이썬이 설치된 지 몇 비트 환경인가"를 추가로 출력해 보세요. *(힌트: `platform.architecture()` 를 찾아보세요.)*

## 6. 자주 하는 실수

- **`python` 과 `python3` 혼용**: 맥에서 `python` 은 없거나 다른 버전일 수 있습니다. 항상 `python3` 로 통일하세요(가상환경 안에서는 `python` 도 안전해집니다 — 다음 레벨에서!).
- **설치만 하고 터미널을 안 껐다 켬**: PATH 변경은 새 터미널 창부터 적용되는 경우가 많습니다. 설치 후 명령이 안 되면 터미널을 새로 열어 보세요.
- **REPL 에 파일 실행 명령을 입력**: `>>>` 상태에서 `python3 main.py` 를 치면 에러입니다. 파일 실행은 REPL 을 나간 뒤 셸에서 하는 것입니다. 지금 내가 셸(`$`)에 있는지 REPL(`>>>`)에 있는지 프롬프트로 구분하세요.
- **에러 메시지를 안 읽고 재설치부터**: "command not found" 와 "SyntaxError" 는 원인이 전혀 다릅니다. 메시지 첫 줄과 마지막 줄만 읽어도 방향이 잡힙니다.
