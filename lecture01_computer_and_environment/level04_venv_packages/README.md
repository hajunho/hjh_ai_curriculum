# Lecture 01 · Level 04 — 가상환경과 패키지 관리

> 프로젝트마다 독립된 파이썬 작업실(venv)을 만들고, pip 으로 필요한 도구(패키지)를 조달하는 방법을 배웁니다.

**난이도** ⭐⭐ / **선행** level03 / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

소프트웨어 업계의 오래된 농담이 있습니다. "내 컴퓨터에서는 되는데요?" — 개발자 A 의 코드가 개발자 B 의 컴퓨터에서 안 도는 상황입니다. 원인의 대부분은 두 사람이 설치한 **패키지(package)의 구성이나 버전이 다르기 때문**입니다. A 는 어떤 라이브러리 2.0 을, B 는 1.5 를 쓰고 있었던 식입니다.

이 문제는 개인에게도 옵니다. 프로젝트 X 는 구버전 라이브러리가, 새 프로젝트 Y 는 신버전이 필요할 때, 컴퓨터 전체에 하나만 설치할 수 있다면 둘 중 하나는 망가집니다. 해결책이 **가상환경(virtual environment)** — 프로젝트마다 독립된 파이썬 설치 공간을 하나씩 만드는 것입니다. 실무 파이썬 프로젝트는 예외 없이 가상환경으로 시작하며, 이 커리큘럼의 저장소에도 `.venv` 라는 가상환경이 있습니다. 이 레벨을 마치면 "지금 나는 어떤 환경에서, 어떤 도구를 갖고 일하는가"를 항상 답할 수 있게 됩니다.

## 2. 비유로 이해하기

**패키지는 전문 도구, 가상환경은 프로젝트 전용 도구상자**입니다.

파이썬을 설치하면 기본 공구(표준 라이브러리)는 딸려 옵니다. 망치·드라이버 수준의 필수품입니다. 그런데 데이터 분석에는 전동 드릴(pandas), 그림에는 도색 장비(matplotlib) 같은 전문 도구가 필요합니다. 이런 도구를 전 세계 공용 창고(PyPI, Python Package Index)에서 가져다 주는 조달 담당자가 **pip** 입니다.

문제는 도구를 모두 **회사 공용 공구함 하나**에 넣을 때 생깁니다. 리모델링 팀은 구형 드릴 규격이, 신축 팀은 신형이 필요한데 공구함엔 한 종류만 둘 수 있다면? 한 팀이 도구를 교체하는 순간 다른 팀 작업이 멈춥니다.

그래서 현명한 회사는 **프로젝트마다 전용 도구상자**를 꾸립니다. 이것이 가상환경입니다. 프로젝트 폴더 안에 `.venv` 라는 상자를 만들어 그 프로젝트용 파이썬과 패키지만 담습니다. 상자끼리는 완전히 독립이라 서로를 망가뜨릴 수 없고, 프로젝트가 끝나면 상자째 버리면 그만입니다. "activate(활성화)"는 작업 시작 전에 **그 프로젝트의 도구상자를 허리에 차는 행위**입니다.

## 3. 핵심 개념

### 3-1. 가상환경 생명주기 4단계

```bash
# 1) 만들기 — 프로젝트 폴더에서 한 번만
python3 -m venv .venv

# 2) 활성화 — 작업 시작할 때마다
source .venv/bin/activate        # 맥/리눅스
# .venv\Scripts\activate         # 윈도우 (PowerShell)

# 3) 도구 설치 — 활성화된 상태에서
pip install requests

# 4) 비활성화 — 작업 끝나면
deactivate
```

활성화되면 프롬프트 앞에 `(.venv)` 가 붙습니다. 이 표시가 "지금 어느 도구상자를 차고 있는지"의 시각적 신호입니다. 활성화 상태에서는 `python` 과 `pip` 이 모두 그 상자 안의 것으로 바뀝니다.

### 3-2. pip 필수 명령

| 명령 | 하는 일 |
|---|---|
| `pip install 이름` | 공용 창고(PyPI)에서 패키지 설치 |
| `pip install 이름==2.1.0` | 특정 버전 지정 설치 |
| `pip list` | 이 환경에 설치된 패키지 목록 |
| `pip uninstall 이름` | 제거 |
| `pip freeze > requirements.txt` | 현재 도구 목록을 파일로 기록 |
| `pip install -r requirements.txt` | 그 목록대로 한 번에 재구성 |

`requirements.txt` 는 **도구상자의 물품 목록표**입니다. 이 파일만 넘기면 동료가 자기 컴퓨터에 같은 구성의 상자를 그대로 재현할 수 있습니다. "내 컴퓨터에선 되는데요"의 1차 백신이 바로 이 파일입니다(2차 백신은 level10 의 도커입니다).

### 3-3. 내가 어느 환경에 있는지 아는 법

파이썬 코드 안에서 확인하는 확실한 방법이 있습니다.

- `sys.prefix` — 지금 파이썬이 도구를 찾는 설치 공간의 위치
- `sys.base_prefix` — 원본(시스템) 파이썬의 위치
- 이 둘이 **다르면 가상환경 안**, 같으면 시스템 파이썬을 그대로 쓰는 중입니다.

비유하면 `sys.base_prefix` 는 본사 공구 창고 주소, `sys.prefix` 는 지금 허리에 찬 상자의 주소입니다. 주소가 다르면 전용 상자를 차고 있는 것이죠.

### 3-4. 지켜야 할 관례

- 가상환경 폴더 이름은 관례상 `.venv` 로 짓고 프로젝트 폴더 바로 아래에 둡니다.
- `.venv` 폴더는 Git 에 올리지 않습니다(용량이 크고 컴퓨터마다 다르므로). 대신 `requirements.txt` 를 올립니다.
- 시스템 파이썬에 `pip install` 을 남발하지 않습니다. 최근 운영체제는 아예 막아 두기도 합니다(externally-managed 에러). 가상환경 안에서만 설치하는 습관을 들이세요.

## 4. 실습 — main.py

```bash
python3 main.py
```

이 스크립트는 **지금 실행 중인 환경의 진단서**를 출력합니다. 저장소의 `.venv` 파이썬으로 실행하면(`../../.venv/bin/python main.py` 또는 활성화 후 `python main.py`) "가상환경 안"으로, 시스템 `python3` 로 실행하면 "시스템 파이썬"으로 판정이 달라지는 것을 직접 비교해 보세요.

- **[1] 어느 도구상자인가**: `sys.prefix` 와 `sys.base_prefix` 를 나란히 출력하고 두 값을 비교해 가상환경 여부를 판정합니다.
- **[2] 도구상자 내용물**: `importlib.metadata` 로 설치된 패키지 목록과 버전을 나열합니다. `pip list` 가 보여주는 것과 같은 정보를 코드로 얻는 것입니다.
- **[3] 표준 라이브러리 확인**: 설치 없이 쓸 수 있는 기본 공구 몇 가지(json, csv, datetime 등)가 이미 있음을 확인합니다.
- **[4] requirements.txt 미리보기**: 현재 환경의 패키지 목록을 `이름==버전` 형식으로 출력해, `pip freeze` 가 만드는 물품 목록표의 정체를 보여줍니다.

핵심 코드는 `sys.prefix != sys.base_prefix` 비교 한 줄과, `importlib.metadata.distributions()` 순회입니다. 파이썬은 자기 환경을 자기 코드로 들여다볼 수 있다는 것 — 이것이 환경 문제를 두려워하지 않아도 되는 이유입니다.

2. **(보통)** 아무 연습용 폴더에서 `python3 -m venv test_env` 로 새 가상환경을 만들어 활성화하고, `pip list` 로 거의 빈 상자임을 확인한 뒤, `deactivate` 하고 폴더째 지워 보세요. *(힌트: 상자는 만들고 버리는 데 부담이 없어야 정상입니다.)*
3. **(도전)** [2] 출력에서 패키지를 이름순이 아니라 "이름 길이 순"으로 정렬해 보세요. *(힌트: `sorted(..., key=...)` 의 key 함수를 바꾸면 됩니다.)*

## 6. 자주 하는 실수

- **활성화를 잊고 설치**: `(.venv)` 표시 없이 `pip install` 하면 엉뚱한 곳(시스템)에 설치됩니다. 설치 전 프롬프트를 확인하세요.
- **가상환경을 만들어 놓고 IDE 는 다른 파이썬 사용**: 에디터(VS Code 등)에는 인터프리터를 별도로 지정해야 합니다(다음 레벨에서 다룹니다). "설치했는데 import 가 안 돼요"의 단골 원인입니다.
- **`.venv` 폴더를 통째로 복사·이동**: 가상환경은 만든 위치에 묶여 있어 옮기면 깨지기 쉽습니다. 옮길 땐 `requirements.txt` 로 새로 만드는 것이 정석입니다.
- **requirements.txt 갱신을 잊음**: 패키지를 추가했으면 `pip freeze` 로 목록표를 다시 만들어야 동료의 환경도 따라옵니다.
