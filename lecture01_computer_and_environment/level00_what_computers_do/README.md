# Lecture 01 · Level 00 — 컴퓨터는 무엇을 하는 기계인가

> 컴퓨터는 결국 "입력을 받아 → 계산하고 → 출력하는" 기계이며, CPU·메모리·저장장치가 회사 조직처럼 분업한다는 것을 이해합니다.

**난이도** ⭐ / **선행** 없음 / **예상 시간** 30분

## 1. 왜 배우나 — 비즈니스 관점

앞으로 이 커리큘럼에서 우리는 컴퓨터에게 수많은 일을 시킬 것입니다. 데이터를 정리시키고, 그래프를 그리게 하고, 나중에는 AI 모델을 학습시키기도 합니다. 그런데 일을 시키는 쪽이 일하는 쪽의 사정을 전혀 모르면 곤란한 일이 생깁니다. 예를 들어 "왜 이 작업은 1초 만에 끝나는데 저 작업은 한 시간이 걸리지?", "왜 프로그램을 껐더니 작업하던 내용이 사라졌지?", "메모리가 부족하다는 에러는 무슨 뜻이지?" 같은 질문에 스스로 답할 수 없게 됩니다.

직장에서도 마찬가지입니다. 협력 업체에 일을 맡길 때 그 회사의 조직 구조와 일하는 방식을 대략이라도 알면 견적과 일정이 왜 그렇게 나오는지 이해할 수 있습니다. 컴퓨터도 우리가 매일 일을 맡기는 "협력 업체"입니다. 내부 구조를 큰 그림으로만 알아 두어도, 이후 모든 레벨에서 마주칠 용어들(CPU, 메모리, 디스크, 프로세스)이 낯설지 않게 됩니다.

이 레벨의 목표는 단 하나입니다. **컴퓨터는 "입력 → 계산 → 출력"을 반복하는 기계**라는 큰 그림을 몸에 새기는 것입니다.

## 2. 비유로 이해하기

컴퓨터를 작은 회사라고 상상해 봅시다.

- **CPU(중앙처리장치)는 실무 담당자**입니다. 실제로 계산하고 판단하는 유일한 존재입니다. 엄청나게 빠르지만 한 번에 아주 작은 일(덧셈, 비교 같은 것)밖에 못 합니다. 대신 그 작은 일을 1초에 수십억 번 처리합니다. 서류 한 장을 0.0000001초 만에 결재하는 초고속 담당자인 셈입니다.
- **메모리(RAM)는 담당자의 책상**입니다. 지금 당장 작업 중인 서류를 펼쳐 놓는 공간입니다. 책상 위 서류는 손만 뻗으면 바로 집을 수 있어 매우 빠르지만, 퇴근(전원 꺼짐)하면 책상이 싹 치워집니다. 즉 **메모리는 빠르지만 휘발성**입니다. "저장 안 하고 껐더니 문서가 날아갔다"는 사고가 바로 이것입니다.
- **저장장치(SSD/HDD)는 문서 창고**입니다. 서류를 영구 보관하는 곳입니다. 창고까지 걸어가서 서류를 찾아오는 데는 시간이 걸리지만(메모리보다 수백~수천 배 느림), 전원을 꺼도 내용이 남습니다. 파일을 "저장한다"는 것은 책상 위 서류를 창고에 정식으로 보관하는 행위입니다.
- **입력장치(키보드·마우스)는 고객 접수창구**, **출력장치(모니터·프린터)는 결과 발송부서**입니다.

일이 처리되는 흐름은 회사의 업무 흐름과 똑같습니다. 접수창구로 주문이 들어오면(입력), 창고에서 필요한 자료를 꺼내 책상에 펼치고(저장장치 → 메모리), 담당자가 계산하고(CPU), 결과를 고객에게 발송하고(출력), 기록을 창고에 보관합니다(메모리 → 저장장치). 여러분이 엑셀을 열고, 수식을 넣고, 저장하는 과정이 정확히 이 흐름입니다.

## 3. 핵심 개념

### 3-1. 입력 → 계산 → 출력 (IPO 모델)

모든 프로그램은 예외 없이 이 세 단계로 이루어집니다. 이를 IPO(Input-Process-Output) 모델이라고 부릅니다.

| 단계 | 엑셀에서의 예 | 이 레벨 실습에서의 예 |
|---|---|---|
| 입력(Input) | 셀에 매출 숫자 입력 | 주문 목록 데이터 |
| 계산(Process) | SUM, AVERAGE 수식 | 합계·평균을 파이썬으로 계산 |
| 출력(Output) | 화면에 결과 표시, 파일 저장 | 화면 출력 + 파일 저장 |

앞으로 어떤 복잡한 AI 프로그램을 보더라도 "입력이 뭐고, 무슨 계산을 하고, 출력이 뭐지?"라고 세 조각으로 나눠 보면 절반은 이해한 것입니다.

### 3-2. 컴퓨터는 왜 0과 1인가

CPU 는 전기 신호로 일합니다. 전기가 흐른다/안 흐른다 두 가지 상태만 확실하게 구분할 수 있어서, 모든 정보를 0과 1(이진법, binary)로 표현합니다. 0 또는 1 하나를 비트(bit), 8개 묶음을 바이트(byte)라고 합니다. 글자, 사진, 동영상, 엑셀 파일 모두 결국 0과 1의 나열입니다. "1MB, 1GB" 같은 용량 단위는 이 바이트를 백만 개, 십억 개 단위로 센 것입니다.

### 3-3. 속도의 계층 — 왜 어떤 작업은 느린가

책상(메모리)과 창고(저장장치)의 비유에서 핵심은 **속도 차이**입니다. 대략의 감각만 잡아 두세요.

- CPU 내부 계산: 1초에 수십억 번
- 메모리 읽기: CPU 계산보다 수십~수백 배 느림
- SSD 읽기: 메모리보다 수백 배 느림
- 인터넷 다운로드: SSD 보다 또 수십 배 이상 느림

그래서 프로그램이 느릴 때 원인은 대부분 "계산이 많아서"가 아니라 "창고(디스크)나 외부(네트워크)를 자주 오가서"입니다. 이 감각은 나중에 대용량 데이터 강의에서 다시 등장합니다.

### 3-4. 프로그램과 프로세스

창고에 보관된 업무 매뉴얼(파일로 저장된 프로그램)은 그 자체로는 아무 일도 하지 않습니다. 담당자가 매뉴얼을 책상에 펼치고 실제로 일을 시작해야 업무가 진행됩니다. 이렇게 **실행 중인 프로그램을 프로세스(process)**라고 부릅니다. 같은 매뉴얼로 여러 담당자가 동시에 일할 수 있듯이, 하나의 프로그램(예: 크롬)을 여러 개 실행하면 여러 프로세스가 생깁니다.

## 4. 실습 — main.py

터미널에서 이 폴더로 이동해 실행합니다. (터미널이 낯설다면 level02 에서 자세히 배우니, 지금은 일단 따라 해 보세요.)

```bash
python3 main.py
```

이 스크립트는 작은 "카페 본사 매출 집계 업무"를 컴퓨터 회사 조직에 빗대어 처리합니다.

- **[1] 입력**: 지점별 주문 데이터가 들어옵니다(접수창구).
- **[2] 저장장치 → 메모리**: 데이터를 임시 파일(창고)에 저장했다가 다시 읽어 와서, "저장하면 남고, 메모리는 휘발된다"는 차이를 보여줍니다.
- **[3] 계산**: CPU 역할로 합계·평균·최고 매출 지점을 계산합니다. 같은 계산을 1백만 번 반복해도 1초가 안 걸리는 것을 시간 측정으로 확인합니다.
- **[4] 출력**: 사람이 읽기 좋은 보고서 형태로 화면에 출력합니다.
- **[5] 이진법 맛보기**: "AI"라는 글자가 실제로 어떤 0/1 로 저장되는지 보여줍니다.

코드에서 눈여겨볼 부분은 `process_orders()` 함수입니다. 입력(orders 리스트)을 받아 계산(합계·평균)을 하고 출력(딕셔너리 반환)을 하는, IPO 모델이 함수 하나에 그대로 담긴 구조입니다. 파이썬 문법을 아직 몰라도 괜찮습니다. `#` 뒤의 한국어 주석만 따라 읽으면 흐름이 보이도록 작성했습니다.

## 6. 자주 하는 실수

- **"저장"과 "실행 중"을 혼동**: 문서를 편집하는 동안 내용은 책상(메모리)에만 있습니다. 저장 버튼을 눌러야 창고(디스크)에 보관됩니다. 코드도 마찬가지로, 파일을 수정했으면 저장한 뒤 실행해야 바뀐 내용이 반영됩니다.
- **용량과 속도를 혼동**: "메모리 16GB"와 "SSD 512GB"는 둘 다 저장 공간이지만 역할이 다릅니다. 메모리는 책상 크기(동시에 펼칠 수 있는 작업량), SSD 는 창고 크기(보관 가능한 총량)입니다.
- **컴퓨터가 똑똑하다고 오해**: 컴퓨터는 시킨 것만, 시킨 그대로 합니다. 이후 강의에서 에러를 만나면 "컴퓨터가 이상하다"가 아니라 "내 지시가 어디서 모호했나"를 먼저 의심하는 습관을 들이세요.
