# Lecture 01 · Level 02 — 터미널 첫걸음

> 마우스 없이 키보드 명령만으로 컴퓨터에게 일을 시키는 터미널의 기본 명령(pwd, ls, cd, mkdir, cp, mv, rm)을 익힙니다.

**난이도** ⭐ / **선행** level01 / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

앞으로 이 커리큘럼의 모든 실습은 터미널에서 `python3 main.py` 를 입력하는 것으로 시작합니다. 개발자와 협업할 때도, 클라우드 서버에 접속할 때도, AI 도구를 설치할 때도 화면에 나타나는 것은 마우스로 클릭할 버튼이 아니라 깜빡이는 커서 하나입니다. 터미널을 두려워하면 그 앞에서 매번 멈추게 됩니다.

터미널이 강력한 이유는 **말로 시킨 일은 기록되고 반복할 수 있기 때문**입니다. 마우스로 폴더 100개를 만드는 일은 100번의 클릭이지만, 터미널에서는 한 줄이면 됩니다. 그리고 그 한 줄을 저장해 두면 다음 달에도, 후임자도 똑같이 실행할 수 있습니다. 반복 업무 자동화(level08)의 출발점이 바로 여기입니다.

## 2. 비유로 이해하기

**GUI(그래픽 화면)는 손짓으로 일 시키기, 터미널은 말로 일 시키기**입니다.

부하 직원에게 서류 정리를 시킨다고 해 봅시다. 손짓으로 하려면 직접 캐비닛 앞까지 걸어가 "이거, 이쪽으로" 하며 하나하나 가리켜야 합니다(마우스 클릭·드래그). 반면 말로 하면 "3층 캐비닛의 2023년 서류를 전부 창고로 옮겨 주세요" 한 문장이면 끝나고, 같은 지시를 문서로 남겨 매달 반복시킬 수도 있습니다.

터미널의 명령 구조도 실제 지시어와 닮았습니다.

```
cp  report.txt  backup/
동사    목적어      장소
"복사해, report.txt를, backup 폴더로"
```

명령어는 동사, 그 뒤에 오는 것들은 목적어와 부사어(옵션)입니다. `ls -l` 의 `-l` 처럼 `-` 로 시작하는 것은 "자세히", "전부" 같은 부사 역할의 **옵션(option)**입니다.

한 가지 더: 터미널에는 항상 "내가 지금 서 있는 위치", 즉 level01 에서 배운 **현재 작업 디렉터리(CWD)**가 있습니다. 모든 명령은 지금 서 있는 방을 기준으로 실행됩니다. 그래서 터미널 작업의 제1습관은 "내가 지금 어디지?"를 확인하는 것입니다.

## 3. 핵심 개념

### 3-1. 생존 명령어 7가지

| 명령 | 뜻 | 비유 |
|---|---|---|
| `pwd` | 현재 위치 출력 (print working directory) | "여기가 몇 층 무슨 방이죠?" |
| `ls` | 현재 폴더 내용 나열 (list) | "이 방에 뭐가 있죠?" |
| `cd 폴더` | 위치 이동 (change directory) | "그 방으로 이동" |
| `mkdir 폴더` | 폴더 생성 (make directory) | "새 캐비닛 설치" |
| `cp 원본 대상` | 복사 (copy) | "사본 떠서 저쪽에" |
| `mv 원본 대상` | 이동 또는 이름 변경 (move) | "옮겨. 같은 방 안이면 이름표만 교체" |
| `rm 파일` | 삭제 (remove) | "파쇄기로. **휴지통 없이 즉시**" |

자주 쓰는 조합: `cd ..` (한 층 위로), `cd ~` (내 홈 폴더로), `ls -l` (상세 목록), `mkdir -p a/b/c` (중간 폴더까지 한 번에).

### 3-2. 맥과 윈도우의 차이

- **맥(macOS)**: 기본 앱 "터미널"을 열면 됩니다. 리눅스와 같은 계열(유닉스)이라 위 명령이 그대로 통합니다. 개발 서버 대부분이 리눅스이므로, 맥 사용자는 익힌 것을 서버에서도 그대로 씁니다.
- **윈도우(Windows)**: 전통적인 "명령 프롬프트(cmd)"는 명령이 다릅니다(`ls` 대신 `dir`, `cp` 대신 `copy`). 최근에는 **PowerShell** 이 `ls`, `cd` 등 상당수를 지원하고, 개발용으로는 **WSL(Windows Subsystem for Linux)** 을 설치해 윈도우 안에서 리눅스 터미널을 쓰는 것이 표준적인 선택입니다. 이 커리큘럼의 명령은 맥/리눅스(WSL 포함) 기준입니다.

| 용도 | 맥/리눅스/WSL | 윈도우 cmd |
|---|---|---|
| 목록 | `ls` | `dir` |
| 복사 | `cp` | `copy` |
| 이동 | `mv` | `move` |
| 삭제 | `rm` | `del` |
| 경로 구분자 | `/` | `\` |

### 3-3. 셸이라는 통역사

터미널 창 안에서 실제로 명령을 해석해 실행하는 프로그램을 **셸(shell)**이라고 합니다. 맥의 기본 셸은 zsh, 리눅스는 주로 bash 입니다. "터미널은 창문, 셸은 그 안에서 지시를 알아듣는 통역사"라고 기억하면 됩니다. 나중에 `.sh` 파일(셸 스크립트)을 만나면, 그것이 이 통역사에게 줄 지시서 묶음입니다.

### 3-4. 위험한 명령에 대한 경고

`rm` 은 휴지통을 거치지 않고 즉시 삭제합니다. 특히 `rm -rf 폴더` 는 폴더와 그 안의 모든 것을 되돌릴 수 없이 지웁니다. 실무에서는 삭제 전에 `ls` 로 대상을 먼저 확인하는 습관, 그리고 와일드카드(`*.txt` 같은 패턴)를 쓸 때 한 번 더 읽어 보는 습관이 사고를 막습니다.

## 4. 실습 — main.py

```bash
python3 main.py
```

진짜 터미널을 조작하기 전에, 파이썬으로 만든 **미니 셸 시뮬레이터**로 안전하게 연습합니다. 스크립트는 임시 폴더 안에 작은 연습용 사무실을 만들고, 미리 짜인 시나리오의 명령을 한 줄씩 "입력 → 실행 → 결과"로 보여줍니다.

- **[1] 연습장 준비**: 임시 폴더에 샘플 파일 몇 개를 깝니다. 실수해도 여러분 컴퓨터에는 아무 영향이 없습니다.
- **[2] 시나리오 실행**: `pwd → ls → mkdir backup → cp → cd → mv(이름 변경) → rm` 순서로, 실제 업무(보고서 백업·정리)를 명령으로 처리합니다. 각 명령마다 "무엇을 한 것인지" 한국어 해설이 붙습니다.
- **[3] 최종 상태 확인**: 정리가 끝난 폴더 구조를 보여주고, 같은 작업을 마우스로 했다면 몇 번의 클릭이었을지 비교합니다.

핵심 코드는 `MiniShell` 클래스입니다. `cwd`(현재 위치)를 상태로 들고 있으면서 `cmd_ls`, `cmd_cd` 같은 메서드가 각 명령을 pathlib 으로 구현합니다. 즉 **셸이 하는 일이란 결국 "현재 위치를 기억하며 파일 시스템 함수를 호출하는 것"**임을 코드로 확인하는 셈입니다. 시뮬레이터로 흐름을 익힌 뒤, 진짜 터미널을 열어 같은 명령을 직접 쳐 보세요.

## 5. 직접 해보기

1. **(쉬움)** 진짜 터미널을 열고 `pwd`, `ls`, `cd Documents`(또는 있는 폴더 아무 곳), `cd ..` 를 순서대로 쳐 보세요. 각 명령 후 `pwd` 로 위치가 어떻게 변하는지 확인하세요. *(힌트: 길을 잃으면 `cd ~` 로 홈에 돌아옵니다.)*
2. **(보통)** main.py 의 `SCENARIO` 리스트에 `mkdir archive` 와 `mv 회의록.txt archive` 두 명령을 추가해, 회의록이 archive 폴더로 이동하도록 만들어 보세요. *(힌트: 기존 시나리오 항목의 형식을 그대로 따라 하면 됩니다.)*
3. **(도전)** `MiniShell` 에 `cat 파일` 명령(파일 내용 출력)을 추가해 보세요. *(힌트: `cmd_cat` 메서드를 만들고 `read_text()` 를 쓰면 됩니다. 다른 `cmd_` 메서드가 등록되는 방식을 관찰하세요.)*

## 6. 자주 하는 실수

- **현재 위치를 확인하지 않고 명령 실행**: 엉뚱한 폴더에 파일을 만들거나 지우는 사고의 주범입니다. 습관처럼 `pwd` 와 `ls` 를 먼저 치세요.
- **공백이 있는 이름을 그대로 입력**: `cd My Documents` 는 "My"와 "Documents" 두 개의 목적어로 해석됩니다. `cd "My Documents"` 처럼 따옴표로 감싸야 합니다.
- **`rm` 을 휴지통으로 착각**: 터미널의 삭제는 즉시·영구입니다. 중요한 폴더에서는 `rm` 대신 일단 `mv` 로 다른 곳에 치워 두는 것도 안전한 요령입니다.
- **명령이 안 듣는다고 당황**: 오타이거나(명령은 철자에 엄격합니다), 윈도우 cmd 에서 맥/리눅스 명령을 친 경우가 대부분입니다. 에러 메시지를 그대로 읽어 보는 습관이 최고의 선생님입니다.

## 다음 레벨 예고

터미널이라는 대화 창구를 익혔으니, 이제 그 창구에서 **파이썬을 불러낼 차례**입니다. level03 에서는 파이썬이 설치되어 있는지 확인하고, REPL 과 스크립트 실행의 차이를 배우며, 내 컴퓨터의 파이썬 환경을 자가진단하는 스크립트를 실행해 봅니다.
