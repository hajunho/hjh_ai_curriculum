# Lecture 08 · Level 10 — 학습률 스케줄과 학습 안정화

> 같은 모델·같은 데이터라도 "학습률을 어떻게 운전하느냐"에 따라 발산 사고와 최고 성능이 갈립니다. warmup·cosine decay·그래디언트 클리핑·배치정규화를 통제 실험으로 배웁니다.

**난이도** ⭐⭐⭐⭐ / **선행** level09 (과적합 방지) / **예상 시간** 55분

## 1. 왜 배우나 — 비즈니스 관점

최신 모델 학습 보고서나 논문 기술 문서에는 거의 예외 없이 "warmup 후 cosine decay, gradient clipping 1.0" 같은 문구가 등장합니다. LLM 학습 레시피의 표준 문법이기 때문입니다. 이 레벨을 마치면 그 문구가 해독됩니다. 실무 가치는 더 직접적입니다 — 학습 로그에서 loss 가 NaN 으로 터졌을 때, "학습률 낮추고 클리핑 거세요"라는 1차 대응을 스스로 할 수 있게 됩니다. GPU 시간은 곧 돈이므로, 발산으로 날리는 학습 1회를 막는 것만으로도 이 레벨의 학습 비용은 회수됩니다. 또한 level06 에서 "일단 Adam"으로 시작했다면, 이번엔 SGD 계열을 고성능으로 운전하는 기술을 배웁니다.

## 2. 비유로 이해하기

**학습률 운전의 3원칙.**

- **warmup = 출근 직후 바로 전력질주하지 않기.** 학습 초반의 가중치는 난수 상태라, 초반 기울기는 "아직 사정을 모르는 신입의 강한 주장" 같습니다. 처음 몇 스텝은 보폭을 서서히 올리며 지형 파악부터 합니다.
- **cosine decay = 마감이 다가올수록 세밀하게 다듬기.** 프로젝트 초반엔 과감한 방향 전환이 유익하지만, 마감 직전엔 미세 조정만 해야 합니다. 학습률을 코사인 곡선처럼 부드럽게 0 근처까지 내리면, 골짜기 바닥에서 잔진동 없이 정착합니다.
- **그래디언트 클리핑 = 핸들 최대 회전각 제한.** 이상한 배치 하나가 "핸들을 720도 꺾어!"라는 신호(거대 기울기)를 보내도, 물리적으로 일정 각도 이상 안 꺾이게 만든 안전장치입니다. 방향은 유지하되 크기만 자릅니다.
- **배치정규화 = 층 사이 눈금 교정기.** 공정이 길어지면(층이 깊어지면) 중간 산출물의 단위가 제멋대로 커지거나 쪼그라듭니다. 각 공정 입구에서 눈금을 평균 0·분산 1 로 다시 맞춰 주면, 뒤 공정이 항상 익숙한 범위의 입력을 받아 안정됩니다.

## 3. 핵심 개념

### 3-1. 발산의 해부

level03 에서 본 "너무 큰 학습률 → 골짜기 건너뛰기"가 다층 신경망에서는 더 극적으로 나타납니다. 한 번 크게 튄 가중치가 더 큰 기울기를 만들고, 모멘텀이 그 방향으로 가속을 붙여 몇 스텝 만에 loss 가 무한대(NaN)로 갑니다. 실습의 조건 B 가 정확히 이 사고입니다. 로그에서 loss 가 NaN 이면: 학습률↓, 클리핑 추가, (심하면) 데이터 이상치 점검 — 이 순서로 대응합니다.

### 3-2. warmup + cosine decay 의 스케줄 함수

- 전체 스텝의 앞 10%: lr 를 0 → base_lr 로 선형 증가.
- 이후: lr = base_lr × 0.5 × (1 + cos(π × 진행률)) — 부드럽게 0 으로.

PyTorch 에서는 `torch.optim.lr_scheduler.LambdaLR` 이나 `CosineAnnealingLR` 로 쓰지만, 실습에서는 원리가 보이도록 스텝마다 `param_groups[0]["lr"]` 를 직접 바꿉니다. 프레임워크 스케줄러도 내부에서 하는 일이 이것입니다.

### 3-3. 클리핑의 두 종류

- **norm 클리핑(표준)**: 모든 기울기를 하나의 벡터로 보고 전체 길이가 임계값을 넘으면 비율로 축소. 방향 보존. `clip_grad_norm_(params, max_norm)`.
- **value 클리핑**: 각 성분을 [-c, c] 로 자름. 방향이 틀어질 수 있어 보조적.

임계값은 0.5~1.0 이 흔한 출발점이며, "평상시 기울기 크기보다 약간 큰 값"이 요령입니다.

### 3-4. 배치정규화 개념 (이번엔 개념까지만)

`nn.BatchNorm1d(64)` 를 Linear 뒤에 끼우면 배치 단위로 정규화하고, 학습 가능한 늘리기/이동 파라미터(γ, β)로 표현력을 복원합니다. 평가 시에는 학습 중 적립한 이동평균 통계를 쓰므로 `model.eval()` 전환이 여기서도 중요합니다. 깊은 CNN(lecture09)에서 본격적으로 사용합니다.

실행:

같은 초기 가중치(시드 고정)의 1-64-64-1 MLP 로 y=sin(2x) 곡선 회귀를 네 가지 레시피로 학습합니다.

| 조건 | 레시피 | 최종 valid MSE |
|---|---|---|
| A | 고정 lr=0.05 | 0.0071 |
| B | 고정 lr=0.2 | **NaN (발산)** |
| C | lr=0.2 + 클리핑 0.5 | 0.0528 |
| D | warmup+cosine(0.2) + 클리핑 | **0.0045 (최고)** |

- B: 학습률을 4배 올렸을 뿐인데 몇 스텝 만에 폭발합니다. 출력의 "발산(NaN)"이 실제 사고 로그의 모습입니다.
- C: 같은 과속에서도 클리핑이 있으면 죽지 않습니다. 다만 성능은 어중간 — 안전장치는 사고를 막을 뿐 좋은 운전을 대신하지 않습니다.
- D: 클리핑 + 스케줄 조합이 안전 운전(A)보다도 좋아집니다. 중반의 높은 학습률로 넓게 탐색하고 막판에 미세 정착한 덕분입니다. `assert` 로 B 의 발산과 D<A 를 재현 보장합니다.
- `outputs/lr_schedule_compare.png`: 왼쪽은 조건별 valid loss(로그 눈금, NaN 은 위쪽에 캡 표시), 오른쪽은 A 와 D 의 스텝별 학습률 곡선 — 사다리꼴 모양의 warmup+cosine 을 눈으로 확인해 보세요.

## 6. 자주 하는 실수

- **스케줄을 에폭 단위로만 갱신.** warmup 은 보통 "스텝" 단위입니다. 에폭 단위로 하면 워밍업이 통째로 건너뛰어질 수 있습니다.
- **클리핑을 backward 전에 호출.** 기울기는 `backward()` 후에 생깁니다. 순서는 backward → clip → step.
- **발산 후 이어서 학습.** NaN 이 한 번 뜨면 가중치가 이미 오염된 것입니다. 재시작(또는 마지막 정상 체크포인트 복구)이 정답입니다.
- **Adam 에 과한 스케줄 의존.** Adam 은 자체 적응 기능이 있어 스케줄 이득이 SGD 보다 작을 수 있습니다. 반대로 대형 모델 학습(LLM)에서는 AdamW + warmup + cosine 이 표준 — 규모에 따라 상식이 달라집니다.
- **배치정규화 + 배치 크기 1~2.** 통계가 불안정해 오히려 해롭습니다. 작은 배치에는 LayerNorm 계열을 씁니다(트랜스포머가 그 예).
