# Lecture 08 · Level 08 — 학습 루프·배치·에폭

> 데이터를 접시(미니배치)에 나눠 담아 학습하는 실무 표준 루프를 Dataset/DataLoader 로 구현하고, train/valid loss 곡선을 그려 "학습 건강검진표" 읽는 법을 배웁니다.

**난이도** ⭐⭐⭐ / **선행** level07 (MLP 분류 모델) / **예상 시간** 55분

## 1. 왜 배우나 — 비즈니스 관점

이 레벨에서 만드는 학습 루프 템플릿은 앞으로 여러분이 보게 될 **모든 딥러닝 코드의 뼈대**입니다. 컴퓨터 비전(lecture09), NLP(lecture10), LLM 파인튜닝(lecture12) — 모델과 데이터만 바뀔 뿐 루프는 그대로입니다. 그리고 실무에서 딥러닝 담당자가 하루에도 몇 번씩 보는 화면이 바로 학습곡선(learning curve)입니다. 곡선 두 줄만 읽을 줄 알면 "지금 잘 되고 있나요?", "더 돌리면 좋아지나요?", "언제 멈추죠?" 같은 질문에 데이터로 답할 수 있습니다. 외주 개발사의 주간 보고서에 실려 오는 그 그래프를, 이번 레벨 후에는 직접 해석하게 됩니다.

## 2. 비유로 이해하기

**뷔페 접시 비유.** 창고(전체 데이터 1,600건)의 음식을 한 번에 다 먹을 수는 없습니다(메모리 한계). 그래서 접시(배치 64건)에 나눠 담아 여러 번 왕복합니다.

- **배치(batch)** = 접시 한 번에 담는 양.
- **스텝(step)** = 접시 하나를 비우는 것(배치 1개로 가중치 1회 업데이트).
- **에폭(epoch)** = 창고 전체를 한 바퀴 다 먹는 것(1,600 ÷ 64 = 25스텝).
- **셔플(shuffle)** = 매 에폭 접시 담는 순서를 무작위로 섞기. 항상 같은 순서로 먹으면 마지막 접시의 맛(최근 배치의 경향)에 입맛이 길들여집니다.

**Dataset = 창고 사서, DataLoader = 배식 담당.** 사서(Dataset)는 두 가지 질문에만 답합니다 — "전체 몇 건?"(`__len__`), "i번째 것 주세요"(`__getitem__`). 배식 담당(DataLoader)이 사서에게 번호표를 불러 접시를 꾸리고, 섞고, 배급합니다. 역할이 분리되어 있어 데이터가 CSV 든 이미지 폴더든 사서만 바꾸면 루프는 그대로입니다.

## 3. 핵심 개념

### 3-1. 왜 미니배치인가

| 방식 | 장점 | 단점 |
|---|---|---|
| full-batch (전체 한 번에) | 기울기가 정확 | 메모리 한계, 업데이트 1회/에폭으로 느림 |
| 배치 1건 (온라인) | 업데이트 잦음 | 기울기가 널뜀, 하드웨어 비효율 |
| **미니배치 (32~512)** | 둘의 절충 + GPU 병렬에 최적 | 배치 크기라는 하이퍼파라미터 추가 |

미니배치의 "적당히 널뛰는" 기울기는 단점만은 아닙니다 — 얕은 웅덩이(나쁜 지역해)를 빠져나오게 돕는 순기능도 있습니다.

### 3-2. 표준 학습 루프 템플릿

```
for epoch in range(n_epochs):
    train 한 바퀴: 배치마다 zero_grad → forward → loss → backward → step
    valid 한 바퀴: no_grad 로 채점만 (backward 없음!)
    두 loss 를 기록
```

실습 코드의 `run_epoch()` 함수는 opt 유무로 학습/평가를 겸하는 실무형 작성법입니다. 평가 시 `model.eval()` + `torch.no_grad()` 를 켜는 것, loss 를 배치 크기로 가중 평균하는 것이 포인트입니다.

### 3-3. 학습곡선 = 건강검진표

- **train·valid 함께 하강**: 정상. 계속 진행.
- **train 하강, valid 상승(벌어지는 가위)**: 과적합 시작. 기출문제 점수만 오르는 중 — 멈추거나 level09 의 처방 적용.
- **둘 다 높게 정체**: 과소적합. 모델 용량·학습률·특징을 재검토.
- **톱니처럼 요동**: 학습률 과대 또는 배치가 너무 작음.

### 3-4. BCEWithLogitsLoss

이번 모델은 끝에 Sigmoid 를 빼고 로짓(logit, 확률로 바꾸기 전의 점수)을 그대로 출력합니다. `BCEWithLogitsLoss` 가 Sigmoid+BCE 를 내부에서 수치적으로 안전하게 한 번에 계산해 주기 때문입니다. 실무 표준이므로 여기서부터 이 방식을 씁니다. 판정도 확률 0.5 대신 로짓 0 초과로 동일하게 할 수 있습니다.

## 6. 자주 하는 실수

- **valid 루프에서 backward 호출.** 검증 데이터로 학습해 버리는 중대 사고입니다. 반드시 no_grad + opt 없이 채점만.
- **에폭 loss 를 단순 평균.** 마지막 배치는 크기가 다를 수 있으므로 `loss.item() * len(xb)` 로 가중 평균해야 정확합니다.
- **매 에폭 Dataset 을 다시 생성.** 전처리가 매번 반복돼 시간을 낭비합니다. Dataset 은 한 번 만들고 재사용합니다.
- **num_workers 부터 올리기.** 병렬 로딩은 대형 이미지 데이터에서 유효하지만, 소형 데이터에서는 프로세스 생성 비용이 더 커 오히려 느립니다(이 실습은 기본값 0).
- **"에폭을 늘리면 늘 좋아진다"는 믿음.** 이번 실행이 반증입니다 — 40에폭의 valid 성능은 5에폭보다 나쁩니다.

## 다음 레벨 예고

이번 실행에서 목격한 "가위 모양"(train↓ valid↑)이 바로 과적합입니다. level09 에서는 일부러 심한 과적합을 만들어 놓고, 드롭아웃(무작위 결근 훈련)·weight decay(큰 가중치에 세금)·조기종료(성적 나빠지면 하산) 세 가지 처방이 각각 valid 성능을 얼마나 회복시키는지 비교 실험합니다.
