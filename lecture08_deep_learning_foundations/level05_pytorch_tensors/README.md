# Lecture 08 · Level 05 — PyTorch 첫걸음, 텐서

> 딥러닝 프레임워크 PyTorch 의 기본 재료인 텐서(tensor)를 numpy 와 비교하며 투어합니다. 결론부터: numpy 를 알면 90% 는 이미 배운 것입니다.

**난이도** ⭐⭐⭐ / **선행** level04 (역전파 밑바닥 구현) / **예상 시간** 40분

## 1. 왜 배우나 — 비즈니스 관점

level00~04 에서 신경망의 원리를 numpy 로 전부 구현했습니다. 이제 실무의 언어로 갈아탈 차례입니다. PyTorch 는 연구와 산업 양쪽에서 가장 널리 쓰이는 오픈소스 딥러닝 프레임워크로, 이후 컴퓨터 비전·NLP·LLM 강의의 모든 코드가 PyTorch 로 작성됩니다. 협력사의 모델 코드를 검수하든, 사내 데이터 과학자와 대화하든, 채용 공고를 읽든 PyTorch 는 공용어입니다. 그리고 그 공용어의 명사(名詞)가 텐서입니다. 텐서의 모양(shape)·자료형(dtype)·장치(device) 세 가지만 읽을 줄 알면, 낯선 딥러닝 코드도 데이터가 어떻게 흘러가는지 따라갈 수 있습니다.

## 2. 비유로 이해하기

**텐서 = 엑셀 시트의 일반화 + 두 가지 초능력.**

- 숫자 하나(스칼라)는 셀 1칸, 벡터는 1열, 행렬은 시트 1장. 텐서는 여기서 더 나아가 "시트 여러 장 묶음"(3차원), "묶음의 묶음"(4차원)까지 자연스럽게 확장한 것입니다. 예: 흑백 이미지 100장은 (100, 16, 16) 텐서.
- numpy 배열도 여기까지는 똑같습니다. 텐서의 초능력은 두 가지입니다.
  1. **자동미분**: 계산 과정을 스스로 장부에 기록해 두었다가, 나중에 미분(책임 추적)을 자동으로 해 줍니다. level04 에서 손으로 한 일이 공짜가 됩니다.
  2. **GPU 이사**: `.to('cuda')` 한 줄로 계산 장소를 CPU 에서 GPU 로 옮깁니다. 이삿짐 트럭 한 번이면 같은 살림(데이터)이 훨씬 큰 작업장에서 돌아갑니다.

**device 는 "어느 책상에서 일하는가"** 입니다. CPU 책상, NVIDIA GPU 책상(cuda), 애플 실리콘 GPU 책상(mps). 중요한 규칙 하나 — 같은 책상 위에 있는 재료끼리만 연산할 수 있습니다. CPU 텐서와 GPU 텐서를 섞으면 에러가 납니다.

## 3. 핵심 개념

### 3-1. 텐서 3속성: shape, dtype, device

에러 메시지의 90%는 이 셋 중 하나가 안 맞아서 납니다. 낯선 텐서를 만나면 반사적으로 `x.shape, x.dtype, x.device` 를 확인하는 습관을 들이세요.

### 3-2. 모양 바꾸기와 브로드캐스팅

- `reshape` / `view` 는 데이터를 옮기지 않고 "보는 창"만 바꿉니다. 원소 12개는 (3,4)로도 (2,6)으로도 볼 수 있습니다.
- 브로드캐스팅: (3,1) + (4,) 처럼 모양이 달라도, 규칙(뒤 차원부터 1 또는 동일이면 확장)에 맞으면 자동으로 늘려 계산합니다. numpy 와 규칙이 동일합니다.

### 3-3. numpy 와의 관계 — 공유 vs 복사

| 방법 | 동작 | 주의 |
|---|---|---|
| `torch.from_numpy(arr)` | **메모리 공유** (같은 종이를 같이 봄) | 한쪽을 고치면 다른 쪽도 바뀜 |
| `t.numpy()` | **메모리 공유** (CPU 텐서만) | 위와 동일 |
| `torch.tensor(arr)` | **복사본** 생성 | 안전하지만 메모리 2배 |

공유는 빠르지만 "멀리서 값이 바뀌는" 사고의 원인이 되기도 합니다. 실습 [5]에서 직접 확인합니다.

### 3-4. dtype — 정밀도와 메모리의 거래

float32(4바이트)가 기본값입니다. float16(2바이트)은 메모리와 속도를 절반/2배로 만드는 대신 소수점 뒷자리를 잃습니다. 이 거래가 level11 의 혼합정밀도(mixed precision) 학습으로 이어집니다.

### 3-5. 왜 numpy 를 그냥 쓰면 안 되나

"numpy 로도 level04 에서 신경망을 다 만들었는데, 굳이 갈아타야 하나요?" 좋은 질문입니다. 소형 실습은 numpy 로 충분합니다. 하지만 (1) 가중치가 수백만 개가 되면 미분을 손으로 짜는 것이 불가능에 가깝고, (2) CPU 만으로는 학습 시간이 수백 배 길어지며, (3) 검증된 층(layer)·옵티마이저·데이터 로더 부품을 재사용할 수 없습니다. PyTorch 는 이 세 문제를 각각 autograd, device, nn 모듈로 해결합니다. 즉 numpy 가 "손계산 + 종이 장부"라면 PyTorch 는 "회계 시스템"입니다. 원리는 같지만 규모가 달라지면 도구를 바꿔야 합니다.

### 3-6. 이 실습의 한계 안내

이번 레벨의 텐서는 아직 "미분 기능을 끈" 상태입니다. `requires_grad` 스위치를 켜는 순간부터가 진짜 딥러닝이고, 그것이 다음 레벨입니다.

출력 순서:

- **[2]~[4]** reshape·전치·브로드캐스팅·집계·행렬곱. `(3,4) @ (4,2) = (3,2)` 가 곧 신경망 한 층입니다. level01~04 에서 numpy 로 하던 그 연산입니다.
- **[5]** `from_numpy` 로 만든 텐서는 numpy 배열과 메모리를 공유함을 실험으로 증명합니다. numpy 쪽을 99로 고치면 텐서도 99가 됩니다.

- **[7]** float32 → float16 변환에서 뒷자리가 깎이는 것을 눈으로 확인합니다.
- **[8]** numpy ↔ torch API 매핑표. 이 표를 옆에 두면 numpy 경험이 그대로 이식됩니다.

## 6. 자주 하는 실수

- **정수 텐서로 신경망 계산.** `torch.tensor([1, 2])` 는 int64 가 됩니다. 가중치 계산에는 float 이 필요하므로 `[1.0, 2.0]` 이나 `dtype=torch.float32` 를 명시하세요.
- **공유/복사 혼동.** `from_numpy` 로 만든 텐서를 수정했는데 원본 numpy 배열까지 바뀌어 "귀신 버그"가 됩니다. 확실하지 않으면 `clone()` 하세요.
- **device 불일치.** `RuntimeError: Expected all tensors to be on the same device` — 모델은 GPU, 데이터는 CPU 에 있을 때 납니다. 데이터와 모델을 같은 책상으로 옮기세요.
- **`view` 실패에 당황.** 전치 등으로 메모리가 연속이 아니게 되면 `view` 가 거부합니다. 그때는 `reshape` 나 `contiguous().view()` 를 쓰면 됩니다.
