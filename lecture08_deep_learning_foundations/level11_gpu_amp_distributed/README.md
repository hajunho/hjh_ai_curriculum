# Lecture 08 · Level 11 — GPU·혼합정밀도·분산학습 개념

> 왜 딥러닝은 GPU 를 쓰는지, fp16/bf16 이라는 "자릿수 적은 계산기"가 왜 등장했는지, 모델이 GPU 한 장에 안 들어갈 때 어떻게 나눠 드는지(DDP/FSDP)를 — 코드 실행이 아니라 **견적 계산**으로 이해합니다.

**난이도** ⭐⭐⭐⭐⭐ / **선행** level10 (학습률·안정화) / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

이 레벨의 목표는 GPU 클러스터를 직접 운영하는 것이 아닙니다. **인프라 예산 회의에서 속지 않는 것**입니다. "8B 모델 파인튜닝하려면 GPU 몇 장이 필요한가요?", "A사는 bf16 으로 학습했다는데 무슨 뜻인가요?", "FSDP 를 쓰면 비용이 줄어드나요?" — 이런 질문에 근거 숫자로 답하는 사람과 감으로 답하는 사람의 차이는 곧 수천만 원 단위의 견적 차이가 됩니다. 다행히 핵심 계산은 곱셈 하나입니다: **파라미터 수 × 바이트 수 + 활성값**. 이번 레벨에서 그 곱셈을 직접 해 봅니다. 여기서 만든 감각은 lecture12(LLM)에서 API 비용·파인튜닝 전략을 판단할 때 그대로 재사용됩니다.

## 2. 비유로 이해하기

- **CPU vs GPU = 박사 몇 명 vs 산수 요원 수천 명.** CPU 코어는 복잡한 분기·판단을 잘하는 박사 소수 정예입니다. GPU 는 단순 곱셈·덧셈만 하는 요원 수천 명입니다. 딥러닝 계산의 90% 이상은 행렬곱 — "단순 곱셈을 대량으로 동시에" — 이므로 산수 요원 부대의 압승 종목입니다.
- **fp16/bf16 = 자릿수 적은 계산기.** fp32 는 자릿수 넉넉한 계산기(4바이트), fp16 은 자릿수 절반짜리(2바이트)입니다. 반값·2배속이지만 아주 크거나 아주 작은 수에서 오차가 납니다. bf16 은 같은 2바이트인데 "표현 가능한 범위(지수부)"를 fp32 만큼 넓게 잡고 대신 정밀한 자리(가수부)를 줄인 변형 — 기울기처럼 크기가 널뛰는 수에 강해 대형 모델 학습의 표준이 됐습니다.
- **혼합정밀(AMP) = 계산은 속기, 원본은 정서(正書).** 빠른 계산(곱셈)은 반정밀로 하고, 실수가 쌓이면 안 되는 원본 장부(가중치 마스터 사본, 누적 합산)는 fp32 로 유지합니다. fp16 사용 시엔 너무 작은 기울기가 0으로 사라지지 않게 loss 를 일부러 키웠다 되돌리는 loss scaling 을 병행합니다.
- **DDP = 같은 짐을 복사해서 들고 각자 다른 상자를 나름.** 모델(짐)이 한 장에 들어갈 때, GPU 마다 모델을 복사하고 데이터(상자)만 나눠 처리한 뒤 기울기를 평균합니다. 목적은 **속도**.
- **FSDP/ZeRO = 짐 자체를 쪼개 나눠 들기.** 모델이 한 장에 안 들어가면, 가중치·그래디언트·옵티마이저 상태를 조각내 GPU 들이 나눠 보관하고, 계산에 필요한 순간에만 조각을 모았다가 흩습니다. 목적은 **한 장의 한계 돌파**.

## 3. 핵심 개념

### 3-1. 연산량은 세제곱으로 큰다

(n,n) 행렬곱의 연산량은 약 2n³ FLOP 입니다. n 이 8배면 연산량은 512배 — 모델 폭을 "조금" 키워도 계산은 폭증합니다. GPU 가 선택이 아니라 필수가 되는 이유입니다.

### 3-2. 추론 메모리 vs 학습 메모리

- **추론**: 가중치만 있으면 됩니다. 8B × 2바이트(bf16) ≈ 15GB — 큰 GPU 한 장 감입니다.
- **학습**: 가중치 + 그래디언트 + **Adam 상태(m, v)** + 활성값이 전부 필요합니다. 관례적 근사로 **파라미터당 16바이트**(ZeRO 논문 계열의 표준 셈법): fp32 는 4+4+8, 혼합정밀도 fp16 가중치 2 + grad 2 + fp32 마스터 4 + Adam 8 로 결국 16입니다. 즉 **AMP 를 써도 "저장" 메모리는 거의 안 줄어듭니다** — 이득은 계산 속도(~2배), 활성값 절반, 통신량 절반에서 나옵니다. level06 에서 "Adam 은 파라미터당 이동평균 2개를 저장한다"고 했던 그 비용이 여기서 청구서로 돌아옵니다.

### 3-3. 8B 학습 견적 한 줄 계산

8e9 × 16바이트 ≈ 119GB (상태) + 활성값 10~20GB ≈ **130~140GB** → 80GB GPU 한 장에 안 들어감 → 분산 필요. 이 세 줄이 이 레벨의 핵심 산출물입니다.

### 3-4. DDP 와 FSDP 선택 기준

| 상황 | 선택 | 메모리/장 | 효과 |
|---|---|---|---|
| 모델이 1장에 들어감, 더 빨리 | DDP | 그대로 (전체 복사) | 처리량 ~장 수 배 |
| 모델이 1장에 안 들어감 | FSDP/ZeRO | 상태 ÷ 장 수 + 활성값 | 큰 모델 학습 가능 |

FSDP 는 통신이 늘어나 장당 효율은 DDP 보다 낮습니다. "들어가면 DDP, 안 들어가면 FSDP"가 1차 규칙입니다.

## 6. 자주 하는 실수

- **추론 견적으로 학습 예산을 잡기.** "8B = 15GB 니까 한 장이면 되죠?"는 추론 얘기입니다. 학습은 ~9배(16+활성 vs 2바이트)로 뜁니다.
- **fp16 과 bf16 을 같은 것으로 취급.** 같은 2바이트지만 fp16 은 범위가 좁아 loss scaling 필수, bf16 은 범위가 넓어 다루기 쉽습니다. 하드웨어가 bf16 을 지원하는지도 확인 항목입니다.
- **GPU 수 = 속도 배수라는 기대.** 통신 비용 때문에 8장이 8배가 되지는 않습니다. 특히 FSDP 는 모았다 흩는 통신이 커서, 네트워크(NVLink 등)가 병목이 되기도 합니다.
- **활성값을 잊은 견적.** 상태 메모리만 계산하면 배치를 조금만 키워도 OOM(메모리 부족)이 납니다. 견적서에는 항상 "활성값 + 여유 10~20%"를 더하세요.
- **분산 = 만능 절약이라는 오해.** FSDP 는 메모리를 나누는 것이지 총비용을 줄이는 것이 아닙니다. 총 GPU·시간 비용은 오히려 늘 수 있습니다 — 목적은 "불가능을 가능으로"입니다.
