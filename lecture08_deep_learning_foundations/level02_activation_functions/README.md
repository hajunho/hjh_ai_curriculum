# Lecture 08 · Level 02 — 활성화 함수

> 층을 아무리 쌓아도 비선형 활성화가 없으면 결국 선형 모델 하나와 같다는 사실을 행렬곱으로 수치 증명하고, sigmoid/tanh/ReLU의 모양과 기울기를 그림으로 비교하며 기울기 소실과 죽은 ReLU 문제를 이해합니다.

**난이도** ⭐⭐ / **선행** level01_perceptron_from_scratch / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

level00~01에서 우리는 두 가지를 확인했습니다. 직선 하나(선형 모델)로는 XOR 같은 얽힌 문제를 못 풀고, 좌표 변환(은닉 표현)을 거치면 풀린다는 것입니다. 그럼 "선형 변환을 여러 층 쌓으면 되지 않을까?"라는 생각이 자연스럽게 듭니다. 이번 레벨의 첫 번째 결론은 냉정합니다. 선형 층은 100개를 쌓아도 수학적으로 선형 층 1개와 완전히 같습니다. 층 사이에 비선형(nonlinear) 함수, 즉 활성화 함수(activation function)를 끼워 넣어야 비로소 "깊이"가 의미를 가집니다.

실무에서 이 지식은 두 장면에서 쓰입니다. 첫째, 딥러닝 도구를 쓸 때 ReLU, sigmoid 같은 이름이 설정 화면과 코드 예제 곳곳에 등장하는데, 각각의 성격을 알면 기본값을 왜 그렇게 두는지 이해하고 함부로 바꾸지 않게 됩니다. 둘째, "모델이 학습이 안 된다"는 보고를 받았을 때 원인 후보로 기울기 소실(vanishing gradient)이나 죽은 ReLU(dead ReLU) 같은 진단 용어를 알아들을 수 있습니다. 오늘 배우는 내용은 딥러닝 역사에서 실제로 판도를 바꾼 부품 교체 이야기이기도 합니다.

## 2. 비유로 이해하기

결재 라인을 생각해 보세요. 담당자, 팀장, 본부장이 차례로 검토하는 3단계 결재입니다. 그런데 세 사람 모두 "받은 점수에 일정 비율을 곱하고 얼마를 더해서 위로 올리는" 기계적인 일만 한다면 어떨까요? 담당자가 2배 하고, 팀장이 0.5배 하고, 본부장이 3배 하는 식이라면, 세 단계를 합친 효과는 결국 "3배"라는 곱셈 한 번과 같습니다. 도장이 세 개 찍혔을 뿐, 판단은 한 번만 일어난 것입니다. 이것이 선형 층만 쌓은 신경망의 모습입니다.

결재가 의미 있으려면 각 단계에 판단이 있어야 합니다. "기준 미달이면 여기서 반려한다", "일정 금액 이상은 별도 트랙으로 보낸다"처럼 조건에 따라 다르게 반응하는 순간, 3단계 결재는 곱셈 한 번으로 압축되지 않는 진짜 3단계가 됩니다. 활성화 함수가 바로 이 "판단"입니다. ReLU는 "음수 점수는 0으로 잘라 버리는" 단호한 반려 담당자이고, sigmoid는 어떤 점수든 0~1 사이의 확신 정도로 바꿔 말하는 신중한 보고자입니다.

기울기 소실은 이렇게 비유할 수 있습니다. sigmoid 담당자는 점수가 아주 크든 아주 작든 대답이 거의 "1에 가깝습니다" 또는 "0에 가깝습니다"로 굳어 버립니다. 이런 상태에서는 입력을 조금 바꿔도 반응이 거의 변하지 않아, "어느 방향으로 고쳐야 좋아지나요?"라는 질문(기울기)에 사실상 무응답이 됩니다. 피드백이 층을 거슬러 올라갈수록 점점 작아져 아래층까지 전달되지 않는 것, 그것이 기울기 소실입니다.

## 3. 핵심 개념

### 3.1 왜 비선형이 필요한가 — 선형의 합성은 선형

행렬로 쓰면 한 줄입니다. 3개 층이 각각 W1, W2, W3라는 행렬 곱셈이라면, 전체는 `y = W3 @ (W2 @ (W1 @ x)) = (W3 @ W2 @ W1) @ x`입니다. 행렬 곱은 결합법칙이 성립하므로 `W3 @ W2 @ W1`을 미리 곱해 하나의 행렬 W로 만들 수 있고, 3층 네트워크는 1층 네트워크와 완전히 같아집니다. 층 사이에 비선형 함수 f를 끼우면 `W3 @ f(W2 @ f(W1 @ x))`가 되어 이 압축이 불가능해지고, 그제서야 깊이가 표현력을 만듭니다. 실습에서 이 두 경우를 숫자로 직접 비교합니다.

### 3.2 대표 활성화 함수 비교

| 함수 | 식 | 출력 범위 | 특징 |
|------|-----|-----------|------|
| sigmoid | 1/(1+e^-z) | (0, 1) | 확률처럼 해석 가능. 양끝에서 포화 |
| tanh | (e^z - e^-z)/(e^z + e^-z) | (-1, 1) | 0 중심이라 sigmoid보다 유리. 역시 포화 |
| ReLU | max(0, z) | [0, ∞) | 계산이 싸고 양수 구간 기울기 1. 현대 기본값 |
| Leaky ReLU | z<0에서 0.01z | (-∞, ∞) | 음수 구간에도 작은 기울기를 남김 |

포화(saturation)란 입력이 커지거나 작아질 때 출력이 평평해지는 현상입니다. sigmoid의 기울기는 최대가 0.25(z=0)이고, z=5만 되어도 약 0.0066으로 곤두박질칩니다.

### 3.3 기울기 소실과 죽은 ReLU

학습은 "출력의 오차를 각 층의 기울기와 곱해 가며 거꾸로 전달"하는 방식으로 이루어집니다(자세한 원리는 이후 레벨에서 다룹니다). 기울기가 최대 0.25인 sigmoid를 10층에 끼우면, 전달되는 신호는 최대로 잡아도 0.25의 10제곱, 약 백만분의 1 수준으로 줄어듭니다. 아래층은 사실상 학습을 멈춥니다. 이것이 깊은 신경망이 오랫동안 잘 안 되던 핵심 이유이고, 기울기가 양수 구간에서 항상 1인 ReLU가 이 문제를 크게 완화하며 표준이 되었습니다.

다만 ReLU에도 약점이 있습니다. 어떤 뉴런의 가중합이 데이터 전 구간에서 음수가 되어 버리면 출력도 0, 기울기도 0이라 다시는 갱신되지 않습니다. 이것이 죽은 ReLU입니다. 음수 구간에 0.01 같은 작은 기울기를 남겨 두는 Leaky ReLU는 이 위험을 줄이려는 변형입니다.

## 4. 실습 — main.py

실행 방법은 다음과 같습니다.

```bash
cd lecture08_deep_learning_foundations/level02_activation_functions
python3 main.py
```

출력은 다섯 단계입니다.

- **[1]** sigmoid, tanh, ReLU, Leaky ReLU의 함수 모양을 2x2 그림으로 그려 `outputs/activations.png`에 저장하고 경로를 출력합니다. 각 패널에는 함수(실선)와 도함수(점선)가 함께 그려집니다.
- **[2]** 네 함수의 기울기(도함수)만 한 축에 겹쳐 그린 `outputs/gradients.png`를 저장합니다. sigmoid/tanh의 기울기가 양끝에서 0으로 깔리는 모습과 ReLU의 기울기가 양수 구간에서 1로 유지되는 모습을 비교할 수 있습니다.
- **[3]** 포화를 숫자로 확인합니다. sigmoid'(0)=0.25가 sigmoid'(5)에서 얼마로 줄어드는지, 그 값을 10층 곱하면 얼마가 되는지 출력해 기울기 소실을 체감하고, 죽은 ReLU와 Leaky ReLU의 차이도 수치로 보여 줍니다.
- **[4]** 핵심 증명입니다. 난수 행렬 W1, W2, W3로 선형 층 3개를 합성한 결과와, 미리 곱해 둔 단일 행렬 `W3 @ W2 @ W1`을 같은 입력에 적용한 결과의 최대 오차를 출력합니다. 오차가 사실상 0(부동소수점 한계 수준)임을 확인합니다.
- **[5]** 층 사이에 ReLU를 끼운 결과는 어떤 단일 선형 행렬로도 흉내 낼 수 없음을 보여 줍니다. 같은 입력에 대해 결과가 크게 달라지고, 선형성의 기본 성질인 `f(a+b) = f(a)+f(b)`도 깨지는 것을 수치로 확인합니다.

코드 핵심부는 `linear_stack_vs_single` 함수(결합법칙 확인)와 `relu_breaks_linearity` 함수(가법성 붕괴 확인)입니다. 그림 코드는 색을 함수마다 고정 배정하고, 도함수는 근사가 아닌 해석적 공식으로 계산합니다.

## 6. 자주 하는 실수

- **"층을 많이 쌓았으니 복잡한 모델"이라고 믿는 것.** 활성화 함수가 없으면 100층도 1층입니다. 깊이는 비선형과 함께일 때만 의미가 있습니다.
- **sigmoid를 은닉층 기본값으로 쓰는 것.** sigmoid는 출력층에서 확률을 표현할 때는 여전히 유용하지만, 깊은 은닉층에 쓰면 기울기 소실을 자초합니다. 은닉층 기본값은 ReLU 계열입니다.
- **죽은 ReLU를 데이터 문제로 오해하는 것.** 학습 중 일부 뉴런의 출력이 항상 0이 되는 것은 흔한 현상이며, 학습률이 너무 크거나 초기화가 나쁠 때 심해집니다. Leaky ReLU나 학습률 조정이 처방입니다.
- **도함수를 수치 미분으로만 확인하는 것.** ReLU처럼 꺾이는 점(z=0)이 있는 함수는 그 점에서 수치 미분이 애매한 값을 냅니다. 해석적 공식과 병행해 확인하는 습관이 안전합니다.
- **부동소수점 오차 1e-15를 "다르다"고 읽는 것.** [4]의 최대 오차는 0이 아니라 아주 작은 수로 나올 수 있는데, 이는 컴퓨터 소수 계산의 한계이지 두 계산이 다르다는 뜻이 아닙니다.
