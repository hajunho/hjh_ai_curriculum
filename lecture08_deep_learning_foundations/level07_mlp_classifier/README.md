# Lecture 08 · Level 07 — MLP 분류 모델 만들기

> nn.Module 로 나만의 다층 퍼셉트론(MLP)을 조립하고, 구독 이탈 데이터에서 로지스틱 회귀와 정면 대결을 시킵니다. 결과는 예상과 다를 수 있습니다.

**난이도** ⭐⭐⭐ / **선행** level06 (autograd·옵티마이저), lecture06 level05 (로지스틱 회귀) / **예상 시간** 55분

## 1. 왜 배우나 — 비즈니스 관점

여기서 처음으로 딥러닝을 "장난감 문제(XOR)"가 아닌 **비즈니스 데이터**에 적용합니다. 구독 서비스의 이탈 예측은 마케팅 예산 배분과 직결되는 대표적 실무 과제입니다. 동시에 이 레벨은 중요한 현실 감각을 심어 줍니다 — 표(테이블) 형태 데이터에서는 딥러닝이 단순한 로지스틱 회귀를 항상 이기지는 않는다는 것. "우리도 딥러닝 도입합시다"라는 회의에서, 여러분은 "먼저 단순 모델과 비교 실험을 해 보시죠"라고 말할 수 있는 사람이 됩니다. 또한 PyTorch 실무 코드의 표준 골격인 `nn.Module` 클래스 작성법은 이후 모든 강의(CNN, 트랜스포머)의 기반 문법입니다.

## 2. 비유로 이해하기

**nn.Module = 레고 조립 설명서.** 모델 클래스는 두 부분으로 나뉩니다.

- `__init__`: **부품 상자를 여는 단계.** 필요한 블록(Linear 층, ReLU, Sigmoid)을 선언해 상자에 담아 둡니다. 이때 각 Linear 블록 안의 가중치가 자동으로 만들어지고, `model.parameters()` 로 옵티마이저에게 한꺼번에 넘겨집니다.
- `forward`: **조립 순서도.** 입력이 들어오면 블록을 어떤 순서로 통과시킬지 적습니다. `model(X)` 라고 부르면 PyTorch 가 알아서 forward 를 실행합니다.

**로지스틱 회귀 = 은닉층 0개 신경망.** lecture06 에서 배운 로지스틱 회귀는 사실 `Linear(6,1) + Sigmoid` — 즉 가장 작은 신경망입니다. 신경망은 로지스틱 회귀 "앞에" 특징을 가공하는 은닉층(자동 피처 엔지니어링 팀)을 붙인 것뿐입니다. 그래서 이번 대결은 "피처 가공팀을 새로 채용하면 성과가 오르는가?"에 대한 실험이기도 합니다.

## 3. 핵심 개념

### 3-1. 은닉층 설계 감각

- **폭(너비)**: 입력 6개 → 16 → 8 → 1 처럼, 점점 좁아지는 깔때기 모양이 무난한 출발점입니다.
- **깊이**: 표 데이터는 은닉 1~2층이면 충분한 경우가 대부분입니다. 층을 늘릴수록 표현력은 늘지만 과적합·학습 난이도도 늘어납니다(level09).
- **파라미터 수 감각**: 로지스틱 회귀 7개 vs MLP 257개. 파라미터가 37배지만 성능이 37배가 되지는 않습니다.

### 3-2. 표준화와 데이터 누설

특징들의 단위가 제각각이면(개월 수 1~60, 요금 9,900~29,900) 경사하강이 비틀거립니다. 그래서 평균 0, 표준편차 1 로 표준화합니다. 단, **평균·표준편차는 학습 데이터로만 계산**해야 합니다. 테스트 데이터를 섞어 계산하면 시험 문제를 미리 본 셈(데이터 누설)이 됩니다. `customer_id` 를 특징에서 뺀 것도 같은 맥락 — 의미 없는 식별자는 과적합 재료일 뿐입니다.

### 3-3. model.eval() 과 no_grad

- `model.eval()`: "지금은 시험 시간" 모드 전환. 드롭아웃(level09) 같은 학습 전용 동작을 끕니다.
- `torch.no_grad()`: 평가 중에는 미분 장부 기록을 꺼서 메모리·시간을 아낍니다.

둘은 하는 일이 다르므로 평가 때 **둘 다** 쓰는 것이 표준입니다.

### 3-4. 불균형 데이터에서 성적표 읽기

이탈률이 13~18%면 "전원 유지"라고만 찍어도 정확도 85% 내외가 나옵니다. 그래서 정확도만 보면 안 되고, 이탈(양성) 클래스의 **정밀도**(이탈이라 찍은 것 중 진짜 비율)와 **재현율**(진짜 이탈 중 잡아낸 비율)을 함께 봅니다. lecture06 level06 의 "정확도의 함정" 그대로입니다.

### 3-5. 그럼 표 데이터에는 무엇을 쓰나

실무 감각으로 정리하면 이렇습니다. 표 형태 데이터의 1차 후보는 로지스틱 회귀·트리 계열(lecture06 의 랜덤포레스트, 부스팅)입니다. 신경망이 표 데이터에서 확실히 유리해지는 경우는 (1) 특징 간 상호작용이 복잡하고 데이터가 아주 많을 때, (2) 이미지·텍스트 같은 비정형 데이터와 표를 함께 넣을 때, (3) 임베딩(embedding)으로 고유번호형 특징(상품 ID 등)을 압축 표현해야 할 때입니다. "일단 단순 모델로 기준선을 만들고, 신경망은 그 기준선을 이겨야 채택"이 건강한 프로세스입니다.

## 4. 실습 — main.py

실행:

```bash
cd lecture08_deep_learning_foundations/level07_mlp_classifier
python3 main.py
```

출력 순서:

- **[1]** churn_table 2000건을 75:25 로 나누고 표준화합니다. "전원 유지 찍기" 기준선(~87%)을 먼저 출력합니다.
- **[2]~[3]** 로지스틱 회귀(파라미터 7개)와 MLP(257개)를 같은 조건(Adam, 800에폭 full-batch)으로 학습합니다. MLP 의 train loss 가 더 낮게 내려갑니다(표현력이 크므로 당연).
- **[4]** 테스트 성능: 정확도는 둘 다 기준선 근처(0.85~0.87)이고, 재현율은 둘 다 낮습니다. train loss 우위가 테스트 우위로 이어지지 않는 것 — 이것이 핵심 관찰입니다.
- **[5]** MLP 의 임계값을 0.5 → 0.3 으로 내리면 정확도를 약간 내주고 재현율이 0.09 → 0.24 로 뜁니다. 모델을 다시 학습하지 않고도 비즈니스 목적(이탈 고객 놓치지 않기)에 맞게 조정할 수 있습니다.
- **[6]** 해석: 이 데이터의 이탈 규칙은 거의 선형이라 MLP 의 이점이 작습니다. "딥러닝이 항상 이기지는 않는다"를 데이터로 확인합니다.

코드에서 볼 곳은 `ChurnMLP` 클래스입니다. `__init__` 의 부품 선언과 `forward` 의 조립 — 이 두 칸 구조가 모든 PyTorch 모델의 뼈대입니다.

## 5. 직접 해보기

1. **(쉬움)** MLP 의 은닉 크기를 (16, 8) → (64, 32) 로 키워 보세요. train loss 와 테스트 성능이 각각 어떻게 변하나요? *힌트: train loss 는 확실히 내려가지만 테스트는 그렇지 않을 것입니다. 과적합의 냄새입니다.*
2. **(보통)** 표준화를 끄고(µ=0, σ=1 로 두고) 학습해 보세요. loss 곡선이 어떻게 달라지나요? *힌트: 요금(수만 단위) 특징이 경사를 지배해 수렴이 눈에 띄게 나빠집니다.*
3. **(도전)** 임계값을 0.1~0.9 로 훑으며 정밀도·재현율 표를 만들어 보세요. "이탈 고객 1명 놓치면 5만 원 손해, 쿠폰 발송 1건에 5천 원"이라는 가정으로 총비용이 최소가 되는 임계값을 찾아 보세요. *힌트: for 문으로 evaluate(threshold=...) 를 반복하면 됩니다.*

## 6. 자주 하는 실수

- **forward 를 직접 호출.** `model.forward(X)` 가 아니라 `model(X)` 로 부르세요. 후자가 훅(hook) 등 내부 절차를 올바르게 거칩니다.
- **표준화 통계를 전체 데이터로 계산.** 흔한 데이터 누설입니다. 반드시 학습 세트로만 계산해 테스트에 적용합니다.
- **BCELoss 와 로짓 혼용.** 모델 끝에 Sigmoid 를 뒀으면 BCELoss, 안 뒀으면 BCEWithLogitsLoss 입니다. 섞으면 조용히 성능이 망가집니다(후자가 수치적으로 더 안정적이라 실무 선호).
- **train loss 만 보고 승자 판정.** 표현력이 큰 모델은 train loss 는 거의 항상 이깁니다. 판정은 반드시 테스트/검증 성능으로.
