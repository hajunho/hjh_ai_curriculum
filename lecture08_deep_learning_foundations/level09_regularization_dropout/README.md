# Lecture 08 · Level 09 — 과적합 방지 기법

> 일부러 과적합 사고를 낸 다음, 드롭아웃·weight decay·조기종료라는 세 가지 처방이 검증 성능을 얼마나 회복시키는지 통제 실험으로 비교합니다.

**난이도** ⭐⭐⭐⭐ / **선행** level08 (학습 루프·배치·에폭) / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

과적합(overfitting)은 딥러닝 프로젝트가 실패하는 경로 1위입니다. 개발 단계 성적표는 화려한데 출시 후 성능이 무너지는 사고 — "데모에서는 잘 됐는데요"의 정체가 대부분 이것입니다. 무서운 점은 과적합이 조용히 온다는 것입니다. train 지표만 보고 있으면 모든 것이 좋아 보입니다. 이 레벨을 마치면 여러분은 (1) 학습곡선에서 과적합을 조기에 발견하고, (2) 상황에 맞는 처방을 고르고, (3) "이 모델 성능 수치를 믿어도 되나요?"라는 질문에 검증 체계 관점으로 답할 수 있게 됩니다. lecture06 level09 에서 트리 모델의 과적합을 봤다면, 이번엔 신경망 버전 + 신경망 고유의 처방(드롭아웃)입니다.

## 2. 비유로 이해하기

**과적합 = 기출문제 통암기.** 학습 데이터 120건, 모델 파라미터 4,700개. 문제 120개를 파라미터 4,700개로 공부하는 것은, 시험 범위 전체를 이해하는 대신 기출 120문제의 답을 통째로 외우는 것과 같습니다. 기출(train) 점수는 100점, 실전(valid) 점수는 추락합니다.

세 가지 처방도 전부 "외우지 못하게 방해하기"입니다.

- **드롭아웃(dropout) = 무작위 결근 훈련.** 매 훈련마다 팀원(뉴런)의 절반이 무작위로 결근합니다. "그 문제는 김 대리만 안다" 식의 특정 뉴런 의존(공동 적응)이 불가능해지고, 모두가 서로를 커버할 수 있는 일반적인 지식을 갖추게 됩니다. 실전(평가) 때는 전원 출근합니다 — 이것이 `model.train()`/`model.eval()` 전환의 정체입니다.
- **weight decay = 큰 가중치에 세금.** 특정 입력 하나에 극단적으로 의존하는(가중치가 큰) 답안일수록 세금을 물립니다. 모델은 "여러 근거를 조금씩 반영하는" 온건한 답안을 선호하게 됩니다.
- **조기종료(early stopping) = 성적 정점에서 하산.** 모의고사(valid) 점수가 나빠지기 시작하면, 아직 공부(에폭)가 남았어도 그 시점의 실력을 최종본으로 채택합니다.

## 3. 핵심 개념

### 3-1. 과적합의 조건: 데이터 대비 과한 용량

파라미터 수 ≫ 데이터 수일 때 모델은 데이터를 "이해"하는 대신 "저장"할 수 있게 됩니다. 실습에서 train 정확도 100%는 자랑이 아니라 경고입니다 — 이탈 여부에는 본질적 무작위성이 있어, 정직한 모델이라면 train 에서도 100%가 나올 수 없기 때문입니다.

### 3-2. 드롭아웃의 동작

- 학습 시: 각 뉴런 출력을 확률 p 로 0으로 만들고, 남은 출력은 1/(1-p) 배로 보정(전체 신호 크기 유지).
- 평가 시: 아무것도 끄지 않습니다. `model.eval()` 을 잊으면 평가 때도 결근시켜 성능을 갉아먹습니다.
- 효과의 다른 해석: 매번 다른 부분 네트워크를 학습시키므로, 수많은 작은 모델의 앙상블(lecture06 level08)과 비슷해집니다.

### 3-3. weight decay 의 동작

손실에 가중치 제곱합 × λ 를 더하는 L2 규제와 (SGD 에서) 동등합니다. PyTorch 에서는 `optim.Adam(..., weight_decay=3e-2)` 인자 하나면 됩니다. λ 가 크면 과소적합으로 넘어가니(실습에서 train 정확도가 0.89 로 내려간 것이 그 조짐) 검증 성능으로 조절합니다.

### 3-4. 조기종료의 동작

에폭마다 valid loss 를 재고, 최저 기록이 갱신될 때 모델을 저장합니다. 일정 에폭(patience) 동안 갱신이 없으면 중단하고 저장본으로 복귀합니다. 공짜(추가 학습 비용 0)에 가까우면서 효과가 커, 실무에서는 사실상 기본 장착입니다.

### 3-5. 처방 선택 가이드

| 상황 | 1순위 처방 |
|---|---|
| 무엇이든 일단 | 조기종료 (비용 0, 부작용 적음) |
| 큰 네트워크, 데이터 부족 | 드롭아웃 + weight decay 병행 |
| 격차가 심하고 예산이 있다 | 데이터 수집·증강 (근본 치료) |
| train 성능조차 낮다 | 과적합 아님 — 규제를 풀고 용량·학습률 재검토 |

## 6. 자주 하는 실수

- **평가 때 `model.eval()` 누락.** 드롭아웃이 켜진 채 평가되어 성능이 들쭉날쭉해집니다. 반대로 학습 재개 시 `model.train()` 복귀도 잊지 마세요.
- **조기종료 기준을 train loss 로 잡기.** train loss 는 거의 항상 내려가므로 영원히 안 멈춥니다. 기준은 반드시 valid.
- **테스트 셋으로 조기종료.** valid 로 멈출 시점을 고르고, 최종 보고는 손대지 않은 테스트로 — 안 그러면 테스트가 사실상 학습에 참여한 것입니다.
- **처방을 전부 최대로 걸기.** 드롭아웃 0.5 + 강한 weight decay + 이른 종료를 한꺼번에 걸면 과소적합으로 직행합니다. 하나씩 넣고 곡선으로 확인하세요.
