# Lecture 08 · Level 06 — autograd 와 옵티마이저

> level04 에서 손으로 짰던 역전파 30줄이 `loss.backward()` 한 줄이 되는 순간을 직접 확인하고, SGD 와 Adam 이라는 두 가지 "하산 전략"을 비교합니다.

**난이도** ⭐⭐⭐ / **선행** level05 (PyTorch 텐서), level04 (역전파) / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

딥러닝이 산업 전반으로 퍼진 결정적 이유 중 하나가 자동미분(automatic differentiation)입니다. 미분을 손으로 짜야 했다면, 층을 하나 바꿀 때마다 수학 전공자가 역전파 코드를 다시 유도해야 했을 것입니다. autograd 덕분에 "모델 구조를 바꾸는 실험"이 몇 분 단위로 가능해졌고, 이것이 곧 기업의 실험 속도(iteration speed)가 되었습니다. 실무 관점에서 이 레벨의 수확은 두 가지입니다. 첫째, 어떤 PyTorch 학습 코드를 열어도 반드시 나오는 5단계 루프(zero_grad → forward → loss → backward → step)를 읽을 수 있게 됩니다. 둘째, "옵티마이저는 뭘 쓰나요?"라는 실무 단골 질문에 근거를 갖고 답할 수 있게 됩니다.

## 2. 비유로 이해하기

**autograd = 법인카드 자동 기록.** level04 의 numpy 역전파는 "수기 장부"였습니다. 지출(계산)이 있을 때마다 우리가 직접 적고, 결산(미분) 때 장부를 거꾸로 넘기며 책임을 배분했습니다. autograd 는 법인카드입니다. `requires_grad=True` 카드로 결제(연산)하면 내역이 자동으로 기록되고, `backward()` 를 부르는 순간 결산 — 즉 모든 파라미터에 대한 책임 추적(미분) — 이 자동으로 끝납니다. level04 에서 수치미분으로 검증했듯, 이 자동 결산은 수학적으로 정확합니다.

**옵티마이저 = 하산 전략.** 기울기(어느 쪽이 내리막인지)는 autograd 가 알려 줍니다. 그 정보로 "어떻게 걸을지"가 전략입니다.

- **SGD**: 기본 걸음. 기울기 × 학습률만큼 이동. 단순하고 정직합니다.
- **SGD + 모멘텀**: 관성 있는 걸음. 계속 같은 방향이면 가속이 붙어 얕은 굴곡을 지나칩니다.
- **Adam**: 스마트워치를 찬 등산가. 방향의 이동평균(모멘텀)에 더해, 파라미터마다 지형의 험준함을 기록해 보폭을 개별 조절합니다. 가파른 축은 조심조심, 완만한 축은 성큼성큼.

## 3. 핵심 개념

### 3-1. requires_grad 와 backward

```
x = torch.tensor(2.0, requires_grad=True)   # 기록 시작
y = x**2 + 3*x                              # 계산 그래프가 몰래 만들어짐
y.backward()                                # 그래프를 거꾸로 훑으며 미분
x.grad                                      # dy/dx = 7.0
```

PyTorch 는 연산할 때마다 "무엇으로 무엇을 만들었는지"의 그래프(계산 그래프)를 기록합니다. `backward()` 는 이 그래프를 출력에서 입력 방향으로 — 정확히 level04 의 역전파처럼 — 거슬러 올라가며 연쇄법칙을 적용합니다.

### 3-2. 기울기는 누적된다 — zero_grad 의 존재 이유

`backward()` 는 `grad` 에 값을 **더합니다**(덮어쓰지 않습니다). 두 번 부르면 7 + 7 = 14 가 됩니다. 그래서 학습 루프의 매 스텝 첫 줄이 `opt.zero_grad()` 입니다. 이를 빼먹으면 지난 스텝들의 기울기가 계속 쌓여, loss 가 요동치는 "귀신 버그"가 됩니다.

### 3-3. 표준 5단계 학습 루프

```
opt.zero_grad()      # 1. 장부 백지화
p = model(X)         # 2. 순전파
loss = loss_fn(p, y) # 3. 채점
loss.backward()      # 4. 역전파 (level04 의 30줄)
opt.step()           # 5. 가중치 업데이트 (level03 의 x -= lr*grad)
```

이후 어떤 레벨·어떤 강의에서도 이 5줄의 뼈대는 변하지 않습니다.

### 3-4. 옵티마이저는 상태를 가진다

SGD 는 기울기만 보고 걷지만, 모멘텀·Adam 은 "지금까지의 이동 기록"을 내부에 저장합니다. Adam 은 파라미터 1개당 이동평균 2개(방향, 크기)를 유지하므로, 모델 파라미터의 약 2배 메모리를 추가로 씁니다. 소형 모델에서는 무시할 수준이지만, 수십억 파라미터 모델에서는 이 옵티마이저 상태가 GPU 메모리의 큰 몫을 차지합니다 — level11 의 메모리 견적에서 이 숫자가 다시 등장합니다.

### 3-5. SGD vs Adam — 언제 무엇을

| | SGD(+모멘텀) | Adam |
|---|---|---|
| 보폭 | 전 파라미터 공통 | 파라미터별 자동 조절 |
| 학습률 민감도 | 높음 (튜닝 필수) | 낮음 (기본값 0.001로 대체로 무난) |
| 전형적 용도 | 비전 모델 최종 성능 짜내기 | 첫 시도 기본값, NLP/LLM 표준 |

실무 요령: **일단 Adam 으로 시작**해 빠르게 기준선을 만들고, 성능을 짜낼 단계에서 SGD+모멘텀+스케줄(level10)을 실험합니다.

## 6. 자주 하는 실수

- **zero_grad 누락.** 가장 흔한 실수 1위. loss 가 내려가다 요동치면 이것부터 확인하세요.
- **`loss.backward()` 를 두 번 호출.** 계산 그래프는 backward 후 기본적으로 해제됩니다. 같은 그래프에 다시 부르면 RuntimeError — 루프에서는 매 스텝 forward 부터 다시 합니다.
- **평가 코드에서 기록 낭비.** 추론만 할 때는 `with torch.no_grad():` 로 장부 기록을 꺼야 메모리와 시간이 절약됩니다 (다음 레벨에서 사용).
- **`.item()` 없이 loss 를 리스트에 저장.** 텐서를 그대로 모으면 계산 그래프까지 붙잡아 메모리가 샙니다. 숫자만 필요하면 `loss.item()`.
