# Lecture 08 · Level 01 — 퍼셉트론 직접 만들기

> 신경망의 최소 단위인 퍼셉트론을 numpy 약 30줄로 직접 구현하고, 틀릴 때마다 가중치를 고쳐 가는 학습 규칙이 AND/OR를 푸는 과정과 XOR에서 실패하는 과정을 에폭 단위로 관찰합니다.

**난이도** ⭐⭐ / **선행** level00_why_neural_networks / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

거대한 언어 모델도 결국 아주 단순한 부품 수십억 개의 조합입니다. 그 부품 하나가 퍼셉트론(perceptron), 즉 인공 뉴런입니다. 부품 하나의 동작을 정확히 이해하면, 이후에 나오는 "층을 쌓는다", "가중치를 학습한다", "모델이 수렴한다" 같은 말들이 더 이상 마법처럼 들리지 않습니다.

실무 관점에서 이번 레벨의 진짜 수확은 학습(learning)이라는 단어의 실체를 보는 것입니다. AI가 학습한다는 것은 신비한 일이 아니라, "예측하고, 틀린 만큼 숫자를 조금 고치고, 다시 예측하는" 반복 작업입니다. 이 감각이 있으면 협력사가 "모델을 재학습했습니다"라고 보고할 때 무엇을 얼마나 했다는 뜻인지, 왜 학습에 시간이 걸리는지, 왜 어떤 문제는 아무리 학습해도 안 되는지(XOR처럼) 판단할 수 있게 됩니다. 마지막 실패 시연은 특히 중요합니다. 도구의 한계를 아는 사람만이 도구를 제대로 고를 수 있기 때문입니다.

## 2. 비유로 이해하기

퍼셉트론은 회의에서의 가중 투표와 같습니다. 안건 하나를 두고 참석자 여러 명이 찬성(1) 또는 반대(0) 의견을 냅니다. 다만 모든 사람의 발언권이 같지는 않습니다. 팀장의 의견에는 가중치 3, 신입의 의견에는 가중치 0.5가 붙는 식입니다. 각 의견에 발언권을 곱해 모두 더한 값이 통과 기준선을 넘으면 안건 가결, 못 넘으면 부결입니다. 여기서 참석자들의 의견이 입력(x), 발언권이 가중치(w), 기준선을 조정하는 값이 편향(b)입니다.

그러면 학습은 무엇일까요? 이 회의체가 내린 결정을 나중에 결과와 대조해 보는 것입니다. 가결했는데 결과가 나빴다면(정답 0, 예측 1), 찬성표를 던졌던 사람들의 발언권을 조금 줄입니다. 부결했는데 알고 보니 좋은 안건이었다면(정답 1, 예측 0), 찬성했던 사람들의 발언권을 조금 키웁니다. 결정이 맞았다면 아무것도 바꾸지 않습니다. 이 단순한 인사 조정을 안건(데이터)마다 반복하면, 발언권 배분이 점점 "좋은 결정을 내리는 배분"으로 이동합니다. 이것이 퍼셉트론 학습 규칙의 전부입니다.

한 가지 미리 말씀드리면, 이 회의체는 위원회가 하나뿐인 단층 구조라서 level00에서 본 직선 하나의 한계를 그대로 물려받습니다. XOR처럼 직선으로 안 나뉘는 문제 앞에서는 발언권을 아무리 조정해도 영원히 결론이 오락가락합니다.

## 3. 핵심 개념

### 3.1 퍼셉트론의 계산

입력 x1, x2에 대해 퍼셉트론은 두 단계로 계산합니다.

1. 가중합: `z = w1*x1 + w2*x2 + b`
2. 계단 함수(step function): `z >= 0`이면 1, 아니면 0을 출력

level00의 선형 모델과 계산식이 같습니다. 차이는 계수를 구하는 방식입니다. level00에서는 최적 직선을 공식(최소제곱)과 전수 탐색으로 찾았지만, 퍼셉트론은 데이터를 한 건씩 보며 점진적으로 찾아갑니다.

### 3.2 퍼셉트론 학습 규칙

데이터 (x, 정답 y)를 하나 보고 예측 p를 냈을 때, 업데이트는 다음 한 줄입니다.

```
w <- w + lr * (y - p) * x
b <- b + lr * (y - p)
```

여기서 lr은 학습률(learning rate)로, 한 번에 얼마나 크게 고칠지 정하는 보폭입니다. `(y - p)`는 0(맞음), +1(1인데 0으로 예측), -1(0인데 1로 예측) 세 값만 가지므로, 맞으면 그대로 두고 틀리면 틀린 방향의 반대로 미는 규칙이라는 것을 알 수 있습니다. 데이터 전체를 한 바퀴 도는 것을 에폭(epoch)이라고 부르고, 한 에폭 동안 한 번도 틀리지 않으면 학습이 수렴(convergence)한 것입니다.

### 3.3 수렴 정리와 그 한계

퍼셉트론에는 유명한 보장이 하나 있습니다. 데이터가 직선(고차원에서는 초평면)으로 나뉠 수 있는 문제라면, 이 규칙은 유한한 횟수의 수정 안에 반드시 수렴합니다. AND와 OR가 여기에 해당합니다. 반대로 XOR처럼 직선으로 나뉘지 않는 문제에서는 수렴이 원리적으로 불가능합니다. 어떤 가중치에서도 틀리는 점이 최소 하나 남고, 그 점을 고치려는 업데이트가 다른 점을 다시 틀리게 만들어 가중치가 영원히 진동합니다. 실습에서 이 진동을 숫자로 직접 보게 됩니다.

## 4. 실습 — main.py

실행 방법은 다음과 같습니다.

```bash
cd lecture08_deep_learning_foundations/level01_perceptron_from_scratch
python3 main.py
```

출력은 네 단계입니다.

- **[1]** 약 30줄짜리 `Perceptron` 클래스를 소개하고 초기 가중치(시드 고정 난수)를 보여 줍니다.
- **[2]** AND 학습: 에폭마다 `w1, w2, b`와 그 에폭의 오분류(틀린 예측) 수를 한 줄씩 출력합니다. 오분류가 0이 되는 순간 수렴을 선언하고 최종 진리표 검증을 보여 줍니다.
- **[3]** OR 학습: 같은 과정을 반복합니다. AND보다 빨리 또는 비슷하게 수렴하는 모습을 볼 수 있습니다.
- **[4]** XOR 학습: 에폭 상한(25회)까지 돌려도 오분류가 0이 되지 않습니다. 가중치가 에폭 안에서 이리저리 고쳐지다가 결국 제자리로 돌아오는 진동(순환)에 갇혀, 정확도가 50%에 머무는 것을 보여 줍니다. 마지막에 "구조를 바꿔야 한다"는 결론으로 마무리합니다.

코드에서 눈여겨볼 곳은 `fit` 메서드 안의 업데이트 두 줄입니다. 3.2절의 수식이 numpy 코드로 그대로 옮겨져 있습니다. 또 `errors == 0`일 때 조기 종료하는 부분은 "수렴"의 정의를 코드로 쓴 것입니다. 출력에서 가중치가 에폭마다 어떻게 움직이는지 따라가 보면, 학습이란 결국 숫자 세 개가 자리를 잡아가는 과정임이 눈에 보입니다.

## 5. 직접 해보기

1. **(쉬움)** 학습률 `lr`을 0.1에서 0.5로, 다시 0.01로 바꿔 실행해 보세요. 수렴까지 걸리는 에폭 수가 어떻게 달라지나요? 힌트: 보폭이 크면 빨리 움직이지만 지나칠 수 있고, 작으면 안정적이지만 오래 걸립니다. 이 데이터는 작아서 차이가 크지 않을 수도 있습니다.
2. **(보통)** `Perceptron` 초기화의 시드를 7에서 다른 값으로 바꿔 몇 번 실행해 보세요. 최종 가중치가 실행마다 다른데도 진리표는 전부 맞습니다. "정답 직선은 하나가 아니다"라는 사실을 확인하고, 그래도 재현성을 위해 시드를 고정하는 이유를 생각해 보세요.
3. **(도전)** NAND(둘 다 1일 때만 0)를 학습시키는 코드를 [3] 뒤에 추가해 보세요. 그리고 손으로 만든 두 퍼셉트론 출력, 즉 NAND 결과와 OR 결과를 새 입력으로 삼아 세 번째 퍼셉트론에게 AND를 학습시키면 전체가 XOR이 됩니다. 힌트: level00의 은닉 표현과 같은 구조입니다. 퍼셉트론 세 개를 이으면 2층 신경망이 됩니다.

## 6. 자주 하는 실수

- **XOR 실패를 보고 코드 버그를 의심하는 것.** 오분류가 0으로 떨어지지 않는 것은 버그가 아니라 이 레벨의 핵심 결과입니다. 단층 구조의 수학적 한계입니다.
- **에폭과 업데이트 횟수를 혼동하는 것.** 에폭 1회는 데이터 4건을 전부 한 바퀴 도는 것이고, 업데이트는 그중 틀린 건수만큼 일어납니다.
- **학습률을 무조건 키우면 빨라진다고 생각하는 것.** 이 예제는 작아서 티가 덜 나지만, 실전에서는 큰 학습률이 발산(값이 튀며 영영 수렴 못 함)의 주범입니다.
- **가중치 초기값을 전부 0으로 두는 것.** 퍼셉트론 하나는 0에서 시작해도 학습되지만, 나중에 다층 신경망에서는 뉴런들이 전부 똑같이 움직여 학습이 망가집니다. 지금부터 작은 난수로 초기화하는 습관을 들이는 이유입니다.
- **계단 함수의 경계(`z = 0`) 처리를 잊는 것.** `>=`인지 `>`인지에 따라 경계 위 점의 분류가 달라지니 구현과 설명을 일치시켜야 합니다.
