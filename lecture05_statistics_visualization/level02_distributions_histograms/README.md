# Lecture 05 · Level 02 — 분포와 히스토그램

> 대표값이 데이터의 이력서라면, 분포는 데이터의 얼굴입니다. 얼굴을 봐야 오해가 없습니다.
**난이도** ⭐⭐ / **선행** level01 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

평균과 중앙값을 배웠지만, 숫자 몇 개로는 여전히 놓치는 것이 있습니다.
고객 대기 시간 데이터를 예로 들면 — 평균 4분, 중앙값 3분. 나쁘지 않아
보입니다. 그런데 분포를 그려 보니 대부분은 2~3분인데, 20분 넘게 기다린
고객이 매일 십수 명 있었습니다. 클레임과 이탈은 바로 이 **꼬리**에서
나옵니다. 평균을 개선하는 것과 꼬리를 줄이는 것은 완전히 다른 프로젝트
입니다.

분포(distribution)를 그리는 가장 기본 도구가 히스토그램(histogram)입니다.
값의 범위를 구간(bin)으로 나누고 각 구간의 빈도를 막대로 그립니다.
엑셀 피벗으로 구간별 COUNTIF 를 해 본 적이 있다면 이미 히스토그램을
손으로 만들어 본 것입니다. 이 레벨에서는 파이썬으로 그것을 한 줄에
그리고, "bin 크기를 바꾸면 이야기가 달라진다"는 함정까지 배웁니다.

## 2. 비유로 이해하기

히스토그램은 **아파트 단지의 야간 점등 사진**입니다. 각 세대(값)가 어느
동(구간)에 사는지 보여주죠. 어느 동에 불이 많이 켜져 있는지(빈도가
높은지), 단지가 한 덩어리인지 두 단지로 갈라져 있는지(봉우리 개수),
외딴 곳에 불 켜진 집이 있는지(극단값)가 한눈에 들어옵니다.

bin 크기는 **지도의 축척**입니다. 전국 지도(큰 bin)로 보면 "수도권에
사람이 많다" 정도만 보이고, 동네 지도(작은 bin)로 보면 골목 하나하나가
보이지만 전체 패턴은 사라집니다. 축척이 잘못된 지도는 없지만, **목적에
안 맞는 축척**은 있습니다. 히스토그램도 마찬가지로, bin 을 몇 개로
나누느냐에 따라 같은 데이터가 밋밋해 보이기도, 울퉁불퉁해 보이기도
합니다.

## 3. 핵심 개념

### 3.1 히스토그램 읽는 법

히스토그램에서 보는 것은 네 가지입니다.

1. **중심**: 봉우리가 어디쯤인가 (대표값과 연결)
2. **퍼짐**: 옆으로 얼마나 넓은가 (표준편차와 연결)
3. **모양**: 좌우 대칭인가, 한쪽으로 꼬리가 긴가, 봉우리가 몇 개인가
4. **특이점**: 본체에서 뚝 떨어진 막대(극단값), 이상하게 빈 구간

봉우리가 두 개(bimodal)라면 "서로 다른 집단이 섞여 있다"는 강한
신호입니다. 평일/주말, 신규/단골처럼 집단을 나눠 다시 그려야 합니다.

### 3.2 왜도 — 꼬리의 방향

왜도(skewness)는 분포가 한쪽으로 치우친 정도입니다.

- **오른쪽 꼬리(양의 왜도)**: 매출, 연봉, 대기시간. 대부분 작은 값 +
  드물게 큰 값. 이때 평균 > 중앙값.
- **왼쪽 꼬리(음의 왜도)**: 만점 근처에 몰린 시험 점수처럼 큰 값이
  많고 작은 값이 드문 경우. 이때 평균 < 중앙값.

평균과 중앙값의 대소만 봐도 꼬리 방향을 짐작할 수 있습니다.
level01 에서 본 "평균 > 중앙값" 현상의 정체가 바로 오른쪽 꼬리였습니다.

### 3.3 bin 크기의 영향

| bin 개수 | 보이는 것 | 위험 |
|---|---|---|
| 너무 적음 (5개) | 큰 흐름만 | 두 봉우리가 하나로 뭉개짐 |
| 적당함 (20~40개) | 중심·퍼짐·모양 | — |
| 너무 많음 (200개) | 세부 요철 | 난수 잡음을 패턴으로 착각 |

정답 공식은 없지만 관례적인 출발점은 "루트 n 개" 또는 20~50개 사이에서
몇 가지를 그려 보고 이야기가 안정되는 지점을 찾는 것입니다. **bin 을
바꿔도 살아남는 패턴만 믿는다** — 이것이 실무 규칙입니다.

### 3.4 히스토그램 vs 막대그래프

생김새는 비슷하지만 다릅니다. 히스토그램은 **연속된 수치를 구간으로
나눈 것**이라 막대가 붙어 있고 순서가 의미를 갖습니다. 막대그래프는
지점·카테고리 같은 **범주**의 비교라 막대가 떨어져 있고 순서를 바꿔도
됩니다. 보고서에서 이 둘을 혼동하면 읽는 사람이 축을 오해합니다.

### 3.5 분포를 숫자 하나로 — 백분위수 맛보기

히스토그램을 요약하는 보조 숫자로 백분위수(percentile)가 있습니다. 90
백분위수가 8분이라는 말은 "고객의 90%는 8분 안에 처리된다"는 뜻입니다.
IT 서비스의 응답 속도 목표를 평균이 아니라 p95, p99 로 잡는 이유가 바로
꼬리 관리 때문입니다. 실습 [1]에서 매출의 p50(중앙값)과 p95 를 함께
출력하니, 두 숫자의 간격으로 꼬리의 길이를 느껴 보세요.

## 6. 자주 하는 실수

- **bin 하나만 그려 보고 결론 내리기**: 봉우리 개수 같은 중요한 판단은
  반드시 bin 을 2~3가지로 바꿔 확인하세요.
- **집단이 섞인 채로 분포 해석**: 봉우리 두 개를 "이상한 분포"라고 넘기지
  말고 집단을 분리해 다시 그리세요. 대부분 평일/주말, 지점, 상품군 같은
  숨은 축이 있습니다.
- **y축이 빈도인지 비율인지 안 밝히기**: 표본 크기가 다른 두 분포를
  비교할 때는 `density=True`(비율)로 맞춰야 공정합니다.
- **극단값을 잘라내고 그린 사실을 숨기기**: 시각화를 위해 범위를 제한하는
  것은 괜찮지만, "상위 1% 제외" 같은 문구를 반드시 그림에 남기세요.
