# Lecture 02 · Level 05 — 함수: 재사용 가능한 업무 절차

> 함수는 자주 쓰는 절차에 이름을 붙여 두고 "이 일 좀 처리해 줘"라고 위임하는 장치입니다. 인자로 일감을 넘기고 반환값으로 결과를 돌려받습니다.
**난이도** ⭐⭐ / **선행** level04 / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

부가세 계산 로직이 회사 코드 여섯 군데에 복사되어 있다고 합시다. 세율이 바뀌면
여섯 군데를 전부 찾아 고쳐야 하고, 하나라도 놓치면 부서마다 다른 세금을 계산하는
사고가 납니다. 실제 실무 버그의 큰 축이 이런 "복사-붙여넣기 로직의 불일치"입니다.

함수(function)는 로직을 **한 곳에** 정의하고 필요한 곳마다 이름으로 불러 쓰는 장치입니다.
세율이 바뀌면 함수 안 한 줄만 고치면 모든 곳에 반영됩니다. 게다가 `calc_vat(총액)` 처럼
이름이 곧 설명이 되어 코드가 업무 절차서처럼 읽힙니다. 이번 실습에서는 세금·할인 계산이
덕지덕지 복사된 "리팩터링 전" 코드와 함수로 정리한 "후" 코드를 나란히 실행해
그 차이를 확인합니다.

## 2. 비유로 이해하기

**업무 위임 비유.** 팀장이 경비 정산을 직접 하지 않고 담당자에게 맡기는 장면을 떠올려 보세요.

> 팀장: "정산 담당자님, 이 영수증 묶음(입력) 정산 좀 부탁해요."
> 담당자: (자기 자리에서 자기 방식으로 처리한 뒤) "정산 결과 32만 원입니다(출력)."

여기서 핵심이 세 가지입니다.

1. **이름** — "정산 담당자"라는 역할 이름만 알면 됩니다. → 함수 이름
2. **입력** — 영수증 묶음을 건네줍니다. → 인자(argument)
3. **출력** — 결과 금액을 돌려받습니다. → 반환값(return value)

그리고 중요한 것: 팀장은 담당자가 **어떻게** 계산하는지 몰라도 됩니다. 담당자의
책상 위(함수 내부의 변수들)는 담당자의 영역이고, 팀장 책상과 섞이지 않습니다.
이것이 스코프(scope, 유효 범위)입니다. 위임이 잘 된 조직일수록 각자의 책상이
분리되어 있듯, 좋은 함수는 바깥세상과 인자·반환값으로만 소통합니다.

## 3. 핵심 개념

### 3.1 정의와 호출

```python
def calc_vat(amount):          # 정의: '이런 절차가 있다'고 등록만 함
    return int(amount * 0.1)   # 반환: 결과를 호출한 쪽에 돌려줌

vat = calc_vat(50000)          # 호출: 실제로 일을 시키는 순간 (-> 5000)
```

`def` 는 정의(define)일 뿐 실행이 아닙니다. 함수 이름 뒤에 괄호를 붙여 **호출**해야
비로소 몸통이 실행됩니다. `return` 을 만나면 함수는 즉시 종료되고 값을 들고 돌아갑니다.
`return` 이 없는 함수는 `None` 을 돌려줍니다.

### 3.2 인자 — 여러 개, 이름 지정, 기본값

```python
def calc_discount(amount, grade, rate=0.05):     # rate 는 기본값 있는 인자
    ...

calc_discount(100000, "VIP")                     # rate 는 기본값 0.05 사용
calc_discount(100000, "VIP", rate=0.1)           # 필요할 때만 지정
calc_discount(amount=100000, grade="VIP")        # 키워드 인자: 순서 무관, 의미 명확
```

기본값(default) 인자는 "특별한 지시가 없으면 표준 규정대로 처리"에 해당합니다.
**기본값 있는 인자는 없는 인자 뒤에** 와야 합니다. 호출할 때 이름을 붙이는
키워드 인자는 인자가 3개를 넘어가면 가독성을 크게 높여 줍니다.

### 3.3 반환값 — 여러 개 돌려주기

```python
def summarize(sales):
    return sum(sales), len(sales), max(sales)    # 튜플로 묶여 반환

total, count, best = summarize(data)             # 언패킹으로 받기
```

level04 의 튜플 언패킹이 여기서 빛을 발합니다. "합계·건수·최댓값"처럼 세트로
나오는 결과를 한 번에 돌려줄 수 있습니다.

### 3.4 스코프 — 함수 안의 변수는 함수 안에서만

```python
def process():
    temp = 100        # 지역 변수(local): 이 함수의 책상 위에만 존재

process()
print(temp)           # NameError! 바깥에서는 보이지 않음
```

함수 안에서 만든 변수는 함수가 끝나면 사라집니다(지역 변수). 함수 밖의 변수(전역 변수,
global)를 함수 안에서 읽을 수는 있지만, **수정하는 습관은 들이지 마세요.** 어디서 값이
바뀌었는지 추적이 안 되는 코드가 됩니다. 필요한 값은 인자로 받고 결과는 return 으로
돌려주는 것 — 이것이 "각자의 책상" 원칙입니다.

### 3.5 좋은 함수의 조건

- **한 가지 일만** 합니다. "세금 계산 겸 파일 저장 겸 메일 발송" 함수는 셋으로 쪼갭니다.
- **이름이 동사구**입니다: `calc_vat`, `apply_discount`, `format_receipt`.
- **docstring**(함수 첫 줄의 설명 문자열)으로 용도·인자·반환을 한두 줄 적습니다.
- 같은 코드를 **두 번 복사하게 되는 순간**이 함수로 뽑을 타이밍입니다
  (DRY 원칙: Don't Repeat Yourself).

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture02_python_basics/level05_functions
python3 main.py
```

주문 3건의 결제 금액(등급 할인 + 부가세)을 계산하는 예제를 두 가지 방식으로 실행합니다.

- **[1] 리팩터링 전**: 할인율 판정과 세금 계산 로직이 주문마다 복사-붙여넣기 되어 있습니다.
  20여 줄이 반복되고, 그중 한 곳에는 **일부러 심어 둔 불일치 버그**(세율 오타)가 있어
  주문 2건의 결과가 미묘하게 어긋납니다.
- **[2] 리팩터링 후**: `get_discount_rate`, `calc_vat`, `calc_payment` 세 함수로 정리해
  같은 계산을 수행합니다. 로직이 한 곳뿐이므로 불일치가 원천 차단됩니다.
- **[3] 전/후 비교**: 두 방식의 결과를 나란히 놓고 어느 주문에서 얼마나 어긋났는지 출력합니다.
- **[4] 함수 문법 정리**: 기본값 인자, 키워드 인자, 다중 반환, 스코프(NameError 재현)를
  짧게 시연합니다.

`calc_payment` 가 내부에서 다른 두 함수를 부르는 구조 — 담당자가 다시 실무자에게
위임하는 구조 — 도 눈여겨보세요. 함수는 이렇게 계층으로 쌓입니다.

## 6. 자주 하는 실수

- **print 와 return 혼동** — print 는 화면에 보여 줄 뿐 값을 돌려주지 않습니다.
  `result = show_total(...)` 했는데 `None` 이 담겨 있다면 함수가 return 대신 print 만
  한 것입니다. "계산은 return, 보고는 print"로 역할을 나누세요.
- **호출 괄호 빠뜨림** — `calc_vat` 만 쓰면 함수 자체(객체)이고, `calc_vat(50000)` 이어야
  실행입니다.
- **인자 순서 실수** — `calc_discount("VIP", 100000)` 처럼 순서를 바꿔 넣으면 엉뚱한
  계산이 됩니다. 헷갈리면 키워드 인자로 이름을 붙여 호출하세요.
- **전역 변수 수정** — 함수 안에서 바깥 변수를 몰래 바꾸면 버그 추적이 악몽이 됩니다.
  인자로 받고 return 으로 돌려주세요.
- **기본값에 리스트 사용** — `def f(items=[])` 는 호출들끼리 리스트를 공유하는 유명한
  함정입니다. `def f(items=None)` 후 함수 안에서 `if items is None: items = []` 로 처리하세요.
