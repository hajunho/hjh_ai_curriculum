# Lecture 02 · Level 10 — 컴프리헨션·제너레이터·람다·데코레이터 맛보기

> "목록에서 조건에 맞는 것을 골라 변환해 새 목록으로"를 한 줄로 쓰는 컴프리헨션, 데이터를 한 번에 만들지 않고 필요할 때 하나씩 흘려보내는 제너레이터 — 파이썬다운 코드의 4대 표현을 맛봅니다.
**난이도** ⭐⭐⭐⭐ / **선행** level09 / **예상 시간** 60분

## 1. 왜 배우나 — 비즈니스 관점

여기까지 배운 문법만으로도 모든 프로그램을 짤 수 있습니다. 그런데 실무에서 남의 코드 —
동료의 스크립트, 오픈소스 예제, AI 가 생성해 준 코드 — 를 열어 보면
`[row["amount"] for row in rows if row["ok"]]` 같은 한 줄이 쏟아집니다.
이 표현들을 모르면 읽지 못하고, 읽지 못하면 고치지도 못합니다.

또 하나, 데이터가 커질 때의 문제가 있습니다. 1억 건짜리 거래 로그를 리스트로 몽땅
메모리에 올리면 컴퓨터가 멈춥니다. 제너레이터(generator)는 "필요할 때 한 건씩"
흘려보내는 방식으로 이 문제를 해결하며, 대용량 스트림 처리라는 실무 기법의 입구입니다.
이번 레벨은 문법 암기가 아니라 **읽는 눈 + 메모리 감각**을 얻는 것이 목표입니다.

## 2. 비유로 이해하기

**컴프리헨션 = 엑셀 필터+수식 한 방.** "매출 시트에서 강남점 행만 걸러서, 금액에
1.1을 곱한 새 시트를 만들어라." 엑셀에서는 필터 걸고 수식 끌어 채우는 두 동작이지만,
말로는 한 문장입니다. 컴프리헨션(comprehension)은 그 한 문장을 그대로 코드로 옮긴
문법입니다: `[x * 1.1 for x in sales if x.store == "강남"]` — "강남점인 x 각각에 대해
1.1을 곱한 것들의 목록".

**제너레이터 = 수도꼭지.** 리스트는 생수를 페트병 1억 개에 미리 다 담아 창고(메모리)에
쌓아 두는 방식입니다. 제너레이터는 수도꼭지입니다 — 틀 때마다 한 컵씩 나오고,
창고가 필요 없습니다. 월말 정산에서 "전체를 다 모아 놓고 계산"이 아니라
"흘러오는 건별로 누적"하는 방식이라고 생각하면 됩니다.

**람다 = 포스트잇 지시.** 정식 절차서(def 함수)를 만들 것도 없는 한 줄짜리 지시 —
"금액 기준으로 정렬해 줘" — 를 포스트잇에 적어 건네는 것이 람다(lambda)입니다.

**데코레이터 = 결재 도장.** 기존 문서(함수)의 내용은 건드리지 않고, 겉에
"검토필" 도장을 찍어 공통 절차(시간 기록, 로그)를 덧입히는 장치가 데코레이터(decorator)입니다.

## 3. 핵심 개념

### 3.1 리스트 컴프리헨션

```python
# 루프 방식 (4줄)
result = []
for x in sales:
    if x >= 100000:
        result.append(int(x * 1.1))

# 컴프리헨션 (1줄) — 뜻: "10만 이상인 x 각각에 1.1을 곱한 목록"
result = [int(x * 1.1) for x in sales if x >= 100000]
```

읽는 순서는 **for 부터**: "sales 의 각 x 에 대해 → 조건에 맞으면 → 앞의 식을 계산해 담는다".
딕셔너리 버전 `{k: v for ...}`, 집합 버전 `{x for ...}` 도 같은 원리입니다.
단, 조건이 두 개를 넘거나 식이 복잡해지면 **루프로 풀어 쓰는 편이 낫습니다.**
한 줄에 우겨넣은 암호문은 세련된 코드가 아닙니다.

### 3.2 제너레이터 — 필요할 때 하나씩

```python
def transaction_stream(n):
    for i in range(n):
        yield make_row(i)        # return 대신 yield: 한 건 내보내고 멈춰 대기

for row in transaction_stream(100_000_000):   # 1억 건이어도 메모리는 한 건 분량
    process(row)
```

`yield` 가 있는 함수는 호출해도 바로 실행되지 않고 "수도꼭지"(제너레이터 객체)를
돌려줍니다. for 가 한 바퀴 돌 때마다 다음 yield 까지만 실행되어 값을 하나 내보내고
멈춥니다. 전부 메모리에 올리지 않으므로 대용량 처리의 표준 기법입니다.
컴프리헨션의 대괄호를 소괄호로 바꾼 `(x * 1.1 for x in sales)` 는
제너레이터식(generator expression)으로, `sum(...)` 에 바로 넣는 용법이 흔합니다.
수도꼭지에서 나온 물은 다시 담을 수 없듯 **한 번 소비하면 끝**이라는 점만 주의하세요.

### 3.3 람다 — 이름 없는 한 줄 함수

```python
sorted(rows, key=lambda r: r["amount"], reverse=True)   # 금액 기준 내림차순
max(rows, key=lambda r: r["amount"])                     # 최고 매출 행
```

`lambda 인자: 반환식` 형태로, `sorted`/`max`/`min` 의 `key` 인자에 "무엇을 기준으로?"를
전달할 때가 주 무대입니다. 두 줄 이상 필요하면 그냥 `def` 로 이름 있는 함수를 만드세요.

### 3.4 데코레이터 — 함수를 감싸는 함수 (맛보기)

```python
@stopwatch                 # = report = stopwatch(report) 의 줄임 표기
def report():
    ...
```

데코레이터는 "함수를 받아 기능을 덧입힌 새 함수를 돌려주는 함수"입니다.
실행 시간 측정, 로그 남기기, 권한 확인처럼 **여러 함수에 공통으로 찍을 도장**에 씁니다.
직접 만들 일은 당분간 없지만, `@` 표기를 읽을 수 있어야 실무 코드와 프레임워크
문서를 읽을 수 있습니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture02_python_basics/level10_comprehensions_generators
python3 main.py
```

지점 매출 데이터 변환을 소재로 네 표현을 차례로 시연합니다.

- **[1] 루프 vs 컴프리헨션**: 같은 변환(10만 원 이상 거래에 부가세 반영)을 두 방식으로 짜서
  결과가 동일함을 확인합니다. 딕셔너리 컴프리헨션으로 "지점 -> 매출" 표도 만듭니다.
- **[2] 제너레이터**: 거래 100만 건 스트림을 리스트로 쌓을 때와 제너레이터로 흘릴 때의
  **메모리 사용량을 실측 비교**합니다 (표준 라이브러리 `sys.getsizeof` 사용).
  약 8MB vs 200바이트 — 숫자로 보는 것이 백 마디 설명보다 강합니다.
- **[3] 람다**: 매출 상위 3개 지점 정렬, 최고·최저 지점 찾기를 `key=lambda` 로 처리합니다.
- **[4] 데코레이터 맛보기**: 실행 시간을 재는 `@stopwatch` 도장을 두 함수에 찍어,
  함수 본문을 안 고치고 공통 기능이 덧입혀지는 것을 확인합니다.

## 6. 자주 하는 실수

- **컴프리헨션 과욕** — 조건 3개, 중첩 2단짜리 한 줄은 아무도 못 읽습니다.
  "한 줄로 짧게"가 아니라 "한 문장으로 읽히게"가 기준입니다.
- **제너레이터 재사용** — 한 번 소비한 제너레이터를 다시 돌리면 빈 결과가 나옵니다.
  두 번 쓸 데이터면 리스트로 받거나 제너레이터를 다시 만드세요.
- **len() 시도** — 제너레이터는 길이를 미리 모릅니다. `len(gen)` 은 TypeError.
  건수가 필요하면 흘려보내며 세야 합니다.
- **람다에 로직 우겨넣기** — 조건문이 든 긴 람다는 def 로 승격시키세요.
  람다는 "포스트잇", 절차서가 필요하면 정식 문서(def)로.
- **컴프리헨션 안 변수가 샌다고 착각** — 루프 변수 `x` 는 컴프리헨션 밖으로 새지
  않습니다(파이썬 3 기준). 바깥의 같은 이름 변수와 별개입니다.
