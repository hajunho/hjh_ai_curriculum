# Lecture 02 · Level 00 — 프로그래밍이란 무엇인가

> 프로그래밍은 컴퓨터가 오해 없이 따라 할 수 있도록 일의 절차를 적는 것이며, 그 절차는 순차·분기·반복 세 가지로 전부 표현됩니다.
**난이도** ⭐ / **선행** 없음 (lecture01 level03 을 마쳤다면 더 좋습니다) / **예상 시간** 30분

## 1. 왜 배우나 — 비즈니스 관점

회사에서 우리는 매일 "절차"를 만들고 따릅니다. 신입사원 온보딩 체크리스트, 월말 정산 순서,
고객 클레임 대응 매뉴얼 — 전부 절차서입니다. 프로그래밍(programming)은 이 절차서를
사람이 아니라 컴퓨터가 읽고 실행할 수 있는 형태로 적는 일입니다.

차이가 하나 있습니다. 사람은 매뉴얼이 조금 애매해도 "알아서" 채워 읽지만,
컴퓨터는 적힌 그대로만 합니다. 그래서 프로그래밍을 배우면 두 가지 능력이 생깁니다.
첫째, 반복 업무를 컴퓨터에게 통째로 넘길 수 있습니다. 둘째, 애매함 없이 절차를
설계하는 사고력이 생겨서 코드를 안 쓰는 업무 문서까지 좋아집니다.
이번 레벨에서는 코드 문법을 외우기 전에, "프로그램이란 무엇인가"라는 큰 그림을 잡습니다.

## 2. 비유로 이해하기

**레시피 비유.** 라면 레시피를 떠올려 보세요. "물 550ml를 끓인다 → 면과 스프를 넣는다 →
4분 30초 끓인다." 위에서 아래로 차례대로 실행됩니다. 이것이 **순차(sequence)**입니다.

레시피에는 갈림길도 있습니다. "매운맛을 원하면 청양고추를 넣고, 아니면 넣지 않는다."
조건에 따라 다른 길을 가는 것, 이것이 **분기(branch)**입니다.

그리고 "면이 익을 때까지 저어 준다"처럼 같은 동작을 여러 번 하는 것이 **반복(loop)**입니다.

놀랍게도, 세상의 모든 프로그램은 이 세 가지의 조합입니다. 급여 계산 시스템도,
스마트폰 게임도, 챗봇도 결국 순차·분기·반복을 아주 많이, 아주 정교하게 쌓아 올린 것입니다.
새 문법을 만날 때마다 "이건 셋 중 무엇을 편하게 해 주는 도구인가?"라고 물으면
길을 잃지 않습니다.

**업무 매뉴얼 비유.** 카페 아르바이트 첫날 받는 주문 처리 매뉴얼을 생각해 보세요.
"주문을 받는다 → 결제 금액을 계산한다 → 포인트 회원이면 적립한다 → 음료를 만든다 →
손님이 받을 때까지 진동벨을 울린다." 이 매뉴얼을 컴퓨터 언어로 옮기면 그게 바로
프로그램입니다. 이번 실습의 main.py 가 정확히 이 일을 합니다.

## 3. 핵심 개념

### 3.1 프로그램 = 데이터 + 절차

프로그램은 두 가지로 이루어집니다. 다루는 재료인 **데이터(data)** — 주문 수량, 단가,
고객 이름 — 와, 재료를 가공하는 **절차(procedure)** — 계산하고, 판단하고, 출력하는 단계들.
엑셀에 비유하면 셀에 든 값이 데이터, 수식과 매크로가 절차입니다.

### 3.2 순차 — 위에서 아래로

파이썬 코드는 특별한 지시가 없으면 첫 줄부터 마지막 줄까지 차례대로 실행됩니다.
순서가 바뀌면 결과도 바뀝니다. "할인 적용 후 부가세 계산"과 "부가세 계산 후 할인 적용"이
다른 금액을 내는 것처럼요.

### 3.3 분기 — 조건에 따라 다른 길

"만약 ~라면 A, 아니면 B." 파이썬에서는 `if` 라는 단어로 씁니다. 자세한 문법은
level02 에서 배우고, 오늘은 "프로그램이 스스로 판단하는 지점"이라는 개념만 잡으면 됩니다.

### 3.4 반복 — 같은 일을 여러 번

"목록에 있는 모든 주문에 대해 ~를 하라." 파이썬에서는 `for` 라는 단어로 씁니다.
사람은 100번 반복하면 지치고 실수하지만 컴퓨터는 100만 번도 동일한 품질로 해냅니다.
자동화의 이득 대부분이 여기서 나옵니다.

### 3.5 왜 컴퓨터에게는 정확하게 적어야 하나

신입사원에게 "적당히 정리해서 보고해 주세요"라고 하면 어떻게든 결과가 나옵니다.
경험과 상식으로 빈칸을 채우기 때문입니다. 컴퓨터에게는 그 상식이 없습니다.
"매출을 집계하라"고만 적으면 어떤 파일의, 어떤 열을, 어떤 기준으로 더할지 몰라
멈춥니다. 그래서 프로그래밍의 절반은 "내가 아는 절차를 빠짐없이, 애매함 없이
말로 풀어내는 일"입니다. 코드를 쓰기 전에 절차를 한국어 문장으로 번호 매겨 적어 보는
습관(이를 의사코드(pseudocode)라고 부릅니다)을 들이면, 문법을 몰라도 프로그램의
설계는 이미 끝난 셈입니다.

### 3.6 프로그래밍 언어와 파이썬

컴퓨터가 알아듣는 절차 표기법을 프로그래밍 언어(programming language)라고 합니다.
그중 파이썬은 문법이 영어 문장에 가까워 비전공자가 배우기 가장 수월하고,
데이터 분석·AI 분야의 표준 언어라서 이 커리큘럼 전체에서 사용합니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture02_python_basics/level00_what_is_programming
python3 main.py
```

main.py 는 카페의 "아메리카노 주문 처리" 절차를 코드로 옮긴 데모입니다.
출력은 네 단계로 나옵니다.

- **[1] 순차**: 주문 접수 → 금액 계산 → 영수증 출력이 위에서 아래로 실행되는 모습을 보여 줍니다.
- **[2] 분기**: 포인트 회원인지에 따라 적립 문구가 달라집니다. 코드의 `if is_member:` 부분이 갈림길입니다.
- **[3] 반복**: 주문 3건을 `for` 반복문 하나로 처리합니다. 주문이 300건이어도 코드는 그대로라는 점이 핵심입니다.
- **[4] 요약**: "모든 프로그램은 순차·분기·반복의 조합"이라는 오늘의 결론을 출력합니다.

아직 문법을 배우지 않았으니 코드를 전부 이해하려 하지 마세요.
`cup_price * quantity` 같은 부분이 "어? 읽히네?" 싶으면 성공입니다.
주석(#으로 시작하는 한국어 설명)을 따라 어느 줄이 순차·분기·반복인지 표시만 찾아보세요.

## 5. 직접 해보기

1. **값 바꿔 보기** — main.py 를 열어 `cup_price = 4500` 을 다른 값으로 바꾸고 다시 실행해 보세요.
   출력 금액이 어떻게 달라지나요? (힌트: 데이터가 바뀌면 같은 절차라도 결과가 바뀝니다.)
2. **분기 체험** — `is_member = True` 를 `False` 로 바꾸고 실행해, 출력에서 어떤 줄이
   사라지는지 확인하세요. (힌트: `if` 아래 들여쓰기된 줄이 실행되지 않게 됩니다.)
3. **일상 업무를 절차로 쪼개기** — 여러분이 매주 하는 업무 하나(예: 주간 보고 작성)를
   골라 순차·분기·반복이 각각 어디에 있는지 종이에 적어 보세요.
   (힌트: "~까지 반복", "~인 경우에만"이라는 말이 나오면 그 지점입니다.)

## 6. 자주 하는 실수

- **문법 암기부터 시작하기** — 문법은 도구일 뿐입니다. "무슨 절차를 자동화하려는가"를
  먼저 말로 정리하는 습관이 훨씬 중요합니다.
- **컴퓨터가 알아서 해 줄 거라 기대하기** — 컴퓨터는 적힌 그대로만 합니다.
  "당연히 부가세 포함이겠지"라고 생각해도 코드에 없으면 계산되지 않습니다.
- **한 번에 완벽한 프로그램을 만들려 하기** — 실무 프로그램도 작은 절차를 만들고
  실행해 확인하고 조금씩 키우는 식으로 만듭니다. 실행 버튼을 자주 누르세요.
- **에러를 실패로 여기기** — 에러 메시지는 컴퓨터가 보내는 질문입니다.
  level07 에서 읽는 법을 배우니, 지금은 겁내지 않는 것만으로 충분합니다.
