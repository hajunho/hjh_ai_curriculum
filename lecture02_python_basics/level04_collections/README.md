# Lecture 02 · Level 04 — 리스트·튜플·딕셔너리·집합

> 값 여러 개를 담는 네 가지 그릇 — 순서 있는 목록(리스트), 못 바꾸는 목록(튜플), 이름표 서랍장(딕셔너리), 중복 없는 주머니(집합) — 의 용도와 선택 기준을 배웁니다.
**난이도** ⭐⭐ / **선행** level03 / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

실무 데이터는 값 하나가 아니라 묶음으로 옵니다. 이번 달 판매 기록 목록, 상품별 재고 수량표,
거래처 사업자번호 명단. 이 묶음을 어떤 그릇에 담느냐에 따라 코드의 길이와 속도,
버그 발생률이 완전히 달라집니다.

예를 들어 "상품 코드로 재고 수량 찾기"를 리스트로 짜면 매번 전체를 뒤져야 하지만,
딕셔너리(dictionary)로 짜면 한 번에 꺼냅니다. "이번 주 방문 고객 중 중복 제거"는
집합(set) 한 줄로 끝납니다. 그릇 선택은 사소해 보여도, 엑셀에서 표를 어떻게 설계하느냐가
업무 효율을 좌우하는 것과 같은 문제입니다. 이번 레벨에서는 재고 관리 미니 예제로
네 그릇을 전부 써 보고 선택 기준을 몸에 익힙니다.

## 2. 비유로 이해하기

사무실 비품 관리로 비유해 보겠습니다.

- **리스트(list) = 입고 기록 대장.** 들어온 순서대로 한 줄씩 적습니다. 순서가 의미 있고,
  같은 품목이 여러 번 나올 수 있고, 줄을 추가·수정·삭제할 수 있습니다.
- **튜플(tuple) = 코팅해 둔 규격표.** "A4용지, 500매, 25000원"처럼 한 번 정해지면
  바꾸지 않는 묶음입니다. 수정이 안 되는 게 단점이 아니라 **실수로도 못 바꾼다는 안전장치**입니다.
- **딕셔너리(dict) = 이름표 붙은 서랍장.** "볼펜" 서랍을 열면 재고 37개가 나옵니다.
  서랍 이름(키, key)만 알면 위에서부터 뒤질 필요 없이 바로 꺼냅니다(값, value).
- **집합(set) = 중복을 허락하지 않는 주머니.** 같은 것을 두 번 넣어도 하나만 남습니다.
  "이번 주에 발주한 품목의 종류"처럼 **있냐/없냐와 종류**만 중요할 때 씁니다.

## 3. 핵심 개념

### 3.1 리스트 — 순서 있는 목록

```python
sales = [45000, 120000, 89000]
sales.append(56000)       # 끝에 추가
sales[0]                  # 첫 항목 (번호는 0부터!)
sales[-1]                 # 마지막 항목
sales[1:3]                # 슬라이스: 1번부터 3번 직전까지
len(sales), sum(sales), sorted(sales)   # 개수, 합계, 정렬본
```

인덱스(index)가 0부터 시작한다는 것, 슬라이스의 끝 번호는 포함되지 않는다는 것
(range 와 같은 규칙)을 기억하세요.

### 3.2 튜플 — 변경 불가 묶음

```python
product = ("P001", "볼펜", 1200)     # (코드, 이름, 단가)
code, name, price = product           # 언패킹: 한 번에 꺼내기
```

튜플은 만들고 나면 항목을 바꿀 수 없습니다(불변, immutable). 좌표·설정값·함수의
복수 반환값처럼 "세트로 다니는 값"에 씁니다. level03 에서 `for name, qty in orders:` 로
꺼내 쓴 것이 바로 튜플 언패킹(unpacking)이었습니다.

### 3.3 딕셔너리 — 키로 값 찾기

```python
stock = {"볼펜": 37, "A4용지": 12, "스테이플러": 4}
stock["볼펜"]              # 37 (키로 즉시 조회)
stock["형광펜"] = 20       # 새 항목 추가
stock.get("지우개", 0)     # 없으면 0 반환 (KeyError 방지)
for item, qty in stock.items():   # 키-값 쌍 순회
    ...
```

없는 키를 대괄호로 조회하면 `KeyError` 가 납니다. 있는지 확실하지 않으면
`in` 으로 확인하거나 `get(키, 기본값)` 을 쓰는 것이 실무 습관입니다.

### 3.4 집합 — 중복 제거와 소속 검사

```python
visited = {"P001", "P002", "P001"}    # -> {"P001", "P002"} 중복 자동 제거
"P001" in visited                      # 소속 검사가 매우 빠름
a & b, a | b, a - b                    # 교집합, 합집합, 차집합
```

"양쪽 명단에 모두 있는 고객"(교집합), "발주했지만 입고 안 된 품목"(차집합) 같은
명단 대조 업무가 연산자 하나로 끝납니다. 단, 집합은 순서가 없습니다.

### 3.5 선택 기준 요약

| 상황 | 그릇 | 이유 |
|---|---|---|
| 순서 있는 기록, 추가/수정 필요 | 리스트 | 입고 대장 |
| 바뀌면 안 되는 값 묶음 | 튜플 | 규격표 |
| 이름(키)으로 빠른 조회 | 딕셔너리 | 서랍장 |
| 중복 제거, 있냐/없냐, 명단 대조 | 집합 | 주머니 |

그리고 실무 데이터의 표준 형태는 **"딕셔너리들의 리스트"**입니다.
한 행(row)이 딕셔너리, 표 전체가 리스트 — 엑셀 표 한 장이 그대로 옮겨진 모양이며,
lecture03 의 pandas 로 자연스럽게 이어집니다.

## 6. 자주 하는 실수

- **인덱스는 0부터** — `items[1]` 은 두 번째 항목입니다. "첫 번째"가 필요하면 `items[0]`.
- **없는 키 조회** — `stock["지우개"]` 는 지우개가 없으면 `KeyError` 로 프로그램이 멈춥니다.
  `stock.get("지우개", 0)` 또는 `if "지우개" in stock:` 을 쓰세요.
- **리스트 복사 착각** — `b = a` 는 복사가 아니라 같은 목록에 이름표를 하나 더 붙인 것입니다.
  `b.append(...)` 하면 a 도 바뀝니다. 진짜 복사는 `b = a.copy()`.
- **튜플인데 수정 시도** — `product[2] = 1500` 은 `TypeError` 입니다. 바꿔야 할 값이면
  애초에 리스트나 딕셔너리에 담으세요.
- **집합에 순서 기대** — 집합은 넣은 순서를 보장하지 않습니다. 순서가 필요하면
  `sorted(집합)` 으로 정렬해 리스트로 받으세요.
