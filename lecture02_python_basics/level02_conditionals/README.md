# Lecture 02 · Level 02 — 조건문: 컴퓨터에게 판단시키기

> if/elif/else 는 "만약 ~라면 A, 그 외에 ~라면 B, 모두 아니면 C"라는 사내 결재 규정을 코드로 옮긴 것입니다.
**난이도** ⭐ / **선행** level01 / **예상 시간** 45분

## 1. 왜 배우나 — 비즈니스 관점

회사 업무의 상당수는 "규정에 따라 판단하기"입니다. 출장경비가 15만 원 이하면 팀장 전결,
넘으면 본부장 결재. 재고가 안전 수량 아래로 떨어지면 발주. 고객 등급이 VIP면 추가 할인.
이런 판단을 사람이 하면 하루 수백 건에 지치고, 담당자마다 기준이 흔들립니다.

조건문(conditional)을 배우면 규정집을 코드로 옮겨 **판단 자체를 자동화**할 수 있습니다.
한 번 정확히 적어 두면 1건이든 10만 건이든 같은 기준으로 즉시 판정합니다.
이번 레벨의 실습이 바로 "출장경비 자동 승인 판정기"입니다. 엑셀의 `IF` 함수를
써 봤다면 이미 절반은 아는 내용이고, 파이썬에서는 훨씬 읽기 쉽게 쓸 수 있습니다.

## 2. 비유로 이해하기

**결재 규정 비유.** 사내 경비 규정이 이렇게 적혀 있다고 합시다.

> 1. 금액이 5만 원 이하이면: 자동 승인
> 2. 그 외에, 금액이 15만 원 이하이고 영수증이 있으면: 팀장 전결
> 3. 그 외에, 금액이 50만 원 이하이면: 본부장 결재
> 4. 위 어디에도 해당하지 않으면: 반려 후 소명 요청

이 문서 구조가 조건문 그 자체입니다. "만약(if)" — "그 외에 만약(elif)" —
"모두 아니면(else)". 그리고 중요한 규칙 하나: 결재 규정을 위에서부터 읽다가
**처음으로 해당되는 조항에서 멈추는 것**처럼, 파이썬도 위에서부터 검사해
처음 참(True)이 되는 가지 하나만 실행하고 빠져나옵니다. 7만 원짜리 경비는
2번 조항에 걸리는 순간 3번, 4번은 아예 읽지 않습니다.

## 3. 핵심 개념

### 3.1 if / elif / else 기본 골격

```python
if amount <= 50000:
    result = "자동 승인"
elif amount <= 150000 and has_receipt:
    result = "팀장 전결"
elif amount <= 500000:
    result = "본부장 결재"
else:
    result = "반려"
```

- 조건 뒤에는 콜론(`:`)을 붙이고, 실행할 줄은 **들여쓰기(indentation)** 4칸으로 안쪽에 씁니다.
  파이썬은 들여쓰기로 "어디까지가 이 조건의 소관인지"를 구분합니다. 괄호가 아니라
  들여쓰기가 문법이라는 점이 파이썬의 특징입니다.
- `elif` 는 몇 개든 이어 붙일 수 있고, `else` 는 마지막에 하나만, 생략도 가능합니다.
- 위에서부터 검사해 **첫 번째로 참인 가지 하나만** 실행됩니다. 그래서 조건의 순서가
  곧 규정의 우선순위입니다.

### 3.2 비교 연산자 — 참/거짓을 만드는 도구

| 연산자 | 의미 | 예 | 결과 |
|---|---|---|---|
| `==` | 같다 | `grade == "VIP"` | True/False |
| `!=` | 다르다 | `status != "취소"` | True/False |
| `<` `<=` `>` `>=` | 크기 비교 | `amount <= 150000` | True/False |

비교식의 결과는 항상 불리언(bool), 즉 `True` 아니면 `False` 입니다.
**`=` (대입)과 `==` (비교)를 절대 혼동하지 마세요.** 조건 자리에 `=` 를 쓰면 문법 에러가 납니다.

### 3.3 논리 연산자 — 조건 조합하기

규정은 보통 조건 여러 개의 조합입니다.

- `and` : 둘 다 참이어야 참. "15만 원 이하 **이고** 영수증 있음"
- `or` : 하나라도 참이면 참. "임원 **이거나** 해외 출장"
- `not` : 참/거짓 뒤집기. "영수증이 **없으면**" → `not has_receipt`

`and` 가 `or` 보다 먼저 계산되므로, 섞어 쓸 때는 괄호로 의도를 명시하세요.
`(a or b) and c` 와 `a or (b and c)` 는 완전히 다른 규정입니다.

### 3.4 파이썬만의 편리한 표현

```python
if 50000 < amount <= 150000:     # 범위를 수학처럼 이어서 비교
if grade in ("VIP", "VVIP"):     # 여러 값 중 하나인가
if has_receipt:                  # == True 라고 쓸 필요 없음
```

`in` 은 "이 값이 목록 안에 있는가"를 묻는 연산자로, 등급·카테고리 판정에 특히 유용합니다.

### 3.5 중첩과 가독성

if 안에 if 를 넣는 중첩(nesting)도 가능하지만, 3단 이상 겹치면 규정집이 미로가 됩니다.
`and` 로 조건을 합치거나, 예외 케이스를 먼저 걸러내고(early return, level05 에서 다룹니다)
평평하게 쓰는 편이 읽기 좋습니다. "규정집을 처음 보는 신입도 이해할 수 있는가"가 기준입니다.

## 6. 자주 하는 실수

- **`=` 와 `==` 혼동** — `if grade = "VIP":` 는 `SyntaxError` 입니다. 판단은 항상 `==`.
- **들여쓰기 불일치** — 같은 블록인데 어떤 줄은 4칸, 어떤 줄은 3칸이면
  `IndentationError` 가 납니다. 에디터의 자동 들여쓰기를 믿고, 탭과 스페이스를 섞지 마세요.
- **조건 순서 실수** — `if amount <= 500000` 을 맨 위에 두면 5만 원짜리도 전부
  "본부장 결재"가 됩니다. 좁은(엄격한) 조건을 위에, 넓은 조건을 아래에 두세요.
- **`else` 남용으로 규정 구멍 만들기** — 마지막 `else` 는 "위 모든 조항에 해당 없음"입니다.
  거기에 "승인"을 두면 예상 못 한 케이스가 전부 승인됩니다. else 에는 안전한 기본값
  (반려, 보류, 담당자 확인)을 두는 것이 원칙입니다.
- **float 를 `==` 로 비교** — level01 의 오차 때문에 `0.1 + 0.2 == 0.3` 은 False 입니다.
  범위 비교나 `round` 후 비교를 쓰세요.
