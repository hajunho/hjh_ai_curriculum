# Lecture 02 · Level 08 — 모듈과 패키지

> 모듈은 함수·변수를 담은 파이썬 파일 하나이고, import 는 다른 부서의 전문가를 내 업무에 불러오는 호출입니다. 파이썬은 표준 라이브러리라는 사내 전문 부서를 기본 제공합니다.
**난이도** ⭐⭐⭐ / **선행** level07 / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

코드가 300줄을 넘어가면 한 파일 안에서 길을 잃기 시작합니다. 회사가 커지면
한 사람이 총무·회계·영업을 다 할 수 없어 부서를 나누듯, 프로그램도 기능별로
파일을 나눠야 합니다. 그 단위가 모듈(module)이고, 모듈을 폴더로 묶은 것이
패키지(package)입니다.

또 하나의 실익은 "이미 만들어진 전문 부서"를 그냥 쓰는 것입니다. 날짜 계산,
수학 함수, 난수, 집계 도구 — 이런 것을 직접 만들 필요가 없습니다. 파이썬 설치에
기본 포함된 표준 라이브러리(standard library)가 수백 개 모듈을 제공하며,
`import` 한 줄이면 끝입니다. "바퀴를 다시 발명하지 말라"는 개발 격언이 실무에서는
"검증된 라이브러리를 두고 내 코드로 버그를 만들지 말라"로 번역됩니다.

## 2. 비유로 이해하기

**부서 호출 비유.** 여러분이 기획서를 쓰다가 법률 검토가 필요해졌습니다.
법학을 독학하지 않고 법무팀을 부르죠.

> `import legal` → "법무팀과 연결해 줘"
> `legal.review(contract)` → "법무팀의 review 담당자에게 이 계약서를 넘겨"

`모듈.함수()` 라는 표기는 "부서.담당자()"입니다. 소속을 명시하니 어느 부서의
누구인지 헷갈리지 않습니다. 자주 부르는 담당자는 직통 번호를 딸 수도 있습니다:
`from legal import review` → 이제 `review(contract)` 라고 바로 부릅니다. 편하지만,
여러 부서에서 같은 이름의 담당자를 데려오면(예: 영업팀 review 와 법무팀 review)
누가 누군지 섞이는 위험이 생깁니다.

우리가 직접 만드는 모듈은 "우리 팀의 업무 매뉴얼 바인더"입니다. 자주 쓰는 절차
(함수)를 바인더(utils.py)에 정리해 두면, 어느 문서(main.py)에서든 꺼내 쓸 수 있습니다.

## 3. 핵심 개념

### 3.1 import 의 세 가지 형태

```python
import math                      # 부서 통째로: math.sqrt(2)
from math import sqrt            # 담당자 직통: sqrt(2)
from math import sqrt as rt      # 별명 붙이기: rt(2)
```

기본 권장은 첫 번째 형태입니다. `math.sqrt` 처럼 출처가 보여서 코드 리뷰가 쉽습니다.
`from 모듈 import *` (전원 호출)는 이름 충돌의 온상이므로 금지 습관으로 두세요.

### 3.2 내 모듈 만들기 — 파일이 곧 모듈

같은 폴더에 `utils.py` 를 만들고 함수를 정의하면, `main.py` 에서
`import utils` 로 불러 `utils.format_krw(1200000)` 처럼 씁니다. 규칙은 단순합니다.

- 파일 이름이 모듈 이름입니다 (`utils.py` → `import utils`, `.py` 는 뗍니다).
- 파이썬은 실행 스크립트가 있는 폴더 등 정해진 경로 목록(`sys.path`)에서 모듈을 찾습니다.
- **import 하는 순간 그 파일의 코드가 위에서 아래로 한 번 실행됩니다.** 그래서 모듈에는
  함수·변수 정의만 두고, 실행 코드는 `if __name__ == "__main__":` 아래에 둡니다.
  이 관용구의 정체가 바로 이것입니다 — "직접 실행할 때만 동작하고, import 될 때는
  정의만 제공하라." 지금까지 모든 main.py 에 써 온 이유가 여기서 밝혀집니다.

### 3.3 패키지 — 모듈을 폴더로 묶기

모듈이 많아지면 폴더로 묶습니다. 폴더에 `__init__.py` 파일을 두면 파이썬이
그 폴더를 패키지로 인식하고, `from mypkg import utils` 처럼 경로로 불러옵니다.
pip 로 설치하는 numpy, pandas 도 결국 남이 만들어 배포한 패키지일 뿐입니다
(설치와 가상환경은 lecture01 level04 에서 다뤘습니다).

### 3.4 표준 라이브러리 투어 — 오늘의 네 부서

| 모듈 | 담당 업무 | 대표 기능 |
|---|---|---|
| `datetime` | 날짜·시간 | 오늘 날짜, 날짜 차이, D-day, 서식화 |
| `math` | 수학 | 제곱근, 올림/내림, 로그, 원주율 |
| `random` | 난수 | 추첨, 샘플링, 셔플 (seed 로 재현성 확보) |
| `collections` | 자료구조 확장 | Counter(빈도 집계), defaultdict(기본값 서랍장) |

특히 `collections.Counter` 는 "카테고리별 건수 세기"를 한 줄로 끝내 주어
실무 등장 빈도가 매우 높습니다. 이 밖에 `csv`(level06), `os`, `json`, `statistics` 등
"필요할 때 표준 라이브러리부터 검색"하는 습관이 중요합니다.

## 4. 실습 — main.py

실행 방법:

```bash
cd lecture02_python_basics/level08_modules_packages
python3 main.py
```

이 레벨 폴더에는 파일이 두 개 있습니다. **utils.py** — 통화 서식, 부가세 계산,
영업일 계산 함수를 담은 우리 팀 공용 모듈 — 과 그것을 불러 쓰는 **main.py** 입니다.

- **[1] 내 모듈 import**: `import utils` 로 공용 함수를 불러 매출 요약을 만듭니다.
  `utils.py` 를 import 하는 순간 모듈 상단의 print 가 딱 한 번 실행되는 것,
  utils 를 직접 실행할 때만 도는 자체 데모(`__name__` 구분)도 관찰합니다.
- **[2] datetime**: 오늘 날짜(고정된 기준일 사용), 프로젝트 마감까지 D-day,
  날짜 서식화를 시연합니다.
- **[3] math**: 예산 배분에 올림(`ceil`)이 왜 필요한지 — 17명을 5인승 차량에 나눠 태우기 —
  로 보여 줍니다.
- **[4] random**: seed 고정 후 경품 추첨(`sample`)과 근무 순번 셔플(`shuffle`)을 합니다.
- **[5] collections**: `Counter` 로 주문 카테고리 빈도를 한 줄에 집계하고
  `defaultdict` 로 지점별 매출을 모읍니다.

먼저 `python3 utils.py` 로 모듈을 **직접 실행**해 자체 데모를 보고, 그다음
`python3 main.py` 로 **import 되는 쪽**을 실행해 두 경우의 차이를 비교해 보세요.

## 6. 자주 하는 실수

- **모듈 이름과 같은 파일명 만들기** — 내 파일을 `random.py` 로 지으면 파이썬이
  표준 라이브러리 대신 내 파일을 import 해서 미궁의 에러가 납니다. 표준 모듈 이름은 피하세요.
- **import 위치 산발** — import 는 파일 맨 위에 모아 두는 것이 관례입니다.
  코드 중간에 흩어 놓으면 의존 관계 파악이 어렵습니다.
- **`from ... import *`** — 어디서 온 이름인지 알 수 없어지고 충돌도 잦습니다.
- **모듈에 실행 코드 방치** — `if __name__ == "__main__":` 없이 실행 코드를 두면
  import 만 해도 그 코드가 돌아 버립니다. 정의와 실행을 분리하세요.
- **random seed 미고정** — 테스트·보고서 재현이 필요한 작업에서 seed 를 고정하지 않으면
  "어제는 됐는데 오늘은 다른" 결과가 나옵니다. 실험 재현성은 AI 실습 전체의 기본기입니다.
