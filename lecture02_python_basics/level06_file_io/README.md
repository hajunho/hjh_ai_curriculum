# Lecture 02 · Level 06 — 파일 읽고 쓰기

> open/with 로 텍스트와 CSV 파일을 읽고 쓰는 법을 배우면, 프로그램이 끝나도 남는 결과물 — 리포트·데이터 파일 — 을 만들 수 있습니다.
**난이도** ⭐⭐ / **선행** level05 / **예상 시간** 50분

## 1. 왜 배우나 — 비즈니스 관점

지금까지의 실습은 결과를 화면에만 출력했습니다. 프로그램이 끝나면 변수도 결과도
모두 사라집니다. 실무는 다릅니다. 매출 데이터는 CSV 파일로 도착하고,
분석 결과는 파일로 저장해 메일에 첨부하거나 공유 폴더에 올려야 합니다.

파일 입출력(file I/O)은 프로그램과 바깥세상을 잇는 관문입니다. 이 레벨을 마치면
"매일 아침 거래내역 CSV 를 읽어 요약 리포트 텍스트를 만드는 일"을 자동화할 수
있습니다 — 실제로 많은 직장인이 파이썬으로 처음 자동화하는 업무가 바로 이것입니다.
그리고 한국어 데이터를 다루는 사람이 반드시 만나는 함정, 인코딩(encoding) 문제를
미리 예방하는 법도 배웁니다.

## 2. 비유로 이해하기

**서류 캐비닛 비유.** 파일을 다루는 절차는 사무실 캐비닛에서 서류철을 꺼내 쓰는 것과 같습니다.

1. 캐비닛에서 서류철을 **꺼낸다** → `open("파일명")`
2. 읽거나 내용을 **추가한다** → `read()` / `write()`
3. 반드시 제자리에 **돌려놓는다** → `close()`

서류철을 책상에 쌓아 두고 퇴근하면 다음 사람이 못 쓰고, 분실 위험도 생기죠.
파일도 닫지 않으면 내용이 저장되지 않거나 다른 프로그램이 열지 못할 수 있습니다.
문제는 사람이 깜박한다는 것. 그래서 파이썬은 `with` 라는 "자동 반납 시스템"을
제공합니다. `with` 블록이 끝나면 — 도중에 에러가 나서 뛰쳐나가더라도 — 파일이
자동으로 닫힙니다. 도서관의 자동 반납기라고 생각하면 됩니다.

**인코딩은 문자 저장 규격**입니다. 같은 한글 문서라도 어떤 규격(utf-8, cp949 등)으로
저장했는지에 따라 다른 규격으로 열면 글자가 깨집니다. 해외 규격 콘센트에 맞는
어댑터 없이 플러그를 꽂으려는 상황과 같습니다. 오늘날의 표준은 utf-8 이며,
**열고 쓸 때 항상 `encoding="utf-8"` 을 명시**하는 것이 한국어 데이터의 생존 수칙입니다.

## 3. 핵심 개념

### 3.1 with open — 표준 패턴

```python
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("1분기 요약\n")          # \n 은 줄바꿈 (자동으로 넣어 주지 않음!)

with open("report.txt", "r", encoding="utf-8") as f:
    content = f.read()               # 전체를 문자열 하나로
```

모드(mode) 세 가지만 우선 기억하세요.

| 모드 | 의미 | 주의 |
|---|---|---|
| `"r"` | 읽기 (기본값) | 파일이 없으면 FileNotFoundError |
| `"w"` | 쓰기 | **기존 내용을 전부 지우고** 새로 씀 |
| `"a"` | 추가(append) | 기존 내용 끝에 이어 씀 (로그에 적합) |

`"w"` 가 기존 파일을 통째로 덮어쓴다는 점은 실무에서 가장 아픈 실수이니 두 번 강조합니다.

### 3.2 줄 단위로 읽기

큰 파일을 `read()` 로 통째로 읽으면 메모리를 다 씁니다. 파일 객체는 반복문에 넣으면
한 줄씩 나오므로, 다음이 표준 패턴입니다.

```python
with open("data.txt", encoding="utf-8") as f:
    for line in f:                   # 한 줄씩 (메모리 절약)
        line = line.strip()          # 끝의 줄바꿈 문자 제거
        ...
```

`strip()` 을 빼먹으면 모든 줄 끝에 보이지 않는 `\n` 이 붙어 비교·변환이 실패합니다.

### 3.3 CSV — 표 데이터의 공용어

CSV(comma-separated values)는 쉼표로 구분한 표 형식 텍스트로, 엑셀·DB·파이썬이
모두 읽는 공용어입니다. 쉼표를 직접 `split(",")` 해도 되지만, 값 안에 쉼표가 든 경우
("서울시, 강남구") 깨지므로 표준 라이브러리 `csv` 모듈을 씁니다.

```python
import csv

with open("sales.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["date", "item", "amount"])       # 헤더
    writer.writerow(["2026-09-01", "볼펜", 24000])

with open("sales.csv", encoding="utf-8", newline="") as f:
    for row in csv.DictReader(f):                     # 각 행이 딕셔너리로!
        print(row["item"], row["amount"])
```

`DictReader` 는 헤더를 키로 삼아 각 행을 딕셔너리로 돌려줍니다 — level04 에서 배운
"딕셔너리들의 리스트" 형태 그대로입니다. CSV 에서 읽은 값은 **전부 문자열**이므로
숫자는 `int()`/`float()` 변환이 필수입니다(level01 의 그 함정입니다).
쓰기 시 `newline=""` 은 윈도우에서 빈 줄이 끼는 문제를 막는 관례입니다.

### 3.4 경로와 os.makedirs

결과 파일은 실습 폴더 아래 `outputs/` 처럼 정해진 곳에 모읍니다.

```python
import os
os.makedirs("outputs", exist_ok=True)     # 폴더가 없으면 만들고, 있으면 조용히 통과
```

스크립트를 어느 폴더에서 실행하느냐에 따라 상대 경로의 기준이 달라지므로,
main.py 에서는 `os.path.dirname(__file__)` 로 "이 파일이 있는 폴더" 기준 경로를 만듭니다.

## 6. 자주 하는 실수

- **`"w"` 로 소중한 파일 덮어쓰기** — 쓰기 모드는 기존 내용을 즉시 지웁니다.
  원본 데이터 파일은 읽기만 하고, 결과는 항상 **다른 이름**으로 저장하세요.
- **encoding 생략** — 생략하면 운영체제 기본값이 쓰여, 윈도우(cp949)에서 만든 파일이
  맥/리눅스에서 깨집니다. 읽기·쓰기 모두 `encoding="utf-8"` 을 습관으로.
- **CSV 값을 문자열인 채 계산** — `row["amount"] + 100` 은 TypeError 또는 엉뚱한
  문자열 연결이 됩니다. 반드시 `int(row["amount"])`.
- **close 없이 open** — `f = open(...)` 만 쓰고 닫지 않으면 버퍼가 저장되지 않을 수
  있습니다. 항상 `with` 를 쓰면 고민할 필요가 없습니다.
- **줄 끝 `\n` 방치** — 읽은 줄을 비교하기 전에 `strip()`. `"볼펜\n" == "볼펜"` 은 False 입니다.
